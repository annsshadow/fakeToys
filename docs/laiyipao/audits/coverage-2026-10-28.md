本文件是 B1 的退出证据：在**真实 PostgreSQL** 上跑全量 `go test ./...`，
记录当前 HEAD 的包级覆盖率、Skip 口径与复现命令。

## 1. 口径

- 代码：当前工作树 HEAD（含 2026-10-28 的 19 个 goose 迁移与 seed 数据）。
- 数据库：本机 PostgreSQL（`postgres:17`），库 `laiyipao` 已执行
  `cmd/migrate`（版本 19）与 `cmd/seed`。
- 命令：

  ```bash
  cd laiyipao/server
  export TEST_DATABASE_URL="postgres://postgres@127.0.0.1:5432/laiyipao?sslmode=disable"
  go test ./... -timeout 1200s -count=1 \
    -coverprofile=coverage.out -covermode=atomic
  go tool cover -func=coverage.out | tail -1
  ```

- 覆盖率是**一次全包运行的合并 profile**（`-covermode=atomic`），不是各包单独跑
  后取平均。`go test` 输出的包级百分比与 profile 聚合结果逐包一致。

## 3. 与 2026-09-28 旧审计的关系

`docs/laiyipao/audits/coverage-2026-09-28.md` 里的 `domain 100% / httpapi 99.8% /
service 94.5% / store 93.9%` **在当前 HEAD 上不可复现**。本轮不沿用旧数字，也不把
旧文档当作回归基线：

- 旧文档是各包单独跑、且经过逐行豁免后的口径；本轮是**一次全包合并 profile**。
- 2026-10-27 起 `httpapi` 的 e2e 夹具改为认 `TEST_DATABASE_URL`/`DATABASE_URL`，
  74 条原本静默 Skip 的用例才真正执行；本轮 `httpapi 86.0%` 是它们跑过的结果，
  不是旧口径的退步。
- 旧文档的「100%」依赖大量逐行豁免；本轮先给出**未豁免的原始读数**，再决定哪些
  行值得豁免。两者不是同一把尺子。

后续以本文件为 server 的基线；旧文档保留作历史记录，但不再作为「当前覆盖率」引用。

## 4. Skip 口径

全量 `go test ./... -v -count=1` 的 Skip 统计见 §6。判据是：

- **不允许**「连不上数据库 ⇒ 整个 e2e 包 Skip」这种静默降级；`TEST_DATABASE_URL`
  或 `DATABASE_URL` 必须指向已 migrate+seed 的库。
- 允许显式 opt-in 的探针（例如 `TestProbeReplayDump` 需要 `PROBE_*` 环境变量）
  与数据前置不满足的用例 Skip；它们必须在 `-v` 日志里留下 `--- SKIP` 与理由。
- CI 的 Test 步骤带真库；覆盖率门禁**不解析 Skip 数**，所以日志里 Skip 异常上升时
  必须人工复核，不能只看「测试通过」。

## 5. 门禁建议

- 总量 floor：**85%**（当前 85.8%，留 0.8 个点给噪声）。
- 包级 floor（写进审计、暂不单独接线）：`domain ≥95`、`auth/config ≥90`、
  `seeder ≥91`、`store ≥89`、`service/httpapi ≥86`。
- 覆盖率产物（`coverage.out`）只作 CI 运行期临时文件，不入库；`laiyipao/server/.gitignore`
  已逐项拦住 `coverage.out` / `coverage-go` / `coverage-go.out`。
