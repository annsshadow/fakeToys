# 子项目系统文档生成

## Summary

为仓库中 6 个子项目各产出一份正式系统说明文档，统一存放于 `docs/systems/`，每份包含系统概述、架构图（Mermaid）、依赖与运行环境、配置说明、构建运行步骤、核心功能/接口说明、故障排查；存在明显数据流转逻辑的项目另附数据流图，另附一个索引 README。

---

## Problem Frame

仓库现有 6 个子项目（cool、csv2sql、watering、oa、storage、train），但各项目几乎无系统文档。storage 仅有 14 行安装说明，oa 的 README 是第三方项目介绍，其余项目仅有源码和配置文件，无任何架构、依赖、运行方式、数据流的正式说明。新成员上手、代码交接、外部审计均需依赖口头解释或逐行读源码，效率低且信息易遗漏。

---

## Requirements

**文档目录与索引**
- [P0] R1. 在 `docs/systems/` 下为每个子项目创建独立文档文件，并生成索引 README，列出所有文档及项目简介。
- [P0] R2. 索引 README 包含各文档的快速导航和项目技术栈速览表。

**统一章节模板**
- [P0] R3. 每个项目文档包含以下章节（按顺序）：系统概述、系统架构（Mermaid 图）、依赖与运行环境、配置说明、构建与运行、核心功能/接口说明、故障排查。Mermaid 架构图为必选项，每个文档必须包含 Mermaid 源码；仅在 Markdown 渲染器不支持 Mermaid 时，才在架构图位置额外附文字描述作为补充，不得以文字描述替代 Mermaid 图。数据流图在项目中存在明显数据流转逻辑时必含——具体触发条件：数据在独立组件之间转换、存储或传输，或通过外部系统（如 OBS、钉钉 API、百度 ERNIE API）进出项目边界时，必须包含数据流图。

**各项目文档内容**
- [P1] R4. cool：说明其为 O2OA 平台 SSO 免登 Token 生成工具，描述 AES/MD5 加解密逻辑、支持的用户身份类型（UserId / 工号 / 手机号 / 邮箱）、输入输出。
- [P1] R5. csv2sql：说明其从华为云 OBS 下载 CSV 并导入 SQLite 内存库，描述依赖的 OBS 凭证、流式读取逻辑、错误处理策略（单条记录失败跳过）。
- [P1] R6. watering：描述其通过钉钉开放 API 发送群消息触发蚂蚁森林浇水的机制，包括配置结构（批次、账号组）、token 管理（缓存+过期刷新）、发送失败处理。描述其数据流（群消息 → 配置加载 → token 获取与缓存 → 钉钉 API 调用 → 蚂蚁森林浇水触发 → 失败重试），并提供 Mermaid 数据流图。
- [P1] R7. oa：描述 O2OA 平台的整体定位（JavaEE 分布式 OA 平台）、本仓库中存在的前端端侧（o2server / o2web）、运行环境要求、启动方式，同时产出**模块级详细说明**：在 R3 模板的"系统架构"章节后插入完整模块索引表（模块名、命名空间、一句话职责），在"配置说明"章节后插入"配置与部署深度指南"章节，包含各配置样例文件（如 `web.json`、`externalDataSources_*.json`）的用途说明、JVM 启动参数详解、多平台启动脚本矩阵及端口与目录结构说明。oa 作为分布式平台，必须包含数据流图，描述模块间的数据流转逻辑。深度边界：模块级职责 + 配置/部署参数，不包含类/方法签名、源码实现细节或逐函数说明。注意：o2android 和 o2ios 端侧源码不在本仓库中，本次文档仅覆盖本仓库实际存在的端侧；若需覆盖移动端，应在规划阶段明确是否引入其他仓库的源码。
- [P1] R8. storage：描述 MinIO 存储服务的安装流程、架构兼容检测（x86_64 / ARM64）、健康检查与自动拉起机制、crontab 配置、防火墙规则。
- [P1] R9. train：描述 NLP 训练数据扩充工具的数据流（输入 JSON → 规则替换 + 百度 ERNIE API 扩充 → 输出增强数据集），标注依赖的外部库和 API 凭证要求，说明失败缓存与断点续传机制。

**文档质量**
- [P0] R11. 所有配置参数、环境变量、文件路径均以示例或占位符形式给出，不包含真实密钥或凭证。
- [P0] R12. 故障排查章节覆盖各项目已知常见问题（构建失败、网络错误、权限不足、服务未启动等）及对应排查步骤。

**规模测量与阈值**
- [P2] R13. 文档编写前，测量每个子项目的实际代码规模（LOC、文件数、圈复杂度），记录于 `docs/systems/scale-measurements.md`。
- [P2] R14. 人工文档阈值：LOC ≤ 5000 且文件数 ≤ 100 的项目采用纯人工模板；超过任一阈值的项目改为拆分子单元文档处理，并在 Key Decisions 中记录决策原因。

**维护与更新**
- [P2] R15. 每个项目文档指定一名维护负责人，负责文档准确性审阅。
- [P2] R16. 文档更新触发条件：项目发生 major refactor、public API 变更、或部署方式变更时，维护负责人在 30 个日历天内完成对应文档更新。
- [P2] R17. 每季度进行一次文档准确性巡检，确认文档内容与当前代码一致。

## Acceptance Examples

- AE1. **Covers R1, R2, R3.** 进入 `docs/systems/`，看到 `README.md` 索引，列出 6 个项目文档及技术栈速览表；打开任一文档（如 `cool.md`），章节顺序符合模板要求，含 Mermaid 架构图。
- AE2. **Covers R4, R5, R6, R7, R8, R9, R11.** 阅读 `cool.md` 时能看到 SSO Token 支持 4 种用户身份类型；阅读 `csv2sql.md` 能看到 OBS 凭证配置方式和单条记录失败跳过策略；阅读 `train.md` 能看到数据流图和断点续传说明；阅读 `watering.md` 能看到 token 缓存与过期刷新机制；阅读 `oa.md` 时能看到覆盖全部 Maven 模块的索引表，以及配置样例文件（如 `web.json`、`externalDataSources_*.json`）的用途说明、JVM 启动参数和多平台启动脚本矩阵；检查各项目文档的配置示例均使用占位符（如 `YOUR_API_KEY`），无真实密钥或凭证残留。
- AE3. **Covers R12.** 打开 `storage.md` 的故障排查章节，能看到服务未启动、架构不兼容、防火墙未开放等常见问题及解决步骤。
- AE4. **Covers R7.** 阅读 `oa.md` 时能看到：O2OA 平台整体定位和本仓库存在的端侧（o2server / o2web）说明；覆盖全部 Maven 模块的索引表（含模块名、命名空间、职责）；配置样例文件（如 `web.json`、`externalDataSources_*.json`）的用途说明；JVM 启动参数详解；多平台启动脚本矩阵（区分 Windows/Linux/macOS/ARM 等）；端口与目录结构说明；分布式平台数据流图。

## Success Criteria

- `docs/systems/README.md` 可导航到全部 6 份项目文档
- 每份文档结构一致，含 Mermaid 架构图
- 存在明显数据流转逻辑的项目含数据流图
- 阅读任意文档即可独立理解该项目的作用、依赖、构建方式、运行方法、常见故障
- 阅读 `oa.md` 即可独立理解 O2OA 的模块全貌（通过索引表定位任意模块）、配置参数含义、JVM 启动要求、多平台启动方式及端口目录结构
- 文档中无真实密钥或凭证残留
- 每个项目文档已由维护负责人审阅，确认内容与当前代码一致
- 维护更新策略已建立，代码重大变更后 30 个日历天内对应文档得到更新

## Scope Boundaries

- 仅覆盖当前仓库中 6 个现有子项目，后续新增子项目不纳入本次范围
- 不做代码重构、注释补充或功能开发，仅基于现有源码编写说明文档
- oa 子项目产出"双视图"详细文档：完整模块索引表 + 配置与部署深度指南，不包含类/方法签名或源码实现
- 不生成自动提取脚本（方案 2 暂不实施）
- 不产出部署架构图或生产环境拓扑图，只关注项目代码级别的架构

---

## Key Decisions

- 以人工阅读源码+统一模板方式生成，而非自动提取：在测量各项目实际代码规模后，若单项目超过阈值（LOC > 5000 或文件数 > 100），则该项目改为拆分子单元文档；未超阈值的项目保持纯人工，保证质量。
- 每个项目独立文档 + 索引 README：便于单独维护和查阅，不需要汇总为单一巨型文档。
- Mermaid 图作为模板必选项：纯文本描述架构和数据流不如可视化直观，Mermaid 维护成本低，且支持代码评审和文档工具渲染。
- oa 采用"模块索引表 + 配置/部署深度章节"双视图：oa 模块数量多（约 60+ Maven 模块）且为第三方平台源码，逐模块写长段落维护成本过高，但纯概述又不够详细；索引表保证完整覆盖和可维护性，配置/部署章节提供实际操作所需的深度。
- oa 文档深度边界止于模块职责和配置参数：不包含类/方法签名、源码实现细节或逐函数说明，避免文档膨胀和版本耦合。

---

## Dependencies / Assumptions

- 各子项目的源码和配置文件在当前仓库中保持稳定，文档编写期间无大规模重构
- 文档工具链（Markdown 渲染器）支持 Mermaid 语法渲染；每个文档必须包含 Mermaid 源码，文字描述仅作为渲染不支持时的补充说明，不得替代 Mermaid 图
- 各项目中硬编码的示例密钥（如 `YOUR_APP_KEY`）已被占位符替换，不视为真实凭证
- 各项目维护负责人已指定，并同意承担文档审阅和更新责任
- 测量步骤（R13）显示所有项目均未超过人工文档阈值，或超阈值项目已改为拆分子单元文档
