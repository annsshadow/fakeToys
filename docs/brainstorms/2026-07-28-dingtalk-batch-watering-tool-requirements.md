# 钉钉工号批量浇水工具

## Summary

构建一个本地/服务端自动化工具，以1个主账号收能量为目标，管理100个钉钉工号通过群消息定时触发蚂蚁森林浇水，支持手动触发，并在浇水完成后自动检测状态、对未完成的批次补漏闭环，解决用户自己的收能量需求。

---

## Problem Frame

蚂蚁森林的能量收益来自好友浇水，但每天手动操作100个钉钉号逐一浇水不现实，且无法保证每个号都浇到、每批都完整执行。用户已有的使用模式是通过钉钉群消息（"1"、"2"）触发固定批次浇水，每批约50人，但这种手动发消息的方式仍然依赖人工记忆和执行，容易遗漏或错过时间窗口。

---

## Requirements

**定时触发浇水**
- R1. 工具支持配置每日定时任务，在指定时间自动在钉钉群里发送"1"、"2"两条消息，触发两批固定名单浇水。
- R2. 定时任务的执行时间可配置，支持多个时间窗口。
- R3. 定时任务支持暂停和恢复，不丢失已有配置。

**手动触发浇水**
- R4. 工具提供手动触发入口，支持立即发送指定批次（"1"或"2"）的浇水消息，不限于定时任务窗口。

**浇水状态检测与补漏**
- R5. 每次浇水触发后，工具定期检测主账号各工号的浇水状态，识别未完成或未成功的批次。
- R6. 对未完成的浇水，工具自动重新发送对应批次的消息进行补漏，补漏次数可配置上限。
- R7. 一轮浇水闭环完成后（定时触发 + 补漏完成），工具记录本次执行结果（成功/失败批次、补漏次数）。

**工号管理**
- R8. 工具支持维护100个工号的列表，每个工号关联其对应的钉钉登录态或发送能力配置。
- R9. 工具支持将100个工号按批次分组（每批约50人），并配置每批对应的触发消息内容（如"1"对应第一批、"2"对应第二批）。

**运行与监控**
- R10. 工具记录每次定时任务的执行日志，包括触发时间、发送批次、补漏次数、最终结果。
- R11. 工具在浇水批次发送失败时记录错误，不中断后续批次执行。
- R12. 工具支持查看当前100个工号的配置列表和分组状态。

---

## Acceptance Examples

- AE1. **Covers R1, R2, R5, R6.** Given 已配置每日9:00和18:00两个定时任务，每批50人，when 到达9:00，工具自动发送"1"触发第一批浇水，随后检测到有8人未浇水，自动补发"1"一次，补漏后全部成功，记录本次执行完成。
- AE2. **Covers R4, R11.** Given 定时任务未到执行时间，when 用户手动触发第二批，工具立即发送"2"对应批次的浇水消息，若发送失败5人，记录错误日志但继续后续流程，不中断。
- AE3. **Covers R3, R7, R10.** Given 用户暂停了18:00的定时任务，when 用户在16:00恢复任务，18:00到达时正常执行，执行完成后日志记录触发时间、批次、补漏次数和最终结果。

---

## Success Criteria

- 定时任务每天自动执行，两批浇水消息在配置时间准确发出
- 每批浇水闭环完成率可达95%以上（含自动补漏）
- 用户可以通过手动触发随时补充浇水，无需等待定时窗口
- 执行日志可追溯，能确认每天每批的执行结果和补漏情况
- 100个工号的配置和分组可通过工具管理，无需手动记录

---

## Scope Boundaries

- 仅解决用户自己的收能量需求，不扩展为多人共用或SaaS化
- 不涉及支付宝直接API调用，浇水仅通过钉钉群消息触发
- 100个工号为固定名单，不做群成员动态增减
- 不做能量收取的自动化，只关注浇水触发和状态闭环
- 不做钉钉账号的批量注册或登录态自动获取

---

## Key Decisions

- 采用定时 + 手动混合模式：日常靠定时任务自动执行，异常或临时需求可通过手动触发补充，避免定时任务 missed 后无兜底。
- 以"发消息触发"为唯一浇水手段：不依赖钉钉开放API直接操作蚂蚁森林，降低平台依赖风险。
- 补漏机制内置于工具：不依赖用户人工检查谁没浇，由工具自动检测和补发。

---

## Dependencies / Assumptions

- 用户已有100个钉钉工号，且每个号已加入目标钉钉群、具备发送消息能力
- 蚂蚁森林的浇水触发机制在工具生命周期内保持稳定（群消息"1"、"2"能稳定触发浇水）
- 100个工号的钉钉登录态由用户自行维护，工具负责批量调用发送能力
- 工具运行环境能稳定访问钉钉服务（网络、登录态有效性等由用户侧保障）
