
## MHI (Modem Host Interface)


本文档提供关MHI 协议的信息
## 概述


MHI 是由 Qualcomm Innovation Center, Inc. 开发的协议。主机处理器使用它来通过高速外设总线或共享内存控制调制解调器设备并与之通信。尽MHI 可以很容易地适配到任何外设总线，但它主要配合基PCIe 的设备使用。MHI 在物理总线之上提供逻辑通道，并允许通过这些逻辑通道中的至少一条来传输调制解调器协议，例如 IP 数据包、调制解调器控制消息和诊断信息。此外，MHI 协议提供数据确认（acknowledgment）特性，并通过一个或多个逻辑通道管理调制解调器的电源状态
## MHI 内部机制


### MMIO


MMIO（Memory mapped IO，内存映IO）由设备硬件中的一组寄存器组成，这些寄存器PCIe 之类的外设总线映射到主机内存空间。MMIO 寄存器空间的主要组成部分如下
MHI 控制寄存器：用于访问 MHI 配置寄存
MHI BHI 寄存器：BHI（Boot Host Interface，引导主机接口）寄存器由主机用于MHI 初始化之前将固件下载到设备
通道门铃（Doorbell）数组：通道门铃（DB）寄存器由主机用于在有待处理工作时通知设备
事件门铃数组：与事件上下文数组相关联，事件门铃（DB）寄存器由主机用于在有新事件可用时通知设备
调试寄存器：设备用来向主机暴露性能、功能性和稳定性等调试信息的一组寄存器和计数器
### 数据结构


MHI 使用的所有数据结构都位于主机系统内存中。设备通过物理接口访问这些数据结构。主机系统内存区域中MHI 数据结构和数据缓冲区已映射给设备
通道上下文数组：所有通道配置组织在通道上下文数据数组中
传输环（Transfer rings）：由主机用于为通道调度工作项。传输环组织为传输描述符（TD）的循环队列
事件上下文数组：所有事件配置组织在事件上下文数据数组中
事件环（Event rings）：由设备用于向主机发送完成和状态转换消
命令上下文数组：所有命令配置组织在命令上下文数据数组中
命令环（Command rings）：由主机用于向设备发MHI 命令。命令环组织为命令描述符（CD）的循环队列
### 通道


MHI 通道是主机与设备之间的逻辑、单向数据管道。MHI 中通道的概念类似于 USB 中的端点。MHI 最多支256 个通道。不过，具体的设备实现支持的通道数可能少于允许的最大数量
两个各自带有相关传输环的单向通道组成一个双向数据管道，上层协议可用它来传输应用数据包（例如 IP 包、调制解调器控制消息、诊断消息等）。每个通道都关联一个传输环
### 浼犺緭鐜。

主机与设备之间的传输由通道组织，并由传输描述符（TD）定义。TD 通过传输环管理，传输环为每个设备与主机之间的通道定义，并驻留在主```
        [Read Pointer (RP)] ----------->[Ring Element] } TD
        [Write Pointer (WP)]-           [Ring Element]
                             -          [Ring Element]
                              --------->[Ring Element]
                                        [Ring Element]

```
以下是传输环的基本用法：

- 主机为传输环分配内存- 主机在相应的通道上下文中设置基指针、读指针和写指针- RP == WP 时，环被视为空- WP + 1 == RP 时，环被视为满- RP 指向设备将要处理的下一个元素- 当主机有新的缓冲区要发送时，它用缓冲区信息更新环元素，WP 递增到下一个元素，并拉响相应通道DB（门铃）
### 事件

设备到主机的事件组织在事件环中，由事件描述符（ED）定义。事件环由设备用于向主机报告事件，例如数据传输完成状态、命令完成状态以及状态变化。事件环是驻留在主机中的 ED 数组
```
        [Read Pointer (RP)] ----------->[Ring Element] } ED
        [Write Pointer (WP)]-           [Ring Element]
                             -          [Ring Element]
                              --------->[Ring Element]
                                        [Ring Element]

```
以下是事件环的基本用法：

- 主机为事件环分配内存- 主机在相应的通道上下文中设置基指针、读指针和写指针- 主机和设备都各自持有一RP、WP 的本地副本- WP + 1 == RP 时，环被视为空（没有待处理事件）- RP == WP 时，环被视为充满事件- 当设备有需要发送的新事件时，设备更RP 所指向ED，将 RP 递增到下一个元素，并触发中断
### 环元

环元素是一种用于在主机与设备之间传输单个数据块的数据结构。传输环元素类型包含一个缓冲区指针、缓冲区大小以及额外的控制信息。其他环元素类型可能只包含控制和状态信息。对于单缓冲区操作，一个环描述符由单个元素组成。对于大型多缓冲区操作（例如分散-聚集，scatter and gather），可以将元素链接起来形成更长的描述符
## MHI 操作


### MHI 状

#### MHI_STATE_RESET

上电或硬件复位后，MHI 处于复位状态。此时不允许主机访问设备 MMIO 寄存器空间
#### MHI_STATE_READY

MHI 已准备好进行初始化。主机可以通过MMIO 寄存器编程来开MHI 初始化
#### MHI_STATE_M0

MHI 在设备中运行且可操作。主机可以通过发出通道启动命令来启动通道
#### MHI_STATE_M1

MHI 操作被设备挂起。当设备在预设时间内检测到物理接口上无活动时进入此状态
#### MHI_STATE_M2

MHI 处于低功耗状态。MHI 操作被挂起，设备可能进入更低的功耗模式
#### MHI_STATE_M3

MHI 操作被主机停止。当主机挂起 MHI 操作时进入此状态
### MHI 初始

系统启动后，设备通过物理接口被枚举。在 PCIe 情况下，设备被枚举，并为MMIO 寄存器空间分BAR-0。要在设备中初始MHI，主机执行以下操作：

- 为事件、通道和命令数组分MHI 上下文- 初始化上下文数组，并准备中断- 等待设备进入 READY 状态- MHI MMIO 寄存器编程，并将设备设为 MHI_M0 状态- 等待设备进入 M0 状态
### MHI 数据传输


MHI 数据传输由主机发起，以将数据传给设备。以下是主机为向设备传输数据而执行的操作序列
- 主机用缓冲区信息准备 TD- 主机递增相应通道传输环的 WP- 主机拉响通道 DB 寄存器- 设备唤醒以处TD- 设备通过更新 ED 为已处理TD 生成完成事件- 设备递增相应事件环的 RP- 设备触发 IRQ 以唤醒主机- 主机唤醒并检查事件环以寻找完成事件- 主机更新相应事件环的 WP，以表明数据传输已成功完成
