## Linux LZO 解压器所理解的 LZO 流格式


## 简介


  这不是一份规范。LZO 流格式似乎没有公开的规范可用。本文档描述了 Linux 内核中实现的
  LZO 解压器所能理解的输入格式。本次分析的对象文件是 lib/lzo/lzo1x_decompress_safe.c。
  没有对压缩器或任何其他实现做过分析，不过该格式似乎与标准格式一致。本文档的目的是
  为了更好地理解代码在做什么，以便为将来的缺陷报告提出更高效的修复。

## 描述


  该流由一系列指令、操作数和数据组成。指令由代表操作码（opcode）的少数几位，以及
  构成该指令操作数的若干位组成，操作数的大小和位置取决于操作码以及上一条指令复制的
  字面量（literal）数量。操作数用于指示：

    - 从字典（过去的输出缓冲区）复制数据时的距离
    - 一个长度（从字典复制的字节数）
    - 要复制的字面量数量，它作为供后续指令使用的信息保存在 "state" 变量中。

  根据操作码和操作数的不同，可能还会跟随额外的数据。这些额外数据可以是操作数的补充
  （例如编码在更大数值上的长度或距离），或者是要复制到输出缓冲区的字面量。

  块的首字节与其他字节采用不同的编码，它似乎只针对字面量使用做了优化，因为在该字节
  之前还没有字典。

  长度总是以可变大小编码，从操作数中少量的位开始。如果位数不足以表示长度，则最多可
  通过消耗更多字节以每次最多 255 的增量添加最多 255（因此压缩比不能超过
```

       length = byte & ((1 << #bits) - 1)
       if (!length) {
               length = ((1 << #bits) - 1)
               length += 255*(number of zero bytes)
               length += first-non-zero-byte
       }
       length += constant (generally 2 or 3)

  对于字典的引用，距离是相对于输出指针的。距离使用属于某些范围的极少几位进行编码，
  从而产生使用不同编码的多个复制指令。某些编码涉及一个额外字节，另一些涉及两个形成
  小端 16 位量（在下面标记为 LE16）的额外字节。

  在除大字面量复制之外的任何指令之后，在开始下一条指令之前会复制 0、1、2 或 3 个字面量。
  所复制字面量的数量可能会改变下一条指令的含义和行为。实际上，只有一条指令需要知道
  复制的是 0 个、少于 4 个，还是更多字面量。这就是该实现中保存在 <state> 变量里的信息。
  待复制的立即字面量数量通常编码在指令的最后两位中，但也可能取自某个额外操作数（例如
  距离）的最后两位。

  当看到距离为 0 的块复制时，即宣告流结束。只有一条指令可以编码这个距离（0001HLLL），
  它使用一个 LE16 操作数作为距离，因此需要 3 个字节。

  .. important::

     在代码中缺少某些长度检查，因为某些指令是在"其后跟随了一定数量的字节"这一假设下
     被调用的，而这已在解析指令之前得到了保证。它们只需在消耗额外字节时"补充"这笔
     信用。这是一个与算法或编码无关的实现设计选择。

```
版本

0：原始版本
1：LZO-RLE

LZO 的第 1 版实现了一个扩展，使用游程编码（run length encoding）来编码连续的零。
这对于包含大量零的数据（这是 zram 的常见情况）提升了速度。它以向后兼容的方式修改了
比特流（v1 可以正确解压 v0 压缩的数据，但 v0 无法读取 v1 的数据）。

为了最大兼容性，两个版本以不同的名称提供（lzo 和 lzo-rle）。编码上的差异在本文档中以
例如：version 1 only 标出。

## 字节序列


```

      0..16   : 遵循常规指令编码，见下文。值得注意的是，代码 16 将表示一次来自
                空字典的块复制，在这个位置它始终是无效的。

      17      : 比特流版本。如果首字节是 17，且压缩流长度至少为 5 字节（最短可能的
                带版本比特流的长度），则下一字节给出比特流版本（仅 version 1）。
                否则，比特流版本为 0。

      18..21  : 复制 0..3 个字面量
                state = (byte - 17) = 0..3  [ 复制 <state> 个字面量 ]
                跳过该字节

      22..255 : 复制字面量字符串
                length = (byte - 17) = 4..238
                state = 4 [ 不复制额外字面量 ]
                跳过该字节

  指令编码::

      0 0 0 0 X X X X  (0..15)
        取决于上一条指令复制的字面量数量。
        如果上一条指令没有复制任何字面量（state == 0），该编码将是 4 个或更多字面量的
        复制，必须按如下方式解释：

           0 0 0 0 L L L L  (0..15)  : 复制长字面量字符串
           length = 3 + (L ?: 15 + (zero_bytes * 255) + non_zero_byte)
           state = 4  (不复制额外字面量)

        如果上一条指令用于复制 1 到 3 个字面量（编码在指令的操作码或距离中），则该
        指令是从 1kB 距离内字典中复制一个 2 字节块。值得注意的是，该指令节省很少，因为
        它用 2 个字节来编码另外 2 个字节的复制，但它免费编码了随后字面量的数量。必须
        按如下方式解释：

           0 0 0 0 D D S S  (0..15)  : 从 <= 1kB 距离复制 2 字节
           length = 2
           state = S (在此块之后复制 S 个字面量)
         总是恰好后跟一个字节：H H H H H H H H
           distance = (H << 2) + D + 1

        如果上一条指令用于复制 4 个或更多字面量（如 state == 4 所检测），该指令变成从
        2..3kB 距离字典中复制一个 3 字节块，必须按如下方式解释：

           0 0 0 0 D D S S  (0..15)  : 从 2..3 kB 距离复制 3 字节
           length = 3
           state = S (在此块之后复制 S 个字面量)
         总是恰好后跟一个字节：H H H H H H H H
           distance = (H << 2) + D + 2049

      0 0 0 1 H L L L  (16..31)
           从 16..48kB 距离复制块（最好小于 10B）
           length = 2 + (L ?: 7 + (zero_bytes * 255) + non_zero_byte)
        总是恰好后跟一个 LE16：D D D D D D D D : D D D D D D S S
           distance = 16384 + (H << 14) + D
           state = S (在此块之后复制 S 个字面量)
           如果 distance == 16384 则到达流结束
           仅在 version 1 中，为防止在 RLE 情况下出现歧义，当
           ((distance & 0x803f) == 0x803f) && (261 <= length <= 264) 时，压缩器
           不得发出距离和长度满足这些条件的块复制。

        仅在 version 1 中，如果 distance = 0xbfff（即 H = 1 且 D 位全为 1），该指令
           也用于编码连续的零。在这种情况下，它后跟第四个字节 X。
           run length = ((X << 3) | (0 0 0 0 0 L L L)) + 4

      0 0 1 L L L L L  (32..63)
           从 16kB 距离内复制小块（最好小于 34B）
           length = 2 + (L ?: 31 + (zero_bytes * 255) + non_zero_byte)
        总是恰好后跟一个 LE16：D D D D D D D D : D D D D D D S S
           distance = D + 1
           state = S (在此块之后复制 S 个字面量)

      0 1 L D D D S S  (64..127)
           从 2kB 距离内块复制 3-4 字节
           state = S (在此块之后复制 S 个字面量)
           length = 3 + L
         总是恰好后跟一个字节：H H H H H H H H
           distance = (H << 3) + D + 1

      1 L L D D D S S  (128..255)
           从 2kB 距离内块复制 5-8 字节
           state = S (在此块之后复制 S 个字面量)
           length = 5 + L
         总是恰好后跟一个字节：H H H H H H H H
           distance = (H << 3) + D + 1

```
