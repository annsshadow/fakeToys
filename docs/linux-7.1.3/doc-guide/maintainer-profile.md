
## 文档子系统维护者条目档案


文档“子系统”是内核文档及其相关基础设施的中央协调点。它涵盖 Documentation/（Documentation/devicetree 除外）下的层级结构、scripts/ 下的各种工具，以及至少部分 LICENSES/ 目录。

不过值得注意的是，该子系统的边界比其他子系统更加模糊。许多其他子系统的维护者喜欢保留对 Documentation/ 部分内容的控制权，并且更多时候会在方便时自由地对其应用修改。除此之外，内核的大量文档以 kerneldoc 注释的形式存在于源码中；这些文档通常由相关子系统的维护者维护（但不总是如此）。

文档的邮件列表是 linux-doc@vger.kernel.org。补丁应当尽可能基于 docs-next 树制作。

### 提交检查清单补充


在修改文档时，你应当实际构建文档并确保没有引入新的错误或警告。生成 HTML 文档并查看结果有助于避免因渲染方式而产生不美观的误解。

所有新文档（包括对现有文档的补充）理想情况下都应当在变更日志中的某处说明其预期目标读者是谁；这样我们就能确保文档最终出现在正确的位置。一些可能的类别包括：内核开发者（专家或初学者）、用户空间程序员、最终用户和/或系统管理员，以及发行版。

### 关键周期日期


补丁可以随时发送，但在合并窗口（merge window）期间响应会比平时慢。文档树往往会在合并窗口开启前较晚关闭，因为文档补丁带来回归的风险较低。

### 审查节奏


我是文档子系统唯一的维护者，并且是在我自己的时间做这项工作，因此对补丁的响应偶尔会比较慢。当一个补丁被合并时（或者当我决定某个补丁不能被合并时），我都会尽量发出通知。如果你在发送补丁后一周内没有收到回复，请不要犹豫地发一个 ping 提醒。
