## QNX6 文件系统


qnx6fs 用于较新QNX 操作系统版本（例Neutrino）。它QNX 6.4.0 中引入，并从 6.4.1 起作为默认文件系统
## 选项（Option

mmi_fs		以例如奥MMI 3G 系统所使用的文件系统方式挂
## 规范（Specification

qnx6fs 与传Unix 文件系统有许多共同特性。它具有块、inode 和目录的概念
QNX 上可以创建小端（little endian）和大端（big endian）的 qnx6 文件系统。该特性使得可以为运行在不同字节序平台上的目标（QNX 用于相当广泛的嵌入式系统）创建和使用不同字节序的文件系统
Linux 驱动透明地处理字节序（LE BE）
### 块（Blocks

设备或文件中的空间被分割为块。这些块的大小固定为 512024048 4096，在创建文件系统时决定
块指针为 32 位，因此可寻址的最大空间为 2^32 * 4096 字节，即 16TB
### 超级块（The superblocks

超级块包含文件系统的所有全局信息。每qnx6fs 有两个超级块，每个都有一64 位序列号。该序列号用于标识“活动”的超级块。在写模式下，每次生成新快照（在每次同步写之后），新主超级块的序列号会递增（旧超级块序列号 + 1）
因此，快照功能基本上是通过对序列号进行原子的最终更新来实现的。在更新该序列号之前，所有修改都是通过在该特定写请求（或周期）期间复制所有被修改的块，并在非活动超级块下构建一个新的（稳定的）文件系统结构来完成的
每个超级块为文件系统的不同部分保存一组根 inode（Inode、Bitmap Longfilenames）。这些根节点中的每一个都保存着诸如所存储数据的总大小和该特定树中的寻址级别等信息。如果级别值为 0，则每个节点最多可以寻址 16 个直接块
级别 1 增加了一个额外的间接寻址级别，其中每个间接寻址块最多可容纳 blocksize / 4 字节的数据块指针。级2 又增加了一个额外的间接寻址块级别（因此，这样一棵树最多可寻址 16 ** 256 ** 256 = 1048576 个块）
未使用的块指针始终设~0——无论是根节点、间接寻址块还inode
数据叶子始终位于最低级别。因此，上层树级别上不存储任何数据
第一个超级块位于 0x2000。（0x2000 是启动块的大小）奥迪 MMI 3G 的第一个超级块直接从字0 开始
第二个超级块的位置既可以从超级块信息（文件系统块的总数）计算，也可以取最高设备地址，将最3 字节清零，然后减0x1000 得到
0x1000 是为每个超级块保留的大小——与文件系统的块大小无关
### Inode


文件系统中的每个对象都由一inode（索引节点）表示。inode 结构包含指向文件系统中包含该对象数据的块的指针，以及除长文件名外关于该对象的所有元数据（长27 字符的文件名）。关于一个对象的元数据包括权限、所有者、组、标志、大小、使用的块数、访问时间、更改时间和修改时间
对象模式字段POSIX 格式（这使得事情更简单）
如果对象数据可以16 个直接块寻址，还有指向前 16 个块的指针
对于超过 16 个块的情况，使用另一种形式的树进行间接寻址（方案与超级块根节点所用的相同）
文件大小64 位存储。inode 计数1 开始（而长文件inode 0 开始）
### 目录（Directories

目录是一个文件系统对象，并且像文件一样拥有一inode。它是一种特殊格式的文件，包含将每个名称inode 号关联的记录
'.' inode 号指向该目录自身inode
'..' inode 号指向父目录inode
每个文件名记录还额外有一个文件名长度字段
一个特殊情况是长文件名或子目录名
它们在相应的目录记录中设置了文件名长度字段为 0xff，同时该记录中还存储了长文件inode 号
借助该长文件inode 号，可以从超级块的长文件名根节点指针开始遍历长文件名树
### 特殊文件（Special files

符号链接也是具有 inode 的文件系统对象。它们在 inode 模式字段中有一个特定位将其标识为符号链接
目录项中的文inode 指针指向目标文件inode
硬链接有一inode、一个目录项，但设置了特定模式位，没有块指针，且目录文件记录指向目标文件inode
字符设备和块特殊设备QNX 中不存在，因为那些文件由 QNX 内核/驱动处理，并/dev 下独立于底层文件系统创建
### 长文件名（Long filenames

长文件名存储在一个独立的寻址树中。起始点是活动超级块中的长文件名根节点
每个数据块（树叶子）保存一个长文件名。该文件名限制为 510 字节。开头的两个字节用作实际文件名的长度字段
如果这种结构要适用于所有允许的块大小，就清楚了为什么实际存储的文件名有 510 字节的限制
### 位图（Bitmap

qnx6fs 文件系统的分配位图存储在超级块中位图根节点下的树中，位图中的每个位代表一个文件系统块
第一个块是块 0，它从超级块起始之后 0x1000 处开始。因此对于正常的 qnx6fsx3000（启动块 + 超级块）是块 0 所在的物理地址
如果设备小于位图中的寻址空间，则最后一个位图块末尾的位被设1
### 位图系统区域（Bitmap system area

位图本身分为三个部分
首先是系统区域，它被分成两半
然后是用户空间
对静态、固定的预分配系统区域的要求来源qnx6fs 处理写操作的方式
每个超级块拥有其自己一半的系统区域。因此超级块 #1 始终使用较低一半的块，而超级块 #2 只写入由较高一半位图系统区域位表示的块
这两个树结构（系统区域）的位图块、inode 块和间接寻址块都被视为系统块
其背后的原理是，一个写请求可以在新快照（非活动——即序列号较低的超级块的系统区域）上工作，而同时另一半系统区域中仍然存在一个完整的稳定文件系统结构
当写操作完成（同步写完成、达到最大同步间隔或请求文件系统同步）后，先前非活动超级块的序列号被原子地递增，文件系统切换到那个——然后被声明为稳定的——超级块
对于系统区域之外的所有数据，在写入时只是被复制
