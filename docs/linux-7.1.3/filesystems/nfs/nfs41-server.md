## NFSv4.1 服务器实现

下文先说明 4.1 服务器（基于 RFC 5661）的启用方式与会话、布局、状态管理等核心机制，随后以操作表列出各 NFSv4.1 操作的实现状态与可选特性（pNFS、Delegation 等），便于对照 RFC 核查内核支持范围。



对 minorversion 1 的服务器支持可以使用 /proc/fs/nfsd/versions 控制文件来控制。读取该文件返回的字符串输出将相应地包含"+4.1"或"-4.1"。

目前，对 minorversion 1 的服务器支持默认启用。可以通过向 /proc/fs/nfsd/versions 控制文件写入字符串"-4.1"在运行时禁用它。请注意，要写入此控制文件，必须先停止 nfsd 服务。你可以为此使用 rpc.nfsd；参见 rpc.nfsd(8)。

（警告：较旧的服务器会将"+4.1"和"-4.1"分别解释为"+4"和"-4"。因此，旨在同时适用于新旧内核的代码，必须在开启或关闭版本 4 支持**之前**，先开启或关闭 4.1；rpc.nfsd 会正确地执行此操作。）

nfsd 中的 NFSv4 minorversion 1（NFSv4.1）实现基于 RFC 5661。

在 NFSv4.1 的众多新特性中，当前实现侧重于必须实现的 NFSv4.1 Sessions，提供"exactly 一旦"（恰好一次）语义，以及对为每个客户端分配的资源更好的控制和节流。

下表取自 NFSv4.1 文档，列出了在 次要 版本 1 中必须实现（REQ）、可选（OPT），以及要求不实现的 NFSv4.0 操作（MNI）。第一列指示了 linux 服务器实现尚不支持的操作。

所标识的可选特性及其缩写如下：

- **pNFS**	并行 NFS（并行 NFS）
- **FDELG**	文件 Delegations（文件委派）
- **DDELG**	Directory Delegations（目录委派）

以下缩写表示 linux 服务器实现的状态。

- **I**	已实现的 NFSv4.1 操作。
- **NS**	不支持（不 受支持）。
- **NS\***	未实现的 可选 特性。

## 实现说明：


SSV:
  规范声称这是强制的，但我们实际上并不知道有任何实现，因此暂时忽略它。服务器在 EXCHANGE_ID 上返回 NFS4ERR_ENCR_ALG_UNSUPP，这应该具有前瞻性（future-proof）。

GSS 在 the backchannel（后向通道上的 GSS）:
  同样，理论上是要求的，但未被广泛实现（特别是，当前的 Linux 客户端不会请求它）。我们在 创建_会话 上返回 NFS4ERR_ENCR_ALG_UNSUPP。

DELEGPURGE:
  仅对支持 CLAIM_DELEGATE_PREV 和/或 CLAIM_DELEG_PREV_FH（允许客户端保留跨客户端重启持续的委派）的服务器是强制的。因此我们现在无需实现它。

EXCHANGE_ID:
  实现 id 被忽略

创建_会话:
  后向通道属性被忽略

SEQUENCE:
  不支持动态槽表重协商（可选）

非标准 compound 限制：
  不支持同时需要 ca_maxrequestsize 请求和 ca_maxresponsesize 回复的 sessions fore channel RPC compound，因此我们可能无法兑现我们在 创建_会话 fore channel 协商中所做的承诺。

另请参见 http://wiki.linux-nfs.org/wiki/index.php/Server_4.0_and_4.1_issues。
