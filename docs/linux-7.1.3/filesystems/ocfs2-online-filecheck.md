
## OCFS2 文件系统 - 在线文件检查


本文档描述 OCFS2 在线文件检查特性。

## 简介


OCFS2 常用于高可用系统。然而，OCFS2 在遇到错误时通常会将文件系统转换为只读。这可能
并不必要，因为将文件系统设为只读也会影响其他正在运行的进程，降低可用性。
于是引入了挂载选项（errors=continue），它会向调用进程返回 -EIO 错误码并终止进一步
处理，从而避免文件系统被进一步损坏。文件系统不会被转换为只读，有问题的文件 inode
号会被报告到内核日志。用户可以尝试通过在线文件检查特性来检查/修复该文件。

## 范围


这项工作的目标是检查/修复可能通过将文件系统设为只读而影响集群文件系统日常运行的小问题。
检查/修复的范围是文件级别，最初针对普通文件，最终覆盖文件系统的所有文件（包括系统文件）。

如果目录到文件的链接不正确，该目录 inode 会被报告为有误。

该特性不适合涉及文件系统其他组件依赖关系的过度检查，例如（但不限于）检查文件块的比特位
是否已在分配中设置。如果出现此类错误，建议（或应）使用离线的 fsck。

最后，此类操作/特性不应被自动化，以免文件系统受到比修复尝试前更多的损坏。因此，它必须
在用户交互与同意下执行。

## 用户接口


当 OCFS2 文件系统中出现错误时，通常伴有导致该错误的 inode 号。该 inode 号将作为检查/修复
文件的输入。

```

  /sys/fs/ocfs2/<devname>/filecheck

```
这里，<devname> 表示已挂载的 OCFS2 卷设备名称。上面的文件将接受 inode 号。这可用于
与内核空间通信，告知将检查或修复哪个文件（inode 号）。目前支持三种操作，包括检查 inode、
修复 inode 以及设置结果记录历史的大小。

```

    # echo "<inode>" > /sys/fs/ocfs2/<devname>/filecheck/check
    # cat /sys/fs/ocfs2/<devname>/filecheck/check

   输出类似于::

    INO		DONE	ERROR
    39502		1	GENERATION

   <INO> 列出 inode 号。
   <DONE> 指示操作是否已完成。
   <ERROR> 说明发现了何种错误。详细的错误号请参考文件 linux/fs/ocfs2/filecheck.h。

```
```

    # echo "<inode>" > /sys/fs/ocfs2/<devname>/filecheck/fix
    # cat /sys/fs/ocfs2/<devname>/filecheck/fix

   输出类似于::

    INO		DONE	ERROR
    39502		1	SUCCESS

   这一次，<ERROR> 列指示此次修复是否成功。

```
3. 记录缓存用于存储检查/修复结果的历史。其默认大小为 10，可在 10 ~ 100 范围内调整。
   你可以通过
```

    # echo "<size>" > /sys/fs/ocfs2/<devname>/filecheck/set

```
## 修复内容


收到 inode 后，文件系统将读取 inode 与文件元数据。如果出现错误，文件系统将修复错误并在
内核日志中报告所修复的问题。作为预防措施，在执行最终修复之前，必须先检查 inode 是否有
错误。

inode 与结果历史会临时保存在一个小的链表缓冲区中，其中包含最后（N）个被修复/检查的
inode，所修复/检查的详细错误会打印在内核日志中。
