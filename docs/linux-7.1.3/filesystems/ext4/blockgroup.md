
### 块组

#### 布局

标准块组的布局大致如下（这些字段中的每一个都在下面的单独小节中讨论）：

   :widths: 1 1 1 1 1 1 1 1
   :header-rows: 1

   - - Group 0 填充区
     - ext4 超级块
     - 组描述符
     - 保留的 GDT 块
     - 数据块位图
     - inode 位图
     - inode 表
     - 数据块
   - - 1024 字节
     - 1 个块
     - 多个块
     - 多个块
     - 1 个块
     - 1 个块
     - 多个块
     - 更多个块

对于块组 0 这一特殊情况，前 1024 字节是未使用的，以便安装 x86 引导扇区和其他
特殊内容。超级块将从偏移量 1024 字节处开始，无论它恰好位于哪个块（通常是块 0）。
但是，如果出于某种原因块大小 = 1024，那么块 0 会被标记为已使用，超级块则位于
块 1 中。对于所有其他块组，没有填充区。

ext4 驱动主要使用位于块组 0 中的超级块和组描述符。超级块和组描述符的冗余副本
会被写入磁盘上的一些块组中，以防磁盘开头被损坏，不过并非所有块组都必定承载
冗余副本（详见下一段）。如果该组没有冗余副本，则块组以数据块位图开始。还要
注意，当文件系统刚刚被格式化时，mkfs 会在块组描述符之后、块位图开始之前分配
"保留 GDT 块"空间，以便文件系统将来扩展。默认情况下，文件系统允许在原始大小
基础上增大 1024 倍。

inode 表的位置由 `grp.bg_inode_table_*` 给出。它是一段连续的块范围，足够容纳
`sb.s_inodes_per_group * sb.s_inode_size` 字节。

至于块组内各项的排列顺序，通常的约定是：如果存在超级块和组描述符表，它们将
位于块组的开头。位图和 inode 表可以位于任意位置，位图完全可能在 inode 表之后，
或者两者都在不同的组中（flex_bg）。剩余空间用于文件数据块、间接块映射、extent
树块以及扩展属性。

#### 灵活块组

从 ext4 开始，新增了一个称为灵活块组（flex_bg）的特性。在 flex_bg 中，若干个块组
被绑定为一个逻辑块组；flex_bg 中第一个块组的位图空间和 inode 表空间会被扩展，以
包含 flex_bg 中所有其他块组的位图和 inode 表。例如，如果 flex_bg 大小为 4，那么
组 0 将（按顺序）包含超级块、组描述符、组 0-3 的数据块位图、组 0-3 的 inode 位图、
组 0-3 的 inode 表，组 0 中的剩余空间用于文件数据。这样做的效果是将块组元数据
聚集在一起以加快加载速度，并使大文件在磁盘上保持连续。超级块和组描述符的备份副本
始终位于块组的开头，即使启用了 flex_bg 也是如此。构成一个 flex_bg 的块组数量由
2 ^ `sb.s_log_groups_per_flex` 给出。

#### 元块组

在没有 META_BG 选项的情况下，出于安全考虑，所有块组描述符副本都保存在第一个块组
中。给定默认的 128MiB（2^27 字节）块组大小和 64 字节的组描述符，ext4 最多可以有
2^27/64 = 2^21 个块组。这将整个文件系统的大小限制为 2^21 * 2^27 = 2^48 字节，即
256TiB。

该问题的解决方案是使用元块组特性（META_BG），该特性在所有 2.6 版本的 ext3 中
已经存在。借助 META_BG 特性，ext4 文件系统被划分为许多元块组。每个元块组是一个
块组的簇，其组描述符结构可以存储在一个磁盘块中。对于块大小为 4 KB 的 ext4 文件系统，
单个元块组分区包含 64 个块组，即 8 GiB 的磁盘空间。元块组特性将组描述符的位置从
整个文件系统拥挤的第一个块组，移动到每个元块组自身的第一个组中。备份位于每个
元块组的第二个和最后一个组中。这将 2^21 的最大块组上限提升到了硬上限 2^32，从而
支持 512PiB 的文件系统。

文件系统格式的变更，替换了当前"超级块后面跟着可变长度的块组描述符集合"的方案。
取而代之的是，将超级块和单个块组描述符块放置在元块组的第一个、第二个和最后一个
块组的开头。元块组是一组可以用单个块组描述符块描述的块组。由于块组描述符结构的
大小为 64 字节，因此对于块大小为 1KB 的文件系统，一个元块组包含 16 个块组；对于
块大小为 4KB 的文件系统，包含 64 个块组。文件系统既可以使用这种新的块组描述符
布局来创建，也可以对现有文件系统进行在线调整大小，超级块中的字段 s_first_meta_bg
将指示第一个使用这种新布局的块组。

关于 `BLOCK_UNINIT`，请参阅块和 inode 位图相关章节中的重要说明。

#### 惰性块组初始化

ext4 的一个新特性是三个块组描述符标志，它们使 mkfs 能够跳过初始化块组元数据的
其他部分。具体来说，INODE_UNINIT 和 BLOCK_UNINIT 标志意味着该组的 inode 和块
位图可以被计算出来，因此在磁盘上的位图块不会被初始化。对于空块组或只包含固定位置
块组元数据的块组，通常就是这种情况。INODE_ZEROED 标志意味着 inode 表已经被初始化；
mkfs 会清除该标志，并依赖内核在后台初始化 inode 表。

通过不向位图和 inode 表写入零，mkfs 的时间显著缩短。注意，该特性标志是
RO_COMPAT_GDT_CSUM，但 dumpe2fs 的输出将其打印为 "uninit_bg"。它们是同一回事。
