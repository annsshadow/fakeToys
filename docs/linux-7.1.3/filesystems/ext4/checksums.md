
### 校验和（Checksums）


从 2012 年初开始，所有主要的 ext4 和 jbd2 数据结构都加入了元数据校验和。相关的特性标志是 metadata_csum。期望的校验和算法在超级块（superblock）中指明，不过截至 2012 年 10 月，唯一受支持的算法是 crc32c。某些数据结构没有足够空间容纳完整的 32 位校验和，因此只存储了低 16 位。启用 64bit 特性会增加数据结构的大小，从而可以为许多数据结构存储完整的 32 位校验和。然而，现有的 32 位文件系统无法被扩展以启用 64bit 模式，至少在不使用实验性的 resize2fs 补丁的情况下不行。

可以在现有文件系统上通过针对底层设备运行 `tune2fs -O metadata_csum` 来添加校验和。如果 tune2fs 遇到缺少足够空闲空间以添加校验和的目录块，它会要求你运行 `e2fsck -D` 来用带校验和的方式重建目录。这还附带一个好处，即移除目录文件中的空闲空间并重新平衡 htree 索引。如果你_忽略_这一步，你的目录将不会受到校验和的保护！

下表描述了组成每种校验和的数据元素。除非另有说明，校验和函数就是超级块所描述的那样（截至 2013 年 10 月为 crc32c）。

   :widths: 20 8 50
   :header-rows: 1

   - - 元数据
     - 长度
     - 组成成分
   - - 超级块
     - __le32
     - 整个超级块，直到校验和字段为止。UUID 位于超级块内部。
   - - MMP
     - __le32
     - UUID + 整个 MMP 块，直到校验和字段为止。
   - - 扩展属性
     - __le32
     - UUID + 整个扩展属性块。校验和字段被设为零。
   - - 目录项
     - __le32
     - UUID + inode 号 + inode 生成号 + 目录块，直到包围校验和字段的伪条目为止。
   - - HTREE 节点
     - __le32
     - UUID + inode 号 + inode 生成号 + 所有有效的区段（extent） + HTREE 尾部。
       校验和字段被设为零。
   - - 区段（Extents）
     - __le32
     - UUID + inode 号 + inode 生成号 + 整个区段块，直到校验和字段为止。
   - - 位图
     - __le32 或 __le16
     - UUID + 整个位图。校验和存储在组描述符中，如果组描述符大小为 32 字节（即 ^64bit）则被截断。
   - - Inode
     - __le32
     - UUID + inode 号 + inode 生成号 + 整个 inode。校验和字段被设为零。每个 inode 都有自己的校验和。
   - - 组描述符
     - __le16
     - 如果是 metadata_csum，则为 UUID + 组号 + 整个描述符；
       否则如果是 gdt_csum，则为 crc16(UUID + 组号 + 整个描述符)。在所有情况下，都只存储低 16 位。
