## 文件

如同OS/2 中一样，文件名不区分大小写。然而，shell 认为名字是区分大小写的，
因此例如当你创建一个文FOO 时，你可以使'cat FOO'cat Foo'cat foo'
'cat f**'，但不能使用 'cat f**'。注意，由于内核会创建像 bootsect.S bootsect.s 这样名字不同的文件，你也无法HPFS 上编linux 内核（也许还有其东西）。当搜索名字中包>= 128 字符的文件时，会使用代码页——见下文OS/2 忽略文件名末尾的点和空格，因此本驱动也同样如此。如果你创建 'a. ...'，将创建
文件 'a'，但你仍然可以用 'a.'a..'a .  . . ' 等名字访问它

## 扩展属

HPFS 分区上，OS/2 可以为每个文件关联一种称为扩展属性的特殊信息。扩展属性是
（键，值）对，其中键是标识该属性的 ascii 字符串，值是任意长度的字节串。OS/2 在其存储窗口和图标位置以及文件类型。那么，何不把它用于像文件所有者或访问权限这样unix 专有信息呢？本驱动可以做到。如果你hpfs 分区上执chown/chgrp/chmod，会创建
键为 "UID"GID" "MODE"、值为 2 字节的扩展属性。只会创建那些值与挂载选项中指定的
默认值不同的扩展属性。一旦创建，扩展属性就永远不会被删除，它们只是被修改。这意味着你的默认 uid=0 而你输入类似 'chown luser file; chown root file' 时，该文件将包含扩展
属UID=0。而当你卸载该文件系统并以 uid=luser_uid 重新挂载时，该文件仍将归 root 所有！
如果你把文件 chmod 444，则不会设置扩展属"MODE"，这个特殊情况通过设置只读标志来处理当你 mknod 一个块设备或字符设备时，除"MODE" 之外，还会创建特殊的 4 字节扩展属"DEV"，其中包含设备号。目前本驱动无法调整扩展属性的大小——这意味着如果有人（我不知是谁？）设置了大小不同的 "UID"GID"MODE" "DEV" 属性，它们将不会被重写，修改这值也不会生效

## 符号链接


你可以在 HPFS 分区上创建符号链接，符号链接通过设置一个名"SYMLINK"、值为符号链接目标扩展属性来实现。就像在 ext2 上一样，你可chown chgrp 符号链接，但我不知道这有什么用对符号链接执chmod 会导致对符号链接所指向的文件执chmod。这些符号链接仅Linux 使用OS/2 不兼容。OS/2 PmShell 符号链接不被支持，因为它们以非常古怪的方式存储。它们试做到当文件被移动时链接也随之改变……有时能工作。但该链接部分存储在目录扩展属性中，部分存OS2SYS.INI 中。我既不想（也不知道如何）去分析或修OS2SYS.INI

## 已知缺陷


OS/2 服务器上HPFS386 不受支持。安装在普OS/2 客户端上HPFS386 应当可以工作。如果你OS/2 服务器，请仅使用只读模式。我不知道如何处理某HPFS386 结构，如访问控制列表或扩展权列表，我不知道在文件被删除时如何删除它们，也不知道如何避免用扩展属性覆盖它们。给我发一些关这些结构的信息，我会实现它。不过，本驱动应当能检测到 HPFS386 结构的存在，重新挂载为只读，并且
不破坏它们（我希望如此）
当扩展属性的空间不足时，它们会被截断，且不返回任何错误
OS/2 在路径长度超过约 256 个字符时无法访问文件，但本驱动允许你这样做。chkdsk 忽略此类错误
有时你将无法删除某个非常满的文件系统上的某些文件（返回错ENOSPC）。这是因为目录树中非叶子
节点中的文件（一个目录如果很大，HPFS 中其目录项以树的形式组织）在被删除时必须被另一个节替换。而那个新文件可能拥有比旧文件更长的名字，因此新名字无法放入目录节点（dnode）中。那导致目录树分裂，从而占用磁盘空间。变通办法是删除其他为叶子节点的文件（该文件为非叶子的概率约1/50），或者先截断文件以腾出一些空间只有当拥有许多目录时你才会遇到这个问题，
```

	number_of_directories / size_of_filesystem_in_mb > 4.

```
你不能删除已打开的目录
你不能跨目录重命名（这有什么用？）
仅改变大小写的文件重命名不起作用。本驱动支持它，vfs 不支持。类'mv file FILE' 这样的操不会工作
所atime 和目mtime 都不被更新。这是出于性能原因。如果你极度希望更新它们，告诉我，我会写
（但那会很慢）
当系统内存和交换空间不足时，它可能会轻微损坏文件系统（丢失文件、目录不平衡）。（我猜所有文系统都可能这样）
编译时，你会得到警告：function declaration isn't a prototype（函数声明不是原型）。有人知道这什么意思吗

## “unbalanced tree”（不平衡树）消息是什么意思？


本驱动的早期版本有时会创建不平衡dnode 树。OS/2 chkdsk 在树不平衡时不会尖叫（它有时也会
创建不平衡的:-），HPFS HPFS386 都包含一bug，即当树不平衡时它极少情况下会崩溃。本
驱动正确处理不平衡树，并在发现它们时写下警告。如果你看到这条消息，这很可能是因为用本驱动的早版本创建的目录。变通办法是把该目录中的所有文件移动到另一个目录，然后再移回来。在 Linux 中做而不OS/2！如果你在这个驱动创建的整个目录中看到这条消息，那就BUG——请告诉我

## OS/2 中的缺陷


当你有两个（或更多）互相指向的丢失目录时，chkdsk 在修复文件系统时锁死
有时（我认为是随机的），当你OS/2 下创建单字符名字的文件时，OS/2 把它标记为“长”。chkdsk
随后移除这个标志，说“Minor fs error corrected（修正了轻微fs 错误）”
"a .b" 这样的文件名会被 OS/2 标记为“长”，chkdsk “修正”它并把它们标记为短（并写下
“minor fs error corrected”）。这bug HPFS386 中不存在
