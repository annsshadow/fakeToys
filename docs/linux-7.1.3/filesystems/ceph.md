
## Ceph 分布式文件系统


Ceph 是一个分布式网络文件系统，旨在提供良好的性能、可靠性与可扩展性。

基本特性包括：

 - POSIX 语义
 - 从 1 个节点到数千个节点的无缝扩展
 - 高可用性与可靠性，没有单点故障
 - 数据在存储节点间的 N 路复制
 - 节点故障后的快速恢复
 - 节点增删时数据的自动再均衡
 - 易于部署：绝大多数文件系统组件都是用户空间守护进程

此外还有：

 - 灵活的快照（可在任意目录上创建）
 - 递归统计（嵌套的文件、目录、字节数）

与 GFS、OCFS2、GPFS 这类依赖所有客户端对称访问共享块设备的集群文件系统不同，Ceph 把数据和元数据管理分离为相互独立的服务器集群，这一点与 Lustre 类似。但不同于 Lustre 的是，Ceph 的元数据和存储节点完全以用户空间守护进程的形式运行。文件数据以大块方式条带化分布到各个存储节点，以分散负载并提升吞吐量。当存储节点发生故障时，数据由存储节点自身以分布式方式重新复制（仅需集群监视器做极少量协调），使系统极为高效且可扩展。

元数据服务器实际上在文件命名空间之上构成了一个巨大、一致、分布式的的内存缓存，极具可扩展性，能够随工作负载变化动态重新分布元数据，并可容忍任意（非拜占庭式）节点故障。元数据服务器采用了一种略显另类的元数据存储方法，以显著提升常见工作负载的性能。具体而言，只有一个硬链接的 inode 被内嵌到目录中，从而可用一次 I/O 操作把整个目录的 dentry 和 inode 载入其缓存。超大目录的内容可以被分片并由相互独立的元数据服务器管理，从而支持可扩展的并发访问。

该系统在从只有几个节点的小集群扩展到数百个节点时提供自动的数据再均衡/迁移，无需管理员把数据集切分为静态卷，也无需经历在服务器间迁移数据的繁琐过程。当文件系统接近写满时，可以轻松加入新节点，一切都会“自动就绪”。

Ceph 包含灵活的快照机制，允许用户对系统中任意子目录（及其嵌套内容）创建快照。快照的创建与删除就像 `mkdir .snap/foo` 和 `rmdir .snap/foo` 一样简单。

快照名称有两个限制：

- 不能以 “_”（下划线）开头，因为这些名称保留供 MDS 内部使用。
- 长度不能超过 240 个字符。这是因为 MDS 内部使用长快照名，其格式为：`_<SNAPSHOT-NAME>_<INODE-NUMBER>`。由于一般文件名不能超过 255 个字符，而 `<node-id>` 占用 13 个字符，所以长快照名最多为 255 - 1 - 1 - 13 = 240。

Ceph 还对目录提供针对嵌套文件的递归统计
```

 getfattr -n ceph.dir.rfiles /some/dir
 getfattr -n ceph.dir.rbytes /some/dir

```
分别用于获取嵌套文件的总数及其合计大小。这使得识别占用大量磁盘空间者相对快捷，因为无需执行 `du` 或类似的文件系统递归扫描。

最后，Ceph 还允许在系统中的任意目录上设置配额。配额可以限制该目录层级之下所存储的字节数或文件数。配额可使用如下命令设置
```

 setfattr -n ceph.quota.max_bytes -v 100000000 /some/dir
 getfattr -n ceph.quota.max_bytes /some/dir

```
当前配额实现的一个限制是，它依赖挂载该文件系统的客户端的配合，在达到上限时阻止写入者。一个被篡改或恶意的客户端无法被阻止写入其所需的数据量。

## 挂载语法


```

 # mount -t ceph user@fsid.fs_name=/[subdir] mnt -o mon_addr=monip1[:port][/monip2[:port]]

```
只需指定单个监视器即可，因为客户端在连接时会获取完整列表。（不过，如果你指定的监视器恰好宕机，挂载将不会成功。）如果监视器使用默认端口，端口部分可以省略。因此，若监视器位于
```

 # mount -t ceph cephuser@07fe3187-00d9-42a3-814b-72a4d5e7d5be.cephfs=/ /mnt/ceph -o mon_addr=1.2.3.4

```
就足够了。如果安装了 /sbin/mount.ceph，则可以使用主机名代替 IP 地址，并且集群 FSID 可以省略（因为挂载辅助程序会通过读取 ceph 配置来填充它
```

  # mount -t ceph cephuser@cephfs=/ /mnt/ceph -o mon_addr=mon-addr

```
```

  # mount -t ceph cephuser@cephfs=/ /mnt/ceph -o mon_addr=192.168.1.100/192.168.1.101

```
使用挂载辅助程序时，监视器地址可从 ceph 配置文件读取（如果可用）。注意，集群 FSID（作为设备字符串的一部分传入）会通过与监视器报告的 FSID 比对来进行校验。

## 挂载选项


  mon_addr=ip_address[:port][/ip_address[:port]]
	到集群的监视器地址。用于引导与集群的连接。一旦连接建立，即遵循监视器映射中的监视器地址。

  fsid=cluster-id
	集群的 FSID（来自 `ceph fsid` 命令）。

  ip=A.B.C.D[:N]
	指定客户端应在本地绑定的 IP 和/或端口。通常没有太大必要这样做。如果未指定 IP，客户端的 IP 地址由其到监视器的连接发起地址决定。

  wsize=X
	指定最大写入大小（字节）。默认：64 MB。

  rsize=X
	指定最大读取大小（字节）。默认：64 MB。

  rasize=X
	指定最大预读大小（字节）。默认：8 MB。

  mount_timeout=X
	在非响应 Ceph 文件系统的情况下，指定挂载超时值（秒）。默认 60 秒。

  caps_max=X
	指定可持有 cap 的最大数量。当 cap 数量超过限制时，未使用的 cap 会被释放。默认 0（无限制）

  rbytes
	当对目录调用 stat() 时，把 st_size 设为 'rbytes'，即该目录之下所有嵌套文件大小之和。这是默认行为。

  norbytes
	当对目录调用 stat() 时，把 st_size 设为该目录中的条目数量。

  nocrc
	禁用数据写入的 CRC32C 计算。若设置此项，存储节点必须依赖 TCP 的纠错来检测数据载荷中的损坏。

  dcache
        利用 dcache 内容，在客户端已缓存整个目录内容时执行否定查找（negative lookup）和 readdir。（这不会改变正确性；客户端仅在租约或 capability 确保其有效时才使用缓存的元数据。）

  nodcache
        不按上述方式使用 dcache。这避免了大量复杂代码，牺牲性能但不影响正确性，对排查 bug 很有用。

  noasyncreaddir
	不按上述方式对 readdir 使用 dcache。

  noquotadf
        在 statfs 中报告整体文件系统用量，而不是使用根目录配额。

  nocopyfrom
        不使用 RADOS 的 'copy-from' 操作执行远程对象拷贝。目前它仅用于 copy_file_range，若使用此选项会回退到默认 VFS 实现。

  recover_session=<no|clean>
	在客户端被列入黑名单（blocklisted）的情况下，设置自动重连模式。可用模式为 "no" 和 "clean"。默认 "no"。

 - no：当客户端检测到自己被列入黑名单时，绝不尝试重连。被列入黑名单后，操作通常会失败。

 - clean：客户端在检测到自己被列入黑名单时自动重连到 ceph 集群。重连期间，客户端丢弃脏数据/元数据，并使页缓存和可写文件句柄失效。重连后，文件锁会失效，因为 MDS 失去了对它们的追踪。如果某个 inode 含有任何失效文件锁，在应用程序释放所有失效文件锁之前，不允许对该 inode 进行读/写。
