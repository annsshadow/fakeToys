
## Linux 目录通知


	   Stephen Rothwell <sfr@canb.auug.org.au>

目录通知的目的是在目录或其任意文件发生变化时通知用户应用程序。基本机制是应用程序使用 fcntl(2) 调用在目录上注册通知，而通知本身通过信号递送。

应用程序决定它希望被通知哪些“事件”。目前定义的事件有：

	=========	=====================================================
	DN_ACCESS	目录中的某个文件被访问（读取）
	DN_MODIFY	目录中的某个文件被修改（写入、截断）
	DN_CREATE	目录中创建了某个文件
	DN_DELETE	目录中某个文件被取消链接
	DN_RENAME	目录中的某个文件被重命名
	DN_ATTRIB	目录中的某个文件属性被更改（chmod、chown）
	=========	=====================================================

通常，应用程序必须在每次通知后重新注册，但如果将 DN_MULTISHOT 与事件掩码做“或”运算，则注册将一直保持，直到被显式移除（通过注册无事件）。

默认情况下，SIGIO 会被递送给进程，而没有其他有用信息。然而，如果使用 F_SETSIG fcntl(2) 调用来让内核知道要递送哪个信号，则会向信号处理函数传递一个 siginfo 结构体，该结构体的 si_fd 成员将包含发生事件的目录所对应的文件描述符。

应用程序最好选择实时信号之一（SIGRTMIN + <n>），以便通知可以被排队。如果指定了 DN_MULTISHOT，这一点尤其重要。注意 SIGRTMIN 常常被阻塞，因此最好使用（至少）SIGRTMIN + 1。

### 实现预期（特性与缺陷 :-）)


通知应当对任意对文件的本地访问都有效，即使实际的文件系统位于远程服务器上。这意味着对由本地用户态服务器所服务文件的远程访问也应被通知。同样，对由本地内核 NFS 服务器所服务文件的远程访问也应被通知。

为了使对文件系统代码的影响尽可能小，硬链接到文件的问题被忽略。因此，如果文件（x）存在于两个目录（a 与 b）中，那么使用名称 "a/x" 对文件所做的更改应当通知给期待目录 "a" 通知的程序，但不会被通知给期待目录 "b" 通知的程序。

此外，被取消链接的文件仍会在它们最后链接到的目录中引发通知。

### 配置


Dnotify 通过 CONFIG_DNOTIFY 配置选项控制。当被禁用时，fcntl(fd, F_NOTIFY, ...) 将返回 -EINVAL。
