
## 通用文件系统缓存


## 概述


该设施是一个用于网络文件系统的通用缓存，尽管它也可用于缓存其他内容，例ISO9660 文件系统
FS-Cache 在缓存后端（例如 CacheFiles）与网络
```
	+---------+
	|         |                                    +--------------+
	|   NFS   |--+                                 |              |
	|         |  |                             +-->|   CacheFS    |
	+---------+  |               +----------+  |   |  /dev/hda5   |
	             |               |          |  |   +--------------+
	+---------+  +-------------->|          |  |
	|         |      +-------+   |          |--+
	|   AFS   |----->|       |   | FS-Cache |
	|         |      | netfs |-->|          |--+
	+---------+  +-->|  lib  |   |          |  |
	             |   |       |   |          |  |   +--------------+
	+---------+  |   +-------+   +----------+  |   |              |
	|         |  |                             +-->|  CacheFiles  |
	|   9P    |--+                                 |  /var/cache  |
	|         |                                    +--------------+
	+---------+
```
换一个角度看，FS-Cache 是一个为网络文件系统提供缓存设施的模块，使得缓存在对
```
	+---------+
	|         |
	| Server  |
	|         |
	+---------+
	     |                  NETWORK
	~~~~~|~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
	     |
	     |           +----------+
	     V           |          |
	+---------+      |          |
	|         |      |          |
	|   NFS   |----->| FS-Cache |
	|         |      |          |--+
	+---------+      |          |  |   +--------------+   +--------------+
	     |           |          |  |   |              |   |              |
	     V           +----------+  +-->|  CacheFiles  |-->|  Ext3        |
	+---------+                        |  /var/cache  |   |  /dev/sda6   |
	|         |                        +--------------+   +--------------+
	|   VFS   |                                ^                     ^
	|         |                                |                     |
	+---------+                                +--------------+      |
	     |                  KERNEL SPACE                      |      |
	~~~~~|~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~|~~~~~~|~~~~
	     |                  USER SPACE                        |      |
	     V                                                    |      |
	+---------+                                           +--------------+
	|         |                                           |              |
	| Process |                                           | cachefilesd  |
	|         |                                           |              |
	+---------+                                           +--------------+
```
FS-Cache 并不采用这样的思路：在允许访问某个 netfs 文件之前，先将其完整载入缓存，之后从该缓存而非 netfs inode 提供页面，原因是
 (1) 必须在没有缓存的情况下也能实际运行
 (2) 任何可访问文件的大小都不得受限于缓存的大小
 (3) 所有已打开文件的总大小（包括已映射的库）不得受限于缓存的大小
 (4) 不应强迫用户为一次性访问文件的很小一部分（例如使"file" 程序时所做的那样）而下载整个文件
相反，它在被使用netfs 请求时按需分块提供缓存

FS-Cache 提供以下设施
   - 可同时使用多个缓存。可以通过标签显式地选择缓存
   - 缓存可随时添/ 移除，即使在被访问时也可以
   - netfs 会获得一个接口，允许任一方从某个文件中撤除缓存设施（(2) 所需）
   - 提供netfs 的接口尽可能少地返回错误，而是倾向于让 netfs 保持无感知
   - 共有三类 cookie：cache、volume data file cookie。cache cookie 代表整个缓存，通常netfs 不可见；netfs 会获得一volume cookie 来代表一组文件（通常相当netfs 会为超级块获取的东西）；data file cookie 用于缓存数据（相当于会为 inode 获取的东西）
   - volume 通过 key 进行匹配。这是一个可打印字符串，用于编码区分不同超级块所需的所有信息。它可以是诸如单元名或服务器地址、卷名或共享路径等信息的组合。它必须是一个有效的路径名
   - cookie 通过 key 进行匹配。这是一个二进制 blob，用于表volume 内的对象（因volume key 无需成为blob 的一部分）。它可能包含诸如 inode 号与唯一标识符或文件句柄之类的信息
   - 通过cookie 标记为使用中（in-use）来建立并钉cookie 资源。这可以防止后端资源被回收。采用定时垃圾回收来清除短时间内未被使用cookie，从而减轻资源过载。这旨在在文件打开或关闭时使用
    一cookie 可被同时多次标记为使用中；每次标记都必须被解除
   - 提供begin/end 访问函数，用于在操作期间延迟缓存撤除，并防止在查看结构体时其被释放
   - 数据 I/O 通过异步 DIO 完成，作用于netfs 使用 iov_iter 描述的缓冲区
   - 提供了失效（invalidation）设施，用于丢弃缓存中的数据，并处理正在访问旧数据的进行I/O
   - cookie 在释放时可以被“退役（retired）”，从而导致该对象从缓存中移除

## 缓存列表


FS-Cache 提供一cache cookie 列表
	/proc/fs/fscache/caches

```
	# cat /proc/fs/fscache/caches
	CACHE    REF   VOLS  OBJS  ACCES S NAME
	======== ===== ===== ===== ===== = ===============
	00000001     2     1  2123     1 A default
```
各列含义如下
	=======	===============================================================
	COLUMN	描述
	=======	===============================================================
	CACHE	缓存 cookie 调试 ID（也会出现在 trace 中）
	REF	缓存 cookie 上的引用计数
	VOLS	此缓存中volume cookie 数量
	OBJS	使用中的缓存对象数量
	ACCES	钉住缓存的访问次	S	状	NAME	缓存的名称	=======	===============================================================

状态可以是 (-) Inactive（非活跃）P)reparing（准备中）A)ctive（活跃）E)rror（错误）(W)ithdrawing（撤除中）

## 卷列

FS-Cache 提供一volume cookie 列表
	/proc/fs/fscache/volumes

```
	VOLUME   REF   nCOOK ACC FL CACHE           KEY
	======== ===== ===== === == =============== ================
	00000001    55    54   1 00 default         afs,example.com,100058
```
各列含义如下
	=======	===============================================================
	COLUMN	描述
	=======	===============================================================
	VOLUME	volume cookie 调试 ID（也会出现在 trace 中）
	REF	volume cookie 上的引用计数
	nCOOK	卷中cookie 数量
	ACC	钉住缓存的访问次	FL	volume cookie 上的标志
	CACHE	缓存的名称或	KEY	该卷的索key
	=======	===============================================================

## 调试


如果启用CONFIG_NETFS_DEBUG，则 FS-Cache 设施NETFS 支持可以
```
	/sys/module/netfs/parameters/debug
```
这是一个用于启用调试流的位掩码
	=======	=======	===============================	=======================
				位置
	=======	=======	===============================	=======================
	0	1	缓存管理		函数入口 trace
	1	2					函数出口 trace
	2	4					常规
	3	8	Cookie 管理			函数入口 trace
	4	16					函数出口 trace
	5	32					常规
	6-8						（未使用	9	512	I/O 操作管理			函数入口 trace
	10	1024					函数出口 trace
	11	2048					常规
	=======	=======	===============================	=======================

应把一组合适的值进OR 运算，并将结果写```
	echo $((1|8|512)) >/sys/module/netfs/parameters/debug
```
将开启所有函数入口调试
