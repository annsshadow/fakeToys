
## v9fs: Plan 9 Resource Sharing for Linux


## About


v9fs 是 Plan 9 的 9p 远程文件系统协议的 Unix 实现。

该软件最初由 Ron Minnich <rminnich@sandia.gov> 和 Maya Gokhale 开发。Greg Watson
<gwatson@lanl.gov> 以及最近的 Eric Van Hensbergen <ericvh@gmail.com>、Latchesar Ionkov
<lucho@ionkov.net> 和 Russ Cox <rsc@swtch.com> 进行了额外的开发。

关于 Linux 中 9p 客户端实现及应用的最佳详细说明，以 USENIX 论文形式提供：

   https://www.usenix.org/events/usenix05/tech/freenix/hensbergen.html

其他应用在下列论文中描述：

 - XCPU 与集群
	  http://xcpu.org/papers/xcpu-talk.pdf
 - KVMFS：用于 KVM 的控制文件系统
	  http://xcpu.org/papers/kvmfs.pdf
 - CellFS：面向 Cell BE 的一种新编程模型
	  http://xcpu.org/papers/cellfs-talk.pdf
 - PROSE I/O：使用 9p 实现应用分区
	  http://plan9.escet.urjc.es/iwp9/cready/PROSE_iwp9_2006.pdf
 - VirtFS：一种感知虚拟化的文件系统透传
	  https://kernel.org/doc/ols/2010/ols2010-pages-109-120.pdf

## Usage


```

	mount -t 9p 10.10.1.2 /mnt/9

```
```

	mount -t 9p `namespace`/acme /mnt/9 -o trans=unix,uname=$USER

```
```

	mount -t 9p -o trans=virtio <mount_tag> /mnt/9

```
其中 mount_tag 是服务器为每个导出的挂载点生成的标签。每个 9P 导出在客户端看来是一个
具有关联“mount_tag”属性的 virtio 设备。可用的挂载标签可以通过读取
/sys/bus/virtio/drivers/9pnet_virtio/virtio<n>/mount_tag 文件查看。

## USBG Usage


```

	mount -t 9p -o trans=usbg,aname=/path/to/fs <device> /mnt/9

```
```

	root=<device> rootfstype=9p rootflags=trans=usbg,cache=loose,uname=root,access=0,dfltuid=0,dfltgid=0,aname=/path/to/rootfs

```
其中 <device> 是由 usb gadget 传输关联的标签。它由 configfs 实例名定义。

## USBG Example


USB 主机导出一个文件系统，而 USB 设备侧的 gadget 使其可挂载。

Diod（9pfs 服务器）和转发器（forwarder）位于开发主机上，根文件系统实际存储在那里。gadget
在嵌入式板卡启动期间（或之后）初始化。然后转发器会在 USB 总线上找到它并开始转发请求。

在这种情况下，9p 请求来自设备并由主机处理。原因是 PC 上通常没有可用的 USB 设备端口，因此
反方向的连接将无法工作。

使用 usbg 传输时，目前没有原生的 usb 主机服务能够处理来自 gadget 驱动器的请求。为此，我们
必须使用 tools/usb 下的额外 python 工具 p9_fwd.py。

```

        $ diod -f -n -d 0 -S -l 0.0.0.0:9999 -e $PWD

```
```

        $ python $kernel_dir/tools/usb/p9_fwd.py list

        Bus | Addr | Manufacturer     | Product          | ID        | Path
        --- | ---- | ---------------- | ---------------- | --------- | ----
          2 |   67 | unknown          | unknown          | 1d6b:0109 | 2-1.1.2
          2 |   68 | unknown          | unknown          | 1d6b:0109 | 2-1.1.3

```
```

        $ python $kernel_dir/tools/usb/p9_fwd.py --path 2-1.1.2 connect -p 9999

```
之后，gadget 驱动就可以如上所述使用。

一个用例是在开发嵌入式 Linux 设备时，将其作为 NFS 根启动的替代方案。

## Options


  ============= ===============================================================
  trans=name	选择一种替代传输。当前有效的选项有：

			========  ============================================
			unix 	 指定一个命名管道挂载点
			tcp	 指定一个普通的 TCP/IP 连接
			fd   	 用于已传入的文件描述符进行连接
                                  （见 rfdno 和 wfdno）
			virtio	 连接到下一个可用的 virtio 通道
				  （来自启用了 trans_virtio 模块的 QEMU）
			rdma	 连接到一个指定的 RDMA 通道
			usbg	 连接到一个指定的 usb gadget 通道
			========  ============================================

  uname=name	尝试以远程服务器上的该用户名挂载。服务器可能会覆盖或忽略此值。某些
  		用户名可能需要认证。

  aname=name	当服务器提供多个导出的文件系统时，aname 指定要访问的文件树。

  cache=mode	指定缓存策略。默认不使用任何缓存。mode 可以指定为位掩码，也可以使用
  		已有的常见“快捷方式”之一。位掩码描述如下：（未指定位为保留位）

			==========  ====================================================
			0b00000000  禁用所有缓存，禁用 mmap
			0b00000001  启用文件缓存
			0b00000010  启用元数据缓存
			0b00000100  回写行为（与直写相对）
			0b00001000  松散缓存（与服务器无显式一致性）
			0b10000000  启用 fscache 用于持久化缓存
			==========  ====================================================

		当前的快捷方式及其关联的位掩码为：

			=========   ====================================================
			none        0b00000000（无缓存）
			readahead   0b00000001（仅预读文件缓存）
			mmap        0b00000101（预读 + 回写文件缓存）
			loose       0b00001111（非一致的文件与元数据缓存）
			fscache     0b10001111（持久化松散缓存）
			=========   ====================================================

		注意：目前只测试过这些快捷方式对应的操作模式，因此使用其他位模式
		组合可能无效。更好的缓存支持正在开发中。

		重要：松散缓存（以及由此目前的 fscache）不一定在服务器上验证缓存值。
		换句话说，服务器上的更改不保证会反映到客户端系统。只有在你拥有独占
		挂载、且服务器不会在你之下修改文件系统时，才使用此操作模式。

  debug=n	指定调试级别。调试级别是一个位掩码。

			=====   ================================
			0x01    显示详细的错误消息
			0x02    开发者调试（DEBUG_CURRENT）
			0x04    显示 9p 跟踪
			0x08    显示 VFS 跟踪
			0x10    显示封送（Marshalling）调试
			0x20    显示传输调试
			0x40    显示分配调试
			0x80    显示协议消息调试
			0x100   显示 Fid 调试
			0x200   显示数据包调试
			0x800   显示 fscache 跟踪调试
			=====   ================================

  rfdno=n	用于 trans=fd 读取的文件描述符

  wfdno=n	用于 trans=fd 写入的文件描述符

  msize=n	用于 9p 数据包载荷的字节数

  port=n	连接到远程服务器的端口

  noextend	强制使用传统模式（无 9p2000.u 或 9p2000.L 语义）

  version=name	选择 9P 协议版本。有效选项为：

			========        ==============================
			9p2000          传统模式（与 noextend 相同）
			9p2000.u        使用 9P2000.u 协议
			9p2000.L        使用 9P2000.L 协议
			========        ==============================

  dfltuid	尝试以特定的 uid 挂载

  dfltgid	尝试以特定的 gid 挂载

  afid		安全通道——由 Plan 9 认证协议使用

  nodevmap	不映射特殊文件——将它们表示为普通文件。这可用于在主机之间共享
  		设备/命名管道/套接字。此功能将在后续版本中扩展。

  directio	在所有读/写操作中绕过页缓存

  ignoreqv	忽略 qid.version==0 作为忽略缓存的标记

  noxattr	在此挂载上不提供 xattr 函数。

  access	有四种访问模式。
			user
				如果用户首次访问 v9fs 文件系统上的一个文件，v9fs
			        会为该用户发送一个 attach 命令（Tattach）。
				这是默认模式。
			<uid>
				只允许 uid=<uid> 的用户访问挂载文件系统上的文件
			any
				v9fs 执行单次 attach，并以一个用户身份执行所有操作
			clien
				在 9p 客户端侧基于 ACL 进行访问校验以验证访问

  cachetag	缓存标签，用于使用指定的持久化缓存。现有缓存会话的缓存标签可在
  		/sys/fs/9p/caches 列出。（仅适用于 cache=fscache）
  ============= ===============================================================

## Behavior


本节旨在描述 9p 与本地文件系统行为可能不同的“怪癖”（quirks）。

 - 在文件上设置 O_NONBLOCK 会使客户端读取尽早返回，只要服务器返回了部分数据，而不是
   试图用请求数量的字节填满读缓冲区或到达文件末尾。
