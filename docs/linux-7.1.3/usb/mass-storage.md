## 大容量存储 Gadget（MSG）


## 概述


  大容量存储 Gadget（Mass Storage Gadget，简称 MSG）充当 USB 大容量存储设备，在主机
  （host）看来就是一个磁盘或 CD-ROM 驱动器。它支持多个逻辑单元（LUNs）。每个 LUN 的
  后端存储由一个普通文件或块设备提供，访问可以被限制为只读，并且 gadget 可以表明
  它是可移除的和/或 CD-ROM（后者意味着只读访问）。

  它的要求不高；只需要一个 bulk-in 和一个 bulk-out 端点。内存需求相当于两个 16K 的
  缓冲区。它支持全速（full-speed）、高速（high-speed）和 SuperSpeed 操作。

  注意，该驱动在可移植性上略有欠缺，因为它假定单个内存/DMA 缓冲区可同时用于 bulk-in
  和 bulk-out 端点。对于大多数设备控制器这不成问题，但可能存在一些硬件限制，使得一个
  缓冲区无法被多个端点使用。

  本文档描述如何从用户空间使用该 gadget、它与大容量存储功能（Mass Storage Function，
  简称 MSF）的关系，以及使用它的不同 gadget，以及它与文件存储 Gadget（File Storage
  Gadget，简称 FSG）（已不再包含在 Linux 中）的区别。关于如何在复合（composite）
  gadget 中使用 MSF，本文只做简要说明。

## 模块参数


  大容量存储 gadget 接受以下大容量存储专用的模块参数：

  - file=filename[,filename...]

    该参数列出用作每个逻辑单元后端存储的文件或块设备的路径。最多可以设置
    FSG_MAX_LUNS（8）个 LUN。如果指定了更多文件，它们会被静默忽略。另见 “luns” 参数。

    **注意** 如果某个文件被用作后端存储，则它不能被任何其他进程修改。这是因为主机
    假定数据不会在它不知情的情况下发生变化。它可以读取，但（如果该逻辑单元可写）
    由于主机侧的缓冲，其内容是不确定的。

    逻辑单元的大小会被向下取整到完整的逻辑块。逻辑块大小对于模拟 CD-ROM 的 LUN 是
    2048 字节，如果后端文件是块设备则为该设备的块大小，否则为 512 字节。

  - removable=b[,b...]

    该参数指定每个逻辑单元是否可移除。“b” 为 “y”、“Y” 或 “1” 表示真，为 “n”、“N”
    或 “0” 表示假。

    如果为某个逻辑单元设置了该选项，gadget 会接受 “弹出”（eject）SCSI 请求
    （Start/Stop Unit）。当该请求发出时，后端文件会被关闭以模拟弹出，在用户空间在
    设备上指定新的后端文件之前（见 “sysfs 条目” 一节），主机将无法挂载该逻辑单元。

    如果某个逻辑单元不可移除（默认值），则必须在模块加载时通过 “file” 参数为其指定
    后端文件。如果模块是内建的，同样适用，没有例外。

    该标志的默认值是假，**然而**它曾经是真。这一改动是为了更好地与文件存储 Gadget
    匹配，并且毕竟看起来是一个更合理的默认值。因此，为了保持与旧内核的兼容性，最好
    显式指定默认值。另外，如果曾依赖旧的默认值，现在需要显式指定 “n”。

    注意，“removable” 是指逻辑单元的介质可以被弹出或移除（正如 CD-ROM 驱动器或
    读卡器那样）。它**并非**指整个 gadget 可以从主机上拔下；那个概念的正确术语是
    “hot-unpluggable”（可热插拔）。

  - cdrom=b[,b...]

    该参数指定每个逻辑单元是否模拟 CD-ROM。默认值为假。

  - ro=b[,b...]

    该参数指定每个逻辑单元是否应报告为只读。这将阻止主机修改后端文件。

    注意，如果某个给定逻辑单元的该标志为假，但后端文件无法以读写模式打开，则 gadget
    无论如何都会回退到只读模式。

    非 CD-ROM 逻辑单元的默认值为假；对于模拟 CD-ROM 的逻辑单元则强制为真。

  - nofua=b[,b...]

    该参数指定是否忽略发送到给定逻辑单元的 SCSI Write10 和 Write12 命令中的 FUA 标志。

    MS Windows 默认以 “Removal optimised mode”（优化移除模式）挂载可移动存储。所有对
    介质的写入都是同步的，这是通过在 SCSI Write(10,12) 命令中设置 FUA（Force Unit
    Access，强制单元访问）位来实现的。这强制每次写入都等待数据实际写出，并阻止块层
    中的 I/O 请求聚合，从而显著降低性能。

    注意，这可能意味着如果该设备由 USB 供电，而用户在未先卸载的情况下拔下设备
    （至少一些 Windows 用户会这样做），数据可能会丢失。

    默认值为假。

  - luns=N

    该参数指定 gadget 将拥有的逻辑单元数量。它受 FSG_MAX_LUNS（8）限制，更大的值会被
    截断。

    如果提供了该参数，且 “file” 参数中指定的文件数大于 “luns” 的值，多余的
    文件都会被忽略。

    如果未提供该参数，则逻辑单元的数量将从 “file” 参数中指定的文件数推导出来。如果
    文件参数也缺失，则假定为 1 个。

  - stall=b

    指定是否允许 gadget 暂停（halt）bulk 端点。默认值取决于 USB 设备控制器的类型，
    但通常为真。

  除上述之外，该 gadget 还接受由复合框架定义的以下参数（它们对所有复合 gadget 通用，
  因此仅做简要列举）：

  - idVendor      -- USB 厂商 ID（16 位整数）
  - idProduct     -- USB 产品 ID（16 位整数）
  - bcdDevice     -- USB 设备版本（BCD）（16 位整数）
  - iManufacturer -- USB 厂商字符串（字符串）
  - iProduct      -- USB 产品字符串（字符串）
  - iSerialNumber -- 序列号字符串（字符串）

## sysfs 条目


  对于每个逻辑单元，gadget 在 sysfs 层次结构中创建一个目录。在其中会创建以下三个文件：

  - file

    读取时，它返回给定逻辑单元的后端文件路径。如果没有后端文件（只有在逻辑单元可移除
    时才可能），则内容为空。

    写入时，它更改给定逻辑单元的后端文件。即使给定逻辑单元未被指定为可移除，也可以
    执行此更改（但这在主机看来可能有些奇怪）。不过，如果主机通过 Prevent-Allow Medium
    Removal SCSI 命令禁止了介质移除，则可能会失败。

  - ro

    反映给定逻辑单元的 ro 标志状态。它可以随时读取，并在没有为该逻辑单元打开后端文件
    时写入。

  - nofua

    反映给定逻辑单元的 nofua 标志状态。它可以读取和写入。

  - forced_eject

    写入时，它会强制将后端文件从该 LUN 上分离，无论主机是否允许。内容无关紧要，写入
    任意非零字节数都会触发弹出。

    不可读取。

  除此之外，像往常一样，模块参数的值可以从
  /sys/module/g_mass_storage/parameters/* 文件中读取。

## 使用大容量存储功能的其他 gadget


  大容量存储 Gadget 使用大容量存储功能（Mass Storage Function）来处理大容量存储协议。
  作为一个复合功能，MSF 也可以被其他 gadget 使用（例如 g_multi 和 acm_ms）。

  前面各节中的信息对于使用 MSF 的其他 gadget 同样有效，只是对大容量存储相关模块参数的
  支持可能缺失，或者参数可能带有前缀。要判断是否存在这些情况，需要查阅该 gadget 的
  文档或其源代码。

  关于如何在 gadget 中纳入大容量存储功能的示例，可以参考 mass_storage.c、acm_ms.c
  和 multi.c（按复杂度排序）。

## 与文件存储 Gadget 的关系


  大容量存储功能（Mass Storage Function）以及由此而来的大容量存储 Gadget 是基于文件
  存储 Gadget（File Storage Gadget）构建的。两者区别在于：MSG 是一个复合 gadget（即
  使用复合框架），而文件存储 Gadget 是一个传统 gadget。从用户空间的角度看，这一区别
  其实无关紧要，但从内核开发者的角度看，这意味着 (i) MSG 不会重复处理基本 USB 协议
  命令所需的代码，(ii) MSF 可以用于任何其他复合 gadget。

  因此，文件存储 Gadget 已在 Linux 3.8 中被移除。所有用户都需要迁移到大容量存储
  Gadget。两者从外部看行为大多相同，除了：

  1. 在 FSG 中，“removable” 和 “cdrom” 模块参数设置所有逻辑单元的标志，而在 MSG 中
     它们接受每个逻辑单元的 y/n 值列表。如果只使用单个逻辑单元，这没有影响；但如果有
     多个，则需要为每个逻辑单元重复 y/n 值。

  2. FSG 的 “serial”、“vendor”、“product” 和 “release” 模块参数在 MSG 中由复合层
     的相应参数处理，分别为：“iSerialnumber”、“idVendor”、“idProduct” 和 “bcdDevice”。

  3. MSG 不支持 FSG 的测试模式，因此 FSG 的 “transport”、“protocol” 和 “buflen”
     模块参数不被支持。MSG 始终使用 SCSI 协议、仅 bulk 传输模式（bulk only transport）
     以及 16 KiB 的缓冲区。
