## ACPI WMI 接口


ACPI WMI 接口是 Microsoft 对 ACPI 规范的私有扩展，用于允许硬件厂商在其 ACPI 固件中嵌入 WMI（Windows Management Instrumentation，Windows 管理规范）对象。通过 ACPI WMI 实现的典型功能包括现代笔记本上的热键（hotkey）事件以及 BIOS 选项的配置。

### PNP0C14 ACPI 设备


WMI 对象的发现是通过定义具有 PNP ID 为 `PNP0C14` 的 ACPI 设备来处理的。这些设备会包含一组用于映射和执行 WMI 方法（methods）及/或查询的 ACPI 缓冲区和方法的集合。如果存在多个此类设备，则每个设备都必须具有唯一的 ACPI UID。

### _WDG 缓冲区


`_WDG` 缓冲区用于发现 WMI 对象，并且要求为静态的。其内部由大小为 20 字节的数据块组成，包含以下数据：

======= =============== =====================================================
Offset  Size (in bytes) Content
======= =============== =====================================================
0x00    16              128 位 Variant 2 对象 GUID。
0x10    2               2 字符的方法 ID 或单字节通知 ID。
0x12    1               对象实例计数。
0x13    1               对象标志。
======= =============== =====================================================

WMI 对象标志控制使用方法是方法 ID 还是通知 ID：

- 0x1: 数据块收集代价高昂。
- 0x2: 数据块包含 WMI 方法。
- 0x4: 数据块包含 ASCIZ 字符串。
- 0x8: 数据块描述一个 WMI 事件，应使用通知 ID 而非方法 ID。

每个 WMI 对象 GUID 可以在系统内出现多次。
方法/通知 ID 用于构造用于与 WMI 对象交互的 ACPI 方法名。

### WQxx ACPI 方法


如果某个数据块不包含 WMI 方法，则其内容可通过此必需的 ACPI 方法获取。ACPI 方法名的最后两个字符是要查询的数据块的方法 ID。其唯一参数为一个描述应查询实例的整数。如果该数据块仅包含单个实例，则可省略此参数。

### WSxx ACPI 方法


与 `WQxx` ACPI 方法类似，但它为可选的，并将一个额外的缓冲区作为其第二个参数。实例参数同样不能被省略。

### WMxx ACPI 方法


用于执行与数据块关联的 WMI 方法。ACPI 方法名的最后两个字符是包含 WMI 方法的数据块的方法 ID。其第一个参数是描述应执行方法所属实例的整数。第二个参数是描述要执行的 WMI 方法 ID 的整数，第三个参数是包含 WMI 方法参数的缓冲区。如果数据块被标记为包含 ASCIZ 字符串，则该缓冲区应包含 ASCIZ 字符串。该 ACPI 方法将返回所执行 WMI 方法的结果。

### WExx ACPI 方法


用于可选地启用/禁用 WMI 事件，ACPI 方法的最后两个字符是描述该 WMI 事件的数据块的通知 ID（以十六进制值表示）。其第一个参数为一个整数，如果要禁用 WMI 事件则其值为 0，其他值将启用该 WMI 事件。

这些 ACPI 方法即使对于未注册为收集代价高昂的 WMI 事件也总是被调用，以匹配 Windows 驱动的行为。

### WCxx ACPI 方法


与 `WExx` ACPI 方法类似，但它控制的不是 WMI 事件，而是注册为收集代价高昂的数据块的数据收集。因此 ACPI 方法名的最后两个字符是要启用/禁用的数据块的方法 ID。

这些 ACPI 方法也会在设置数据块之前被调用，以匹配 Windows 驱动的行为。

### _WED ACPI 方法


用于检索额外的 WMI 事件数据，其唯一参数为一个保存该事件通知 ID 的整数。每次接收到 ACPI 通知时都应求值此方法，因为某些 ACPI 实现使用队列来存储 WMI 事件数据项。如果在收到若干 WMI 事件后未检索关联的 WMI 事件数据，该队列将溢出。

### ACPI 数据类型的转换规则


ACPI-WMI 接口的消费者使用二进制缓冲区与 WMI 驱动核心交换数据，
缓冲区内部结构仅为消费者所知。因此 WMI 驱动核心负责将缓冲区内的数据转换为
合适的 ACPI 数据类型，以供 ACPI 固件消费。此外，各种 ACPI 方法返回的任何数据
都需要转换回二进制缓冲区。

所述缓冲区的布局由相关 WMI 方法或数据块的 MOF 描述定义 [^1^]_：

=============== ======================================================================= =========
Data Type       Layout                                                                  Alignment
=============== ======================================================================= =========
`string`      以无符号 16 位小端整数开始，指定字符串数据的长度（以字节为单位），后跟       2 bytes
                以 UTF-16LE 编码的字符串数据，带有**可选的** NULL 终止符和填充。
                请记住，某些固件实现可能依赖末尾 NULL 字符的存在。同时填充应
                始终使用 NULL 字符完成。
`boolean`    单字节，其中 0 表示 `false`，非零表示 `true`。                      1 byte
`sint8`       有符号 8 位整数。                                                       1 byte
`uint8`       无符号 8 位整数。                                                       1 byte
`sint16`      有符号 16 位小端整数。                                                  2 bytes
`uint16`      无符号 16 位小端整数。                                                  2 bytes
`sint32`      有符号 32 位小端整数。                                                  4 bytes
`uint32`      无符号 32 位小端整数。                                                  4 bytes
`sint64`      有符号 64 位小端整数。                                                  8 bytes
`uint64`      无符号 64 位小端整数。                                                  8 bytes
`datetime`   固定长度 25 字符的 UTF-16LE 字符串，格式为                               2 bytes
                **yyyymmddhhmmss.mmmmmmsutc**，其中 **yyyy** 为 4 位年份，**mm** 为
                2 位月份，**dd** 为 2 位日期，**hh** 为基于 24 小时制的 2 位小时，
                **mm** 为 2 位分钟，**ss** 为 2 位秒，**mmmmmm** 为 6 位微秒，**s** 为
                加号或减号字符，取决于 **utc** 是相对于 UTC 的正偏移还是负偏移
                （或若日期为间隔则为冒号）。未填充的字段应以星号填充。
=============== ======================================================================= =========

数组应基于其基类型的对齐方式进行对齐，而对象应基于其内部最大对齐元素进行对齐。

所有由 WMI 驱动核心返回的缓冲区都是 8 字节对齐的。将 ACPI 数据类型转换为此类缓冲区时，适用以下转换规则：

=============== ============================================================
ACPI Data Type  Converted into
=============== ============================================================
Buffer         原样复制。
Integer        转换为 `uint32`。
String         转换为带有终止 NULL 字符的 `string`，
                以匹配 Windows 驱动的行为。
Package        包内的每个元素都被转换，并遵从其结果数据类型的对齐。
                不允许嵌套包（Nested packages）。
=============== ============================================================

Windows 驱动确实尝试处理嵌套包，但这会导致内部结构（`_ACPI_METHOD_ARGUMENT_V1`）被错误地复制到结果缓冲区中。
因此 ACPI 固件实现不应从与 ACPI-WMI 接口关联的 ACPI 方法返回嵌套包。
