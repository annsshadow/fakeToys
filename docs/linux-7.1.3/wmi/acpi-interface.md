## ACPI WMI 接口


ACPI WMI 接口Microsoft ACPI 规范的私有扩展，用于允许硬件厂商在其 ACPI 固件中嵌WMI（Windows Management Instrumentation，Windows 管理规范）对象。通过 ACPI WMI 实现的典型功能包括现代笔记本上的热键（hotkey）事件以BIOS 选项的配置
### PNP0C14 ACPI 设备


WMI 对象的发现是通过定义具有 PNP ID `PNP0C14` ACPI 设备来处理的。这些设备会包含一组用于映射和执行 WMI 方法（methods）及/或查询的 ACPI 缓冲区和方法的集合。如果存在多个此类设备，则每个设备都必须具有唯一ACPI UID
### _WDG 缓冲

`_WDG` 缓冲区用于发WMI 对象，并且要求为静态的。其内部由大小为 20 字节的数据块组成，包含以下数据：

======= =============== =====================================================
Offset  Size (in bytes) Content
======= =============== =====================================================
0x00    16              128 Variant 2 对象 GUID0x10    2               2 字符的方ID 或单字节通知 ID0x12    1               对象实例计数0x13    1               对象标志======= =============== =====================================================

WMI 对象标志控制使用方法是方ID 还是通知 ID
- 0x1: 数据块收集代价高昂- 0x2: 数据块包WMI 方法- 0x4: 数据块包ASCIZ 字符串- 0x8: 数据块描述一WMI 事件，应使用通知 ID 而非方法 ID
每个 WMI 对象 GUID 可以在系统内出现多次方法/通知 ID 用于构造用于与 WMI 对象交互ACPI 方法名
### WQxx ACPI 方法


如果某个数据块不包含 WMI 方法，则其内容可通过此必需ACPI 方法获取。ACPI 方法名的最后两个字符是要查询的数据块的方法 ID。其唯一参数为一个描述应查询实例的整数。如果该数据块仅包含单个实例，则可省略此参数
### WSxx ACPI 方法


`WQxx` ACPI 方法类似，但它为可选的，并将一个额外的缓冲区作为其第二个参数。实例参数同样不能被省略
### WMxx ACPI 方法


用于执行与数据块关联WMI 方法。ACPI 方法名的最后两个字符是包含 WMI 方法的数据块的方ID。其第一个参数是描述应执行方法所属实例的整数。第二个参数是描述要执行WMI 方法 ID 的整数，第三个参数是包含 WMI 方法参数的缓冲区。如果数据块被标记为包含 ASCIZ 字符串，则该缓冲区应包含 ASCIZ 字符串。该 ACPI 方法将返回所执行 WMI 方法的结果
### WExx ACPI 方法


用于可选地启用/禁用 WMI 事件，ACPI 方法的最后两个字符是描述WMI 事件的数据块的通知 ID（以十六进制值表示）。其第一个参数为一个整数，如果要禁WMI 事件则其值为 0，其他值将启用WMI 事件
这些 ACPI 方法即使对于未注册为收集代价高昂WMI 事件也总是被调用，以匹Windows 驱动的行为
### WCxx ACPI 方法


`WExx` ACPI 方法类似，但它控制的不是 WMI 事件，而是注册为收集代价高昂的数据块的数据收集。因ACPI 方法名的最后两个字符是要启禁用的数据块的方ID
这些 ACPI 方法也会在设置数据块之前被调用，以匹Windows 驱动的行为
### _WED ACPI 方法


用于检索额外的 WMI 事件数据，其唯一参数为一个保存该事件通知 ID 的整数。每次接收到 ACPI 通知时都应求值此方法，因为某ACPI 实现使用队列来存WMI 事件数据项。如果在收到若干 WMI 事件后未检索关联的 WMI 事件数据，该队列将溢出
### ACPI 数据类型的转换规

ACPI-WMI 接口的消费者使用二进制缓冲区与 WMI 驱动核心交换数据缓冲区内部结构仅为消费者所知。因WMI 驱动核心负责将缓冲区内的数据转换合适的 ACPI 数据类型，以ACPI 固件消费。此外，各种 ACPI 方法返回的任何数都需要转换回二进制缓冲区
