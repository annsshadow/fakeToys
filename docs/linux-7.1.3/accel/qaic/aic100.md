
##  Qualcomm Cloud AI 100 (AIC100)


## 概述


Qualcomm Cloud AI 100/AIC100 系列产品（包括 SA9000P —— Snapdragon Ride 的一部分）
是 PCIe 适配器卡，其中包含一个专用的 SoC ASIC，用于高效地运行人工智能（AI）深度
学习推理工作负载。它们是 AI 加速器。

AIC100 的 PCIe 接口能够在八条通道（x8）上达到 PCIe Gen4 速率。一张卡上的单个 SoC
最多可有 16 个 NSP 用于运行工作负载。每个 SoC 有一个 A53 管理 CPU。卡上最多可有
32 GB 的 DDR。

多张 AIC100 卡可以安装在同一系统中以扩展整体性能。AIC100 卡支持多用户，并且能够以
并发方式执行来自多个用户的工作负载。

## 硬件描述


一张 AIC100 卡由 AIC100 SoC、卡上 DDR 以及一组杂项外设（PMIC 等）组成。

AIC100 卡可以是 PCIe HHHL 外形规格（传统 PCIe 卡），也可以是双 M.2 卡。两者都使用
PCIe 连接到主机系统。

作为 PCIe 端点/适配器，AIC100 使用标准的 VendorID（VID）/DeviceID（DID）组合来唯一
标识自己。AIC100 使用标准的 Qualcomm VID（0x17cb）。所有 AIC100 SKU 都使用相同的
AIC100 DID（0xa100）。

AIC100 不实现 FLR（功能级复位）。

AIC100 实现 MSI 但不实现 MSI-X。AIC100 偏好使用 17 个 MSI 来运行（1 个用于 MHI，
16 个用于 DMA Bridge）。在无法预留 32 个 MSI 的场景下，回退到 1 个 MSI 是可行的。

作为 PCIe 设备，AIC100 利用 BAR 来向主机提供对设备硬件的接口。AIC100 提供 3 个
64 位 BAR。

- 第一个 BAR 大小为 4K，向主机暴露 MHI 接口。

- 第二个 BAR 大小为 2M，向主机暴露 DMA Bridge 接口。

- 第三个 BAR 的大小基于单个 AIC100 的配置而可变，但默认为 64K。该 BAR 目前没有
  用途。

从主机的角度看，AIC100 有几个关键的硬件组件 ——

- MHI（Modem Host Interface，调制解调器主机接口）
- QSM（QAIC Service Manager，QAIC 服务管理器）
- NSP（Neural Signal Processor，神经信号处理器）
- DMA Bridge（DMA 桥）
- DDR

### MHI


AIC100 通过 PCIe 拥有一个 MHI 接口。MHI 本身在 Documentation/mhi/index.rst 中有
文档说明。MHI 是主机用来与 QSM 通信的机制。除了经由 DMA Bridge 的工作负载数据外，
与设备的所有交互都通过 MHI 进行。

### QSM


QAIC Service Manager。这是一个 ARM A53 CPU，运行卡上的主要固件并执行卡上管理任务。
它也通过 MHI 与主机通信。每个 AIC100 有一个这样的组件。

### NSP


Neural Signal Processor。每个 AIC100 最多有 16 个这样的处理器。这些是在 AIC100 上
运行工作负载的处理器。每个 NSP 是一个带有 HVX 和 HMX 的 Qualcomm Hexagon（Q6）DSP。
每个 NSP 一次只能运行一个工作负载，但多个 NSP 可以被分配给单个工作负载。由于每个
NSP 只能运行一个工作负载，AIC100 最多只能有 16 个并发工作负载。工作负载的“调度”
属于主机的职责范围。AIC100 不会自动进行时间片轮转。

### DMA Bridge


DMA Bridge 是管理进出工作负载的数据流的定制 DMA 引擎。AIC100 有一个这样的组件。
DMA Bridge 有 16 个通道，每个通道由一组请求/响应 FIFO 组成。每个活跃的工作负载被
分配一个单独的 DMA Bridge 通道。DMA Bridge 暴露硬件寄存器来管理 FIFO（头/尾指针），
但需要主机内存来存储 FIFO。

### DDR


AIC100 有卡上 DDR。总共，一个 AIC100 最多可有 32 GB 的 DDR。这块 DDR 用于存储工作
负载、工作负载的数据，并被 QSM 用于管理设备。NSP 对 DDR 某些区域的访问由 QSM 授予。
主机没有直接访问 DDR 的权限，必须向 QSM 发出请求才能将数据传送到 DDR。

## 高层使用流程


AIC100 是一个多用户、可编程的加速器，通常用于以推理模式运行神经网络，以高效地执行
AI 运算。AIC100 并非为训练神经网络而设计。AIC100 也可用于通用计算工作负载。

假设一个用户想要使用 AIC100，他们会遵循以下步骤：

1. 将工作负载编译为面向 NSP 的 ELF
2. 向 QSM 发出请求，将工作负载及相关制品加载到设备 DDR 中
3. 向 QSM 发出请求，将工作负载激活到一组空闲的 NSP 上
4. 向 DMA Bridge 发出请求，将输入数据发送给工作负载进行处理，并发出其他请求以从
   工作负载接收处理过的输出数据。
5. 一旦不再需要该工作负载，向 QSM 发出请求使工作负载停用，从而将 NSP 放回空闲状态。
6. 一旦工作负载及相关制品在将来的会话中不再需要，向 QSM 发出请求将 DDR 中的数据
   卸载。这就释放了 DDR 以供其他用户使用。


## 启动流程


AIC100 使用源自 Qualcomm MSM 的无闪存（flashless）启动流程。

当 AIC100 首次上电时，它开始从 ROM 执行 PBL（Primary Bootloader，主引导加载程序）。
PBL 枚举 PCIe 链路，并初始化 MHI 的 BHI（Boot Host Interface，引导主机接口）组件。

使用 BHI，主机将 PBL 指向 SBL（Secondary Bootloader，次引导加载程序）映像的位置。
PBL 从主机拉取该映像，验证它，并开始执行 SBL。

SBL 初始化 MHI，并使用 MHI 通知主机设备已进入 SBL 阶段。SBL 执行若干操作：

- SBL 初始化大部分硬件（PBL 遗留未初始化的任何部分），包括 DDR。
- SBL 将启动日志（bootlog）卸载到主机。
- SBL 与主机同步时间戳以供将来记录日志。
- SBL 使用 Sahara 协议从主机获取运行时固件映像。

一旦 SBL 获取并验证了运行时固件，它就将 NSP 退出复位，并跳转到 QSM。

QSM 使用 MHI 通知主机设备已进入 QSM 阶段（MHI 术语中的 AMSS）。此时，AIC100 设备
已完全可用，并准备好处理工作负载。

## DMA Bridge


### 概述


DMA Bridge 是从设备到主机的主要接口之一（另一个是 MHI）。作为将工作负载激活到
NSP 上运行的一部分，QSM 为该网络分配一个 DMA Bridge 通道。一个工作负载的 DMA Bridge
通道（简称 DBC）仅供该工作负载使用，不与其他工作负载共享。

每个 DBC 是一对管理进出工作负载数据的 FIFO。一个 FIFO 是请求 FIFO。另一个 FIFO 是
响应 FIFO。

每个 DBC 在硬件中包含 4 个寄存器：

- 请求 FIFO 头指针（偏移 0x0）。主机只读。表示设备已消费的 FIFO 中的最新元素。
- 请求 FIFO 尾指针（偏移 0x4）。主机可读写。主机递增此寄存器以向 FIFO 添加新元素。
- 响应 FIFO 头指针（偏移 0x8）。主机可读写。表示主机已消费的 FIFO 中的最新元素。
- 响应 FIFO 尾指针（偏移 0xc）。主机只读。设备递增此寄存器以向 FIFO 添加新元素。

每个寄存器中的值都是 FIFO 中的索引。要获取该寄存器所指向的 FIFO 元素的位置：
FIFO 基地址 + 寄存器值 * 元素大小。

DBC 寄存器通过第二个 BAR 暴露给主机。每个 DBC 在 BAR 中占用 4KB 空间。

实际的 FIFO 由主机内存支持。当向 QSM 发送请求以激活一个网络时，主机必须捐献用于
FIFO 的内存。由于设备的内部映射限制，每个 DBC 必须提供一块连续的内存块，其中同时
容纳两个 FIFO。请求 FIFO 将占用内存块的起始部分，响应 FIFO 将占用内存块的末尾部分。

### Request FIFO


一个请求 FIFO 元素具有以下结构：


  struct request_elem {
	u16 req_id;
	u8  seq_id;
	u8  pcie_dma_cmd;
	u32 reserved;
	u64 pcie_dma_source_addr;
	u64 pcie_dma_dest_addr;
	u32 pcie_dma_len;
	u32 reserved;
	u64 doorbell_addr;
	u8  doorbell_attr;
	u8  reserved;
	u16 reserved;
	u32 doorbell_data;
	u32 sem_cmd0;
	u32 sem_cmd1;
	u32 sem_cmd2;
	u32 sem_cmd3;
  };

请求字段描述：

req_id
	请求 ID。具有相同请求 ID 的请求 FIFO 元素和响应 FIFO 元素指代同一条命令。

seq_id
	请求内的序列 ID。DMA Bridge 忽略它。

pcie_dma_cmd
	描述此请求的 DMA 元素。

 - Bit(7) 是 force msi 标志，它会覆盖 DMA Bridge 的 MSI 逻辑，并在该请求完成时
	  生成一个 MSI；QSM 配置 DMA Bridge 以查看此位。
 - Bits(6:5) 保留。
 - Bit(4) 是完成码标志，表示 DMA Bridge 应在该请求完成时生成一个响应 FIFO 元素。
 - Bit(3) 指示此请求是链表传输（0）还是批量传输（1）。
 - Bit(2) 保留。
 - Bits(1:0) 指示传输类型。无传输（0）、到设备（1）、从设备（2）。值 3 非法。

pcie_dma_source_addr
	批量传输的源地址，或链表的地址。

pcie_dma_dest_addr
	批量传输的目标地址。

pcie_dma_len
	批量传输的长度。注意此字段的大小将传输限制为 4G。

doorbell_addr
	此请求完成时要响铃的 doorbell（门铃）地址。

doorbell_attr
	doorbell 属性。

 - Bit(7) 指示是否要执行对 doorbell 的写入。
 - Bits(6:2) 保留。
 - Bits(1:0) 包含 doorbell 长度的编码。0 为 32 位，1 为 16 位，2 为 8 位，3 保留。
	  doorbell 地址必须自然对齐到指定长度。

doorbell_data
	要写入 doorbell 的数据。只有与 doorbell 长度对应的位有效。

sem_cmdN
	信号量命令。

 - Bit(31) 指示此信号量命令已启用。
 - Bit(30) 是到设备的 DMA 栅栏。阻塞此请求，直到所有到设备的 DMA 传输完成。
 - Bit(29) 是从设备的 DMA 栅栏。阻塞此请求，直到所有从设备的 DMA 传输完成。
 - Bits(28:27) 保留。
 - Bits(26:24) 是信号量命令。0 为 NOP。1 为用指定值初始化。2 为递增。3 为递减。
	  4 为等待直到信号量等于指定值。5 为等待直到信号量大于等于指定值。6 为“P”，
	  等待直到信号量大于 0，然后递减 1。7 保留。
 - Bit(23) 保留。
 - Bit(22) 是信号量同步。0 为 postsync，表示信号量操作在 DMA 传输之后进行。1 为
	  presync，它门控 DMA 传输。每个请求只允许一个 presync。
 - Bit(21) 保留。
 - Bits(20:16) 是要操作的信号量的索引。
 - Bits(15:12) 保留。
 - Bits(11:0) 是操作中使用的信号量值。

总体而言，一个请求分 4 步处理：

1. 如果指定，presync 信号量条件必须为真
2. 如果启用，发生 DMA 传输
3. 如果指定，postsync 信号量条件必须为真
4. 如果启用，写入 doorbell

通过将信号量与运行在 NSP 上的工作负载结合使用，可以对数据管道进行同步，使得主机
可以排队多个待工作负载处理的数据请求，但 DMA Bridge 只会在工作负载准备好处理下
一个输入时才将数据复制到该工作负载的内存中。

### Response FIFO


一旦一个请求被完全处理，如果 pcie_dma_cmd 中指定了，就会生成一个响应 FIFO 元素。
响应 FIFO 元素的结构：


  struct response_elem {
	u16 req_id;
	u16 completion_code;
  };

req_id
	匹配生成此元素的请求的 req_id。

completion_code
	此请求的状态。0 表示成功。非零表示错误。

DMA Bridge 会作为对 DBC 的响应 FIFO 中活动的反应，向主机生成一个 MSI。DMA Bridge
硬件有一个 IRQ 风暴缓解算法，即它只在响应 FIFO 从空变为非空时才生成 MSI（除非启用了
force MSI 并触发）。作为对此 MSI 的响应，主机应当排空响应 FIFO，并且必须注意处理
排空 FIFO 与设备向 FIFO 插入元素之间的任何竞态条件。

## 神经网络控制（NNC）协议


NNC 协议是主机向 QSM 发出请求以管理工作负载的方式。它使用 QAIC_CONTROL MHI 通道。

每个 NNC 请求被打包成一个消息。每个消息是一系列事务。一个 passthrough 类型的事务
可以包含称为命令的元素。

QSM 要求 NNC 消息采用小端编码，并且字段自然对齐。由于某些 NNC 消息中存在 64 位
元素，必须保持 64 位对齐。

一个消息包含一个头部，然后是一系列事务。从 QSM 到主机的消息最多为 4K。从主机到
QSM，一个消息最多为 64K（单个 MHI 包的最大大小），但有一个续传特性，即消息 N+1 可以
被标记为消息 N 的续传。这用于超大的 DMA 传输（xfer）事务。

### 事务描述


passthrough
	允许用户空间将一个不透明负载直接发送给 QSM。这用于 NNC 命令。用户空间负责管理
	负载中的 QSM 消息要求。

dma_xfer
	DMA 传输。描述一个对象，QSM 应通过地址和大小元组将其 DMA 到设备中。

activate
	将工作负载激活到 NSP 上。主机必须提供供 DBC 使用的内存。

deactivate
	停用活跃的工作负载，并将 NSP 放回空闲状态。

status
	向 QSM 查询其 NNC 实现。返回 NNC 版本，以及是否使用了 CRC。

terminate
	释放用户的资源。

dma_xfer_cont
	先前 DMA 传输的续传。如果一个 DMA 传输无法在单个消息中指定（高度碎片化），
	此事务可用于指定更多范围。

validate_partition
	向 QSM 查询以确定一个分区标识符是否有效。

每个消息都带有用户 id 和分区 id 标签。用户 id 允许 QSM 跟踪资源，并在用户消失时
（例如进程崩溃）释放它们。分区 id 标识 QSM 管理的、此消息所适用的资源分区。

消息可以有 CRC。在 QSM 通过 status 事务报告不再需要 CRC 之前，消息都应应用 CRC。
SA9000P 上的 QSM 需要 CRC 以实现黑通道安全（black channel safing）。

## 子系统重启（SSR）


SSR 是限制错误影响范围的概念。一个 AIC100 设备可能有多个用户，每个用户运行自己的
工作负载。如果一个用户的工作负载崩溃，其后果应被限制在该工作负载内，而不影响其他
工作负载。SSR 实现了这一点。

如果某个特定工作负载崩溃，QSM 通过 QAIC_SSR MHI 通道通知主机。该通知通过其分配的
DBC 标识该工作负载。随后使用一个多阶段恢复过程来清理双方，并使 DBC/NSP 进入工作
状态。

当 SSR 发生时，工作负载中的任何状态都会丢失。任何正在处理中、或已排队但尚未被服务
的输入都会丢失。已加载的制品将保留在卡上 DDR 中，但如果主机想要恢复该工作负载，
则需要重新激活它。

当特定 NSP 发生 SSR 时，所分配的 DBC 按顺序经历以下状态事务：

DBC_STATE_BEFORE_SHUTDOWN
	指示受影响的 NSP 被发现处于不可恢复的错误状态。
DBC_STATE_AFTER_SHUTDOWN
	指示 NSP 处于复位之中。
DBC_STATE_BEFORE_POWER_UP
	指示 NSP 的调试信息已被收集，并准备好由主机收集（如果需要）。在该阶段，NSP
	由 QSM 重新启动。
DBC_STATE_AFTER_POWER_UP
	指示 NSP 已被重新启动，完全可运行并处于空闲状态。

SSR 还具有一个可选的 crashdump 收集特性。如果启用，主机可以收集崩溃 NSP 的内存转储，
并通过 dev_coredump 子系统将其转储到用户空间。主机也可以拒绝来自设备的 crashdump
收集请求。

## 可靠性、可用性、可服务性（RAS）


AIC100 预期会部署在应用了 RAS 理念的服务器系统中。简而言之，RAS 是检测、分类和报告
错误的概念。虽然 PCIe 有 AER（Advanced Error Reporting，高级错误报告）属于 RAS 的
范畴，但 AER 不允许设备报告内部错误的详细信息。因此，AIC100 实现了一套定制的 RAS
机制。当发生 RAS 事件时，QSM 会通过 QAIC_STATUS MHI 通道报告带有适当详细信息的事件。
系统管理员可以根据 RAS 报告判定某个特定设备需要额外的服务。

## 遥测（Telemetry）


QSM 能够报告设备的各种物理属性，并且在某些情况下允许主机控制它们。例子包括温度
限制、温度读数和功率读数。这些项目通过 QAIC_TELEMETRY MHI 通道进行通信。
