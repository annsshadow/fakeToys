## 内核驱动 ds2490


支持芯片
  - 基于 Maxim DS2490

作者：Evgeniy Polyakov <johnpol@2ka.mipt.ru>


### 描述


Maxim/Dallas Semiconductor DS2490 是一颗允许构USB <-> W1 桥接的芯片
DS9490(R) 是一USB <-> W1 总线主设备，集成0x81 ID 芯片以及 DS2490
底层操作芯片
注意事项与限制
- 弱上拉电流最小为 0.9mA，最大为 6.0mA- 5V 强上拉受支持，最小为 5.9mA，最大为 30.4 mA。（取自 DS2490.pdf- 硬件会在下一次总线（复位？）操作时检测到有设备挂到总线上，但只会打印一  消息，因为核w1 代码没有利用该信息。连接一个设备往往会给出多条新设备通知- 如果 w1_reset_send 被加API，就可以减少 USB 总线事务数。名称仅是个建议  它会以一个写缓冲区和一个读缓冲区（连同大小）作为参数。ds2490 I/O 命令
  支持在一次命令中完成复位、写缓冲区、读缓冲区以及强上拉，而不是当前的
  1 复位总线 写匹rom 命令和从 rom id 块写和读数据。写缓冲区需要把
  匹配 rom 命令和从 rom id 前置到所请求的写缓冲区前面，这两者驱动都是已知的- 硬件支持普通、灵活和超速总线通信速度，但只支持普通速度- 已注册的 w1_bus_master 函数没有定义错误条件。如果正在进行总线搜索ds2490
  被移除，在总线搜索完成之前会产生大量错误输出- 硬件支持检测某些错误条件，例如短路、复位时存在告警（alarming presence）以  复位时无存在（no presence），但驱动没有查询这些值- ds2490 规范没有详细涵盖bulk in 读，但据我观察，如果请求的字节数少于
  可用字节数，bulk 读会返回错误，硬件会清空整个 bulk in 缓冲区。可以读取最  缓冲区大小来避免碰到此错误条件，只有缓冲区中多余的字节才是驱动的逻辑错误  代码应当匹配读和写以及数据大小。读和写是串行的，状态在读执行前会验证芯片空  （且数据可用），所以本不应发生- x86_64 2.6.24 UHCI 下、运行于 x86_64 2.6.22-rc6 之下OHCI 控制器的
  qemu 0.9.0 中，ds2490 在客户机内于 qemu 挂接 ds2490 硬件后第一次加载模块时
  会正常工作，但如果模块被卸载再重新加载，大多数时bulk out in 其中之一
  （通常bulk in）会失败。qemu 设置50ms 超时，即使状态显示数据可用，bulk in
  也会超时。一bulk out 写会显示成功完成，但 ds2490 状态寄存器会显示写入了 0 字节  qemu ds2490 硬件分离再重新挂接会清除该问题。客户机和主机中usbmon 输出
  没有解释该问题。我猜测qemu 或主机操作系统中的一bug，更可能是主机操作系统
