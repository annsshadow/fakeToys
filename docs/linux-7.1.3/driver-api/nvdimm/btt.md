## BTT - 块转换表（Block Translation Table
## 1. 简
基于持久化内存（persistent memory）的存储能够以字节（更准确地说是缓存行）粒度执行 IO。然而，我们经常希望将此类存储作为传统的块设备暴露出来。持久化内存的块驱动程序正是这样做的。但是，它们不提供任何原子性保证。传SSD 通常借助电容中存储的能量在硬件层面提供针对撕裂扇区（torn sectors）的保护，以完成进行中的块写入，或者通过固件来实现。持久化内存则没有这种奢侈——如果一次写入正在进行中，而我们遭遇了断电，那么该块将包含新旧数据的混合。应用程序可能并未准备好处理这种情况
块转换表（BTT）为持久化内存设备提供原子扇区更新语义，从而使那些依赖扇区写入不被撕裂的应用程序能够继续如此工作。BTT 表现为一个堆叠的块设备，并为自身元数据保留底层存储的一部分空间。其核心是一张重定向表，对所有卷上的块进行重新映射。它可以被视作一个极其简单的文件系统，仅提供原子扇区更新
## 2. 静态布局

### b. BTT Flog

BTT 通过将每次写入都变为“分配式写入（allocating write）”来提供扇区原子性，即每次写入都写入一个“空闲”块。空闲块的运行时列表BTT flog 的形式维护。“Flog”是“free list（空闲列表）”与“log（日志）”两个词的结合。flog 包含“nfree”个条目，每个条目包含：

========  =====================================================================
lba       正在写入premap ABA
old_map   旧的 postmap ABA - 本次写入完成后，它将成为空闲块new_map   新的 postmap ABA。映射表将更新以反映	  lba->postmap_aba 映射，但我们在这里记录它以便需要时进行恢复seq	  序列号，用于标记flog 条目两个区段中哪一个有最新。在正常
	  操作中它01->10->11->01（二进制）之间循环，00 表示未初始化状态lba'	  备用lba 条目
old_map'  备用old postmap 条目
new_map'  备用new postmap 条目
seq'	  备用的序列号========  =====================================================================

上述每个字段均为 32 位，因此一个条目为 32 字节。条目还被填充到 64 字节，以避免缓存行共享或别名。对 flog 的更新保证：对于任何正在写入的条目，
a. 基于序列号覆盖条目中的“旧”区b. 写入“新”区段，并保证序列号最后写入
### c. 通道（lanes）的概念

虽然“nfree”描述了竞技场可以并发处理的 IO 数量，“nlanes”则BTT 设备作为一个整体可以处理的 IO 数量
```

	nlanes = min(nfree, num_cpus)

```
在任IO 开始时会获取一个通道号，并在IO 持续期间用于索引所有的磁盘与内存数据结构。如CPU 数量超过了可用通道的最大数量，则通道由自旋锁保护
### d. 内存数据结构：读取跟踪表（RTT
考虑这样一种情况：我们有两个线程，一个在读取，另一个在写入。我们可能会遇到这样的状况：写入线程抓取了一个空闲块来进行新IO，而（较慢的）读取线程仍正在从中读取。换言之，读取线程查阅了某个映射表项，并开始读取对应的块。一个写入线程开始向同一external LBA 写入，并完成写入，将external LBA 的映射表更新为指向其新的 postmap ABA。此时，读取线程（仍在）读取的内postmap 块已被插入空闲块列表。如果另一个写入针对同一LBA 到来，它就可能抓取这个空闲块并开始向其写入，从而导致读取线程读到错误的数据。为防止这种情况，我们引入了 RTT
RTT 是一张简单的、每个竞技场包含“nfree”个条目的表。每个读取线程将正在读取postmap ABA 插入 `rtt[lane_number]`，并在读取完成后清除它。每个写入线程在抓取空闲块之后，检RTT 中是否存在该块。如postmap 空闲块在 RTT 中，则等待读取线程清除该 RTT 条目，之后才开始写入
### e. 内存数据结构：映射表
考虑两个写入线程向同一 LBA 写入的情况。可能会
```

	free[lane] = map[premap_aba]
	map[premap_aba] = postmap_aba

```
两个线程都会用相同的旧、已释放postmap_aba 更新它们各自`free[lane]`。这会使布局变得不一致：丢失一个空闲条目，同时又是两个通道的空闲条目重复
为解决此问题，本可以使用一个单一的映射锁（每个竞技场）来在执行上述序列前获取，但我们觉得那可能争用过于激烈。因此我们改用一组（nfree 个）`map_locks`，以 `(premap_aba nfree)` 进行索引
### f. Flog 重建

启动时，我们分析 BTT flog 以创建空闲块列表。我们遍历所有条目，对每个通道，在一组两个可能的“区段”中，我们总是只看最新的那个（基于序列号）。重建规步骤很简单：

- 读取 map[log_entry.lba]- 如果 log_entry.new 与映射表项匹配，log_entry.old 为空闲- 如果 log_entry.new 与映射表项不匹配，则 log_entry.new 为空闲  （这种情况只能由断电/不安全关机引起）

## 4. 错误处理

如果任何元数据不可恢复地损坏（无论是由于 bug 还是介质错误），竞技场将处于错误状态。以下情况表明存在错误：

- 信息块校验和不匹配（且从副本恢复也失败）
- 所有内部可用块未被映射块与空闲块（来自 BTT flog）之和唯一且完整地寻址- flog 重建空闲列表时发现缺重复/不可能的条目
- 映射表项越界

如果遇到上述任一错误情况，该竞技场会被置于只读状态，使用信息块中的一个标志
## 5. 用法

BTT 可以设置libnvdimm 子系统（pmem blk 模式）暴露的任何磁盘（namespace）上。设置这样一namespace 最简单的方法是使`ndctl` 工具 [^1^]
```

    ndctl create-namespace -f -e namespace0.0 -m sector -l 4k

```
更多选项请参`ndctl create-namespace --help`
