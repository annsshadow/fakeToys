## 固件使用指南（Firmware Guidelines

切换到更新内核的用户**不应**需要安装更新的固件文件来让他们的硬件继续工作。同时，
更新的固件文件绝不能对使用更旧内核版本的用户的任何功能造成回归
使用来自 linux-firmware 的固件的驱动应遵循本指南中的规则。（在对固件控制有限情况下，即公司不支持 Linux、固件来自各处杂源时，这些规则当然不会严格适用。）

- 固件文件的设计应允许检查固ABI 版本的变化。建议固件文件至少带有主/次版本号
  进行版本化。建linux-firmware 中的固件文件以某个设备特定的名称、且仅以  版本号命名。固件版本应存储在固件头部中，或者作为例外，作为固件文件名的一部分  以便让驱动检测任何非 ABI 的修更改。linux-firmware 中的固件文件应被最新的
  兼容主版本覆盖。较新的主版本固件应与加载该主版本号的所有内核保持兼容
- 如果针对该硬件的内核支持通常是非激活的，或者该硬件尚未向公众提供，那么可以
  忽略这一点，直到第一个启用该硬件的内核版本发布。这意味着在不保留对较旧主版本  向后兼容性的情况下，不得进行主版本号的提升。次版本的提升不应引入较新内核非可  地依赖的新特性
- 如果一个安全修复需要固件与内核修复步调一致才能成功，那么linux-firmware
  仓库中、当前受支持stable/LTS 内核所要求的所有受支持主版本，都应使用该安  修复进行更新。内核补丁应当检测固件是否足够新，以声明该安全问题是否已修复。所  围绕安全修复的沟通都应同时指向固件与内核修复。如果安全修复需要弃用旧的主版本  那么这只能作为最后的选择，并且应在所有沟通中明确说明
- 影响用户 API（UAPI）的固件文件不得引入破坏现有用户空间程序的更改。对此类固件  更新必须确保与现有用户空间应用程序的向后兼容性。这包括维护用户空间程序所依赖  一致接口与行为
