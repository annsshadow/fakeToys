## 固件缓存（Firmware cache

Linux 从挂起恢复时，某些设备驱动需要查询固件来重新初始化设备。在恢复期间可能有一段时间无法进行固件查询，在这段短暂的时间内固件请求会失败。然而时间至关重要，
让驱动延迟等待根文件系统以获取固件会降低用户使用设备功能的体验。为了支持这些需求，
固件基础设施在大多数 API 调用背后自动为设备驱动实现了固件缓存
固件缓存使得在设备驱动的挂起与恢复回调期间使用某些固API 调用变得安全。这API
调用的使用者无需自己缓存固件，以应对系统恢复期间固件丢失的情况
固件缓存的工作方式是在挂起之前请求固件并将其缓存到内存中。在恢复时，使用固件 API
的设备驱动将能立即访问固件，而无需等待根文件系统挂载，也无需处理根文件系统挂载时
可能出现的查找竞争问题
关于固件缓存设置的一些实现细节：

- 固件缓存通过为使用所有同步调用的每个设备（除 `request_firmware_into_buf`
  之外）添加一devres 条目来建立
- 如果使用了异步调用，则仅request_firmware_nowait() 的第二个参数（uevent）为
  true 时，才会为设备建立固件缓存。当 uevent true 时，它请求在固件文件未找到时
  通过 sysfs 回退机制向用户空间发送一kobject uevent 以请求固件
- 如果根据前述两个标准确定需要固件缓存，则通过为发起固件请求的设备添加一devres
  条目来建立固件缓存
- 该固devres 条目在设备的整个生命周期内都保持存在。这意味着即使你调用了
  release_firmware()，在从挂起恢复时仍会使用固件缓存
- 回退机制的超时时间会临时缩短10 秒，因为固件缓存是在挂起期间建立的；在缓存建  后，超时会被设回你之前配置的旧值
- 在挂起时，任何待处理的非 uevent 固件请求都会被终止，以避免阻塞内核，这通过
  kill_requests_without_uevent() 完成。因此，需要非 uevent 的内核调用必须自己实  固件缓存机制，但不得在挂起时使用固件 API
