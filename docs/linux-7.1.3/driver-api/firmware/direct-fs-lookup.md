## 直接文件系统查找


直接文件系统查找是内核执行的固件查找中最常见的方式。内核在根文件系统的“固件搜索路径”一节所记录的路径上直接查找固件。文件系统查找在 fw_get_filesystem_firmware() 中实现，它使用通用核心内核文件加载设施 kernel_read_file_from_path()。允许的最大路径为 PATH_MAX——目前是 4096 个字符。

建议你将 /lib/firmware 路径保留在根文件系统上，避免为它们单独分区，以避免查找时可能出现的竞争，并避免使用下文记录的自定义回退机制。

### 固件与 initramfs


内置（built-in）到内核的驱动应该也将固件作为用于引导内核的 initramfs 的一部分集成进去，否则在加载驱动时真实根文件系统尚未就绪的情况下可能出现竞争。将固件塞入 initramfs 解决了这个竞争问题，但请注意，使用 initrd 不足以解决同样的竞争。

有些情况有理由不将固件纳入 initramfs，例如处理 remote-proc 子系统的大固件文件。对于这类情况，使用用户空间回退机制目前是唯一可行的解决方案，因为只有用户空间能够确切知道真实根文件系统何时已经就绪并挂载。
