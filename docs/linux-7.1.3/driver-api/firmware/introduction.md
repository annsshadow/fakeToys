## 简介


固件 API 使内核代码能够向用户空间请求功能所需的文件，
其用途多样：

- CPU 微码（microcode）用于修正 CPU 缺陷（errata）
- 设备驱动固件，需加载到设备微控制器上
- 设备驱动信息数据（校准数据、EEPROM 覆盖值），
  其中部分可完全为可选。

## 固件请求的类型


共有两类调用：

- 同步（Synchronous）
- 异步（Asynchronous）

使用哪一类取决于你的需求，不过经验法则是应尽量使用异步 API，
除非你已经在使用的异步初始化机制不会阻塞或延迟启动。即使加载
固件耗时不多，处理固件却可能耗时，这仍可能延迟启动或初始化，
因此诸如异步 probe 等机制有助于辅助驱动。
