## PXA/MMP - DMA 从设备控制器


## 约束


a) 传输热排提交并下发传输的驱动应当被授予这样的保证：即使在正在运行DMA 通道上，传输也被排队这意味着排队不等待前一次传输结束，并且描述符链接不仅发生在由传输结束触发的
irq/tasklet 代码中phy 上提交并下发的传输不等待 phy 停止再重启，而是提交到一正在运行的通道"上其他驱动，尤其是 mmp_pdma，在重新启动新传输之前会等待 phy 停止
b) 所有请求了确认的传输都应有信号
任何带有 DMA_PREP_INTERRUPT 下发的传输都应触发一次回调调用。这意味着即使 irq/tasklet
tx1 结束触发，但irq/dma 时刻 tx2 已经结束，也应调tx1->complete() tx2->complete()
c) 通道运行状驱动应当能够查询通道是否正在运行。对于多媒体情况，例如视频采集，如果提交了一次传输，
然后查询 DMA 通道报告"通道已停，则在该传输不应下发，直到下一帧开始中因此需要知道通道是处于运行状态还是停止状态
d) 带宽保证
PXA 架构4 个级别的 DMA 优先级：高、普通、低。高优先级获得的带宽是普通优先级的两倍，
普通优先级获得的带宽又是低优先级的两倍驱动应当能够请求一个优先级，尤其是pxa_camera 这样具有（大）吞吐量的实时驱动
## 设计


a) 虚拟通道
sa11x0 驱动中概念相同，即驱动被分配一个与请求者信号线相连虚拟通道"，而物DMA 通道在传输下发时动态分配
b) 分散/聚集传输的传输解

```

   +------------+-----+---------------+----------------+-----------------+
   | desc-sg[0] | ... | desc-sg[last] | status updater | finisher/linker |
   +------------+-----+---------------+----------------+-----------------+

```
该结构由 dma->sg_cpu 指向。描述符的使用如下：

    - desc-sg[i]：第 i 个描述符，将i sg 元素传输到视频缓冲区的分聚集

    - status updater
      传输单个 u32 到一个众所周知dma 一致性内存，以留下此传输已完成的痕迹      "众所周知"在每个物理通道上是唯一的，这意味着读取该值将告知当时最后一个完成的
      传输是哪个
    - finisher：ddadr=DADDR_STOP，dcmd=ENDIRQEN

    - linker：ddadr= desc-sg[^0^] of next transfer，dcmd=0

c) 传输热链假设正在运行的链是：

```

   Buffer 1              Buffer 2
   +---------+----+---+  +----+----+----+---+
   | d0 | .. | dN | l |  | d0 | .. | dN | f |
   +---------+----+-|-+  ^----+----+----+---+
                    |    |
                    +----+

```
在调dmaengine_submit(b3) 之后，链将看起来像：

```

   Buffer 1              Buffer 2              Buffer 3
   +---------+----+---+  +----+----+----+---+  +----+----+----+---+
   | d0 | .. | dN | l |  | d0 | .. | dN | l |  | d0 | .. | dN | f |
   +---------+----+-|-+  ^----+----+----+-|-+  ^----+----+----+---+
                    |    |                |    |
                    +----+                +----+

                                         new_link

```
如果在创new_link DMA 通道停止了，它_不_会被重启。热链接不打dma_async_issue_pending() 用于确保传输实际启动这一假设
这条规则的一个例外：

- 如果 Buffer1 Buffer2 的所有地址都是 8 字节对齐
- 并且如果 Buffer3 至少有一个地址不是 4 字节对齐
- 那么热链接无法发生，因为通道必须停止，必须设对齐，并重启通道。因此，这样
  的传tx_submit() 将被排队到已提交队列中，并且在这DMA 已在对齐模式下运行的
  特定情况
d) 传输完成更新每次一个通道上的传输完成时，可能会或可能不会生成中断，取决于客户端的请求。但在每情况下，传输的最后一个描述符，即"status updater"，将把最近完成的传输写入物理通道完成标记
这将加速残留量计算，对于像视频缓冲区这样持有约 6k 或更多描述符的大传输。这也允无需任何锁即可找出正在运行的 DMA 链中最近完成的传输
e) 传输完成、irq tasklet
当标记为 "DMA_PREP_INTERRUPT" 的传输完成时，会触发 dma irq。在该中断上，会为物通道调度一tasklet
tasklet 负责
- 读取物理通道最后的更新器标
- 根据该标记以及每个传输的标志，调用所有已完成的传输的回调

如果在处理过程中一个传输完成了，会触发 dma irq，并tasklet 将再次被调度，得到一个新更新器标记
f) 残留残留量的粒度将基于描述符。已下发但未完成的传输将针对当前正在运行的描述符扫描其所描述符
g) 驱动 tx 队列最复杂的情最棘手的情况是
 - 有未"acked"的传输（tx0
 - 驱动提交了一个对齐的 tx1，未链接

 - 驱动提交了一个对齐的 tx2 => tx2 被冷链接tx1

 - 驱动下发tx1+tx2 => 通道在对齐模式下运行

 - 驱动提交了一个对齐的 tx3 => tx3 被热链接

 - 驱动提交了一个未对齐tx4 => tx4 被放入已提交队列，未链接

 - 驱动下发tx4 => tx4 被放入已下发队列，未链接

 - 驱动提交了一个对齐的 tx5 => tx5 被放入已提交队列，未链接

 - 驱动提交了一个对齐的 tx6 => tx6 被放入已提交队列，冷链接tx5

 这转化为（在 tx4 下发之后）：

 - 已下发队
```

      +-----+ +-----+ +-----+ +-----+
      | tx1 | | tx2 | | tx3 | | tx4 |
      +---|-+ ^---|-+ ^-----+ +-----+
          |   |   |   |
          +---+   +---+
        - 已提交队      +-----+ +-----+
      | tx5 | | tx6 |
      +---|-+ ^-----+
          |   |
          +---+

```
- 已完成队列：
- 已分配队列：tx0

应该注意的是，在 tx3 完成之后，通道会停止，并重启为"未对齐模来处tx4
