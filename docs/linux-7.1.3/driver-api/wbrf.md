
## WBRF - WiFi 频段射频干扰（RFI）缓

由于某些平台设计上的电气和机械限制，GPU 显存时钟的相对高功率谐波有可能会与某WiFi 频段所使用的本地无线电模块频段发生干扰
为缓解可能的 RFI 干扰，生产者可以通告其正在使用的频率，而消费者可以利用这些信息，避免在敏感特性中使用这些频率
当平台已知其包含的任何设备存在此问题时，平台设计者将通过带有设备特定方法（_DSM）的 ACPI 设备来宣告该特性的可用性- 带有_DSM 的生产者将能够通告正在使用的频率- 带有_DSM 的消费者将能够注册以接收正在使用频率的通知
## 一些通用术语


Producer（生产者）：能够产生高功率射频的组件Consumer（消费者）：能够响应其他组件的射频，调整自身在用频率以缓解可能 RFI 的组件
为使该机制发挥作用，那些生产者应通告其特定频率的活跃使用情况，以便其他消费者在必要时做相应的内部调整，从而避免这种共振
## ACPI 接口


尽管最初用WiFi + dGPU 的场景，ACPI 接口可以扩展到平台设计者发现可能造成干扰的任何类型设备

## 使用示例


生产者的预期流程1. probe 期间，调`acpi_amd_wbrf_supported_producer` 检查该设备是否可以启用 WBRF2. 在使用某个频段时，以 'add' 参数调用 `acpi_amd_wbrf_add_remove`，以恰当通知其他消费者3. 或者在停止使用某个频段时，'remove' 参数调用 `acpi_amd_wbrf_add_remove`，以通知其他消费者
消费者的预期流程1. probe 期间，调`acpi_amd_wbrf_supported_consumer` 检查该设备是否可以启用 WBRF2. 调用 `amd_wbrf_register_notifier` 注册以接收来自其他生产者的频段变化（增加或移除）通知3. 在开始时调用 `amd_wbrf_retrieve_freq_band`，取回当前活跃的频段，这是因为某些生产者可能在消费者启动之前就广播了此类信息4. 在收到频段变化通知时，再次运行 `amd_wbrf_retrieve_freq_band` 取回最新的活跃频段5. 在驱动清理期间，调用 `amd_wbrf_unregister_notifier` 注销通知器
