## 部分奇偶校验日志（Partial Parity Log）


部分奇偶校验日志（PPL，Partial Parity Log）是 RAID5 阵列可用的一项特性。PPL 要解决的问题是：在异常关机（dirty shutdown）之后，某个条带（stripe）的奇偶校验可能与其余成员盘上的数据不一致。如果该阵列同时处于降级（degraded）状态，由于缺少其中一块盘，将无法重新计算奇偶校验。这会在重建阵列或以降级方式使用时导致静默数据损坏——对于在异常关机期间未被写请求触及的阵列块，由奇偶校验计算得出的数据可能是不正确的。这种情况被称为 RAID5 写洞（Write Hole）。因此，md 默认不允许启动一个脏的降级阵列。

一次写操作的部分奇偶校验是本此写未修改的条带数据块的 XOR。它刚好是足以从写洞中恢复所需的数据。将部分奇偶校验与已修改的块做 XOR，即可得到该条带的奇偶校验，且与写操作之前的状态一致，无论哪些块的写入已完成。如果该条带中某个未被修改的数据盘缺失，则可以用这份更新后的奇偶校验来恢复其内容。在异常关机后、所有磁盘均可用的情况下启动阵列时，也会执行 PPL 恢复，从而无需重新同步（resync）阵列。因此，同时使用写意图位图（write-intent bitmap）与 PPL 是不被支持的。

在处理写请求时，PPL 会在新数据与奇偶校验被分派到磁盘之前写入部分奇偶校验。PPL 是一个分布式日志——它存储在阵列成员盘的元数据区域中、特定条带的奇偶校验盘上。它不需要专用的日志盘。写性能最多降低 30%-40%，但它随阵列中磁盘数量而扩展，且日志盘不会成为瓶颈或单点故障。

与 raid5-cache（md 中用于填补写洞的另一种方案）不同，PPL 并非真正的日志。它不保护免于丢失在途数据，只保护免于静默数据损坏。如果某个条带的脏盘丢失，则不会对该条带执行 PPL 恢复（奇偶校验不更新）。因此，如果该盘丢失，条带中被写入的部分有可能包含任意数据。在这种情况下，其行为与普通的 raid5 相同。

PPL 可用于 md version-1 元数据以及外部（特别是 IMSM）元数据阵列。它可通过 mdadm 选项 --consistency-policy=ppl 启用。

PPL 对阵列中磁盘数量有最多 64 块的限制。这样可以使数据结构与实现保持简单。由于多盘同时失效风险较高，拥有如此多磁盘的 RAID5 阵列并不常见。这样的限制不应是一个现实中的限制。
