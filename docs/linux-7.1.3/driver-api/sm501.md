
## SM501 驱动


:Copyright: |copy| 2006, 2007 Simtec Electronics

Silicon Motion SM501 多媒体协处理器是一款多功能设备，可提供多种接口，包括
USB 主控制器、USB gadget、异步串行端口、音频功能以及双显示视频接口。该设备
可通过 PCI 或本地总线连接，并启用不同的功能。

### 核心


核心驱动位于 drivers/mfd，为管理具体硬件模块的驱动提供通用服务。这些服务
包括公共寄存器的锁保护、时钟控制以及资源管理。

核心通过 platform device 和 driver 系统为基于 PCI 与通用总线的芯片注册驱动。

在检测到设备时，核心会初始化芯片（可由 platform data 指定），然后将所选的
外设集合作为 platform device 导出给具体驱动。

核心复用了 platform device 系统，因为 platform device 系统已经提供了足够的
特性来支持这些驱动，无需再创建一种新的总线类型及其相关代码。


### 资源


每个外设对设备都有一个视图，该视图被隐式地限定为该外设正常工作所需的
特定资源集合。

集中的内存分配使驱动能够确保为视频子系统分配尽可能多的资源，因为视频子系统
是片上功能中对资源最敏感的部分。

内存分配的主要问题在于：一旦选定显示模式，视频缓冲区就难以移动。事实上，
当发生视频模式切换时，视频子系统的内存占用会随之变化。

由于视频内存在不改变显示的情况下难以移动（除非能为旧模式和新模式同时提供
足够的连续内存），视频驱动会充分利用分配给它的内存区域：将 fb0 对齐到区域
起始位置，将 fb1 对齐到区域末尾。中间剩余的内存用于加速功能，这些功能是
临时的，因此其位置不太关键，可以被移动。


### 配置


platform device 驱动使用一组 platform data 将配置传递给核心及附属驱动，
从而可以在单一内核镜像中支持多块搭载 SM501 的系统。

PCI 驱动假设 PCI 卡的行为符合 Silicon Motion 的参考设计。

存在一处影响 M1XCLK 与 M1CLK 频率选择的勘误（AB-5）。这两个时钟必须源自
同一个 PLL，尽管它们之后可以分别被分频。如果未如此设置，SM501 可能会锁死
并挂起整个系统。若 PLL 选择不同，驱动将拒绝加载。
