
#### USB 错误码


:Revised: 2004-Oct-21

本文档记录了（希望是）所有可能从 usbcore 返回的错误码及其解释。

其中一些由主机控制器驱动（HCDs）返回，设备驱动只能通过 usbcore 看到它们。一般来说，所有 HCD 的行为应当一致，仅在传输速度相关的特性以及某些故障的报告方式上存在差异。


## 由 :c:func:`usb_submit_urb` 返回的错误码


非 USB 特定的：


=============== ===============================================
0		URB 提交成功

`-ENOMEM`		没有可用于分配内部结构的内存
=============== ===============================================

USB 特定的：

=======================	=======================================================
`-EBUSY`			URB 已经处于活动状态。

`-ENODEV`			指定的 USB 设备或总线不存在

`-ENOENT`			指定的接口或端点不存在或未启用

`-ENXIO`			主机控制器驱动不支持对此类 urb 进行排队。（应视为主机控制器缺陷。）

`-EINVAL`			a) 指定的传输类型无效（或不被支持）
				b) 无效或不受支持的周期性传输间隔
				c) ISO：尝试更改传输间隔
				d) ISO：`number_of_packets` 小于 0
				e) 其他各种情况

`-EXDEV`			ISO：未指定 `URB_ISO_ASAP`，且 URB 本应被调度进入的所有帧都已过期。

`-EFBIG`			主机控制器驱动无法调度那么多 ISO 帧。

`-EPIPE`			URB 中指定的管道类型与端点的实际类型不匹配。

`-EMSGSIZE`			(a) 端点 maxpacket 大小为 0；在当前接口 altsetting 中不可用。
				(b) ISO 包大于端点的 maxpacket。
				(c) 请求的数据传输长度无效：负数或对主机控制器而言过大。

`-EBADR`			控制 URB 的 setup 包中的 wLength 值与 URB 的 transfer_buffer_length 不匹配。

`-ENOSPC`			该请求会超出为周期性传输（中断、等时）预留的 USB 带宽。

`-ESHUTDOWN`			设备或主机控制器因某个无法绕过的的问题而被禁用。

`-EPERM`			提交失败，因为设置了 `urb->reject`。

`-EHOSTUNREACH`		URB 被拒绝，因为设备处于挂起状态。

`-ENOEXEC`			控制 URB 不包含 Setup 包。
=======================	=======================================================

## 由 ``in urb->status`` 或 ``iso_frame_desc[n].status`` 返回的错误码（针对 ISO）


USB 设备驱动只能在完成处理程序中测试 urb 状态值。这是因为否则会出现竞争：HCD 在一个 CPU 上更新这些值，而设备驱动在另一个 CPU 上测试它们。

即使报告了错误，一次传输的 actual_length 也可能为正。这是因为传输通常涉及多个包，因此在一个错误停止进一步的端点 I/O 之前，可能已经有一个或多个包完成。

对于等时（isochronous）URB，只有当 URB 被取消链接、设备被移除、主机控制器被禁用，或者传输总长度小于请求长度且设置了 `URB_SHORT_NOT_OK` 标志时，urb 状态值才非零。等时 URB 的完成处理程序应只看到 `urb->status` 被设置为 0、`-ENOENT`、`-ECONNRESET`、`-ESHUTDOWN` 或 `-EREMOTEIO`。各个帧描述符的状态字段可能会报告更多的状态码。


===============================	===============================================
0				传输成功完成

`-ENOENT`			URB 被 `usb_unlink_urb` 同步取消链接

`-EINPROGRESS`		URB 仍在等待中，尚无结果
				（也就是说，如果驱动看到此值即为缺陷。）

`-EPROTO` [#f1]_, [#f2]_	a) 位填充（bitstuff）错误
				b) 在规定的总线周转时间内未收到响应包
				c) 未知的 USB 错误

`-EILSEQ` [#f1]_, [#f2]_	a) CRC 不匹配
				b) 在规定的总线周转时间内未收到响应包
				c) 未知的 USB 错误

				注意，控制器硬件通常无法区分 a)、b)、c) 几种情况，
				因此驱动无法判断是协议错误、响应失败（通常由设备断开引起）
				还是其他故障。

`-ETIME` [#f2]_		在规定的总线周转时间内未收到响应包。该错误也可能被报告为
				`-EPROTO` 或 `-EILSEQ`。

`-ETIMEDOUT`			同步 USB 消息函数使用此代码表示在传输完成前超时已过期，
				且主机控制器未报告其他错误。

`-EPIPE` [#f2]_		端点停滞（stalled）。对于非控制端点，使用
				`usb_clear_halt` 重置此状态。

`-ECOMM`			在 IN 传输期间，主机控制器从端点接收数据的速度快于写入系统内存的速度

`-ENOSR`			在 OUT 传输期间，主机控制器无法足够快地从系统内存检索数据
				以跟上 USB 数据速率

`-EOVERFLOW` [#f1]_	端点返回的数据量大于端点的 max packet 大小或剩余缓冲区大小。
				“Babble”（数据溢出）。

`-EREMOTEIO`		从端点读取的数据未填满指定缓冲区，且 `urb->transfer_flags`
				中设置了 `URB_SHORT_NOT_OK`。

`-ENODEV`		设备已被移除。通常在此之前会出现一连串其他错误，因为集线器驱动
				不会立即检测到设备移除事件。

`-EXDEV`		ISO 传输仅部分完成
				（仅在 `iso_frame_desc[n].status` 中设置，而不在 `urb->status` 中）

`-EINVAL`		ISO 异常，如果发生：注销并回家

`-ECONNRESET`		URB 被 `usb_unlink_urb` 异步取消链接

`-ESHUTDOWN`		设备或主机控制器因某个无法绕过的的问题（例如物理断开）而被禁用。
===============================	===============================================



   `-EPROTO`、`-EILSEQ` 和 `-EOVERFLOW` 这样的错误码通常表示硬件问题，例如不良设备（包括固件）或线缆。


   这也是各类主机控制器用来指示因设备断开而导致传输失败的多个代码之一。在集线器驱动开始断开处理之前的这段时间，设备可能会针对每个请求收到此类故障报告。



## 由 usbcore 函数返回的错误码



`usb_register`：

======================= ===================================
`-EINVAL`		注册新驱动时发生错误
======================= ===================================

`usb_get_**/usb_set_**()`、
`usb_control_msg`、
`usb_bulk_msg()`：

======================= ==============================================
`-ETIMEDOUT`		传输完成前超时已过期。
