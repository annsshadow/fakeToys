
#### 系统挂起期间 USB 设备的持久性


:Author: Alan Stern <stern@rowland.harvard.edu>
:Date: September 2, 2006 (Updated February 25, 2008)


## 问题是什么？


根据 USB 规范，当 USB 总线被挂起时，总线必须继续提供挂起电流（约 1-5 mA）。
这样设备才能保持其内部状态，并且集线器可以检测到连接变更事件（设备被插入或
拔出）。术语上称之为“电源会话”（power session）。

如果某个 USB 设备的电源会话被中断，系统就必须表现得如同该设备已被拔出一样。
这是一种保守的做法；在没有挂起电流的情况下，计算机无法得知实际发生了什么。
也许同一个设备仍然连接着，也许它已被移除并且端口上插入了另一个不同的设备。
系统必须做最坏的假设。

默认情况下，Linux 按照规范行事。如果 USB 主机控制器在系统挂起期间失去电力，
那么当系统唤醒时，挂接在该控制器上的所有设备都会被当作已断开连接处理。这始终
是安全的，也是“官方正确”的做法。

对于许多类型的设备，这种行为无关紧要。如果内核认为你的 USB 键盘在系统睡眠时
被拔出、而在系统唤醒时插入了一个新的键盘，谁会在意呢？你敲击它时它仍然能照常
工作。

遗憾的是，问题_确实_可能出现，尤其是对于大容量存储设备。其效果与设备真的在
系统挂起期间被拔出完全一样。如果你在该设备上挂载了文件系统，那你就倒霉了——
该文件系统中的一切现在都不可访问了。如果你的根文件系统位于该设备上，这就
尤其恼人，因为你的系统会立即崩溃。

电力丢失并不是唯一需要担心的原因。任何中断电源会话的机制都会产生相同的效果。
例如，即使系统睡眠期间可能维持了挂起电流，但在许多系统的唤醒初始阶段，固件
（即 BIOS）会复位主板的 USB 主机控制器。结果：所有电源会话都被销毁，又变得像
你拔掉了所有 USB 设备一样。没错，这完全是 BIOS 的错，但除非你能说服 BIOS 供应商
修复这个问题（祝你好运！），否则这对_你_没有任何好处。

在许多系统上，USB 主机控制器会在挂起到 RAM 后被复位。在几乎所有系统上，休眠
（也称为 swsusp 或挂起到磁盘）期间都没有可用的挂起电流。你可以在恢复后查看内核
日志，看是否发生了上述任一情况；查找写着 “root hub lost power or was reset” 的
行。

实际上，人们被迫在挂起前卸载 USB 设备上的任何文件系统。如果根文件系统位于 USB
设备上，系统根本无法挂起。（好吧，它_可以_被挂起——但它一旦唤醒就会崩溃，这并好
不了多少。)


## 解决方案是什么？


内核包含一项称为 USB-persist 的特性。它试图通过允许核心的 USB 设备数据结构在
电源会话中断期间保持持久，来规避这些问题。

它的工作方式如下。如果内核发现某个 USB 主机控制器在恢复期间不处于预期状态
（即，如果控制器被复位或以其它方式失去了电力），那么它会对该控制器下、且设置了
“persist”属性的每个 USB 设备应用一个持久性检查。它不会尝试恢复该设备；一旦电源
会话消失，这就无法奏效了。相反，它会发出一个 USB 端口复位，然后重新枚举该设备。
（这完全与每次 USB 设备被复位时发生的事情相同。）如果重新枚举显示现在连接到该
端口的设备与之前具有相同的描述符，包括厂商 ID 和产品 ID，那么内核将继续使用相同
的设备结构。实际上，内核把该设备当作仅仅是被复位而非被拔出一样对待。

如果主机控制器处于预期状态，但某个 USB 设备被拔出后又重新插入，或者某个 USB 设备
无法执行正常的恢复，也会发生同样的事情。

如果没有设备现在连接到该端口，或者描述符与内核记忆中的不同，那么处理方式正如你
所预期的。内核销毁旧的设备结构，并表现得如同旧设备已被拔出、而新设备被插入。

最终的结果是该 USB 设备仍然可用。文件系统挂载和内存映射不受影响，世界现在变得
美好而快乐。

注意，“USB-persist”特性只会应用于那些启用了它的设备。你可以通过以下方式启用
该特性
```

	echo 1 >/sys/bus/usb/devices/.../power/persist

```
其中“...”应填入设备的 ID。通过将 1 改为 0 来禁用该特性。对于集线器，该特性会被
自动且永久地启用，并且 power/persist 文件甚至不存在，所以你只需在真正重要的设备上
操心设置它。


## 这是最佳的解决方案吗？


也许不是。可以说，在设备断开连接期间跟踪已挂载文件系统和内存映射，应该由集中式的
逻辑卷管理器来处理。这样的解决方案可以让你插入一个 USB 闪存设备，创建一个与之
关联的持久卷，拔出闪存设备，稍后再插回来，仍然拥有与该设备相同的持久卷。因此，它
会比 USB-persist 影响更深远。

另一方面，编写一个持久卷管理器将是一项大工程，而且使用它需要用户大量的参与。这个
解决方案要快得多、也容易得多——而且它现在已经存在，这是它的一大优势！

此外，USB-persist 特性适用于_所有_ USB 设备，而不仅仅是大容量存储设备。它对其它
设备类型（例如网络接口）可能同样有用。


## 警告：USB-persist 可能很危险！！


在恢复被中断的电源会话时，内核会尽力确保 USB 设备没有被更换；也就是说，与之前
相同设备仍然插在端口上。但这些检查并不保证 100% 准确。

如果你用一个同类型的另一个设备（相同的制造商、相同的 ID 等）替换了一个 USB 设备，
内核极有可能检测不到这一变化。序列号字符串和其它描述符会与内核存储的值进行比较，但
这可能没有帮助，因为制造商经常完全省略其设备中的序列号。

此外，在更换介质的同时保持 USB 设备完全不变是相当有可能的。如果你在系统睡眠时更换
了 USB 读卡器中的闪存卡，内核将无从得知你做了这件事。内核会假设什么都没有发生，并
继续使用旧卡的 partition 表、inode 和内存映射。

如果内核以这种方式被蒙骗，几乎必然会导致数据损坏并使你的系统崩溃。这只能怪你自己。

对于那些设置了 avoid_reset_quirk 属性的设备，持久化可能会失败，因为它们在复位后
可能“变形”。

你已经收到警告了！风险自负！

话虽如此，大多数时候根本不应该有任何麻烦。USB-persist 特性可以极其有用。好好利用它。
