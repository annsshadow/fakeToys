
### 数字电视 Demux kABI


#### 数字电视 Demux


内核数字电视 Demux kABI 定义了一套驱动内部接口，用于把底层的、硬件相关的驱动注册到一个与硬件无关的 demux 层。它只对数字电视设备驱动开发者有用。该 kABI 的头文件名为 `demux.h`，位于 `include/media` 目录。

系统中的每个 demux 都应实现该 demux kABI。它用于选择 demux 的 TS 源并管理 demux 资源。当 demux 客户端通过该 demux kABI 分配一个资源时，会收到一个指向该资源 kABI 的指针。

每个 demux 的 TS 输入来自一个 DVB 前端或来自内存，具体通过此 demux kABI 设置。在拥有多个前端的系统中，该 kABI 可用于选择其中一个 DVB 前端作为某个 demux 的 TS 源，除非这在硬件平台上已经是固定的。

该 demux kABI 只控制前端与 demux 之间的连接关系；用于设置其他前端参数（例如调谐）的 kABI 由数字电视前端 kABI 定义。

实现抽象 demux 接口的函数应定义为 static 或模块私有，并注册到 Demux 核心以供外部访问。并不需要在 `dmx_demux` 结构体中实现每个函数。例如，某个 demux 接口可能支持 Section（段）过滤，但不支持 PES 过滤。kABI 客户端在调用函数前应检查任意函数指针的值：值为 `NULL` 表示该函数不可用。

每当 demux API 的函数修改共享数据时，都应考虑丢失更新和竞态条件问题，例如通过用互斥体（mutex）保护部分代码来解决。

注意，从下半部（bottom half）上下文调用的函数不能睡眠。即使是不使用 `GFP_ATOMIC` 的一次简单内存分配，如果需要交换（swapping），也可能导致内核线程被置为睡眠。例如，Linux 内核从下半部上下文调用网络设备的接口函数。因此，如果 demux kABI 函数是从网络设备代码调用的，该函数就不能睡眠。

#### Demux 回调 API


该内核空间 API 由把过滤后的数据递交给 demux 客户端的回调函数组成。与其他 DVB kABI 不同，这些函数由客户端提供，并由 demux 代码调用。

该抽象接口的函数指针不像其他 demux API 那样打包进一个结构体中，因为回调函数是彼此独立地注册和使用的。例如，API 客户端可以提供多个用于接收 TS 包的回调函数，而不提供任何用于 PES 包或段的回调。

实现回调 API 的函数不需要是可重入的：当 demux 驱动调用其中一个函数时，在该次调用返回之前，驱动不允许再次调用该函数。如果回调由硬件中断触发，建议使用 Linux 下半部机制，或启动一个 tasklet，而不是直接从硬件中断中调用回调函数。

该机制由 `dmx_ts_cb()` 和 `dmx_section_cb()` 回调实现。
