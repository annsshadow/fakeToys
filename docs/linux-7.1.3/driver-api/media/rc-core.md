
### 遥控器设备


#### 遥控器核心


遥控器核心实现了用于接收与发送遥控器键盘按键与鼠标事件的基础设施。

每次在遥控器上按下按键，都会产生一个扫描码（scan code）。此外，在大多数硬件上，
将某个键按住几十毫秒以上会产生一个重复按键事件。这在一定程度上类似于 Linux\ [#f1]_ 内部
对普通键盘或鼠标的处理方式。因此，遥控器核心实现于 linux input/evdev 接口之上。


   主要区别在于，对于键盘事件，键盘控制器会为按键按下产生一个事件，为按键释放产生
   另一个事件。而在基于红外线的遥控器上，没有按键释放事件。取而代之的是，会产生一个
   额外的码来指示按键重复。

然而，大多数遥控器使用红外（IR）来传输信号。由于调制红外信号使用了多种协议，核心的
一个重要部分致力于调整驱动与核心系统，以支持发射器所使用的红外协议。

红外传输通过用载波让红外发射器闪烁来完成。载波可由 IR 发射器硬件打开或关闭。当载波
打开时，称为 **PULSE**（脉冲）。当载波关闭时，称为 **SPACE**（间隔）。

换句话说，一个典型的 IR 传输可视为一系列 **PULSE** 与 **SPACE** 事件，每个事件带有给定的
时长。

载波参数（频率、占空比）以及 **PULSE** 与 **SPACE** 事件的间隔取决于协议。例如，NEC 协议
使用 38kHz 的载波，传输以 9ms 的 **PULSE** 与 4.5ms 的 SPACE 开始。随后传输 16 位扫描码，
其中 8 位为地址（对于给定遥控器通常是固定数值），接着 8 位为码。位 “1” 以 560µs 的
**PULSE** 后跟 1690µs 的 **SPACE** 调制，位 “0” 以 560µs 的 **PULSE** 后跟 560µs 的
**SPACE** 调制。

在接收端，可以使用一个简单的低通滤波器将接收到的信号转换为一系列 **PULSE/SPACE** 事件，
滤除载波频率。因此，接收器不关心载波的实际频率参数：它要做的只是测量接收 **PULSE/SPACE**
事件的时长。因此，带有此类接收器的简单 IR 接收器硬件只会向内核提供这些事件的时序序列。
带有此类接收器的硬件驱动由 `RC_DRIVER_IR_RAW` 标识，定义于 `rc_driver_type`\ [#f2]_。
其他硬件带有一个微控制器，用于解码 **PULSE/SPACE** 序列并向内核返回扫描码。此类接收器
由 `RC_DRIVER_SCANCODE` 标识。


   RC 核心也支持只有 IR 发射器、没有任何接收器的设备。目前，所有此类设备都只在
   原始 TX（raw TX）模式下工作。此类硬件标识为 `RC_DRIVER_IR_RAW_TX`。

当 RC 核心收到来自 `RC_DRIVER_IR_RAW` IR 接收器的事件时，它需要解码 IR 协议，以获得
对应的扫描码。RC 核心支持的协议定义于枚举 `rc_proto`。

当 RC 核心收到一个扫描码（无论是直接来自 `RC_DRIVER_SCANCODE` 类型的驱动，还是通过其
IR 解码器），它需要将其转换为一个 Linux 输入事件码。这是通过一张映射表完成的。

内核支持在大多数媒体设备上可用的映射表。它也支持在运行时通过一些 sysfs 节点加载
映射表。详见 RC 用户空间 API <Remote_controllers_Intro>。
