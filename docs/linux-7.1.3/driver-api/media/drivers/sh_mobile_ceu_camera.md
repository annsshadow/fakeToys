
## sh_mobile_ceu_camera 驱动中使用的裁剪与缩放算法


作者：Guennadi Liakhovetski <g.liakhovetski@gmx.de>

### 术语


sensor scales：传感器缩放，由传感器驱动配置的水平和垂直缩放
host scales：-"- 主机驱动
combined scales：sensor_scale * host_scale

在上图中，减号与斜杠代表“真实”数据量，点与圆点代表“有用”数据，即基本上是从客户端
源平面映射回来的 CEU 缩放并裁剪后的输出。

这样的配置可由用户请求产生：

S_CROP(left / top = (5) - (1), width / height = (5') - (5))
S_FMT(width / height = (6') - (6))

此处：

(1) 到 (1') - 整个最大宽度或高度
(1) 到 (2)  - 传感器裁掉左或上
(2) 到 (2') - 传感器裁掉的宽度或高度
(3) 到 (3') - 传感器缩放
(3) 到 (4)  - CEU 裁掉左或上
(4) 到 (4') - CEU 裁掉的宽度或高度
(5) 到 (5') - 应用到 CEU 裁掉的宽度或高度的逆向传感器缩放
(2) 到 (5)  - 应用到 CEU 裁掉左或上的逆向传感器缩放
(6) 到 (6') - CEU 缩放 - 用户窗口


### S_FMT


不要触碰输入矩形 - 它已经是最优的。

1. 计算当前传感器缩放：

	scale_s = ((2') - (2)) / ((3') - (3))

2. 计算“有效”输入裁剪（传感器子窗口）- 在当前的传感器缩放下将 CEU 裁剪缩放回输入窗口 -
   这就是用户 S_CROP：

	width_u = (5') - (5) = ((4') - (4)) * scale_s

3. 从“有效”输入窗口到请求的用户窗口计算新的组合缩放：

	scale_comb = width_u / ((6') - (6))

4. 通过对真实输入窗口应用组合缩放来计算传感器输出窗口：

	width_s_out = ((7') - (7)) = ((2') - (2)) / scale_comb

5. 对传感器输出窗口应用迭代的传感器 S_FMT。

	subdev->video_ops->s_fmt(.width = width_s_out)

6. 取回传感器输出窗口（g_fmt）

7. 计算新的传感器缩放：

	scale_s_new = ((3')_new - (3)_new) / ((2') - (2))

8. 计算新的 CEU 裁剪 - 对先前计算的“有效”裁剪应用传感器缩放：

	width_ceu = (4')_new - (4)_new = width_u / scale_s_new
	left_ceu = (4)_new - (3)_new = ((5) - (2)) / scale_s_new

9. 使用 CEU 裁剪裁剪到新窗口：

	ceu_crop(.width = width_ceu, .left = left_ceu)

10. 使用 CEU 缩放缩放到请求的用户窗口：

	scale_ceu = width_ceu / width


### S_CROP


V4L2 裁剪 API <crop-scale> 说明：

"...规范没有定义原点或单位。但按照惯例，驱动应相对于 0H 水平计数未缩放的采样。"

我们选择遵循该建议，并将裁剪单位解释为客户端输入像素。

裁剪按以下 6 个步骤执行：

1. 向传感器请求恰好为用户的矩形。

2. 如果更小 - 迭代直到获得更大的矩形。结果：传感器裁剪到 2 : 2'，目标裁剪 5 : 5'，
   当前输出格式 6' - 6。

3. 在上一步中，传感器已尽量保留其输出帧，但它可能已改变。再次取回它。

4. 传感器缩放到 3 : 3'。传感器的缩放为 (2' - 2) / (3' - 3)。计算中间窗口：
   4' - 4 = (5' - 5) * (3' - 3) / (2' - 2)

5. 计算并应用主机缩放 = (6' - 6) / (4' - 4)

6. 计算并应用主机裁剪：6 - 7 = (5 - 2) * (6' - 6) / (5' - 5)
