
设备与协议


CXL 设备的类型（内存、加速器等）决定了许多配置步骤。本节介绍设备类型以及平台与操作系统使用的设备端资源的一些基本背景，这些内容会影响配置。

协议


CXL 有三个核心协议。就本文档而言，我们仅讨论非常高层级的定义，因为具体的硬件细节在很大程度上对 Linux 是透明的。更多细节请参阅 CXL 规范。

CXL.io

基本的交互协议，类似于 PCIe 配置机制。通常用于初始化、配置，以及除内存（CXL.mem）或缓存（CXL.cache）操作之外的任何 I/O 访问。

Linux CXL 驱动通过各种 sysfs 接口和 /dev/cxl/ 设备（提供对设备邮箱的直接访问）暴露对 .io 功能的访问。

CXL.cache

设备可一致地访问并缓存主机内存的机制。

配置完成后对 Linux 基本透明。

CXL.mem

CPU 可一致地访问并缓存设备内存的机制。

配置完成后对 Linux 基本透明。


设备类型


Type-1


一个 Type-1 CXL 设备：

- 支持 cxl.io 与 cxl.cache 协议
- 实现完全一致的缓存
- 允许设备到主机的一致性以及主机到设备的窥探。
- 不具有主机管理的设备内存（HDM）

Type-1 设备的典型例子是智能网卡（Smart NIC）——它可能希望直接在主机内存（DMA）上操作以存储传入的数据包。这些设备主要依赖 CPU 附加的内存。

Type-2


一个 Type-2 CXL 设备：

- 支持 cxl.io、cxl.cache 与 cxl.mem 协议
- 可选地实现一致缓存与主机管理设备内存
- 通常是一个带有高带宽内存的加速器设备。

Type-1 与 Type-2 设备的主要区别在于是否存在主机管理的设备内存，该内存允许设备在本地内存区上操作——而 CPU 仍然对同一内存具有一致的 DMA 访问。

这使得 GPU 等设备可以通过 DAX 设备或文件描述符暴露其内存，允许驱动和程序直接访问设备内存，而无需使用块传输语义。

Type-3


一个 Type-3 CXL 设备

- 支持 cxl.io 与 cxl.mem
- 实现主机管理的设备内存
- 可提供易失性或持久化内存容量（或两者兼具）。

Type-3 设备的一个基本例子是简单的内存扩展器，其本地内存容量暴露给 CPU，以便通过基本的一致 DMA 直接访问。

Switch


CXL 交换机是一种能够在上游、下游或对等设备之间路由任何 CXL（以及扩展意义上的 PCIe）协议的器件。许多设备（例如多逻辑设备）都隐含了某种形式的交换。

逻辑设备与头


CXL 设备可呈现一个或多个“逻辑设备”给一个或多个主机（通过物理“头”）。

单逻辑设备（SLD）是向一个或多个头呈现单个设备的器件。

多逻辑设备（MLD）是可向一个或多个上游设备呈现多个设备的器件。

单头设备仅暴露单个物理连接。

多头设备暴露多个物理连接。

MHSLD

多头单逻辑设备（MHSLD）向多个头暴露单个逻辑设备，这些头可连接到一个或多个独立主机。一个简单的例子是内存池，它可以在启动前静态配置，以通过 [CEDT <../platform/acpi/cedt>](CEDT <../platform/acpi/cedt>) 将部分内存暴露给 Linux。

MHMLD

多头多逻辑设备（MHMLD）向多个头暴露多个逻辑设备，这些头可连接到一个或多个独立主机。一个例子是动态容量设备（Dynamic Capacity Device），它可以在运行时配置以将部分内存暴露给 Linux。

示例设备


Memory Expander

Type-3 设备最简单的形式是内存扩展器。内存扩展器将主机管理的设备内存（HDM）暴露给 Linux。该内存可以是易失性或非易失性（持久化）的。

内存扩展器通常被视为单头、单逻辑设备的一种形式——因为其外形通常是附加卡（AIC）或其他类似外形。

Linux CXL 驱动支持对基本内存扩展器进行静态或动态配置。平台可以在 OS 初始化之前对解码器进行编程（例如自动解码器），或者如果平台将这些操作推迟到 OS，则由用户对结构进行编程。

多个内存扩展器可以添加到外部机箱，并通过连接到 CXL 交换机的头暴露给主机。这就是“内存池”，根据交换机平台提供的管理能力，它被视为 MHSLD 或 MHMLD。

截至 v6.14，Linux 尚未提供用于管理非 DCD 的 MHSLD 或 MHMLD 设备的规范化接口。

Dynamic Capacity Device (DCD)


动态容量设备（DCD）是一种 Type-3 设备，提供对内存容量的动态管理。DCD 的基本理念是向“结构管理器”（Fabric Manager，一个外部、具有特权、可更改其他主机配置的主机）提供类似分配器的物理内存容量接口。

DCD 管理“内存范围”（Memory Extents），其可以是易失性或持久化的。范围也可以专属于单个主机，或在多个主机之间共享。

截至 v6.14，Linux 尚未提供用于管理 DCD 设备的规范化接口，但 LKML 上已有面向未来版本的相关工作进行中。
