## 简介（Introduction

I3C（读"eye-three-see"）是 MIPI 标准化的协议，旨在克I2C 的局（速度有限、中断需要外部信号、无法自动检测连接到总线上的设备等），同仍保持低功耗
## I3C 总线（I3C Bus

一I3C 总线由若I3C 设备组成，也可能包含一I2C 设备，但我们暂时
先关I3C 设备
I3C 总线上的 I3C 设备可以具有以下角色之一
- Master（主设备）：驱动总线的设备。它负责发起事务或决定谁被允许在
  总线上通信（I3C 中允许从设备生成事件，见下文）- Slave（从设备）：作为从设备，无法向总线上的另一个从设备发送帧。如  主设备允许，该设备仍可以主动向其发送事件
I3C 是一种多主（multi-master）协议，因此总线上可能存在多个主设备，但任一时刻只有一个设备可以作为主设备。为了获得总线所有权，主设备必须遵循
特定的流程
I3C 总线上的每个设备都必须被分配一个动态地址（dynamic address）才能进通信。在分配完成之前，设备只能响应有限的一组命令。如果它具有静态地址
（也称为 legacy I2C address，传I2C 地址），则该设备可以回复 I2C 传输
除了这些每设备地址之外，协议还定义了一个广播地址，用于寻址总线上的所设备
一旦为某设备分配了动态地址，该地址将用于与该设备的任何直接通信。注意，
即使在分配了动态地址之后，该设备仍应处理广播消息
## I3C 设备发现（I3C Device discovery

I3C 协议定义了一种机制，用于自动发现总线上存在的设备、它们的能力以及
它们提供的功能。在这方面，I3C 更接近像 USB 这样可发现的总线，而非 I2C SPI
该发现机制称DAA（Dynamic Address Assignment，动态地址分配），因为它不发现设备，还会为它们分配动态地址
DAA 过程中，每个 I3C 设备报告 3 项重要内容：

- BCR：Bus Characteristic Register（总线特性寄存器）。这8 位寄存器描述
  设备的与总线相关的能力- DCR：Device Characteristic Register（设备特性寄存器）。这8 位寄存器
  描述设备提供的功能- Provisioned ID：一48 位的唯一标识符。在给定总线上不应出Provisioned
  ID 冲突，否则发现机制可能失败
## I3C 从设备事件（I3C slave events

I3C 协议允许从设备自行生成事件，从而允许它们临时控制总线
该机制称IBI（In Band Interrupts，带内中断），正如其名称所示，它允设备在不依赖外部信号的情况下生成中断
DAA 过程中，总线上的每个设备都已被分配一个地址，该地址将作为优先级
标识符，用于决定当两个不同设备同时在总线上生成中断时谁获胜（动态地址
越小优先级越高）
主设备如果愿意，可以禁止中断。该禁止请求可以是广播的（适用于所有设备）也可以是发送给特定设备的
## I3C 热加入（I3C Hot-Join

Hot-Join（热加入）机制类似于 USB 热插拔。该机制允许从设备在主设备完总线初始化之后加入总线
它涵盖以下使用场景：

- 探测总线时设备未上电
- 设备通过扩展板热插到总线
该机制依赖于从设备事件来通知主设备有新设备加入了总线，并正在等待一动态地址
主设备随后可自由地按其意愿处理该请求：忽略它，或为从设备分配一个动地址
## I3C 传输类型（I3C transfer types

如果忽略 SMBus（它只是关于如何访问 I2C 设备所暴露寄存器的标准化），I2C
只有一种传输类型
除了为兼I2C 设备而保留的 I2C 传输之外，I3C 还定义了 3 类不同的传输
### I3C CCC 命令（I3C CCC commands

CCC（Common Command Code，通用命令码）命令用于任何与总线管理以及一设备共有的特性相关的事务
CCC 命令包含一个描述所执行命令8 CCC ID。该 ID 的最高位（MSB）指这是广播命令（bit7 = 0）还是单播（unicast）命令（bit7 = 1）
命令 ID 之后可以跟随一个有效载荷（payload）。根据命令的不同，该有效载荷
要么由发出命令的主设备发送（CCC 命令），要么由接收命令的从设备发（读 CCC 命令）。当然，读访问仅适用于单播命令。注意，当向特定设备发CCC 命令时，设备地址在有效载荷的第一个字节中传递
有效载荷长度不会在总线上显式传递，应从 CCC ID 中提取
注意，厂商可以使用一段专用的 CCC ID 范围用于其自有命令（0x61-0x7f 0xe0-0xef）
### I3C 私有 SDR 传输（I3C Private SDR transfers

私有 SDR（Single Data Rate，单数据速率）传输应用于任何设备相关且不需高传输速度的场景
它相当于 I2C 世界中的 I2C 传输。每次传输都传入设备地址（DAA 期间分配动态地址）、一个有效载荷和一个方向
I2C 唯一的区别在于传输快得多（典型时钟频率为 12.5MHz）
### I3C HDR 命令（I3C HDR commands

HDR 命令应用于任何设备相关且需要高传输速度的场景
附在 HDR 命令之后的第一项是 HDR 模式。I3C 规范目前定义3 种不同的模式
（更多细节请参阅规范）：

- HDR-DDR：Double Data Rate（双倍数据速率）模- HDR-TSP：Ternary Symbol Pure（纯三元符号）。仅可用于无 I2C 设备的总线
- HDR-TSL：Ternary Symbol Legacy（传统三元符号）。可用于I2C 设备的总线

发HDR 命令时，整条总线必须进入 HDR 模式，这通过广播 CCC 命令完成一旦总线进入特定HDR 模式，主设备便发HDR 命令。一HDR 命令由以部分组成
- 一16 位的大端（big endian）命令字
- N 16 位的大端数据
这些字可能被特定的前导码/后导码（preamble/postamble）包裹，这些取决于所HDR 模式，并在此处详述（更多细节请参阅规范）
16 位命令字由以下部分组成：

- bit[^15^]：方向位，读1，写0
- bit[14:8]：命令码。标识正在执行的命令、数据字的数量及其含- bit[7:1]：本命令所寻址设备I3C 地址
- bit[^0^]：保奇偶校验
## I2C 设备的向后兼容（Backward compatibility with I2C devices

I3C 协议被设计成I2C 设备向后兼容。这种向后兼容性允许在同一条总线混合连接 I2C I3C 设备，不过为了真正高效，I2C 设备应当配备 50 ns 毛刺（spike）滤波器
