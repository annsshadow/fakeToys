## PCA953x I²C GPIO 扩展器兼容性列表


:Author: Levente Révész <levente.revesz@eilabs.com>

我查阅了所有的数据手册，并创建了这份笔记，列出芯片功能与寄存器布局。

## 芯片概述


### 具有基本 4 个寄存器的芯片


这些芯片拥有 4 个寄存器组：input、output、invert 和 direction。每个
寄存器组包含 (lines/8) 个寄存器，每个 GPIO 端口对应一个。

寄存器组的偏移量始终是 2 的幂：

- 4 线  -> 寄存器组偏移为 1
- 8 线  -> 寄存器组偏移为 1
- 16 线 -> 寄存器组偏移为 2
- 24 线 -> 寄存器组偏移为 4
- 32 线 -> 寄存器组偏移为 4
- 40 线 -> 寄存器组偏移为 8

例如，具有 24 线的 GPIO 扩展器的寄存器布局：

+------+-----------------+--------+
| addr | function        | bank   |
+======+=================+========+
|  00  | input port0     |        |
+------+-----------------+        |
|  01  | input port1     | bank 0 |
+------+-----------------+        |
|  02  | input port2     |        |
+------+-----------------+--------+
|  03  | n/a             |        |
+------+-----------------+--------+
|  04  | output port0    |        |
+------+-----------------+        |
|  05  | output port1    | bank 1 |
+------+-----------------+        |
|  06  | output port2    |        |
+------+-----------------+--------+
|  07  | n/a             |        |
+------+-----------------+--------+
|  08  | invert port0    |        |
+------+-----------------+        |
|  09  | invert port1    | bank 2 |
+------+-----------------+        |
|  0A  | invert port2    |        |

     除了 pcal6534 之外，所有受支持的芯片都遵循此布局。

### 带有 LED 闪烁与亮度控制的芯片

## 功能概述


本节列出驱动已经支持的芯片功能，或者至少在多种芯片中通用的功能。

### 输入、输出、反相、方向


基本的 4 个 GPIO 功能在所有芯片类别中都存在，只有一个例外，即
`带有 LED 闪烁与亮度控制的芯片`_ 缺少 invert 寄存器。

这些寄存器使用了 3 种不同的布局：

    1. 寄存器组 0、1、2、3，寄存器组偏移为 2^n
        - 所有其他芯片

    2. 寄存器组 0、1、2、3，寄存器组紧密排列
        - pcal6534

    3. 寄存器组 0、5、1、4，寄存器组偏移为 2^n
        - pca9574
        - pca9575

### 中断


#### 仅含中断掩码寄存器

所有这些芯片使用相同的布局：

    1. 寄存器组 5，寄存器组偏移为 2^n
        - pca9505
        - pca9506
        - pca9698

#### 中断掩码与中断状态寄存器

在所有芯片中这些以相同的方式工作：mask 和 status 每个线对应一个比特，
mask 中为 1 表示中断已启用。

布局：

    1. 基址偏移 0x40，寄存器组 5 和寄存器组 6，寄存器组偏移为 2^n
        - pcal6408
        - pcal6416
        - pcal9535
        - pcal9554b
        - pcal9555a
        - pcal6524
        - tcal6408
        - tcal6416

    2. 基址偏移 0x30，寄存器组 5 和 6，寄存器组紧密排列
        - pcal6534

    3. 寄存器组 6 和 7，寄存器组偏移为 2^n
        - pca9574
        - pca9575

    4. 寄存器组 5 和 7，寄存器组偏移为 2^n
        - xra1202

#### 特定边沿上的中断

`带有扩展中断与输出配置功能的 PCAL 芯片`_ 具有 int_edge 寄存器。每个线
包含 2 个比特，可以为每个线选择 4 种事件之一：

    0：电平，1：上升沿，2：下降沿，3：任意边沿

布局：

    1. 基址偏移 0x40，寄存器组 7，寄存器组偏移为 2^n

        - pcal6524

    2. 基址偏移 0x30，寄存器组 7 + 偏移 0x01，寄存器组紧密排列
       （out_conf 为 1 字节，而非 (lines/8) 字节，因此有 0x01 偏移）

        - pcal6534

`XRA1202`_ 芯片对同样的功能采用了不同的机制：它们具有一个 rising mask
（上升沿掩码）和一个 falling mask（下降沿掩码），每个线对应一个比特。

布局：

    1. 寄存器组 5，寄存器组偏移为 2^n

### 输入锁存


仅 `基本 PCAL 芯片`_ 和 `带有扩展中断与输出配置功能的 PCAL 芯片`_ 具有
此功能。当锁存启用时，在读取输入端口之前中断不会被清除。当锁存禁用时，
即使未读取输入寄存器，只要输入引脚恢复到产生中断之前的电平值，中断也会
被清除。默认锁存禁用。

目前驱动为每条启用了中断的线启用锁存。

一个中断状态寄存器记录了哪些引脚触发了中断。然而，状态寄存器和输入端口
寄存器必须分别读取；没有原子机制可以同时读取二者，因此可能出现竞态。请
参阅 `中断源检测`_ 一章，了解其影响以及驱动如何仍然利用锁存特性。

    1. 基址偏移 0x40，寄存器组 2，寄存器组偏移为 2^n
        - pcal6408
        - pcal6416
        - pcal9535
        - pcal9554b
        - pcal9555a
        - pcal6524
        - tcal6408
        - tcal6416

    2. 基址偏移 0x30，寄存器组 2，寄存器组紧密排列
        - pcal6534

### 上拉与下拉


`基本 PCAL 芯片`_ 和 `带有扩展中断与输出配置功能的 PCAL 芯片`_ 使用相同
的机制：它们的 pull_en 寄存器启用上拉或下拉功能，它们的 pull_sel 寄存器
选择方向。它们都使用每个线一个比特。

    0：下拉，1：上拉

布局：

    1. 基址偏移 0x40，寄存器组 3（en）和 4（sel），寄存器组偏移为 2^n
        - pcal6408
        - pcal6416
        - pcal9535
        - pcal9554b
        - pcal9555a
        - pcal6524

    2. 基址偏移 0x30，寄存器组 3（en）和 4（sel），寄存器组紧密排列
        - pcal6534

`寄存器布局完全不同的 PCA957X 芯片`_ 具有一个 pull_sel 寄存器（每个线一个
比特），以及其 config 寄存器中的一个全局 pull_en 比特。

布局：

    1. 寄存器组 2（config），寄存器组 3（sel），寄存器组偏移为 2^n
        - pca9574
        - pca9575

`XRA1202`_ 芯片只能上拉。它们具有一个 pullup_en 寄存器。

布局：

    1. 寄存器组 4，寄存器组偏移为 2^n
        - xra1202

### 推挽与开漏


`带有额外 int_mask 和 out_conf 寄存器的芯片`_ 具有此功能，但仅针对选定的
IO 端口。寄存器每个 2 条线对应 1 个比特。在 pca9698 中，只有 port0 和
port1 具有此功能。

    0：开漏，1：推挽

布局：

    1. 基址偏移 5*bankoffset
        - pca9698

`基本 PCAL 芯片`_ 在一个单独的 out_conf 寄存器中每个端口对应 1 个比特。
只能配置整个端口。

    0：推挽，1：开漏

布局：

    1. 基址偏移 0x4F
        - pcal6408
        - pcal6416
        - pcal9535
        - pcal9554b
        - pcal9555a
        - tcal6408
        - tcal6416

`带有扩展中断与输出配置功能的 PCAL 芯片`_ 可以为每个线单独设置此项。它们
具有与 `基本 PCAL 芯片`_ 相同的按端口 out_conf 寄存器，但还拥有一个
indiv_out_conf 寄存器（每个线一个比特），它会反转按端口设置的效果。

    0：推挽，1：开漏

布局：

    1. 基址偏移 0x40 + 7*bankoffset（out_conf），
       基址偏移 0x60，寄存器组 4（indiv_out_conf），寄存器组偏移为 2^n

        - pcal6524

    2. 基址偏移 0x30 + 7*banksize（out_conf），
       基址偏移 0x54，寄存器组 4（indiv_out_conf），寄存器组紧密排列

        - pcal6534

此功能目前驱动尚不支持。

## 中断源检测


当被 GPIO 扩展器的中断触发时，驱动通过读取输入端口寄存器来确定哪些 IRQ
处于挂起状态。

为了能够对所有兼容设备上的特定中断事件进行过滤，驱动会跟踪各线先前的
输入状态，并且只为正确的边沿或电平发出 IRQ。该系统与所启用中断的数量
无关。即使事件发生在 GPIO 扩展器的中断与实际 I2C 读取之间，也不会丢失
事件。当然，如果在 I2C 读取之前相关信号电平已变回驱动先前保存的值，则
边沿可能会被漏掉。PCAL 变体正是出于这一原因提供了输入锁存功能。

### PCAL 输入锁存


PCAL 变体具有输入锁存，驱动为所有启用了中断的线启用此功能。只有在读取
输入端口时，中断才会被清除。这些变体提供了一个中断状态寄存器，记录哪些
引脚触发了中断，但状态寄存器和输入寄存器无法以原子方式读取。如果在读取
状态寄存器之后、但在采样输入端口寄存器之前，另一条线上发生了另一次中断，
该事件不会反映在先前的状态快照中，因此仅依赖中断状态寄存器是不够的。

因此，PCAL 变体也必须使用现有的电平变化逻辑。

对于短脉冲，当读取输入寄存器时会捕获第一个边沿，但如果在该读取之前信号
已恢复到先前的电平，则不会观察到第二个边沿。结果是，连续的脉冲在读取时
可能产生相同的输入值，从而检测不到电平变化，导致中断被漏掉。下面的时序
图展示了这种情况，其中顶部信号是

```
       │         │              │         │                │         │
       │         │              │         │                │         │
       └────────*┘              └────────*┘                └────────*┘
  Latched       │                        │                          │
                ▼                        ▼                          ▼
              READ 0                   READ 0                     READ 0
                                     NO CHANGE                  NO CHANGE

```
为了应对这种情况，中断状态寄存器指示的事件与通过现有电平变化逻辑检测到的
事件会被合并。结果是：

- 第二个边沿不可见的短脉冲，通过中断状态寄存器被检测到，并且
- 发生在状态读取与输入读取之间的中断，仍然被通用的电平变化逻辑捕获。

请注意，这仍然是最佳努力：状态寄存器和输入寄存器是分别读取的，其他线上的
短脉冲可能在这两次读取之间发生。此类脉冲仍可能被锁存为中断，而在读取时
不会留下可观察到的电平变化，并且可能无法归因于特定的边沿。这并不会比通用
路径降低检测能力，但反映了固有的原子性限制。
