## Linux 中使GPIO 

Linux 内核的存在是为了把硬件抽象并呈现给用户。GPIO 线本身通常不是面向用户的抽象使用 GPIO 线最显而易见、最自然也是最推荐的方式，是让内核硬件驱动来处理它们
关于已有的通用驱动示例（这些示例也是你希望编写的任何其他内核驱动的好范例），参Documentation/driver-api/gpio/drivers-on-gpio.rst

对于任何你想要支持的量产系统，例如服务器、笔记本、手机、平板、路由器，以及任何消费办公或商业产品，使用合适的核驱动至关重要。当你觉得代码足够成熟时，将其提交以纳入
上游 Linux 内核，你会获得帮助来完善它，参见 Documentation/process/submitting-patches.rst
Linux 中，GPIO 线也有用户空ABI
用户空间 ABI 面向一次性部署。例子包括原型、工厂产线、创客社区项目、车间样机、生产工具工业自动化、PLC 类型用例、门禁控制器，简言之，那些不是批量生产的专用设备，要求操作对设备有深入的了解，并知晓需要建立的软件-硬件接口。它们不应天然契合任何已有的内核子系统，
也不太适合作为操作系统，因为它们不够可复用或抽象，或者涉及大量与计算机硬件无关的策略
有充分理由从用户空间使用工业 I/O（IIO）子系统的应用程序，很可能也适合从用户空间使GPIO 线
在任何情况下都不要滥GPIO 用户空间 ABI 来在任何产品开发项目中走捷径。如果你用它做原型，
不要把原型产品化：请用合适的内核驱动重写它。在任何情况下都不要部署任何使用用户空间 GPIO
的统一产品
用户空间 ABI 是每GPIO 硬件单元（GPIO chip）的一个字符设备。这些设备会`/dev/gpiochip0` `/dev/gpiochipN` 的形式出现在系统中。如何直接使用用户空ABI 示例可在内核树的 `tools/gpio` 子目录中找到
对于结构化和受管理的应用程序，我们建议你使用 libgpiod_ 库。它提供辅助抽象、命令行工具以及对同一 GPIO chip 上多个并发消费者的仲裁
