
## vmcoreinfo 中可恢复硬件错误的跟踪


### 概述


该特性在内核中提供了一个通用基础设施，用于跟踪和记录可恢复的硬件错误。这些是可恢复的硬件错误，可见，可能不会立即导致 panic，但可能影响健康，主要是因为在内核中会执行新的代码路径。

通过将可恢复错误的计数和时间戳记录到 vmcoreinfo crash dump notes 中，该基础设施有助于事后崩溃分析工具将硬件事件与内核故障关联起来。这使得在硬件问题常见的超大规模云环境中，能够更快地进行分类并更好地理解根本原因。

### 收益


- 便于将可恢复的硬件错误与导致系统崩溃的内核 panic 或异常代码路径关联起来。
- 为运维人员和云提供商提供快速洞察，提高可靠性并减少排障时间。
- 作为对现有完整硬件诊断的补充，而非替代它们。

### 数据暴露与消费


- 被跟踪的错误数据由每类错误（error-type）的计数以及最近一次发生的时间戳组成。
- 该数据存储在 `hwerror_data` 数组中，按错误源类型分类，如 CPU、memory、PCI、CXL 等。
- 它通过 vmcoreinfo crash dump notes 暴露，可以使用 `crash`、`drgn` 或其他内核崩溃分析工具读取。
- 除了从崩溃转储中读取外，没有其他方式可以读取这些数据。
- 这些错误按区域划分，包括 CPU、Memory、PCI、CXL 等。

典型用法示例（在 drgn REPL 中）：


    >>> prog['hwerror_data']
    (struct hwerror_info[HWERR_RECOV_MAX]){
        {
            .count = (int)844,
            .timestamp = (time64_t)1752852018,
        },
        ...
    }

### 启用


- 当设置了 CONFIG_VMCORE_INFO 时启用此特性。
