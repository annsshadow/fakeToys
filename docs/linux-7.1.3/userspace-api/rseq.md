## 可重启序列（Restartable Sequences）


可重启序列允许注册一个每线程用户空间内存区域，用作内核与用户空间之间的 ABI，用于三个目的：

 - 用户空间可重启序列

 - 从用户空间快速访问读取当前 CPU 编号、节点 ID

 - 调度器时间片扩展

### 可重启序列（每 CPU 原子操作）


可重启序列允许用户空间对每 CPU 数据执行更新操作，而不需要重量级原子操作。实际 ABI 不幸地只在代码和 selftests 中提供。

### 快速访问 CPU 编号、节点 ID


允许高效地实现每 CPU 数据。文档在代码和 selftests 中。:(

### 优化的 RSEQ V2


在使用通用 entry 代码和通用 TIF 位的架构上，内核支持 RSEQ 的运行时优化，这也启用了诸如调度器时间片扩展等增强特性。

要启用它们，任务必须注册 RSEQ 区域，其长度至少为 getauxval(AT_RSEQ_FEATURE_SIZE) 所通告的长度。

如果现有的二进制以 RSEQ_ORIG_SIZE（32 字节）注册，内核会保留传统的低性能模式，以满足现有用户对于原始 RSEQ 实现行为的期望。

下表记录了传统模式与优化的 V2 模式的 ABI 和行为保证。

   :header-rows: 1

   - - Nr
     - 内容

     - 传统
     - 优化的 V2

   - - 1
     - cpu_id_start、cpu_id、node_id 和 mm_cid 字段（用户模式只读）
       .. 传统
     - 在每次上下文切换之后以及信号投递之前，由内核无条件更新
       .. 优化的 V2
     - 当且仅当它们发生变化时由内核更新，即如果任务被迁移或 mm_cid 发生变化

   - - 2
     - rseq_cs 临界区字段
       .. 传统
     - 在每次上下文切换之后以及信号投递之前，无条件地进行评估和处理的
       .. 优化的 V2
     - 仅当用户空间被中断并被调度出去，或在被中断的上下文中投递信号之前，才进行条件性的评估和处理

   - - 3
     - 只读字段
       .. 传统
     - 除调试模式外不严格执行
       .. 优化的 V2
     - 严格执行

   - - 4
     - membarrier(...RSEQ)
       .. 传统
     - 进程的所有运行线程都被中断，ID 字段被重写，最终活动的临界区在返回用户空间之前被中止。所有被调度出去的线程，无论是自愿与否，都被上面的 #1/#2 覆盖。
       .. 优化的 V2
     - 进程的所有运行线程都被中断，最终活动的临界区在返回用户空间之前被中止。ID 字段仅在因中断而发生变化的时才更新。所有被调度出去的线程，无论是自愿与否，都被上面的 #1/#2 覆盖。

   - - 5
     - 时间片扩展
       .. 传统
     - 不支持
       .. 优化的 V2
     - 支持

传统模式显然性能较低，因为它执行无条件的更新和临界区检查，即使 ABI 契约并不严格要求。这无法再更改，因为某些用户依赖于这种观察到的行为，而这反过来又使它们能够违反 ABI，并为自己的目的覆盖 cpu_id_start 字段。这显然是不被鼓励的，因为它使 RSEQ 与预期用途不兼容，并破坏了同一应用中其他库的期望。

符合 ABI 的优化 v2 模式尊重只读字段，不需要无条件的更新，因此性能要好得多。内核验证只读字段的合规性。如果用户空间修改了它们，进程将被杀死。合规的使用允许多个库在同一个应用中受益于 RSEQ 功能而互不干扰。符合 ABI 的优化 v2 模式还启用了扩展的 RSEQ 特性，如时间片扩展。


### 调度器时间片扩展


这允许线程在进入临界区时请求时间片扩展，以避免在线程在临界区内被调度出去时对资源产生争用。

此功能的先决条件是：

    - 在 Kconfig 中启用

    - 在引导时启用（默认启用）

    - 已为线程在优化的 V2 模式中注册了 rseq 用户空间指针

```

    prctl(PR_RSEQ_SLICE_EXTENSION, PR_RSEQ_SLICE_EXTENSION_SET,
          PR_RSEQ_SLICE_EXT_ENABLE, 0, 0);

```
prctl() 成功时返回 0，否则返回以下错误码：

========= ==============================================================
错误码      含义
========= ==============================================================
EINVAL	  功能不可用或函数参数无效。
          注意：arg4 和 arg5 必须为零
ENOTSUPP  功能已在内核命令行上被禁用
ENXIO	  可用，但未注册 rseq 用户结构
========= ==============================================================

```

  prctl(PR_RSEQ_SLICE_EXTENSION, PR_RSEQ_SLICE_EXTENSION_GET, 0, 0, 0);

```
prctl() 在启用时返回 `PR_RSEQ_SLICE_EXT_ENABLE`，禁用时返回 0。否则它返回以下错误码：

========= ==============================================================
错误码      含义
========= ==============================================================
EINVAL	  功能不可用或函数参数无效。
          注意：arg3、arg4 和 arg5 必须为零
========= ==============================================================

可用性和状态也通过 rseq ABI 结构体 flags 字段经由 `RSEQ_CS_FLAG_SLICE_EXT_AVAILABLE_BIT` 和 `RSEQ_CS_FLAG_SLICE_EXT_ENABLED_BIT` 暴露。这些位对用户空间是只读的，仅用于提供信息。

如果通过 prctl() 启用了该机制，线程可以通过设置 rseq
: slice_ctrl::request 为 1 来请求时间**片扩展**。如果线程被中断，且该中断导致内核中的重新调度请求，那么内核可以授予时间片扩展并返回用户空间，而不是调度出去。扩展的长度由 debugfs:rseq/slice_ext_nsec 决定。默认值是 5 微秒；这也是最小值。它可以增加到 50 微秒，但这样做可能会/将会影响最小调度延迟。

任何对此默认值的拟议更改都必须附带一个 selftest 和 rseq-slice-hist.py 的输出，以表明新值有其价值。

**内核通过设置 rseq**
: slice_ctrl::granted 为 1 来**指示授予**，同时清除 rseq
: slice_ctrl::request。如果在授予扩展后线程被重新调度，内核会清除 granted 位以向用户空间表明这一点。

如果离开临界区时 request 位仍然置位，用户空间可以清除它并继续。

如果 granted 位置位，那么用户空间在离开临界区时调用 rseq_slice_yield(2) 以 relinquish CPU。内核通过设置一个定时器来强制执行这一点，以防止行为不当的用户空间滥用此机制。

如果离开临界区时 request 位和 granted 位都为假，则表明授予被撤销，用户空间不需要进一步的操作。

```

    rseq->slice_ctrl.request = 1;
    barrier();  // 防止编译器重排
    critical_section();
    barrier();  // 防止编译器重排
    rseq->slice_ctrl.request = 0;
    if (rseq->slice_ctrl.granted)
        rseq_slice_yield();

```
由于这一切都是严格的 CPU 本地操作，因此没有原子性要求。
```

    if (rseq->slice_ctrl.granted)
      -> 中断导致调度和授予撤销
        rseq_slice_yield();

```
因此，假装这可以通过原子操作来解决是没有意义的。

如果线程在授予的时间片扩展内发出了 rseq_slice_yield(2) 之外的系统调用，授予也会被撤销，并且在进入内核时立即 relinquish CPU。这是必需的，因为当抢占模型为 NONE 或 VOLUNTARY 时，系统调用在到达调度点之前可能消耗任意的 CPU 时间，因此可能远远超出授予的时间。

用户空间首选的解决方案是使用 rseq_slice_yield(2)，它是无副作用的。支持任意系统调用是为了支持洋葱层架构（onion layer）的应用程序，其中处理临界区并请求时间片扩展的代码无法控制临界区内的代码。

内核强制标志一致性，如果检测到违规，将以 SIGSEGV 终止线程。
