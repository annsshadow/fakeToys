## 平台配置档选择（例如 /sys/firmware/acpi/platform_profile）


在现代系统中，平台的性能、温度、风扇及其他与硬件相关的特性通常可以动态调整。平台配置常常由某种自动机制（很可能位于内核之外）根据当前状况自动调整。

这些自动平台调整机制通常可以用若干平台配置档（platform profile）之一进行配置，偏向低功耗运行或偏向性能。

platform_profile 属性的目的是提供一个通用的 sysfs API，用于选择这些自动机制的平台配置档。

请注意，此 API 仅用于选择平台配置档，其目标并不在于监控由此产生的性能特征。性能监控最好使用设备或厂商专用的工具（例如 turbostat）来完成。

具体来说，在选择高性能配置档时，实际达到的性能可能受到多种因素的制约，例如：其他组件产生的热量、室温、笔记本电脑底部的自由气流等。此 API 的明确目标并不包括让用户空间了解任何阻碍达到所请求性能水平的次优条件。

由于单凭数字无法表达一个配置档将调整的多个变量（功耗、发热等），此 API 使用字符串来描述各个配置档。为了让用户空间获得一致的体验，sysfs-platform_profile ABI 文档定义了一组固定的配置档名称。驱动**必须**将其内部配置档表示映射到这组固定集合上。

如果在映射时没有合适的匹配，可以新增一个配置档名称。希望引入新配置档名称的驱动必须：

 1. 说明为何无法使用现有配置档名称。
 2. 将新配置档名称连同对其预期行为的清晰描述，加入 sysfs-platform_profile ABI 文档。

## “自定义”（Custom）配置档支持

platform_profile 类同时也支持声明“custom”配置档的驱动。当驱动中的设置被修改为某个标准配置档无法表示的当前状态时，应当设置该配置档。

## 多驱动支持

当系统上有多个驱动声明了平台配置档处理器（platform profile handler）时，平台配置档处理器核心只会向 `/sys/firmware/acpi` 接口公开所有驱动共同支持的那些配置档。

这是为了确保当并非所有处理器都支持某个配置档时，配置档名称的含义不会产生歧义。

各个驱动将注册一个 `platform_profile` 类设备，其语义与 `/sys/firmware/acpi/platform_profile` 接口类似。

用户可以通过读取该类设备的 `name` 属性来发现与某个平台配置档处理器相关联的驱动。

用户可以通过读取该类接口的 `choices` 属性来发现可用的配置档。

如果用户想为某个特定驱动选择配置档，可以向该驱动类设备的 `profile` 属性写入。

这将允许用户为同一系统上的不同驱动设置不同的配置档。如果各个驱动所选择的配置档不一致，平台配置档处理器核心将显示 `custom` 配置档，以表明这些配置档并不相同。

在 `platform_profile` 属性的值为 `custom` 期间，向平台配置档处理器核心的 platform_profile 属性写入来自 `platform_profile_choices` 的某个公共配置档，将为所有驱动设置该配置档。
