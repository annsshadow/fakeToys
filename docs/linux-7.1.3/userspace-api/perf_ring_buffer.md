## 1. 简


环形缓冲区是数据传输的基础机制。perf 使用环形缓冲区将事件数据从内
传输到用户空间，另一种被称为辅助（AUX）环形缓冲区的环形缓冲区，在
配合 Intel PT、Arm CoreSight 等进行硬件追踪时也起着重要作用

环形缓冲区的实现至关重要，但它同时也是一项极具挑战的工作。一方面
内核与用户空间中perf 工具使用环形缓冲区来交换数据并存入数据文件，
因此环形缓冲区需要以高吞吐量传输数据；另一方面，缓冲区的管理应避免
显著的额外开销，以免干扰性能剖析结果

本文档深入探perf 环形缓冲区的实现细节，分为两个部分：首先解释 perf
环形缓冲区的实现，然后第二部分讨AUX 环形缓冲区的机制

## 2. 环形缓冲区实


### 2.1 基本算法


通常，一个典型的环形缓冲区由头指针（head pointer）和尾指针（tail
pointer）管理；头指针由写入者操作，而尾指针则由读取者分别更新

```

        +---------------------------+
        |   |   |***|***|***|   |   |
        +---------------------------+
                `-> Tail    `-> Head

        * : 由写入者填充的数据

                Figure 1. 环形缓冲

```
Perf 采用相同的方式来管理其环形缓冲区。在实现中，有一组连续页面共
保存着两个关键数据结构：控制结构，以及环形缓冲区本身。保存控制结构的
页面被称为“用户页”（user page）。连续虚拟地址的布局简化了定位环形
缓冲区地址的过程，它位于用户页所在页面之后的那些页面中

控制结构名为 `perf_event_mmap_page`，它包含一个头指针 `data_head`
和一个尾指针 `data_tail`。当内核开始将记录填入环形缓冲区时，它会更
头指针来预留内存，以便稍后能安全地将事件存入缓冲区。另一方面，当用户
页是可写映射时，perf 工具有权在从环形缓冲区消费数据后更新尾指针。还
一种情况是针对用户页的只读映射，这将在 writing_samples_into_buffer
一节中说明

```

          user page                          ring buffer
    +---------+---------+   +---------------------------------------+
    |data_head|data_tail|...|   |   |***|***|***|***|***|   |   |   |
    +---------+---------+   +---------------------------------------+
        `          `----------------^                   ^
         `----------------------------------------------|

              * : 由写入者填充的数据

                Figure 2. Perf 环形缓冲

```
使用 `perf record` 工具时，可以通过 `-m` `--mmap-pages=` 选项指定
环形缓冲区大小，给定的大小会被向上取整为页大小倍数2 的幂。虽然内
会一次性分配所有内存页，但将这些页面映射到 VMA 区域会延迟到 perf 工具
从用户空间访问缓冲区时才进行。换言之，perf 工具在用户空间首次访
缓冲区的某一页时，会触发一个页错误的缺页异常，内核借此机会将该页映射到
进程VMA 中（参见 `perf_mmap_fault()`），从而在异常返回perf 工具
可以继续访问该页

### 2.2 不同追踪模式下的环形缓冲


perf 以多种模式对程序进行剖析：默认模式、每线程模式、每 CPU 模式以及
系统范围模式。本节描述这些模式以及环形缓冲区如何满足它们的需求。最
我们将审视这些模式所引起的竞态条件

##### 2.2.1 默认模式


通常我们执行 `perf record` 命令并后接一个被剖析的程
```

        perf record test_program

```

##### 2.2.2 每线程模


通过perf 命令中指`--per-thread` 选项，例如：

```

        perf record --per-thread test_program

```
perf 事件不会映射到任CPU，而只绑定
```

    evsel::threads::map[] = { pid }
    evsel::attr::inherit  = 0

```

并在下一CPU 上相应地启用事件

                Figure 4. 每线程模式下的环形缓冲区

### 2.3 访问缓冲


基于对环形缓冲区如何在各种模式下被分配的理解，本节解释如何访问环
缓冲区

##### 2.3.1 生产消费者模


Linux 内核中，PMU 事件可以产生采样并存储到环形缓冲区中；用户空间中
perf 命令通过从环形缓冲区读出数据来消费采样，并最终将数据存入文件以便
后续分析。这是使用环形缓冲区的一个典型生产消费者模型

perf 进程轮询 PMU 事件，在无事件到来时睡眠。为了防止内核与用户空间之间
频繁交换，内核事件核心层引入了一个水位线（watermark），*存储
``perf_buffer** : watermark``。当采样被记录到环形缓冲区中，且已用
缓冲区超过水位线时，内核会唤perf 进程从环形缓冲区读取采样

```

                       Perf
                       / | 读取采样
             Polling  /  `--------------|               Ring buffer
                     v                  v    ;---------------------v
    +----------------+     +---------+---------+   +-------------------+
    |Event wait queue|     |data_head|data_tail|   |***|***|   |   |***|
    +----------------+     +---------+---------+   +-------------------+
             ^                  ^ `------------------------^
             | 唤醒任务         | 存储采样
          +-----------------------------+
          |  Kernel event core layer    |
          +-----------------------------+

              * : 由写入者填充的数据

                Figure 7. 环形缓冲区的写入与读

```
当内核事件核心层通知用户空间时，由于多个事件可能共享同一个环形缓冲区
来记录采样，核心层会遍历与该环形缓冲区关联的每个事件，并唤醒等待在该
事件上的任务。这由内核函`ring_buffer_wakeup()` 完成

perf 进程被唤醒后，开始逐个检查环形缓冲区，如果发现某个环形缓冲区中包
采样，就会读出这些采样以进行统计或存入数据文件。由perf 进程可以
任意 CPU 上运行，这导致环形缓冲区可能被多CPU 同时访问，从而引发竞
条件。竞态条件的处理memory_synchronization 一节中描述

##### 2.3.2 环形缓冲区的特


Linux 内核支持环形缓冲区的两种写入方向：正向（forward）与反向
（backward）。正向写入从环形缓冲区的起始处保存采样，反向写入则以相反
方向从环形缓冲区的末尾存储数据。perf 工具决定写入方向

此外，该工具可以以读写模式或只读模式将缓冲区映射到用户空间

读写模式下的环形缓冲区以属`PROT_READ | PROT_WRITE` 映射。借助写权限，
perf 工具更新 `data_tail` 以指示数据的起始位置。结合作为当前数据结
位置的头指针 `data_head`，perf 工具可以很容易地知道从哪里读出数据

相反，在只读模式下，只有内核持续更新 `data_head`，而用户空间由于映
属`PROT_READ` 的原因无法访`data_tail`

因此，下面的矩阵展示了方向与映射特性的各种组合。perf 工具采用其中的两
组合来支持缓冲区类型：非覆写（non-overwrite）缓冲区和可覆写（overwritable
缓冲区

   :widths: 1 1 1
   :header-rows: 1

   - - 映射模式
     - 正向
     - 反向
   - - 读写
     - 非覆写环形缓冲区
     - 未使
   - - 只读
     - 未使
     - 可覆写环形缓冲区

非覆写环形缓冲区使用读写映射配合正向写入。它从环形缓冲区的起始处开
保存数据，并在溢出时回绕，这与普通环形缓冲区中的读写模式一起使用。当
消费者跟不上生产者时，会丢失部分数据，内核会记录它丢弃了多少条记录，
并在下一次在环形缓冲区中发现空闲空间时生`PERF_RECORD_LOST` 记录

可覆写环形缓冲区使用只读模式配合反向写入。它从环形缓冲区的末尾保存数据，
`data_head` 保持当前数据的位置，perf 始终知道它从何处开始读取直到环
缓冲区的末尾，因此它不需`data_tail`。在此模式下，它不会生成
`PERF_RECORD_LOST` 记录


##### 2.3.3 向缓冲区写入采样


当一次采样被采集并保存到环形缓冲区时，内核根据采样类型准备采样字段；
然后它准备用于写入环形缓冲区的信息，该信息存储在 `perf_output_handle`
结构中。最后，内核将采样输出到环形缓冲区，并更新用户页中的头指针，以便
perf 工具能看到最新的值

`perf_output_handle` 结构充当一个临时上下文，用于跟踪与缓冲区相关的
信息。它的优势在于使不同事件能够并发写入缓冲区。例如，一个软件事件和
一个硬PMU 事件同时被启用进行剖析，两个 `perf_output_handle` 实例分别
作为软件事件和硬件事件的独立上下文。这使得每个事件都能预留自己的内
空间来填充记录数据

##### 2.3.4 从缓冲区读取采样


在用户空间中，perf 工具利用 `perf_event_mmap_page` 结构来处理缓冲区
头与尾。它还使`perf_mmap` 结构来跟踪环形缓冲区的一个上下文，该上下
包含缓冲区起始与结束地址的信息。此外，掩码值可用于计算循环缓冲区指针，
即便发生溢出也是如此

与内核类似，用户空间perf 工具首先读出环形缓冲区中已记录的数据，然
更新缓冲区的**尾指``perf_event_mmap_page** : data_tail``


##### 2.3.5 内存同步


采用宽松内存模型的现CPU 无法保证内存访问顺序，这意味着访问环形
缓冲区和 `perf_event_mmap_page` 结构可能乱序进行。为了保证访perf 环形
缓冲区内存的特定顺序，使用了内存屏障（memory barrier）来保证数据依赖
使用内存屏障的原理依据如
```

  Kernel                          User space

  if (LOAD ->data_tail) {         LOAD ->data_head
                   (A)            smp_rmb()        (C)
    STORE $data                   LOAD $data
    smp_wmb()      (B)            smp_mb()         (D)
    STORE ->data_head             STORE ->data_tail
  }

```
tools/include/linux/ring_buffer.h 中的注释很好地描述了为何以及如何使用
内存屏障，这里我们仅给出另一种解释：

(A) 是一个控制依赖，因此 CPU 保证了检*指针
``perf_event_mmap_page** : data_tail`` 与将采样填入环形缓冲区之间的顺序

(D) (A) 配对D) 将环形缓冲区数据读取与写入指`data_tail` 分离开来，
perf 工具先消费采样，然后告知内核该数据块已被释放。由于读取操作之后紧
写入操作，因(D) 是一个完全内存屏障

(B) 是两个写入操作中间的写入屏障，它确保记录采样必须先于更新头指针

(C) (B) 配对C) 是一个读取内存屏障，用于确保先获取头指针再读取采样

为了实现上述算法，内核中引入`perf_output_put_handle()` 函数，用户空
中引入了两个辅助函数 `ring_buffer_read_head()` `ring_buffer_write_tail()`
它们依赖上述内存屏障来保证数据依赖

某些架构支持使用 load-acquire store-release 操作的单向可穿透屏障，这些
屏障更为宽松，性能开销更小，因(C) (D) 可以分别优化为使`smp_load_acquire()`
`smp_store_release()` 屏障

如果某个架构的内存模型不支持 load-acquire store-release，它将回退
旧式的内存屏障操作。在这种情况下，`smp_load_acquire()` 封装
`READ_ONCE()` + `smp_mb()`，由`smp_mb()` 开销较大，`ring_buffer_read_head()`
不会调用 `smp_load_acquire()`，而是使用 `READ_ONCE()` + `smp_rmb()` 屏障

## 3. AUX 环形缓冲区的机制


在本章中，我们将解释 AUX 环形缓冲区的实现。第一部分讨论 AUX 环形缓冲
与常规环形缓冲区之间的联系，然后第二部分考察 AUX 环形缓冲区如何与常规
环形缓冲区协同工作，以及 AUX 环形缓冲区为采样机制带来的额外特性

### 3.1 AUX 与常规环形缓冲区的关


一般而言，AUX 环形缓冲区是常规环形缓冲区的辅助。常规环形缓冲区主要用于
存储事件采样，且每种事件格式都符合联合体 `perf_event` 中的定义；AUX 环形
缓冲区用于记录硬件追踪数据，而追踪数据的格式依赖于硬IP

AUX 环形缓冲区的一般用途和优势在于，它由硬件直接写入，而非由内核写入
例如，写入常规环形缓冲区的常规剖析采样会引发一次中断。追踪执行需要大
采样，而使用中断对常规环形缓冲区机制来说会不堪重负。拥有一AUX 缓冲
可以提供一块与内核解耦程度更高、且由硬件追踪直接写入的内存区域

AUX 环形缓冲区在缓冲区管理上复用了与常规环形缓冲区相同的算法。控制结
`perf_event_mmap_page` AUX 环形缓冲区的头、尾指针扩展了新字段 `aux_head`
鍜?`aux_tail`銆。

在初始化阶段，除mmap() 映射的常规环形缓冲区外，perf 工具还在
`auxtrace_mmap__mmap()` 函数中以非零文件偏移量发起第二次系统调用mmap
AUX 缓冲区；内核中的 `rb_alloc_aux()` 相应地分配页面，这些页面会被延迟
处理页错误时再映射到 VMA，这与常规环形缓冲区采用相同的惰性机制

AUX 事件AUX 追踪数据是两件不同的事。请看一个示
```

        perf record -a -e cycles -e cs_etm// -- sleep 2

```
上述命令启用了两个事件：一个来PMU 的事**cycles**，另一个是来自 Arm
CoreSight AUX 事件 **cs_etm**，二者都保存到常规环形缓冲区，CoreSight
AUX 追踪数据则存储在 AUX 环形缓冲区中

因此，我们可以看到常规环形缓冲区AUX 环形缓冲区是成对分配的。perf 
默认模式下按 CPU 分配常规环形缓冲区和 AUX 环形缓冲区，这与系统范围模式
相同，不过默认模式只为被剖析程序记录采样，而后者则对系统中所有程序进
剖析。对于每线程模式，perf 工具在整个会话期间只为线程分配一个常规环
缓冲区和一AUX 环形缓冲区。对于每 CPU 模式，perf 为选项 `-C` 指定
所CPU 分配两类环形缓冲区

### 3.2 AUX 事件


`perf_output_begin()` `perf_output_end()` 对常规环形缓冲区的作
类似，`perf_aux_output_begin()` `perf_aux_output_end()` 服务AUX 环形
缓冲区，用于处理硬件追踪数据

一旦硬件追踪数据被存入 AUX 环形缓冲区，PMU **驱动将调``pmu**
: stop()`` 回调来停止硬件追踪* 与常规环形缓冲区类似，AUX 环形缓冲
需要应memory_synchronization 一节中讨论的内存同步机制。由AUX 环形
缓冲区由 PMU 驱动管理，屏(B)（即一个写入屏障，用于确保追踪数据在更新头
指针之前对外可见）需要在 PMU 驱动中实现

**然后 ``pmu** : stop()` 可以安全地调`perf_aux_output_end()`` 函数来完成两件事

- 它向常规环形缓冲区填入一`PERF_RECORD_AUX` 事件，该事件传递一段已存入
  AUX 环形缓冲区的硬件追踪数据的起始地址与数据大小信息；

- 由于硬件追踪驱动已将新的追踪数据存入 AUX 环形缓冲区，参数 **size** 表示
  硬件追踪已消费了多少字节，因`perf_aux_output_end()` 更新头指
  `perf_buffer::aux_head` 以反映最新的缓冲区使用情况

最后，PMU 驱动会重新启动硬件追踪。在这段临时挂起期间，会丢失硬件追踪数据
这将在解码阶段引入不连续性

事件 `PERF_RECORD_AUX` 表示一个在内核中处理的 AUX 事件，但它缺少在 perf 文件
中保AUX 追踪数据所需的信息。当 perf 工具将追踪数据从 AUX 环形缓冲区复制到
perf 数据文件时，它会综合出一`PERF_RECORD_AUXTRACE` 事件，该事件并非内核
ABI，它perf 工具定义，用于描AUX 环形缓冲区中哪一部分数据被保存。此后，
perf 工具根据 `PERF_RECORD_AUXTRACE` 事件perf 文件中读AUX 追踪数据，
`PERF_RECORD_AUX` 事件则用于按时间顺序关联来解码一段数据

### 3.3 快照模式


perf 支持 AUX 环形缓冲区的快照模式，在此模式下，用户仅在感兴趣的特定时
点记AUX 追踪数据。例如，下面给出了如何获取快照的示例
```

  perf record -e cs_etm//u -S -a program &
  PERFPID=$!
  while true; do
      kill -USR2 $PERFPID
      sleep 1
  done

```
快照模式的主要流程如下：

- 在获取快照之前，AUX 环形缓冲区处于自由运行（free run）模式。在自由运行
  模式下，perf 不会记录任何 AUX 事件和追踪数据；

- 一perf 工具收到 **USR2** 信号，它会触发回调函
  `auxtrace_record::snapshot_start()` 来停用硬件追踪。内核驱动随后将硬件
  追踪数据填充AUX 环形缓冲区中，并`PERF_RECORD_AUX` 事件存入常规环形
  缓冲区；

- 然后 perf 工具进行快照，`record__read_auxtrace_snapshot()` AUX 环形
  缓冲区读出硬件追踪数据并保存perf 数据文件

- 快照完成后，`auxtrace_record::snapshot_finish()` 重新启动用于 AUX 追踪
  PMU 事件

**perf 在快照模式下只访问头指针 ``perf_event_mmap_page**
: aux_head``，而不触碰尾指`aux_tail`，这是因AUX 环形缓冲区在自由运行
模式下可能溢出，尾指针在这种情况下是无用的。作为替代，引入了回
**``auxtrace_record** : find_snapshot()`` 用于判断 AUX 环形缓冲区是否已
回绕，最终它修正 AUX 缓冲区的头，该头用于计算追踪数据的大小

如我们所知，缓冲区的部署可以是每线程模式、每 CPU 模式或系统范围模式，
快照可应用于其中任意一种模式。下面是对系统范围模式进行快照的示例
