


######## 通用错误码（Generic Error Codes


    :header-rows:  0
    :stub-columns: 0
    :widths: 1 16


    - -  `EAGAIN`（即 `EWOULDBLOCK`
       - ioctl 无法被处理，因为设备处于无法执行它的状态。例如这可能发生在设	 正在睡眠、ioctl 被用来查询统计信息时。当 ioctl 需要等待某个事件，	 设备是以非阻塞模式打开时，也会返回它
    - -  `EBADF`

       - 文件描述符无效
    - -  `EBUSY`

       - ioctl 无法被处理，因为设备正忙。这通常会在设备正在流传输、ioctl
	 试图更改会影响该流、或需要使用已被分配的硬件资源时返回。ioctl 不能
	 在未先执行其它操作修复问题的情况下重试（典型情况：在重试前先停止	 传输）
    - -  `EFAULT`

       - 在从用户空间复制数据到内核或反之的过程中发生故障，可能由无效的指	 引用引起
    - -  `EINVAL`

       - 一个或多个 ioctl 参数无效或超出允许范围。这是一个被广泛使用的错误码	 具体原因请参见各ioctl 请求
    - -  `ENODEV`

       - 未找到设备，或设备已被移除
    - -  `ENOMEM`

       - 没有足够的内存来处理期望的操作
    - -  `ENOTTY`

       - 文件描述符不支持ioctl
    - -  `ENOSPC`

       - USB 设备上，流传ioctl 可能返回此错误，意味着该请求会过度占用	 周期性传输保留的 USB 带宽（最高达 USB 带宽80%）
    - -  `EPERM`

       - 权限被拒绝。如果设备需要写权限，或需要某些特殊能力（例如 root），	 可能返回
    - -  `EIO`

       - I/O 错误。通常用于与硬件设备通信出现问题时，可能表示硬件损坏或不稳定	 它是一种“出问题了，我放弃！”类型的错误
    - - `ENXIO`

       - 没有与此设备特殊文件对应的设备


  #. 此列表并非详尽无遗；ioctl 可能返回其它错误码。由于错误可能有副作用（例如
     驱动重置），应用程序应该在遇到意外错误时中止，否则应假定设备处于错误状态
  #. 特定于请求的错误码列在各个请求的描述中
