## V4L2 read()


### 名称

v4l2-read - V4L2 设备读取

### 概要


    #include <unistd.h>


### 参数


`fd`
    `open()` 返回的文件描述符
`buf`
   待填充的缓冲
`count`
  读取的最大字节数

### 描述

`read()` 试图从文件描述符 `fd` 读取最`count` 个字节到`buf` 开始的缓冲区中缓冲区中数据的布局在相应的设备接口小节中讨论，##。如`count` 为零`read()` 返回零且不产生其它结果。如`count` 大于 `SSIZE_MAX`，结果是未指定的无论 `count` 取何值，每次 `read()` 调用最多只会提供一帧（两个场）的数据
默认情况`read()` 会阻塞，直到有数据可用。如果向 `open()` 传入`O_NONBLOCK`
标志，则当没有数据可用时会立即返`EAGAIN` 错误码。也可以使用 `select()` `poll()` 函数来挂起执行，直到有数据可用。所有支`read()` 函数的驱动也必须
支持 `select()` `poll()`
驱动可以用不同方式实现读取功能，使用单个或多个缓冲区，并在内部缓冲区填满后丢最旧或最新的帧
`read()` 绝不会返回一个正在填充中的缓冲区的“快照”。使用单个缓冲区时，驱动会在
应用程序开始读取该缓冲区时停止采集，直到读取完成。因此只有垂直消隐间隔期间可于读取，或者采集速率必须降到该视频标准标称帧率以下
在有效图像期间或分隔上下场的垂直消隐期间调用 `read()` 时的行为取决于丢弃策略丢弃最旧帧的驱动会持续采集到内部缓冲区，不断覆盖之前未被读取的帧，并在 `read()`
调用时刻所接收的帧完成时立即返回它
丢弃最新帧的驱动会停止采集，直到下一`read()` 调用。读取时刻正在接收的帧被丢弃转而返回随后的那一帧。这同样意味着采集速率降低到标称帧率的一半或更少。这种模型的
一个例子是 bttv 驱动的视频读取模式，它在 `read()` 被调用时发起一次到用户内存DMA，并DMA 完成时返回
在多缓冲区模型中，驱动维护一个内部缓冲区的环，自动前进到下一个空闲缓冲区。这允许应用程序能足够快地清空缓冲区时持续采集。同样，驱动耗尽空闲缓冲区时的行为取决于丢弃
策略
应用程序可以通过 VIDIOC_G_PARM <VIDIOC_G_PARM> VIDIOC_S_PARM <VIDIOC_G_PARM>
ioctl 获取和设置驱动内部使用的缓冲区数量。不过它们是可选的。丢弃策略既不被报告
也无法更改。最低要求参见相应设备小节
### 杩斿洖鍊。
成功时返回读取的字节数。如果这个数小于请求的字节数，或小于一帧所需的数据量，并
不算错误。例如这可能是因`read()` 被信号中断。出错时返回 -1，并相应地设`errno` 变量。这种情况下下一次读取将从新帧的开头开始。可能的错误码如下：

EAGAIN
    使用O_NONBLOCK 选择了非阻塞 I/O，且没有立即可读的数据
EBADF
    `fd` 不是有效的文件描述符，或未以读方式打开，或进程已打开的文件数达到上限
EBUSY
    驱动不支持多路读取流，且设备已在使用中
EFAULT
    `buf` 引用了一个不可访问的内存区域
EINTR
    在任何数据被读取之前，调用被信号中断
EIO
    I/O 错误。这表示某些硬件问题，或与远端设备（USB 摄像头等）通信失败
EINVAL
    该驱动不支持 `read()` 函数，或在当前设备上，或一般地在此类设备上不支持
