

## 媒体总线格式

本文说明 Video4Linux 子设备（subdev）媒体总线格式结构体的各字段含义，涵盖图像宽度与高度、像素代码、字段顺序、色彩空间、Y'CbCr/HSV 编码、量化范围与传输函数等属性，并解释应用程序如何通过相应标志请求驱动进行色彩空间转换，供摄像头与 ISP 驱动开发者在对接媒体管线时参考。

### 媒体总线像素代码


媒体总线像素代码描述了在物理总线上传输的图像格式（既存在于独立的物理
组件之间，也存在于 SoC 器件内部）。不应将其与 V4L2 像素格式混淆，后者使用
四字符代码（four character codes）描述存储在内存中的图像格式。

尽管总线上的图像格式与内存中的图像格式之间存在关联（原始的 Bayer 图像
不会因为存入内存就神奇地转换为 JPEG），但二者之间并不存在一一对应的关系。

虽然媒体总线像素代码是基于像素在并行总线上的传输方式来命名的，但串行总线
并没有定义独立的代码。按照惯例，它们使用在单个时钟周期内传输一个采样的
代码，并且其从 LSB 到 MSB 的位序对应于串行总线上色彩分量的传输顺序。例如，
MIPI CSI-2 的 24 位 RGB（RGB888）格式使用 MEDIA_BUS_FMT_RGB888_1X24 媒体总线
代码，因为 CSI-2 先传输蓝色分量，随后是绿色和红色，而
MEDIA_BUS_FMT_RGB888_1X24 将蓝色的第一位定义在 bit 0。尽管该代码用于并行
总线上的 24 位 RGB 数据，但 MEDIA_BUS_FMT_RGB888_3X8 或
MEDIA_BUS_FMT_BGR888_1X24 代码不得用于 CSI-2。
##### 打包 RGB 格式


这些格式将像素数据作为红、绿、蓝分量进行传输。格式代码由以下信息构成。

- 红、绿、蓝分量的顺序代码，编码在一个像素采样中。可能的值为 RGB 和 BGR。

- 每个分量的位数，各分量可以不同。常见值为 555 和 565。

- 每个像素的总线采样数。比总线宽度更宽的像素必须在多个采样中传输。常见值为 1 和 2。

- 总线宽度。

- 对于总位数小于“总线采样数 × 总线宽度”的格式，需要一个填充值，指明字节是填充在其最高位（PADHI）还是最低位（PADLO）。对于各分量分别填充在最高位（CPADHI）或最低位（CPADLO）的情况，使用“C”前缀。

- 对于总线采样数大于 1 的格式，需要一个端序值，指明像素是高位优先（MSB first，BE）还是低位优先（LSB first，LE）传输。

例如，若像素编码为 5 位红、5 位绿和 5 位蓝，并在高位填充，以每像素 2 个 8 位采样传输，且最高有效位（填充位、红色以及一半的绿色值）先传输，则该格式命名为
`MEDIA_BUS_FMT_RGB555_2X8_PADHI_BE`。

##### Bayer 格式


这些格式将像素数据作为红、绿、蓝分量进行传输。格式代码由以下信息构成。

- 红、绿、蓝分量的顺序代码，编码在一个像素采样中。可能的值见 bayer-patterns。

- 每个像素分量的位数。所有分量都以相同的位数传输。常见值为 8、10 和 12。

- 压缩（可选）。如果像素分量经过 ALAW 或 DPCM 压缩，则需说明压缩方案以及每个压缩后像素分量的位数。

- 每个像素的总线采样数。比总线宽度更宽的像素必须在多个采样中传输。常见值为 1 和 2。

- 总线宽度。

- 对于总位数小于“总线采样数 × 总线宽度”的格式，需要一个填充值，指明字节是填充在其最高位（PADHI）还是最低位（PADLO）。

- 对于总线采样数大于 1 的格式，需要一个端序值，指明像素是高位优先（MSB first，BE）还是低位优先（LSB first，LE）传输。

例如，若一种格式包含未压缩的 10 位 Bayer 分量，按红、绿、绿、蓝的排列，以每像素 2 个 8 位采样传输，且最低有效位先传输，则命名为 `MEDIA_BUS_FMT_SRGGB10_2X8_PADHI_LE`。

##### 打包 YUV 格式


这些数据格式将像素数据作为（可能经过下采样的）Y、U 和 V 分量进行传输。部分格式在其某些采样中包含虚拟位，统称为“YDYC”（Y-Dummy-Y-Chroma，Y-虚拟-Y-色度）格式。不能依赖这些虚拟位的值，因为它们是未定义的。

格式代码由以下信息构成。

- Y、U 和 V 分量的顺序代码，按总线上的传输顺序排列。对于无虚拟位的格式，可能的值为 YUYV、UYVY、YVYU 和 VYUY；对于 YDYC 格式，可能的值为 YDYUYDYV、YDYVYDYU、YUYDYVYD 和 YVYDYUYD。

- 每个像素分量的位数。所有分量都以相同的位数传输。常见值为 8、10 和 12。

- 每个像素的总线采样数。比总线宽度更宽的像素必须在多个采样中传输。常见值为 0.5（编码为 0_5；此时每总线采样传输两个像素）、1、1.5（编码为 1_5）和 2。

- 总线宽度。当总线宽度大于每个像素分量的位数时，多个分量被打包进单个总线采样中。分量按顺序代码指定的顺序排列，代码中左侧的分量在高位中传输。常见值为 8 和 16。

例如，若像素编码为 8 位 YUV 值，下采样为 4:2:2，并以每像素 2 个 8 位总线采样、按 U、Y、V、Y 的顺序传输，则命名为 `MEDIA_BUS_FMT_UYVY8_2X8`。

v4l2-mbus-pixelcode-yuv8 列出了已有的打包 YUV 格式，并描述了每个采样中像素数据的组织方式。当一种格式模式被拆分到多个采样中时，会描述该模式中每个采样。

通过总线传输的每个位的角色由下列代码之一标识。

- y\ `x` 表示亮度分量第 x 位

- u\ `x` 表示蓝色色度分量第 x 位

- v\ `x` 表示红色色度分量第 x 位

- a\ `x` 表示 alpha 分量第 x 位

- 表示不可用位（对应高于总线宽度的位置）

- d 表示虚拟位

##### HSV/HSL 格式


这些格式以圆柱形坐标系使用色相-饱和度-明度（Hue-Saturation-Value）或
色相-饱和度-亮度（Hue-Saturation-Lightness）分量来传输 RGB 像素数据。格式代码由以下信息构成。

- 色相、饱和度、明度或亮度以及可选的 alpha 分量顺序代码，编码在一个像素采样中。当前唯一受支持的值为 AHSV。

- 每个分量的位数。各分量可以不同。当前唯一受支持的值为 8888。

- 每个像素的总线采样数。比总线宽度更宽的像素必须在多个采样中传输。当前唯一受支持的值为 1。

- 总线宽度。

- 对于总位数小于“总线采样数 × 总线宽度”的格式，需要一个填充值，指明字节是填充在其最高位（PADHI）还是最低位（PADLO）。

- 对于总线采样数大于 1 的格式，需要一个端序值，指明像素是高位优先（MSB first，BE）还是低位优先（LSB first，LE）传输。
