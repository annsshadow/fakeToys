######## 璇，鍐。

VIDIOC_QUERYCAP ioctl 返回struct `v4l2_capability` `capabilities`
字段中的 `V4L2_CAP_READWRITE` 标志被设置时，输入与输出设备分别支持 `read()`
`write()` 函数
驱动可能需CPU 来复制数据，但它们也可能支持与用户内存之间的 DMA，因此这I/O 方法并不一定比仅交换缓冲指针的其他方法效率低。不过它被认为较差，因为
不会传递帧计数器或时间戳等元信息。这些信息对于识别帧丢弃以及与其他数据流
同步是必要的。然而，这也是最简单的 I/O 方法，几乎不需要任何设置即可交数据。它允许像这样的命令行技巧（vidctrl 工具是虚构的）：


    $ vidctrl /dev/video --input=0 --format=YUYV --size=352x288
    $ dd if=/dev/video of=myimage.422 bs=202752 count=1

要从设备读取，应用程序使`read()` 函数；要写入则使`write()` 函数。如驱动与应用程序交换数据，则必须实现一I/O 方法，但不一定是这一种。[#f1]_
当支持读或写时，驱动还必须支`select()` `poll()` 函数。[#f2]_

   理想情况下，应用程序可以依赖驱动支持所I/O 接口；但由于复杂的内存映   I/O 对某些设备可能并不合适，我们没有理由要求此接口，而它对于捕获静态图   的简单应用程序最为有用
   在驱动层面，`select()` `poll()` 是相同的，`select()` 过于重要   不能是可选的
