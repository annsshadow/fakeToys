

######## RGB 格式

本页介绍 V4L2 的 RGB 像素格式族，说明这些紧凑（packed）格式如何将每个像素的 R/G/B（及可选的 Alpha 或填充）分量以不同位宽与内存排列顺序存储，并列出各格式的位布局表，供摄像头与显示驱动开发者选用合适的像素格式。



这些格式将每个像素编码为一个 RGB 值三元组。它们是 packed（紧凑）格式，即一个像素的
RGB 值连续存储在内存中，每个像素占用整数个字节。当存储一个像素所需的位数未对齐到字节边界时，
数据会用额外的位进行填充以填满剩余的字节。

这些格式的区别在于每个 RGB 分量（通常但不总是所有分量都相同）的位数、内存中分量的排列顺序，
以及是否存在 alpha 分量或额外的填充位。

在支持 alpha 位的格式（命名为 ARGB 或其排列组合，统称为 alpha 格式）中，alpha 位的
用法和取值取决于设备类型和硬件操作。捕获 <capture> 设备（包括 mem-to-mem 设备的
捕获队列）会在内存中填充 alpha 分量。当设备捕获 alpha 通道时，alpha 分量将具有有意义的值。
否则，当设备不捕获 alpha 通道但可以将 alpha 位设置为用户可配置的值时，将使用
V4L2_CID_ALPHA_COMPONENT <v4l2-alpha-component> 控制项来指定该 alpha 值，并且所有
像素的 alpha 分量将被设置为该控制项指定的值。否则，必须使用没有 alpha 分量的相应格式
（XRGB 或 XBGR）来替代 alpha 格式。

输出 <output> 设备（包括 mem-to-mem 设备的输出队列和视频输出叠加 <osd> 设备）
从内存中读取 alpha 分量。当设备处理 alpha 通道时，应用程序必须用有意义的值填充 alpha 分量。
否则，必须使用没有 alpha 分量的相应格式（XRGB 或 XBGR）来替代 alpha 格式。

包含填充位的格式被命名为 XRGB（或其排列组合）。填充位包含未定义的值，对于捕获和输出设备，
应用程序、设备和驱动都必须忽略这些填充位。


   - 在以下所有表格中，位 7 是一个字节中的最高有效位。
   - 'r'、'g' 和 'b' 分别表示红色、绿色和蓝色分量的位。'a' 表示 alpha 分量（如果格式支持）
     的位，'x' 表示填充位。


## 每个分量少于 8 位


这些格式将一个 RGB 三元组存储在一个、两个或四个字节中。它们根据在 8 位、16 位或 32 位
字中所见的 RGB 分量顺序来命名，然后该字以小端字节序存储在内存中（除非 4CC 值中存在位 31 另有说明），
并依据每个分量的位数来命名。例如，RGB565 格式将一个像素存储在一个 16 位字 [15:0] 中，
排列为 [R\ `4` R\ `3` R\ `2` R\ `1`
R\ `0` G\ `5` G\ `4` G\ `3` G\ `2` G\ `1`
G\ `0` B\ `4` B\ `3` B\ `2` B\ `1` B\ `0`]，并以两个字节存储在内存中，
先是 [R\ `4` R\ `3` R\ `2` R\ `1`
R\ `0` G\ `5` G\ `4` G\ `3`]，其后是 [G\ `2`
G\ `1` G\ `0` B\ `4` B\ `3` B\ `2` B\ `1`
B\ `0`].

## 每个分量 8 位


这些格式将一个 RGB 三元组存储在三个或四个字节中。它们根据内存中存储的 RGB 分量顺序以及
每像素的总位数来命名。例如，RGB24 格式将像素的 [R\ `7`
R\ `6` R\ `5` R\ `4` R\ `3` R\ `2` R\ `1`
R\ `0`] 存储在第一字节，[G\ `7` G\ `6` G\ `5` G\ `4`
G\ `3` G\ `2` G\ `1` G\ `0`] 存储在第二字节，[B\ `7` B\ `6`
B\ `5` B\ `4` B\ `3` B\ `2` B\ `1` B\ `0`] 存储在第三字节。这与
DRM 格式命名不同，后者使用在 24 位或 32 位小端字中所见的各分量顺序。

## 每个分量 16 位

第 0 和第 1 字节。这与 DRM 格式命名不同，后者使用在 48 位小端字中所见的各分量顺序。
