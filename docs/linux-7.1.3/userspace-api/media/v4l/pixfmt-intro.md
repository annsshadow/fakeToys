######## 标准图像格式


为了在驱动与应用程序之间交换图像，必须具有双方会以相同方式解释的标准图像数据格式V4L2 包含了若干此类格式，本节旨在作为 V4L2 中标准图像数据格式的无歧义规范
然而，V4L2 驱动并不局限于这些格式。驱动特定的格式也是可能的。在这种情况下，应用程序
可能依赖于编解码器（codec）在需要时把图像转换为标准格式之一。但数据仍可以以专有格式
存储和检索。例如，某设备可能支持一种专有的压缩格式。应用程序仍可以捕获并以压缩格式
保存数据，从而节省大量磁盘空间，并在稍后视频要显示时再用编解码器把图像转换为 X Windows
屏幕格式
即便如此，最终还是需要某些标准格式，因此如果没有定义良好的标准格式，V4L2 规范将是完整的
V4L2 标准格式主要是未压缩格式。像素在内存中总是从左到右、从上到下排列。图像缓冲区的第一个数据字节总是对应最上面一行的最左边像素。在其之后是该像素正右侧的像素，依此类推直到该行像素的末尾。在像素行最右侧像素之后，可能有零个或多个填充（padding）字节，保证每一行像素数据具有某种对齐。在填充字节（若有）之后，是最上面第二行最左边像素的数据，
依此类推。最后一行的填充字节数量与其他行相同

头文件中。这些标识符表示四字符（FourCC）代<v4l2-fourcc>，下面也一并列出，但它们与

对于某些格式，数据存储在分离的、不连续的内存缓冲区中。这些格式由一组独立的 FourCC 代码
标识，被称为 “multi-planar formats（多平面格式）”。例如，一YUV422 <V4L2-PIX-FMT-YUV422M>
帧通常存放在一个内存缓冲区中，但它也可以放在两个或三个独立的缓冲区中，2 平面版本Y 分量在一个缓冲区、CbCr 分量在另一个缓冲区，在 3 平面情况下每个分量各自在一个缓冲区中这些子缓冲区被称*planes（平面）**”
