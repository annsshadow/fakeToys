
## 简介


媒体设备越来越多地处理多个相关功能。许多 USB 摄像头包含麦克风，视频采集硬件也可以输出视频，或者 SoC 摄像头接口也执行类似于视频编解码器的内存到内存操作。

独立的功能，即使在同一硬件中实现，也可以建模为独立的设备。带有麦克风的 USB 摄像头会以 V4L2 和 ALSA 采集设备的形式呈现给用户空间应用程序。设备之间的关系（使用网络摄像头时，最终用户不应手动选择关联的 USB 麦克风）虽然不会由驱动直接提供给应用程序，但通常可以从 sysfs 中检索。

随着越来越多先进的 SoC 设备被引入，当前的方法将无法扩展。设备拓扑结构日益复杂，并且不能总是由树形结构表示。硬件模块在不同的功能之间共享，从而在不相关的设备之间产生了依赖关系。

V4L2 和 ALSA 等内核抽象 API 为应用程序提供了访问硬件参数的手段。随着较新的硬件暴露出越来越多的此类参数，驱动需要根据有限的信息猜测应用程序真正需要什么，从而实现了本应属于用户空间的策略。

媒体控制器 API 旨在解决这些问题。
