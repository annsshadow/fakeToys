


######## ioctl MEDIA_REQUEST_IOC_QUEUE


## 名称


MEDIA_REQUEST_IOC_QUEUE - 将一个请求入
## 概要


`int ioctl(int request_fd, MEDIA_REQUEST_IOC_QUEUE)`

## 参数


`request_fd`
    MEDIA_IOC_REQUEST_ALLOC 返回的文件描述符
## 描述


如果媒体设备支持请求 <media-request-api>，那么可以使用这个请ioctl 先前已分配的请求入队
如果请求成功入队，则可以对该文件描述符进行轮<request-func-poll>，以等待
请求完成
如果该请求此前已被入队，则返`EBUSY`。如果请求的内容包含无效或不一致的
数据，也可能返回其它错误，常见错误码列表见下一节。出错时，请求与驱动状均保持不变
一旦请求被入队，驱动就有责任优雅地处理将该请求应用到硬件时发生的错误例外`EIO` 错误，它表示需要应用程序停止流传输以重置硬件状态的致命错误
不允许将入队请求与直接入队缓冲区（不使用请求）混用。如果第一个缓冲区被直入队，而你接下来尝试入队一个请求，或者反之，都会返回 `EBUSY`
一个请求必须至少包含一个缓冲区，否则该 ioctl 会返`ENOENT` 错误
## 杩斿洖鍊。

成功时返0，出错时返回 -1，并相应地设`errno` 变量。通用错误码在
Generic Error Codes <gen-errors> 一章中描述
EBUSY
    请求已被入队，或者应用程序直接入队了第一个缓冲区，但后来又尝试使    请求。不允许混用这两APIENOENT
    请求不包含任何缓冲区。所有请求都必须至少有一个缓冲区。如果请求中缺少
    某些必需的配置，也可能返回此错误ENOMEM
    在为这个请求分配内部数据结构时内存不足EINVAL
    请求包含无效数据EIO
    硬件处于不良状态。要恢复，应用程序需要停止流传输以重置硬件状态，然后
    尝试重新启动流传输
