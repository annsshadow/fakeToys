
## KVM 上的 s390 DIAGNOSE 调用


KVM on s390 支持使用 DIAGNOSE 调用进行超级调用（hypercall），既可用于原生的超级
调用，也可用于其他 s390 虚拟机监控器上发现的选定的超级调用。

请注意，位的编号遵循通常的 s390 约定（最高有效位在左侧）。


### 一般性说明


客户机发起的 DIAGNOSE 调用会导致一次强制拦截（intercept）。这意味着所有受支持的
DIAGNOSE 调用都需要由 KVM 或其用户态来处理。

```

  --------------------------------------
  |  '83'  | R1 | R3 | B2 |     D2     |
  --------------------------------------
  0        8    12   16   20           31

```
第二操作数地址（通过基址/位移计算获得）不用于寻址数据。相反，该地址的位 48-63
指定了功能码，而位 0-47 被忽略。

受支持的 DIAGNOSE 功能码因所使用的用户态而异。对于非 KVM 特定的 DIAGNOSE 功能码，
请参阅定义它们的 s390 虚拟机监控器的文档。


### DIAGNOSE 功能码 0x500 - KVM 功能


如果功能码指定为 0x500，则会执行各种 KVM 特定的功能，包括 virtio 功能。

通用寄存器 1 包含子功能码。受支持的子功能取决于 KVM 的用户态。关于 virtio 子功能，
用户态通常提供 s390-virtio（子码 0-2）或 virtio-ccw（子码 3）。

DIAGNOSE 指令完成时，通用寄存器 2 包含该功能的返回码，该返回码要么是返回码，要么
是子码特定值。

如果指定的子功能不受支持，则会触发 SPECIFICATION 异常。

Subcode 0 - s390-virtio 通知与早期控制台 printk
    由用户态处理。

Subcode 1 - s390-virtio 复位
    由用户态处理。

Subcode 2 - s390-virtio 设置状态
    由用户态处理。

Subcode 3 - virtio-ccw 通知
    由用户态或 KVM 处理（ioeventfd 情形）。

    通用寄存器 2 包含一个子通道标识字，表示要通知的 virtio-ccw 代理设备的子通道。

    通用寄存器 3 包含要通知的 virtqueue 的编号。

    通用寄存器 4 包含一个供 KVM 使用的 64 位标识符（kvm_io_bus cookie）。如果通用
    寄存器 4 不包含有效标识符，则会被忽略。

    DIAGNOSE 调用完成后，通用寄存器 2 可能包含一个 64 位标识符（在 kvm_io_bus cookie
    情形下），如果发生内部错误，则可能包含一个负的错误值。

    另请参阅 virtio 标准以了解关于此超级调用的讨论。

Subcode 4 - 存储上限（storage-limit）
    由用户态处理。

    DIAGNOSE 调用完成后，通用寄存器 2 将包含存储上限：在整个 VM 生命周期内可能用于
    存储的最大物理地址。

    存储上限并不表示当前可用的存储，它可能包含空洞、备用存储以及为其他用途（例如
    内存热插拔或 virtio-mem 设备）保留的区域。必须使用其他用于检测实际可用存储的
    接口（例如 SCLP）与此子功能配合使用。

    请注意，存储上限可以更大，但绝不能小于 SCLP 通过“最大存储增量”和“增量大小”
    所指示的最大存储地址。


### DIAGNOSE 功能码 0x501 - KVM 断点


如果功能码指定为 0x501，则可以执行断点功能。此功能码由用户态处理。

此诊断功能码没有子功能，也不使用任何参数。


### DIAGNOSE 功能码 0x9C - 主动时间片让出（Voluntary Time Slice Yield）


通用寄存器 1 包含目标 CPU 地址。

在使用共享主机 CPU 的 LPAR、KVM 或 z/VM 等虚拟机监控器的客户机中，使用功能码 0x9c
的 DIAGNOSE 可以通过让运行客户机 CPU 的主机 CPU 让出，分配给另一个客户机 CPU（最好
是包含指定目标 CPU 的逻辑 CPU），从而改善系统性能。


DIAG 0x9C 转发
+++++++++++++++++++

客户机可以发送一个 DIAGNOSE 0x9c 以让出给某个特定的其他 vcpu。一个例子是试图让出给
当前持有自旋锁但未在运行的 vcpu 的 Linux 客户机。

然而，在主机上，支撑该 vcpu 的真实 CPU 本身可能并未在运行。将客户机最初发送的
DIAGNOSE 0x9c 转发给支撑 CPU，有望使该 CPU 以及随之的客户机 vcpu 被调度运行。


diag9c_forwarding_hz
    KVM 内核参数，用于指定每秒 DIAGNOSE 0x9c 转发的最大次数，以避免 DIAGNOSE 0x9c
    转发风暴。
    值为 0 时关闭转发。
