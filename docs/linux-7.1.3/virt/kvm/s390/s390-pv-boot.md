
## s390 (IBM Z) 受保护虚拟机（PVM）的引导/IPL


### 概述


受保护虚拟机（PVM）的内存I/O hypervisor 不可访问。在 hypervisor 需要访PVM 内存的那些情况下，必须使该内存可访问。提供给 hypervisor 的内存将被加密。详情请参阅 Documentation/virt/kvm/s390/s390-pv.rst

IPL（引导）时，会启动一个小的明文引导加载程序，它向 KVM 提供关于加密组件的信息与必要的元数据，以解密受保护的虚拟机

基于这些数据，KVM 将使受保护虚拟机Ultravisor（UV）所知，并指示它保护 PVM 的内存、解开组件、验证数据与地址列表哈希，以确保完整性。之KVM 可以通过 SIE 指令运行 PVM，该指令将由 UV 拦截并代KVM 执行

由于客户机镜像就像一个自己进行切换到 PV 模式的不透明内核镜像，用户可以通过每种可用的方法（网络、dasd、scsi、直接内核……）加载加密的客户机可执行文件与数据，而无需更改引导过程

这条诊断指令是处理虚拟机 IPL 及相关操作的基本机制。VM 可以设置与获IPL 信息块，这些块指定了 IPL 方法/设备，并请求 VM 内存与子系统复位，以IPL

对于 PVM，这一概念通过新的子码进行了扩展：

子码 8：设置类5 IPL 信息块（用于 PVM 的信息块
子码 9：将保存的块存入客户机内
子码 10：进入受保护虚拟化模

新的 PV 加载设备特定参数字段指定了进PV 模式所需的全部数据

- PV 澶村師鐐。
- PV 澶撮暱搴。
- 由以下组成的组件列表
   - AES-XTS Tweak 前缀
   - 原点
   - 大小

PV 头包UV 将用来解密与验证 PV 的密钥与哈希，以及控制标志与起始 PSW

组件例如加密的内核、内核参数与 initrd。组件由 UV 解密

在初始导入加密数据之后，所有已定义的页将包含客户机内容。所有未指定的页在首次访问时将以零页开始


当运行在受保护虚拟化模式时，某些子码将导致异常或返回错误码

子码 4 7 指定了不清除客户机内存的操作，将导致指定异常。这是因UV 会在安全 VM 被移除时清除所有内存，因此不允许非清除IPL 子码
