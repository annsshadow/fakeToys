
## s390 (IBM Z) 受保护虚拟机（PVM）的引导/IPL


### 概述


受保护虚拟机（PVM）的内存对 I/O 或 hypervisor 不可访问。在 hypervisor 需要访问 PVM 内存的那些情况下，必须使该内存可访问。提供给 hypervisor 的内存将被加密。详情请参阅 Documentation/virt/kvm/s390/s390-pv.rst。

在 IPL（引导）时，会启动一个小的明文引导加载程序，它向 KVM 提供关于加密组件的信息与必要的元数据，以解密受保护的虚拟机。

基于这些数据，KVM 将使受保护虚拟机为 Ultravisor（UV）所知，并指示它保护 PVM 的内存、解开组件、验证数据与地址列表哈希，以确保完整性。之后 KVM 可以通过 SIE 指令运行 PVM，该指令将由 UV 拦截并代表 KVM 执行。

由于客户机镜像就像一个自己进行切换到 PV 模式的不透明内核镜像，用户可以通过每种可用的方法（网络、dasd、scsi、直接内核……）加载加密的客户机可执行文件与数据，而无需更改引导过程。


### Diag308


这条诊断指令是处理虚拟机 IPL 及相关操作的基本机制。VM 可以设置与获取 IPL 信息块，这些块指定了 IPL 方法/设备，并请求 VM 内存与子系统复位，以及 IPL。

对于 PVM，这一概念通过新的子码进行了扩展：

子码 8：设置类型 5 的 IPL 信息块（用于 PVM 的信息块）
子码 9：将保存的块存入客户机内存
子码 10：进入受保护虚拟化模式

新的 PV 加载设备特定参数字段指定了进入 PV 模式所需的全部数据。

- PV 头原点
- PV 头长度
- 由以下组成的组件列表
   - AES-XTS Tweak 前缀
   - 原点
   - 大小

PV 头包含 UV 将用来解密与验证 PV 的密钥与哈希，以及控制标志与起始 PSW。

组件例如加密的内核、内核参数与 initrd。组件由 UV 解密。

在初始导入加密数据之后，所有已定义的页将包含客户机内容。所有未指定的页在首次访问时将以零页开始。


当运行在受保护虚拟化模式时，某些子码将导致异常或返回错误码。

子码 4 与 7 指定了不清除客户机内存的操作，将导致指定异常。这是因为 UV 会在安全 VM 被移除时清除所有内存，因此不允许非清除的 IPL 子码。

子码 8、9、10 将导致指定异常。重新 IPL 进入保护模式只能通过绕道进入非保护模式来实现。

### 密钥


每个 CEC 都会有一个唯一的公钥，以使工具能够构建加密镜像。相关工具请参阅 `s390-tools <https://github.com/ibm-s390-linux/s390-tools/>`_。
