
## s390（IBM Z）受保护虚拟化转储


### 摘要


转储一个 VM 是调试其内部问题的重要工具。当受保护的 VM 遇到麻烦时尤其如此，
因为在它运行时无法从外部访问其内存与寄存器。

然而，在转储受保护的 VM 时，我们需要保持其机密性，直到转储交到 VM 所有者
手中——应当只有 VM 所有者能够分析它。

VM 转储的机密性由 Ultravisor 保障，它向 KVM 提供一个接口，可以经由该接口
请求加密的 CPU 与内存数据。加密基于客户通信密钥（Customer Communication
Key），这是一种以客户能够解密的方式对 VM 数据进行加密的密钥。


### 转储过程


一次转储分 3 步完成：

**发起（Initiation）**

此步骤初始化转储过程，生成加密种子，并提取用于加密 VM 转储数据的转储密钥。

**数据收集（Data gathering）**

目前可以从 VM 收集两类数据：内存与 vcpu 状态。

vcpu 状态包含某个 vcpu 的所有重要寄存器——通用寄存器、浮点寄存器、向量
寄存器、控制寄存器以及 tod/定时器。如果某个 vcpu 是在超级管理程序帮助下
模拟某条指令时被转储的，vcpu 转储可能包含不完整的数据。这由转储数据中的
一个标志位指示。出于同样的原因，非常重要的一点是不仅要写出加密的 vcpu 状态，
还要写出来自超级管理程序的未加密状态。

内存状态进一步划分为加密内存及其元数据（由加密 tweak 与状态标志组成）。
加密内存在被导出后就可以简单地读取。导出的时间无关紧要，因为不需要重新加密。
已被换出从而被导出的内存可以从交换区读取并写入转储目标，无需任何特殊操作。

已导出页面的 tweak / 状态标志需要从 Ultravisor 请求。

**完成（Finalization）**

完成步骤将提供解密 vcpu 与内存数据所需的资料，并结束转储过程。当此步骤
成功完成后，可以开始一次新的转储发起。
