
## s390 (IBM Z) Ultravisor and Protected VMs


### Summary


受保护虚拟机（PVM）是不允许 KVM 访问 VM 状态（如客户机内存或客户机寄存器）的 KVM 虚拟机。相反，PVM 主要由一个名为 Ultravisor（UV，超级管理器）的新实体管理。UV 提供一个 API，PVM 和 KVM 可以使用它来请求管理操作。

每个客户机以非保护模式启动，然后可以发出请求转换到保护模式。在转换时，KVM 将客户机及其 VCPU 注册到 Ultravisor，并为运行它准备好一切。

Ultravisor 会保护并解密客户机的引导内存（即 kernel/initrd）。在客户机运行时，它会保护状态变更，如 VCPU 的启动/停止以及注入的中断。

由于运行 VM 通常需要访问客户机状态（例如 SIE 状态描述符），SIE 指令的行为做了一些改变。引入了一种新的 format 4 状态描述符，其中某些字段对 PVM 有不同的含义。SIE 退出被尽可能最小化，以提高速度并减少暴露的客户机状态。


### Interrupt injection


中断注入由 Ultravisor 保护。由于 KVM 无法访问 VCPU 的 lowcore，注入通过 format 4 状态描述符处理。

Machine check、external、IO 和 restart 中断各自可以在 SIE 入口通过中断注入控制字段（偏移 0x54）中的一个位来注入。如果在注入时客户机 cpu 未启用该中断，则会识别一个有效性拦截（validity interception）。format 4 状态描述符包含拦截数据块中的字段，中断相关的数据可以通过这些字段传输。

Program 和 Service Call 异常有另一层保护；它们只能针对已被拦截进 KVM 的指令注入。这些异常必须是 KVM 指令模拟的有效结果，例如我们永远不能注入一个寻址异常，因为它们由 SIE 报告，而 KVM 无法访问客户机内存。


### Mask notification interceptions


KVM 不再能拦截 lctl(g) 和 lpsw(e) 以在 PVM 启用某类中断时获得通知。作为替代，引入了两个新的拦截码：一个表示 CR 0、6 或 14 的内容已被更改，表示不同的中断子类；另一个表示 PSW 位 13 已被更改，表示请求了 machine check 干预并且现在已启用。


### Instruction emulation


对于 PVM 使用 format 4 状态描述符，SIE 指令已经比使用 format 2 时解释更多的指令。它无法解释每一条指令，而是需要将一些任务交给 KVM；因此，SIE 和 ultravisor 保护模拟的输入和输出。

与 SIE 相关的控制结构提供了安全指令数据区（SIDA）、拦截参数（IP）和安全拦截通用寄存器保存区。客户机 GR 和大部分指令数据（如 I/O 数据结构）被过滤。指令数据在需要时复制到 SIDA 或从 SIDA 复制出来。客户机 GR 被放入/从安全拦截通用寄存器保存区取回。

只会复制模拟指令所需的 GR 值，并且真实的寄存器编号会被隐藏。

拦截参数状态描述符字段仍然包含指令文本的字节，但使用预设的寄存器值而不是实际值。也就是说，每条指令始终使用相同的指令文本，以免泄露客户机指令文本。这也意味着从 hypervisor 的角度看，客户机在 r<n> 中的寄存器内容可能在 r<m> 中。

安全指令数据区包含指令存储数据。指令数据，即指令所引用的数据（如 sclp 的 SCCB），通过 SIDA 移动。当指令被拦截时，SIE 只允许该指令的数据和程序中断通过前面讨论的两个数据区移动到客户机。其他数据要么被忽略，要么导致有效性拦截。


### Instruction emulation interceptions


有两种类型的 SIE 安全指令拦截：普通类型和通知类型。普通的 SIE 安全指令拦截会使客户机挂起，等待被拦截指令类型的指令完成，即在 SIE 入口会尝试用 KVM 提供的数据完成该指令的模拟。这可能是程序异常或指令完成。

通知类型的拦截会通知 KVM 由于客户机指令解释而导致的客户机环境变更。例如，对于存储前缀（store prefix）指令会识别这样的拦截，以提供新的 lowcore 位置。在 SIE 重新进入时，数据区中的任何 KVM 数据都被忽略，执行继续，就好像客户机指令已经完成。因此 KVM 不允许注入程序中断。
