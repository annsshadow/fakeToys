
## arm64 的半虚拟化时间支

Arm 规范 DEN0057/A 定义了面AArch64 客户机的半虚拟化时间支持标准
https://developer.arm.com/docs/den0057/a

KVM/arm64 通过提供一hypervisor 服务调用，实现了该规范中“被窃取时间”（stolen time部分，以支持半虚拟化客户机获取其执行时间被窃取多少的视图
定义了两个新的兼SMCCC 的超级调用（hypercall）：

- PV_TIME_FEATURES: 0xC5000020
- PV_TIME_ST:       0xC5000021

这些仅在 SMC64/HVC64 调用约定下可用，因为半虚拟化时间32 Arm 客户机不可用在调PV_TIME_FEATURES 之前，应使用 SMCCC 1.1 ARCH_FEATURES 机制探测其是否存在
PV_TIME_FEATURES

    ============= ========    =================================================
    Function ID:  (uint32)    0xC5000020
    PV_call_id:   (uint32)    要查询是否支持的函数                              目前仅支PV_TIME_ST    Return value: (int64)     NOT_SUPPORTED (-1) SUCCESS (0)，取决于相关
                              PV-time 特性是否被 hypervisor 支持    ============= ========    =================================================

PV_TIME_ST

    ============= ========    ==============================================
    Function ID:  (uint32)    0xC5000021
    Return value: (int64)     VCPU 的被窃取时间数据结构IPA。失败时                              NOT_SUPPORTED (-1)
    ============= ========    ==============================================

PV_TIME_ST 返回IPA 应由客户机映射为具有内、外写回缓存属性、位于内部可共享（inner
shareable）域的普通内存。hypervisor 保证从返回的 IPA 开始的16 字节会被有意义地填充
（见下方结构）
PV_TIME_ST 返回调用 VCPU 的结构
### 被窃取时间（Stolen Time

PV_TIME_ST 超级调用所指向的结构如下：

+-------------+-------------+-------------+----------------------------+
| Field       | Byte Length | Byte Offset | Description                |
+=============+=============+=============+============================+
| Revision    |      4      |      0      | 版本 1.0 必须0          |
+-------------+-------------+-------------+----------------------------+
| Attributes  |      4      |      4      | 必须0                  |
+-------------+-------------+-------------+----------------------------+
| Stolen time |      8      |      8      | 以无符号纳秒表示的被窃取时间|
|             |             |             | 指示VCPU 线程在物CPU |
|             |             |             | 上被非自愿停止运行的时长|
+-------------+-------------+-------------+----------------------------+

结构中的所有值均以小端（little-endian）方式存储
该结构将hypervisor 在调VCPU 之前更新。它将位于提供给客户机的普通内存中的一个保区域内。客户机不应尝试写入该内存。客户机的每VCPU 都有一个这样的结构
建议预留一个或多个 64k 页用于这些结构，而不作他用，这样可使客户机使64k 页映射该区域并避免与其他内存产生属性冲突
