## KVM 暂停轮询（halt polling）机制

KVM 的暂停轮询功能提供了一种特性：在某些情形下，它可以降低客户机（guest）进入宿主机（host）的时延——当客户机 vCPU 主动让出（cede）处理器时，宿主机内核并不会立即把处理器交还给调度器，而是在一段时间内轮询唤醒条件，从而让客户机 vCPU 能够运行得更久。例如在 PowerPC 上，当某个 vcore 中唯一的 vCPU 让出处理器时，宿主机内核会在放弃处理器、交还给调度器以便让其他任务运行之前，先轮询唤醒条件。

轮询带来的时延优势体现在客户机很快再次运行的场景：至少省去了一次进入调度器的开销，通常量级为几微秒，不过性能收益取决于具体工作负载。当唤醒事件源在轮询间隔内到达时，任务被放入运行队列，调度器随之被调用。因此，对于那些唤醒周期非常短、轮询所花时间被尽量压缩、从而避免调用调度器所节省的时延可明显区分的工作负载，暂停轮询尤为有用。

通用的暂停轮询代码实现于：

virt/kvm/kvm_main.c: kvm_vcpu_block()

PowerPC kvm-hv 的特定情形实现于：

arch/powerpc/kvm/book3s_hv.c: kvmppc_vcore_blocked()

## 暂停轮询间隔（Halt Polling Interval）

在调用调度器之前进行轮询的最长时间称为“暂停轮询间隔（halt polling interval）”。该间隔会根据每次轮询尝试所感知到的有效性而增大或减小，以限制无意义的轮询。该值按 vCPU 存储：

kvm_vcpu->halt_poll_ns

在 PowerPC 的 kvm-hv 情形下，则按 vcore 存储：

kvmppc_vcore->halt_poll_ns

因此这是每个 vCPU（或 vcore）的值。

如果在暂停轮询间隔内收到了轮询唤醒源，则间隔保持不变。如果在该间隔内没有收到唤醒源（因而调度器被调用），则分两种情况：轮询总阻塞时间小于全局最大轮询间隔（参见模块参数），或者轮询总阻塞时间大于全局最大轮询间隔。

若轮询总阻塞时间小于全局最大轮询间隔，则暂停轮询间隔会被增大，期望下一次更长的轮询间隔能够收到唤醒源，从而让宿主机获得轮询时延收益。轮询间隔的增大由函数 grow_halt_poll_ns() 完成，它将当前值乘以模块参数 halt_poll_ns_grow 与 halt_poll_ns_grow_start。

若轮询总阻塞时间大于全局最大轮询间隔，说明宿主机从未轮询到足以（受全局最大值限制）收到唤醒源的时长，此时为了避免无意义的轮询，轮询间隔会被缩小。轮询间隔的缩小由函数 shrink_halt_poll_ns() 完成，它将当前值除以模块参数 halt_poll_ns_shrink；当 halt_poll_ns_shrink 为 0 时，间隔被设为 0。

值得指出的是，调整过程会尝试收敛到一个稳态的轮询间隔；当唤醒以近似恒定的速率到来时，它做得相当好，否则轮询间隔会持续被调整。

[^0^] 轮询总阻塞时间：从暂停轮询函数被调用，到收到唤醒源为止的时间（无论该函数内部是否调用了调度器）。

## 模块参数

kvm 模块提供 4 个可调节的模块参数，用于调整全局最大轮询间隔、初始值（从 0 开始增长）以及轮询间隔增大/缩小的速率。相关变量定义于 include/linux/kvm_host.h，模块参数则定义于 virt/kvm/kvm_main.c，PowerPC 的 kvm-hv 情形还涉及 arch/powerpc/kvm/book3s_hv.c。

+-----------------------+---------------------------+-------------------------+
| 模块参数              | 描述                      | 默认值                  |
+-----------------------+---------------------------+-------------------------+
| halt_poll_ns          | 全局最大轮询间隔；定义    | KVM_HALT_POLL_NS_DEFAULT|
|                       | vCPU 轮询间隔的上限值     | （各架构取值不同）      |
+-----------------------+---------------------------+-------------------------+
| halt_poll_ns_grow     | 在 grow_halt_poll_ns()    | 2                       |
|                       | 函数中，轮询间隔被乘以    |                         |
|                       | 的值                      |                         |
+-----------------------+---------------------------+-------------------------+
| halt_poll_ns_grow_start | 在 grow_halt_poll_ns()  | 10000                   |
|                       | 函数中，从零开始增长的    |                         |
|                       | 初始值                    |                         |
+-----------------------+---------------------------+-------------------------+
| halt_poll_ns_shrink   | 在 shrink_halt_poll_ns()  | 2                       |
|                       | 函数中，轮询间隔被除以    |                         |
|                       | 的值                      |                         |
+-----------------------+---------------------------+-------------------------+

模块参数通过 sysfs 文件设置：

/sys/module/kvm/parameters/

说明：模块参数为系统级取值，但也可基于每个虚拟机（VM）进行调节。对参数的修改会在新的以及已有的 vCPU 下一次暂停时被读取，但使用 KVM_CAP_HALT_POLL 的虚拟机是个明显的例外（参见下一节）。

## KVM_CAP_HALT_POLL

KVM_CAP_HALT_POLL 这一 VM 级别的能力（capability）允许用户态按每个 VM 覆盖 halt_poll_ns 的取值。使用了 KVM_CAP_HALT_POLL 的虚拟机会完全忽略 halt_poll_ns（但仍遵循 halt_poll_ns_grow、halt_poll_ns_grow_start 与 halt_poll_ns_shrink）。

关于该能力的更多信息，请参阅 Documentation/virt/kvm/api.rst。

## 补充说明

- 将 halt_poll_ns 模块参数设为一个较大的值时要格外小心，因为它可能把一台原本几乎完全空闲的机器的处理器占用率推高到 100%。即便客户机唤醒所做的工作很少、且两次唤醒间隔相当长，只要该间隔短于全局最大轮询间隔（halt_poll_ns），宿主机就会在整个阻塞时间内持续轮询，从而使处理器利用率达到 100%。
- 暂停轮询本质上是在功耗与时延之间做权衡；模块参数即用于调节这种倾向。空闲的处理器时间实质上被转化为宿主机内核时间，目的是降低进入客户机的时延。
- 暂停轮询仅在宿主机上仍有可运行任务时才会进行；否则轮询会立即停止并调用调度器，让该任务得以运行。因此，它不会允许某个客户机造成对处理器的拒绝服务（denial of service）。
