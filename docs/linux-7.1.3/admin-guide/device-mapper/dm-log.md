## Device-Mapper 日志

device-mapper 日志代码被某些 device-mapper RAID 目标用来跟踪磁盘上不一致的区域。
磁盘的某个区域（或地址空间的一部分）之所以可能不一致，是因为当前正在操作某个
RAID 条带，或者在该区域被修改时机器崩溃了。对于镜像而言，当你向某个区域写入时，
该区域会被视为脏/不一致，因为写入需要复制给镜像的所有分支（leg），且可能不会
同时到达各分支。一旦所有写入完成，该区域又被视为干净。

device-mapper RAID 实现使用一套通用的日志接口来执行日志操作（参见
include/linux/dm-dirty-log.h 中的 dm_dirty_log_type）。有多种不同的日志实现可用，
提供不同的能力。列表如下：

==============	==============================================================
Type		Files
==============	==============================================================
disk		drivers/md/dm-log.c
core		drivers/md/dm-log.c
userspace	drivers/md/dm-log-userspace* include/linux/dm-log-userspace.h
==============	==============================================================

### “disk” 日志类型

该日志实现将日志状态提交到磁盘。这样，日志状态可在重启/崩溃后存活。

### “core” 日志类型

该日志实现将日志状态保存在内存中。日志状态不会在重启或崩溃后存活，但性能可能会
略有提升。如果没有可用的存储设备来保存日志状态，也可以使用此方法。

### “userspace” 日志类型

该日志类型只是提供了一种将日志 API 导出到用户空间的方式，从而可以在用户空间
实现日志。这是通过将大多数日志请求转发到用户空间、由一个守护进程接收并处理该
请求来完成的。

内核与用户空间之间用于通信的结构位于 include/linux/dm-log-userspace.h。由于
内核与用户空间之间交换的频率、多样性以及双向通信的特性，使用 “connector” 作为
通信接口。

目前有两个用户空间日志实现利用该框架——“clustered-disk” 和 “clustered-core”。
这些实现为共享存储提供集群一致的日志。当采用集群日志实现时，device-mapper 镜像
可在共享存储环境中使用。
