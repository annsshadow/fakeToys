## writecache 目标


writecache 目标在持久内存或 SSD 上缓存写入。它不缓存读取，因为读取应在普RAM 页缓存中被缓存
创建设备时，第一个扇区应被清零，或者应包含来自上一次调用的有效超级块
构造参数：

1. 缓存设备的类- "p" "s"
 - p - 持久内存
 - s - SSD
2. 将被缓存的底层设3. 缓存设备
4. 块大小（推荐 4096；最大块大小为页大小5. 可选参数的数量（带参数的参数计为两个）

	start_sector n		（默认：0		从缓存设备起始位置起的偏移，512 字节扇区为单	high_watermark n	（默认：50		当已用块数达到该水位线时开始回	low_watermark x		（默认：45		当已用块数低于该水位线时停止回写
	writeback_jobs n	（默认：不限		限制回写过程中在途的块数量。设置该值会降低回写吞吐		但可能改善读请求的延	autocommit_blocks n	（默认：pmem 64，ssd 65536		当应用程序写入这么多块而未发出 FLUSH 请求时，这些块会		自动提交
	autocommit_time ms	（默认：1000		自动提交时间（毫秒）。若超过该时间且未收FLUSH 请求		数据会被自动提交
	fua			（默认开启）
		仅适用于持久内- 当将持久内存中的数据写回底层设备		使用 FUA 标志
	nofua
		仅适用于持久内- 回写数据时不使用 FUA 标志，随后发		FLUSH 请求

  - 某些底层设备fua 下表现更好，某些nofua 下更好。用户应当测试	cleaner
		激活该选项时（无论是在构造参数中还是通过消息），缓存将不		提升新的写入（但对已缓存块的写入仍会被提升，以避免因乱序写入
		导致数据损坏），并会逐渐回写任何已缓存的数据。用户态随后可		"dmsetup status" 监控清理过程。当缓存块数量降为零时，用户态可		卸载 dm-writecache 目标并用 dm-linear 或其他目标替换它	max_age n
		指定块的最大存活时间（毫秒）。如果某个块在缓存中存放过久		它会被写入底层设备并清理	metadata_only
		仅将元数据提升进缓存。该选项可改善较REQ_META 工作负载的性能	pause_writeback n	（默认：3000		若最n 毫秒内有某些I/O 被重定向到源卷，则暂停回写
状态：

1. 错误指示 - 0 表示无错误，否则为错误号
2. 块数3. 空闲块数4. 处于回写中的块数5. 读取块数6. 命中缓存的读取块数量
7. 写入块数8. 命中未提交块的写入块数量
9. 命中已提交块的写入块数量
10. 绕过缓存的写入块数量
11. 在缓存中分配的写入块数量
12. 因空闲链表而被阻塞的写请求数量
13. 刷新请求数量
14. 被丢弃的块数
消息	flush
		刷新缓存设备。若缓存设备被无错误地刷新，则该消息成功返回	flush_on_suspend
		在下一次挂起时刷新缓存设备。当你要移除缓存设备时使用该消息		移除缓存设备的正确顺序是
  1. 发"flush_on_suspend" 消息
  2. 加载一个指向底层设备的线性目标的非活动表
  3. 挂起设备
  4. 请求状态并确认没有错误
  5. 恢复设备，使其使用线性目  6. 缓存设备现已停用，可以被删除
	cleaner
		见上"cleaner" 构造参数文档	clear_stats
		清除状态行上报告的统计信息
