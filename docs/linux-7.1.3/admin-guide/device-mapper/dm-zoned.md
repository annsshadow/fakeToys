## dm-zoned


dm-zoned 设备映射器目标将一个分区块设备（ZBC 和 ZAC 兼容设备）暴露为一个没有任何写入模式约束的常规块设备。实际上，它实现了一个驱动器管理（drive-managed）的分区块设备，对用户（文件系统或做原始块设备访问的应用程序）隐藏了主机管理（host-managed）分区块设备的顺序写入约束，并能缓解主机感知（host-aware）分区块设备因过度随机写入而可能导致的设备端性能下降。

关于分区块设备模型及其约束的更详细描述，请参见（针对 SCSI 设备）：

https://www.t10.org/drafts.htm#ZBC_Family

以及（针对 ATA 设备）：

http://www.t13.org/Documents/UploadedDocuments/docs2015/di537r05-Zoned_Device_ATA_Command_Set_ZAC.pdf

dm-zoned 实现简单，并最小化系统开销（CPU 与内存使用，以及存储容量损失）。对于一个具有 256 MB 区域的 10TB 主机管理磁盘，dm-zoned 每个磁盘实例的内存使用量最多为 4.5 MB，且内部最多使用 5 个区域来存储元数据和执行回收（reclaim）操作。

dm-zoned 目标设备使用 dmzadm 工具进行格式化和检查，该工具可在以下位置获取：

https://github.com/hgst/dm-zoned-tools

## 算法


dm-zoned 实现了一种磁盘内缓冲（on-disk buffering）方案，用于处理对分区块设备顺序区域的乱序写入访问。
常规（conventional）区域用于缓存以及存储内部元数据。它也可以将常规块设备与分区块设备一起使用；在那种情况下，常规块设备将在逻辑上被拆分为与分区块设备相同大小的区域。这些区域将被放置在分区块设备区域的前面，并像常规区域一样被处理。

设备（们）的区域被分为 2 种类型：

1) 元数据区域：这些是常规区域，用于存储元数据。
元数据区域不作为可用容量报告给用户。

2) 数据区域：所有剩余的区域，其中绝大多数将是
专门用于存储用户数据的顺序区域。设备的常规区域也可用于缓冲用户随机写入。
这些区域中的数据可能直接映射到常规区域，但随后被移动到一个顺序区域，以便该常规区域可以被重用于缓冲传入的随机写入。

dm-zoned 暴露一个逻辑设备，其扇区大小为 4096 字节，无论所使用的后端分区块设备的物理扇区大小如何。这有助于减少管理有效块（已写入的块）所需的元数据量。

磁盘上的元数据格式如下：

1) 找到的第一个常规区域的第一个块包含超级块（super block），它描述了元数据的磁盘数量和位置。

2) 在超级块之后，一组块用于描述逻辑设备块的映射。映射按块（chunk）进行，块大小等于分区块设备大小。映射表由块号索引，每个映射条目指示存储该块数据的设备区域号。每个映射条目还可以指示是否使用了常规区域号来缓冲对数据区域的随机修改。

3) 一组用于存储位图（bitmap）的块紧接映射表之后，这些位图指示数据区域中块的有效性。有效块被定义为已写入且未被丢弃的块。对于一个被缓冲的数据块，一个块只有在映射该块的数据区域中或在块的缓冲区域中时才有效。

对于一个映射到常规区域的逻辑块，所有写操作都通过直接写入该区域来处理。如果映射区域是一个顺序区域，则只有当逻辑块内的写入偏移量等于顺序数据区域内的写指针偏移量（即写操作与区域写指针对齐）时，写操作才被直接处理。否则，写操作使用缓冲区域间接处理。在这种情况下，分配一个未使用的常规区域并分配给正在访问的块。将块写入块的缓冲区域将自动使映射该块的顺序区域中的相同块失效。如果顺序区域的所有块都失效，该区域被释放，块的缓冲区域变为映射该块的主区域，从而产生类似于常规块设备的原生随机写入性能。

读操作根据位图提供的块有效性信息进行处理。有效块从映射块的顺序区域读取，或者如果块被缓冲，则从分配的缓冲区域读取。如果访问的块没有映射，或者访问的块无效，读缓冲区被清零并终止读操作。

一段时间后，可用的有限数量的常规区域可能被耗尽（全部用于映射块或缓冲顺序区域），并且对未缓冲块的未对齐写入变得不可能。为了避免这种情况，一个回收（reclaim）进程会定期扫描已用的常规区域，并尝试通过将缓冲区域的有效块复制到空闲顺序区域来回收最近最少使用的区域。一旦复制完成，块映射被更新为指向顺序区域，并且缓冲区域被释放以供重用。

## 元数据保护


为了防止元数据在突然断电或系统崩溃时损坏，使用了 2 组元数据区域。一组（主集）用作主元数据区域，而另一组（次集）用作暂存区（staging area）。修改后的元数据首先写入次集，并通过更新次集中的超级块进行验证，使用一个代计数器（generation counter）来指示该集包含最新的元数据。一旦此操作完成，就可以在主元数据集中进行元数据块更新。这确保其中一组始终是一致的（所有修改都已提交，要么完全不提交）。flush 操作被用作提交点。收到 flush 请求后，元数据修改活动被临时阻止（对于传入的 BIO 处理和回收进程），并且所有脏元数据块被暂存并更新。然后恢复正常操作。因此刷新元数据只是暂时延迟了写入和丢弃请求。在元数据 flush 执行期间，读请求可以并发处理。

如果常规设备与分区块设备一起使用，则第三组元数据（不带区域位图）会被写入分区块设备的起始位置。此元数据的代计数器为 '0'，并且在正常操作期间永远不会被更新；它仅用于识别目的。元数据的第一份和第二份副本位于常规块设备的起始位置。

## 用法


分区块设备必须首先使用 dmzadm 工具进行格式化。这将分析设备的区域配置，确定在设备上放置元数据组的位置，并初始化元数据组。

```
	dmzadm --format /dev/sdxx
```
如果要使用两个驱动器，则必须指定两个设备，以常规块设备作为第一个设备。

```
	dmzadm --format /dev/sdxx /dev/sdyy
```
格式化后的设备也可以用 dmzadm 工具启动：

```
	dmzadm --start /dev/sdxx /dev/sdyy
```
关于区域内部布局和当前使用情况的信息可以通过 dmsetup 的 'status' 回调获取：

```
	dmsetup status /dev/dm-X
```
将返回一行

	0 <size> zoned <nr_zones> zones <nr_unmap_rnd>/<nr_rnd> random <nr_unmap_seq>/<nr_seq> sequential

其中 <nr_zones> 是区域总数，<nr_unmap_rnd> 是未映射（即空闲）的随机区域数，<nr_rnd> 是随机区域总数，<nr_unmap_seq> 是未映射的顺序区域数，<nr_seq> 是顺序区域总数。

通常，当空闲随机区域少于 50% 时，回收进程将启动。为了在达到此阈值之前手动启动回收进程，可以使用 'dmsetup message' 函数：

```
	dmsetup message /dev/dm-X 0 reclaim
```
将启动回收进程，随机区域将被移动到顺序区域。
