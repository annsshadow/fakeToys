Last modified: 2008-10-03

### 1. 简

ATA/ATAPI-7 规定了带unload（卸载）特性的 IDLE IMMEDIATE 命令。发出此
命令应使驱动器切换到空闲模式并卸载磁头。在现代笔记本电脑中，这一特与加速度计及相应软件配合使用，以实现减震保护功能。其思路是，在预见到
危急情况时，停止内部硬盘上的所I/O 操作，并将磁头停泊到斜坡（ramp上。在 GNU/Linux 系统上需要这样一个功能的愿望，是当初Linux 内核实现通用磁盘磁头停泊接口的原始动机。不过请注意，要让磁盘减震保护工作，
你的系统上还必须配置好其他组件（参见下文3 节“参考资料”以获取更多
相关信息）

### 2. 接口


对于每个 ATA 设备，内核在 sysfs 中导出文`block/*/device/unload_heads`
（此处假sysfs 挂载/sys 下）。如果设备不支持 unload 特性，`/sys/block/*/device/unload_heads` 的访问将-EOPNOTSUPP 拒绝。否则，
向该文件写入一个整数值会使相应驱动器的磁头离开盘片，并阻塞所I/O
操作指定的毫秒数。当超时到期、且期间没有再发出进一步的磁头停泊请求时，
将恢复正常操作。接受的超时最大值为 30000 毫秒。超出此限制将返-EOVERFLOW，但磁头仍会被停泊，且超时将被设30 秒。不过，你总可以在
前一个超时到期之前，通过发出后续的磁头停泊请求将超时改为 0 30000
之间的任意值。特别是，总超时可以超30 秒，更重要的是，你可以通过指定
超时 0 来取消之前设置的超时并立即恢复正常操作。小-2 的值会-EINVAL
拒绝（关-1 -2 的特殊含义见下文）。如果为最近一次磁头停泊请求指定的
超时尚未到期，那么从 `/sys/block/*/device/unload_heads` 读取将报告到
恢复正常操作所剩的毫秒数；否则，读unload_heads 属性将返回 0
例如，要对驱动器停泊磁头，请执行
```

	# echo 5000 > /sys/block/sda/device/unload_heads

```
```

	# cat /sys/block/sda/device/unload_heads

```
将显示恢复正常操作之前还剩多少毫秒
一句警告：该接口以毫秒为基础运作，这一事实可能让人产生现实中无法满的期望。事实上，ATA 规范明确指出，unload 操作完成的时间是厂商相关的ATA-7 中“通常会在 500 毫秒内完成”的提示ATA-8 中显然已被去掉
此实现有一个技术细节可能引起困惑，应在此讨论。当一次磁头停泊请求成发给某设备后，该设备所连控制器端口上的所I/O 操作都将被推迟。也就是说，
连接到同一端口的任何其他设备也会受到影响。唯一的例外是，对该另一设备后续磁头 unload 请求会立即执行。该端口上的进一步操作将被推迟，直到为该
端口上任一设备指定的超时到期。就 PATA（旧IDE）配置而言，任一端口最只能连接两个设备。在 SATA 世界中我们有端口乘法器（port multiplier），意味着用户对某一设备发出的磁头停泊请求，实际上可能导致停止对一大堆设备
I/O。不过，由于该特性预期用于笔记本电脑，在其他环境中似乎用处不大，
因此通常每个端口只有一个设备。即CD/DVD 刻录机恰好与硬盘连接到同一
端口，它一般也应当能从因对 HD 的磁头停泊请求而偶尔导致的缓冲欠载**良好**地恢复。实际上，当你使用的ide 驱动而非libata 对应驱动（即你的磁盘名为 /dev/hda 而非 /dev/sda），停泊一个驱动器（驱动器 X）的
磁头通常不会如上所述影响同一端口上另一驱动器（驱动Y）的运行模式。只当需要一个端口复位才能从驱动Y 上的异常中恢复时，该驱动器上的进一I/O
操作（以及复位本身）才会被推迟，直到驱动X 不再处于停泊状态
最后，有一些硬盘虽然也支持 unload 特性，但只符合早于 ATA-7 ATA 标准
版本。遗憾的是，Linux 无法安全地检测这些设备，因此你将无法写入
unload_heads 属性。如果你知道你的设备确实支持 unload 特性（例如，你笔记本电脑厂商或硬盘本身告诉过你），那么你可以通过写入来告知内核对驱动器启用此特性的使用
```

	# echo -1 > /sys/block/sda/device/unload_heads

```
将为 /dev/sda 启用该特性，而用 -2 代替 -1 则会再次禁用它
