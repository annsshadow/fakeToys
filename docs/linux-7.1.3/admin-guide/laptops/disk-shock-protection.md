### 1. 简介


ATA/ATAPI-7 规定了带有 unload（卸载）特性的 IDLE IMMEDIATE 命令。发出此
命令应使驱动器切换到空闲模式并卸载磁头。在现代笔记本电脑中，这一特性
与加速度计及相应软件配合使用，以实现减震保护功能。其思路是，在预见到
危急情况时，停止内部硬盘上的所有 I/O 操作，并将磁头停泊到斜坡（ramp）
上。在 GNU/Linux 系统上需要这样一个功能的愿望，是当初在 Linux 内核中
实现通用磁盘磁头停泊接口的原始动机。不过请注意，要让磁盘减震保护工作，
你的系统上还必须配置好其他组件（参见下文第 3 节“参考资料”以获取更多
相关信息）。


### 2. 接口


对于每个 ATA 设备，内核在 sysfs 中导出文件 `block/*/device/unload_heads`
（此处假定 sysfs 挂载于 /sys 下）。如果设备不支持 unload 特性，对
`/sys/block/*/device/unload_heads` 的访问将以 -EOPNOTSUPP 拒绝。否则，
向该文件写入一个整数值会使相应驱动器的磁头离开盘片，并阻塞所有 I/O
操作指定的毫秒数。当超时到期、且期间没有再发出进一步的磁头停泊请求时，
将恢复正常操作。接受的超时最大值为 30000 毫秒。超出此限制将返回
-EOVERFLOW，但磁头仍会被停泊，且超时将被设为 30 秒。不过，你总可以在
前一个超时到期之前，通过发出后续的磁头停泊请求将超时改为 0 到 30000
之间的任意值。特别是，总超时可以超过 30 秒，更重要的是，你可以通过指定
超时 0 来取消之前设置的超时并立即恢复正常操作。小于 -2 的值会以 -EINVAL
拒绝（关于 -1 和 -2 的特殊含义见下文）。如果为最近一次磁头停泊请求指定的
超时尚未到期，那么从 `/sys/block/*/device/unload_heads` 读取将报告到
恢复正常操作所剩的毫秒数；否则，读取 unload_heads 属性将返回 0。

例如，要对驱动器停泊磁头，请执行
```

	# echo 5000 > /sys/block/sda/device/unload_heads

```
```

	# cat /sys/block/sda/device/unload_heads

```
将显示恢复正常操作之前还剩多少毫秒。

一句警告：该接口以毫秒为基础运作，这一事实可能让人产生现实中无法满足
的期望。事实上，ATA 规范明确指出，unload 操作完成的时间是厂商相关的。
ATA-7 中“通常会在 500 毫秒内完成”的提示在 ATA-8 中显然已被去掉。

此实现有一个技术细节可能引起困惑，应在此讨论。当一次磁头停泊请求成功
发给某设备后，该设备所连控制器端口上的所有 I/O 操作都将被推迟。也就是说，
连接到同一端口的任何其他设备也会受到影响。唯一的例外是，对该另一设备的
后续磁头 unload 请求会立即执行。该端口上的进一步操作将被推迟，直到为该
端口上任一设备指定的超时到期。就 PATA（旧式 IDE）配置而言，任一端口最多
只能连接两个设备。在 SATA 世界中我们有端口乘法器（port multiplier），这
意味着用户对某一设备发出的磁头停泊请求，实际上可能导致停止对一大堆设备
的 I/O。不过，由于该特性预期用于笔记本电脑，在其他环境中似乎用处不大，
因此通常每个端口只有一个设备。即使 CD/DVD 刻录机恰好与硬盘连接到同一
端口，它一般也应当能从因对 HD 的磁头停泊请求而偶尔导致的缓冲欠载中
**良好**地恢复。实际上，当你使用的是 ide 驱动而非其 libata 对应驱动时
（即你的磁盘名为 /dev/hda 而非 /dev/sda），停泊一个驱动器（驱动器 X）的
磁头通常不会如上所述影响同一端口上另一驱动器（驱动器 Y）的运行模式。只有
当需要一个端口复位才能从驱动器 Y 上的异常中恢复时，该驱动器上的进一步 I/O
操作（以及复位本身）才会被推迟，直到驱动器 X 不再处于停泊状态。

最后，有一些硬盘虽然也支持 unload 特性，但只符合早于 ATA-7 的 ATA 标准
版本。遗憾的是，Linux 无法安全地检测这些设备，因此你将无法写入
unload_heads 属性。如果你知道你的设备确实支持 unload 特性（例如，你的
笔记本电脑厂商或硬盘本身告诉过你），那么你可以通过写入来告知内核对该
驱动器启用此特性的使用
```

	# echo -1 > /sys/block/sda/device/unload_heads

```
将为 /dev/sda 启用该特性，而用 -2 代替 -1 则会再次禁用它。


### 3. 参考资料


有多家厂商的若干笔记本电脑具备减震保护能力。由于厂商迄今拒绝支持所需
软件组件的开源开发，Linux 对不同硬件实现的减震保护支持差异很大。理想
情况下，本节应包含一个指向不同项目（旨在不同系统上实现减震保护）的列表。
可惜，我只知道一个项目，尽管仍被视为实验性，但已可投入使用。请随意补充
