
## 攻击向量控制


攻击向量控制提供了一种简单的方法，仅针对根据系统的预期用途而相关的 CPU 漏洞启用缓解
措施。鼓励管理员考虑哪些攻击向量是相关的，并禁用所有其他向量，以收回系统性能。

当发现新的相关 CPU 漏洞时，它们会被添加到这些攻击向量控制中，因此管理员很可能无需
重新配置其命令行参数，因为缓解措施将继续基于所选的攻击向量控制被正确应用。

### 攻击向量


内核目前支持 5 组攻击向量缓解措施：

#. user_kernel
#. user_user
#. guest_host
#. guest_guest
#. smt

要控制启用哪些攻击向量，请参阅 cmdline。

##### 用户到内核（User-to-Kernel）


用户到内核的攻击向量涉及恶意用户空间程序试图通过利用 CPU 漏洞将内核数据泄露到用户空间。
所涉及的内核数据可能仅限于某些内核内存，也可能包含系统中的全部内存，取决于所利用的
漏洞。

如果没有运行不受信任的用户空间应用程序（例如单用户系统），可以考虑禁用用户到内核的
缓解措施。

注意，Linux 缓解的 CPU 漏洞通常未被证明可从基于浏览器的沙箱中利用。因此，用户到内核的
缓解措施只有在不可信用户可能运行未知的用户空间应用程序时才大多相关。

**用户到内核的缓解措施默认启用**

##### 用户到用户（User-to-User）


用户到用户的攻击向量涉及恶意用户空间程序试图影响另一个毫无防备的用户空间程序的行为，
以窃取数据。用户空间程序的脆弱性基于程序本身及其提供的接口。

如果没有运行不受信任的用户空间应用程序，可以考虑禁用用户到用户的缓解措施。

注意，由于 Linux 内核包含全部物理内存的映射，要防止恶意用户空间程序从另一个用户空间
程序泄露数据，需要同时缓解用户到内核的攻击才能提供完整的保护。

**用户到用户的缓解措施默认启用**

##### 客体到主机（Guest-to-Host）


客体到主机的攻击向量涉及恶意 VM 试图将虚拟机监控器数据泄露到 VM 中。所涉及的数据可能是
有限的，也可能潜在包含系统中的全部内存，取决于所利用的漏洞。

如果没有运行不受信任的 VM，可以考虑禁用客体到主机的缓解措施。

**如果存在 KVM 支持，客体到主机的缓解措施默认启用**

##### 客体到客体（Guest-to-Guest）


客体到客体的攻击向量涉及恶意 VM 试图影响另一个毫无防备的 VM 的行为，以窃取数据。VM 的
脆弱性基于 VM 内部的代码及其提供的接口。

如果没有运行不受信任的 VM，或者只运行单个 VM，可以考虑禁用客体到客体的缓解措施。

与用户到用户的攻击向量类似，由于 Linux 内核的物理内存映射，防止恶意 VM 从另一个 VM 泄露
数据也需要同时缓解客体到主机的攻击。

**如果存在 KVM 支持，客体到客体的缓解措施默认启用**

##### 跨线程（Cross-Thread）


跨线程的攻击向量涉及恶意用户空间程序或恶意 VM 观察或试图影响运行在 SMT 兄弟线程上的
代码的行为，以窃取数据。

许多跨线程攻击只有在禁用 SMT 时才能被缓解，这将导致 CPU 核心数减少、性能降低。

如果跨线程缓解措施被完全启用（'auto,nosmt'），所有针对跨线程攻击的缓解措施都将被启用。
SMT 可能会根据 CPU 中存在哪些漏洞而被禁用。

如果跨线程缓解措施被部分启用（'auto'），针对跨线程攻击的缓解措施将被启用，但 SMT 不会被
禁用。

如果跨线程缓解措施被禁用，则不会启用任何针对跨线程攻击的缓解措施。

如果使用核心调度（core-scheduling）或类似技术来防止不受信任的工作负载在 SMT 兄弟线程上
运行，则可能不需要跨线程缓解。

**跨线程缓解措施默认部分启用**

### 命令行控制


攻击向量通过 mitigations= 命令行选项控制。所提供的值以全局选项开头，然后可以可选地
包含一个或多个用于禁用各种攻击向量的选项。

格式：
	| `mitigations=[global]`
	| `mitigations=[global],[attack vectors]`

全局选项：

============ =============================================================
Option       Description
============ =============================================================
'off'        禁用所有攻击向量。
'auto'       启用所有攻击向量，部分跨线程缓解。
'auto,nosmt' 启用所有攻击向量，完整跨线程缓解。
============ =============================================================

攻击向量选项：

================= =======================================
Option            Description
================= =======================================
'no_user_kernel'  禁用用户到内核的缓解措施。
'no_user_user'    禁用用户到用户的缓解措施。
'no_guest_host'   禁用客体到主机的缓解措施。
'no_guest_guest'  禁用客体到客体的缓解措施
'no_cross_thread' 禁用所有跨线程缓解措施。
================= =======================================

多个攻击向量选项可以用逗号分隔的列表指定。如果未指定全局选项，则默认为 'auto'。全局选项
'off' 等价于禁用所有攻击向量。

示例：
	| `mitigations=auto,no_user_kernel`

	启用除用户到内核外的所有攻击向量。部分跨线程缓解。

	| `mitigations=auto,nosmt,no_guest_host,no_guest_guest`

	启用所有攻击向量和跨线程缓解，除了客体到主机和客体到客体的缓解措施。

	| `mitigations=,no_cross_thread`

	启用所有攻击向量但不启用跨线程缓解。

### 与命令行选项的交互


特定于漏洞的控制（例如 "retbleed=off"）优先于所有攻击向量控制。无论攻击向量控制如何，
都可以通过各自的命令行选项开启或关闭单个漏洞的缓解措施。

### 攻击向量缓解措施摘要


当某个漏洞因攻击向量控制而被缓解时，使用的是该特定漏洞的默认缓解选项。要使用不同的
缓解措施，请使用特定于漏洞的命令行选项。

下表总结了在启用不同攻击向量（并假设 CPU 存在漏洞）时，哪些漏洞会被缓解。

攻击向量需要该缓解，或者通过特定于漏洞的命令行选项显式选择了该缓解。
