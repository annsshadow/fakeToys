


## 跨线程返回地址预测


某些 AMD 和 Hygon 处理器存在跨线程返回地址预测漏洞。当在 SMT 模式下运行且一个兄弟线程退出 C0
状态时，另一个兄弟线程可能会使用从该退出 C0 状态的兄弟线程得来的返回目标预测。

Spectre v2 缓解措施保护 Linux 内核，因为它在上下文切换到空闲线程时会用安全目标填充返回地址
预测条目。然而，KVM 确实允许 VMM 在退出 C0 时阻止退出客户机模式。这可能导致兄弟线程消耗一个
由客户机控制的返回目标。

### 受影响的处理器


以下 CPU 存在漏洞：

    - AMD Family 17h 处理器
    - Hygon Family 18h 处理器

### 相关 CVE


与以下问题相关的 CVE 条目如下：

   ==============  =======================================
   CVE-2022-27672  跨线程返回地址预测
   ==============  =======================================

### 问题


受影响的支持 SMT 的处理器在启用 SMT 时支持 1T 和 2T 执行模式。在 2T 模式下，核心中的两个线程
都在执行代码。要使处理器核心进入 1T 模式，需要其中一个线程请求退出 C0 状态。这可以通过 HLT
指令或请求非 C0 的 MWAIT 指令来传达。当该线程重新进入 C0 状态时，假设另一个线程也仍处于 C0
状态，处理器会切换回 2T 模式。

在受影响的处理器中，返回地址预测器（RAP）根据 SMT 模式进行分区。例如，在 2T 模式下每个线程
使用私有的 16 项 RAP，而在 1T 模式下，活动线程使用 32 项 RAP。在 1T/2T 模式之间切换时，RAP
内容不会被修改，但 RAP 指针（控制用于预测的下一个返回目标）可能会改变。此行为可能导致一个
SMT 线程的返回目标在 1T/2T 切换后被兄弟线程的 RET 预测使用。特别是，在切换到 1T 后立即执行的
RET 指令可能会使用刚变为空闲的线程的返回目标。理论上，如果所使用的返回目标并非来自可信代码，
这可能导致信息泄露。

### 攻击场景


可以通过在受影响处理器上执行一系列带有目标返回位置的 CALL 指令，然后退出 C0 状态来发起攻击。

### 缓解机制


在进入空闲状态之前，内核上下文切换到空闲线程。该上下文切换通过执行一系列 CALL 指令，用安全目标
填充 RAP 条目（在 Linux 中称为 RSB）。

通过拦截 HLT 和 MWAIT 指令，防止客户机 VM 直接将处理器置于空闲状态。

要完全解决此问题，两种缓解措施都是必需的。

### 内核命令行上的缓解控制


使用现有的 Spectre v2 缓解措施，它会在上下文切换时填充 RSB。

### 针对 KVM 的缓解控制 - 模块参数


默认情况下，KVM hypervisor 通过拦截客户机退出 C0 的尝试来缓解此问题。VMM 可以使用
KVM_CAP_X86_DISABLE_EXITS 能力覆盖这些拦截，但由于这不常见，覆盖此路径的缓解默认并未启用。

针对 KVM_CAP_X86_DISABLE_EXITS 能力的缓解可以通过布尔模块参数 mitigate_smt_rsb 开启，例如
`kvm.mitigate_smt_rsb=1`。
