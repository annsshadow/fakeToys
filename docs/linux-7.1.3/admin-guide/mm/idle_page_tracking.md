## Idle Page Tracking


## Motivation


空闲页面跟踪（idle page tracking）特性允许跟踪一个工作负载正在访问哪些内存页，以及哪些页面处于空闲状态。这一信息可用于估算工作负载的工作集（working set）大小，进而可在配置工作负载参数、设置内cgroup 限制，或决定在計算集群中将工作负载放置在何处时加以考虑
它由 CONFIG_IDLE_PAGE_TRACKING=y 启用

## User API


空闲页面跟踪 API 位于 `/sys/kernel/mm/page_idle`。目前它只包含一个可读写文件 `/sys/kernel/mm/page_idle/bitmap`
该文件实现了一个位图，其中每个位对应一个内存页。该位图由一8 字节整数的数组表示，PFN #i 的页映射到数组元#i/64 的位 #i%64，字节序为本地序。当一个位被置位时，对应的页为空闲
如果一个页自被标记为空闲以来未被访问，则被视为空闲（关访问"实际含义的更多细节，请参:ref:`实现细节 <impl_details>` 一节）。要将一个页标记为空闲，必须通过写入该文件来设置对应的位。写入文件的值会与当前位图值进OR 运算
只跟踪对用户内存页的访问。这些是被映射到进程地址空间的页、页缓存和缓冲区页、交换缓存页。对于其他页类型（例SLAB 页），将页标记为空闲的尝试会被静默忽略，因此这类页永远不会被报告为空闲
对于大页，空闲标志只设置在头页（head page）上，因此必须读`/proc/kpageflags` 才能正确统计空闲大页
如果你不是在 8 字节边界上开始读/写，或者读/写的大小不是 8 字节的倍数，则`/sys/kernel/mm/page_idle/bitmap` 的读或写会返-EINVAL。写入该文件超过最PFN 会返-ENXIO
也就是说，为了估算一个工作负载未使用的页面数量，应当
 1. 通过`/sys/kernel/mm/page_idle/bitmap` 中设置相应的位，将所有工作负载的页标记为空闲。如果这些页由一个进程表示，可以通过读取 `/proc/pid/pagemap` 找到它们；如果工作负载被放置在内cgroup 中，则可以通过 `/proc/kpagecgroup` 过滤掉外来页
 2. 等待工作负载访问它的工作集
 3. 读取 `/sys/kernel/mm/page_idle/bitmap` 并统计被置位的位数量。如果想忽略某些类型的页（例mlocked 页，因为它们不可回收），可以使用 `/proc/kpageflags` 将其过滤掉
tools/mm 目录下的 page-types 工具可用于协助此过程。如果该工具最初以适当的选项运行，它会将所有被查询的页标记为空闲。随后再次运行该工具就可以显示在此期间哪些页的空闲标志被清除了
关于 `/proc/pid/pagemap`、`/proc/kpageflags` `/proc/kpagecgroup` 的更多信息，请参Documentation/admin-guide/mm/pagemap.rst

## Implementation Details


内核在内部跟踪对用户内存页的访问，以便在内存不足时优先回收未被引用的页。如果一个页最近通过进程地址空间被访问过，则认为它被引用了，在这种情况下它映射到的一个或多个 PTE 会设Accessed 位，或者由内核显式标记为已访问（参mark_page_accessed()）。后者发生在以下情形
 - 用户空间进程使用系统调用（例read(2) write(2)）读或写一个页

 - 一个用于存储文件系统缓冲区的页被读或写，因为进程需要存储在其中的文件系统元数据（例如列出目录树
 - 一个设备驱动使get_user_pages() 访问一个页

当由于内存回收或超过脏内存限制而将脏页写入交换区或磁盘时，它不会被标记为已引用
空闲内存跟踪特性添加了一个新的页标志——Idle 标志。该标志通过写入 `/sys/kernel/mm/page_idle/bitmap`（参User API <user_api> 一节）手动设置，并在页面被如上定义的引用时自动清除
当一个页被标记为空闲时，必须清除它映射到的所PTE 中的 Accessed 位，否则我们将无法检测到来自进程地址空间对该页的访问。为了避免与回收器（reclaimer）产生干扰（如上所述，回收器使Accessed 位来提升被主动引用的页），又引入了一个页标志——Young 标志。当由于设置或更新一个页Idle 标志而清PTE Accessed 位时，会在该页上设置 Young 标志。回收器Young 标志视为额外PTE Accessed 位，因此会将这样的页视为已被引用
由于空闲内存跟踪特性基于内存回收器逻辑，它只对位于 LRU 列表上的页起作用，其他页会被静默忽略。这意味着它会忽略一个用户内存页（如果该页被隔离），但由于通常这样的页不多，不会对整体结果产生明显影响。为了不妨碍空闲页位图的扫描，被锁定的页也可能会被跳过
