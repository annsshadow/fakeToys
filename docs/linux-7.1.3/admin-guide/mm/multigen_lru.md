## 多代 LRU

多代 LRU LRU 的一种替代实现，它针对页回收进行了优化，并在内存压力
提升性能。页回收决定了内核的缓存策略以及超额提交（overcommit）内存的能力
它直接影kswapd CPU 使用率与内存效率

## 快速开

使用以下配置构建内核

- `CONFIG_LRU_GEN=y`
- `CONFIG_LRU_GEN_ENABLED=y`

全部完成

## 运行时选项

`/sys/kernel/mm/lru_gen/` 包含以下小节中描述的稳定 ABI

### 总开

`enabled` 接受不同的值，以启用或禁用下列组件。其默认值取决于
`CONFIG_LRU_GEN_ENABLED`。除非某些组件存在不可预见的副作用，否则应当启用
全部组件。当某个组件不被硬件支持时，`enabled` 写入不会产生任何效果
即使主开关处于关闭状态，有效的值也会被接受

====== ===============================================================
取组件
====== ===============================================================
0x0001 多代 LRU 的主开关
0x0002 MMU 设置页表项中的访问位时（例如 x86 上），以大批次方式清
       叶子页表项中的访问位。理论上该行为会加剧锁竞争（mmap_lock）。如
       禁用它，对于连续映射热页的工作负载，多代 LRU 会遭受轻微的性能下降
       因为否则可以用更少、更大的批次清除这些访问位
0x0004 MMU 设置页表项中的访问位时（例如 x86 上），同时清除非叶子页表
       中的访问位。除 Intel AMD 之外x86 变体上未验证该行为。如果禁
       它，多代 LRU 会遭受可忽略的性能下降
[yYnN] 应用于上述所有组件
====== ===============================================================

例如
```

    echo y >/sys/kernel/mm/lru_gen/enabled
    cat /sys/kernel/mm/lru_gen/enabled
    0x0007
    echo 5 >/sys/kernel/mm/lru_gen/enabled
    cat /sys/kernel/mm/lru_gen/enabled
    0x0005

```
### 抖动预防

个人计算机对抖动更为敏感，因为它会导致卡顿（渲染 UI 时的延迟）并对用户体
产生负面影响。多LRU 为大多数没有 `oomd` 的笔记本和台式机用户提供抖动
预防

用户可以`min_ttl_ms` 写入 `N`，以防止 `N` 毫秒内的工作集被换出。如
无法将该工作集保留在内存中，就会触发 OOM killer。换句话说，该选项相当于一
可调节的泄压阀，当它打开时，会终止那些希望未被使用的应用程序

基于人类可感知的平均延迟（约 100ms），`N=1000` 通常可以消除因抖动导致的
无法忍受的卡顿。更大的值（`N=3000`）会使卡顿不那么明显，但存在过早触发
OOM kill 的风险

默认`0` 表示禁用

## 实验特

`/sys/kernel/debug/lru_gen` 接受以下小节中描述的命令。支持多条命令行
也支持使用分隔符 `,` `;` 进行拼接

`/sys/kernel/debug/lru_gen_full` 提供额外的调试统计数据。`CONFIG_LRU_GEN_STATS=y`
会在此文件中保留被回收代的历史统计信息

### 工作集估

工作集估计用于衡量应用程序在给定时间间隔内需要多少内存，通常对应用程
性能的影响很小。例如，数据中心希望优化作业调度（装箱）以提高内存利用率
当新作业到来时，作业调度器需要先确定其管理的每台服务器是否能为该新作
分配一定量的内存，然后才能挑选候选服务器。为此，作业调度器需要估计现
作业的工作集

读取时，`lru_gen` 会返回针对每memcg 和节点的、在不同时间间隔内被访问
页数的直方图。`MAX_NR_GENS` 决定每个直方图的区间数量。这些直方图是非累积的
```

    memcg  memcg_id  memcg_path
       node  node_id
           min_gen_nr  age_in_ms  nr_anon_pages  nr_file_pages
           ...
           max_gen_nr  age_in_ms  nr_anon_pages  nr_file_pages

```
每个区间包含一段估计的、在 `age_in_ms` 内被访问的页数。例如，`min_gen_nr`
包含最冷的页，`max_gen_nr` 包含最热的页，因为前者的 `age_in_ms` 最大，
而后者的 `age_in_ms` 最小

用户可以`lru_gen` 写入以下命令来创建新的一`max_gen_nr+1`

    `+ memcg_id node_id max_gen_nr [can_swap [force_scan]]`

`can_swap` 默认采用交换（swap）设置；若将其设`1`，则会在交换关闭时强
扫描匿名页，反之亦然。`force_scan` 默认值为 `1`；若将其设为 `0`，则会采
启发式方法以降低开销，但同时也可能降低覆盖度

一个典型用例是：作业调度器按一定时间间隔运行该命令来创建新的代，并根据
该时间间隔所定义的冷页大小对其管理的服务器进行排名

### 主动回收

主动回收在没有内存压力时也会触发页回收，通常仅针对冷页。例如，当新作业
到来时，作业调度器希望在其选中的服务器上主动回收冷页，以提高成功部署该
新作业的机会

用户可以`lru_gen` 写入以下命令，以回收小于等于 `min_gen_nr` 的代

    `- memcg_id node_id min_gen_nr [swappiness [nr_to_reclaim]]`

`min_gen_nr` 应小`max_gen_nr-1`，因`max_gen_nr` `max_gen_nr-1`
尚未完全老化（等同于活跃链表），因此无法被回收。`swappiness` 会覆
`/proc/sys/vm/swappiness` 中的默认值，其有效范围为 [0-200, max]，其max
专用于匿名内存的回收。`nr_to_reclaim` 限制要回收的页数

一个典型用例是：作业调度器在尝试将新作业部署到某台服务器之前运行该命令
如果由于高估而未能生成足够的冷页，它会根据工作集估计步骤得到的排名结
