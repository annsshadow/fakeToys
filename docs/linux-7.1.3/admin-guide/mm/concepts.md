## 概念概述


Linux 中的内存管理是一个复杂的系统，它历经多年演进，包含越来越多
的功能，以支撑从没有 MMU 的微控制器到超级计算机等各种系统。没有 MMU
的系统所采用的内存管理称为 `nommu`，它确实值得一份专门的文档，希望
这份文档最终能够写出来。不过，尽管其中一些概念是相同的，这里我们假设
系统中存在 MMU，并且 CPU 能够将虚拟地址转换为物理地址。


## 虚拟内存入门


计算机系统中的物理内存是一种有限资源，即便对于支持内存热插拔的系统，
所能安装的内存总量也存在硬性上限。物理内存不一定是连续的；它可能是
作为一组互不相连的地址区间来访问的。此外，不同的 CPU 架构，甚至同一
架构的不同实现，对于这些地址区间如何定义都有着不同的视角。

这些都使得直接处理物理内存变得相当复杂，为了避免这种复杂性，人们
发展出了虚拟内存的概念。

虚拟内存将物理内存的细节从应用程序软件中抽象出来，允许只在物理内存
中保留必要的信息（按需分页），并提供进程之间数据保护与受控共享的机制。

有了虚拟内存，每一次内存访问都使用一个虚拟地址。当 CPU 解码一条从
（或向）系统内存读取（或写入）的指令时，它会将那条指令中编码的
`virtual`（虚拟）地址转换为内存控制器能够理解的 `physical`（物理）地址。

物理系统内存被划分为页帧，或称页。每页的大小与具体架构相关。某些架构
允许从若干个受支持的值中选择页大小；这种选择是在内核构建时通过
设置相应的内核配置选项来完成的。

每个物理内存页可以被映射为一个或多个虚拟页。这些映射由页表描述，
页表允许把程序使用的虚拟地址转换为物理内存地址。页表按层次结构组织。

层次结构最底层的表包含软件所使用的实际页的物理地址。更高层的表包含
属于下层的那些页的物理地址。指向顶层页表的指针存放在一个寄存器中。
当 CPU 执行地址转换时，它使用这个寄存器来访问顶层页表。虚拟地址的
高位用于在顶层页表中索引一个表项。随后该项被用来访问层次中的下一层，
以下一段虚拟地址位作为该层页表的索引。虚拟地址的最低几位定义了在实际
页内部的偏移量。

## 大页（Huge Pages）


地址转换需要多次访问内存，而内存访问相对于 CPU 速度而言是较慢的。为了
避免把宝贵的处理器周期耗费在地址转换上，CPU 维护着一个此类转换的缓存，
称为转换检测缓冲区（Translation Lookaside Buffer，即 TLB）。通常 TLB
是一种相当稀缺的资源，工作集较大的应用程序会因为 TLB 未命中而遭受
性能损失。

许多现代 CPU 架构允许由页表的高层直接映射内存页。例如，在 x86 上，
可以利用第二层和第三层页表中的表项映射 2M 乃至 1G 的页。在 Linux 中，
这样的页被称为 `huge`（大页）。使用大页能显著减轻 TLB 的压力，提高
TLB 命中率，从而提升系统的整体性能。

Linux 中有两种机制能够以大页形式映射物理内存。第一种是 `HugeTLB
文件系统`，即 hugetlbfs。它是一个以 RAM 作为后备存储的伪文件系统。
在这个文件系统中创建的文件，其数据驻留在内存中，并且使用大页映射。
hugetlbfs 在 Documentation/admin-guide/mm/hugetlbpage.rst 中有描述。

另一种较新的、能够使用大页的机制称为 `Transparent HugePages`，即
THP（透明大页）。与 hugetlbfs 需要用户和/或系统管理员配置系统中哪些
部分的内存应当并且可以由大页映射不同，THP 对用户透明地管理这类映射，
因此得名。关于 THP 的更多细节请参阅
Documentation/admin-guide/mm/transhuge.rst。

## 内存区域（Zones）


硬件经常会对不同物理内存区间的访问方式施加限制。在某些情况下，设备无法
对所有可寻址内存执行 DMA。在另一些情况下，物理内存的大小超过了虚拟内存
的最大可寻址大小，需要特殊的操作才能访问内存的某些部分。Linux 根据内存
页的可能用途将其分组到 `zones`（区域）中。例如，ZONE_DMA 将包含可供设备
进行 DMA 的内存，ZONE_HIGHMEM 将包含未永久映射到内核地址空间的内存，而
ZONE_NORMAL 将包含按常规方式寻址的页。

内存区域的实际布局依赖于硬件，因为并非所有架构都定义了所有区域，而且
不同平台对 DMA 的要求也不相同。

## 节点（Nodes）


许多多处理器机器是 NUMA —— 非一致内存访问（Non-Uniform Memory
Access）—— 系统。在这类系统中，内存被组织成若干个存储库（bank），
根据与处理器的“距离”远近，访问延迟各不相同。每个存储库被称为一个
`node`（节点），Linux 为每个节点构建一个独立的内存管理子系统。一个节点
拥有自己的一组区域、空闲页与已用页的链表以及各种统计计数器。关于 NUMA
的更多细节，可以参阅 Documentation/mm/numa.rst` 以及
Documentation/admin-guide/mm/numa_memory_policy.rst。

## 页缓存（Page cache）


物理内存是易失性的，将数据读入内存的常见情况是从文件中读取。每当读取
一个文件时，数据会被放入 `page cache`（页缓存），以避免后续读取时昂贵的
磁盘访问。类似地，当向文件写入时，数据被放入页缓存，并最终写入后备存储
设备。被写入的页被标记为 `dirty`（脏页），当 Linux 决定把它们另作他用时，
会确保将设备上的文件内容与更新后的数据同步。

## 匿名内存（Anonymous Memory）


`anonymous memory`（匿名内存）或 `anonymous mappings`（匿名映射）表示不
由文件系统作为后备的内存。这类映射会为程序的栈和堆隐式创建，或者通过
对 mmap(2) 系统调用的显式调用来创建。通常，匿名映射只定义程序被允许访问
的虚拟内存区域。读访问会导致创建一个引用特殊全零物理页的页表项。当程序
执行写操作时，会分配一个常规的物理页来保存写入的数据。该页会被标记为脏页，
如果内核决定重新利用它，这个脏页就会被换出。

## 回收（Reclaim）


在系统的整个生命周期中，一个物理页可用于存储不同类型的数据。它可以是
内核内部的数据结构、供设备驱动使用的可 DMA 缓冲区、从文件系统读取的数据、
用户空间进程分配的内存等等。

根据页的用途，Linux 内存管理对它们区别对待。那些随时可被释放的页 —— 要么
因为它们缓存了别处可得的数据（例如硬盘上），要么因为它们可以被换出（同样
换到硬盘上）—— 被称为 `reclaimable`（可回收）。最值得注意的可回收页类别
是页缓存和匿名内存。

在大多数情况下，持有内核内部数据以及用作 DMA 缓冲区的页无法被重新利用，
它们会一直保持固定（pinned），直到被其使用者释放为止。这样的页被称为
`unreclaimable`（不可回收）。然而，在某些情形下，即便是被内核数据结构占用的
页也可以被回收。例如，文件系统元数据的在内存缓存可以从存储设备重新读取，
因此在系统处于内存压力下时，可以将它们从主内存中丢弃。

释放可回收的物理内存页并重新加以利用的过程称为（没错，就是这么直白！）
`reclaim`（回收）。Linux 既可以异步也可以同步地回收页，这取决于系统的状态。
当系统负载不高时，大部分内存是空闲的，分配请求会立即从空闲页供给中得到
满足。随着负载增加，空闲页的数量下降，当它降到某个阈值（低水位线，low
watermark）时，分配请求会唤醒 `kswapd` 守护进程。它会异步地扫描内存页，
如果页中所包含的数据在别处可得就直接释放它们，否则就驱逐到后备存储设备
（还记得那些脏页吗？）。当内存使用量进一步增加并达到另一个阈值 —— 最小水位线
（min watermark）—— 时，分配会触发 `direct reclaim`（直接回收）。在这种
情况下，分配会被阻塞，直到回收出足够的内存页来满足请求为止。

## 内存规整（Compaction）


随着系统运行，任务不断地分配和释放内存，内存变得碎片化。尽管借助虚拟内存
可以把分散的物理页呈现为虚拟上连续的区间，但有时仍然需要分配大的物理连续
内存区域。这种需求可能出现在，例如，设备驱动需要一个大的 DMA 缓冲区，或者
THP 分配一个大页的时候。内存 `compaction`（规整）就是用来解决碎片问题的。
这种机制把已占用的页从内存区域的较低部分移动到该区域的较高部分的空闲页处。
当一次规整扫描结束时，空闲页会聚集到区域的起始位置，从而可以进行大的物理
连续区域的分配。

与回收类似，规整既可以在 `kcompactd` 守护进程中异步发生，也可以作为内存
分配请求的结果同步发生。

## OOM 杀手（OOM killer）


在一台负载较重的机器上，有可能出现内存耗尽、内核无法回收足够内存以继续
运转的情况。为了保全系统的其余部分，它会调用 `OOM killer`（OOM 杀手）。

`OOM killer` 会选择一个任务作为牺牲品，以换取整个系统的健康。被选中的任务
会被杀死，期望它退出后能释放足够的内存，使系统能够继续正常运行。
