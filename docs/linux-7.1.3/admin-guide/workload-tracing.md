
## 发现工作负载所使用的 Linux 内核子系统


:Authors: - Shuah Khan <skhan@linuxfoundation.org>
          - Shefali Sharma <sshefali021@gmail.com>
:maintained-by: Shuah Khan <skhan@linuxfoundation.org>

## 关键要点


 - 理解构建并运行一个工作负载所必需的系统资源是很重要的。
 - Linux 追踪（tracing）与 strace 可用于发现工作负载正在使用的系统资源。系统使用信息的完整性取决于工作负载覆盖的完整程度。
 - 操作系统的性能与安全性可以借助如下工具进行分析：
   `perf <https://man7.org/linux/man-pages/man1/perf.1.html>`_、
   `stress-ng <https://www.mankier.com/1/stress-ng>`_、
   `paxtest <https://github.com/opntr/paxtest-freebsd>`_。
 - 一旦我们发现并理解了工作负载的需求，就可以重点针对它们以避免回归，并用其来评估安全性方面的考量。

## 方法论


`strace <https://man7.org/linux/man-pages/man1/strace.1.html>`_ 是一个
诊断、教学与调试工具，可用于发现工作负载正在使用的系统资源。一旦我们发现并理解了
工作负载的需求，就可以重点针对它们以避免回归，并用其来评估安全性方面的考量。我们使用 strace 工具来追踪工作负载。

这种使用 strace 进行追踪的方法会告诉我们工作负载所发起的系统调用，但并不会包含它
可能发起的全部系统调用。此外，这种追踪方法只会告诉我们这些系统调用中被实际执行的
代码路径。例如，如果一个工作负载成功打开并读取了一个文件，那么被追踪的就是成功路径。
该次系统调用中的任何错误路径都不会被追踪。如果存在一个能够完整覆盖某工作负载的
负载，那么此处所述的方法将会追踪并找出所有可能的代码路径。系统使用信息的完整性
取决于工作负载覆盖的完整程度。

目标是在运行默认内核、无需安装自定义内核的系统上追踪工作负载。

## 我们如何收集细粒度的系统信息？


strace 工具可用于追踪进程发起的系统调用及其接收到的信号。系统调用是应用程序与
操作系统内核之间的基础接口，它们使程序能够向内核请求服务。例如，Linux 中的 open()
系统调用用于提供对文件系统中某个文件的访问。strace 使我们能够追踪应用程序发起的
所有系统调用，它会列出进程发起的所有系统调用及其结果输出。

你可以通过结合 strace 与 perf record 工具生成性能剖析数据，以记录与某个进程相关的
事件与信息，从而深入了解该进程。"perf annotate" 工具会生成程序每条指令的统计信息。
本文档将详细介绍如何收集工作负载使用系统资源的细粒度信息。

我们使用 strace 追踪了 perf、stress-ng、paxtest 这几个工作负载，以说明我们用于发现
工作负载所使用资源的方法。这一过程同样适用于追踪其他工作负载。

## 工作负载概览


如前所述，我们使用 strace 追踪了 perf bench、stress-ng 与 paxtest 这几个工作负载，
以展示如何分析一个工作负载并识别这些工作负载所使用的 Linux 子系统。让我们先概览这
三个工作负载，以便更好地理解它们的作用以及如何使用它们。

### perf bench (all) 工作负载


perf bench 命令包含多个多线程微内核基准测试，用于执行 Linux 内核中的不同子系统与
系统调用。这使我们能够轻松衡量变更所带来的影响，从而有助于缓解性能回归。它还充当
一个通用的基准测试框架，使开发者能够轻松创建测试用例、透明地集成，并使用丰富的
性能工具子系统。

### Stress-ng netdev 压力源工作负载


stress-ng 用于对内核进行压力测试。它允许你借助“压力源（stressor）”来演练计算机的
各种物理子系统以及操作系统内核的接口。这些压力源可用于 CPU、CPU 缓存、设备、I/O、
中断、文件系统、内存、网络、操作系统、管道、调度器以及虚拟机。请参考
`stress-ng man-page <https://www.mankier.com/1/stress-ng>`_ 查看所有可用压力源的描述。
netdev 压力源会启动指定数量（N）的工作进程，跨所有可用的网络设备演练各种 netdevice
ioctl 命令。

### paxtest kiddie 工作负载


paxtest 是一个用于测试内核中缓冲区溢出的程序。它测试内核对内存使用施加的限制。通常，
在某些内存段中执行会使缓冲区溢出成为可能。它会运行一组试图破坏内存使用的程序。它被
用作 PaX 的回归测试套件，但也可能有助于测试内核的其他内存保护补丁。我们使用的
paxtest kiddie 模式用于查找简单的漏洞。

## 什么是 strace，我们如何使用它？


如前所述，strace 是一个有用的诊断、教学与调试工具，可用于发现工作负载正在使用的
系统资源。它可以用于：

 - 查看进程如何与内核交互。
 - 查看某个进程为何失败或挂起。
 - 对进程进行逆向工程。
 - 查找程序所依赖的文件。
 - 分析应用程序的性能。
 - 排查与操作系统相关的各类问题。

此外，strace 可以为每个系统调用生成关于耗时、调用次数与错误的运行时统计，并在程序
退出时输出一份摘要，同时抑制常规输出。这会尝试展示系统时间（即运行在内核中消耗的
CPU 时间），与墙上时钟时间相互独立。我们计划利用这些特性来获取工作负载系统使用情况的
信息。

strace 命令支持基本、详细与统计三种模式。strace 命令在详细模式下运行时会给出关于
进程所发起系统调用的更详细信息。

运行 `strace -c` 会生成一份报告，包含每个系统调用所占用时间的百分比、总耗时（秒）、
每次调用的微秒数、调用总次数、因错误而失败的系统调用计数，以及所发起系统调用的类型。

 - 用法：strace <要追踪的命令>
 - 详细模式用法：strace -v <命令>
 - 收集统计：strace -c <命令>

我们使用 “-c” 选项来收集本分析中选定的三个工作负载在运行时使用的细粒度统计信息。

 - perf
 - stress-ng
 - paxtest

## 什么是 cscope，我们如何使用它？


现在让我们看看 `cscope <https://cscope.sourceforge.net/>`_，这是一个用于浏览 C、C++
或 Java 代码库的命令行工具。我们可以用它来查找对某个符号的所有引用、全局定义、某
函数调用的函数、调用某函数的函数、文本字符串、正则表达式模式，以及包含某文件的文件。

我们可以使用 cscope 来查找某个系统调用属于哪个子系统。通过这种方式，我们能够在进程
执行时发现其所使用的内核子系统。

```
  git clone git://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git linux
  cd linux
  cscope -R -p10  # builds cscope.out database before starting browse session
  cscope -d -p10  # starts browse session on cscope.out database

```

注意：运行 "cscope -R -p10" 以构建数据库，运行 "cscope -d -p10" 以进入浏览会话。
cscope 默认使用 cscope.out 数据库。要退出该模式请按 ctrl+d。-p 选项用于指定要显示的
文件路径组件个数。-p10 对于浏览内核源码来说是最优的。

## 什么是 perf，我们如何使用它？


Perf 是一个基于 Linux 2.6+ 系统的分析工具，它抽象了 Linux 中性能度量的 CPU 硬件差异，
并提供了一个简单的命令行接口。Perf 基于内核导出的 perf_events 接口，对于剖析系统以及
查找应用程序中的性能瓶颈非常有用。

如果你尚未检出 Linux 主线仓库，可以执行：

```
  git clone git://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git linux
  cd linux
  make -j3 all
  cd tools/perf
  make

```

注意：perf 命令无需构建仓库中的内核即可编译，并且可以在较旧的内核上运行。不过，使
内核与 perf 的版本相匹配能够获得关于子系统使用情况更准确的信息。

我们使用了 "perf stat" 与 "perf bench" 选项。要获取关于 perf 工具的详细信息，请运行
"perf -h"。

### perf stat


perf stat 命令会生成一份关于各种硬件与软件事件的报告。它借助现代 CPU 中用于对这些
活动进行计数的硬件计数器寄存器来实现。"perf stat cal" 会显示 cal 命令的统计信息。

### Perf bench


perf bench 命令包含多个多线程微内核基准测试，用于执行 Linux 内核中的不同子系统与
系统调用。这使我们能够轻松衡量变更所带来的影响，从而有助于缓解性能回归。它还充当
一个通用的基准测试框架，使开发者能够轻松创建测试用例、透明地集成，并使用丰富的
性能工具。

"perf bench all" 命令会运行以下基准测试：

 - sched/messaging
 - sched/pipe
 - syscall/basic
 - mem/memcpy
 - mem/memset

## 什么是 stress-ng，我们如何使用它？


如前所述，stress-ng 用于对内核进行压力测试。它允许你借助压力源来演练计算机的各种
物理子系统以及操作系统内核的接口。这些压力源可用于 CPU、CPU 缓存、设备、I/O、中断、
文件系统、内存、网络、操作系统、管道、调度器以及虚拟机。

netdev 压力源会启动 N 个工作进程，跨所有可用的网络设备演练各种 netdevice ioctl
命令。以下 ioctl 会被演练：

 - SIOCGIFCONF, SIOCGIFINDEX, SIOCGIFNAME, SIOCGIFFLAGS
 - SIOCGIFADDR, SIOCGIFNETMASK, SIOCGIFMETRIC, SIOCGIFMTU
 - SIOCGIFHWADDR, SIOCGIFMAP, SIOCGIFTXQLEN

```
  stress-ng --netdev 1 -t 60 --metrics command.

```

我们可以使用 perf record 命令来记录与某个进程相关的事件与信息。该命令会将剖析数据
记录在同一目录下的 perf.data 文件中。

使用以下命令，你可以记录与 netdev 压力源相关的事件，查看生成的报告 perf.data，并对
其进行注解：

```
  perf record stress-ng --netdev 1 -t 60 --metrics command.
  perf report
  perf annotate

```

## 什么是 paxtest，我们如何使用它？


paxtest 是一个用于测试内核中缓冲区溢出的程序。它测试内核对内存使用施加的限制。通常，
在某些内存段中执行会使缓冲区溢出成为可能。它会运行一组试图破坏内存使用的程序。它被
用作 PaX 的回归测试套件，并且对于测试内核的其他内存保护补丁也很有用。

paxtest 提供 kiddie 与 blackhat 两种模式。paxtest kiddie 模式以正常模式运行，而
blackhat 模式则试图绕过内核的保护以测试漏洞。我们在此重点关注 kiddie 模式，并将
"paxtest kiddie" 的运行与 "perf record" 结合，以收集 paxtest kiddie 运行的 CPU 栈
回溯，从而查看在性能剖析中是哪个函数在调用其他函数。随后可以使用 "dwarf"（DWARF 的
调用帧信息）模式来回溯栈。

可以使用以下命令在调用图中查看生成的报告：

```
  perf record --call-graph dwarf paxtest kiddie
  perf report --stdio

```
