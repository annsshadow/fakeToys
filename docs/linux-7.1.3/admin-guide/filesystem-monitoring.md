
## 使用 fanotify 进行文件系统监控


## 文件系统错误上报


Fanotify 支持 FAN_FS_ERROR 事件类型，用于整个文件系统的错误上报。它旨在供文件系统健康监控守护进程使用，这些守护进程监听这些事件，并在检测到文件系统问题时采取行动（通知系统管理员、启动恢复）
按设计，FAN_FS_ERROR 通知暴露了足够的信息，让监控工具能够知道文件系统中发生了问题。它不一定向用户空间应用提供用于验证某次 IO 操作是否成功执行的语义。这超出了本特性的范围。相反，它只作为一个用于早期检测文件系统问题并报告恢复工具的框架
当文件系统操作失败时，初始故障之后常会级联出几十个内核错误，从而掩盖了原始故障日志——而原始故障日志通常是最有用的调试数据。因此，FAN_FS_ERROR 只尝试上报自上次通知以来文件系统中发生的第一个错误，并简单地对额外的错误进行计数。这确保了最重要的信息永远不会丢失
FAN_FS_ERROR 要求 fanotify 组使FAN_REPORT_FID 标志来建立
在撰写本文时，唯一发出 FAN_FS_ERROR 通知的文件系统是 Ext4
```

  ::

     [ 通知元数据（必选） ]
     [ 通用错误记录  （必选） ]
     [ FID 记录            （必选） ]

```

记录的顺序无法保证，并且未来可能会添加新的记录。因此，应用程序不能依赖顺序，并且必须准备好跳过未知的记录。有关解析器的示例，请参`samples/fanotify/fs-monitor.c`
### 通用错误记录


通用错误记录提供了足够的信息，让与文件系统无关的工具能够了解文件系统中的问题，而无需提供关于该问题的任何额外细节。该记录`struct fanotify_event_info_header.info_type` 被设置为 FAN_EVENT_INFO_TYPE_ERROR 来标识
```

     struct fanotify_event_info_error {
          struct fanotify_event_info_header hdr;
         __s32 error;
         __u32 error_count;
     };

```

`error` 字段使用 errno 值来标识错误类型。`error_count` 记录自上次通知以来发生并被抑制（以保留原始错误信息）的错误数量
### FID 记录


FID 记录可用于通过 fsid 与文件句柄的组合来唯一标识触发错误inode。一个文件系统特定的应用可以利用该信息尝试进行恢复操作。与 inode 无关的错误会以类型为 FILEID_INVALID 的空文件句柄来上报
