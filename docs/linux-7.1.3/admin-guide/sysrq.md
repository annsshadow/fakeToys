## Linux 魔术系统请求键（Magic SysRq Key）技巧

sysrq.c 的文档

#### 什么是魔术 SysRq 键？

它是你可以按下的一个“魔术”组合键，内核会对其作出响应，而不管它正在做其他什么事——除非它已完全死锁。

#### 如何启用魔术 SysRq 键？

在配置内核时，你需要对 “Magic SysRq key (CONFIG_MAGIC_SYSRQ)” 回答 “yes”。当运行一个编译了 SysRq 的内核时，`/proc/sys/kernel/sysrq` 控制允许通过 SysRq 键调用的功能。该文件的默认值由 `CONFIG_MAGIC_SYSRQ_DEFAULT_ENABLE` 配置符号设置，其自身默认值为 1。以下是 `/proc/sys/kernel/sysrq` 中可能的取值列表：

   - 0 - 完全禁用 sysrq
   - 1 - 启用 sysrq 的所有功能
   - >1 - 允许的 sysrq 功能的位掩码（详细功能见下文）

```
          2 =   0x2 - 启用控制台日志级别控制
          4 =   0x4 - 启用键盘控制（SAK、unraw）
          8 =   0x8 - 启用进程等调试转储
         16 =  0x10 - 启用 sync 命令
         32 =  0x20 - 启用以只读方式重新挂载
         64 =  0x40 - 启用向进程发信号（term、kill、oom-kill）
        128 =  0x80 - 允许重启/关机
        256 = 0x100 - 允许对所有 RT 任务进行 nice 调整

```
```
    echo "number" >/proc/sys/kernel/sysrq

```
这里写入的数值可以是十进制，也可以是带 0x 前缀的十六进制。`CONFIG_MAGIC_SYSRQ_DEFAULT_ENABLE` 必须始终以十六进制写入。

注意，`/proc/sys/kernel/sysrq` 的值只影响通过键盘的调用。通过 `/proc/sysrq-trigger` 调用任何操作总是被允许的（由具有管理员权限的用户）。

#### 如何使用魔术 SysRq 键？

在 x86 上
	按下组合键 `ALT-SysRq-<命令键>`。

```
	   Some
           有些键盘可能没有标为 'SysRq' 的键。'SysRq' 键也被称为 'Print Screen' 键。另外，有些键盘无法同时处理这么多按键被按下，所以你不妨尝试以下方式：按下 `Alt`，按下 `SysRq`，
	   释放 `SysRq`，按下 `<命令键>`，释放所有键。

```
在 SPARC 上
	你按下 `ALT-STOP-<命令键>`，我相信是这样。

在串口控制台上（仅限 PC 风格的标准串口）
        你发送一个 `BREAK`，然后在 5 秒内发送一个命令键。发送两次
        `BREAK` 会被解释为普通的 BREAK。

在 PowerPC 上
	按下 `ALT - Print Screen`（或 `F13`）- `<命令键>`。
        `Print Screen`（或 `F13`）- `<命令键>` 可能就足够了。

在其他架构上
	如果你知道其他架构的按键组合，请提交一个补丁以便纳入本节。

在所有架构上
	向 /proc/sysrq-trigger 写入单个字符。
	只处理第一个字符，字符串的其余部分被忽略。但是，不建议写入任何额外的字符，因为行为未定义，并且可能在未来的版本中改变。
```
		echo t > /proc/sysrq-trigger

	或者，写入以下划线为前缀的多个字符。
	这样，所有字符都会被处理。例如：

		echo _reisub > /proc/sysrq-trigger

```
`<命令键>` 区分大小写。

#### “命令”键有哪些？

=========== ===================================================================
命令        功能
=========== ===================================================================
`b`	    将立即重启系统，不同步或卸载你的磁盘。

`c`	    将执行一次系统崩溃，如果已配置则会获取崩溃转储（crashdump）。

`d`	    显示所有被持有的锁。

`e`	    向除 init 之外的所有进程发送 SIGTERM。

`f`	    将调用 oom killer 来杀死一个占用内存的进程，但如果无可杀死者也不会 panic。

`g`	     由 kgdb（内核调试器）使用

`h`	    将显示帮助（实际上，这里列出的任何其他键也会显示帮助。但 `h` 容易记住 :-)

`i`	    向除 init 之外的所有进程发送 SIGKILL。

`j`	    强制 “Just thaw it”（解冻它）——由 FIFREEZE ioctl 冻结的文件系统。

`k`	    安全访问键（SAK，Secure Access Key）杀死当前虚拟控制台上所有程序。注意：参见下文 SAK 一节中的重要注释。

`l`	    显示所有活动 CPU 的栈回溯。

`m`	    将转储当前内存信息到你的控制台。

`n`	    用于使 RT 任务可被 nice 调整。

`o`	    将关闭你的系统（如果已配置且受支持）。

`p`	    将转储当前寄存器和标志到你的控制台。

`q`	    将转储所有已触发的 hrtimer 的每 CPU 列表（但不含常规的 timer_list 定时器）以及关于所有时钟事件设备的详细信息。

`r`	    关闭键盘原始（raw）模式并将其设置为 XLATE。

`s`	    将尝试同步所有已挂载的文件系统。

`t`	    将转储当前任务列表及其信息到你的控制台。

`u`	    将尝试以只读方式重新挂载所有已挂载的文件系统。

`v`	    强制恢复帧缓冲控制台
`v`	    导致 ETM 缓冲区转储 [ARM 专用]

`w`	    转储处于不可中断（阻塞）状态的任务。

`x`	     由 ppc/powerpc 平台上的 xmon 接口使用。
            在 sparc64 上显示全局 PMU 寄存器。
            在 MIPS 上转储所有 TLB 条目。

`y`	    显示全局 CPU 寄存器 [SPARC-64 专用]

`z`	    转储 ftrace 缓冲区

`0`-`9` 设置控制台日志级别，控制哪些内核消息将被打印到你的控制台。（例如，`0` 会使得只有像 PANIC 或 OOPS 这样的紧急消息才会到达你的控制台。）

`R`	    在控制台上重放内核日志消息
=========== ===================================================================

#### 那么，我可以用它们来做什么？

当你的 X 服务器或 svgalib 程序崩溃时，unraw(r) 非常方便。

sak(k)（安全访问键）在你想要确保没有可能在你尝试登录时窃取密码的木马程序运行于控制台时很有用。它会杀死给定控制台上的所有程序，从而让你确信所看到的登录提示确实是来自 init 的那个，而非某个木马程序。

   它在其真正形态上并非像 c2 兼容系统上那样的真正 SAK，不应被误认为是那样。

其他人发现它作为（System Attention Key，系统注意键）也很有用，当你想退出一个不让你切换控制台的某个程序时（例如 X 或 svgalib 程序）。

`reboot(b)` 在你无法关机时很有用，它等效于按下 “reset”（重置）按钮。

`crash(c)` 可用于在系统挂起时手动触发崩溃转储。注意，如果没有可用的转储机制，这只会触发一次崩溃。

`sync(s)` 在拔出可移动介质之前或在使用一个不提供优雅关机的救援 shell 之后很方便——它将确保你的数据被安全地写入磁盘。注意，在你看到屏幕上出现 “OK” 和 “Done” 之前，sync 尚未完成。

`umount(u)` 可用于将文件系统标记为正确卸载。从运行中的系统的角度看，它们将被以只读方式重新挂载。在你看到屏幕上出现 “OK” 和 “Done” 消息之前，重新挂载尚未完成。

日志级别 `0`-`9` 在你的控制台被你不想要的内核消息淹没时很有用。选择 `0` 将阻止除最紧急的内核消息之外的所有消息到达你的控制台。（不过，如果 syslogd/klogd 还活着，它们仍会被记录。）

`term(e)` 和 `kill(i)` 在你有一些无法以其他方式杀死的失控进程时很有用，尤其是当它在衍生其他进程时。

“just thaw `it(j)`”（解冻它）在你系统因通过 FIFREEZE ioctl 冻结的（很可能是根）文件系统而变得无响应时很有用。

`Replay logs(R)`（重放日志）在系统挂起或你无法使用 dmesg 命令查看 printk 缓冲区中的消息时，用于查看内核日志消息很有用。如果控制台系统繁忙，用户可能必须多次按下组合键。如果它已完全死锁，那么消息不会被打印。输出消息取决于当前控制台日志级别，可以使用 sysrq[0-9]（见上文）修改。

#### 有时在使用 SysRq 之后它似乎会“卡住”，我该怎么办？

当这种情况发生时，尝试在键盘两侧轻敲 shift、alt 和 control，并再次按下一个无效的 sysrq 序列。（即类似 `alt-sysrq-z` 这样的。）

切换到另一个虚拟控制台（`ALT+Fn`）然后再切回来也应该有帮助。

#### 我按了 SysRq，但似乎什么也没发生，哪里出错了？

有些键盘为 SysRq 产生的键码不同于预定义值 99
（参见 `include/uapi/linux/input-event-codes.h` 中的 `KEY_SYSRQ`），或者根本没有 SysRq 键。在这些情况下，运行 `showkey -s` 来查找合适的扫描码序列，并使用 `setkeycodes <sequence> 99` 将该序列映射到通常的 SysRq 码（例如 `setkeycodes e05b 99`）。最好将此命令放入引导脚本中。哦，顺便说一句，你通过十秒内不输入任何内容来退出 `showkey`。

#### 我想向模块中添加 SysRQ 键事件，它是如何工作的？

为了向表中注册一个基本函数，你必须首先包含头文件 `include/linux/sysrq.h`，这将定义你需要的所有其他内容。接下来，你必须创建一个 `sysrq_key_op` 结构，并填入 A）你将使用的键处理程序函数，B）一个 help_msg 字符串（在 SysRQ 打印帮助时打印），以及 C）一个 action_msg 字符串（在你的处理程序被调用之前立即打印）。你的处理程序必须符合 'sysrq.h' 中的原型。

在创建 `sysrq_key_op` 之后，你可以调用内核函数 `register_sysrq_key(int key, const struct sysrq_key_op *op_p);`，如果表中的该槽位为空，这将在表的键 'key' 处注册由 `op_p` 指向的操作。在模块卸载时，你必须调用函数 `unregister_sysrq_key(int key, const struct sysrq_key_op *op_p)`，当且仅当该键操作当前注册在该槽位时，它才会从键 'key' 中移除由 'op_p' 指向的键操作。这是为了防止该槽位自你注册后被覆盖。

魔术 SysRQ 系统通过针对一个键操作查找表注册键操作来工作，该表定义于 'drivers/tty/sysrq.c'。该键表在编译时被注册了若干操作，但它是可变的。

```
	register_sysrq_key 和 unregister_sysrq_key。

```
当然，永远不要在表中留下无效指针。也就是说，当调用了 `register_sysrq_key()` 的模块退出时，它必须调用 `unregister_sysrq_key()` 来清理它所使用的 sysrq 键表项。表中的空指针始终是安全的。:)

如果由于某种原因你觉得需要在由 handle_sysrq 调用的函数内部调用 handle_sysrq 函数，你必须意识到你正处于一个锁中（你同时也处于中断处理程序中，这意味着不要睡眠！），因此你必须改用 `__handle_sysrq_nolock`。

#### 当我按下 SysRq 键组合时，控制台上只出现了头部？

Sysrq 输出与其他所有控制台输出一样，受相同的控制台日志级别控制。这意味着，如果内核是以 'quiet' 引导（这在发行版内核中很常见），输出可能不会出现在实际控制台上，尽管它会出现在 dmesg 缓冲区中，并且可通过 dmesg 命令以及 `/proc/kmsg` 的消费者访问。作为一个特定例外，sysrq 命令的头部行会被传递给所有控制台消费者，就好像当前日志级别是最大值一样。如果只输出了头部，几乎可以肯定是内核日志级别过低。如果你需要在控制台通道上获取输出，那么你将需要：

```
    echo 8 > /proc/sysrq-trigger

```
在触发你感兴趣的 sysrq 命令之后，记得将日志级别恢复正常。
