
## 动态热功耗管理（Dynamic Thermal Power Management）框

在嵌入式领域，SoC 的复杂性导致越来越多的热点需要作为一个整体进行监控和缓解，以防止温度超过规范和法律规定的“皮肤温度（skin temperature）”
另一个方面是在给定的功耗预算内维持性能，例如虚拟现实场景中，如果性能在大 CPU 处理其他事务时被限制，用户会感到眩晕。或者，由于耗散功率相对于其他设备消耗的功率过高，而降低电池充电速度
用户空间是动态作用于不同设备的最合适位置，它可以根据应用程序配置文件通过限制设备的功率来施加影响：它掌握平台的状况
动态热功耗管理（DTPM）是一种通过在不同设备之间限制和/或平衡功耗预算来作用于设备功率的技术
DTPM 框架提供了一个统一的接口来作用于设备功率
## 概述


DTPM 框架依赖 powercap 框架sysfs 目录中创powercap 条目，并实现后端驱动以完成与可功耗管理设备的连接
DTPM 是一种树形表示，描述设备之间共享的功率约束，而非它们的物理位置
树的节点是对子节点的功率特性及其功率限制进行聚合的虚拟描述
树的叶子是真实的可功耗管理设备
```

  SoC
   |
   `-- pkg
	|
	|-- pd0 (cpu0-3)
	|
	`-- pd1 (cpu4-5)

```
```

  SoC (400mW - 3100mW)
   |
   `-- pkg (400mW - 3100mW)
	|
	|-- pd0 (100mW - 700mW)
	|
	`-- pd1 (300mW - 2400mW)

```
```

  SoC (600mW - 5900mW)
   |
   |-- pkg (400mW - 3100mW)
   |    |
   |    |-- pd0 (100mW - 700mW)
   |    |
   |    `-- pd1 (300mW - 2400mW)
   |
   `-- pd2 (200mW - 2800mW)

```
```

  SoC (w=1024)
   |
   |-- pkg (w=538)
   |    |
   |    |-- pd0 (w=231)
   |    |
   |    `-- pd1 (w=794)
   |
   `-- pd2 (w=486)

   注意同一层级的权重之和等1024
```
```

  SoC (w=1024) <--- power_limit = 3200mW
   |
   |-- pkg (w=538) --> power_limit = 1681mW
   |    |
   |    |-- pd0 (w=231) --> power_limit = 378mW
   |    |
   |    `-- pd1 (w=794) --> power_limit = 1303mW
   |
   `-- pd2 (w=486) --> power_limit = 1519mW



```
### 扁平描述


将创建一个根节点，它是所有节点的父节点。这种描述是最简单的一种，旨在向用户空间提供所有支持功率限制设备的扁平表示，而无需任何功率限制分配
### 分层描述


支持功率限制的不同设备以分层方式表示。有一个根节点，所有中间节点对子节点进行分组，这些子节点也可以是中间节点或真实设备
中间节点聚合功率信息，并允许根据节点的权重设置功率限制
## 用户空间 API


正如概述中所述，DTPM 框架构建powercap 框架之上。因sysfs 接口是相同的，更多细节请参阅 powercap 文档
 - power_uw：瞬时功耗。如果节点是中间节点，则功耗将是所有子节点功耗之和
 - max_power_range_uw：由最大功率减去最小功率得到的功率范围
 - name：节点的名称。这取决于具体实现。即使用户空间不推荐，多个节点也可以具有相同的名称
 - constraint_X_name：约束的名称
 - constraint_X_max_power_uw：适用于该节点的最大功率限制
 - constraint_X_power_limit_uw：要应用于该节点的功率限制。如果设置了 constraint_X_max_power_uw 中包含的值，则该约束将被移除
 - constraint_X_time_window_us：该文件的含义取决于约束编号
### 约束


 - 约束 0：立即应用功率限制，在时间上不加限制
## 内核 API


### 概述


DTPM 框架没有功耗限制后端支持。它是通用的，并提供一API，让不同的驱动实现功耗限制的后端部分并创建功率约束树
由平台提供初始化函数，以分配并链接树的不同节点
有一个特殊的宏，其作用是通过一个描述结构声明一个节点及相应的初始化函数。该结构包含一个可选的 parent 字段，允许在启动时将不同设备挂接到已存在的树上
```

	struct dtpm_descr my_descr = {
		.name = "my_name",
		.init = my_init_func,
	};

	DTPM_DECLARE(my_descr);

```
DTPM 树的节点通过 dtpm 结构描述。添加一个新的可功率限制设备的步骤如下三步：

 - 分配 dtpm 节点
 - 设置 dtpm 节点的功率数 - 注册 dtpm 节点

dtpm 节点的注册通过 powercap ops 完成。基本上，它必须实现用于获取和设置功率及限制的回调
或者，如果要插入的节点是中间节点，则可以使用一个简单的函数将其作为未来的父节点插入
如果某个设备的功率特性发生变化，则必须使用新的功率数值和权重更新树
### 术语


 - dtpm_alloc()：分配并初始化一dtpm 结构

 - dtpm_register()：将 dtpm 节点添加到树
 - dtpm_unregister()：从树中移除 dtpm 节点

 - dtpm_update_power()：更dtpm 节点的功率特
