## RT 互斥体（rt-mutex）子系统的优先级继承（PI）支

RT 互斥体通过优先级继承（priority inheritance）来支持 PI-futexes，从而启pthread_mutex_t 的优先级继承属性（PTHREAD_PRIO_INHERIT）。[参见文档/锁机pi-futex.rst 了解更多关于 PI-futexes 的细节。]

该技术源-rt 树，并对 pthread_mutex 的支持进行了精简

### 基本原理

RT 互斥体在简单互斥体（mutex）的语义之上扩展出优先级继承协议

当一个低优先级的属主（owner）持有某RT 互斥体时，它会继承等待者（waiter）中最高优先级的优先级，直到该 RT 互斥体被释放。当被临时提升优先级的属主自身又阻塞在另一RT 互斥体上时，优先级提升会沿等待链继续传播。一RT 互斥体被解锁，优先级提升会立即被撤销

这种方法使我们能够缩短高优先级任务被保护共享资源的互斥体阻塞的时间。优先级继承并非解决设计不良应用的灵丹妙药；但它允许设计良好的应用在对关键部分使用用户空间锁的高优先级线程时，不会丧失确定性

等待者会按优先级顺序排入 rtmutex 的等待树（waiter tree）；相同优先级时FIFO 顺序选择。对于某RT 互斥体，优先级最高的等待者会被排入属主自己的优先级等待者树中。该树同样按优先级顺序排队。每当优先级最高的等待者任务发生变化（例如因超时或收到信号）时，属主任务的优先级会被重新调整。优先级的入队操作由 "pi_waiters" 处理

RT 互斥体对无竞争（uncontended）互斥体的加/ 解锁等快速路径（fastpath）操作进行了优化，以降低内部锁开销。该优化的快速路径操作需cmpxchg 指令的支持。[RT 互斥体内部使用自旋锁。]

RT 互斥体的状态由 rt_mutex 结构体中owner 字段跟踪

->owner 保存指向 owner task_struct 指针。其0 位用于记录“存在等待者（waiters）”的状态：

============ ======= ================================================
owner         bit0    说明
============ ======= ================================================
NULL          0       锁空闲（可进行快速获取）
NULL          1       锁空闲但存在等待者，最高优先级等待者即将获取锁 [^1^]_
taskpointer   0       锁被持有（可进行快速释放）
taskpointer   1       锁被持有且存在等待[^2^]_
============ ======= ================================================

只有owner 字段的第 0 位为 0 时，才能基于原子比较交换（compare exchange）进行快速的获取与释放

在持->wait_lock 的情况下，为防止快速路径的 cmpxchg 获取该锁，需要在 owner NULL 的短时间内设置第 0 位以表明“正在查看该锁”，因此这是一个过渡状态

当存在等待者时，会在获取锁的慢速路径（slow path）中发生。为防止 cmpxchg 在属主释放锁时成功，需要在“正在查看该锁”时设置该位

顺便一提，“Pending Owner（待定属主）”在技术上仍然成立，只是不再这样称呼。待定属主出现在最高优先级等待者被唤醒去获取锁、而锁仍由当前属主持有时
