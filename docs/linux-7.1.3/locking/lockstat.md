## 锁统计（Lock Statistics）

## 是什么

顾名思义，它提供关于锁的统计信息。

## 为什么

因为诸如锁竞争（lock contention）之类的问题会严重影响性能。

## 怎么做

Lockdep 已经在锁函数中放置了钩子，并将锁实例映射到锁类。我们在此基础上构建（参见 Documentation/locking/lockdep-design.rst）。下图展示了锁函数与各种
```

        __acquire
            |
           lock _____
            |        \
            |    __contended
            |         |
            |       <wait>
            | _______/
            |/
            |
       __acquired
            |
            .
          <hold>
            .
            |
       __release
            |
         unlock

  lock, unlock	- 常规的锁函数
  __*		- 钩子
  <> 		- 状态

```
借助这些钩子，我们提供以下统计信息：

 con-bounces
 - 涉及跨 CPU（x-cpu）数据的锁竞争次数
 contentions
 - 必须等待的锁获取次数
 wait time
     min
 - 我们曾等待一把锁的最短（非 0）时间
     max
 - 我们曾等待一把锁的最长时间
     total
 - 我们花在等待这把锁上的总时间
     avg
 - 花在等待这把锁上的平均时间
 acq-bounces
 - 涉及跨 CPU（x-cpu）数据的锁获取次数
 acquisitions
 - 我们获取该锁的次数
 hold time
     min
 - 我们曾持有该锁的最短（非 0）时间
     max
 - 我们曾持有该锁的最长时间
     total
 - 该锁被持有的总时间
     avg
 - 该锁被持有的平均时间

这些数字按每个锁类、每个读/写状态（适用时）收集。

它还按每个类跟踪 4 个竞争点（contention point）。竞争点是一个在锁获取时不得不等待的调用点。

### 配置

锁统计通过 CONFIG_LOCK_STAT 启用。

### 用法

```

	# echo 1 >/proc/sys/kernel/lock_stat

```
```

	# echo 0 >/proc/sys/kernel/lock_stat
```
