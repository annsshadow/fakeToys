## MSM 抢占（Preemption）

抢占允许 Adreno GPU 在工作被推送到更高优先级的 ring 时切换到该 ring，从而降低
高优先级提交（submission）的延迟。

启用抢占时会初始化 4 个 ring，对应于不同的优先级级别。拥有多个 ring 纯粹是软件
概念，因为 GPU 只有用于跟踪一个图形 ring 的寄存器。内核可以通过请求抢占来切换
当前正在被处理的 ring。当满足某些取决于优先级级别的条件时，GPU 会将其当前状态
保存到一系列缓冲区中，然后从内核指定的一组类似缓冲区中恢复状态。随后它恢复执行
并触发一个 IRQ，以让内核知道上下文切换已经完成。

内核可以利用此机制在 ring 之间切换。每当发生一次提交时，内核会找到优先级最高的、
非空的 ring，如果该 ring 不是当前正在执行的那个，就抢占过去。每当一次提交完成时
也会这样做，以确保当高优先级 ring 完成后，执行会在低优先级 ring 上恢复。

### 抢占级别

抢占只能发生在某些边界处。可以通过更改抢占级别来配置具体的条件，这允许在延迟
（即内核请求抢占到 SQE 开始保存状态之间所经过的时间）与开销（需要保存的状态量）
之间进行权衡。

GPU 提供 3 个级别：

Level 0
  抢占只发生在提交（submission）级别。这需要的保存状态量最少，因为用户空间提交的
  IB 的执行永远不会被打断，但与完全不启用任何形式的抢占相比，它带来的好处非常有限。

Level 1
  抢占发生在 bin 级别（如果使用 GMEM 渲染时），或 draw 级别（在 sysmem 渲染的情况
  下）。

Level 2
  抢占发生在 draw 级别。

Level 1 是 msm 驱动使用的模式。

此外，GPU 允许指定一个 `skip_save_restore` 选项。这会禁用除与 SQE 自身操作相关的
寄存器以外的所有寄存器的保存和恢复，从而降低开销。只有在配合 Level 1 抢占使用
GMEM 时才会跳过保存和恢复。启用此选项时，期望用户空间在每次发生抢占时设置未被
保留的状态，这是通过指定 preamble（前导）和 postamble（后导）来完成的。它们是在
抢占前后执行的 IB。

### 抢占缓冲区

需要一系列缓冲区来存储 ring 在未被执行的空闲期间的状态。有不同的抢占记录（record）
类型，其中大多数每个 ring 需要一个缓冲区。这是因为在同一个 ring 上提交之间永远不会
发生抢占，当 ring 处于活动状态时，它们总是顺序运行。这意味着每个 ring 实际上只有
一个上下文处于活动状态。

SMMU_INFO
  该缓冲区包含当前 SMMU 配置的信息，例如 ttbr0 寄存器。SQE 固件实际上无法保存此
  记录。因此，必须在触发抢占之前，由 CP 手动将 SMMU 信息保存到缓冲区，并用该缓冲区
  中的信息更新 SMMU 记录。

NON_SECURE
  这是主要的抢占记录，大部分状态保存在这里。它对内核基本是不透明的，除了前几个字
  必须由内核初始化。

SECURE
  保存与 GPU 安全（secure）模式相关的状态。

NON_PRIV
  此记录的预期用途未知。SQE 固件实际上会忽略它，因此 msm 也不处理它。

COUNTER
  此记录用于保存和恢复性能计数器。

处理这些缓冲区的权限对安全性至关重要。除 NON_PRIV 以外的所有记录都必须对用户空间
不可访问，因此它们必须使用 MSM_BO_MAP_PRIV 标志映射到内核地址空间。例如，使
NON_SECURE 记录对用户空间可访问，将允许任何进程操纵已保存 ring 的 RPTR，从而可以
跳过 ring 中某些数据包的执行，并以更高的权限执行用户命令。
