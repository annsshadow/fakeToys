## 指南


本文档描述了适用于 nova-core 与 nova-drm 的总体项目指南。

## 语言


Nova 项目使用 Rust 编程语言。在此背景下，[Rust for Linux 项目](../../rust/general-information) 中
记录的所有规则均适用。此外，以下规则适用。

- 除非技术上确有必要（例如 uAPI），所有驱动代码均用 Rust 编写。

- 除非技术上必要，必须避免使用 unsafe Rust 代码。在技术上必要的情况下，unsafe 代码应隔离在
  一个单独的组件中，为其他驱动代码提供安全的 API 使用。

### 风格


[Rust for Linux 项目](../../rust/coding-guidelines) 中记录的所有规则均适用。

关于提交检查清单，还请参见 `Rust for Linux 提交检查清单补充 <https://rust-for-linux.com/contributing#submit-checklist-addendum>`_。

## 文档


适当的文档可用性在项目的可扩展性、对新贡献者的可及性以及总体可维护性方面至关重要，尤其是
对于像 Nova 这样面向复杂硬件运行的驱动而言。

因此，项目非常鼓励添加任何形式的文档。

除此之外，还有一些最低要求。

- 每个非私有结构体至少需要一段简要的文档注释，解释该结构体的语义含义，以及潜在的加锁与
  生命周期要求。也鼓励对非平凡的非私有结构体采用同样的最低文档要求。

- uAPI 必须用 kernel-doc 注释完整记录；此外，必须解释其语义行为，包括潜在的特殊或边界情况。

- 连接第一级驱动（nova-core）与第二级驱动的 API 必须完整记录。这包括文档注释、潜在的加锁与
  生命周期要求，以及适用的示例代码。

- 缩写一经引入必须解释；术语必须唯一定义。

- 寄存器地址、布局、移位值和掩码必须正确定义；除非显而易见，否则必须记录其语义含义。这仅在
  作者能够获得相应信息时适用。
