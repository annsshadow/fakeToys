## 长时间运行的工作负载与计算


长时间运行的工作负载（计算）是指无法在 10 秒内完成的工作负载。（这个时间是让用户
在伸手去按电源按钮之前愿意等待的时间）。这意味着需要采用其它技术来管理那些无法
使用围栏（fence）的工作负载。

某些硬件可能会调度计算任务，并且无法抢占它们，或无法将其内存换出。或者它们只是
希望自己的工作负载根本不被抢占或换出。

这意味着它与 driver-api/dma-buf.rst 中所描述的内容不同。

与正常的计算任务一样，可能完全不使用 dma-fence。在这种情况下，甚至无法用于强制
抢占。驱动被迫在解绑（unbind）时立即从该长计算任务的地址空间中取消映射一个 BO
（buffer object），甚至不等待工作负载完成。在没有硬件支持来恢复的情况下，这实际
上会终止该工作负载。

由于这是不希望发生的，因此需要有缓解措施来防止工作负载被终止。有几种可能的方法，
各有其优点与缺点。

你可能会尝试的第一种方法是固定（pin）计算所使用的所有缓冲区。这保证了任务会不
间断地运行，但也允许一种非常有效的拒绝服务攻击：尽可能多地固定内存，独占所有 GPU
内存，以及可能的一大块 CPU 内存。

第二种单独来看效果稍好的方法，是在创建新任务（任何类型）时添加一个不逐出
（evict）的选项。如果所有用户空间都选择加入这个标志，它将防止合作的用户空间为了
启动新任务而被迫终止更旧的计算任务。

如果任务抢占与可恢复缺页（recoverable pagefault）都不可用，那么这些是唯一可能的
方法。因此即使如此，你也希望有一种单独的方式来控制资源。内核做这件事的标准方式是
cgroups。

这创造了第三种选项，使用 cgroups 来防止逐出。GPU 与驱动分配的 CPU 内存都将被计入
正确的 cgroup，并且逐出将变为 cgroup 感知的。这允许将 GPU 划分为 cgroups，从而让
任务彼此相邻运行而互不干扰。

cgroup 的接口将类似于当前的 CPU 内存接口，在语义上类似 min/low/high/max（如果逐出
可以做到 cgroup 感知的话）。

应该注意的是，每个内存区域（例如 tile 内存）都应有自己的记账。

key 设为驱动设置的 regionid，例如 "tile0"。对于 $card 的值，我们使用 drmGetUnique()。
