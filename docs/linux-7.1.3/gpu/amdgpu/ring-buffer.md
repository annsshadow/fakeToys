##  环形缓冲区（Ring Buffer

为了处理用户空间与内核空间之间的通信，AMD GPU 使用环形缓冲区设计来为各个引擎（GFX、Compute、SDMA、UVD、VCE、VCN、VPE 等）
提供指令。请参见下图，它说明了这种通信是如何工作的
amdgpu 中的环形缓冲区以生产消费者模型工作，其中用户空间充当生产者，不断用待执行GPU 命令填充环形缓冲区与此同时，GPU 从环中取出信息，解析它，并将特定的指令集分配给不同的 amdgpu 模块
从图中可以看出，环有一个读指针（rptr），它表示引擎当前正在从环中读取数据包的位置；还有一个写指针（wptr），
它表示软件已向环中添加了多少个数据包。当 rptr wptr 相等时，环处于空闲状态。当软件向环中添加数据包时，
它会更新 wptr，这会导致引擎开始获取并处理数据包。随着引擎处理数据包，rptr 得到更新，直rptr 追上 wptr
并再次相等
通常，驱动中的环形缓冲区大小有限（搜`amdgpu_ring_init()` 的出现位置）。环形缓冲区较小的原因之一CP（Command Processor，命令处理器）能够跟随插入环中的地址；图中通过引用 IB（Indirect Buffer，间接缓冲区对此进行了说明。IB 使用户空间有可能在内存中拥有一块区域，CP 可以读取该区域并用额外的指令喂给硬件
GFX11 之前的所ASIC 都使用所谓的内核队列（kernel queue），这意味着环分配在内核空间，并且有一些限制，
例如无法被调度器直接抢占<amdgpu-mes>。GFX11 及更新的版本支持内核队列，但也提供了一种名为用户队（user queuesamdgpu-userq> 的新机制，其中队列被移到用户空间，并可以通过调度器映射和取消映射。实际上两种队列都将来自不同作业的用户空间生成的 GPU 命令插入到所请求的组件环中
