
## Display Core Next（DCN，显示核心下一代）


为了让读者具AMD Display Core Next（DCN）如何工作的基本知识，我们需要从
硬件流水线的概述开始。在下方你可以看到一张提DCN 概述的图，请记住这是一通用示意图，我们在每ASIC 上都有变体

基于这张图，我们可以逐个经过每个模块并简要描述它们：

- **Display Controller Hub（DCHUB，显示控制器枢纽*：这是可扩展数据端口（SDP  DCN 之间的网关。该组件具有多种特性，例如内存仲裁、旋转和光标操作
- **Display Pipe and Plane（DPP，显示管道与平面*：该模块提供预混合的像素
  处理，例如色彩空间转换、像素数据线性化、色调映射和色域映射
- **Multiple Pipe/Plane Combined（MPC，多管道/平面合并*：该组件使用全局  逐像素的 alpha 来执行多个平面的混合
- **Output Pixel Processing（OPP，输出像素处理）**：处理并格式化像素，以便
  发送给显示器
- **Output Pipe Timing Combiner（OPTC，输出管道时序合并器*：它生成时间输出
  以合并流或划分能力。CRC 值在此模块中生成
- **Display Output（DIO，显示输出）**：将输出编码到连接到我们 GPU 的显示器
- **Display Writeback（DWB，显示写回）**：它提供将显示管道的输出作为视频  写回内存的能力
- **Multi-Media HUB（MMHUBBUB，多媒体枢纽*：用DMCUB DWB 的内存控制器
  接口（注DWB 尚未连接）
- **DCN Management Unit（DMU，DCN 管理单元*：它提供带有访问控制的寄存器，并
  将控制器中断SOC 主机中断单元。该模块包含显示微控制器单元 B 版（DMCUB），
  它通过固件处理
- **DCN Clock Generator Block（DCCG，DCN 时钟生成模块*：它为所有显示控制器
  时钟域提供时钟和复位
- **Azalia（AZ*：音频引擎
上面的图DCN 的架构泛化，这意味着每个 ASIC 都在此基础模型周围有变体。注显示流水线通过 DCHUB 连接到可扩展数据端口（SDP）；你可以把 SDP 看作我们的数fabric 中向显示管道提供数据的元素
要始终将 DCN 架构视为某种可以多种方式配置和重新配置的灵活东西；换句话说，每个
模块可以根据用户空间的需求进行设置或忽略。例如，如果我们想以启用 DSC 来驱一8k@60Hz，我们的 DCN 可能需4 DPP 2 OPP。为每种特定场景驱动最配置DC 的责任。将所有这些组件编排在一起需要一个复杂的通信接口，这通过连接
每个模块的边在图中被高亮显示；从图中看，这些模块之间的每个连接表示：

1. 像素数据接口（红色）：表示像素数据流2. 全局同步信号（绿色）：它是一组由 VStartup、VUpdate VReady 组成的同步信号；
3. 配置接口：负责配置模块；
4. 旁路信号（Sideband signals）：所有不属于前述类别的其他信号
这些信号至关重要，并DCN 中扮演重要角色。尽管如此，全局同步值得在下一节中进行
更详细的说明
所有这些组件都由一个名dc_state 的数据结构表示。从 DCHUB MPC，我们有一称为 dc_plane 的表示；MPC OPTC，我们有 dc_stream；而输出（DIO）由 dc_link
处理。请记住，HUBP 使用从内存读取的特定格式来访问一surface，而我们的 dc_plane
应努力将平面中的所有像素转换为可以通过 dc_stream dc_link 发送给显示器的东西
### Front End and Back End（前端与后端

显示流水线可以拆分为两个通常被称**Front End（FE，前端）** **Back End
（BE，后端）** 的组件，其中 FE 由以下部分组成：

- DCHUB（主要指的是一个名HUBP 的子组件- DPP
- MPC

另一方面，BE 由以下部分组成：

- OPP
- OPTC
- DIO（DP/HDMI 流编码器与链路编码器
OPP OPTC FE BE 之间的两个连接模块。顺便一提，这是链路编码器到 PHY 一对一映射，但我们可以DCN 配置为选择哪个链路编码器连接到哪个 PHY。FE 的主职责是改变、混合和合成像素数据，BE 的工作是将一个通用的像素流组帧为特定显示器像素流
### Data Flow（数据流

最初，数据通过数据 fabric（DF）以原生像素格式VRAM 传入。这种数据格式一直保持到
DCHUB 中的 HUBP，HUBP 在那里解包不同的像素格式，并通过 4 个通道 个用alpha +
3 个用于颜色）以统一流的形式输出DPP
然后，DPP 中的 Converter and Cursor（CNVC，转换器与光标）将规范化数据表示，并将其
转换DCN 特定的浮点格式（即不同于 IEEE 浮点格式）。在此过程中，CNVC 还应用一degmma 函数，将数据从非线性空间转换为线性空间，以简化随后的浮点计算。数据将DPP
OPP 一直保持这种浮点格式
OPP 开始，由于色彩转换和混合已经完成（即可以丢alpha），并且最终的接收端不需浮点所提供的精度和动态范围（即所有显示器都是整数深度格式），位深缩减/抖动（dithering将会启动。在 OPP 中，我们还会应用一regamma 函数，把之前移除gamma 重新引入最终，我们DIO 以整数格式输出数据
### AMD Hardware Pipeline（AMD 硬件流水线）


在讨Linux 上的图形时，**pipeline（流水线* 这个术语有时会被赋予多种含义而过载，
因此定义我们所说的 **pipeline** 很重要。在 DCN 驱动程序中，我们使用 **hardware
pipeline（硬件流水线* **pipeline** 或简**pipe** 作为抽象，来表示为了实现
某种特定配置而实例化的一DCN 模块。DC 核心DCN 模块视为独立的资源，这意味着我们
可以通过获取所有独立硬件模块的资源来组成一个流水线。实际上，我们不能将一个管道中任意模块连接到另一个管道中的模块；它们是线性路由的，除DSC 可以按需任意分配。我有这个流水线概念是为了尝试优化带宽利用

### Global Sync（全局同步

许多 DCN 寄存器是双缓冲的，最重要的是 surface 地址。这允许我们针对页面翻转（page
flip），以及大多数其他不需要启用或禁用新管道的更新，以原子方式更新 DCN 硬件
（注意：在许多情况下，DC 会决定预留额外的管道，以支持需要非常高像素时钟的输出，
或出于省电目的。）

这些原子寄存器更新由 DCN 中的全局同步信号驱动。为了理解原子更新如何与 DCN 硬件交互以及 DCN 如何发出页面翻转vblank 事件，有助于理解全局同步是如何编程的
全局同步由三个信号组成：VSTARTUP、VUPDATE VREADY。它们由显示模式DML
（drivers/gpu/drm/amd/display/dc/dml）基于大量参数计算，并确保我们的硬件能够在任给定系统配置下为 DCN 流水线提供数据而不会发生欠流（underflow）或挂起。全局同步信号
总是发生VBlank 期间，独立于 VSync 信号，并且彼此不重叠
VUPDATE 是唯一让其余驱动程序栈或用户空间客户端感兴趣的信号，因为它标志着硬件锁存
到以原子方式编程（即双缓冲）的寄存器的时间点。尽管它独立VSync 信号，我们仍使用
VUPDATE 来发VSync 事件，因为它最好地指示了原子提交与硬件如何交互
由于 DCN 硬件是双缓冲的，DC 驱动程序可以在帧期间的任何时刻对硬件进行编程
