## Linux I2C 涓?DMA


鉴于 I2C 是一条低速总线，其上传输的绝大多数消息都很小，它并不被视为 DMA 访问的主要用户在撰写本文时，只10% I2C 总线主控制器驱动实现DMA 支持。而且绝大多数事务都很小，
为其设置 DMA 可能比一次普通的 PIO 传输增加更多开销
因此，I2C 消息的缓冲区**并不**强制要求DMA 安全的。在这个特性如此罕见使用的情况下，施加
额外的负担似乎并不合理。但是，如果你的消息大小可能适用DMA，则建议使用 DMA 安全的缓冲区大多数驱动的这个阈值大约在 8 字节（截至目前，mostly 是一个有根据的猜测）。对于任16
字节或更大的消息，采DMA 安全缓冲区很可能是个非常好的主意。请注意，你使用的其他子系统可能
会增加要求。例如，如果你的 I2C 总线主控制器驱动使用 USB 作为桥接，那么你必须始终使用 DMA 安全
缓冲区，因为 USB 要求如此
### 瀹㈡埛绔。

对于客户端，如果你在 i2c_msg 中使DMA 安全缓冲区，请同时设I2C_M_DMA_SAFE 标志。这样，
I2C 核心与驱动就知道可以对它安全地执DMA。注意使用此标志是可选的。未更新以使用此标志I2C
主机驱动会像以前一样工作。并且像以前一样，它们有使用不安全 DMA 缓冲区的风险。为了改善这一状况计划在越来越多的客户端与主机驱动中使I2C_M_DMA_SAFE。另请注意，设置此标志只在内核空间有意义用户空间数据无论如何都会被复制到内核空间。I2C 核心会确保内核空间中的目标缓冲区始终DMA 可用的此外，当核心通过 I2C 模拟 SMBus 事务时，块传输的缓冲区是 DMA 安全的。一旦知道自己的缓冲区是
DMA 安全的，i2c_master_send() i2c_master_recv() 函数的使用者现在可以使用其 DMA 安全变体
（i2c_master_send_dmasafe() i2c_master_recv_dmasafe()）。i2c_transfer() 的使用者必须手设置 I2C_M_DMA_SAFE 标志
### 主机控制

希望实现安全 DMA 的总线主控制器驱动可以使用来自 I2C 核心的辅助函数。其中一个会为给定的 i2c_msg
返回 DMA 安全缓冲区，前提```

	dma_buf = i2c_get_dma_safe_msg_buf(msg, threshold_in_byte);

```
如果返回了缓冲区，它要么I2C_M_DMA_SAFE 情况下的 msg->buf，要么是一个反弹缓冲区。但你无需
关心这个细节，直接使用返回的缓冲区即可。如果返NULL，则说明未达到阈值，或无法分配反弹缓冲区在这种情况下请回退PIO
无论如何，从上述获得的缓冲区都需要被释放。另一个辅助函```

	i2c_put_dma_safe_msg_buf(dma_buf, msg, xferred);

```
最后一个参'xferred' 控制缓冲区是否被同步回消息。在设置 DMA 出错且没有数据传输的情况下，无需同步
核心的反弹缓冲区处理是通用且简单的。它总是分配一个新的反弹缓冲区。如果你想要更复杂的处理（例复用预分配的缓冲区），可以自行实现
有关细节，也请查看内核内文档。i2c-sh_mobile 驱动可作为如何使用上述辅助函数的参考示例
最后说明：如果你计划将 DMA 用于 I2C（或者实际上用于任何其他事物），请确保在开发期间启用了
CONFIG_DMA_API_DEBUG。它可以帮助你发现各种问题，否则这些问题可能很难调试
