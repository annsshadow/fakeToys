## I2C 多路复用器与复杂拓扑


有若干原因需要构建比“单个适配器加一个或多个设备”的直连 I2C 总线更复杂的 I2C 拓扑。

一些示例用例：

1. 总线上可能需要一个多路复用器（mux）来防止地址冲突。

2. 总线可能可被某个外部总线主设备（bus master）访问，此时可能需要仲裁（arbitration）
   来决定是否可以访问该总线。

3. 某个设备（尤其是 RF 调谐器）可能希望避开来自 I2C 总线的数字噪声（至少在大多数时间），
   它位于一个门控（gate）之后，在访问该设备之前必须先操作这个门控。

若干类型的硬件组件，例如 I2C 多路复用器、I2C 门控和 I2C 仲裁器，可用于满足此类需求。

在 Linux 中，这些组件被表示为 I2C 适配器树，其中每个适配器都有一个父适配器（根适配器除外）
以及零个或多个子适配器。根适配器是实际发出 I2C 传输的适配器，所有带有父适配器的适配器都是
某个 “i2c-mux” 对象的一部分（加引号是因为它也可能是一个仲裁器或门控）。

依据具体多路复用器驱动的不同，当某个子适配器上发生 I2C 传输时，会发生某些动作。多路复用器
驱动显然可以操作一个多路复用器，但它也可以与外部总线主设备进行仲裁，或者打开一个门控。
多路复用器驱动为此有两个操作：select（选择）和 deselect（取消选择）。select 在传输之前被
调用，（可选的）deselect 在传输之后被调用。


## 锁


I2C 多路复用器有两种可用的锁变体：可以是 mux-locked（多路复用器锁定）或 parent-locked
（父适配器锁定）的多路复用器。


### 多路复用器锁定的多路复用器


多路复用器锁定的多路复用器在完整的 select-传输-deselect 事务期间不会锁定整个父适配器，只
会锁定父适配器上的多路复用器。多路复用器锁定的多路复用器主要在 select 和/或 deselect 操作
必须使用 I2C 传输来完成其任务时才有意义。由于在完整事务期间父适配器并未被完全锁定，不相关的
I2C 传输可能会交错出现在事务的不同阶段之间。这样做的好处是多路复用器驱动可能更容易、更清晰地
实现，但也存在一些注意事项。

#### 多路复用器锁定示例


```

                   .----------.     .--------.
    .--------.     |   mux-   |-----| dev D1 |
    |  root  |--+--|  locked  |     '--------'
    '--------'  |  |  mux M1  |--.  .--------.
                |  '----------'  '--| dev D2 |
                |  .--------.       '--------'
                '--| dev D3 |
                   '--------'

```
当访问 D1 时，发生的事情如下：

 1. 某方向 D1 发起一次 I2C 传输。
 2. M1 锁定其父适配器上的多路复用器（本例中为根适配器）。
 3. M1 调用 ->select 以使多路复用器就绪。
 4. M1（大概）作为其 select 的一部分执行一些 I2C 传输。这些传输是锁定父适配器的普通 I2C 传输。
 5. M1 将第 1 步的 I2C 传输作为锁定父适配器的普通 I2C 传输送给其父适配器。
 6. M1 若有 deselect，则调用 ->deselect。
 7. 与第 4 步相同的规则，但针对 ->deselect。
 8. M1 解锁其父适配器上的多路复用器。

这意味着在整个操作的整个持续期间，对 D2 的访问被锁定排除在外。但对 D3 的访问可能在任意时刻
被交错插入。

#### 多路复用器锁定的注意事项


使用多路复用器锁定的多路复用器时，请注意以下限制：

[ML1]
  如果你构建的拓扑中，一个多路复用器锁定的多路复用器作为父级、其下又是一个父适配器锁定的
  多路复用器，则可能会破坏父适配器锁定的多路复用器关于“事务期间根适配器被锁定”的预期。

[ML2]
  当存在地址冲突的两个（或更多）多路复用器锁定的多路复用器不是兄弟关系时，构建任意拓扑并
  不安全。这里指的是这些非兄弟多路复用器的子适配器上的设备之间存在地址冲突。

  也就是说，针对例如 mux-one 之后地址为 0x42 的设备的 select-传输-deselect 事务，可能会与
  针对 mux-two 之后地址为 0x42 的设备的类似操作交错进行。在这种假设示例中，此类拓扑的意图
  是 mux-one 和 mux-two 不应被同时选中，但多路复用器锁定的多路复用器并不能在所有拓扑下保证
  这一点。

[ML3]
  一个多路复用器锁定的多路复用器不能被驱动用于自动关闭的门控/多路复用器，即在某些数量（多数
  情况下为一个）的 I2C 传输之后自动关闭的东西。不相关的 I2C 传输可能会悄悄插入并使其提前关闭。

[ML4]
  如果多路复用器驱动中的任何非 I2C 操作改变了 I2C 多路复用器的状态，该驱动必须在该操作期间
  锁定根适配器。否则，当某个非 I2C 的改变多路复用器的操作正在进行时，若有不相关的 I2C 传输
  正在运行，从多路复用器后面的设备看来，总线上可能会出现垃圾数据。


### 父适配器锁定的多路复用器


父适配器锁定的多路复用器在完整的 select-传输-deselect 事务期间锁定父适配器。其含义是，多路
复用器驱动必须确保事务期间通过该父适配器的任何及所有 I2C 传输都是已解锁的 I2C 传输（例如使用
`__i2c_transfer`），否则将导致死锁。

#### 父适配器锁定示例


```

                   .----------.     .--------.
    .--------.     |  parent- |-----| dev D1 |
    |  root  |--+--|  locked  |     '--------'
    '--------'  |  |  mux M1  |--.  .--------.
                |  '----------'  '--| dev D2 |
                |  .--------.       '--------'
                '--| dev D3 |
                   '--------'

```
当访问 D1 时，发生的事情如下：

 1. 某方向 D1 发起一次 I2C 传输。
 2. M1 锁定其父适配器上的多路复用器（本例中为根适配器）。
 3. M1 锁定其父适配器。
 4. M1 调用 ->select 以使多路复用器就绪。
 5. 如果 M1 作为其 select 的一部分执行任何 I2C 传输（在这个根适配器上），那些传输必须是已解锁
     的 I2C 传输，以免它们使根适配器死锁。
 6. M1 将第 1 步的 I2C 传输作为已解锁的 I2C 传输送给根适配器，以免使父适配器死锁。
 7. M1 若有 deselect，则调用 ->deselect。
 8. 与第 5 步相同的规则，但针对 ->deselect。
 9. M1 解锁其父适配器。
 10. M1 解锁其父适配器上的多路复用器。

这意味着对 D2 和 D3 的访问在整个操作的整个持续期间都被锁定排除在外。

#### 父适配器锁定的注意事项


使用父适配器锁定的多路复用器时，请注意以下限制：

[PL1]
  如果你构建的拓扑中，一个父适配器锁定的多路复用器是另一个多路复用器的子级，则可能会破坏子
  多路复用器关于“在 select 操作和实际传输之间根适配器未被使用”的可能假设（例如，若子多路
  复用器是自动关闭的，而父多路复用器在其 select 过程中发出了 I2C 传输）。这在父多路复用器是
  多路复用器锁定的情况下尤为突出，但即便父多路复用器是父适配器锁定的，也可能发生。

[PL2]
  如果 select/deselect 调用到 gpio、pinctrl、regmap 或 iio 等其他子系统，那么这些子系统引起的
  任何 I2C 传输都必须是已解锁的，这一点至关重要。要做到这一点可能很绕，如果追求一个可接受的
  干净方案，甚至可能是不可能的。


## 复杂示例


### 父适配器锁定的多路复用器作为父适配器锁定的多路复用器的父级


```

                   .----------.     .----------.     .--------.
    .--------.     |  parent- |-----|  parent- |-----| dev D1 |
    |  root  |--+--|  locked  |     |  locked  |     '--------'
    '--------'  |  |  mux M1  |--.  |  mux M2  |--.  .--------.
                |  '----------'  |  '----------'  '--| dev D2 |
                |  .--------.    |  .--------.       '--------'
                '--| dev D4 |    '--| dev D3 |
                   '--------'       '--------'

```
当访问任意设备时，所有其他设备在整个操作期间都被锁定排除在外（两个多路复用器都锁定它们的父级，
特别是当 M2 请求其父级锁定时，M1 把责任传递给根适配器）。

如果 M2 是自动关闭的多路复用器，而 M1->select 在根适配器上发出了可能泄漏过去并被 M2 适配器
看到、从而提前关闭 M2 的已解锁 I2C 传输，那么这种拓扑是不好的。


### 多路复用器锁定的多路复用器作为多路复用器锁定的多路复用器的父级


```

                   .----------.     .----------.     .--------.
    .--------.     |   mux-   |-----|   mux-   |-----| dev D1 |
    |  root  |--+--|  locked  |     |  locked  |     '--------'
    '--------'  |  |  mux M1  |--.  |  mux M2  |--.  .--------.
                |  '----------'  |  '----------'  '--| dev D2 |
                |  .--------.    |  .--------.       '--------'
                '--| dev D4 |    '--| dev D3 |
                   '--------'       '--------'

```
当访问设备 D1 时，对 D2 的访问在整个操作期间被锁定排除在外（M1 顶层子适配器上的多路复用器被
锁定）。但对 D3 和 D4 的访问可能在任意时刻被交错插入。

对 D3 的访问会锁定排除 D1 和 D2，但对 D4 的访问仍可能被交错插入。


### 多路复用器锁定的多路复用器作为父适配器锁定的多路复用器的父级


```

                   .----------.     .----------.     .--------.
    .--------.     |   mux-   |-----|  parent- |-----| dev D1 |
    |  root  |--+--|  locked  |     |  locked  |     '--------'
    '--------'  |  |  mux M1  |--.  |  mux M2  |--.  .--------.
                |  '----------'  |  '----------'  '--| dev D2 |
                |  .--------.    |  .--------.       '--------'
                '--| dev D4 |    '--| dev D3 |
                   '--------'       '--------'

```
当访问设备 D1 时，对 D2 和 D3 的访问在整个操作期间被锁定排除在外（M1 锁定根适配器上的子多路
复用器）。但对 D4 的访问可能在任意时刻被交错插入。

这种拓扑通常不合适，大概应该避免。原因是 M2 大概假设在其对 ->select 和 ->deselect 的调用期间
不会有 I2C 传输发生，而如果发生了，任何此类传输都可能作为不完整的 I2C 传输出现在 M2 的从设备
一侧，即产生垃圾数据甚至更糟。这可能导致设备挂起和/或其他问题。

如果 M2 是自动关闭的多路复用器，这种拓扑尤其麻烦。在那种情况下，任何对 D4 的交错访问都可能
提前关闭 M2，M1->select 的任何 I2C 传输也可能如此。

但如果 M2 并未做上述假设，且 M2 不是自动关闭的，那么这种拓扑是可以的。


### 父适配器锁定的多路复用器作为多路复用器锁定的多路复用器的父级


```

                   .----------.     .----------.     .--------.
    .--------.     |  parent- |-----|   mux-   |-----| dev D1 |
    |  root  |--+--|  locked  |     |  locked  |     '--------'
    '--------'  |  |  mux M1  |--.  |  mux M2  |--.  .--------.
                |  '----------'  |  '----------'  '--| dev D2 |
                |  .--------.    |  .--------.       '--------'
                '--| dev D4 |    '--| dev D3 |
                   '--------'       '--------'

```
当访问 D1 时，对 D2 的访问在整个操作期间被锁定排除在外（M1 顶层子适配器上的多路复用器被锁定）。
对 D3 和 D4 的访问可能在任意时刻被交错插入，正如对多路复用器锁定的多路复用器所预期的那样。

当访问 D3 或 D4 时，其他一切都被锁定排除。对 D3 的访问，M1 锁定根适配器。对 D4 的访问，根适配器
被直接锁定。


### 两个多路复用器锁定的兄弟多路复用器


```

                                    .--------.
                   .----------.  .--| dev D1 |
                   |   mux-   |--'  '--------'
                .--|  locked  |     .--------.
                |  |  mux M1  |-----| dev D2 |
                |  '----------'     '--------'
                |  .----------.     .--------.
    .--------.  |  |   mux-   |-----| dev D3 |
    |  root  |--+--|  locked  |     '--------'
    '--------'  |  |  mux M2  |--.  .--------.
                |  '----------'  '--| dev D4 |
                |  .--------.       '--------'
                '--| dev D5 |
                   '--------'

```
当访问 D1 时，对 D2、D3 和 D4 的访问被锁定排除。但对 D5 的访问可能在任意时刻被交错插入。


### 两个父适配器锁定的兄弟多路复用器


```

                                    .--------.
                   .----------.  .--| dev D1 |
                   |  parent- |--'  '--------'
                .--|  locked  |     .--------.
                |  |  mux M1  |-----| dev D2 |
                |  '----------'     '--------'
                |  .----------.     .--------.
    .--------.  |  |  parent- |-----| dev D3 |
    |  root  |--+--|  locked  |     '--------'
    '--------'  |  |  mux M2  |--.  .--------.
                |  '----------'  '--| dev D4 |
                |  .--------.       '--------'
                '--| dev D5 |
                   '--------'

```
当访问任意设备时，对所有其他设备的访问都被锁定排除。


### 多路复用器锁定与父适配器锁定的兄弟多路复用器


```

                                    .--------.
                   .----------.  .--| dev D1 |
                   |   mux-   |--'  '--------'
                .--|  locked  |     .--------.
                |  |  mux M1  |-----| dev D2 |
                |  '----------'     '--------'
                |  .----------.     .--------.
    .--------.  |  |  parent- |-----| dev D3 |
    |  root  |--+--|  locked  |     '--------'
    '--------'  |  |  mux M2  |--.  .--------.
                |  '----------'  '--| dev D4 |
                |  .--------.       '--------'
                '--| dev D5 |
                   '--------'

```
当访问 D1 或 D2 时，对 D3 和 D4 的访问被锁定排除，而对 D5 的访问可能被交错插入。当访问 D3 或 D4
时，对所有其他设备的访问都被锁定排除。
