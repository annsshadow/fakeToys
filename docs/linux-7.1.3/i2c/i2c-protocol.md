## I2C 协议


本文档概述了基本的 I2C 事务以及用于执行它们的内核 API。

## 符号说明


=============== =============================================================
S               起始条件（Start condition）
P               停止条件（Stop condition）
Rd/Wr (1 bit)   读/写位。Rd 为 1，Wr 为 0。
A, NA (1 bit)   应答（ACK）与非应答（NACK）位
Addr  (7 bits)  I2C 7 位地址。注意可以扩展为
                获得 10 位 I2C 地址。
Data  (8 bits)  一个普通的数据字节。

[..]            由 I2C 设备发送的数据，而非由主机适配器发送的数据。
=============== =============================================================


## 简单发送事务


```

  S Addr Wr [A] Data [A] Data [A] ... [A] Data [A] P


```

## 简单接收事务


```

  S Addr Rd [A] [Data] A [Data] A ... A [Data] NA P


```

## 组合事务


由 i2c_transfer() 实现。

它们与上面的事务类似，但发送的不是停止条件 P，而是发送一个起始条件 S 并继续该事务。
```

  S Addr Rd [A] [Data] NA S Addr Wr [A] Data [A] P


```

## 修改后的事务


通过对 I2C 消息设置这些标志，也可以生成对 I2C 协议的以下修改。除 I2C_M_NOSTART 外，它们通常只在绕过设备问题时才需要：

I2C_M_IGNORE_NAK:
    通常，如果客户端返回 [NA]，消息会立即被中断。设置此标志会将任何 [NA] 视为 [A]，从而整个
    消息都会被发送。
    这些消息仍可能因 SCL lo->hi 超时而失败。

I2C_M_NO_RD_ACK:
    在读消息中，跳过主机的 A/NA 位。

I2C_M_NOSTART:
    在组合事务中，在某个时刻不会生成 'S Addr Wr/Rd [A]'。例如，在第二条部分消息上设置 I2C_M_NOSTART
```

      S Addr Rd [A] [Data] NA Data [A] P

    如果你在第一条部分消息上设置 I2C_M_NOSTART 变量，
    我们不会生成 Addr，但会生成起始条件 S。
    这可能会把你总线上所有其他客户端搞混，所以不要尝试这样做。

    这通常用来将系统内存中多个数据缓冲区的发送聚集为对
    I2C 设备看似单次传输的内容，但某些罕见设备也可能在方向改变之间使用它。

```

I2C_M_REV_DIR_ADDR:
    这会切换 Rd/Wr 标志。也就是说，如果你想执行写操作，但需要发出
    Rd 而不是 Wr，反之亦然，你就设置此标志
```

      S Addr Rd [A] Data [A] Data [A] ... [A] Data [A] P

```

I2C_M_STOP:
    在消息之后强制产生停止条件（P）。某些与 I2C 相关的协议（如 SCCB）需要这样做。通常情况下，你确实不希望在
    一次传输的多个消息之间被中断。
