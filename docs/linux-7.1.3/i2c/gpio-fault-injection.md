## Linux I2C 故障注入


基于 GPIO I2C 总线主设备驱动可以配置为提供故障注入能力。它随后应连接到另一条由被测 I2C 总线主设备驱动驱动的 I2C 总线。GPIO 故障注入驱动可以在总线上制造特殊状态，被测I2C 总线主设备驱动应当能够优雅地处理这些状态
一旦启用了 Kconfig 选项 I2C_GPIO_FAULT_INJECTOR，在 Kernel debugfs 文件系统中（通常挂载/sys/kernel/debug）就会出现一'i2c-fault-injector' 子目录。每个由 GPIO 驱动I2C 总线都会有一个独立的子目录。每个子目录将包含用于触发故障注入的文件。下面连同它们的预期用例一并描述
## 绾跨姸鎬。

### "scl"


通过读取该文件，你可以获SCL 的当前状态。通过写入，你可以将其状态改为强制拉低或再次释放。因此，使用 "echo 0 > scl" 可以强制 SCL 拉低，从而无法进行任何通信，因为被测总线主设备将无法产生时钟。它应当检测到 SCL 无响应的状况，并向上层报告错误
### "sda"


通过读取该文件，你可以获SDA 的当前状态。通过写入，你可以将其状态改为强制拉低或再次释放。因此，使用 "echo 0 > sda" 可以强制 SDA 拉低，从而无法传输数据。被测总线主设备应当检测到该状况并触发总线恢复（参I2C 规范版本 4，第 3.1.16 节），使Linux I2C 核心的辅助函数（参见 'struct bus_recovery_info'）。然而，总线恢复不会成功，因SDA 仍被拉低，直到你"echo 1 > sda" 手动再次释放它。带有自动释放的测试可以使用 "incomplete transfers" 一类的故障注入器来完成
## 不完整的传输


以下故障注入器制造设备将 SDA 拉低的情况。总线恢复应当能够修复这些情况。但请注意：某些 I2C 客户端设备会检测到自身一SDA 被卡住，并在几毫秒后自行释放。此外，也可能存在对 I2C 总线进行去毛刺和监控的外部设备。它也可能检测到 SDA 被卡住并自行发起总线恢复。如果你要在总线主设备驱动中实现总线恢复，请务必事先检查你的硬件设置中是否存在此类设备。并且始终要用示波器或逻辑分析仪验证！

### "incomplete_address_phase"


该文件只写，你需要向它写入一个已存在I2C 客户端设备的地址。然后，将启动对该设备的一次读传输，但它会在客户端地址被发送后ACK 阶段停止。因为设备会对其存在进行 ACK，这会导SDA SCL 为高时被设备拉低。因此，与上面的 "sda" 文件类似，被测总线主设备应当检测到该状况并尝试总线恢复。不过这一次，它应当成功，设备应在 SCL 翻转后释SDA
### "incomplete_write_byte"


与上面类似，该文件只写，你需要向它写入一个已存在I2C 客户端设备的地址
注入器同样会停在一ACK 阶段，因此设备会因为确认数据而保SDA 为低。然而，'incomplete_address_phase' 相比有两个区别：

a) 发出的消息将是一条写消息
b) 在地址字节之后，将传输一0x00 字节。然后，ACK 处停止
这是一个非常微妙的状态，设备被设置为SCL 上发生进一步时钟脉冲时向寄存器 0x00（如果它有寄存器）写入任意数据。这就是为什么总线恢复（最9 个时钟脉冲）必须检SDA 或发送额外的 STOP 条件以确保总线已被释放。否则随机数据将被写入设备！

## 丢失仲裁


这里，我们要模拟被测主设备在多主设备设置中输给另一个主设备的仲裁的情况
### "lose_arbitration"


该文件只写，你需要写入仲裁干扰的持续时间（单µs，最大为 100ms）。然后调用进程将睡眠并等待下一个总线时钟。不过，该进程是可中断的
丢失仲裁是通过等待被测主设备将 SCL 拉低，然后将 SDA 拉低一段时间来实现的。因此，发出I2C 地址应当被破坏，并且应当被正确检测到。这意味着发出的地址应当包含大量 '1' 位以便能够检测到破坏。该地址处不需要有设备，因为丢失仲裁应当在此之前就被检测到。还要注意，SCL 拉低是通过中断监控的，因此中断延迟可能导致前几位未被破坏。在 otherwise 上使用此故障注入器的一个良好起点是
```

  # echo 200 > lose_arbitration &
  # i2cget -y <bus_to_test> 0x3f

```
## 传输期间Panic


该故障注入器会在被测主设备启动一次传输时制造一次内panic。这通常意味着总线主设备驱动的状态机将被不优雅地中断，总线可能最终处于异常状态。用它来检查你的关重启/启动代码能否处理这种情况
### "inject_panic"


该文件只写，你需要写入检测到传输开始与诱发内核 panic 之间的延迟（单位 µs，最大为 100ms）。然后调用进程将睡眠并等待下一个总线时钟。不过，该进程是可中断的
