
## I2C 地址转换器（I2C Address Translators）


Author: Luca Ceresoli <luca@lucaceresoli.net>
Author: Tomi Valkeinen <tomi.valkeinen@ideasonboard.com>

### 描述


I2C 地址转换器（ATR）是一种位于 I2C 从设备与 I2C 主设备之间、并在二者之间转换
从设备地址的设备。一个 ATR 拥有 N 个 I2C 子（"下游"）端口，以及一个 I2C 父
（"上游"）端口。它会将上游端口上的事务转发到相应的下游端口，并改写从设备地址。
地址改写由硬件完成，父总线上使用的地址称为"别名"（alias），可能与子总线上使用
的物理从设备地址不同。

ATR 看起来与 i2c-mux 类似，区别在于：
- 父总线与子总线上的地址不同；
- 通常无需选择子端口；父总线上使用的别名即隐含了对应的子端口。

ATR 功能可由集成了许多其他特性的芯片提供。内核中的 i2c-atr 提供了一个辅助设施，
用于实现 ATR 驱动。

ATR 会为每个子总线创建一个新的 I2C"子"适配器（adapter）。在子总线上添加设备时，
会触发驱动代码去选择一个可用的别名。维护一个合适的可用别名池，并为新设备挑选
一个别名，这由驱动实现者负责。ATR 维护一张当前已分配别名的表，并据此改写发往
子总线上设备的 I2C 事务。

典型示例如下。

```

                      Slave X @ 0x10
              .-----.   |
  .-----.     |     |---+---- B
  | CPU |--A--| ATR |
  `-----'     |     |---+---- C
              `-----'   |
                      Slave Y @ 0x10

```

别名表：

A、B、C 为三条电气上相互独立的物理 I2C 总线。ATR 接收在总线上发起的事务，并根据
事务中的设备地址（基于别名表）将其传播到总线 B 或总线 C。

别名表：


=============== =====
Client          Alias
=============== =====
X (bus B, 0x10) 0x20
Y (bus C, 0x10) 0x30
=============== =====

事务：

- Slave X 驱动请求在适配器 B 上发起一个事务，从设备地址为 0x10；
- ATR 驱动为总线 B 上的 Slave X 找到别名（0x20），将消息中的地址改写为 0x20，
  并在适配器上转发；
- 总线 A 上发生实际的物理 I2C 事务，从设备地址为 0x20；
- ATR 芯片检测到地址 0x20 上的事务，在表中找到该条目，将事务传播到总线 B，并把
  地址转回 0x10，同时在等待应答期间保持总线 A 上的时钟拉伸（clock stretching）；
- 总线 B 上的 Slave X 芯片检测到发往其自身物理地址 0x10 的事务，并正常应答；
- ATR 芯片停止时钟拉伸，并将应答转发回总线 A，同时把地址转回 0x20；
- ATR 驱动收到应答，将消息中的地址改写回最初请求的 0x10；
- Slave X 驱动取回 msgs[]，应答地址为 0x10。

用法：

1. 驱动（通常在 probe 函数中）通过调用 i2c_atr_new() 并传入 attach/detach 回调
   来添加 ATR；
2. attach 回调被调用以挑选一个合适的别名，并通过传入的 alias_id 参数配置芯片，
   使其返回所选的别名；
3. detach 回调被调用以解除该别名的配置，并将该别名放回池中供后续使用。
