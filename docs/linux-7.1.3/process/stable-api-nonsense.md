
## Linux 内核驱动接口


（你所有的问题都将得到解答，而且还有一些）

Greg Kroah-Hartman <greg@kroah.com>

本文旨在尝试解释为什Linux **没有二进制内核接口，也没有稳定的内核接口**

  请认识到，本文描述的*内核内部**的接口，而不是内核到用户空间的接口
  内核到用户空间的接口是应用程序使用的那个接口，即系统调用（syscall）接口。该接口
  随时*非常**稳定，并且不会破坏。我有一些在 0.9 之前某个版本内核上构建的老程序，
  在最新的 2.6 内核版本上仍然工作得很好。那个接口是用户和应用程序程序员可以指望  保持稳定的接口

### 结论摘要

你以为你想要一个稳定的内核接口，但其实你并不想要，而且你甚至不知道这一点。你想要
的是稳定的运行中的驱动，而只有当你的驱动位于主线内核树中时，你才能得到它。如果你驱动位于主线内核树中，你还会获得许多其他好处，这一切都使得 Linux 成为一个如此强大稳定和成熟的操作系统，而这也正是你首先使用它的原因
### 引言


只有那些想编写内核驱动、需要担心内核内部接口变化的人才需要关注这个问题。对于世界上
绝大多数人来说，他们既看不到这个接口，也根本不在乎它
首先，我不会讨论**任何**关于闭源、隐藏源码、二进制 blob、源码封装器，或任何其他描述
未在 GPL 下发布源代码的那些内核驱动的术语相关的法律问题。如果你有任何法律问题，咨询律师，我是一名程序员，因此我在这里只是描述技术问题（并非轻视法律问题，它们是
真实存在的，你始终需要意识到它们）
那么，这里有两个主要话题：二进制内核接口和稳定内核源码接口。它们相互依赖，但我们将
先讨论二进制的东西以便了结它
### 二进制内核接
假设我们为内核提供了一个稳定的内核源码接口，二进制接口自然也就随之而来了，对吧？错请考虑以下关于 Linux 内核的事实：

  - 取决于你使用C 编译器版本，不同的内核数据结构将包含不同的结构对齐方式，并且
    可能以不同的方式包含不同的函数（是否将函数内联）。单个函数的组织并不那么重要    但不同的数据结构填充（padding）却非常重要
  - 取决于你选择的内核构建选项，内核可以假定各种各样不同的事情
      - 不同的结构可以包含不同的字段
      - 某些函数可能根本没有被实现（例如，一些锁在非 SMP 构建中会被编译为空）
      - 内核中的内存可以以不同的方式对齐，取决于构建选项

  - Linux 运行在各种各样不同的处理器体系结构上。一个体系结构上的二进制驱动绝不可能
    在另一个体系结构上正确运行
现在，通过为确切特定的内核配置编译你的模块，并使用构建该内核时所用的完全相同C
编译器，其中一些问题可以得到解决。如果你想要为某个特Linux 发行版的特定发布版本
提供一个模块，这已经足够了。但是，将这个单一构建乘以不同 Linux 发行版的数量，再乘以
Linux 发行版所支持的不同发布版本的数量，你会迅速地面对一个由不同发布版本上不构建选项组成的噩梦。还要认识到，每Linux 发行版发布都包含许多不同的内核，都针不同的硬件类型（不同的处理器类型和不同的选项）进行了调优，因此即使是单个发布版本你也需要创建你的模块的多个版本
相信我，如果你试图支持这样的发布，随着时间的推移你会发疯的，我很久以前就吃过这个苦头…
### 稳定的内核源码接

如果你去和那些试图让一个不在主线内核树中的 Linux 内核驱动随时间保持最新的人交谈，
这是一波动大得多的主题
Linux 内核开发是持续且快速的，从未停下来放缓脚步。因此，内核开发者会在当前接口中发现
缺陷，或者想出更好的做事方式。如果他们这样做了，他们就会修复当前接口以更好地工作。当
他们这样做时，函数名可能会改变，结构可能会增大或缩小，函数参数可能会被重新设计。如发生这种情况，内核中所有使用该接口的地方都会同时被修正，确保一切继续正常工作
作为一个具体的例子，内核内部的 USB 接口在该子系统的生命周期中至少经历了三次不同重构。这些重构是为了解决许多不同的问题：

  - 从数据流同步模型到异步模型的改变。这降低了许多驱动的复杂性，并提高了所USB
    驱动的吞吐量，使得我们现在几乎能让所USB 设备以其最大可能速度运行  - USB 驱动USB 核心分配数据包的方式发生了变化，使得所有驱动现在需要向 USB 核心
    提供更多信息以修复一些已记录的死锁
这与一些闭源操作系统形成了鲜明对比——它们不得不长期维护其较旧的 USB 接口。这使得开发者有可能意外地使用旧接口并以不当的方式做事，导致操作系统的稳定性受损
在这两种情况下，所有开发者都一致认为这些是必须做出的重要改变，并且这些改变在相较小的痛苦下完成了。如Linux 必须确保保留一个稳定的源码接口，就会创建一个新的接口，
而旧的、有缺陷的接口就必须长期维护，给 USB 开发者带来额外的工作。既然所Linux USB
开发者都是利用自己的时间工作，要求程序员无偿地做没有收益的额外工作，是不可能的
安全问题Linux 也非常重要。当发现一个安全问题时，它会在极短的时间内被修复。有多次
这导致内核内部接口被重构，以防止该安全问题再次发生。当这种情况发生时，所有使用该接口
的驱动也会同时被修复，确保安全问题被修复，并且不会在未来某个时刻意外地再次出现。如内部接口不允许改变，修复这类安全问题并确保它不再发生是不可能的
内核接口会随时间被清理。如果没有人使用某个当前接口，它就会被删除。这确保了内核保尽可能小，并且所有潜在的接口都得到尽可能好的测试（未使用的接口几乎不可能测试其有效性）
### 该怎么

那么，如果你有一个不在主线内核树中的 Linux 内核驱动，作为一个开发者，你该怎么办？
为每个发行版的每个不同内核版本发布一个二进制驱动是一场噩梦，而试图跟上不断变化的内核
接口也是一项艰巨的工作
很简单，把你的内核驱动放进主线内核树中（记住这里我们谈论的是GPL 兼容许可下发布的
驱动，如果你的代码不属于这一类，祝你好运，你只能靠自己了，你这个吸血鬼）。如果你驱动在树中，并且某个内核接口发生了变化，它会被最初做出该内核改动的人修正。这确保了你驱动始终可构建，并且随时间工作，而你只需付出极小的努力
把你的驱动放在主线内核树中带来的非常好的副作用是
  - 驱动的质量会上升，因为（对原始开发者的）维护成本会下降  - 其他开发者会为你的驱动添加特性  - 其他人会发现并修复你驱动中的缺陷  - 其他人会在你的驱动中发现调优机会  - 当外部接口变化需要时，其他人会替你更新驱动  - 驱动会自动随所Linux 发行版一起发布，而无需请求发行版添加它
由于 Linux 比其他任何操作系统都"开箱即地支持更多的不同设备，并且在更多不同处理器体系结构上支持这些设备，这种经过验证的开发模型必定有它做得对的地:)
