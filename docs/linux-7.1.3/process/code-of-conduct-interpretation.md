
## Linux 内核 Contributor Covenant Code 的 Conduct Interpretation


The code_的_conduct 是 一个 通用 document meant 到

The Linux 内核 development effort 是 一个 very personal 进程 compared

### Maintainers


The Code 的 Conduct uses the term "maintainers" numerous times.  在 the

### Responsibilities


The Code 的 Conduct mentions rights 和 responsibilities 用于
maintainers, 和 此 needs 一些 further clarifications.

第一 和 foremost, 它是 一个 reasonable expectation 到 具有 maintainers
lead 由 示例.

该 正在 said, 我们的 community 是 vast 和 broad, 和 存在 无 新
requirement 用于 maintainers 到 unilaterally handle 如何 其他 people

uncertain 关于 approaching the TAB 或 任何 其他 maintainers, 请

在 the end, "为 kind 到 每个 其他" 是 really 什么 the end goal 是 用于
everybody.  我们 know everyone 是 human 和 我们 全部 fail 在 times, 但 the
primary goal 用于 全部 的 us 应当 为 到 work toward amicable resolutions

The 必需 expertise varies depending 在 the area 的 contribution.  它
是 determined mainly 由 上下文 和 technical complexity 和 仅

两者 the expertise expectations 和 decision-making 是 subject 到

make decisions 为了 make progress.  此 prerogative 是 在 the

作为 一个 consequence, 设置 expertise expectations, making decisions 和

同时 maintainers 是 一般而言 welcoming 到 newcomers, 它们的 capacity
的 helping contributors overcome the 条目 hurdles 是 limited, 因此 它们
具有 到 set priorities.  此, 也, 是 不 到 为 seen 作为 一个 violation 的

### Scope


The Linux 内核 community primarily interacts 在 一个 set 的 公共 email
列表 distributed around 一个 数字 的 不同 servers controlled 由 一个
数字 的 不同 companies 或 individuals.  全部 的 这些 列表 是

sent 到 那些 mailing 列表 是 considered covered 由 the Code 的
Conduct.

Developers 谁 使用 the 内核.org bugzilla, 和 其他 子系统 bugzilla
或 bug tracking tools 应当 follow the guidelines 的 the Code 的
Conduct.  The Linux 内核 community 执行 不 具有 一个 "official" project
email 地址, 或 "official" social media 地址.  任何 activity
performed 使用 一个 内核.org email account 必须 follow the Code 的
Conduct 作为 published 用于 内核.org, just 作为 任何 各个 使用 一个
corporate email account 必须 follow the 特定 rules 的 该

The Code 的 Conduct 执行 不 prohibit continuing 到 包含 names, email
地址, 和 associated comments 在 mailing 列出 messages, 内核
change log messages, 或 code comments.

Interaction 在 其他 forums 是 covered 由 whatever rules apply 到 said
forums 和 是 一般而言 不 covered 由 the Code 的 Conduct.  Exceptions
可 为 considered 用于 extreme circumstances.

Contributions submitted 用于 the 内核 应当 使用 appropriate language.
Content 该 已经 exists predating the Code 的 Conduct 将 不 为
addressed 现在 作为 一个 violation.  Inappropriate language 可 为 seen 作为 一个
bug, though; 此类 bugs 将 为 fixed 更多 quickly 若 任何 interested

part 的 the 用户/内核 API, 或 reflect terminology 使用 在 published

### Enforcement 用于 Unacceptable Behavior Code 的 Conduct Violations


The Code 的 Conduct committee works 到 ensure 该 我们的 community continues
到 为 inclusive 和 fosters diverse discussions 和 viewpoints, 和 works
到 improve 那些 characteristics 在…上 time. 一个 majority 的 the reports the

clarification 的 the development 进程 和 the scope 的 the Code 的 Conduct.

behavior 和 make amends 用于 它 在 the 设置 the violation 具有 taken place.

Conduct committee takes measures 到 restore productive 和 respectful

reporters' information 私有. Reports 可以 come 来自 injured parties

Code 的 Conduct Committee 具有 the responsibility 到 investigate 和 resolve

change 在 它们的 understanding 的 the importance 到 repair the damage caused

Code 的 Conduct Committee 将 evaluate 其他 measures 例如 seeking

#### Seek 公共 apology 用于 the violation


The Code 的 Conduct Committee publicly calls out the behavior 在 the

用于 the violation.
