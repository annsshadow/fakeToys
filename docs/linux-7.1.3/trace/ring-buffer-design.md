### 本文档使用的术语


tail
 - 环形缓冲区中发生新写入的位置。

head
 - 环形缓冲区中发生新读取的位置。

producer
 - 写入环形缓冲区的任务（与 writer 相同）

writer
 - 与 producer 相同

consumer
 - 从缓冲区读取的任务（与 reader 相同）

reader
 - 与 consumer 相同。

reader_page
 - 位于环形缓冲区之外、主要（在大多数情况下）
	 供读取者使用的页。

head_page
 - 指向读取者接下来将使用的页的指针

tail_page
 - 指向接下来将被写入的页的指针

commit_page
 - 指向包含最后一个完成的非嵌套写入的页的指针。

cmpxchg
```

	    A = B if previous A == C

	    R = cmpxchg(A, C, B) is saying that we replace A with B if and only
		if current A is equal to C, and we put the old (current)
		A into R

	    R gets the previous A regardless if A is updated with B or not.

	  To see if the update was successful a compare of ``R == C``
	  may be used.

```
### 通用环形缓冲区


环形缓冲区可以在覆盖（overwrite）模式或生产者/消费者（producer/consumer）模式下使用。

在生产者/消费者模式下，如果生产者在消费者释放任何数据之前就填满了缓冲区，生产者将停止写入缓冲区。这将会丢失最近的事件。

在覆盖模式下，如果生产者在消费者释放任何数据之前就填满了缓冲区，生产者将覆盖较旧的数据。这将会丢失最旧的事件。

两个写入者不能同时写入（在同一个 per-cpu 缓冲区上），但一个写入者可能会打断另一个写入者，但被中断的写入者要继续之前，被打断的写入者必须先完成写入。这对算法非常重要。写入者的行为像一个“栈”。中断的工作方式如下：
```


  writer1 start
     <preempted> writer2 start
         <preempted> writer3 start
                     writer3 finishes
                 writer2 finishes
  writer1 finishes

```
这非常类似于一个写入者被中断打断、而该中断也进行了一次写入的情况。

读取者可以在任何时刻进行读取。但两个读取者不能同时运行，读取者也不能抢占/中断另一个读取者。读取者不能抢占/中断写入者，但它可以在写入者写入的同时从缓冲区读取/消费，不过读取者必须位于另一个处理器上才能这样做。读取者可以在自己的处理器上读取，并且可能被写入者抢占。

写入者可以抢占读取者，但读取者不能抢占写入者。但读取者可以在写入者写入的同时（在另一个处理器上）读取缓冲区。

环形缓冲区由通过链表连接在一起的一组页构成。

在初始化时，会为不属于环形缓冲区的读取者分配一个读取者页。

head_page、tail_page 和 commit_page 都被初始化为指向同一个页。

读取者页被初始化为其 next 指针指向 head page，其 previous 指针指向 head page 之前的一个页。

读取者拥有它自己使用的页。在启动阶段，这个页被分配出来但不连入链表。当读取者想要从缓冲区读取时，如果它的页是空的（就像在启动阶段那样），它将用自己的页与 head_page 交换。旧的读取者页将成为环形缓冲区的一部分，而 head_page 将被移出。插入的页（旧 reader_page）之后的页将成为新的 head page。

一旦新页被交给读取者，读取者就可以对它做任何想做的事，只要写入者已经离开了该页。

下面是一个读取者页如何被交换的示例：注意这并不展示缓冲区中的 head page，它仅用于演示一次交换。
```

  +------+
  |reader|          RING BUFFER
  |page  |
  +------+
                  +---+   +---+   +---+
                  |   |-->|   |-->|   |
                  |   |<--|   |<--|   |
                  +---+   +---+   +---+
                   ^ |             ^ |
                   | +-------------+ |
                   +-----------------+


  +------+
  |reader|          RING BUFFER
  |page  |-------------------+
  +------+                   v
    |             +---+   +---+   +---+
    |             |   |-->|   |-->|   |
    |             |   |<--|   |<--|   |<-+
    |             +---+   +---+   +---+  |
    |              ^ |             ^ |   |
    |              | +-------------+ |   |
    |              +-----------------+   |
    +------------------------------------+

  +------+
  |reader|          RING BUFFER
  |page  |-------------------+
  +------+ <---------------+ v
    |  ^          +---+   +---+   +---+
    |  |          |   |-->|   |-->|   |
    |  |          |   |   |   |<--|   |<-+
    |  |          +---+   +---+   +---+  |
    |  |             |             ^ |   |
    |  |             +-------------+ |   |
    |  +-----------------------------+   |
    +------------------------------------+


  +------+
  |buffer|          RING BUFFER
  |page  |-------------------+
  +------+ <---------------+ v
    |  ^          +---+   +---+   +---+
    |  |          |   |   |   |-->|   |
    |  |  New     |   |   |   |<--|   |<-+
    |  | Reader   +---+   +---+   +---+  |
    |  |  page ----^                 |   |
    |  |                             |   |
    |  +-----------------------------+   |
    +------------------------------------+



```
被交换的页有可能同时也是 commit page 和 tail page，前提是环形缓冲区中已有的内容少于一个缓冲区页所能容纳的内容。
```

            reader page    commit page   tail page
                |              |             |
                v              |             |
               +---+           |             |
               |   |<----------+             |
               |   |<------------------------+
               |   |------+
               +---+      |
                          |
                          v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
这种情况对本算法仍然有效。当写入者离开该页时，它直接回到环形缓冲区中，因为读取者页仍然指向环形缓冲区中的下一个位置。


主要指针：

  reader page
     - 仅供读取者使用、不属于环形缓冲区的一部分的页
              （可能会被交换进来）

  head page
     - 环形缓冲区中接下来将与读取者页交换的页。

  tail page
     - 下一次写入将发生的页。

  commit page
     - 最后一个完成写入的页。

commit page 只由写入者栈中最外层的写入者更新。一个打断了另一个写入者的写入者不会移动 commit page。

当数据被写入环形缓冲区时，会在环形缓冲区中预留一个位置并回传给写入者。当写入者完成向该位置写入数据后，它提交（commit）这次写入。

在此事务进行期间的任意时刻，都可能发生另一次写入（或一次读取）。如果发生了另一次写入，它必须在继续之前的写入之前完成。
```

       Buffer page
      +---------+
      |written  |
      +---------+  <--- given back to writer (current commit)
      |reserved |
      +---------+ <--- tail pointer
      | empty   |
      +---------+

   Write commit::

       Buffer page
      +---------+
      |written  |
      +---------+
      |written  |
      +---------+  <--- next position for write (current commit)
      | empty   |
      +---------+


 If a write happens after the first reserve::

       Buffer page
      +---------+
      |written  |
      +---------+  <-- current commit
      |reserved |
      +---------+  <--- given back to second writer
      |reserved |
      +---------+ <--- tail pointer

  After second writer commits::


       Buffer page
      +---------+
      |written  |
      +---------+  <--(last full commit)
      |reserved |
      +---------+
      |pending  |
      |commit   |
      +---------+ <--- tail pointer

  When the first writer commits::

       Buffer page
      +---------+
      |written  |
      +---------+
      |written  |
      +---------+
      |written  |
      +---------+  <--(last full commit and tail pointer)


```
commit 指针指向未被抢占的最后一个已提交写入位置。当一次打断了另一个写入的写入被提交时，它只是一个待提交（pending commit），直到所有写入都被提交后才会成为完整的提交。

commit page 指向包含最后一个完整提交的页。tail page 指向包含最后一次写入（在提交之前）的页。

tail page 总是等于或落后于 commit page。它可能领先好几页。如果 tail page 追上了 commit page，那么就不能再进行任何写入（无论环形缓冲区的模式如何：覆盖模式或生产者/消费者模式）。
```

 head page
 commit page
 tail page

```
```

                               tail page
    head page         commit page  |
        |                 |        |
        v                 v        v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
存在一种特殊情况：head page 位于 commit page 之后，也可能位于 tail page 之后。这种情况发生在 commit（以及 tail）page 已被与读取者页交换时。这是因为 head page 始终是环形缓冲区的一部分，而读取者页不是。只要环形缓冲区内已提交的内容少于一整页，并且某个读取者换出了一页，它换出的就会是 commit page。
```

            reader page    commit page   tail page
                |              |             |
                v              |             |
               +---+           |             |
               |   |<----------+             |
               |   |<------------------------+
               |   |------+
               +---+      |
                          |
                          v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+
                          ^
                          |
                      head page


```
在这种情况下，当 tail 和 commit 移回环形缓冲区时，head page 不会移动。

如果 commit page 仍然在该页上，读取者就不能将一页交换进环形缓冲区。如果读取碰到了最后一个提交（真正的提交，而非待提交或预留），那么就没有更多可读的内容。缓冲区被视为空，直到另一次完整的提交完成。

当 tail 碰到 head page 时，如果缓冲区处于覆盖模式，head page 将被向前推进一页。如果缓冲区处于生产者/消费者模式，写入将失败。
```

              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+
                          ^
                          |
                      head page


              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+
                                   ^
                                   |
                               head page


                      tail page
                          |
                          v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+
                                   ^
                                   |
                               head page

```
注意，读取者页仍将指向之前的 head page。但当发生一次交换时，它将使用最近的 head page。


### 使环形缓冲区无锁：


无锁算法背后的主要思想是：将移动 head_page 指针与将页和读取者交换这两个操作结合起来。状态标志被放置在指向页的指针内部。为此，每个页必须在内存中按 4 字节对齐。这将允许使用该地址的最低 2 位作为标志，因为对于地址而言这 2 位始终为零。要获取地址，
```

  MASK = ~3

  address & MASK

```
这两个位将保存两个标志：

   HEADER
 - 被指向的页是一个 head page

   UPDATE
 - 被指向的页正在被某个写入者更新，
          并且是或即将成为一个 head page。
```

	      reader page
		  |
		  v
		+---+
		|   |------+
		+---+      |
			    |
			    v
	+---+    +---+    +---+    +---+
    <---|   |--->|   |-H->|   |--->|   |--->
    --->|   |<---|   |<---|   |<---|   |<---
	+---+    +---+    +---+    +---+


```
上面指针“-H->”将设置 HEADER 标志。也就是说下一页是读取者接下来将换出的页。这个指针表示下一页是 head page。

当 tail page 碰到 head 指针时，它将使用 cmpxchg 来
```

              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-H->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-U->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
“-U->”表示一个处于 UPDATE 状态的指针。

任何对读取者的访问都需要加某种锁来串行化读取者。但写入者永远不需要加锁来写入环形缓冲区。这意味着我们只需要关心单个读取者，并且写入只以“栈”的形式抢占。

当读取者尝试将页与环形缓冲区交换时，它也将使用 cmpxchg。如果指向 head page 的指针中的标志位没有设置 HEADER 标志，比较将失败，读取者将需要寻找新的 head page 并重试。注意，UPDATE 和 HEADER 标志永远不会同时设置。
```

  +------+
  |reader|          RING BUFFER
  |page  |
  +------+
                  +---+    +---+    +---+
                  |   |--->|   |--->|   |
                  |   |<---|   |<---|   |
                  +---+    +---+    +---+
                   ^ |               ^ |
                   | +---------------+ |
                   +-----H-------------+

```
读取者将读取者页的 next 指针设为 HEADER，指向
```

  +------+
  |reader|          RING BUFFER
  |page  |-------H-----------+
  +------+                   v
    |             +---+    +---+    +---+
    |             |   |--->|   |--->|   |
    |             |   |<---|   |<---|   |<-+
    |             +---+    +---+    +---+  |
    |              ^ |               ^ |   |
    |              | +---------------+ |   |
    |              +-----H-------------+   |
    +--------------------------------------+

```
它使用指向之前 head page 的指针进行一次 cmpxchg，使其指向读取者页。注意新的指针没有 HEADER
```

  +------+
  |reader|          RING BUFFER
  |page  |-------H-----------+
  +------+                   v
    |  ^          +---+   +---+   +---+
    |  |          |   |-->|   |-->|   |
    |  |          |   |<--|   |<--|   |<-+
    |  |          +---+   +---+   +---+  |
    |  |             |             ^ |   |
    |  |             +-------------+ |   |
    |  +-----------------------------+   |
    +------------------------------------+

```
在设置新的 head page 之后，head page 的 previous 指针
```

  +------+
  |reader|          RING BUFFER
  |page  |-------H-----------+
  +------+ <---------------+ v
    |  ^          +---+   +---+   +---+
    |  |          |   |-->|   |-->|   |
    |  |          |   |   |   |<--|   |<-+
    |  |          +---+   +---+   +---+  |
    |  |             |             ^ |   |
    |  |             +-------------+ |   |
    |  +-----------------------------+   |
    +------------------------------------+

  +------+
  |buffer|          RING BUFFER
  |page  |-------H-----------+  <--- New head page
  +------+ <---------------+ v
    |  ^          +---+   +---+   +---+
    |  |          |   |   |   |-->|   |
    |  |  New     |   |   |   |<--|   |<-+
    |  | Reader   +---+   +---+   +---+  |
    |  |  page ----^                 |   |
    |  |                             |   |
    |  +-----------------------------+   |
    +------------------------------------+

```
另一点很重要：读取者页通过其 previous 指针（现在指向新 head page 的那个）回指的那个页，永远不会回指读取者页。这是因为读取者页不属于环形缓冲区。通过 next 指针遍历环形缓冲区将始终停留在环形缓冲区内。而通过 prev 指针遍历环形缓冲区则不一定。

注意，判断一个读取者页的方法很简单，只需检查该页的 previous 指针。如果前一页的 next 指针不
```

             +--------+
             | reader |  next   +----+
             |  page  |-------->|    |<====== (buffer page)
             +--------+         +----+
                 |                | ^
                 |                v | next
            prev |              +----+
                 +------------->|    |
                                +----+

```
head page 前进的方式：

当 tail page 碰到 head page、缓冲区处于覆盖模式、并且发生了更多写入时，写入者必须先向前移动 head page，然后才能移动 tail page。做法是：写入者执行一次 cmpxchg，将指向 head page 的指针从 HEADER 标志转换为设置了 UPDATE 标志。一旦完成这一步，在写入者完成移动之前，读取者将无法将 head page 从缓冲区中换出，也无法移动 head page。

这消除了读取者对写入者可能产生的任何竞争。读取者
```

              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-H->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-U->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
```

             tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-U->|   |-H->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
在设置新的 head page 之后，我们可以设置旧的 head page
```

             tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |-H->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
```

                      tail page
                          |
                          v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |-H->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+


```
以上是一些简单的更新。现在来看更复杂的场景。


如前所述，如果有足够的写入打断了第一次写入，tail page 可能会绕缓冲区一圈并碰到 commit page。此时，我们必须开始丢弃写入（通常会向用户发出某种警告）。但如果 commit 仍然在读取者页上会发生什么呢？commit page 不属于环形缓冲区。tail page
```


            reader page    commit page
                |              |
                v              |
               +---+           |
               |   |<----------+
               |   |
               |   |------+
               +---+      |
                          |
                          v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-H->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+
                 ^
                 |
             tail page

```
如果 tail page 简单地向前推进 head page，当离开读取者页时，commit 将不会指向正确的页。

对此的解决办法是：在向前推进 head page 之前，先测试 commit page 是否在读取者页上。如果在，那么可以认为 tail page 已绕回缓冲区，我们必须丢弃新的写入。

这不是一个竞争条件，因为 commit page 只能由最外层的写入者（被抢占的那个写入者）移动。这意味着当一个写入者正在移动 tail page 时，commit 不会移动。如果读取者页同时被用作 commit page，读取者就不能交换该读取者页。读取者只需简单地检查 commit 已离开读取者页。一旦 commit page 离开读取者页，它将永远不会再回到上面，除非读取者再次与同时作为 commit page 的缓冲区页进行了一次交换。


### 嵌套写入


在向前推进 tail page 时，如果 head page 是下一页，我们必须先向前推进 head page。如果 head page 不是下一页，则只需用一次 cmpxchg 更新 tail page。

只有写入者移动 tail page。这必须原子地完成以保护
```

  temp_page = tail_page
  next_page = temp_page->next
  cmpxchg(tail_page, temp_page, next_page)

```
上述代码将在 tail page 仍然指向预期页时更新它。如果失败，说明一个嵌套写入已将其向前推进，当前写入
```


             temp page
                 |
                 v
              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
```

                      tail page (moved by nested writer)
              temp page   |
                 |        |
                 v        v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
上述情况会使 cmpxchg 失败，但由于 tail page 已经被向前移动，写入者将只是重试在新的 tail page 上预留存储空间。
```

              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-H->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
```

              tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-U->|   |--->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
但如果一个嵌套写入在此处抢占，它将看到下一页是一个 head page，但它也是嵌套的。它将检测到它是嵌套的并保存该信息。检测的依据是它看到的是 UPDATE 标志，而不是 HEADER 或 NORMAL 指针。
```

             tail page
                 |
                 v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-U->|   |-H->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
但它不会将 update 重置回 normal。只有将指针从 HEAD 转换为 UPDATE 的那个写入者才会将它转换回来
```

                      tail page
                          |
                          v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-U->|   |-H->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
在嵌套写入完成后，最外层的写入者将转换
```


                      tail page
                          |
                          v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |--->|   |-H->|   |--->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+


```

  (first writer)

```


  (first writer)

                 A        B    tail page
                 |        |        |
                 v        v        v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-U->|   |-H->|   |-H->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```
如果 tail page 既不等于 A 也不等于 B，那么它必须将指针重置回 NORMAL。它只需要关心嵌套
```


  (first writer)

                 A        B    tail page
                 |        |        |
                 v        v        v
      +---+    +---+    +---+    +---+
  <---|   |--->|   |-U->|   |--->|   |-H->
  --->|   |<---|   |<---|   |<---|   |<---
      +---+    +---+    +---+    +---+

```

  (first writer)
