
## 内核加密 API 接口规范


### 简

内核加密 API 提供了一组丰富的加密算法（cipher），以及其他数据转换机制，以及调用它们的方法。本文档包含API 的描述并提供了示例代码
为了理解并正确使用内核加API，下面简要说明其结构。基于该架构，API 可以划分为不同的组成部分。根据架构规范，还给出了面向加密算法开发者的提示。文末给出了 API 函数调用文档的指引
内核加密 API 将所有算法统称为“转换（transformation）”。因此，cipher 句柄变量通常命名"tfm"。除了加密操作外，内核加API 还支持压缩转换，并像处理 cipher 一样处理它们
内核加密 API 服务于以下两类实体：

- 请求加密服务的消费者（consumer
- 数据转换实现（通常cipher），可由消费者通过内核加密 API 调用

本规范面向内核加API 的消费者，也面向实cipher 的开发者。不过，API 规范不讨论数据转换实现可用的全部 API 调用（即可以注册到内核加API cipher 及其他转换（CRC 甚至压缩算法）的实现）
注意：“转换（transformation）”和 cipher 算法这两个术语可互换使用
### 术语


转换实现是实现了某种具有精确定义行为的转换的实际代码或硬件接口
转换对象（TFM）是转换实现的一个实例。一个转换实现可以关联多个转换对象。这些转换对象中的每一个都由一个加API 消费者或另一个转换持有。当加密 API 消费者请求一个转换实现时，会分配转换对象。随后向消费者提供一个结构体，其中包含转换对象（TFM）
包含转换对象的结构体也可称为“cipher 句柄”。这样的 cipher 句柄始终经历以下阶段，这些阶段体现在适用于该 cipher 句柄API 调用中：

1. cipher 句柄的初始化
2. 执行该句柄适用的所cipher 操作，其中每API 调用都必须提供该 cipher 句柄
3. cipher 句柄的销毁
使用初始API 调用时，会创建并返回一cipher 句柄。因此，请参考所有初始化 API 调用，它们指向消费者预期接收并后续使用的数据结构类型。初始化 API 调用都遵crypto_alloc\* 的命名约定
转换上下文是与转换对象关联的私有数据
