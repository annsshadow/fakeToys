
## Linux NVMe 特性与怪癖（quirk）策略


本文件解释了用于决定 Linux NVMe 驱动支持什么、不支持什么的策略。


## 简介


NVM Express 是一组开放的规范与信息集合。

drivers/nvme/host/ 中的 Linux NVMe 主机驱动支持实现 NVM Express（NVMe）规范族的设备，该规范族目前由若干文档组成：

 - NVMe Base 规范
 - 各种命令集规范（如 NVM Command Set）
 - 各种传输规范（如 PCIe、Fibre Channel、RDMA、TCP）
 - NVMe Management Interface 规范

NVMe 规范参见 https://nvmexpress.org/developers/。


## 支持的特性


NVMe 是一套庞大的规范，其中包含仅对特定用例有用或适用的特性。需要注意，Linux 并不旨在实现规范中的每一个特性。实现的每一个额外特性都会引入更多代码、更多维护工作以及潜在的更多缺陷。因此在 NVMe 主机驱动的功能与可维护性之间存在固有的权衡。

在 Linux NVMe 主机驱动中实现的任何特性必须满足以下要求：

  1. 该特性在官方 NVMe 规范的某个发布版本中指定，或在 NVMe 网站上可用的已批准技术提案（TP）中指定。或者，如果它与线上协议无直接关系，则不得与任何 NVMe 规范相矛盾。
  2. 不与 Linux 体系结构冲突，也不与 NVMe 主机驱动的设计冲突。
  3. 具有清晰、无可争议的价值观，以及在社区中的广泛共识。

厂商特定的扩展通常不受 NVMe 主机驱动支持。

强烈建议与 Linux NVMe 与块层维护者协作，并就打算被 Linux NVMe 主机驱动使用的规范变更获取反馈，以避免后期出现冲突。


## 怪癖（Quirks）


有时开放标准的实现未能正确实现规范的部分内容。Linux 使用基于标识符的怪癖来规避此类实现缺陷。怪癖的目的是处理广泛可用的硬件（通常是消费级硬件），没有这些怪癖 Linux 用户就无法使用。通常这类实现未经过硬件制造商在 Linux 下的测试，或仅进行了表面测试。

Linux NVMe 维护者根据问题对 Linux 用户的影响以及它对驱动可维护性的影响，临时决定是否对实现添加怪癖。一般来说，怪癖是最后手段，即在厂商没有提供固件更新或其他规避方法时才使用。

对于未在大众市场上可用的硬件，不会向 Linux 内核添加怪癖。未能通过企业 Linux 发行版、ChromeOS、Android 或其他 Linux 内核使用方资格认证的硬件，应在出货前修复，而不是依赖 Linux 怪癖。
