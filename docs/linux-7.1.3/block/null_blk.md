
## Null block device driver


## Overview


null 块设备（`/dev/nullb*`）用于对各种块层实现进行基准测试。它模拟一个大小为 X GB 的块设备。它不执行任何读/写操作，只是将它们标记为在请求队列中完成。以下是可能的实例：

  Multi-queue 块层

    - 基于请求（Request-based）。
    - 每个设备可配置提交队列。

  无块层（称为基于 bio）

    - 基于 bio。IO 请求直接提交给设备驱动。
    - 直接接受 bio 数据结构并返回它们。

它们都有一个用于系统中每个核心的完成队列。

## Module parameters


queue_mode=[0-2]: 默认: 2-Multi-queue
  选择模块应以哪个块层实例化。

  =  ============
  0  基于 bio
  1  单队列（已废弃）
  2  多队列
  =  ============

home_node=[0--nr_nodes]: 默认: NUMA_NO_NODE
  选择数据结构从哪个 CPU 节点分配。

gb=[大小（GB）]: 默认: 250GB
  报告给系统的设备大小。

bs=[块大小（字节）]: 默认: 512 字节
  报告给系统的块大小。

nr_devices=[设备数量]: 默认: 1
  实例化的块设备数量。它们被实例化为 /dev/nullb0 等。

irqmode=[0-2]: 默认: 1-Soft-irq
  用于向块层完成 IO 的完成模式。

  =  ===========================================================================
  0  无。
  1  软中断（Soft-irq）。使用 IPI 跨 CPU 节点完成 IO。模拟当 IO 从与设备所连接
     的 home 节点不同的另一个 CPU 节点发出时的开销。
  2  定时器：在每次 IO 完成前等待一个特定周期（completion_nsec）。
  =  ===========================================================================

completion_nsec=[ns]: 默认: 10,000ns
  与 irqmode=2（定时器）结合使用。每个完成事件必须等待的时间。

submit_queues=[1..nr_cpus]: 默认: 1
  附加到设备驱动的提交队列数量。如果未设置，默认为 1。对于多队列，当 use_per_node_hctx 模块参数为 1 时它会被忽略。

hw_queue_depth=[0..qdepth]: 默认: 64
  设备的硬件队列深度。

memory_backed=[0/1]: 默认: 0
  是否使用内存缓冲区来响应 IO 请求

  =  =============================================
  0  不传输数据来响应 IO 请求
  1  使用内存缓冲区来响应 IO 请求
  =  =============================================

discard=[0/1]: 默认: 0
  支持 discard 操作（需要 memory-backed 的 null_blk 设备）。

  =  =====================================
  0  不支持 discard 操作
  1  启用对 discard 操作的支持
  =  =====================================

cache_size=[大小（MB）]: 默认: 0
  memory-backed 设备的缓存大小（MB）。

mbps=[最大带宽（MB/s）]: 默认: 0（无限制）
  设备性能的带宽限制。

### Multi-queue specific parameters


use_per_node_hctx=[0/1]: 默认: 0
  硬件上下文队列的数量。

  =  =====================================================================
  0  提交队列的数量被设置为 submit_queues 参数的值。
  1  多队列块层被实例化，并为系统中的每个 CPU 节点配备一个硬件派发队列。
  =  =====================================================================

no_sched=[0/1]: 默认: 0
  启用/禁用 io 调度器。

  =  ======================================
  0  nullb* 使用默认的 blk-mq io 调度器
  1  nullb* 不使用 io 调度器
  =  ======================================

blocking=[0/1]: 默认: 0
  请求队列的阻塞行为。

  =  ===============================================================
  0  注册为一个非阻塞的 blk-mq 驱动设备。
  1  注册为一个阻塞的 blk-mq 驱动设备，null_blk 会设置
     BLK_MQ_F_BLOCKING 标志，表示其 ->queue_rq() 函数有时/总是
     需要阻塞。
  =  ===============================================================

shared_tags=[0/1]: 默认: 0
  设备之间共享标签（tag）。

  =  ================================================================
  0  标签集不共享。
  1  标签集在设备之间为 blk-mq 共享。仅在 nr_devices > 1 时有意义，
     否则没有可共享的标签集。
  =  ================================================================

zoned=[0/1]: 默认: 0
  设备是随机访问还是分区（zoned）块设备。

  =  ======================================================================
  0  块设备作为随机访问块设备暴露。
  1  块设备作为主机管理（host-managed）的分区块设备暴露。需要
     CONFIG_BLK_DEV_ZONED。
  =  ======================================================================

zone_size=[MB]: 默认: 256
  作为分区块设备暴露时的每区大小。必须是 2 的幂。

zone_nr_conv=[nr_conv]: 默认: 0
  块设备被分区时要创建的常规（conventional）区数量。如果
  zone_nr_conv >= nr_zones，它会被缩减为 nr_zones - 1。
