## 块设备层在 /sys/block/<dev>/stat 中的统计信息


本文件说明了 /sys/block/<dev>/stat 文件的内容。

stat 文件提供了若干关于块设备 <dev> 状态的统计信息。

问：
   为何要把多个统计值放在同一个文件里？sysfs 不是通常每个文件只包含一个值吗？

答：
   通过只用一个文件，内核可以保证这些统计值代表了设备状态在某个一致时刻的快照。如果这些统计值以多个文件分别导出的话，就无从保证一组读数对应于同一个时间点的状态。

stat 文件由一行文本组成，包含 17 个以空白字符分隔的十进制数值。各字段在下表中汇总，并在下文逐一详述。


=============== ============= =================================================
名称            单位          说明
=============== ============= =================================================
read I/Os       请求数        已处理的读 I/O 请求数量
read merges     请求数        与队列中已有 I/O 合并的读 I/O 请求数量
read sectors    扇区数        读取的扇区数量
read ticks      毫秒          读请求的总等待时间
write I/Os      请求数        已处理的写 I/O 请求数量
write merges    请求数        与队列中已有 I/O 合并的写 I/O 请求数量
write sectors   扇区数        写入的扇区数量
write ticks     毫秒          写请求的总等待时间
in_flight       请求数        当前正在处理（in flight）的 I/O 请求数量
io_ticks        毫秒          该块设备处于活跃状态的总时间
time_in_queue   毫秒          所有请求的总等待时间
discard I/Os    请求数        已处理的丢弃（discard）I/O 请求数量
discard merges  请求数        与队列中已有 I/O 合并的丢弃 I/O 请求数量
discard sectors 扇区数        被丢弃的扇区数量
discard ticks   毫秒          丢弃请求的总等待时间
flush I/Os      请求数        已处理的刷新（flush）I/O 请求数量
flush ticks     毫秒          刷新请求的总等待时间
=============== ============= =================================================

## read I/Os、write I/Os、discard I/Os


当某个 I/O 请求完成时，这些数值会递增。

## flush I/Os


当某个刷新（flush）I/O 请求完成时，这些数值会递增。

块设备层会将刷新请求合并，并且同一时刻最多只执行一个。这里统计的是由磁盘执行的刷新请求数量，分区不对其进行统计。

## read merges、write merges、discard merges


当某个 I/O 请求与队列中已有的 I/O 请求合并时，这些数值会递增。

## read sectors、write sectors、discard_sectors


这些数值统计从该块设备读出、写入或丢弃的扇区数量。这里所说的“扇区”是指标准的 UNIX 512 字节扇区，而不是任何设备或文件系统特定的块大小。这些计数器在 I/O 完成时递增。

## read ticks、write ticks、discard ticks、flush ticks


这些数值统计 I/O 请求在该块设备上的等待毫秒数。如果有多个 I/O 请求在等待，这些数值会以大于每秒 1000 的速率增长；例如，如果有 60 个读请求平均等待 30 毫秒，那么 read_ticks 字段将增加 60*30 = 1800。

## in_flight


该数值统计已经下发到设备驱动但尚未完成的 I/O 请求数量。它不包括那些已在队列中但尚未下发到设备驱动的 I/O 请求。

## io_ticks


该数值统计设备存在排队 I/O 请求的毫秒数。

## time_in_queue


该数值统计 I/O 请求在该块设备上的等待毫秒数。如果有多个 I/O 请求在等待，该数值将按“毫秒数 × 等待请求数”的乘积增长（示例见上文“read ticks”）。
