## 块设备层/sys/block/<dev>/stat 中的统计信息


本文件说明了 /sys/block/<dev>/stat 文件的内容
stat 文件提供了若干关于块设备 <dev> 状态的统计信息
问：
   为何要把多个统计值放在同一个文件里？sysfs 不是通常每个文件只包含一个值吗
答：
   通过只用一个文件，内核可以保证这些统计值代表了设备状态在某个一致时刻的快照。如果这些统计值以多个文件分别导出的话，就无从保证一组读数对应于同一个时间点的状态
stat 文件由一行文本组成，包含 17 个以空白字符分隔的十进制数值。各字段在下表中汇总，并在下文逐一详述

=============== ============= =================================================
名称            单位          说明
=============== ============= =================================================
read I/Os       请求       已处理的I/O 请求数量
read merges     请求       与队列中已有 I/O 合并的读 I/O 请求数量
read sectors    扇区       读取的扇区数read ticks      毫秒          读请求的总等待时write I/Os      请求       已处理的I/O 请求数量
write merges    请求       与队列中已有 I/O 合并的写 I/O 请求数量

## read I/Os、write I/Os、discard I/Os


当某I/O 请求完成时，这些数值会递增
## flush I/Os


当某个刷新（flush）I/O 请求完成时，这些数值会递增
块设备层会将刷新请求合并，并且同一时刻最多只执行一个。这里统计的是由磁盘执行的刷新请求数量，分区不对其进行统计
## read merges、write merges、discard merges


当某I/O 请求与队列中已有I/O 请求合并时，这些数值会递增
## read sectors、write sectors、discard_sectors


这些数值统计从该块设备读出、写入或丢弃的扇区数量。这里所说的“扇区”是指标准的 UNIX 512 字节扇区，而不是任何设备或文件系统特定的块大小。这些计数器I/O 完成时递增
## read ticks、write ticks、discard ticks、flush ticks


这些数值统I/O 请求在该块设备上的等待毫秒数。如果有多个 I/O 请求在等待，这些数值会以大于每1000 的速率增长；例如，如果60 个读请求平均等待 30 毫秒，那read_ticks 字段将增60*30 = 1800
## in_flight


该数值统计已经下发到设备驱动但尚未完成的 I/O 请求数量。它不包括那些已在队列中但尚未下发到设备驱动I/O 请求
## io_ticks


该数值统计设备存在排I/O 请求的毫秒数
## time_in_queue


该数值统I/O 请求在该块设备上的等待毫秒数。如果有多个 I/O 请求在等待，该数值将按“毫秒数 × 等待请求数”的乘积增长（示例见上文“read ticks”）
