## matroxfb —Matrox 设备的帧缓冲驱动


这是用于 Alpha、Intel PPC 机器Matrox 设备的图形帧缓冲驱动

优点

 - 它提供了一个漂亮的宽大控制台（1024x768 下为 128 + 48 行），而无需使用
   又小又看不清的字体
 - 你可以在 /dev/fb0 之上运行 XF{68,86}_FBDev XFree86 fbdev 驱动
 - 最重要的是：启logo :-)

缺点

 - 图形模式比文本模式慢……但如果你使用和文本模式相同的分辨率，应该不会察觉到


## 如何使用


切换模式通过 video=matroxfb:vesa:... 引导参数或使`fbset` 程序完成

例如，如果你想启1280x1024x24bpp 的分辨率，应该向内核传入以下命令行：
"video=matroxfb:vesa:0x1BB"銆。

你应该同时编译进 vgacon（以便在你把 Matrox 从机器中移除时启动）matroxfb
（用于图形模式）。除非你的主显示器在Matrox VBE2.0 设备上，否则不应编译
vesafb（详Documentation/fb/vesafb.rst）

## X11


XF{68,86}_FBDev 应该工作得很好，但它没有加速。在intel 架构上，24bpp 视频模式
有一些故障6 32bpp 工作正常

运行另一个（加速的）X-Server，如 XF86_SVGA，也可以。但是（至少）XFree 服务器在
显示器配置下有重大问题（即使在第一台显示器上，更别提第二台了）。运XFree86 4.x
加速的 mga 驱动是可能的，但你必须不启用 DRI——如果你启用了，你的 X 桌面的分辨率
颜色深度必须与你的虚拟控制台的分辨率和颜色深度匹配，否则 X 会破坏加速器设置


## SVGALib


驱动包含 SVGALib 兼容代码。它通过为控制台选择文本模式来开启。你可以在引导时通过
使用 videomode 2,3,7,0x108-0x10C 0x1C0 来做到这一点。在运行时，`fbset -depth 0`
完成这项工作。不幸的是，SVGALib 应用程序退出后，屏幕内容会被破坏。切换到另一
控制台再切回来可以修复它。我希望这是 SVGALib 的问题而不是我的，但我不确定


## 配置


你可以通过 `video=matroxfb:option1,option2:value2,option3`（多个选项之间用逗号分隔
值与选项之间`:` 分隔）向 matroxfb 传递内核命令行选项。接受的选项

============ ===================================================================
mem:X        内存大小（X 可以是兆字节、千字节或字节）
	     你只能减小由驱动确定的值，因为它总是探测内存。默认是使用整个
	     检测到的可用于屏幕显示的内存（即最8 MB）
disabled     不加载驱动；你也可以使用 `off`，但这里也提供了 `disabled`
enabled      加载驱动；如果你LILO 配置中有 `video=matroxfb:disabled`，你可以
	     这个覆盖它（你不能覆`off`）。它是默认
noaccel      不使用加速引擎。它Alphas 上不工作
accel        使用加速引擎。它是默认
nopan        创建初始控制台时 vyres = yres，从而禁用虚拟滚动
pan          创建初始控制台时尽可能高（vyres = memory/vxres）。它是默认
nopciretry   禁用 PCI 重试。某些有缺陷的芯片组需要它，对intel 82437 会自
	     检测。在这种情况下，设备不符PCI 2.1 规范（它不能保证每笔事务
	     32 PCLK 内以成功或重试结束）
pciretry     启用 PCI 重试。除 intel 82437 外，它是默认
novga        禁用 VGA I/O 端口。如BIOS 没有启用设备，它是默认。你不应使用此选项
	     某些板卡之后不关机就无法重启
vga          保留 VGA I/O 端口的状态。它是默认。如BIOS 没有启用，驱动不会启
	     VGA I/O（大多数情况下启用它并不安全）
nobios       禁用 BIOS ROM。如BIOS 没有自行启用 BIOS，它是默认。你不应使用此选项
	     某些板卡之后不关机就无法重启
bios         保留 BIOS ROM 的状态。它是默认。如BIOS 之前没有被启用，驱动不会
	     启用它
noinit       告诉驱动设备已被初始化。如果你G100 或驱动无法检测内存、你在屏
	     上看到奇怪的花纹等等，你应该使用它。未BIOS 启用的设备仍会初始化
	     它是默认
init         驱动初始化它知晓的每个设备
memtype      指定内存类型，隐'init'。它仅对 G200 G400 有效，含义如下：

	       G200:
   - 0 -> 2x128Kx32 芯片，板2MB，可能是 sgram
   - 1 -> 2x128Kx32 芯片，板4MB，可能是 sgram
   - 2 -> 2x256Kx32 芯片，板4MB，可能是 sgram
   - 3 -> 2x256Kx32 芯片，板8MB，可能是 sgram
   - 4 -> 2x512Kx16 芯片，板8/16MB，可能仅 sdram
   - 5 -> 与上面相
   - 6 -> 4x128Kx32 芯片，板4MB，可能是 sgram
   - 7 -> 4x128Kx32 芯片，板8MB，可能是 sgram
	       G400:
   - 0 -> 2x512Kx16 SDRAM锛?6/32MB
   - 2x512Kx32 SGRAM锛?6/32MB
   - 1 -> 2x256Kx32 SGRAM锛?/16MB
   - 2 -> 4x128Kx32 SGRAM锛?/16MB
   - 3 -> 4x512Kx32 SDRAM锛?2MB
   - 4 -> 4x256Kx32 SGRAM锛?6/32MB
   - 5 -> 2x1Mx32 SDRAM锛?2MB
   - 6 -> 保留
   - 7 -> 保留

	     除了 memtype 参数外，你还应该使用 sdram sgram 参数
nomtrr       禁用帧缓冲上的写合并。这会减慢驱动，但有报告称在高负载下，如果启用写
	     合并，GUS DMA XFree 之间存在轻微不兼容（声音中断）
mtrr         启用帧缓冲上的写合并。它大大加快视频访问。它是默认。你必须在内核中启用
	     MTRR 支持，并且你CPU 必须具有 MTRR（例Pentium II 就有）
sgram        告诉驱动你有SGRAM 内存Gxx0。没`init` 则不起作用
sdram        告诉驱动你有SDRAM 内存Gxx0。它是默认
inv24        更改 Millennium Millennium II 24bpp 模式的时序参数。如果你在字
	     周围看到奇怪的彩色阴影，请指定这个
noinv24      使用标准时序。它是默认
inverse      反转屏幕上的颜色（用LCD 显示器）
noinverse    在屏幕上显示真实颜色。它是默认
dev:X        将驱动绑定到设备 X。驱动从 0 N 对设备编号，其中设备 0 是找到的第一
	     `已知` 设备 是第二个，依此类推。lspci 以此顺序列出设备。默认是
	     `每个` 已知设备
nohwcursor   禁用硬件光标（改用软件光标）
hwcursor     启用硬件光标。它是默认。如果你使用非加速模式（`noaccel` `fbset -accel false`），
	     则使用软件光标（文本模式除外）
noblink      禁用光标闪烁。文本模式下的光标总是闪烁（硬件限制）
blink        启用光标闪烁。它是默认
nofastfont   禁用 fastfont 功能。它是默认
fastfont:X   启用 fastfont 功能。X 指定为字体数据保留的内存大小，它必须 >=
	     (fontwidth**fontheight**chars_in_font)/8。在 Gx00 系列上更快，但在较旧
	     卡上较慢
grayscale    启用灰度求和。它PSEUDOCOLOR 模式（文本bppbpp）下工作。在
	     DIRECTCOLOR 模式下，它仅限于通过 putc/putcs 显示的字符。直接访问帧缓冲
	     可以绘制颜色
nograyscale  禁用灰度求和。它是默认
cross4MB     启用像素行跨4MB 边界。它是非 Millennium 的默认
nocross4MB   像素行不得跨4MB 边界。它Millennium I II 的默认，因为这些设备
	     有不允许这样做的硬件限制。但此选项与某些（如果不是所有已发布的）版本
	     XF86_FBDev 不兼容
dfp          启用数字平板接口。此选项与次级（TV）输出不兼容——如DFP 激活，TV 输出
	     必须关闭，反之亦然。DFP 总是使用与初级（监视器）输出相同的时序
dfp:X        为数字平板接口使用设X。X 0 0xFF 之间的数字，每个单独位的含义
	     G400 手册DAC 寄存0x1F 的描述中有说明。对于正常操作，你应将所有位
	     设为零，最低位除外。这个最低位选择显示时钟的来源，G400 还是面板
	     默认值现在从硬件读回——所以你应仅在你也使`init` 参数时才指定此值
outputs:XYZ  设置 CRTC 和输出之间的映射。每个字母可以取 0（无 CRTC）（CRTC1）或
	     2（CRTC2）的值，第一个字母对应初级模拟输出，第二个字母对应次级模拟输出，
	     第三个字母对DVI 输出。G400 以下或没DFP G400 的默认设置为 100
	     DFP G400 101，G450 G550 111。你只能在第一张卡上设置映射，
	     使用 matroxset 设置其他设备
vesa:X       选择启动视频模式。X 0 0x1FF 之间的数字，详细解释见上表。如果驱
	     8bpp 支持，默认是 640x480x8bpp。否则依次为 640x350x4bpp40x480x15bpp
	     640x480x24bpp40x480x32bpp 80x25 文本0x25 文本总是可用）
============ ===================================================================

如果你对 `vesa` 选项选择的视频模式不满意，你可以用这些选项修改它：

============ ===================================================================
xres:X       水平分辨率，以像素计。默认从 `vesa` 选项派生
yres:X       垂直分辨率，以像素行计。默认从 `vesa` 选项派生
upper:X      上边界：VSYNC 脉冲结束到图像第一行像素开始之间的行数。默认从 `vesa`
	     选项派生
lower:X      下边界：图像结束VSYNC 脉冲开始之间的行数。默认从 `vesa` 选项派生
vslen:X      VSYNC 脉冲的长度，以行计。默认从 `vesa` 选项派生
left:X       左边界：HSYNC 脉冲结束到第一个像素之间的像素数。默认从 `vesa` 选项派生
right:X      右边界：图像结束HSYNC 脉冲开始之间的像素数。默认从 `vesa` 选项派生
hslen:X      HSYNC 脉冲的长度，以像素计。默认从 `vesa` 选项派生
pixclock:X   点时钟，ps（皮秒）计。默认从 `vesa` 选项以及 `fh` `fv` 选项派生
sync:X       同步脉冲——位 0 反转 HSYNC 极性，1 反转 VSYNC 极性。如果设置了3
	     （0x08），则生成复合同步而不HSYNC。如果设置了5（0x20），
	     则开启绿色同步。不要忘记，如果你想绿色同步，你可能也想要复合同步。默
	     取决`vesa`
depth:X      每像素位数：0=文本564 32。默认取决于 `vesa`
============ ===================================================================

如果你了解监视器的能力，你可以指定一些（或全部）`maxclk`、`fh` `fv`。在这种
情况下，`pixclock` 会被计算，使pixclock <= maxclk、real_fh <= fh real_fv <= fv

============ ==================================================================
maxclk:X     最大点时钟。X 可以MHz、kHz Hz 指定。默认是 `不关心`
fh:X         最大水平同步频率。X 可以kHz Hz 指定。默认是 `不关心`
fv:X         最大垂直频率。X 必须Hz 指定。默认对于从 `vesa` 派生yres <= 400 
	     模式70，对yres > 400 60Hz

## 限制


有已知和未知bug、特性和缺陷。当前已知以bug

 - SVGALib 退出时不恢复屏幕
 - 通用fbcon-cfbX 过程Alphas 上不工作。因此，Alpha `noaccel`（和 cfb4
   accel）驱动不工作。因此每个能访问 Alpha `/dev/fb*` 的人都可以挂起机器（你应
   限制`/dev/fb*` 的访问——每个能访问此设备的人都可以毁掉你的监视器，相信我……）
 - 在大端架构上4bpp 不能正确支持 XF-FBDev
 - 不支持隔行文本模式；看起来像是硬件限制，但我不确定
 - Gxx0 SGRAM/SDRAM 未被自动检测
 - 可能还有更多…

以及以下缺陷

 - SVGALib 退出时不恢复屏幕
 - 文本模式的点时钟受硬件限制为

    - G200 涓?83 MHz
    - Millennium I 涓?66 MHz
    - Millennium II 涓?60 MHz

   由于我无法访问其他设备，我不知道它们的具体频率。所以驱动不检查这一点，并允许你
   设置比这更高的频率。这会导致屏幕上的火花、黑洞和其他漂亮的效果。测试期间设
   未被毁坏-)
 - 我的 Millennium G200 振荡器频率范围从 35 MHz 380 MHz（并且在320 MHz 点时钟下
   8bpp 工作（并更改mclk））。但 Matrox 在产品表上说 VCO 限制50-250 MHz，所
   我相信他们（也许那个芯片会过热，但它有一个很大的散热器（G100 没有），所以应该能
   工作）
 - Mystique Gx00 的特殊混合视图形视频模式—G8V16 G16V16 不被支持
 - 不支持颜色键控
 - Mystique Gx00 的功能连接器被设置为 VGA 模式（它BIOS 禁用）
 - DDC（监视器检测）通过双头驱动支持
 - 对某些输入值的检查没有应有的那么严格（你可以指定 vslen=4000 等等）
 - 可能还有更多…

以及以下特性：

 - 4bpp 仅在 Millennium I Millennium II 上可用。这是硬件限制
 - 1:5:5:5 5:6:5 16bpp 视频模式之间的选择通过 fbset -rgba 选项完成
   "fbset -depth 16 -rgba 5,5,5" 选择 1:5:5:5，其他任何选择选择 5:6:5 模式
 - 文本模式使用 6 VGA 调色板而不8 位（262144 种颜色中的一种而不16M 种颜
   中的一种）。这是由Millennium I/II 的硬件限制和 SVGALib 兼容性

## 双头 G400


驱动支持双头 G400，有一些限制：
 - 次级头与初级头共享显存。如果你32MB 显存这不是问题，但如果你只有 16MB，你
   选择视频模式前可能要三思（例如两次 1880x1440x32bpp 是不可能的）
 - 由于硬件限制，次级头只能使用 16 32bpp 视频模式
 - 次级头没有加速。当次级头使用加速时，加速的 XFree 出现了严重问题
 - 次级头总是640x480@60-32 视频模式上电。你必须使用 fbset 来更改此模式
 - 次级头总是以监视器模式上电。你必须使用 fbmatroxset 将其更改TV 模式。此外，
   必须NTSC 输出选择至少 525 行，PAL 输出选择 625 行
 - 内核还没有完全为多头做好准备。所以有些事情无法做到
 - 如果你把它编译为模块，你必须i2c-matroxfb、matroxfb_maven matroxfb_crtc2
   插入内核


## 双头 G450


驱动支持双头 G450，有一些限制：
 - 次级头与初级头共享显存。如果你32MB 显存这不是问题，但如果你只有 16MB，你
   选择视频模式前可能要三思
 - 由于硬件限制，次级头只能使用 16 32bpp 视频模式
 - 次级头没有加速
 - 次级头总是640x480@60-32 视频模式上电。你必须使用 fbset 来更改此模式
 - 不支TV 输出
 - 内核还没有完全为多头做好准备，所以有些事情无法做到
 - 如果你把它编译为模块，你必须matroxfb_g450 matroxfb_crtc2 插入内核
