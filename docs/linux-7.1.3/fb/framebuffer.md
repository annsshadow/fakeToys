## 帧缓冲设

Last revised: May 10, 2001


### 0. 简

帧缓冲设备为图形硬件提供了一个抽象。它表示某些视频硬件的帧缓冲，并允许应用程序软件通过一个定义良好的接口访问图形硬件，这样软件就无需了解任何底层（硬件寄存器）的细节
该设备通过特殊的设备节点访问，这些节点通常位于 /dev 目录中，/dev/fb*

### 1. 用户视角下的 /dev/fb*


从用户的角度看，帧缓冲设备看起来/dev 中的任何其他设备一样。它是一个使用主设备29 的字符设备；次设备号指定帧缓冲编号
按照惯例，使用以下设备节点（数字表示设备

```

      0 = /dev/fb0	First frame buffer
      1 = /dev/fb1	Second frame buffer
	  ...
     31 = /dev/fb31	32nd frame buffer

```
为了向后兼容，你可能希望创建以下符号

```

    /dev/fb0current -> fb0
    /dev/fb1current -> fb1

```
等等…
帧缓冲设备也是“普通”的内存设备，这意味着你可
```

  cp /dev/fb0 myfile

```
同一时刻也可以存在多个帧缓冲，例如当你除了内置硬件外还有一块显卡时。相应的帧缓冲设备（/dev/fb0 /dev/fb1 等）独立工作
使用帧缓冲设备的应用软件（例X 服务器）默认会使/dev/fb0（较旧的软件使用 /dev/fb0current）。你可以通过将环境变$FRAMEBUFFER 设置为某个帧缓冲设备的路径名来指定另一个帧缓冲设备，例如（对于 sh/bash

```

    export FRAMEBUFFER=/dev/fb1

```
```

    setenv FRAMEBUFFER /dev/fb1

```
此后 X 服务器将使用第二个帧缓冲

### 2. 程序员视角下/dev/fb*


如你所知，帧缓冲设备是/dev/mem 一样的内存设备，具有相同的特性。你可以读它、写它、定位到其中的某个位置并 mmap() 它（主要用法）。区别仅仅在于特殊文件中出现的不是整个内存，而是某些视频硬件的帧缓冲
/dev/fb* 还允许在其上执行若干 ioctl，通过它们可以查询和设置大量关于硬件的信息。颜色映射的处理也通过 ioctl 完成。有关存在哪ioctl 以及它们作用于哪些数据结构，请查<linux/fb.h>。这里只是一个简要概览：

  - 你可以请求关于硬件的不可变信息，例如名称、屏幕内存的组织方式（位面、紧凑像素……）以及屏幕内存的地址与长度
  - 你可以请求并改变关于硬件的可变信息，例如可见与虚拟几何、深度、颜色映射格式、时序等等。如果你尝试改变这些信息，驱动可能会将某些值向上取整以满足硬件能力（若不可能则返回 EINVAL）
  - 你可以获取并设置颜色映射的一部分。通信时每个颜色分量（红、绿、蓝、透明）使16 位，以支持所有现有硬件。驱动会完成将其应用到硬件所需的所有计算（向下取整到更少位，可能丢弃透明分量）
所有这些硬件抽象使应用程序的实现更容易且更具可移植性。例如，X 服务器完全运行在 /dev/fb* 上，因此无需知道具体硬件的颜色寄存器是如何组织的。XF68_FBDev 是一个用于位图化、无加速视频硬件的通用 X 服务器。唯一需要内建到应用程序中的是屏幕组织方式（位面或紧凑像素等），因为它直接操作帧缓冲图像数据
未来计划将显卡等帧缓冲驱动实现为运行时加载的内核模块。这样的驱动只需调用 register_framebuffer() 并提供一些函数。独立于内核编写和分发这样的驱动将省去很多麻烦…

### 3. 帧缓冲分辨率维护


帧缓冲分辨率使用工具 `fbset` 维护。它可以改变帧缓冲设备的视频模式属性。其主要用途是改变当前的视频模式，例如在启动期间你的某`/etc/rc.*` `/etc/init.d/*` 文件中。Fbset 使用一个存储在配置文件中的视频模式数据库，因此你可以轻松添加自己的模式，并用一个简单标识符引用它们

### 4. X 鏈嶅姟鍣。

X 服务器（XF68_FBDev）是帧缓冲设备最著名的应用程序。从 XFree86 3.2 版开始，X 服务器成XFree86 的一部分，并有两种模式：

  - 如果 /etc/XF86Config `fbdev` 驱动 `Display` 子节
```

	Modes "default"

    line, X 服务器将使用上面讨论的方案，即它将在 /dev/fb0（或 $FRAMEBUFFER，若已设置）所确定的分辨率下启动。不过你仍然必须指定颜色深度（使Depth 关键字）和虚拟分辨率（使Virtual 关键字）。这XFree86 附带配置文件的默认设置。这是最简单的配置，但有一些限制
  - 因此也可以在 /etc/XF86Config 文件中指定分辨率。这允许在保持相同虚拟桌面大小的同时即时切换分辨率。所使用的帧缓冲设备仍然/dev/fb0current（或 $FRAMEBUFFER），但可用分辨率现在/etc/XF86Config 定义。缺点是你需要以不同的格式指定时序（`fbset -x` 可能有帮助）
```
要调整视频模式，你可以使fbset xvidtune。注xvidtune XF68_FBDev 并非 100% 兼容：报告的时钟值总是不正确的

### 5. 视频模式时序


显示器通过电子束在屏幕上绘制图像（彩色型号3 束电子束，单色显示器1 束电子束）。屏幕正面覆盖着彩色荧光粉（像素）的图案。如果荧光粉被电子击中，它会发出光子从而变得可见。电子束从左到右、从上到下绘制水平线（扫描线）。通过改变电子束的强度，可以显示具有各种颜色和强度的像素。每条扫描线绘制完后，电子束必须移回屏幕左侧并到下一行：这称为水平回扫（horizontal retrace）。整个屏幕（帧）绘制完后，电子束移回左上角：这称为垂直回扫（vertical retrace）。在水平与垂直回扫期间，电子束被关闭（消隐）
电子束绘制像素的速度由显卡中dotclock 决定。对于例28.37516 MHz（百
```

    1/(28.37516E6 Hz) = 35.242E-9 s

```
```

    640*35.242E-9 s = 22.555E-6 s

```
用于在一条扫描线上绘640（xres）个像素。但水平回扫

```

    (640+272)*35.242E-9 s = 32.141E-6 s

```
```

    1/(32.141E-6 s) = 31.113E3 Hz

```
整个屏幕包含 480（yres）行，但我们必须考虑垂直

```

    (480+49)*32.141E-6 s = 17.002E-3 s

```
```

    1/(17.002E-3 s) = 58.815 Hz

```
这意味着屏幕数据每秒刷新59 次。为了获得没有可见闪烁的稳定画面，VESA 建议垂直扫描率至少为 72 Hz。但感知到的闪烁非常因人而异：有些人可以50 Hz 下毫无问题地使用，而我如果低于 80 Hz 就会察觉到
由于显示器不知道新扫描线何时开始，显卡会为每条扫描线提供一个同步脉冲（水平同步hsync）。类似地，它会为每个新帧提供一个同步脉冲（垂直同步vsync）。图像在屏幕上的位置受同步脉冲发生时刻的影响

### 6. XFree86 时序值转换为帧缓冲设备时

```

 "800x600"     50      800  856  976 1040    600  637  643  666
 < name >     DCF       HR  SH1  SH2  HFL     VR  SV1  SV2  VFL

```
帧缓冲设备使用以下字段：

  - pixclock：像素时钟，单位ps（皮秒）
  - left_margin：从同步到图像的时间
  - right_margin：从图像到同步的时间
  - upper_margin：从同步到图像的时间
  - lower_margin：从图像到同步的时间
  - hsync_len：水平同步的长度
  - vsync_len：垂直同步的长度

1) 像素时钟
   xfree：单位为 MHz

   fb：单位为皮秒（ps
   pixclock = 1000000 / DCF

2) 水平时序
   left_margin = HFL - SH2

   right_margin = SH1 - HR

   hsync_len = SH2 - SH1

3) 垂直时序
   upper_margin = VFL - SV2

   lower_margin = SV1 - VR

   vsync_len = SV2 - SV1

VESA 时序的良好示例可XFree86 源代码树中找到，位于 "xc/programs/Xserver/hw/xfree86/doc/modeDB.txt"
