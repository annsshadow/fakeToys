## vesafb —— 通用图形帧缓冲驱动


这是一个用于 Intel 机器上图形帧缓冲的通用驱动。

思路很简单：在启动时借助 BIOS 打开图形模式，并将其作为帧缓冲设备 /dev/fb0 使用，就像 m68k（以及其他）移植所做的那样。

这意味着我们在启动时就决定了是要在文本模式还是图形模式下运行。之后（在保护模式下）切换模式是不可能的；BIOS 调用只能在实模式下工作。需要 VESA BIOS Extensions Version 2.0，因为我们需要一个线性帧缓冲。

优点：

 - 它提供了一个很不错的大号控制台（在 1024x768 下为 128 列 + 48 行），而无需使用细小、难以辨认的字体。
 - 你可以在 /dev/fb0 之上运行 XF68_FBDev（=> 为每个符合 VBE 2.0 的图形板卡提供非加速的 X11 支持）。
 - 最重要的是：启动 logo :-)

缺点：

 - 图形模式比文本模式慢……


## 如何使用？


模式切换通过 vga=... 启动参数完成。详细信息请阅读
Documentation/admin-guide/svga.rst。

你应该同时编译进 vgacon（用于文本模式）和 vesafb（用于图形模式）。具体由谁接管控制台，取决于所指定的是文本模式还是图形模式。

图形模式不在你以 vga=ask 启动并回车时所得到的列表中。你希望使用的模式由 VESA 模式号推导而来。下面是这些 VESA 模式号：

====== =======  =======  ======== =========
colors 640x480  800x600  1024x768 1280x1024
====== =======  =======  ======== =========
256    0x101    0x103    0x105    0x107
32k    0x110    0x113    0x116    0x119
64k    0x111    0x114    0x117    0x11A
16M    0x112    0x115    0x118    0x11B
====== =======  =======  ======== =========


Linux 内核的视频模式号是 VESA 模式号加上 0x200：

 Linux_kernel_mode_number = VESA_mode_number + 0x200

因此内核模式号的对应表为：

====== =======  =======  ======== =========
colors 640x480  800x600  1024x768 1280x1024
====== =======  =======  ======== =========
256    0x301    0x303    0x305    0x307
32k    0x310    0x313    0x316    0x319
64k    0x311    0x314    0x317    0x31A
16M    0x312    0x315    0x318    0x31B
====== =======  =======  ======== =========

要启用其中一种模式，你必须在 lilo.conf 文件中指定“vga=ask”并重新运行 LILO。随后你可以在“vga=ask”提示符下输入期望的模式。例如，如果你想使用 1024x768x256 色，则必须在该提示符下输入“305”。

如果这不起作用，可能是因为你的 BIOS 不支持线性帧缓冲，或者根本不支持该模式。即使你的板卡支持，也可能是 BIOS 不支持。需要 VESA BIOS Extensions v2.0，1.2 是不够的。如果出错，你会看到“bad mode number”消息。

1. 注意：LILO 不能处理十六进制，若要直接用“vga=mode-number”启动，你必须将这些数字转换为十进制。
2. 注意：某些较新版本的 LILO 似乎可以使用这些十六进制值，前提是在数字前面加上 0x。

## X11


XF68_FBDev 应该能正常工作，但它是非加速的。运行其他（加速的）X-Server，例如 XF86_SVGA，可能可行也可能不可行。这取决于 X-Server 和图形板卡。

X-Server 必须正确恢复视频模式，否则你最终会得到一个损坏的控制台（而 vesafb 对此无能为力）。


## 刷新率


启动 Linux 之后，无法更改 vesafb 的视频模式和/或时序。如果你对 60 Hz 的刷新率不满意，你有以下选项：

 - 配置并加载该图形板卡的 DOS 工具（如果可用），并用 loadlin 启动 Linux。
 - 如果可用，改用原生驱动（matroxfb/atyfb）而非 vesafb。如果没有可用的，那就写一个！
 - VBE 3.0 也许也能用。我既没有支持 VBE 3.0 的图形板卡，也没有相关规格，因此尚未验证这一点。


## 配置


VESA BIOS 提供了用于更改某些参数的保护模式接口。vesafb 可以将其用于调色板更改和显示平移（pan）。默认它是关闭的，因为它似乎在某些 BIOS 版本上不能工作，但也有打开它的选项。

你可以在内核命令行上通过“video=vesafb:option”向 vesafb 传递选项。多个选项之间应以逗号分隔，例如：“video=vesafb:ypan,inverse”

接受的选项：

inverse	使用反色映射

========= ======================================================================
ypan	  使用 VESA 保护模式接口启用显示平移。
          可见屏幕只是显存中的一个窗口，控制台滚动是通过改变窗口起点来完成的。

          pro：

                - 滚动（全屏）很快，因为无需复制数据。

          kontra：

  - 只滚动屏幕的一部分会导致一些
		  难看的闪烁效果（例如启动 logo 会闪烁）。

ywrap	  与 ypan 相同，但假设你的图形板卡可以环绕
          显存（即到达显存末尾时从顶部重新开始读取）。比 ypan 更快。

redraw	  通过重绘屏幕受影响的部分来滚动，这是安全（且较慢）的默认值。


vgapal	  使用标准 vga 寄存器进行调色板更改。
          这是默认值。
pmipal    使用保护模式接口进行调色板更改。

mtrr:n	  为 vesafb 帧缓冲设置内存类型范围寄存器，其中 n：

              - 0 - 禁用（等同于 nomtrr）（默认）
              - 1 - 不可缓存（uncachable）
              - 2 - 写回（write-back）
              - 3 - 写合并（write-combining）
              - 4 - 写穿透（write-through）

          如果你在 dmesg 中看到以下内容，请选择与上一项匹配的类型。在此例中，使用“mtrr:2”。
...
mtrr:     type mismatch for e0000000,8000000 old: write-back new:
	  write-combining
...

nomtrr    禁用 mtrr

vremap:n
          重映射 'n' MiB 显存。如果为 0 或未指定，则根据视频模式重映射内存。（2.5.66 补丁/想法来自 Antonino Daplas，
          由 tmb@iki.fi 反向移植到 2.4，以提供覆盖可能性（分配比内核更多的 fb 内存））

vtotal:n  如果你的显卡视频 BIOS 不正确地判断了显存总量，使用此选项覆盖 BIOS（单位为 MiB）。
