## 芯片勘误与软件规避方案

下表按实现厂商与勘误编号逐条登记各 ARM64 硅片勘误及其内核规避方案，并说明其触发条件、危害类别与运行时生效方式。建议配合 Kconfig 选项名在内核源码中检索对应的 alternatives 框架补丁实现，便于平台维护者快速判断某条勘误是否已在主线与稳定内核中得到修复。



Author: Will Deacon <will.deacon@arm.com>

Date  : 27 November 2015

硬件生产时常带有所谓的"勘误（errata）"，这是一个无可奈何的事实，在特定情况下可能导致其偏离架构规范。对于 ARM 生产的硬件，这些勘误大致分为以下几类：

  ==========  ========================================================
  Category A  无可行规避方案的关键错误。
  Category B  重大或关键错误，但存在可接受的规避方案。
  Category C  轻微错误，正常情况下预期不会发生。
  ==========  ========================================================

如需更多信息，请查阅 infocenter.arm.com 上提供的"软件开发人员勘误通知（软件 Developers Errata Notice）"文档之一（需要注册）。

就 Linux 而言，B 类勘误可能需要在操作系统中做特殊处理。例如，避免特定的代码序列，或以特定方式配置处理器。较不常见的情况是，可能需要采取类似措施，以将 一个 类勘误降级为 C 类勘误。这些统称为"软件规避方案（软件 workarounds）"，仅在少数情况下需要（例如那些既需要非安全规避方案 **且** 可由 Linux 触发的情况）。

对于那些可能对未受相关勘误影响的系统造成不利影响的软件规避方案，会在"内核功能（内核 特性）"->"通过 alternatives 框架实现的 ARM 勘误规避方案（ARM errata workarounds 通过 the alternatives framework）"下添加一个 Kconfig 选项。除被 Arm 视为"罕见（rare）"的勘误规避方案外，这些选项默认启用，并在检测到受影响的 CPU 时于运行时打补丁。对于侵入性较低的规避方案，不提供 Kconfig 选项，而是通过代码结构（最好附注释）来确保不会触发该勘误。

这种方法使得在任意内核源码树中准确判断哪些勘误已被规避变得略微繁琐，因此本文件作为 Linux 内核中软件规避方案的登记表，将在新的规避方案被提交并回移植到稳定内核时更新。
