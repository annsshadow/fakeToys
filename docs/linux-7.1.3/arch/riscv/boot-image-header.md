## RISC-V Linux 中的引导镜像头（Boot image header

:Author: Atish Patra <atish.patra@wdc.com>
:Date:   20 May 2019

本文档只描述 RISC-V Linux 的引导镜像头细节
```

	u32 code0;		  /* 可执行代*/
	u32 code1;		  /* 可执行代*/
	u64 text_offset;	  /* 镜像加载偏移，小*/
	u64 image_size;		  /* 有效镜像大小，小*/
	u64 flags;		  /* 内核标志，小*/
	u32 version;		  /* 本头部版*/
	u32 res1 = 0;		  /* 保留 */
	u64 res2 = 0;		  /* 保留 */
	u64 magic = 0x5643534952; /* 魔数，小端，"RISCV" */
	u32 magic2 = 0x05435352;  /* 魔数 2，小端，"RSC\x05" */
	u32 res3;		  /* PE COFF 偏移保留 */

```
该头部格式兼PE/COFF 头，并在很大程度上受 ARM64 头启发。因此，未来 ARM64 RISC-V 头可以合并为一个通用头
## 备注


- 该头部也被复用以支持 RISC-V EFI stub。EFI 规范需PE/COFF 镜像头位于内核镜像开头，以便将其作为 EFI 应用程序加载。为支持 EFI stub，code0 被替换为 "MZ" 魔数字符串，res3（位于偏0x3c）指向其余的 PE/COFF 头
- version 字段指示头部版本
	==========  =============
	Bits 0:15   次版本号
	Bits 16:31  主版本号
	==========  =============

  这保持了头部新旧版本之间的兼容性。当前版本定义为 0.2
- "magic" 字段自版0.2 起已废弃。在未来的版本中可能会被移除。它原本应与 ARM64 头的 "magic" 字段一致，但不幸未能做到magic2" 字段取代它，ARM64 头一致
- 在当前头部中，flags 字段只有一个位域
	=====  ====================================
	Bit 0  内核字节序 表示大端（BE），0 表示小端（LE）	=====  ====================================

- 镜像大小对于引导加载程序加载内核镜像是必需的。否则引导将失败
