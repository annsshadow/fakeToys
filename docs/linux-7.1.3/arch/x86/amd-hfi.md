### 概述


AMD 的异构核心实现由不止一种体系结构类别组成，CPU 由具有不同能效与功耗能力的核心
构成：面向性能*经典核心（classic cores*和节能的**密集核心（dense cores*因此，电源管理策略必须被设计成能适应引入不同核心类型所带来的复杂性。异构系统也可以
扩展到两个以上的体系结构类别。调度反馈机制的目的是实时向操作系统调度器提供信息，调度器能够将线程导向最优的核心
AMD 异构架构的目标是通过将后台线程发送到密集核心、同时将高优先级线程发送到经典核心
来获得功耗收益。从性能角度看，将后台线程发送到密集核心可以释放出功耗余量，并让经典
核心以最优方式服务于 demanding 线程。此外，密集核心在面积上的优化特性允许增加物核心的数量。这种更高的核心密度将对多线程性能产生积极影响
### AMD 异构核心驱动


`amd_hfi` 驱动向操作系统提供系统中每个 CPU 的性能和能效能力数据。调度器可以使用来自
HFI 驱动的排序数据来做出任务放置决策
### 线程分类与排序表交互


线程分类用于选择一个排序表，该表描述每个分类的效率和性能排序
线程在运行时被分类为枚举出的类别。这些类别代表了可能受益于特殊调度行为的线程性能/功特征。下表描绘了一个线程分类以及给定线程应基于其线程类别被调度到的偏好的示例。实线程分类被操作系统消费，并用于告知调度器该线程应被放置在哪里
##### 线程分类示例
+----------+----------------+-------------------------------+---------------------+---------+
| class ID | Classification | Preferred scheduling behavior | Preemption priority | Counter |
+----------+----------------+-------------------------------+---------------------+---------+
| 0        | 默认           | 高性能                        | 最               |         |
+----------+----------------+-------------------------------+---------------------+---------+
| 1        | 不可扩展       | 高效                          | 最               | PMCx1A1 |
+----------+----------------+-------------------------------+---------------------+---------+
| 2        | I/O 密集    | 高效                          | 最               | PMCx044 |
+----------+----------------+-------------------------------+---------------------+---------+

线程分类在每次线程被换出（switch out）时由硬件执行。不满足任何硬件指定标准的线程被分类“默认”
### AMD 硬件反馈接口


硬件反馈接口向操作系统提供关于系统中每个 CPU 的性能和能效的信息。每种能力以 [0-255]
范围内的无量纲量给出。更高的性能值表示更高的性能能力，更高的效率值表示更高的效率。能和性能在基于共享内存的排序表中以独立的能力报告
这些能力可能在运行时由于系统运行条件的变化或外部因素的作用而改变。电源管理固件负检测需要重新排序性能和效率排序的事件。表的更新发生得相对不频繁，时间尺度为秒或更长
以下事件会触发一次表更新    - 热应力事件（Thermal Stress Events    - 静默计算（Silent Compute    - 极低电量场景（Extreme Low Battery Scenarios
内核或用户空间策略守护进程可以使用这些能力来修改任务放置决策。例如，如果某个逻辑处理器的
性能或能效能力变为零，则分别表明硬件建议操作系统出于性能或能效原因不要在该处理器上调任何任务
### Linux 的实现细

线程调度的实现包含以下步骤：

1. 一个线程被生成，并使用默认的异构调度策略被调度到理想的核心2. 处理器分析线程执行并分配一个枚举出的分ID。该分类通过逻辑处理器作用域MSR 传达
   给操作系统3. 在线程上下文换出期间，操作系统消费驻留在逻辑处理器作用域 MSR 中的工作负载（WL）分类4. 操作系统在消WL 分类之后、换入新线程之前，通过写入一MSR 触发硬件清除其历史5. 如果由于分类、排序表和处理器可用性，线程不在其理想处理器上，操作系统将考虑在其理想
   处理器（如果可用）上调度该线程
### 排序

排序表是一个共享内存区域，用于传达系统中每CPU 的性能和能效能力
排序表设计包含系统中每个 APIC ID 的排序，以及每个工作负载分类的性能和效率排序
   :doc: amd_shmem_info

### 排序表更

电源管理固件在更新排序表后发出一个平台中断，并准备好让操作系统消费它。CPU 收到此类
中断后，PCCT 表所提供的共享内存中读取新的排序表，然后 `amd_hfi` 驱动解析新表，以
提供用于调度决策的新的消费数据
