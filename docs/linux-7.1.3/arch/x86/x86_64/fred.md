
## 灵活返回与事件投递（Flexible Return and Event Delivery，FRED）


## 概述


FRED 架构定义了改变特权级（ring 转换）的简单新转换。FRED 架构设计有以下目标：

1) 通过用更低延迟的转换取代通过中断描述符表（IDT 事件投递）进行事件投递以及用 IRET 指令进行事件返回，从而改善整体性能和响应时间。

2) 通过确保事件投递建立完整的 supervisor 上下文、事件返回建立完整的用户上下文，从而提高软件健壮性。

FRED 架构定义的新的转换是 FRED 事件投递，以及用于从事件返回的两条 FRED 返回指令。FRED 事件投递可以实现从 ring 3 到 ring 0 的转换，但它也用于投递与 ring 0 相关的事件。一条 FRED 指令（ERETU）实现从 ring 0 到 ring 3 的返回，而另一条（ERETS）在仍处于 ring 0 时返回。总体上，FRED 事件投递和 FRED 返回指令就是 FRED 转换。

除了这些转换外，FRED 架构还定义了一条用于管理 GS 段寄存器状态的新指令（LKGS）。不使用新的 FRED 转换的 64 位操作系统也可以使用 LKGS 指令。

此外，FRED 架构易于为未来的 CPU 架构扩展。

## 基于软件的事件分发


FRED 在事件处理方面与 IDT 不同。FRED 不是基于事件向量直接将事件分发到其处理程序，而是要求软件基于事件的类型和向量将事件分发到其处理程序。因此，必须实现一个事件分发框架以促进事件到处理程序的分发过程。一旦事件被投递，FRED 事件分发框架就接管控制，并采用两级分发。

第一级分发基于事件类型，第二级分发基于事件向量。

## 完整的 supervisor/用户上下文


FRED 事件投递在事件投递和返回时原子地保存和恢复完整的 supervisor/用户上下文。因此，它避免了由于 %cr2 和/或 %dr6 导致的瞬态状态问题，也不再需要处理由半成品进入状态引起的所有棘手边界情况。

FRED 允许用新的事件返回指令 ERETS/ERETU 显式解除 NMI 阻塞，避免了由 IRET 无条件解除 NMI 阻塞所引起的混乱，例如在 NMI 处理期间发生异常时。

FRED 总是恢复 %rsp 的完整值，因此在启用 FRED 时不再需要 ESPFIX。

## LKGS


LKGS 的行为类似于 MOV to GS 指令，不同之处在于它将基址加载到 IA32_KERNEL_GS_BASE MSR 中，而非 GS 段的描述符缓存。借助 LKGS，可以避免弄乱内核 GS，即操作系统始终可以使用它自己的 GS 基址。

由于来自 ring 3 的 FRED 事件投递和 ERETU 都会交换 GS 基址与 IA32_KERNEL_GS_BASE MSR 的值，再加上 LKGS 指令的引入，在启用 FRED 时不再需要 SWAPGS 指令，因此被禁止（#UD）。

## 栈级别


引入了 4 个栈级别 0~3 来取代用于事件处理的不可重入 IST，每个栈级别应配置为使用专用的栈。

FRED 事件投递时，当前栈级别可以保持不变或升高。如果不变，CPU 继续使用当前事件栈。如果升高，CPU 切换到由新栈级别的 MSR 指定的新事件栈，即 MSR_IA32_FRED_RSP[^123^]。

只有执行 FRED 返回指令 ERET[US] 才能降低当前栈级别，使 CPU 切换回在之前提升栈级别的某次事件投递之前所在的栈。
