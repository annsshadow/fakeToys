## Intel 硬件上的调度用硬件反馈接

### 概述


Intel Intel 64 IA-32 架构软件开发人员手册（Intel SDM）第 3 14.6 [^1^]_ 中描述了硬件反馈接口（HFI）
HFI 向操作系统提供系统中每个 CPU 的性能和能效能力数据。Linux 可利用来HFI 的信息来影响任务放置决策
### 硬件反馈接口


硬件反馈接口向操作系统提供系统中每个 CPU 的性能和能效信息。每种能力以
[0-255] 范围内的无量纲量给出。数值越高表示能力越强。能效与性能以独立的
能力分别报告。尽管在某些系统上这两个指标可能相关，但Intel SDM 中它被规定为独立的能力
这些能力可能因系统运行条件的变化或外部因素的作用而在运行时改变。这些能的更新速率因处理器型号而异。在某些型号上，能力在启动时设定且永不改变。在
其他型号上，能力可能每几十毫秒改变一次。例如，可能使用某种远程机制来降热设计功耗（TDP）。这种变化会反映HFI 中。同样，如果系统因过热而需节流，HFI 可能会反映特CPU 上性能的下降
内核或用户态策略守护进程可以利用这些能力来修改任务放置决策。例如，若某逻辑处理器的性能能力或能效能力变为零，则表明硬件建议操作系统出于性能能效原因不要在该处理器上调度任何任务
### Linux 实现细节


处理热事件中断的基础设施由两部分组成。在 CPU 本地 APIC 的本地向量表中，
存在一个用于热监视寄存器的寄存器。该寄存器控制当热监视器产生中断时如将中断投递到 CPU。更多细节见 Intel SDM 3 卷第 10.5 [^1^]_
热监视器可针对每CPU 或每个封装产生中断。HFI 产生封装级中断。该监视通过一组机器特定的寄存器进行配置和初始化。具体地，HFI 中断和状态分别通过
IA32_PACKAGE_THERM_INTERRUPT IA32_PACKAGE_THERM_STATUS 寄存器中指定位进行控制。每个封装存在一HFI 表。更多细节见 Intel SDM 3 14.9 [^1^]_
硬件在更HFI 表并准备好供操作系统消费后发HFI 中断。CPU 通过本地
APIC 本地向量表中的热条目接收此类中断
在为此类中断提供服务时，HFI 驱动解析更新后的表，并通过热通知框架将更转发给用户态。由于每秒可能有许多 HFI 更新，转发给用户态的更新CONFIG_HZ
jiffies 的速率进行节流
