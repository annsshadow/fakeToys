## IBM 3270 显示系统支持


本文档描述了支持 IBM 3270 设备本地通道连接的驱动程序。它由三个部分组成：

 - 简介
 - 安装
 - 操作


## 简介


本文描述了在 Linux/390 下安装和操作 3270 设备。3270 设备是一种块模式的行列
终端，我相信 IBM 及其兼容厂商在二三十年前售出了数亿台。

您可能在内部就有 3270 却浑然不知。如果您正在使用 VM-ESA 操作系统，可以使用
"DEF GRAF <hex-address>" 命令为您的虚拟机定义一个 3270。本文假定您将使用
CP/CMS 命令定义四个 3270：

 - DEF GRAF 620
 - DEF GRAF 621
 - DEF GRAF 622
 - DEF GRAF 623

您从 VM-ESA 的网络连接允许您使用 x3270、tn3270 或其他 3270 模拟器，
这些模拟器可从您 PC 或工作站上的 xterm 窗口启动。借助 DEF GRAF 命令、
诸如 xterm 这样的应用，以及本 Linux-390 3270 驱动程序，您就拥有了另一种
与 Linux 主机交谈的方式。

本文涵盖了该驱动程序的安装以及一个拨号接入的 x3270 的操作。


## 安装


您可以通过安装一个补丁、进行内核构建并运行配置脚本（config3270.sh，位于
本目录下）来安装该驱动程序。

警告：如果您正在使用 3270 控制台支持，则每次更改控制台地址时（可能是通过在
silo 的 /boot/parmfile 中使用 condev= 参数），都必须重新运行配置脚本。更确切地说，
每当您的 3270 集合（包括控制台 3270）彼此之间的子通道标识符发生变化时，
都应该重新运行配置脚本。在运行配置脚本及其生成的 /tmp/mkdev3270 后，
应尽快进行 ReIPL。

如果您选择将 tub3270 编译为模块，则需要向 `/etc/modprobe.d/` 下的某个
配置文件添加一行。如果您在 VM 虚拟机上工作，可以使用 DEF GRAF 定义
虚拟 3270 设备。

您可以同时生成 3270 和 3215 控制台支持，或二者之一，或都不生成。如果两者都生成，
VM 下的控制台类型不会改变。使用 #CP Q TERM 查看当前的控制台类型。使用
#CP TERM CONMODE 3270 将其改为 3270。如果只生成 3270 控制台支持，则当控制台是
3215 时，驱动程序会在启动时自动将其转换为 3270。

简言之，步骤如下：

 1. 安装 tub3270 补丁
 2. （若为模块）向 `/etc/modprobe.d/*.conf` 中的某个文件添加一行
 3. （若为 VM）使用 DEF GRAF 定义设备
 4. 重启
 5. 配置

要测试一切是否正常工作（假设使用 VM 和 x3270）：

 1. 打开一个 x3270 窗口。
 2. 在该窗口中使用 DIAL 命令。
 3. 您应该立即看到 Linux 登录界面。

以下是详细的安装步骤：

 1. 3270 驱动程序是官方 Linux 内核源代码的一部分。
	使用内核源代码及任何必要的
```

		make oldconfig
		(If you wish to disable 3215 console support, edit
		.config; change CONFIG_TN3215's value to "n";
		and rerun "make oldconfig".)
		make image
		make modules
		make modules_install

	2. (Perform this step only if you have configured tub3270 as a
	module.)  Add a line to a file `/etc/modprobe.d/*.conf` to automatically
	load the driver when it's needed.  With this line added, you will see
	login prompts appear on your 3270s as soon as boot is complete (or
	with emulated 3270s, as soon as you dial into your vm guest using the
	command "DIAL <vmguestname>").  Since the line-mode major number is
	227, the line to add should be::

		alias char-major-227 tub3270

	3. Define graphic devices to your vm guest machine, if you
	haven't already.  Define them before you reboot (reipl):

		- DEFINE GRAF 620
		- DEFINE GRAF 621
		- DEFINE GRAF 622
		- DEFINE GRAF 623

	4. Reboot.  The reboot process scans hardware devices, including
	3270s, and this enables the tub3270 driver once loaded to respond
	correctly to the configuration requests of the next step.  If
	you have chosen 3270 console support, your console now behaves
	as a 3270, not a 3215.

	5. Run the 3270 configuration script config3270.  It is
	distributed in this same directory, Documentation/arch/s390, as
	config3270.sh.  Inspect the output script it produces,
	/tmp/mkdev3270, and then run that script.  This will create the
	necessary character special device files and make the necessary
	changes to /etc/inittab.

	Then notify /sbin/init that /etc/inittab has changed, by issuing
	the telinit command with the q operand::

		cd Documentation/arch/s390
		sh config3270.sh
		sh /tmp/mkdev3270
		telinit q

	This should be sufficient for your first time.  If your 3270
	configuration has changed and you're reusing config3270, you
	should follow these steps::

		Change 3270 configuration
		Reboot
		Run config3270 and /tmp/mkdev3270
		Reboot

```
以下是详细的测试步骤：

 1. 打开一个 x3270 窗口，或使用实际的硬件 3278 或
	3279，或使用您选择的 3270 模拟器。您可以在
	PC 或工作站上运行该模拟器。您可以使用
```

		x3270 vm-esa-domain-name &

	if you wanted a 3278 Model 4 with 43 rows of 80 columns, the
	default model number.  The driver does not take advantage of
	extended attributes.

	The screen you should now see contains a VM logo with input
	lines near the bottom.  Use TAB to move to the bottom line,
	probably labeled "COMMAND  ===>".

	2. Use the DIAL command instead of the LOGIN command to connect
	to one of the virtual 3270s you defined with the DEF GRAF
	commands::

		dial my-vm-guest-name

	3. You should immediately see a login prompt from your
	Linux-390 operating system.  If that does not happen, you would
	see instead the line "DIALED TO my-vm-guest-name   0620".

	To troubleshoot:  do these things.

	A. Is the driver loaded?  Use the lsmod command (no operands)
	to find out.  Probably it isn't.  Try loading it manually, with
	the command "insmod tub3270".  Does that command give error
	messages?  Ha!  There's your problem.

	B. Is the /etc/inittab file modified as in installation step 3
	above?  Use the grep command to find out; for instance, issue
	"grep 3270 /etc/inittab".  Nothing found?  There's your
	problem!

	C. Are the device special files created, as in installation
	step 2 above?  Use the ls -l command to find out; for instance,
	issue "ls -l /dev/3270/tty620".  The output should start with the
	letter "c" meaning character device and should contain "227, 1"
	just to the left of the device name.  No such file?  no "c"?
	Wrong major number?  Wrong minor number?  There's your
	problem!

	D. Do you get the message::

		 "HCPDIA047E my-vm-guest-name 0620 does not exist"?

	If so, you must issue the command "DEF GRAF 620" from your VM
	3215 console and then reboot the system.



```
## 操作。


驱动程序在 3270 屏幕上定义了三个区域：日志区、输入区和状态区。

日志区占据了除屏幕底部两行以外的所有区域。驱动程序将终端输出写入该区域，
从最顶部一行开始向下写。当它填满时，状态区从 "Linux Running" 变为
"Linux More..."。经过（默认）5 秒的滚动超时后，屏幕被清除，更多输出
从顶部向下写入。

输入区从屏幕倒数第二行的开头延伸到状态区的起始位置。您在该区域输入命令
并按 ENTER 执行它们。

状态区初始化为 "Linux Running"，给您一种温暖安心的感觉。当日志区填满且
有输出等待时，它变为 "Linux More..."。此时您可以做几件事，也可以什么都不做。
如果什么都不做，屏幕将在（默认）5 秒后清除，并显示更多输出。您可以在
输入区不输入任何内容的情况下按 ENTER，在 "Linux More..." 和 "Linux Holding"
之间切换，后者表示不会发生滚动。（如果您在 "Linux Running" 且未输入任何内容时
按 ENTER，应用程序会收到一个换行符。）

您可以更改滚动超时值。例如，以下
```

	echo scrolltime=60 > /proc/tty/driver/tty3270

```
将滚动超时值更改为 60 秒。如果您希望完全禁止滚动，请将 scrolltime 设为 0。

当日志区填满时，您还可以执行其他操作：按 PA2 清除日志区并向其中写入更多
输出，或按 CLEAR 清除日志区和输入区，并将更多输出写入日志区。

部分 Program Function (PF) 和 Program Attention (PA) 键被预分配了特殊功能。
未被分配功能的键在被按下时会发出警报。

PA1 会向当前运行的应用程序发送 SIGINT。您也可以在输入区通过键入 "^C" 并
按 ENTER 来完成同样的事情。

PA2 会清除日志区。如果有输出等待，则随后将其写入日志区。

PF3 会使应用程序收到一个 EOF 作为输入。您也可以通过键入 "^D" 并按 ENTER
来产生 EOF。

没有 PF 键被预分配用于导致作业挂起，但您可以通过键入 "^Z" 并按 ENTER 来
导致作业挂起。您可能希望将此功能分配给某个 PF 键。要使 PF7 导致作业挂起，
```

	echo pf7=^z > /proc/tty/driver/tty3270

```
如果您输入的文本不以两个字符 "^n" 结尾，驱动程序会附加一个换行符并将其
发送给 tty 驱动程序；否则驱动程序会去掉 "^n" 而不附加换行符。
IBM 3215 驱动程序的行为类似。

Pf10 会从该终端的命令栈（默认深度 20）中取出最近一条命令并显示在输入区。
您可以再次按 PF10 获取更早的一条命令，依此类推。一条命令只有在输入区
未被设为不可见（例如输入密码时）且与当前栈顶条目不同时，才会被压入栈中。
PF10 在命令栈中向后轮转；PF11 向前轮转。您可以将向后功能分配给任何 PF
```

	echo -e pa3=\\033k > /proc/tty/driver/tty3270

```
这将字符串 ESC-k 分配给 PA3。类似地，字符串 ESC-j 执行向前功能。
（理由：在 bash 的 vi 模式命令行编辑中，ESC-k 和 ESC-j 分别检索历史中
的前一条和后一条。欢迎提出建议。）

二十条命令的栈大小不合您的意？您可以随时更改它。要改为保存最近 100 条命令，
请执行
```

	echo recallsize=100 > /proc/tty/driver/tty3270

```
有一条您经常执行的命令？将它分配给某个 PF 或 PA 键！请使用
```

	echo pf24="mkdir foobar; cd foobar" > /proc/tty/driver/tty3270

```
以在您按下 PF24 时立即执行命令 mkdir foobar 和 cd foobar。想在执行前
先看看命令行吗？
```

	echo -n pf24="mkdir foo; cd foo" > /proc/tty/driver/tty3270



```
