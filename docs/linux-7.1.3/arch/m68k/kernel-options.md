## Linux/m68k 的命令行选项


Last Update: 2 May 1999

Linux/m68k version: 2.2.6

Author: Roman.Hodek@informatik.uni-erlangen.de (Roman Hodek)

Update: jds@kom.auc.dk (Jes Sorensen) and faq@linux-m68k.org (Chris Lawrence)

## 0) 简介


经常会有人问我，Linux/m68k 内核能够理解哪些命令行选项，或者某个选项的准确语法是
什么，又或者关于某个选项的一些问题。我希望本文档能解答所有这些疑问……

请注意，部分选项可能已过时，其描述可能不完整或缺失。请更新这些信息并提交补丁。

## 1) 内核选项处理概述


内核在其命令行上支持三类选项：

  1) 内核选项
  2) 环境变量设置
  3) 传给 init 的参数

一个参数属于哪一类，按如下规则判定：如果该选项内核本身已知（即名字，也就是 '='
之前的部分，或者在某些情况下整个参数字符串，对内核来说是已知的），那么它属于第 1
类。否则，如果该参数包含 '='，则属于第 2 类，该定义会被放入 init 的环境变量中。
所有其余参数都作为命令行选项传递给 init。

本文档描述了文首所述版本中 Linux/m68k 所支持的有效内核选项。后续修订版可能会新增
此类选项，而较早的版本中可能缺失部分选项。

一般而言，一个选项的取值（'=' 之后的部分）是一个以逗号分隔的值列表。这些取值的
具体含义由“拥有”该选项的驱动来解释。这种选项与驱动之间的关联，也是部分选项被
进一步细分的原因。

## 2) 通用内核选项


### 2.1) root=


:Syntax: root=/dev/<device>
:or:     root=<hex_number>

该选项告诉内核应将哪个设备挂载为根文件系统。该设备必须是一个带有有效文件系统的
块设备。

第一种语法按名称给出设备。这些名称会在内核内部以一种特殊的方式被转换为主/次设备
号。通常，这种“转换”是由 /dev 中的设备文件完成的，但这里无法这样做，因为根文件系统
（包含 /dev）尚未挂载……因此内核会自行解析名称，并借助一些硬编码的名称到编号的
映射。名称必须始终由两个或三个字母组成，后跟一个十进制数字。

```
  /dev/ram: -> 0x0100 (initial ramdisk)
  /dev/hda: -> 0x0300 (first IDE disk)
  /dev/hdb: -> 0x0340 (second IDE disk)
  /dev/sda: -> 0x0800 (first SCSI disk)
  /dev/sdb: -> 0x0810 (second SCSI disk)
  /dev/sdc: -> 0x0820 (third SCSI disk)
  /dev/sdd: -> 0x0830 (forth SCSI disk)
  /dev/sde: -> 0x0840 (fifth SCSI disk)
  /dev/fd : -> 0x0200 (floppy disk)

```

名称之后必须跟一个十进制数字，代表分区号。在内核内部，该数字的值只是简单地加到上
表中提到的设备号上。例外情况是 /dev/ram 和 /dev/fd：其中 /dev/ram 指代由引导程序
加载的初始内存盘（initial ramdisk）（要了解如何加载初始内存盘，请参阅你的引导程序
的说明）。从内核版本 2.0.18 起，若想从初始内存盘启动，必须将 /dev/ram 指定为根
设备。对于软盘设备 /dev/fd，该数字代表软盘驱动器编号（软盘上没有分区）。也就是说，
/dev/fd0 代表第一个驱动器，/dev/fd1 代表第二个，依此类推。由于该数字只是简单相加，
你也可以通过加上一个大于 3 的数字来强制指定磁盘格式。如果你查看自己的 /dev 目录，
会看到 /dev/fd0D720 的主设备号为 2、次设备号为 16。你可以在内核命令行上写
"root=/dev/fd16" 来将这个设备指定为根文件系统。

[Strange and maybe uninteresting stuff ON]

这种对设备名的特殊转换会带来一些奇怪的后果：例如，如果你建立了一个从 /dev/fd 到
/dev/fd0D720 的符号链接，作为软盘驱动器 #0 的 DD 格式缩写，你就不能将这个名称用于
指定根设备，因为内核在挂载根文件系统之前看不到这个符号链接，而且它也不在上面的表中。
如果你使用了它，根设备根本不会被设置，也不会给出任何错误信息。另一个例子：如果你想
按名称指定，就不能使用例如第六个 SCSI 磁盘上的分区作为根文件系统。这是因为上表中
只到 /dev/sde，而没有 /dev/sdf。不过，你仍然可以使用第六个 SCSI 磁盘作为根文件系统，
只是必须按编号来指定设备……（见下文）。更有甚者，你可以利用分区号没有范围检查这一
事实，结合“每块磁盘占用 16 个次设备号”这一知识，写出 "root=/dev/sde17"（即
/dev/sdf1）。

[Strange and maybe uninteresting stuff OFF]

如果你的根分区所在设备不在上表中，你也可以按主/次设备号来指定。它们以十六进制书写，
前缀和分隔符都省略。例如，如果你的第一台 SCSI 光驱中有一张内容适合作为根文件系统的
光盘，你可以通过 "root=0b00" 从中启动。这里，十六进制的 "0b"（十进制 11）是 SCSI
光驱的主设备号，次设备号 0 代表其中的第一个。你可以查看 include/linux/major.h 来
找到所有有效的主设备号。

除了主/次设备号之外，如果你的根分区所在的设备使用了带有唯一分区标识的分区表格式，
那么你也可以使用它们。例如，"root=PARTUUID=00112233-4455-6677-8899-AABBCCDDEEFF"。
也可以以某个已知的分区 UUID 为起点来引用同一设备上的另一个分区。例如，如果该设备的
第 5 个分区的 UUID 为 00112233-4455-6677-8899-AABBCCDDEEFF，那么第 3 个分区可按如下
方式找到：

  PARTUUID=00112233-4455-6677-8899-AABBCCDDEEFF/PARTNROFF=-2

权威信息可以在 "Documentation/admin-guide/kernel-parameters.rst" 中找到。

### 2.2) ro, rw


:Syntax: ro
:or:     rw

这两个选项告诉内核应以只读还是读写方式挂载根文件系统。默认是只读，软盘内存盘
（ramdisk）除外，后者默认为读写。

### 2.3) debug


:Syntax: debug

该选项将内核日志级别提升到 10（默认是 7）。这与 "dmesg" 命令设置的级别相同，只不过
dmesg 可选择的最大级别是 8。

### 2.4) debug=


:Syntax: debug=<device>

该选项会使某些内核消息被打印到所选的调试设备上。这有助于调试内核，因为这些消息可以
被捕获并在其他机器上分析。可选用的设备取决于机器类型。不会对设备名的有效性做任何
检查；如果该设备未实现，则什么也不会发生。

通过这种方式记录的消息通常是内核内存故障或错误的内核陷阱之后的栈转储，以及内核
崩溃（panic）。准确地说：所有级别为 0（崩溃消息）的消息，以及所有在日志级别为 8 或
更高时打印的消息（其级别无关紧要）。在进行栈转储之前，内核会自动将日志级别设为 10。
也可以通过 "debug" 命令行选项（见 2.3）以及运行时使用 "dmesg -n 8" 将级别设为至少 8。

Amiga 可用的设备：

 - "ser"：
	  内置串口；参数：9600bps，8N1
 - "mem"：
	  将消息保存到芯片内存（chip mem）中的保留区域。重启后，可在 AmigaOS 下用
          'dmesg' 工具读取。

Atari 可用的设备：

 - "ser1"：
	   ST-MFP 串口（"Modem1"）；参数：9600bps，8N1
 - "ser2"：
	   SCC 通道 B 串口（"Modem2"）；参数：9600bps，8N1
 - "ser" ：
	   默认串口
           对于 Falcon 这是 "ser2"，对于其他机器则是 "ser1"
 - "midi"：
	   MIDI 端口；参数：31250bps，8N1
 - "par" ：
	   并口

           该端口的打印例程针对未连接打印机的情况实现了超时（否则内核会锁死）。超时
           并不精确，但通常是几秒。

### 2.6) ramdisk_size=


:Syntax: ramdisk_size=<size>

该选项指示内核建立一个给定大小（以 KB 为单位）的内存盘。如果内存盘的内容是由引导程序
传入的，则不要使用此选项！这种情况下，大小会自动选定，不应被覆盖。

唯一的应用场景是将软盘上的根文件系统载入内存。为此，选择与该软盘大小相应的内存盘
大小，并将根设备设为该软盘驱动器（使用 "root="）。

2.7) swap=

  我在 2.2.6 中找不到这个选项的任何迹象。

### 2.8) buff=


  我在 2.2.6 中找不到这个选项的任何迹象。

## 3) 通用设备选项（Amiga 与 Atari）


### 3.1) ether=


:Syntax: ether=[<irq>[,<base_addr>[,<mem_start>[,<mem_end>]]]],<dev-name>

<dev-name> 是网络驱动的名称，如 Linux 源码中 drivers/net/Space.c 所规定。最常见的有
eth0, … eth3、sl0, … sl3、ppp0, …, ppp3、dummy 以及 lo。

非以太网驱动（sl、ppp、dummy、lo）显然会忽略该选项所做的设置。此外，现有的
Linux/m68k 以太网驱动（ariadne、a2065、hydra）也不会使用它们，因为 Zorro 板卡是真正
的即插即用（Plug-'n-Play），因此 "ether=" 选项对于 Linux/m68k 来说整体上是无用的。

### 3.2) hd=


:Syntax: hd=<cylinders>,<heads>,<sectors>

该选项设置 IDE 磁盘的磁盘几何参数。第一个 hd= 选项用于第一块 IDE 磁盘，第二个用于
第二块。（即，你可以将该选项给出两次。）在大多数情况下，你不必使用此选项，因为内核
可以自行获取几何数据。它只在其中一块磁盘获取失败时才有用。

### 3.3) max_scsi_luns=


:Syntax: max_scsi_luns=<n>

设置要扫描的 SCSI 设备的 LUN（逻辑单元）的最大数量。<n> 的有效取值在 1 到 8 之间。
如果在内核配置时选择了“探测每个 SCSI 设备的所有 LUN”，则默认为 8，否则为 1。

### 3.4) st=


:Syntax: st=<buffer_size>,[<write_thres>,[<max_buffers>]]

设置 SCSI 磁带驱动器的若干参数。<buffer_size> 是为每个设备保留的用于磁带操作的
512 字节缓冲区的数量。<write_thres> 设置必须填满多少块才会开始真正向磁带写入。最大
值为缓冲区总数。<max_buffer> 限制为所有磁带设备分配的总缓冲区数量。

### 3.5) dmasound=


:Syntax: dmasound=[<buffers>,<buffer-size>[,<catch-radius>]]

该选项控制 Linux/m68k DMA 声音驱动（Amiga 与 Atari）的一些配置：<buffers> 是你想使用
的缓冲区数量（最少 4，默认 4），<buffer-size> 是每个缓冲区的大小（以 KB 为单位，最少
4，默认 32），<catch-radius> 表示在设定某个频率时可容忍的误差百分比（最大 10，默认
0）。例如，使用 3% 的误差，你可以在 Falcon 上以其硬件频率 8195Hz 播放 8000Hz 的
AU 文件，从而无需扩展声音。

## 4) 仅适用于 Atari 的选项


### 4.1) video=


:Syntax: video=<fbname>:<sub-options...>

<fbname> 参数指定帧缓冲（frame buffer）的名称，例如大多数 Atari 用户会希望在此指定
`atafb`。<sub-options> 是下述子选项以逗号分隔的列表。

注意：
    请注意，在 1.3.x 内核的开发过程中，该选项从 `atavideo` 更名为 `video`，因此如果
    你从 1.2.x 内核升级到 2.x，可能需要更新你的启动脚本。

又注：
    video= 的行为在 2.1.57 中发生了变化，因此推荐的选项是指定帧缓冲的名称。

### 4.1.1) 视频模式


该子选项可以是任意预定义的视频模式，如 Linux/m68k 源码树中 atari/atafb.c 所列。内核
会在启动时激活给定的视频模式，并在硬件允许的情况下将其设为默认模式。当前已定义的
名称有：

 - stlow           : 320x200x4
 - stmid, default5 : 640x200x2
 - sthigh, default4: 640x400x1
 - ttlow           : 320x480x8, 仅 TT
 - ttmid, default1 : 640x480x4, 仅 TT
 - tthigh, default2: 1280x960x1, 仅 TT
 - vga2            : 640x480x1, 仅 Falcon
 - vga4            : 640x480x2, 仅 Falcon
 - vga16, default3 : 640x480x4, 仅 Falcon
 - vga256          : 640x480x8, 仅 Falcon
 - falh2           : 896x608x1, 仅 Falcon
 - falh16          : 896x608x4, 仅 Falcon

如果命令行上没有给定视频模式，内核会依次尝试名为 "default<n>" 的模式，直到硬件能够
支持其中一个为止。

如果在外部驱动被 "external:" 子选项激活的情况下，设置视频模式就没有意义。

### 4.1.2) inverse


反转显示。这只影响文本控制台。通常背景被设为黑色。使用该选项，你可以将背景设为白色。

### 4.1.3) font


:Syntax: font:<fontname>

指定在文本模式下使用的字体。当前你只能在 `VGA8x8`、`VGA8x16` 和 `PEARL8x8` 之间选择。
如果显示的垂直尺寸小于 400 像素行，则 `VGA8x8` 为默认值；否则 `VGA8x16` 字体为默认值。

### 4.1.4) `hwscroll_`


:Syntax: `hwscroll_<n>`

为加速滚动（“硬件滚动”，hardware scrolling）而预留的额外视频内存行数。只有在内核能够
以足够精细的步长设置视频基地址时，硬件滚动才可能实现。这对于 STE、MegaSTE、TT 和
Falcon 是成立的；而对于普通 ST 和图形卡则不行（前者是因为基地址必须位于 256 字节
边界上，后者是因为内核根本不知道如何设置基地址）。

默认情况下，<n> 被设为显示上可见的文本行数。因此，与不使用硬件滚动相比，视频内存的
用量翻倍。你可以通过将 <n> 设为 0 来彻底关闭硬件滚动。

### 4.1.5) internal:


:Syntax: internal:<xres>;<yres>[;<xres_max>;<yres_max>;<offset>]

该选项指定某些扩展内部视频硬件（例如 OverScan）的能力。<xres> 和 <yres> 给出（扩展后
的）屏幕尺寸。

如果你的 OverScan 需要黑色边框，你就必须写出 "internal:" 的最后三个参数。<xres_max> 是
硬件允许的最大行长度，<yres_max> 是最大行数。<offset> 是屏幕可见部分相对于其物理起始
位置在屏幕内存中的偏移量，以字节为单位。

通常，扩展间隔视频硬件必须以某种方式被激活。为此，请参阅下面的 "sw_*" 选项。

### 4.1.6) external:


:Syntax:
  external:<xres>;<yres>;<depth>;<org>;<scrmem>[;<scrlen>[;<vgabase>
  [;<colw>[;<coltype>[;<xres_virtual>]]]]]


这可能是最复杂的参数了……它表明你拥有某些外部视频硬件（一块图形板卡），以及如何
在 Linux/m68k 下使用它。内核对该硬件的了解不会超过你在此告诉它的内容！内核也无法
设置或更改任何视频模式，因为它不知道任何板卡内部的情况。因此，你必须在启动 Linux 之前
切换到该视频模式，并且在 Linux 启动之后无法再切换到另一种模式。

该子选项的前 3 个参数含义应当很明显：<xres>、<yres> 和 <depth> 给出屏幕的尺寸以及
平面（plane）的数量（即深度，depth）。深度是可选颜色数目的以 2 为底的对数。（或者说，
反过来：颜色数目是 2^depth）。

你还必须告诉内核视频内存是如何组织的。这是通过一个作为 <org> 参数的字母来完成的：

 'n'：
      “常规平面”（normal planes），即一个完整的平面接另一个完整的平面
 'i'：
      “交错平面”（interleaved planes），即第一个平面的 16 位，然后是下一个平面的 16 位，
      依此类推……这种模式只用于内置的 Atari 视频模式，我想没有支持该模式的板卡。
 'p'：
      “紧凑像素”（packed pixels），即 <depth> 个连续位代表一个像素的所有平面；这是图形卡上
      8 个平面（256 色）最常见的模式
 't'：
      “真彩色”（true color）（大体上是紧凑像素，但没有颜色查找表）；深度通常为 24

对于单色模式（即 <depth> 为 1），<org> 字母的含义不同：

 'n'：
      常规颜色，即 0=白色，1=黑色
 'i'：
      反色，即 0=黑色，1=白色

关于视频硬件的下一个重要信息是视频内存的基地址。它由 <scrmem> 参数给出，是一个带
"0x" 前缀的十六进制数。你必须在你的硬件文档中找到这个地址。

下一个参数 <scrlen> 告诉内核视频内存的大小。如果省略，则大小由 <xres>、<yres> 和
<depth> 计算得出。目前在这里写入一个值没有用处。它只会被用于硬件滚动（这在外部驱动下
是不可能的，因为内核无法设置视频基地址），或用于 X 下的虚拟分辨率（X 服务器目前还不
支持）。因此，目前最好的做法是让该字段为空，既可以在视频地址之后结束 "external:"，也
可以写入两个连续的分号（如果你要给出 <vgabase> 的话，允许将该参数留空）。

<vgabase> 参数是可选的。如果未给出，内核就无法读或写视频硬件的任何颜色寄存器，因此你
必须在启动 Linux 之前设置好合适的颜色。但如果你的板卡在某种程度上与 VGA 兼容，你可以
告诉内核 VGA 寄存器组的基地址，这样它就能更改颜色查找表。你必须在板卡文档中查找这个
地址。为避免误解：<vgabase> 是_基地址，即一个 4K 对齐的地址。为了读/写颜色寄存器，内核
使用 vgabase+0x3c7……vgabase+0x3c9 这些地址。<vgabase> 参数与 <scrmem> 一样，以带
"0x" 前缀的十六进制书写。

<colw> 只有在指定了 <vgabase> 时才有意义。它告诉内核每个颜色寄存器有多宽，即单个颜色
（红/绿/蓝）的位数。默认是 6，另一个相当常见的值是 8。

<coltype> 同样与 <vgabase> 一起使用。它告诉内核你的显卡的颜色寄存器模型。目前实现了
"vga"（也是默认值）和 "mv300"（SANG MV300）两种类型。

参数 <xres_virtual> 对于 ProMST 或 ET4000 卡是必需的，因为它们的物理行长度与可见长度
不同。对于 ProMST，xres_virtual 必须设为 2048。对于 ET4000，xres_virtual 取决于
视频卡的初始化。如果你缺少对应的 yres_virtual：外部部分属于遗留（legacy）部分，因此
我们不支持像硬件滚动、平移或消隐这类与硬件相关的功能。

### 4.1.7) eclock:


外部连接到 Falcon VIDEL 移位器的像素时钟。目前仅适用于 ScreenWonder！

### 4.1.8) monitorcap:


:Syntax: monitorcap:<vmin>;<vmax>;<hmin>;<hmax>

这描述了多频显示器的能力。不要将其用于固定频率的显示器！目前只有 Falcon 帧缓冲使用
"monitorcap:" 的设置。

<vmin> 和 <vmax> 分别是你的显示器能够支持的垂直频率的最小值和最大值，单位为 Hz。<hmin>
和 <hmax> 对于水平频率同理，单位为 kHz。

  默认值为 58;62;31;32（VGA 兼容）。

  TV/SC1224/SC1435 的默认值同时涵盖 PAL 与 NTSC 标准。

### 4.1.9) keep


如果给出该选项，帧缓冲设备就不会自行进行任何视频模式的计算和设置。目前唯一这样做的
Atari 帧缓冲设备是 Falcon。

这样做能达到的效果是：对于未知视频扩展的设置不会被驱动覆盖，因此当驱动自身不知道如何
设置该模式时，你仍然可以使用启动时找到的模式。但这也意味着，你再也无法切换视频模式了……

一个你可能想要使用 "keep" 的例子是 Falcon 上的 ScreenBlaster。

### 4.2) atamouse=


:Syntax: atamouse=<x-threshold>,[<y-threshold>]

通过该选项，你可以设置鼠标移动上报的阈值。这是必须累积的鼠标移动像素数，达到之后 IKBD
才会向内核发送一个新的鼠标数据包。较高的值会降低鼠标中断负载，从而减少键盘溢出的
可能；较低的值则使鼠标响应稍快、跟踪稍好。

你可以分别设置 x 和 y 方向的阈值，但这通常实用价值不大。如果选项中只有一个数字，则
两个方向都使用它。两个阈值的默认值都是 2。

### 4.3) ataflop=


:Syntax: ataflop=<drive type>[,<trackbuffering>[,<steprateA>[,<steprateB>]]]

   驱动器类型可以是 0、1 或 2，分别对应 DD、HD 和 ED。该设置影响预留多少缓冲区以及探测
   哪些格式（另见下文）。默认是 1（HD）。只能选择一种驱动器类型。如果你有两台软盘驱动器，
   请选择“更好”的类型。

   第二个参数 <trackbuffer> 告诉内核是否使用磁道缓冲（1）或不使用（0）。默认取决于机器：
   Medusa 为不使用，其他所有机器为使用。

   通过下面两个参数，你可以分别更改用于 A 驱和 B 驱的默认步进速率。

### 4.4) atascsi=


:Syntax: atascsi=<can_queue>[,<cmd_per_lun>[,<scat-gat>[,<host-id>[,<tagged>]]]]

该选项设置 Atari 原生 SCSI 驱动的一些参数。一般而言，末尾的任意数量参数都可以省略。而
对于每个数字，负值都表示“使用默认值”。默认值取决于使用的是 TT 风格还是 Falcon 风格的
SCSI。下面以 n/m 的形式标注默认值，其中第一个值对应 TT-SCSI，第二个值对应 Falcon-SCSI。
如果为某个参数给出了非法值，会打印一条错误消息，并且只忽略那一项设置（其他设置不受影响）。

  <can_queue>：
    这是内部排队到 Atari SCSI 驱动的 SCSI 命令的最大数量。值为 1 实际上会关闭驱动的
    内部多任务处理（如果它引起问题的话）。合法值为 >= 1。<can_queue> 可以取得任意高，
    但大于 <cmd_per_lun> 乘以你拥有的 SCSI 目标（LUN）数量的取值没有意义。默认：16/8。

  <cmd_per_lun>：
    向驱动发出的、针对一个逻辑单元（LUN，通常是一个 SCSI 目标）的 SCSI 命令的最大数量。
    合法值从 1 开始。如果不使用标记队列（见下文），大于 2 的取值没有意义，只会浪费内存。
    否则，最大值为驱动可用的命令标签数量（目前为 32）。默认：8/1。（注意：在 Falcon 上
    取值 > 1 似乎会引起问题，原因尚不清楚。）

    <cmd_per_lun> 的取值在很大程度上决定了 SCSI 为自己预留的内存量。公式相当复杂，但我
    可以给你一些提示：

      无分散/聚集（scatter-gather）：
	cmd_per_lun * 232 字节
      完整分散/聚集：
	cmd_per_lun * 约 17 KB

  <scat-gat>：
    分散/聚集表的大小，即磁盘上可以合并为一个 SCSI 命令的连续请求数量。合法值在 0 到 255
    之间。默认：255/0。注意：在 Falcon 上该值会被强制设为 0，因为 ST-DMA 不支持分散/聚集。
    不使用分散/聚集会显著影响性能。

  <host-id>：
    发起方（你的 Atari）使用的 SCSI ID。通常是 7，即可能的最高 ID。SCSI 总线上的每个 ID
    必须唯一。默认：在运行时确定：如果 NV-RAM 校验和有效，且 NV-RAM 第 30 字节的第 7 位
    被置位，则该字节的低 3 位被用作主机 ID。（该方法由 Atari 定义，部分 TOS HD 驱动也使用
    它。）如果上述条件不满足，默认 ID 为 7（TT 和 Falcon 均为 7）。

  <tagged>：
    0 表示关闭标记队列支持，所有其他 > 0 的值表示对支持它的目标使用标记队列。默认：目前
    为关闭，但当标记队列处理被证明可靠后，这一点可能会改变。

    标记队列意味着可以向一个 LUN 发出多个命令，由 SCSI 设备自身对请求排序，从而以最优
    顺序执行。并非所有 SCSI 设备都支持标记队列（:-)。

### 4.5 switches=


:Syntax: switches=<list of switches>

通过该选项，你可以切换一些常用于启用/禁用某些硬件扩展的硬件信号线。例如 OverScan、
超频……

<list of switches> 是以下各项以逗号分隔的列表：

  ikbd：
	将键盘 ACIA 的 RTS 置高
  midi：
	将 MIDI ACIA 的 RTS 置高
  snd6：
	将 PSG 端口 A 的第 6 位置位
  snd7：
	将 PSG 端口 A 的第 7 位置位

多次提及同一个开关没有意义（与只提及一次没有区别），但你可以给出任意多个开关以启用
不同的功能。这些开关信号线会在内核初始化过程中尽可能早地被设置（甚至在确定当前硬件
之前）。

所有项也可以加上 `ov_` 前缀，即 `ov_ikbd`、`ov_midi`……这些选项用于开启 OverScan 视频
扩展。与不带前缀的选项不同，开启动作在视频初始化之后进行，并以某种方式与 HBLANK 同步。
一个特殊之处是，ov_ikbd 和 ov_midi 会在重启之前被关闭，从而使 OverScan 被禁用、TOS 能
正确启动。

如果你同时给出了带和不带 `ov_` 前缀的选项，则较早的初始化（`ov_`-less）优先。但在这种
情况下，复位时的关闭动作仍会发生。

## 5) 仅适用于 Amiga 的选项：


### 5.1) video=


:Syntax: video=<fbname>:<sub-options...>

<fbname> 参数指定帧缓冲的名称，有效的选项有 `amifb`、`cyber`、`virge`、`retz3` 和
`clgen`，前提是相应的帧缓冲设备已被编译进内核（或编译为可加载模块）。<fbname> 选项
的行为在 2.1.57 中发生了变化，因此现在建议指定该选项。

<sub-options> 是下述子选项以逗号分隔的列表。该选项的组织方式与 Atari 版本的 "video"
选项（4.1）类似，但支持的子选项更少。

### 5.1.1) 视频模式


同样类似于 Atari 的视频模式（见 4.1.1）。预定义的模式取决于所使用的帧缓冲设备。

OCS、ECS 和 AGA 机器都使用彩色帧缓冲。以下是可用的预定义视频模式：

NTSC 模式：
 - ntsc            : 640x200, 15 kHz, 60 Hz
 - ntsc-lace       : 640x400, 15 kHz, 60 Hz 隔行

PAL 模式：
 - pal             : 640x256, 15 kHz, 50 Hz
 - pal-lace        : 640x512, 15 kHz, 50 Hz 隔行

ECS 模式：
 - multiscan       : 640x480, 29 kHz, 57 Hz
 - multiscan-lace  : 640x960, 29 kHz, 57 Hz 隔行
 - euro36          : 640x200, 15 kHz, 72 Hz
 - euro36-lace     : 640x400, 15 kHz, 72 Hz 隔行
 - euro72          : 640x400, 29 kHz, 68 Hz
 - euro72-lace     : 640x800, 29 kHz, 68 Hz 隔行
 - super72         : 800x300, 23 kHz, 70 Hz
 - super72-lace    : 800x600, 23 kHz, 70 Hz 隔行
 - dblntsc-ff      : 640x400, 27 kHz, 57 Hz
 - dblntsc-lace    : 640x800, 27 kHz, 57 Hz 隔行
 - dblpal-ff       : 640x512, 27 kHz, 47 Hz
 - dblpal-lace     : 640x1024, 27 kHz, 47 Hz 隔行
 - dblntsc         : 640x200, 27 kHz, 57 Hz 双扫描
 - dblpal          : 640x256, 27 kHz, 47 Hz 双扫描

VGA 模式：
 - vga             : 640x480, 31 kHz, 60 Hz
 - vga70           : 640x400, 31 kHz, 70 Hz

请注意，ECS 和 VGA 模式需要 ECS 或 AGA 芯片组，并且这些模式在 ECS 芯片组下限制为 2 位
色，在 AGA 芯片组下限制为 8 位色。

### 5.1.2) depth


:Syntax: depth:<nr. of bit-planes>

指定所选视频模式的位平面（bit-plane）数量。

### 5.1.3) inverse


使用反转显示（白底黑字）。功能上与 Atari 的 "inverse" 子选项相同。

### 5.1.4) font


:Syntax: font:<fontname>

指定在文本模式下使用的字体。功能上与 Atari 的 "font" 子选项相同，不同之处在于：如果
显示的垂直尺寸小于 400 像素行，则使用 `PEARL8x8` 而非 `VGA8x8`。

### 5.1.5) monitorcap:


:Syntax: monitorcap:<vmin>;<vmax>;<hmin>;<hmax>

这描述了多频显示器的能力。目前只有彩色帧缓冲使用 "monitorcap:" 的设置。

<vmin> 和 <vmax> 分别是你的显示器能够支持的垂直频率的最小值和最大值，单位为 Hz。<hmin>
和 <hmax> 对于水平频率同理，单位为 kHz。

默认值为 50;90;15;38（通用 Amiga 多频显示器）。

### 5.2) fd_def_df0=


:Syntax: fd_def_df0=<value>

设置“静音”软盘驱动器的 df0 值。该值应为带 "0x" 前缀的十六进制数。

### 5.3) wd33c93=


:Syntax: wd33c93=<sub-options...>

这些选项影响 A590/A2091、A3000 以及 GVP Series II SCSI 控制器。

<sub-options> 是下述子选项以逗号分隔的列表。

### 5.3.1) nosync


:Syntax: nosync:bitmask

bitmask 是一个字节，其中前 7 位对应于 7 个可能的 SCSI 设备。将某一位置位可阻止对该设备
进行同步协商。为了保持向后兼容，诸如 "wd33c93=255" 这样的命令行会被自动翻译为
"wd33c93=nosync:0xff"。默认是禁用所有设备的同步协商，即 nosync:0xff。

### 5.3.2) period


:Syntax: period:ns

`ns` 是 SCSI 数据传输周期中最少需要的纳秒数。默认是 500；可接受的取值为 250 - 1000。

### 5.3.3) disconnect


:Syntax: disconnect:x

指定 x = 0 表示永不允许多路断开（disconnect），x = 2 表示总是允许。x = 1 表示“自适应”
断开，这是默认值，通常也是最佳选择。

### 5.3.4) debug


:Syntax: debug:x

如果定义了 `DEBUGGING_ON`，则 x 是一个位掩码，会导致打印各类调试输出——参见 wd33c93.h
中的 DB_xxx 定义。

### 5.3.5) clock


:Syntax: clock:x

x = WD33c93 芯片的时钟输入频率，单位为 MHz。正常值在 8 到 20 之间。默认值取决于你的
主机适配器（hostadapter）：A3000 内部控制器为 14，A2091 为 8，GVP 主机适配器为 8 或 14，
具体取决于主机适配器以及部分 GVP 主机适配器上存在的 SCSI 时钟跳线。

### 5.3.6) next


无参数。当系统中存在多个基于 wd33c93 的主机适配器时，用于分隔关键字块。

### 5.3.7) nodma


:Syntax: nodma:x

如果 x 为 1（或者该选项仅写作 "nodma"），则 WD33c93 控制器将不使用 DMA（= 直接内存访问）
来访问 Amiga 的内存。这对于某些在使用 DMA 访问芯片内存时存在问题的系统（如带有 A3640
加速器、版本 3.0 的 A3000 和 A4000）很有用。默认值为 0，即在可能的情况下使用 DMA。

### 5.4) gvp11=


:Syntax: gvp11=<addr-mask>

较早版本的 GVP 驱动没有正确处理 DMA 地址掩码设置，导致一些人不得不使用此选项，才能让
他们的 GVP 控制器在 Linux 下运行。这些问题有望已经解决，现在强烈不建议使用此选项！

不正确地使用可能导致不可预测的行为，因此请仅在**确知**自己在做什么并且有理由这样做时
才使用此选项。无论如何，如果你遇到问题并需要使用此选项，请通过邮件告知 Linux/68k 内核
邮件列表。

该选项设置的地址掩码指定了哪些地址对 GVP Series II SCSI 控制器进行 DMA 是有效的。如果
除了掩码中置位的位之外没有其他位被置位，则该地址是有效的。

部分版本的 GVP 只能对 24 位地址范围进行 DMA，部分可以对 25 位地址范围进行 DMA，而其他
版本可以使用整个 32 位地址范围进行 DMA。正确的设置取决于你的控制器，应由驱动自动检测。
例如，24 位区域由掩码 0x00fffffe 指定。
