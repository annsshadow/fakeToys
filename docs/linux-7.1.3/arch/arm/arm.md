## ARM Linux 2.6 及更高版本


    请访问 <ftp://ftp.arm.linux.org.uk/pub/armlinux> 获取更新。

### 内核编译


  为了编译 ARM Linux，你需要一个能够生成带 GNU 扩展的 ARM ELF 代码的
  编译器。已知 GCC 3.3 是一个不错的编译器。幸运的是，你无需猜测。如果你的
  编译器属于已知有问题的版本，内核会报告错误。

  要在本机原生构建 ARM Linux，你无需修改顶层 Makefile 中的 ARCH = 行。
  但是，如果你没有将 ARM Linux ELF 工具安装为默认工具，那么你应该按下面
  详述修改 CROSS_COMPILE 行。

  如果你想进行交叉编译，则修改顶层中的以下行
```

    ARCH = <whatever>

  改为::

    ARCH = arm

  以及::

    CROSS_COMPILE=

  改为::

    CROSS_COMPILE=<your-path-to-your-compiler-without-gcc>

  例如::

    CROSS_COMPILE=arm-linux-

  先执行 'make config'，然后执行 'make Image' 来构建内核
  （arch/arm/boot/Image）。也可以通过执行 'make zImage' 而非
  'make Image' 来构建压缩镜像。

```

  请将补丁发送到补丁系统。更多信息请参见
  http://www.arm.linux.org.uk/developer/patches/info.php
  请始终包含关于补丁做了什么以及为什么需要的说明。

  缺陷报告应发送到 linux-arm-kernel@lists.arm.linux.org.uk，或通过
  http://www.arm.linux.org.uk/developer/ 的网页表单提交。

  发送缺陷报告时，请确保其中包含全部相关信息，例如问题发生前/发生时打印的
  内核消息、你当时在做什么等。


### 头文件


  在 include/asm-arm 下创建了几个新的 include 目录，用于减少顶层目录中的
  杂乱。这些目录及其用途列于下方：

  ============= ==========================================================
   `arch-*`	机器/平台特定的头文件
   `hardware`	驱动内部的 ARM 特定数据结构/定义
   `mach`	通用 ARM 到特定机器接口的描述
   `proc-*`	处理器相关的头文件（目前仅有两类）
  ============= ==========================================================


### 机器/平台支持


  ARM 代码树包含对许多不同机器类型的支持。为了继续支持这些差异，有必要按
  目录拆分机器特定的部分。为此，机器类别被用来选择包含哪些目录和文件
  （我们将用 $(MACHINE) 指代该类别）。

  为此，我们现在有了 arch/arm/mach-$(MACHINE) 目录，用于存放特定机器的
  非驱动文件（例如 PCI、内存管理、架构定义等）。对于所有未来的机器，都应有
  一个对应的 arch/arm/mach-$(MACHINE)/include/mach 目录。


### 模块


  虽然支持模块化（并且 FP 模拟器需要它），但在 ARM2/ARM250/ARM3 机器上，
  每个模块加载时会占用到下一个 32K 边界的内存，因为页的大小如此。因此，在
  这些机器上模块化真的值得吗？

  然而，ARM6 及更高版本的机器允许模块占用 4K 的倍数，因此 Acorn RiscPC
  以及使用这些处理器的其它架构可以很好地利用模块化。


### ADFS 镜像文件


  你可以通过挂载 ADFS 分区，然后使用回环设备驱动来访问 ADFS 分区上的
  镜像文件。你必须安装 losetup。

  请注意，PCEmulator DOS 分区开头有一个分区表，因此你需要给 losetup
  加上 '-o offset'。


### 对开发者的请求


  在编写包含独立汇编文件的设备驱动时，请将其与 C 文件放在一起，而不是放在
  arch/arm/lib 目录中。这样驱动就可以作为可加载模块编译，而无需将一半代码
  编译进内核镜像。

  一般来说，尽量避免使用汇编，除非确实必要。否则会让驱动更难移植到其它
  硬件。


### ST506 硬盘


  ST506 硬盘控制器似乎工作正常（只是稍慢一点）。目前它们只能在 A4x0 主板
  上的控制器上工作，但要让它在 Podule 上工作，只需要一个有 Podule 的人把
  IRQ 掩码和 HDC 基址添加到源码中即可。

  截至 96/3/31，它可以与两个驱动器一起工作（你应该将 ADFS 的 `*configure`
  硬盘设为 2）。我有一个内置 20MB 和一个很大的外置 5.25" FH 64MB 驱动器
  （谁会需要更多呢 :-)）。

  我刚从它上面拿到 240K/s（使用 bs=128k 的 dd）；这大约是 RiscOS 的一半；
  但比我上周拿到的 50K/s 好太多了 :-)

  已知缺陷：驱动器数据错误可能导致挂起；包括在控制器已使用 ECC 修复错误的
  情况下。（可能只有在这种情况下……嗯）。

### `CONFIG_MACH_` 与 `CONFIG_ARCH_`


  2003 年对新机器的宏名称做了一次改动。历史上，`CONFIG_ARCH_` 既用于
  真正的架构（例如 SA1100），也用于架构的实现（例如 Assabet）。为了清晰起见，
  决定将实现相关的宏改为 `CONFIG_MACH_`。此外，没有做回溯修正，因为那会使
  打补丁变得复杂。

  以前的注册信息可以在线找到。

    <http://www.arm.linux.org.uk/developer/machines/>

### 内核入口（head.S）


  进入内核的初始入口经由 head.S，它使用的是与机器无关的代码。机器由入口处
  'r1' 的值选定，该值必须保持唯一。

  由于 Linux 的 ARM 移植提供了大量的机器，我们有一种方法来管理这一点，
  以确保不会最终重复大量代码。

  我们将机器（或平台）支持代码分组为机器类。一个类通常基于一个或多个
  片上系统（SoC）设备，并作为实际实现的天然容器。这些类被赋予目录——
  arch/arm/mach-<class>——其中包含支持该机器类的源文件以及 include/mach/。

  例如，SA1100 类基于 SA1100 和 SA1110 SoC 设备，包含用于支持板载和板外
  设备使用方式、或设备设置方式的代码，并提供该机器特定的“个性”。

  对于支持设备树（DT）的平台，机器选择是在运行时通过将设备树 blob 传递给
  内核来控制的。在编译时，必须选择对该机器类型的支持。这样单一的多平台内核
  构建就可以用于多种机器类型。

  对于不使用设备树的平台，机器选择由机器类型 ID 控制，它同时作为运行时和
  编译时的代码选择方法。你可以通过以下网站注册新机器：

    <http://www.arm.linux.org.uk/developer/machines/>

  注意：请不要为仅支持 DT 的平台注册机器类型。如果你的平台仅支持 DT，你
  不需要注册机器类型。
