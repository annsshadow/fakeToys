## 说明


我们的模拟器似乎在 exp(double) 上存在问题。我至今还未能定位它。Russell King 提供的模拟器不会出现此问题。

我还在模拟器中发现了一种奇怪现象。我认为这不严重，但会指出来。ARM 调用约定要求浮点寄存器 f4-f7 在一次函数调用期间被保留。编译器常常在函数入口处使用 stfe 指令将 f4 保存到栈上，并在返回前使用 ldfe 指令恢复它。

我当时在看一段计算 double 结果、将其存入 f4 然后进行函数调用的代码。从函数调用返回后，f4 中的数字在模拟器中已被转换为扩展精度值。

这是 stfe 指令的副作用。f4 中的 double 必须先转换为扩展精度，然后存储。如果使用的是 lfm/sfm 组合，则不会发生转换。这涉及性能考量。函数调用的结果与 f4 被用于一次乘法运算。如果模拟器看到 double 与 extended 的乘法，它会将 double 提升为 extended，然后在扩展精度下执行乘法。

以下代码会导致此问题：

double x, y, z;
z = log(x)/log(y);

log(x) 的结果（一个 double）将被计算，在 f0 中返回，然后移动到 f4 以在 log(y) 调用期间保留它。由于 log(y) 中用于保存 f4 的 stfe 指令，除法将在扩展精度下执行。
