## 内存对齐


最近，内核代码中由于未被注意到的未对齐内存访问而冒出了太多问题。因此，对齐修复
（alignment fixup）现在是无条件地为基SA11x0 的目标配置的。根Alan Cox 的说法，
将其配置掉是个坏主意，但 Russell King 在一些糟糕的 ARM 架构（如 EBSA110）上这样有充分的理由。不过在我所知的许多设计中（例如所有基SA11x0 的设计）并非如此
当然，一般来说依赖对齐陷阱（alignment trap）来执行未对齐内存访问是个坏主意。如这些访问是可预测的，你最好使include/linux/unaligned.h 提供的宏。对齐陷阱可为这些异常情况修复未对齐访问，但代价是较高的性能。最好是少出现这种情况
现在对于用户空间应用程序，可以将对齐陷阱配置为对任何执行未对齐访问的代码发SIGBUS（有利于调试坏代码），或者像内核代码那样通过软件修复该访问。由于性能原因不推荐使用后一种模式（只要想想以大致相同方式工作的浮点仿真就知道了）。还是去
修正你的代码吧！

请注意，在没有深思熟虑的情况下随意更改这种行为真的很糟糕——它会改变用户空间中
所有未对齐指令的行为，并可能导致程序意外失败
要更改对齐陷阱的行为，只需/proc/cpu/alignment 写入一个数字即可。该数字由若位组成：

===		========================================================
bit		置位时的行为
===		========================================================
0		执行未对齐内存访问的用户进程将导致内核打印一条消息，
		指示进程名、pid、pc、指令、地址以及错误码
1		内核将尝试修复执行未对齐访问的用户进程。这当然很慢
		（想想浮点仿真器），不推荐用于生产环境
2		内核将向执行未对齐访问的用户进程发SIGBUS 信号===		========================================================

注意并非所有组合都受支持——仅0 5 7 没有意义）
例如，以下命令将打开警告，但不进行：

```

	echo 1 > /proc/cpu/alignment

```
你也可以读取同一文件的内容，以获取有关未对齐访问发生次数的统计信息，以及用户空间
代码的当前操作模式
