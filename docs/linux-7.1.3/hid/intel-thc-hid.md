
## Intel 触摸主机控制器（THC，Touch Host Controller）


触摸主机控制器（Touch Host Controller）是 PCH 中用于与触摸设备（例如触摸屏、触摸板等）接口的 IP 模块的名称。它由 3 个关键功能模块组成：

- 一个原生半双工的 Quad I/O 能力 SPI 主控制器
- 用于支持 HIDI2C 兼容设备的低延迟 I2C 接口
- 一个具备到系统内存的读写（RW）DMA 能力的硬件定序器（HW sequencer）

它有一个单一根空间的 IOSF 主接口，支持与触摸设备之间的事务。宿主机驱动通过 THC 接口配置并控制触摸设备。THC 为触摸驱动提供高带宽的 DMA 服务，并将 HID 报告传输到宿主机系统的主内存。

THC 内的硬件定序器负责（通过 DMA）将数据从触摸设备传输到系统内存。使用环形缓冲区来避免因数据消费（由宿主机进行）相对于数据生产（由触摸设备通过 DMA 进行）的异步特性而导致的数据丢失。

与其他常见的 SPI/I2C 控制器不同，THC 直接处理 HID 设备的数据中断和复位信号。

## 1. 概述


### 1.1 THC 软件/硬件栈


下图展示了 THC 软件/硬件栈的高层架构，它完全能够在 Linux 操作系统中支持 HIDSPI/HIDI2C 协议。

```
触摸 IC（TIC），也称为触摸设备（触摸屏或触摸板）。它是离散的模拟组件，用于感知并以 HID 报告的形式通过 SPI/I2C 总线将离散触摸数据或热力图数据传输到宿主机上的 THC 控制器。

THC 主机控制器是一个集成在 PCH 中的 PCI 设备 HBA（host bus adapter，主机总线适配器），充当触摸 IC 与宿主机之间的桥。

THC 硬件驱动为上述 QuickSPI/QuickI2C 驱动提供 THC 硬件操作 API，它访问 THC 的 MMIO 寄存器来配置和控制 THC 硬件。

THC QuickSPI/QuickI2C 驱动，也称为 HIDSPI/HIDI2C 驱动，被注册为一个管理 THC 控制器并实现 HIDSPI/HIDI2C 协议的 HID 底层驱动。

                     |  +------------+ +------------+  |
                      ---------------------------------

```
由于 THC 是作为 PCI 设备暴露的，因此它具有标准的 PCI 配置空间寄存器用于 PCI 枚举和配置。

MMIO 寄存器，为驱动提供访问以配置和控制 THC 硬件的寄存器，这些寄存器包括几类：中断状态与控制、DMA 配置、PIO（Programmed I/O，即编程 I/O，定义见第 3.2 节）状态与控制、SPI 总线配置、I2C subIP 状态与控制、复位状态与控制……

THC 为驱动提供两种方式与外部触摸 IC 通信：PIO 和 DMA。PIO 可以让驱动手动向触摸 IC 写入/读取数据，而 THC DMA 则可以在没有驱动参与的情况下自动写入/读取数据。

硬件定序器包含 THC 的主要逻辑，它从 MMIO 寄存器获取指令来控制 SPI 总线和 I2C 总线以完成一次总线数据事务，还可以根据中断类型自动处理触摸 IC 的中断并启动 DMA 从触摸 IC 接收/向触摸 IC 发送数据。这意味着 THC 硬件定序器理解 HIDSPI/HIDI2C 传输协议，并在没有驱动参与的情况下处理通信，驱动需要做的只是正确配置 THC，并准备好格式化数据包或处理接收到的数据包。

由于 THC 支持 HIDSPI/HIDI2C 协议，它内部包含 SPI 控制器和 I2C subIP 以暴露 SPI 总线和 I2C 总线。THC 还集成了一个 GPIO 控制器以提供中断线支持和复位线支持。

## 2. THC 硬件接口


### 2.1 主机接口


THC 作为“PCI Digitizer device（PCI 数字化仪设备）”暴露给宿主机。PCI 的产品 ID 和设备 ID 在不同代的处理器之间会变化。因此枚举驱动程序的源代码需要逐代更新。


### 2.2 设备接口


THC 支持两种用于连接触摸 IC 的总线类型：增强型 SPI 总线和 I2C 总线。

#### 2.2.1 SPI 端口


当 MMIO 寄存器中的 PORT_TYPE = 00b 时，THC 使用 SPI 接口与外部触摸 IC 通信。THC 增强型 SPI 总线支持不同的 SPI 模式：标准单 I/O 模式、双 I/O 模式和四 I/O 模式。

在单 I/O 模式下，THC 驱动 MOSI 线向触摸 IC 发送数据，并通过 MISO 线从触摸 IC 接收数据。在双 I/O 模式下，THC 同时驱动 MOSI 和 MISO 用于数据发送，并在两条线上都接收数据。在四 I/O 模式下，另外增加了两条线（IO2 和 IO3），THC 同时驱动 MOSI（IO0）、MISO（IO1）、IO2 和 IO3 用于数据发送，并在这 4 条线上接收数据。驱动需要通过设置不同的操作码（opcode）来将 THC 配置为不同模式。

除了 I/O 模式，驱动还需要配置 SPI 总线速度。在 Intel Lunar Lake 平台上，THC 支持最高 42MHz 的 SPI 时钟。

```

 | --------------------THC sends---------------------------------|
 <8Bits OPCode><24Bits Slave Address><Data><Data><Data>...........

```
```

 | ---------THC Sends---------------||-----Touch IC sends--------|
 <8Bits OPCode><24Bits Slave Address><Data><Data><Data>...........

```
#### 2.2.2 I2C 端口


THC 也集成了其中的 I2C 控制器，称为 I2C SubSystem。当 PORT_TYPE = 01 时，THC 被配置为 I2C 模式。与可以通过 MMIO 寄存器直接配置的 SPI 模式相比，THC 需要使用 PIO 读（通过设置 SubIP 读操作码）来获取 I2C subIP APB 寄存器的值，并使用 PIO 写（通过设置 SubIP 写操作码）来进行写操作。

#### 2.2.3 GPIO 接口


THC 还包含两根 GPIO 引脚，一根用于中断，另一根用于设备复位控制。

中断线可以通过设置 MMIO 控制寄存器配置为电平触发或边沿触发。

复位线由 BIOS（或 EFI）通过 ACPI _RST 方法控制，驱动需要在初始化期间调用该设备的 ACPI _RST 方法来复位触摸 IC。

### 2.3 最大输入大小控制


这是 Panther Lake 平台上引入的新特性，THC 硬件允许驱动为 RxDMA 设置最大输入大小。在该最大大小被设置并启用后，对于每次输入报告数据包读取，THC 硬件定序器会先读出传入的输入数据包大小，然后将输入数据包大小与给定的最大大小进行比较：

- 如果输入数据包大小 <= 最大大小，THC 继续使用输入数据包大小完成读取
- 如果输入数据包大小 > 最大大小，传输过程中存在潜在的输入数据崩溃风险，THC 将使用最大大小而不是输入数据包大小进行读取

该特性用于避免会导致 I2C 总线 RxDMA 缓冲区溢出问题的数据损坏，并增强整个系统的稳定性。

### 2.4 中断延迟


由于 MCU 性能限制，某些触摸设备无法在输入数据传输完成后立即撤销（de-assert）中断引脚，从而导致中断翻转延迟。但 THC 总是在处理完上一个输入中断后立即检测下一个中断。在这种情况下，被延迟的中断撤销会被 THC 识别为新的中断信号，从而导致 THC 错误地启动一次输入报告读取。

为了避免这种情况，THC 在 Panther Lake 平台上引入了中断延迟新特性，允许驱动设置一个中断延迟。启用该特性后，THC 会将该给定时间延迟用于下一次中断检测。

## 3. 高层概念


### 3.1 操作码（Opcode）


操作码（opcode，operation code）用于告知 THC 或触摸 IC 将要进行的操作，例如 PIO 读或 PIO 写。

当 THC 被配置为 SPI 模式时，操作码用于确定读/写 I/O 模式。以下是一些 SPI I/O 模式的操作码示例：

=======   ==============================
操作码     对应的 SPI 命令
=======   ==============================
0x0B      读 单 I/O
0x02      写 单 I/O
0xBB      读 双 I/O
0xB2      写 双 I/O
0xEB      读 四 I/O
0xE2      写 四 I/O
=======   ==============================

一般来说，不同的触摸 IC 有不同的操作码定义。根据 HIDSPI 协议白皮书，这些操作码定义在设备的 ACPI 表中，驱动需要在驱动初始化期间通过 OS ACPI API 查询这些信息，然后用正确设置配置 THC 的 MMIO 操作码寄存器。

当 THC 工作在 I2C 模式时，操作码用于告知 THC 下一个 PIO 类型：I2C SubIP APB 寄存器读、I2C SubIP APB 寄存器写、I2C 触摸 IC 设备读、I2C 触摸 IC 设备写、I2C 触摸 IC 设备写后读。

以下是 THC 为 I2C 模式预定义的操作码：

=======   ===================================================   ===========
操作码     对应的 I2C 命令                                     地址
=======   ===================================================   ===========
0x12      读 I2C SubIP APB 内部寄存器                          0h - FFh
0x13      写 I2C SubIP APB 内部寄存器                          0h - FFh
0x14      通过 I2C 总线读外部触摸 IC                            N/A
0x18      通过 I2C 总线写外部触摸 IC                            N/A
0x1C      通过 I2C 总线写后读外部触摸 IC                        N/A
=======   ===================================================   ===========

### 3.2 PIO


THC 提供一个编程 I/O（PIO，Programmed I/O）访问接口，供驱动访问触摸 IC 的配置寄存器或 I2C subIP 的配置寄存器。要使用 PIO 执行 I/O 操作，驱动应当预先编程 PIO 控制寄存器和 PIO 数据寄存器，并启动定序周期。THC 使用不同的 PIO 操作码来区分不同的 PIO 操作（PIO 读/写/写后读）。

如果存在一个正在进行的定序周期（Sequencing Cycle In Progress），此时尝试编程任何控制、地址或数据寄存器都会被阻止，并会遇到序列错误。

一个状态位指示周期何时完成，使驱动能够知道何时可以检查读取结果和/或何时可以发起新命令。如果启用，周期完成断言（cycle done assertion）可以通过中断来中断驱动。

由于 THC 只有 16 个用于 PIO 的 FIFO 寄存器，因此所有通过 PIO 传输的数据不应超过 64 字节。

由于 DMA 需要最大包大小来进行传输配置，而最大包大小信息总是在 HID 设备描述符中，需要 THC 驱动从 HID 设备（触摸 IC）中读出来。因此 PIO 的典型用例是，在 DMA 初始化之前：写 RESET 命令（PIO 写）、读 RESET 响应（PIO 读或 PIO 写后读）、写 Power ON 命令（PIO 写）、读设备描述符（PIO 读）。

关于如何发起一次 PIO 操作，以下是驱动需要遵循的步骤：

- 在 THC_SS_BC 中编程读/写数据大小。
- 在 THC_SW_SEQ_DATA0_ADDR 中编程 I/O 目标地址。
- 如果是写，在 THC_SW_SEQ_DATA0..THC_SW_SEQ_DATAn 中编程写入数据。
- 在 THC_SS_CMD 中编程 PIO 操作码。
- 设置 TSSGO = 1 以启动 PIO 写序列。
- 如果 THC_SS_CD_IE = 1，SW 会在 PIO 完成时收到一个 MSI。
- 如果是读，读出 THC_SW_SEQ_DATA0..THC_SW_SEQ_DATAn 中的数据。

### 3.3 DMA


THC 有 4 个 DMA 通道：读 DMA1、读 DMA2、写 DMA 和软件 DMA。

#### 3.3.1 读 DMA 通道


THC 有两个读 DMA 引擎：第 1 个 RxDMA（RxDMA1）和第 2 个 RxDMA（RxDMA2）。RxDMA1 保留用于原始数据模式。RxDMA2 用于 HID 数据模式，它是当前驱动用于 HID 输入报告数据获取的 RxDMA 引擎。

RxDMA 的典型用例是自动从触摸 IC 接收数据。一旦 RxDMA 被软件启用，THC 就会开始自动处理接收逻辑。

对于 SPI 模式，THC RxDMA 的序列是：当触摸 IC 触发一个中断给 THC，THC 读出报告头以确定报告类型和报告长度，根据上述信息，THC 读出报告体到内部 FIFO，并启动 RxDMA 将数据复制到系统内存。之后，THC 用报告类型更新中断原因寄存器，并更新 RxDMA PRD 表读指针，然后触发一个 MSI 中断来通知驱动 RxDMA 已完成数据接收。

对于 I2C 模式，THC RxDMA 的行为略有不同，由于 HIDI2C 协议与 HIDSPI 协议存在差异，RxDMA 仅用于接收输入报告。序列是：当触摸 IC 触发一个中断给 THC，THC 首先从输入报告地址读出 2 字节以确定包长度，然后使用这个包长度从输入报告地址启动一次 DMA 读取以获取输入报告数据。之后，THC 更新 RxDMA PRD 表读指针，然后触发一个 MSI 中断来通知驱动输入报告数据已就绪于系统内存中。

以上所有序列都由硬件自动处理，驱动需要做的只是配置 RxDMA，并等待中断就绪，然后从系统内存中读出数据。

#### 3.3.2 软件 DMA 通道


THC 支持一种由软件触发的 RxDMA 模式来从触摸 IC 读取触摸数据。这个 SW RxDMA 是第三个 THC RxDMA 引擎，功能与现有的两个 RxDMA 类似，唯一的区别是这个 SW RxDMA 由软件触发，而 RxDMA2 由外部触摸 IC 中断触发。它为软件驱动提供了随时使用 RxDMA 读取触摸 IC 数据的灵活性。

在软件启动一个 SW RxDMA 之前，它应当停止第 1 和第 2 个 RxDMA，清除 PRD 读/写指针，并使设备中断静止（quiesce，THC_DEVINT_QUIESCE_HW_STS = 1），其他操作与 RxDMA 相同。

#### 3.3.3 写 DMA 通道


THC 有一个写 DMA 引擎，可用于自动向触摸 IC 发送数据。根据 HIDSPI 和 HIDI2C 协议，每次只能向触摸 IC 发送一个命令，并且在最后一个命令被完全处理之前，无法发送下一个命令，因此 THC 写 DMA 引擎只支持单个 PRD 表。

驱动需要做的是：准备 PRD 表和 DMA 缓冲区，然后将数据复制到 DMA 缓冲区并用缓冲区地址和缓冲区长度更新 PRD 表，然后启动写 DMA。THC 会自动将数据发送到触摸 IC，并在传输完成后触发一个 DMA 完成中断。

### 3.4 PRD


物理区域描述符（PRD，Physical Region Descriptor）为 THC 的 DMA 提供内存映射描述。

#### 3.4.1 PRD 表与表项


为了改善物理 DMA 内存的使用，现代驱动倾向于为每个数据缓冲区分配一个虚拟连续但物理碎片化的内存缓冲区。Linux 操作系统也提供 SGL（scatter gather list，分散/聚集列表）API 来支持这种用法。

THC 使用 PRD 表（physical region descriptor）来支持描述虚拟到物理缓冲区映射的相应 OS 内核 SGL。

```

  ------------------------      --------------       --------------
 | PRD table base address +----+ PRD table #1 +-----+ PRD Entry #1 |
  ------------------------      --------------       --------------
                                                     --------------
                                                    | PRD Entry #2 |
                                                     --------------
                                                     --------------
                                                    | PRD Entry #n |
                                                     --------------

```
读 DMA 引擎支持在环形缓冲区中持有多个 PRD 表，使 THC 能够支持来自触摸 IC 的多个数据缓冲区。这让宿主 SW 能够用多个缓冲区武装（arm）读 DMA 引擎，使触摸 IC 能够在没有 SW 交互的情况下向 THC 发送多个数据帧。当 CPU 处理触摸帧的速度慢于触摸 IC 发送它们的速度时，就需要这种能力。

为了简化设计，SW 假设最坏情况的内存碎片化。因此，每个 PRD 表应包含相同数量的 PRD 表项，以便用一个全局寄存器（每个触摸 IC 一个）保存每个 PRD 表的 PRD 表项数量。

SW 为每个读 DMA 引擎分配最多 128 个 PRD 表，如 THC_M_PRT_RPRD_CNTRL.PCD 寄存器字段所指定。PRD 表的数量应等于数据缓冲区的数量。

OS 的最大内存碎片化会发生在 4KB 边界，因此为了寻址 1MB 的虚拟连续内存，单个 PRD 表需要 256 个 PRD 表项。SW 将每个 PRD 表的 PRD 表项数量写入 THC_M_PRT_RPRD_CNTRL.PTEC 寄存器字段。PRD 表项的长度必须是 4KB 的整数倍，PRD 表中的最后一个表项除外。

SW 仅在宿主初始化时分配一次所有的数据缓冲区和 PRD 表。

#### 3.4.2 PRD 写指针与读指针


由于 PRD 表被组织为一个环形缓冲区（CB，Circular Buffer），因此需要一个 CB 的读指针和写指针。

DMA 硬件逐个 PRD 表项地消耗 CB 中的 PRD 表，直到在某个 PRD 表项中发现 EOP 位被置位。此时硬件递增 PRD 读指针。因此，读指针指向 DMA 引擎当前正在处理的 PRD。一旦遍历完环形缓冲区的深度，该指针会借助位 [^7^]（Rollover 位，翻转位）发生翻转（roll over）。例如，如果 DMA CB 深度等于 4 个表项（0011b），那么读指针将遵循以下模式（硬件必须遵守此行为）：00h 01h 02h 03h 80h 81h 82h 83h 00h 01h ...

写指针由 SW 更新。写指针指向 DMA CB 中下一个 PRD 表将被存储的位置。SW 需要确保一旦遍历完环形缓冲区的深度，该指针借助 Bit[^7^] 作为翻转位发生翻转。例如，如果 DMA CB 深度等于 5 个表项（0100b），那么写指针将遵循以下模式（SW 必须遵守此行为）：00h 01h 02h 03h 04h 80h 81h 82h 83h 84h 00h 01h ..

#### 3.4.3 PRD 描述符结构


Intel THC 为每个 PRD 表项使用 PRD 表项描述符。每个 PRD 表项描述符占用 128 位内存：

===================   ========   ===============================================
结构体字段            位         描述
===================   ========   ===============================================
dest_addr             53..0      目标内存地址，由于每个表项为 4KB，忽略地址最低 10 位。
reserved1             54..62     保留
int_on_completion     63         完成中断使能位，如果该位置位表示 THC 将触发一个完成中断。该位由 SW 驱动设置。
len                   87..64     该表项中有多少字节的数据。
end_of_prd            88         PRD 表结束位，如果该位置位表示此表项是该 PRD 表中的最后一个表项。该位由 SW 驱动设置。
hw_status             90..89     硬件状态位
reserved2             127..91    保留
===================   ========   ===============================================

并且一个 PRD 表最多可包含 256 个 PRD 表项，由于每个表项为 4K 字节，因此每个 PRD 表可以描述 1M 字节内存。


   struct thc_prd_table {
        struct thc_prd_entry entries[PRD_ENTRIES_NUM];
   };

一般来说，每个 PRD 表对应一个 HID 触摸数据包。每个 DMA 引擎最多可支持 128 个 PRD 表（写 DMA 除外，写 DMA 只有一个 PRD 表）。SW 驱动负责从触摸 IC 获取最大包长度，并用此最大包长度为每个 PRD 表创建 PRD 表项。

## 4. HIDSPI 支持（QuickSPI）


Intel THC 完全兼容 HIDSPI 协议，THC 硬件定序器可以加速 HIDSPI 协议的传输。

### 4.1 复位流程


- 调用 ACPI _RST 方法复位触摸 IC 设备。
- 通过 PIO 读从 TIC 读取复位响应。
- 通过 PIO 写发出命令以从触摸 IC 获取设备描述符。
- 通过 PIO 读从触摸 IC 读取设备描述符。
- 如果设备描述符有效，分配 DMA 缓冲区并配置所有 DMA 通道。
- 通过 DMA 发出命令以从触摸 IC 获取报告描述符。

### 4.2 输入报告数据流


基本流程：

- 触摸 IC 使用带内（in-band）THC 中断中断 THC 控制器。
- THC 定序器通过发送读批准（read approval）作为信号给触摸 IC，以准备让宿主机从设备读取，从而读取输入报告头。
- THC 定序器执行与“Input Report Length（输入报告长度）”字段中反映的值相对应的输入报告体读操作。
- THC DMA 引擎开始从 THC 定序器获取数据，并写入到当前 CB PRD 表项的 PRD 表项 0 处的宿主机内存。此过程持续，直到 THC 定序器发出所有数据已读出的信号，或 THC DMA 读引擎到达其最后一个 PRD 表项的末尾（或两者都满足）。
- THC 定序器检查输入报告头中的“Last Fragment Flag（最后分片标志）”位。如果它清零，THC 定序器进入空闲状态。
- 如果“Last Fragment Flag”位置位，THC 定序器进入帧结束处理（End-of-Frame Processing）。

THC 定序器帧结束处理：

- THC DMA 引擎递增读 PRD CB 的读指针，在 RxDMA2 寄存器（THC_M_PRT_READ_DMA_INT_STS_2）中设置 EOF 中断状态。
- 如果驱动在控制寄存器（THC_M_PRT_READ_DMA_CNTRL_2）中启用了 THC EOF 中断，则向软件生成中断。

从 RX DMA 缓冲区读取数据的步骤序列：

- THC QuickSPI 驱动检查 CB 写指针和 CB 读指针，以确定 DMA 环形缓冲区中是否有数据帧。
- THC QuickSPI 驱动获取第一个未处理的 PRD 表。
- THC QuickSPI 驱动扫描此 PRD 表中的所有 PRD 表项以计算总帧大小。
- THC QuickSPI 驱动复制出所有帧数据。
- THC QuickSPI 驱动根据输入报告体检查数据类型，并调用相关回调函数处理数据。
- THC QuickSPI 驱动更新写指针。

### 4.3 输出报告数据流


通用输出报告流程：

- HID core 调用 raw_request 回调，向 THC QuickSPI 驱动发出请求。
- THC QuickSPI 驱动将请求提供的数据转换为输出报告包，并复制到 THC 的写 DMA 缓冲区。
- 启动 TxDMA 以完成写操作。

## 5. HIDI2C 支持（QuickI2C）


### 5.1 复位流程


- 通过 PIO 写后读从触摸 IC 设备读取设备描述符。
- 如果设备描述符有效，分配 DMA 缓冲区并配置所有 DMA 通道。
- 使用 PIO 或 TxDMA 向 TIC 的命令寄存器写入一个 SET_POWER 请求，并检查写操作是否成功完成。
- 使用 PIO 或 TxDMA 向 TIC 的命令寄存器写入一个 RESET 请求。如果写操作成功完成，等待来自 TIC 的复位响应。
- 使用 SWDMA 通过 TIC 的报告描述符寄存器读取报告描述符。

### 5.2 输入报告数据流


基本流程：

- 触摸 IC 置位（assert）中断，表明它有中断要发送给宿主机。THC 定序器通过 I2C 总线发出一个 READ 请求。HIDI2C 设备返回来自 HIDI2C 设备的前 2 字节，其中包含所接收数据的长度。
- THC 定序器根据长度字段中指示的数据大小继续读操作。
- THC DMA 引擎开始从 THC 定序器获取数据，并写入到当前 CB PRD 表项的 PRD 表项 0 处的宿主机内存。THC 将长度字段的 2 字节加上剩余数据写入 RxDMA 缓冲区。此过程持续，直到 THC 定序器发出所有数据已读出的信号，或 THC DMA 读引擎到达其最后一个 PRD 表项的末尾（或两者都满足）。
- THC 定序器进入输入报告结束处理（End-of-Input Report Processing）。
- 如果设备没有更多要发送给宿主机的输入报告，它撤销（de-assert）中断线。对于任何额外的输入报告，设备保持中断线置位，并重复流程中的第 1 到 4 步。

THC 定序器输入报告结束处理：

- THC DMA 引擎递增读 PRD CB 的读指针，在 RxDMA 2 寄存器（THC_M_PRT_READ_DMA_INT_STS_2）中设置 EOF 中断状态。
- 如果驱动在控制寄存器（THC_M_PRT_READ_DMA_CNTRL_2）中启用了 THC EOF 中断，则向软件生成中断。

从 RX DMA 缓冲区读取数据的步骤序列：

- THC QuickI2C 驱动检查 CB 写指针和 CB 读指针，以确定 DMA 环形缓冲区中是否有数据帧。
- THC QuickI2C 驱动获取第一个未处理的 PRD 表。
- THC QuickI2C 驱动扫描此 PRD 表中的所有 PRD 表项以计算总帧大小。
- THC QuickI2C 驱动复制出所有帧数据。
- THC QuickI2C 驱动调用 hid_input_report 将输入报告内容发送给 HID core，其中包含 Report ID + Report Data Content（从原始报告数据中移除长度字段）。
- THC QuickI2C 驱动更新写指针。

### 5.3 输出报告数据流


通用输出报告流程：

- HID core 调用 THC QuickI2C 的 raw_request 回调。
- THC QuickI2C 使用 PIO 或 TXDMA 向 TIC 的命令寄存器写入一个 SET_REPORT 请求。SET_REPORT 中的报告类型应设置为 Output。
- THC QuickI2C 用要写入 TIC 数据寄存器的 TX 数据编程 TxDMA 缓冲区。前 2 字节应指示报告的长度，其后跟随包含 Report ID 的报告内容。
