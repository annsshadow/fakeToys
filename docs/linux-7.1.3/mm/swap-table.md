## 交换表（Swap Table）


交换表将交换缓存实现为一个按簇（cluster）的交换缓存值数组。

### 交换项（Swap Entry）


一个交换项包含服务于匿名页缺页（page fault）所需的信息。

交换项被编码为两部分：交换类型（swap type）与交换偏移（swap offset）。

交换类型指示使用哪个交换设备。
交换偏移是交换文件中用于读取页数据的偏移。

### 交换缓存（Swap Cache）


交换缓存是一个以交换项为键来查找 folio 的映射。其结果值根据交换项所处的
阶段不同，可能有三种类型。

1. NULL：该交换项未被使用。

2. folio：已分配一个 folio 并绑定到该交换项。这是换出或换入的瞬时状态。
   folio 数据可以在 folio 中、交换文件中，或两者皆有。

3. shadow：影子包含了被换出 folio 的工作集信息。这是被换出页的正常状态。

### 交换表内部机制


此前的交换缓存由 XArray 实现。XArray 是一种树形结构。每次查找都要经过
多个节点。我们能做得更好吗？

注意，大多数时候当我们查找交换缓存时，要么处于换入路径，要么处于换出路径。
我们应该已经拥有包含该交换项的交换簇。

如果我们在簇内用一个数组来存储交换缓存值，簇内的交换缓存查找就可以是非常
简单的数组查找。

我们给这样一个按簇的交换缓存值数组起了一个名字：交换表。

交换表是一个指针数组。每个指针与 PTE 大小相同。一个交换簇的交换表大小通常
与一个 PTE 页表相匹配，在现代 64 位系统上即一页。

有了交换表，交换缓存查找可以实现极佳的局部性，且更简单、更快速。

### 加锁


修改交换表需要获取簇锁。如果要将一个 folio 加入或移出交换表，必须先锁定
该 folio，再获取簇锁。在加入或移出完成后，应解锁该 folio。

交换表的查找由 RCU 与原子读保护。如果查找返回了一个 folio，用户必须在使用
前锁定该 folio。
