## remap_file_pages() system call


remap_file_pages() 系统调用用于创建非线性映射，
即文件中各页以非顺序方式映射到
内存中。与使用重复调用 mmap(2) 相比，使用 remap_file_pages()
的优势在于前者无需让内核创建额外的
VMA（Virtual Memory Area）数据
结构。

支持非线性映射需要内核虚拟内存子系统中大量
重要的非平凡代码，包括热路径。此外，为了让非线性
映射正常工作，内核需要一种方法来区分普通页表项
与带文件偏移的项（pte_file）。内核为此在
PTE 中保留了一个标志位。PTE 标志位是一种稀缺资源，在某些 CPU
架构上尤其如此。若能将该标志位释放用于其他用途会更好。

幸运的是，实际使用中 remap_file_pages() 的用户并不多。
目前仅知某企业的 RDBMS 实现在 32 位系统上使用该系统调用
来映射无法线性放入 32 位
虚拟地址空间的大文件。由于 64 位
系统已广泛可用，该用例已不再关键。

该系统调用已被弃用，现在由模拟层替代。该
模拟层会创建新的 VMA 而非非线性映射。对于 remap_file_pages()
的少数用户而言速度会变慢，但 ABI 得以保留。

模拟的一个副作用（除性能外）是用户可能更容易
因额外的 VMA 而触及 vm.max_map_count 限制。有关该限制的
更多细节，请参阅 DEFAULT_MAX_MAP_COUNT 的注释。
