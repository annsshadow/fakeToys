## 页片段（Page fragments）


页片段是驻留在一个 0 阶或更高阶复合页（compound page）内的、任意长度与
任意偏移的内存区域。该页内的多个片段在页的引用计数器中各自被单独引用计数。

page_frag 函数 page_frag_alloc 与 page_frag_free 为页片段提供了一个简单的
分配框架。网络协议栈与网络设备驱动使用它来提供一个内存后备区域，用作
sk_buff->head，或用于 skb_shared_info 的 “frags” 部分。

为了使用页片段 API，需要一个后备的页片段缓存。这为片段分配提供了一个中心点，
并允许多次调用复用同一个被缓存的页。这样做的好处是可以避免多次调用 get_page，
而这在分配时可能代价高昂。然而，由于这种缓存的特性，要求对该缓存的任何调用
必须受到保护：要么使用每 CPU 限制，要么使用每 CPU 限制并在执行片段分配时
强制禁用中断。

网络协议栈使用每 CPU 的两个独立缓存来处理片段分配。netdev_alloc_cache 由
使用 netdev_alloc_frag 与 __netdev_alloc_skb 调用的调用者使用。napi_alloc_cache
由使用 __napi_alloc_frag 与 napi_alloc_skb 调用的调用者使用。这两种调用之间的
主要区别在于它们可被调用的上下文。“netdev” 前缀的函数可用于任何上下文，因为
这些函数会禁用中断；而 “napi” 前缀的函数只能在软中断（softirq）上下文中使用。

许多网络设备驱动使用类似的方法来分配页片段，但页片段是在环（ring）或描述符
级别被缓存的。为了支持这些情况，有必要提供一种通用的方式来拆除页缓存。出于
这个原因实现了 __page_frag_cache_drain。它允许通过单次调用从一个页中释放多个
引用。这样做的好处是它可以清理为某页添加的多个引用，从而避免每次分配都调用
get_page。
