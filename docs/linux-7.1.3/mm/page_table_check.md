
## 页表检查（Page Table Check

## 简

页表检查（Page table check）通过确保防止某些类型的内存损坏，来加固内核
页表检查在通过将其页表项（PTE、PMD 等）加入表中、从而使新页面可从用户空间访问时，执额外的验证
在检测到大多数损坏的情况下，内核会发生崩溃（crash）。页表检查会带来少量的性能与内存开销因此，它默认是禁用的，但可以在“额外加固的收益超过性能代价”的系统上选择性地启用。此外，由于
页表检查是同步的，它有助于调试双重映射（double map）内存损坏问题——它会在发生错误映射就让内核崩溃，而非像内存损坏类缺陷通常那样在之后才表现出来
它也可用于针对各种标志进行页表项检查，并在检测到非法的表项标志组合时转储警告。目前，
userfaultfd 是唯一使用该机制的用户，用于针对任意可写标志对写保护（wr-protect）位进行
健全性检查。在这种情况下，非法的标志组合不会立即直接导致数据损坏，但会使只读数据变为可写，
从而在页内容随后被修改时导致损坏

## 启用页表检

构建内核时使用：

- PAGE_TABLE_CHECK=y
  注意，它只能在提ARCH_SUPPORTS_PAGE_TABLE_CHECK 的平台上启用
- 以内核参'page_table_check=on' 启动
可选地，使PAGE_TABLE_CHECK_ENFORCED 构建内核，从而无需额外内核参数即可获得页表检查支持
## 实现说明


我们特意决定不使VMA 信息，以避免依赖 MM 状态（除有限的 “struct page信息外）。页表检是一个独立于 Linux-MM 的状态机，用于验证用户可访问的页面不会被错误共享
PAGE_TABLE_CHECK 依赖EXCLUSIVE_SYSTEM_RAM。原因是如果没有 EXCLUSIVE_SYSTEM_RAM，用户就
可以通过 /dev/mem 将任意物理内存区域映射到用户空间。与此同时，页面可能在其仍被映射到用户空的同时改变其属性（例如从匿名页变为命名页），从而导致被页表检查检测为“损坏”
即使EXCLUSIVE_SYSTEM_RAM，I/O 页面仍可能被允许通过 /dev/mem 映射。然而，这些页面始终视为命名页，因此它们不会破坏页表检查所使用的逻辑
