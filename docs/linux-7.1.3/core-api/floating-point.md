
## 浮点 API


内核代码通常禁止使用浮点（FP）寄存器或指令，包括 C 的 float 与 double 数据类型。这条规则减少了系统调用的开销，因为内核不需要保存和恢复用户空间的浮点寄存器状态。

然而，偶尔驱动或库函数可能需要包含 FP 代码。这是通过将被包含 FP 代码的函数隔离到一个单独的翻译单元（单独的源文件），并在调用这些函数前后保存/恢复 FP 寄存器状态来实现的。这就形成了浮点使用的“临界区”。

这种隔离的原因是为了防止编译器在这些临界区之外生成触碰 FP 寄存器的代码。编译器有时会使用 FP 寄存器来优化内联的 `memcpy` 或变量赋值，因为浮点寄存器可能比通用寄存器更宽。

内核中浮点代码的可用性因体系结构而异。此外，由于单个内核可能被配置为同时支持有浮点单元和无浮点单元的平台，因此 FPU 的可用性必须在构建时与运行时都进行检查。

若干体系结构实现了 `linux/fpu.h` 中的通用内核浮点 API，如下所述。一些其他体系结构实现了它们自己独特的 API，这些会单独文档化。

### 构建时 API


如果启用了 `ARCH_HAS_KERNEL_FPU_SUPPORT` 选项，则可以构建浮点代码。对于 C 代码，此类代码必须放在单独的文件中，并且该
```

    CFLAGS_foo.o += $(CC_FLAGS_FPU)
    CFLAGS_REMOVE_foo.o += $(CC_FLAGS_NO_FPU)

```

体系结构应当在其
```

    CC_FLAGS_FPU := -mhard-float

```

```
    CC_FLAGS_NO_FPU := -msoft-float

```

中定义这两个变量之一或两者。普通内核代码假定使用等价于 `CC_FLAGS_NO_FPU` 的标志。

### 运行时 API


运行时 API 在 `linux/fpu.h` 中提供。此头文件不能被实现 FP 代码（即编译标志如上调整过的）的文件包含。相反，它必须在定义 FP 临界区时包含。

        这些函数创建浮点临界区。只有在先前调用 `kernel_fpu_available()` 返回 `true` 之后，才能调用 `kernel_fpu_begin()`。这些函数只保证可在（可抢占或不可抢占的）进程上下文中调用。

        在临界区内可能会禁用抢占，因此应使其规模最小化。它们**不**要求可重入。如果调用者期望嵌套临界区，它必须自行实现引用计数。
