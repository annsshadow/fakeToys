
## 使用 printk 记录消息


printk() 是 Linux 内核中最广为人知的函数之一。它是我们用于打印消息的标准工具，通常也是进行追踪和调试最基本的方式。如果你熟悉 printf(3)，就会知道 printk() 是基于它的，尽管两者存在一些功能上的差异：

  - printk() 消息可以指定一个日志级别。

  - 格式字符串虽然在很大程度上与 C99 兼容，但并不遵循完全相同的规范。它有一些扩展，也存在一些限制（没有 `%n` 或浮点转换说明符）。参见 :ref:`如何正确使用 printk 格式说明符 <printk-specifiers>`。

所有 printk() 消息都会被打印到内核日志缓冲区，这是一个通过 /dev/kmsg 导出到用户空间的环形缓冲区。通常读取它的方式是使用 `dmesg`。

```

  printk(KERN_INFO "Message: %s\n", arg);

```
其中 `KERN_INFO` 是日志级别（注意它被拼接到了格式字符串上，日志级别并不是一个单独的实参）。可用的日志级别如下：

+----------------+--------+-----------------------------------------------+
| Name           | String |  Alias function                               |
+================+========+===============================================+
| KERN_EMERG     | "0"    | pr_emerg()                                    |
+----------------+--------+-----------------------------------------------+
| KERN_ALERT     | "1"    | pr_alert()                                    |
+----------------+--------+-----------------------------------------------+
| KERN_CRIT      | "2"    | pr_crit()                                     |
+----------------+--------+-----------------------------------------------+
| KERN_ERR       | "3"    | pr_err()                                      |
+----------------+--------+-----------------------------------------------+
| KERN_WARNING   | "4"    | pr_warn()                                     |
+----------------+--------+-----------------------------------------------+
| KERN_NOTICE    | "5"    | pr_notice()                                   |
+----------------+--------+-----------------------------------------------+
| KERN_INFO      | "6"    | pr_info()                                     |
+----------------+--------+-----------------------------------------------+
| KERN_DEBUG     | "7"    | pr_debug() and pr_devel() if DEBUG is defined |
+----------------+--------+-----------------------------------------------+
| KERN_DEFAULT   | ""     |                                               |
+----------------+--------+-----------------------------------------------+
| KERN_CONT      | "c"    | pr_cont()                                     |
+----------------+--------+-----------------------------------------------+


日志级别表示一条消息的重要程度。内核会根据消息的日志级别以及当前的 **console_loglevel**（一个内核变量）来决定是否立即显示该消息（即打印到当前控制台）。如果消息的优先级更高（日志级别数值更小）于 **console_loglevel**，该消息就会被打印到控制台。

如果省略日志级别，消息将以 `KERN_DEFAULT` 级别打印。

```

  $ cat /proc/sys/kernel/printk
  4        4        1        7

```
该结果显示了 **current**、**default**、**minimum** 和 **boot-time-default** 这几个日志级别。

要改变当前的 console_loglevel，只需将期望的级别写入
```

  # echo 8 > /proc/sys/kernel/printk

```
```

  # dmesg -n 5

```
将 console_loglevel 设置为打印 KERN_WARNING (4) 或更严重级别的消息到控制台。更多信息参见 `dmesg(1)`。

作为 printk() 的替代方案，你可以使用 `pr_*()` 系列别名来进行日志记录。这一系列宏将日志级别嵌入到宏名中。例如，
```

  pr_info("Info message no. %d\n", msg_num);

```
会打印一条 `KERN_INFO` 消息。

除了比等价的 printk() 调用更简洁之外，它们还可以通过 pr_fmt() 宏为格式字符串使用统一定义。例如，在源文件顶部（在任何 `#include` 之前）定义它
```

  #define pr_fmt(fmt) "%s:%s: " fmt, KBUILD_MODNAME, __func__

```
将为该文件中每一条 pr_*() 消息添加产生该消息的模块名和函数名前缀。

出于调试目的，还有两个条件编译的宏：pr_debug() 和 pr_devel()，除非定义了 `DEBUG`（对于 pr_debug() 而言，还需定义 `CONFIG_DYNAMIC_DEBUG`），否则它们不会被编译进内核。

## 避免过度使用 printk() 导致的锁死


   本节仅与传统的控制台驱动（即未使用 nbcon API 的驱动）以及 !PREEMPT_RT 内核相关。一旦所有控制台驱动都更新为 nbcon，本小节即可删除。

在热路径（如中断处理程序、定时器回调或高频网络接收例程）中使用 `printk()`，且配合传统控制台（例如 `console=ttyS0`）时，可能导致锁死。传统控制台会同步获取 `console_sem` 并在刷新消息时阻塞，可能使中断被禁用足够长的时间，从而触发硬锁死或软锁死检测器。

为避免这种情况：

- 使用限速变体（例如 `pr_*_ratelimited()`）或一次性宏（例如 `pr_*_once()`）来降低消息频率。
- 为非必要消息分配较低的日志级别（例如 `KERN_DEBUG`），并通过 `console_loglevel` 过滤控制台输出。
- 使用 `printk_deferred()` 将消息立即记录到环形缓冲区中，并推迟控制台打印。这是针对传统控制台的一种变通方案。
- 将传统控制台驱动移植到非阻塞的 `nbcon` API（由 `CON_NBCON` 标识）。这是首选方案，因为 nbcon 控制台会将消息打印卸载到专用的内核线程。

对于临时调试，可以使用 `trace_printk()`，但它不得出现在主线代码中。更多信息参见 `Documentation/trace/debugging.rst`。

如果在热路径中需要更持久的输出，可以使用跟踪事件。参见 `Documentation/trace/events.rst` 以及 `samples/trace_events/trace-events-sample.[ch]`。
