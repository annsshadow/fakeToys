
## Theory of operation


:Author: Sebastian Andrzej Siewior <bigeasy@linutronix.de>

## Preface


PREEMPT_RT 将 Linux 内核转变为一个实时内核。它的实现方式是：用一种可抢占、且支持优先级继承的实现（称为 rtmutex）替换锁原语（例如 spinlock_t），并强制使用线程化中断。这样一来，内核就变得完全可抢占，仅有少数关键代码路径（包括入口代码、调度器以及底层中断处理例程）除外。

这种转变为内核执行上下文的大部分置于调度器的控制之下，并显著增加了抢占点的数量。因此，它缩短了高优先级任务变为可运行到其实际在 CPU 上执行之间的延迟。

## Scheduling


Linux 调度的核心原则以及相关的用户空间 API，记录在 man 手册页 sched(7)
`sched(7) <https://man7.org/linux/man-pages/man7/sched.7.html>`_ 中。
默认情况下，Linux 内核使用 SCHED_OTHER 调度策略。在该策略下，当调度器判定某任务相对于其他可运行任务已经消耗了公平的 CPU 时间份额时，该任务会被抢占。然而，当一个新的 SCHED_OTHER 任务变为可运行时，该策略并不保证立即抢占。当前正在运行的任务可能会继续执行。

这种行为不同于实时调度策略（例如 SCHED_FIFO）。当一个采用实时策略的任务变为可运行时，如果它的优先级高于当前正在运行的任务，调度器会立即选择它执行。该任务会一直运行，直到它主动让出 CPU（通常是通过在某个事件上阻塞）。

## Sleeping spin locks


各种锁类型及其在实时配置下的行为，详见 Documentation/locking/locktypes.rst。
在非 PREEMPT_RT 配置中，获取 spinlock_t 的方式是：先禁用抢占，然后主动自旋，直到锁变为可用。一旦锁被释放，就重新启用抢占。从实时角度来看，这种方式并不理想，因为禁用抢占会阻止调度器切换到更高优先级的任务，从而可能增加延迟。

为解决这一问题，PREEMPT_RT 将自旋锁替换为不会禁用抢占的睡眠自旋锁（sleeping spin lock）。在 PREEMPT_RT 上，spinlock_t 通过 rtmutex 实现。试图获取一个争用锁的任务不会自旋，而是禁用 CPU 迁移，将其优先级捐赠给锁的持有者（优先级继承），并在等待锁变为可用时主动调度出去（schedule out）。

禁用 CPU 迁移与禁用抢占具有相同的效果，同时仍然允许抢占，并确保任务在持有睡眠锁期间继续运行在同一个 CPU 上。

## Priority inheritance


在启用了 PREEMPT_RT 的内核中，spinlock_t 和 mutex_t 等锁类型构建于 rtmutex 之上，而 rtmutex 提供了对优先级继承（PI）的支持。当一个任务阻塞于此类锁时，PI 机制会临时将该被阻塞任务的调度参数传播给锁的持有者。

例如，如果一个 SCHED_FIFO 任务 A 阻塞在一个当前由 SCHED_OTHER 任务 B 持有的锁上，任务 A 的调度策略和优先级会被任务 B 临时继承。继承之后，任务 A 进入睡眠以等待锁，而任务 B 实际上成为系统中优先级最高的任务。这使得 B 能够继续执行、取得进展，并最终释放锁。

一旦 B 释放锁，它就会恢复到其原始的调度参数，而任务 A 可以恢复执行。

## Threaded interrupts


中断处理程序是另一类在禁用抢占的情况下执行、且不受调度器控制的代码。为了将中断处理纳入调度器的控制之下，PREEMPT_RT 强制使用线程化中断处理程序。

在强制线程化（forced threading）下，中断处理被分为两个阶段。第一阶段（主处理程序，primary handler）在 IRQ 上下文中、中断被禁用的情况下执行。它唯一的职责是唤醒关联的线程化处理程序。第二阶段（线程化处理程序，threaded handler）是作为中断处理程序传递给 request_irq() 的函数。它在进程上下文中运行，由内核调度。

从唤醒中断线程直到线程化处理完成，中断源在中断控制器中被屏蔽。这确保了设备中断保持挂起状态但不会重新触发 CPU，从而使系统能够退出 IRQ 上下文，并在被调度的线程中处理中断。

默认情况下，线程化处理程序以 SCHED_FIFO 调度策略、优先级 50（MAX_RT_PRIO / 2）执行，该值位于最小和最大实时优先级的中间。

如果线程化中断处理程序在执行过程中引发了任何软中断（soft interrupt），这些软中断例程会在线程化处理程序完成后、在同一线程内被调用。在软中断处理程序的执行期间，抢占保持启用。

## Summary


通过使用睡眠锁和强制线程化中断，PREEMPT_RT 显著减少了中断或抢占被禁用的代码段，使调度器能够抢占当前执行上下文并切换到更高优先级的任务。
