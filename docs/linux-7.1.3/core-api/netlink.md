


## 面向内核开发者的 Netlink 说明


## 通用指南


### 属性枚

较老的家庭（family）通常定义值为 `0`、名`unspec` 的“空”属性和命令。这是被支持的（`type: unused`），但在新家庭中应避免。实践中并不使用 `unspec` 枚举值，因此只需将第一个属性的值设`1` 即可
### 消息枚举


对请求和回复使用相同的命ID。这样更容易将它们对应起来，而且我们有充足的 ID 空间
为通知（notification）使用单独的命令 ID。这样可以更容易地将通知与回复区分开（并通过不同于回复的 API 呈现给用户态应用程序）
### 应答请求


较老的家庭并不会应答所有命令，尤其NEW / ADD 命令。用户只能通过 ACK 得知操作成功与否。应尽量找到有用的数据返回。一旦添加了命令，究竟是返回完整消息还是仅返ACK，都属于 uAPI，无法更改。倾向于返回应答更为稳妥
具体而言，NEW ADD 命令应回复能标识所创建对象的信息，例如所分配对象ID（而无需借助 `NLM_F_ECHO`）
### NLM_F_ECHO


请确保将请求信息传递给 genl_notify()，以`NLM_F_ECHO` 生效。这对于需要内核精确反馈的程序（例如用于日志目的）很有用
### 支持 dump 一致

如果dump 过程中遍历对象可能会跳过或重复对象——请务必通过 `NLM_F_DUMP_INTR` 报告 dump 不一致。这通常通过为该结构维护一个代id，并将其记录struct netlink_callback `seq` 成员中来实现
## Netlink 规范


仅与内核空间相关Netlink 规范部分的文档
### 鍏ㄥ眬椤。

#### kernel-policy


定义内核校验策略`global`（即对该家庭的所有操作相同）、为每个操作单独定义——`per-op`，还是为每个操作和每个操作类型（do dump）分别定义——`split`。新家庭应使`per-op`（默认），以便能够缩小特定命令所接受的属性范围
### 检查项


属性规范中 `checks` 子节的文档
#### unterminated-ok


接受没有 null 结尾的字符串（仅用于旧家庭）。从 `NLA_NUL_STRING` 策略类型切换`NLA_STRING` 策略类型
#### max-len


定义二进制或字符串属性的最大长度（对应struct nla_policy `len` 成员）。对于字符串属性，结尾null 字符不计`max-len`
该字段可以是一个字面整数值，也可以是一个已定义常量的名称。字符串类型可以将该常量减一（即指定 `max-len: CONST - 1`）以保留结尾字符的空间，因此实现应当识别这种模式
#### min-len


`max-len` 类似，但定义的是最小长度
