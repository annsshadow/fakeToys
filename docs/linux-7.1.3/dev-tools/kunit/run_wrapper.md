
## 使用 kunit_tool 运行测试


我们既可以使用 kunit_tool 运行 KUnit 测试，也可以手动运行测试，然后使用 kunit_tool 解析结果。要手动运行测试，请参阅：Documentation/dev-tools/kunit/run_manual.rst。
只要我们能够构建内核，就可以运行 KUnit。

kunit_tool 是一个 Python 脚本，用于配置并构建内核、运行测试并格式化测试结果。

运行命令：


	./tools/testing/kunit/kunit.py run

我们应该会看到以下内容：


	Configuring KUnit Kernel ...
	Building KUnit kernel...
	Starting KUnit kernel...

我们可能希望使用以下选项：


	./tools/testing/kunit/kunit.py run --timeout=30 --jobs=`nproc --all`

- `--timeout` 设置测试运行的最长时间。
- `--jobs` 设置构建内核所用的线程数。

kunit_tool 会在构建目录中生成一个带有默认配置的 `.kunitconfig` 文件（前提是尚不存在其他 `.kunitconfig` 文件）。此外，它会校验生成的 `.config` 文件包含 `.kunitconfig` 中的 `CONFIG` 选项。
It is also possible to pass a separate `.kunitconfig` fragment to
kunit_tool. This is useful if we have several different groups of
tests we want to run independently, or if we want to use pre-defined
test configs for certain subsystems.

To use a different `.kunitconfig` file (such as one
provided to test a particular subsystem), pass it as an option:


	./tools/testing/kunit/kunit.py run --kunitconfig=fs/ext4/.kunitconfig

要查看 kunit_tool 的标志（可选命令行参数），运行：


	./tools/testing/kunit/kunit.py run --help

## 创建 ``.kunitconfig`` 文件


如果我们想要运行一组特定的测试（而不是 KUnit `defconfig` 中列出的那些），可以在 `.kunitconfig` 文件中提供 Kconfig 选项。有关默认的 .kunitconfig，请参阅：
https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/tools/testing/kunit/configs/default.config。
A `.kunitconfig` is a `minconfig` (a .config
generated by running `make savedefconfig`), used for running a
specific set of tests. This file contains the regular Kernel configs
with specific test targets. The `.kunitconfig` also
contains any other config options required by the tests (For example:
dependencies for features under tests, configs that enable/disable
certain code blocks, arch configs and so on).

To create a `.kunitconfig`, using the KUnit `defconfig`:


	cd $PATH_TO_LINUX_REPO
	cp tools/testing/kunit/configs/default.config .kunit/.kunitconfig

然后我们可以添加任何其他 Kconfig 选项。例如：


	CONFIG_LIST_KUNIT_TEST=y

kunit_tool 会确保 `.kunitconfig` 中的所有配置选项在运行测试之前都已在核心 `.config` 中设置。如果未包含选项的依赖项，它会发出警告。

   不会重建 `.config` 文件。仅当 `.kunitconfig` 不是 `.config` 的子集时，配置才会被更新。
   这意味着我们可以使用其他工具（例如：`make menuconfig`）来调整其他配置选项。
   The build dir needs to be set for `make menuconfig` to
   work, therefore  by default use `make O=.kunit menuconfig`。

## 配置、构建与运行测试


如果我们想对 KUnit 构建过程做手动修改，可以独立运行 KUnit 构建过程的一部分。
使用 kunit_tool 时，从 `.kunitconfig` 出发，可以通过 `config` 参数生成 `.config`：


	./tools/testing/kunit/kunit.py config

要从当前的 `.config` 构建 KUnit 内核，可以使用 `build` 参数：


	./tools/testing/kunit/kunit.py build

如果我们已经构建了带有内建 KUnit 测试的 UML 内核，就可以运行该内核，并通过 `exec` 参数显示测试结果：


	./tools/testing/kunit/kunit.py exec

前面“**使用 kunit_tool 运行测试**”一节讨论的 `run` 命令，等同于依次运行上述三个命令。

## 解析测试结果


KUnit 测试以 TAP（Test Anything Protocol，测试任意协议）格式输出结果。运行测试时，kunit_tool 会解析该输出并打印摘要。要查看 TAP 格式的原始测试结果，可以传入 `--raw_output` 参数：


	./tools/testing/kunit/kunit.py run --raw_output

如果我们手头有原始 TAP 格式的 KUnit 结果，可以使用 kunit_tool 的 `parse` 命令解析并打印易于阅读的摘要。该命令接受文件名作为参数，或从标准输入读取。


	# Reading from a file
	./tools/testing/kunit/kunit.py parse /var/log/dmesg
	# Reading from stdin
	dmesg | ./tools/testing/kunit/kunit.py parse

## 过滤测试


通过向 `exec` 或 `run` 命令传入 bash 风格的通配符过滤器，我们可以运行内建于内核中的部分测试。例如：如果只想运行 KUnit 资源测试，使用：


	./tools/testing/kunit/kunit.py run 'kunit-resource*'

这使用带有通配符的标准 glob 格式。


## 在 QEMU 上运行测试


kunit_tool 既支持在 qemu 上运行测试，也支持通过 UML 运行。要在 qemu 上运行测试，默认需要两个标志：

- `--arch`：选择一组配置（Kconfig、qemu 配置选项等），以最小化的方式在指定架构上运行 KUnit 测试。该架构参数与 Kbuild 所用 `ARCH` 变量传入的选项名相同。目前并非所有架构都支持此标志，但我们可以使用 `--qemu_config` 来处理。如果传入 `um`（或忽略此标志），测试将通过 UML 运行。非 UML 架构（例如：i386、x86_64、arm 等）在 qemu 上运行。

  `--arch help` 列出所有有效的 `--arch` 取值。

- `--cross_compile`：指定 Kbuild 工具链。它传入与 Kbuild 所用 `CROSS_COMPILE` 变量相同的参数。提醒一下，这将是工具链二进制文件（如 GCC）的前缀。例如：

  - 如果我们的系统上安装了 sparc 工具链，则为 `sparc64-linux-gnu`。

  - 如果我们将 microblaze 工具链从 0-day 网站下载到了主目录下名为 toolchains 的目录，则为 `$HOME/toolchains/microblaze/gcc-9.2.0-nolibc/microblaze-linux/bin/microblaze-linux`。

这意味着对于大多数架构，在 qemu 下运行就像下面这样简单：


	./tools/testing/kunit/kunit.py run --arch=x86_64

交叉编译时，我们很可能需要指定不同的工具链，例如：


	./tools/testing/kunit/kunit.py run \
		--arch=s390 \
		--cross_compile=s390x-linux-gnu-

如果我们想在 `--arch` 标志不支持的架构上运行 KUnit 测试，或者想以非默认配置在 qemu 上运行 KUnit 测试，那么可以编写我们自己的 `QemuConfig`。
These `QemuConfigs` are written in Python. They have an import line
`from..qemu_config import QemuArchParams` at the top of the file.
The file must contain a variable called `QEMU_ARCH` that has an
instance of `QemuArchParams` assigned to it. See example in:
`tools/testing/kunit/qemu_configs/x86_64.py`。

一旦有了 `QemuConfig`，就可以使用 `--qemu_config` 标志将其传入 kunit_tool。使用该标志时会取代 `--arch` 标志。例如：使用 `tools/testing/kunit/qemu_configs/x86_64.py`，调用形式如下


	./tools/testing/kunit/kunit.py run \
		--timeout=60 \
		--jobs=12 \
		--qemu_config=./tools/testing/kunit/qemu_configs/x86_64.py

## 运行命令行参数


kunit_tool 还有许多其他命令行参数，可能对我们的测试环境有用。以下是最常用的命令行参数：

- `--help`：列出所有可用选项。要列出常用选项，将 `--help` 放在命令之前；要列出该命令专用的选项，将 `--help` 放在命令之后。

  .. note:: 不同的命令（`config`、`build`、`run` 等）支持不同的选项。
- `--build_dir`：指定 kunit_tool 的构建目录。它包含 `.kunitconfig`、`.config` 文件以及编译后的内核。

- `--make_options`：指定传递给 make 的附加选项，用于编译内核（使用 `build` 或 `run` 命令时）。例如：要启用编译器警告，可以传入 `--make_options W=1`。

- `--alltests`：启用一组预定义的选项，以尽可能多地构建测试。

  .. note:: 已启用选项的列表可在 `tools/testing/kunit/configs/all_tests.config` 中找到。

            如果只想在依赖项其他方面已满足的情况下启用所有测试，则改为将 `CONFIG_KUNIT_ALL_TESTS=y` 添加到你的 `.kunitconfig` 中。

- `--kunitconfig`：指定 `.kunitconfig` 文件的路径或目录。例如：

  - `lib/kunit/.kunitconfig` 可以是该文件的路径。

  - `lib/kunit` 可以是该文件所在的目录。

  该文件用于以一组预定义的测试及其依赖项进行构建和运行。例如，用于运行某个给定子系统的测试。

- `--kconfig_add`：指定要追加到 `.kunitconfig` 文件的附加配置选项。例如：

```

	./tools/testing/kunit/kunit.py run --kconfig_add CONFIG_KASAN=y

```
- `--arch`：在指定架构上运行测试。架构参数与 Kbuild 的 ARCH 环境变量相同。例如：i386、x86_64、arm、um 等。非 UML 架构在 qemu 上运行。默认值为 `um`。

- `--cross_compile`：指定 Kbuild 工具链。它传入与 Kbuild 所用 `CROSS_COMPILE` 变量相同的参数。这将是工具链二进制文件（如 GCC）的前缀。例如：

  - 如果我们的系统上安装了 sparc 工具链，则为 `sparc64-linux-gnu-`。

  - 如果我们将 microblaze 工具链从 0-day 网站下载到了主目录下指定路径（名为 toolchains）的目录，则为 `$HOME/toolchains/microblaze/gcc-9.2.0-nolibc/microblaze-linux/bin/microblaze-linux`。

- `--qemu_config`：指定包含自定义 qemu 架构定义的文件路径。该文件应是一个 Python 文件，包含 `QemuArchParams` 对象。

- `--qemu_args`：指定附加的 qemu 参数，例如 `-smp 8`。

- `--jobs`：指定同时运行的作业（命令）数。默认设置为系统上的核心数。

- `--timeout`：指定允许所有测试运行的最大秒数。这不包括构建测试所花费的时间。

- `--kernel_args`：指定附加的内核命令行参数。可重复使用。

- `--run_isolated`：如果设置，则为每个独立的套件/测试单独启动内核。这对于调试非密闭（non-hermetic）测试很有用——这类测试可能根据之前运行的内容而通过/失败。

- `--raw_output`：如果设置，生成来自内核的未格式化输出。可选值有：

   - `all`：要查看完整的内核输出，使用 `--raw_output=all`。

   - `kunit`：这是默认选项，过滤到 KUnit 输出。使用 `--raw_output` 或 `--raw_output=kunit`。

- `--json`：如果设置，将测试结果以 JSON 格式存储并打印到 `stdout`，或者在指定文件名时保存到文件。

- `--filter`：指定对测试属性的过滤器，例如 `speed!=slow`。可以通过用引号包裹输入并用逗号分隔来使用多个过滤器。示例：`--filter "speed>slow, module=example"`。

- `--filter_action`：如果设置为 `skip`，被过滤的测试将在输出中显示为已跳过，而不是不显示任何输出。

- `--list_tests`：如果设置，列出将要运行的所有测试。

- `--list_tests_attr`：如果设置，列出将要运行的所有测试及其所有属性。

- `--list_suites`：如果设置，列出将要运行的所有套件。
