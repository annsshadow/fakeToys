
## 基于 Linux 内核 GPIO 的 sloppy 逻辑分析仪


:作者: Wolfram Sang

## 简介


本文档简要描述如何在隔离的 CPU 上运行基于 GPIO 的内核态 sloppy 逻辑分析仪。

sloppy 逻辑分析仪会利用系统上的若干 GPIO 输入模式引脚快速采样这些数字线，若满足奈奎斯特（Nyquist）准则，则会得到这些线上出现波形近似的时间序列日志。一种使用方式是，用导线（即数字探针）连接这些 GPIO 线来分析外部流量，充当普通的逻辑分析仪。

另一个特性是，如果这些外设的 I/O 单元在作为外设输入或输出使用的同时也能以 GPIO 输入模式使用，则可以侦听片上外设。这意味着你可以，例如，无需任何连线即可侦听 I2C 流量（前提是你的硬件支持）。在引脚控制子系统中，这类引脚控制器被称为“非严格（non-strict）”：某个引脚可以同时与某个外设以及作为 GPIO 输入线使用。

请注意，这是一个最后手段的分析仪，会受到延迟、非确定性代码路径和不可屏蔽中断的影响。它被称为“sloppy”是有原因的。然而，例如对于远程开发，它有助于获得第一印象并辅助进一步调试。

## 设置


你的内核必须启用 CONFIG_DEBUG_FS 和 CONFIG_CPUSETS。理想情况下，你的运行时环境不另作他用使用 cpusets，这样隔离一个 CPU 核心最为容易。如果你确实需要使用 cpusets，请检查 sloppy 逻辑分析仪的辅助脚本不会干扰你的其他设置。

告诉内核哪些 GPIO 用作探针。对于基于设备树（Device Tree）的系统，你需要使用以下绑定。因为这些绑定仅用于
```

    i2c-analyzer {
            compatible = "gpio-sloppy-logic-analyzer";
            probe-gpios = <&gpio6 21 GPIO_OPEN_DRAIN>, <&gpio6 4 GPIO_OPEN_DRAIN>;
            probe-names = "SCL", "SDA";
    };

```
请注意，你必须为指定的每个 GPIO 提供名称。目前最多支持 8 个探针。32 个可能可行但尚未实现。

## 用法


逻辑分析仪通过 debugfs 中的文件进行配置。但是，强烈建议不要直接使用它们，而是使用脚本 `tools/gpio/gpio-sloppy-logic-analyzer`。除了更全面地检查参数外，它还会隔离 CPU 核心，从而将测量时的干扰降到最低。

该脚本有一个 help 选项解释各参数。对于上述分析 Renesas Salvator-XS 板上 400kHz I2C 总线的 DT 片段，使用以下设置：隔离的 CPU 应为 CPU1，因为它是 big.LITTLE 配置中的大核心。由于 CPU1 是默认核心，我们不需要参数。总线速度为 400kHz。因此，采样定理告诉我们至少需要以 800kHz 采样。但是，I2C 起始条件下两个信号的下降沿发生得更快，所以我们需要更高的采样频率，例如 `-s 1500000` 即 1.5MHz。此外，我们不想立即采样，而是等待空闲总线上的起始条件。因此，我们需要将触发条件设为 SCL 保持高时 SDA 的下降沿，即 `-t 1H+2F`。最后是持续时间，这里假设 15ms，对应参数 `-d 15000`。所以，
```

    gpio-sloppy-logic-analyzer -s 1500000 -t 1H+2F -d 15000

```
请注意，该进程会把你返回到提示符，但一个子进程仍在后台采样。在它完成之前，你不会在当前或指定目录中找到结果文件。对于上述示例，我们
```

    i2cdetect -y -r <your bus number>

```
结果是一个 .sr 文件，供自由 `sigrok`_ 项目的 PulseView 或 sigrok-cli 使用。它是一个 zip 文件，同时还包含可供其他软件使用的二进制采样数据。文件名为逻辑分析仪实例名加上自 epoch 以来的时间戳。
