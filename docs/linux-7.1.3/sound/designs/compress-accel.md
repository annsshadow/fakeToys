## ALSA 协处理器加速 API


Jaroslav Kysela <perex@perex.cz>


## 概述


需要暴露能够加速用户空间各种任务（如采样率转换器、压缩流解码器等）的音频硬件。

这是对 compress ALSA API 的扩展描述，该扩展能够处理不绑定到实时操作的“任务”，并允许操作序列化。

## 要求


主要要求有：

- 用户空间多个任务的序列化，以允许在没有用户空间干预的情况下进行多个操作

- 每个操作使用独立的缓冲区（输入 + 输出）

- 使用 mmap 向用户空间暴露缓冲区

- 任务完成时通知用户空间（标准 poll 机制）

## 设计


引入了一个新的方向 SND_COMPRESS_ACCEL 来标识直通（passthrough）API。

该 API 扩展共享来自主压缩 API 的设备枚举与参数处理。所有其他实时流式 ioctl 都被停用，并引入了一组新的
与任务相关的 ioctl。直通设备不支持标准的读/写/mmap I/O 操作。

设备（“流”）状态处理被简化为 OPEN/SETUP。所有其他状态在直通模式下不可用。

数据 I/O 机制使用标准的 dma-buf 接口，具有所有优点，如 mmap、标准 I/O、缓冲区共享等。一个缓冲区用于
输入数据，第二个（独立的）缓冲区用于输出数据。每个任务有独立的 I/O 缓冲区。

对于缓冲参数，fragments 表示给定设备已分配任务的限制。fragment_size 限制给定设备的输入缓冲区大小。
输出缓冲区大小由驱动决定（可能与输入缓冲区大小不同）。

## 直通操作（ioctls）


所有操作都使用 stream->device->lock（互斥锁）保护。

### CREATE


创建一组输入/输出缓冲区。输入缓冲区大小为 fragment_size。分配唯一的 seqno。

硬件驱动为输入和输出缓冲区都分配内部的 'struct dma_buf'（使用 'dma_buf_export()' 函数）。这些缓冲区的
匿名文件描述符被传递给用户空间。

### FREE


释放一组输入/输出缓冲区。如果某个任务处于活动状态，则先执行 stop 操作。如果 seqno 为零，则对所有任务执行该操作。

### START


启动（入队）一个任务。任务启动有两种情况——在任务刚创建后。此时，origin_seqno 必须为零。
第二种情况是用于复用已经完成的任务。origin_seqno 必须标识要复用的任务。在两种情况下，都会分配一个新的
seqno 值并返回给用户空间。

前提是应用程序用新的源数据填满了输入 dma 缓冲区，并设置 input_size 以将真实数据大小传递给驱动。

数据处理的顺序被保留（最先启动的作业必须最先完成）。

如果多个任务需要状态处理（例如重采样操作），用户空间可以设置 SND_COMPRESS_TFLG_NEW_STREAM 标志来标记
新流数据的开始。这对于为新的操作保留已分配的缓冲区、而非使用打开/关闭机制很有用。

### STOP


停止（出队）一个任务。如果 seqno 为零，则对所有任务执行该操作。

### STATUS


获取任务状态（活动、已完成）。此外，驱动将设置真实的输出数据大小（输出缓冲区中的有效区域）。
