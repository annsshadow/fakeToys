
## 用于 Cirrus Logic CS35L54/56/57/63 升压智能放大器的音频驱动

                 Cirrus Logic International Semiconductor Ltd.

Contact: patches@opensource.cirrus.com

## 概述


本文档的高层摘要为：

**如果你有一台使用 CS35L54/56/57/63 放大器但音频无法工作的笔记本，请勿尝试使用另一台笔记本的固件和设置，即使那台笔记本看起来很相似。**

CS35L54/56/57/63 放大器必须按照电源电压、扬声器阻抗、扬声器最大电压/电流以及其他外部硬件连接进行正确配置。

这些放大器具备先进的升压技术，可提高驱动扬声器所用的电压；同时，专有的扬声器保护算法让这些升压放大器能够在不造成损坏的前提下把扬声器的极限推到极致。这些**必须**被正确配置。

### Cirrus Logic 支持的放大器


cs35l56 驱动支持：

- CS35L54
- CS35L56
- CS35L57
- CS35L63

内核中有两个驱动

**对于使用 SoundWire 的系统**：sound/soc/codecs/cs35l56.c 及关联文件

**对于使用 HDA 的系统**：sound/hda/codecs/side-codecs/cs35l56_hda.c

## 固件


放大器由运行在内部 DSP 上的固件控制和管理。固件文件对于启用放大器的全部能力至关重要。

固件发布于 linux-firmware 仓库：
https://gitlab.com/kernel-firmware/linux-firmware.git

在大多数 SoundWire 系统上，放大器具备产生音频的默认最低能力。但这将是：

- 低音量，以保护扬声器，因为扬声器的规格和电源电压未知。
- 左右声道的单声道混合。

在某些同时具有 CS42L43 和 CS35L56/57 的 SoundWire 系统上，CS35L56/57 的音频来自 CS42L43，而不是直接来自主机的 SoundWire 接口。这些系统可通过 dmesg 中 CS42L43 显示为 SoundWire 设备、而 CS35L56/57 显示为 SPI 来识别。在这些系统上，固件是启用从 CS42L43 接收音频的**必需**条件。

在 HDA 系统上，固件是启用 HDA 桥接模式的**必需**条件。没有固件，放大器将没有任何音频输出。

### Cirrus Logic 固件文件


每个放大器需要两个固件文件。一个文件后缀为 .wmfw，另一个后缀为 .bin。

固件由 OEM 针对每台笔记本的硬件定制，且固件专属于该笔记本。因此，linux-firmware 中针对这些放大器存在许多固件文件。固件文件在笔记本之间**不可互换**。

Cirrus Logic 会将已知笔记本的文件提交到上游 linux-firmware 仓库。只要 Cirrus Logic 知晓某台特定的笔记本，并已获得制造商发布该固件的许可，它就会被推送到 linux-firmware。你可能需要升级到更新版本的 linux-firmware 以获取你笔记本的固件。

**重要：** linux-firmware 的 Makefile 会创建 WHENCE 文件中列出的符号链接。CS35L56 驱动要能加载固件，需要这些符号链接。

#### 我该如何知道我应该拥有哪个固件文件？


所有固件文件名都带有唯一的“系统 ID”作为限定。在使用 PCI 音频的普通 x86 PC 上，这是主机 PCI 音频接口的厂商子系统 ID（SSID）。

```

  lspci -v -nn | grep -A2 -i audio
  0000:00:1f.3 Audio device [0403]: Intel Corporation Meteor Lake-P HD Audio Controller [8086:7e28]
  Subsystem: Dell Meteor Lake-P HD Audio Controller [1028:0c63]

```
在此示例中 SSID 为 10280c63。

固件文件名的格式为：

SoundWire：
    cs35lxx-b0-dsp1-misc-SSID[-spkidX]-l?u?

内核 6.16 之前发布的 CS35L56 Rev B0 SoundWire 固件：
    cs35lxx-b0-dsp1-misc-SSID[-spkidX]-ampN

非 SoundWire（HDA 与 I2S）：
    cs35lxx-b0-dsp1-misc-SSID[-spkidX]-ampN

其中：

  - cs35lxx-b0 是放大器型号与硅片版本。该信息由驱动在初始化期间记录。
  - SSID 是 8 位十六进制 SSID 值。
  - l?u? 是本文件所适用放大器在 SoundWire 总线上的物理地址。
  - ampN 是放大器编号（例如 amp1）。这与 ALSA 控制名上的前缀相同，只是文件名中始终为小写。
  - spkidX 是可选部分，用于为内部扬声器不同品牌和型号提供固件配置的笔记本。

早期的 CS35L56 Rev B0 固件使用 ALSA 前缀（ampN）作为文件名限定符。对 l?u? 限定符的支持在内核 6.16 中加入。

### Sound Open Firmware 与 ALSA 拓扑文件


所有 SoundWire 系统都需要主机 CPU 音频 DSP 的 Sound Open Firmware（SOF），以及一份 ALSA 拓扑文件（.tplg）。

SOF 固件通常由主机 CPU（即 Intel 或 AMD）的制造商提供。.tplg 文件通常是 SOF 固件发布的一部分。

SOF 二进制构建可从以下地址获取：https://github.com/thesofproject/sof-bin/releases

SOF 主源码位于：https://github.com/thesofproject

### ALSA-ucm 配置


通常还需要一份适当的 ALSA-ucm 配置文件，供用例管理器及 PipeWire 等音频服务器使用。

配置文件可从 alsa-ucm-conf 仓库获取：
https://git.alsa-project.org/?p=alsa-ucm-conf.git

#### 重要消息


Cirrus Logic CS35L56 Rev B0 OTP3 fw:3.4.4 (patched=0)
  表示驱动已能够读取放大器的设备 ID 寄存器。

    - 显示了实际的放大器类型与硅片版本（本例中为 CS35L56 B0），该值读取自放大器识别寄存器。
    - (patched=0) 是正常的，表示放大器已被硬复位，正在运行默认的 ROM 固件。
    - (patched=1) 表示此前已有内容向放大器下载了固件，而驱动无法控制 RESET 信号来替换这份预加载的固件。对于 BIOS 在 OS 启动前就向放大器下载固件的系统，这是正常的。
      如果 cs35l56 内核模块在某个驱动无法控制 RESET 的系统上被卸载并重新加载，也会看到此状态。SoundWire 系统通常不会把 RESET 的控制权交给驱动，只有 BIOS（重新）启动才能复位放大器。

DSP1: cirrus/cs35l56-b0-dsp1-misc-xxxxxxxx.wmfw
  表示找到了一个 .wmfw 固件文件并已下载。

DSP1: cirrus/cs35l56-b0-dsp1-misc-xxxxxxxx-amp1.bin
  表示找到了一个 .bin 固件文件并已下载。

Calibration applied
  将 EFI 中的出厂校准数据写入了放大器。

## 错误消息


本节解释驱动可能记录的部分错误消息。

Algorithm coefficient version %d.%d.%d but expected %d.%d.%d
  .bin 文件内容的版本与已加载固件不匹配。
  由不匹配的 .wmfw 与 .bin 文件引起，或找到了 .bin 文件但 .wmfw 文件没有。

No %s for algorithm %x
  .bin 文件内容的版本与已加载固件不匹配。
  由不匹配的 .wmfw 与 .bin 文件引起，或找到了 .bin 文件但 .wmfw 文件没有。

.bin file required but not found
  HDA 驱动没有找到与此硬件匹配的 .bin 文件。

Calibration disabled due to missing firmware controls
  驱动无法将 EFI 校准数据写入固件寄存器。
  这通常意味着：

    - 驱动没有为这块硬件找到合适的 wmfw，或
    - 放大器此前已被某内容用固件打过补丁，而驱动无法控制硬 RESET 线来复位放大器并下载它找到的固件文件。这种情况可通过内核日志中的设备识别字符串显示 "(patched=1)" 来表明。

Failed to write calibration
  与 "Calibration disabled due to missing firmware controls" 含义和原因相同。

Failed to read calibration data from EFI
  EFI 中的出厂校准数据缺失、为空或已损坏。
  最可能的原因是意外从该 EFI 文件系统中删除了该文件。

No calibration for silicon ID
  EFI 中的出厂校准数据与本硬件不匹配。
  最可能的原因是主板上的放大器被更换过，却未经过制造商的校准流程来为新放大器生成校准数据。

Did not find any buses for CSCxxxx
  仅出现在 HDA 系统上。HDA 编解码驱动找到了一个用于 Cirrus Logic 配套放大器的 ACPI 条目，但无法枚举 I2C/SPI 总线的 ACPI 条目。其最可能的原因是：

    - 相关的总线驱动（I2C 或 SPI）不属于内核的一部分。
    - HDA 编解码驱动被内建进内核，但 I2C/SPI 总线驱动是一个模块，因此 HDA 编解码驱动无法调用总线驱动的函数。

init_completion timed out
  SoundWire 总线控制器（主机端）没有枚举到放大器。
  换言之，ACPI 说有一个放大器，但出于某种原因，它在总线上未被检测到。

No AF01 node
  表示 ACPI 中存在错误。一个 SoundWire 系统应当有一个名为 "AF01" 的 Device() 节点，但没有找到它。

Failed to get spk-id-gpios
  ACPI 说驱动应当请求一个 GPIO，但驱动无法获取该 GPIO。最可能的原因是内核未包含该系统正确的 GPIO 或 PINCTRL 驱动。

Failed to read spk-id
  ACPI 说驱动应当请求一个 GPIO，但驱动无法读取该 GPIO。

Unexpected spk-id element count
  AF01 中包含的扬声器 ID GPIO 条目数超过了驱动支持的数量。

Overtemp error
  放大器过热保护被触发，放大器为防止自身受损而关闭。

Amp short error
  放大器检测到扬声器输出引脚上存在短路，并出于保护而关闭。这通常表示扬声器已损坏。

Hibernate wake failed
  驱动尝试将放大器从其省电状态唤醒，但没有看到来自放大器的预期响应。这可能由使用了与硬件不匹配的固件引起。
