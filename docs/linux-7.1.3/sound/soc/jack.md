## ASoC 插孔检测


ALSA 有一个用于表示物理插孔（jack）给用户空间的标准 API，其内核侧可见于 include/sound/jack.h。ASoC 提供了该 API 的一个版本，增加了两个额外特性：

 - 它允许多于一种插孔检测方法在同一个用户可见的插孔上协同工作。在嵌入式系统中，单个插孔上存在多个（由独立硬件位处理的）插孔是很常见的。

 - 与 DAPM 集成，允许根据检测到的插孔状态自动更新 DAPM 端点（例如，在没有耳机接入时关闭耳机输出）。

这是通过将插孔拆分为三个协同工作的部分来实现的：由 struct snd_soc_jack 表示的插孔本身、代表要更新的 DAPM 端点的 snd_soc_jack_pins 集合，以及提供插孔报告机制的代码块。

例如，一个系统可能有一个立体声耳机插孔，带有两种报告机制，一种用于耳机，一种用于麦克风。某些系统在连接耳机时将无法使用其扬声器输出，因此会希望在耳机插孔状态改变时同时更新扬声器与耳机。

## 插孔 - struct snd_soc_jack


这表示系统上的一个物理插孔，并且是对用户空间可见的部分。插孔本身是完全被动的，它由机器驱动建立，并由插孔检测机制更新。

插孔由机器驱动调用 snd_soc_jack_new() 创建。

## snd_soc_jack_pin


这些代表要根据插孔支持的某些状态位更新的 DAPM 引脚。每个 snd_soc_jack 有零个或多个这样的引脚，它们会被自动更新。它们由机器驱动创建，并使用 snd_soc_jack_add_pins() 与插孔关联。如果需要，端点状态可以配置为与插孔状态相反（例如，在未通过插孔连接麦克风时启用内置麦克风）。

## 插孔检测方法


实际的插孔检测由能够监视系统某些输入并调用 snd_soc_jack_report()（指定要更新的位子集）来更新插孔的代码完成。插孔检测代码应由机器驱动建立，获取要更新的插孔以及连接插孔时要报告的一组状态。

这通常基于 GPIO 的状态完成——snd_soc_jack_add_gpio() 函数提供了此用途的处理函数。其他方法也可用，例如集成在 CODEC 中。CODEC 集成插孔检测的一个例子可见于 WM8350 驱动。

每个插孔可以有多个报告机制，不过它至少需要一个才有用。

## 机器驱动


所有这些都由机器驱动根据系统硬件连接在一起。机器驱动将建立 snd_soc_jack 与要更新的引脚列表，然后建立一个或多个插孔检测机制，根据它们当前的状态更新该插孔。
