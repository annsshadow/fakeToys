## AD7606 驱动


面向 Analog Devices Inc. AD7606 及类似器件的 ADC 驱动。模块名`ad7606`
## 支持的设

该驱动支持以下芯片：

- `AD7605 <https://www.analog.com/en/products/ad7605.html>`_
- `AD7606 <https://www.analog.com/en/products/ad7606.html>`_
- `AD7606B <https://www.analog.com/en/products/ad7606b.html>`_
- `AD7616 <https://www.analog.com/en/products/ad7616.html>`_

## 支持的特

### SPI 接线模式


这些 ADC 可以在多SDO 线（1/2/4/8）上输出数据。该驱动目前仅支1 SDO 线
### SPI offload 接线


当与 SPI offload 配合使用时，支持的接线配置为

    +-------------+         +-------------+
    |        BUSY |-------->| TRIGGER     |
    |          CS |<--------| CS          |
    |             |         |             |
    |     ADC     |         |     SPI     |
    |             |         |             |
    |         SDI |<--------| SDO         |
    |       DOUTA |-------->| SDI         |
    |        SCLK |<--------| SCLK        |
    |             |         |             |
    |             |         +-------------+
    |      CONVST |<--------| PWM         |
    +-------------+         +-------------+

在这种情况下，需`pwms` 属性还需`#trigger-source-cells = <1>` 属性以连回 SPI offload。SPI offload 将具`trigger-sources` 属性，并带有一cell 来指busy 信号`<&ad7606 AD4695_TRIGGER_EVENT_BUSY>`

### 并行接线模式


还存在一个并行接口，具有 16 条线（在字节模式下可缩减8 条）。并行接口通过在设备树将设备声明为 platform（未定义 io-backends 节点，见下文）来选择
### IIO-backend 模式


该模式可以达到最佳的采样率，但它需要外部硬件（例如 HDL APU）来处理底层通信当在设备树中定义 "io-backends" 属性时，后端模式被启用
当前 IIO-backend 模式实现的参考配置是 ADI 提供HDL 参考：
https://wiki.analog.com/resources/eval/user-guides/ad7606x-fmc/hdl

该实现嵌入了一IIO-backend 兼容IP（adi-axi-adc）以及一个连接到转换触发引脚PWM

    +---+                                       +----------------------------
    |   |               +-------+               |AD76xx
    | A |  controls     |       |               |
    | D |-------------->|  PWM  |-------------->| cnvst
    | 7 |               |       |               |
    | 6 |               +-------+               |
    | 0 | controls  +-----------+-----------+   |
    | 6 |---------->|           |           |<--| frstdata
    |   |           | Backend   |  Backend  |<--| busy
    | D |           | Driver    |           |   |
    | R |           |           |           |-->| clk
    | I |  requests |+---------+| DMA       |   |
    | V |----------->|  Buffer ||<----      |<=>| DATA
    | E |           |+---------+|           |   |
    | R |           +-----------+-----------+   |
    |   |-------------------------------------->| reset/configuration gpios
    +---+                                       +-----------------------------

### 软件与硬件模

虽然所AD7606/AD7616 系列器件都可以使GPIO 配置，但其中一些可以使用寄存器配置
支持软件模式的芯片拥有更多可用于配置器件的值，以及更多设置，并允许按通道控制范围校准
软件模式下每个通道可用的设置如下：
 - 量程（Scale
此外，软件模式下过采样比的选择更广泛
### 转换触发


转换可以通过两种不同的方式触发：

 - 一GPIO 连接到转换触发引脚，并且GPIO 由驱动直接控制。在此配置下，驱动一旦读   所有转换，就将转换触发引脚重新置高
 - 一个外部源连接到转换触发引脚。在当前实现中，它必须是一PWM。在此配置下，驱动不直接
   控制转换触发引脚，而是可以控制 PWM 的频率。此触发器仅iio-backend 启用
### 参考电

支持 2 种可能的参考电压源
 - 内部参考（2.5V - 外部参考（2.5V
该源由设备树决定。如果存`refin-supply`，则使用外部参考，否则使用内部参考

## SPI offload 支持


为了达到最大采样率，该驱动可以`AXI SPI Engine`_ 配合使用以提SPI offload 支持

当使SPI offload 时，某些属性会不同
- `trigger` 目录被移除- 添加 `sampling_frequency` 属性用于设置采样率- `timestamp` 通道被移除- 缓冲区数据格式可能与未使offload 时不同，例如 `in_voltage0_type` 属性
## 设备缓冲

### IIO 触发缓冲

该驱动支IIO 触发缓冲区，带有“内置”触发器，即触发器由驱动分配并链接，并且一旦样本被
传输就触发一次新的转换，同时添加一个时间戳通道，以补偿中断处理延迟所引入的潜在抖动
### IIO 后端缓冲

当使IIO 后端时，不需要触发器，并且采样率被认为是稳定的。没有时间戳通道。通信被委给一个称为后端的外部逻辑，后端的驱动处理缓冲区。当启用此模式时，驱动无法控制转换引脚，
因为 busy 引脚被绑定到后端
