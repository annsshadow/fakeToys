
## AD4695 驱动


用于 Analog Devices Inc. AD4695 及类似器件的 ADC 驱动。模块名`ad4695`

## 支持的设

本驱动支持以下芯片：

- `AD4695 <https://www.analog.com/AD4695>`_
- `AD4696 <https://www.analog.com/AD4696>`_
- `AD4697 <https://www.analog.com/AD4697>`_
- `AD4698 <https://www.analog.com/AD4698>`_


## 支持的特

### SPI 接线模式


驱动目前支持以下 SPI 接线配置
##### 4 线模

在此模式下，CNV CS 连接在一起，并且只有一SDO 线

    +-------------+         +-------------+
    |          CS |<-+------| CS          |
    |         CNV |<-+      |             |
    |     ADC     |         |     HOST    |
    |             |         |             |
    |         SDI |<--------| SDO         |
    |         SDO |-------->| SDI         |
    |        SCLK |<--------| SCLK        |
    +-------------+         +-------------+

要使用此模式，在设备树中省略 `cnv-gpios` `spi-rx-bus-width` 属性
##### SPI offload 接线


SPI offload 配合使用时，支持的接线配置为

    +-------------+         +-------------+
    |    GP0/BUSY |-------->| TRIGGER     |
    |          CS |<--------| CS          |
    |             |         |             |
    |     ADC     |         |     SPI     |
    |             |         |             |
    |         SDI |<--------| SDO         |
    |         SDO |-------->| SDI         |
    |        SCLK |<--------| SCLK        |
    |             |         |             |
    |             |         +-------------+
    |         CNV |<-----+--| PWM         |
    |             |      +--| GPIO        |
    +-------------+         +-------------+

在此情况下，`cnv-gpios` `pwms` 属性都是必需的。`#trigger-source-cells = <2>` 属性也是必需的，用于连接SPI offload。SPI offload 将带`trigger-sources` 属性，其中cells 用于指示 busy 信号以及所使用GPx 引脚，例`<&ad4695 AD4695_TRIGGER_EVENT_BUSY AD4695_TRIGGER_PIN_GP0>`

### 通道配置


由于该芯片支持多种方式配置每个通道，因此必须根据实际连接到输入端的接线，在设备树中进行描述
有三种典型配置：

一`INx` 引脚用作正输入，`REFGND`、`COM` 或下一`INx` 引脚用作负输入
##### REFGND 配对


每个 `INx` 引脚都可以与 `REFGND` 引脚配合使用，作为伪差分输入。设备树将如下所示：


    channel@0 {
        reg = <0>; /** IN0 **/
    };

如果不需要其它通道属性（例如 `adi,no-high-z`），则可以完全省略该通道节点
这将IIO 总线上表现为 `voltage0` 通道。处理后的值（**raw × scale**）将`IN0` 引脚相对`REFGND` 的电压。（`REFGND` 配对时偏移量始终0。）

##### COM 配对


每个 `INx` 引脚都可以与 `COM` 引脚配合使用，作为伪差分输入。设备树将如下所示：


    com-supply = <&vref_div_2>;

    channel@1 {
        reg = <1>; /** IN1 **/
        common-mode-channel = <AD4695_COMMON_MODE_COM>;
        bipolar;
    };

这将IIO 总线上表现为 `voltage1` 通道。处理后的值（**（raw + offset× scale**）将`IN1` 引脚相对`REFGND` 测量的电压。（偏移量由 `com-supply` 电压决定。）

该宏来自

    #include <dt-bindings/iio/adc/adi,ad4695.h>

##### 配对两个 INx 引脚


一个偶数编号的 `INx` 引脚与紧随其后的奇数编号 `INx` 引脚可以用作伪差分输入。使`IN2` 作为正输入、`IN3` 作为负输入的设备树如下所示：


    in3-supply = <&vref_div_2>;

    channel@2 {
        reg = <2>; /** IN2 **/
        common-mode-channel = <3>; /** IN3 **/
        bipolar;
    };

这将IIO 总线上表现为 `voltage2` 通道。处理后的值（**（raw + offset× scale**）将`IN1` 引脚相对`REFGND` 测量的电压。（偏移量由 `in3-supply` 电压决定。）

### VCC 供电


该芯片支持通过 `VCC` 输入由外LDO 供电，或通过 `LDO_IN` 输入由内LDO 供电。驱动会查看设备树以确定当前使用的是哪一种。如果存`ldo-supply`，则使用内部 LDO；如果存`vcc-supply`，则使用外部 LDO 并禁用内LDO
### 参考电

该芯片支持通过 `REF` 输入使用外部参考电压，或通过 `REFIN` 输入使用内部缓冲参考电压。驱动会查看设备树以确定当前使用的是哪一种。如果存`ref-supply`，则使用外部参考电压并禁用内部缓冲器；如果存在 `refin-supply`，则使用内部缓冲参考电压
### 增益/偏移校准


支持通过通道的增益与偏移寄存器进行系统校准，分别使用 `calibscale` `calibbias` 属性
### 杩囬噰鏍。

当使SPI offload 时，该芯片支持每通道过采样，可用的过采样比（OSR）为 1（默认）6 64。在通道上启用过采样会将采样数据的有效位数分别提升到 17（OSR == 4）86）或 194）。这可以通过 `oversampling_ratio` 属性进行设置
设置通道的过采样比也会改变该通道的采样率，因为这需要每 1 个样本进行多次转换。具体来说，新的采样频率PWM 采样频率除以特定OSR。当设置 `oversampling_ratio` 属性时，驱动会自动进行设置。例如，如果设备当前`sampling_frequency` 10000，并且在通道 `voltage0` 上设置了 OSR 4，则该通道报告的新采样率将2500（忽PWM API 的舍入），而所有其它通道仍保10000。随后将该通道的采样频率设置到更高的值会调整所有通道CNV 触发周期，例如，如果`voltage0` 的采样频率从 2500（OSR 4）调整到 10000，则 `in_voltage0_sampling_frequency` 报告的值将10000，但所有其它通道现在将报40000
为简单起见，应在为特定通道配置过采样之前，先设置设备的采样频率（考虑要使用的最高期OSR 值）

- CRC 支持

## SPI offload 支持


为了达到最大采样率，该驱动可以`AXI SPI Engine`_ 配合使用以提SPI offload 支持


当使SPI offload 时，某些属性会有所不同
- `trigger` 目录被移除- 添加`in_voltage0_sampling_frequency` 属性用于设置采样率- 添加`in_voltage0_sampling_frequency_available` 属性用于查询最大采样率- `timestamp` 通道被移除- 缓冲数据格式可能与未使用 offload 时不同，例如 `buffer0/in_voltage0_type` 属性
## 设备缓冲

本驱动支持硬件触发缓冲区。它使用芯片的“高级定序器（advanced sequencer）”特性来触发一阵转换
另请参阅 [iio_devbuf](iio_devbuf) 以获取更通用的信息
### 缓冲读取的有效采样率


当未使用 SPI offload 时，采样率由用户在用户空间手动配置的触发器决定。当接收到触发器时，所有已启用的通道将在一阵转换中被读取
当使SPI offload 时，采样率按通道配置。所有通道将具有相同的速率，因此只需设置一`in_voltageY_sampling_frequency` 属性。由于该速率决定了每次单独转换之间的延迟，因此每个样本的有效采样率实际上是一次缓冲读取中所有已启用通道的周期之和。换句话说，它就`in_voltageY_sampling_frequency` 属性的值除以已启用通道的数量。因此，如果启用4 个通道，且 `in_voltageY_sampling_frequency` 属性被设为 1 MHz，则有效采样率为 250 kHz
启用过采样后，有效采样率还取决于分配给每个通道OSR。例如，如果前面提到4 个通道中有一个配置了 OSR 4，则该通道的有效采样率变为 MHz / 4 250 kHz。于是所有四个通道的有效采样率1 /（（3 / 1 MHz / 250 kHz））142.9 kHz。注意在此情况下“样本”指的是一次对所有已启用通道的读取（即自动定序器的一个完整周期）
