
## 工业 IIO 设备缓冲

## 1. 概述


Industrial I/O 核心提供了一种基于触发源进行连续数据采集的方式。可一次性从
`/dev/iio:deviceX` 字符设备节点读取多个数据通道，从而降CPU 负载
支持缓冲区的设备在其 `/sys/bus/iio/devices/iio:deviceX/` 目录层级下带有一额外的子目录，名bufferY，其中对于只有单个缓冲区的设备，Y 默认0
## 2. 缓冲区属

IIO 缓冲区在 `/sys/bus/iio/iio:deviceX/bufferY/` 下有一个相关联的属性目录这些属性说明如下
### ``length``（长度）


写属性，表示缓冲区能够存储的数据样本总数（容量）
### ``enable``（使能）


写属性，用于启动/停止缓冲区采集。该文件应当最后写入，即在设置 length
（长度）并选择扫描元素之后。如果给定的通道组合不被支持，写入非零值可能导错误（如 EINVAL）
### ``watermark``（水位线

写的正整数属性，指定需要等待的最大扫描元素数量
poll 将阻塞直到达到水位线
阻塞读将等待，直到请求的读取量与低水位线中的较小者可用为止
非阻塞读将检索缓冲区中可用的样本，即使样本数少于水位线。这使得应用程序能够
poll 上以超时阻塞，并在超时到期后读取可用样本，从而获得最大延迟保证
### Data available（可用数据）


只读属性，指示缓冲区中可用的数据字节数。对于输出缓冲区，这表示可用于写数据的空闲空间大小；对于输入缓冲区，这表示可供读取的数据量
### Scan elements（扫描元素）


与置于缓冲区中的通道数据相关联的元信息称扫描元素"（scan element）。扫元素的属性如下
**_en**

写属性，用于启用某个通道。当且仅当其值为非零时，触发的采集才会包含该
通道的数据样本
**_index**

只读无符号整数属性，指定通道在缓冲区中的位置。注意这些位置不依赖于哪些通道
被启用，也可能不是连续的。因此，用户态要建立完整的布局，必须结合所_en
属性来确定哪些通道存在，并结合相关_type 属性来确定数据存储格式
**_type**

只读属性，包含缓冲区中扫描元素数据存储的描述，以及由此决定的、从用户态读它的形式。格式为 [be|le]:[s|u]bits/storagebits[Xrepeat][>>shift]，其中：

- **be** **le** 指定大端或小端- **s** **u** 指定有符号（二进制补码）或无符号- **bits** 为有效数据位数- **storagebits** 为它在缓冲区中占据的位数（含填充位）- **repeat** 指定 bits/storagebits 的重复次数。当 repeat 元素0 1 时，
  repeat 值被省略- **shift** 若指定，则是在屏蔽掉未使用位之前需要施加的移位量
例如，一3 轴加速度计驱动，分辨率为 12 位，数据存放```

          7   6   5   4   3   2   1   0
        +---+---+---+---+---+---+---+---+
        |D3 |D2 |D1 |D0 | X | X | X | X | (LOW byte, address 0x06)
        +---+---+---+---+---+---+---+---+

          7   6   5   4   3   2   1   0
        +---+---+---+---+---+---+---+---+
        |D11|D10|D9 |D8 |D7 |D6 |D5 |D4 | (HIGH byte, address 0x07)
        +---+---+---+---+---+---+---+---+

```
则每个轴的扫描元素类型如下：


        $ cat /sys/bus/iio/devices/iio:device0/buffer0/in_accel_y_type
        le:s12/16>>4

用户态应用程序将把从缓冲区读取的数据样本解释为双字节小端有符号数据，在屏12 位有效数据之前需要右4 位
同样值得一提的是，缓冲区中的数据是自然对齐的，因此用户态应用程序必须相应地
处理缓冲区
以一个具有四个通道的驱动为例，其描述如下：
- channel0：index，type：be:u16/16>>0
- channel1：index，type：be:u32/32>>0
- channel2：index，type：be:u32/32>>0
- channel3：index，type：be:u64/64>>0

```

          0-1   2   3   4-7  8-11  12  13  14  15  16-23   -> buffer byte number
        +-----+---+---+-----+-----+---+---+---+---+-----+
        |CHN_0|PAD|PAD|CHN_1|CHN_2|PAD|PAD|PAD|PAD|CHN_3|  -> buffer content
        +-----+---+---+-----+-----+---+---+---+---+-----+

```
如果仅启channel0 channel3，数据将按如下方式对```

          0-1   2   3   4   5   6   7  8-15    -> buffer byte number
        +-----+---+---+---+---+---+---+-----+
        |CHN_0|PAD|PAD|PAD|PAD|PAD|PAD|CHN_3|  -> buffer content
        +-----+---+---+---+---+---+---+-----+

```
通常缓冲数据以原始格式（未缩放、未应用偏移）存在，但也存在缓冲数据以处理后形式出现的例外情况。请注意，本文档不讨论这些例外情况
完整属性说明请参见 Documentation/ABI/testing/sysfs-bus-iio
