
## N-Trig 触摸屏驱动


:Copyright: |copy| 2008-2010 Rafi Rubin <rafi@seas.upenn.edu>
:Copyright: |copy| 2009-2010 Stephane Chatty

该驱动为 N-Trig 触控笔与多点触控传感器提供支持。单点与多点触控事件会被转换为
hid 与 input 子系统对应的相应协议。触控笔事件足够符合 hid 规范，因此交由 hid
核心处理。该驱动还提供可通过 sysfs 与模块参数访问的额外过滤及辅助功能。

已有报告称该驱动可与多个同时连接的 N-Trig 设备正常工作。


### 参数


注意：在加载时设置的值是全局的，将应用于所有适用的设备。使用 sysfs 调整参数会
覆盖加载时的值，但仅针对那一个设备。

以下参数用于配置过滤器以减少噪声：

+-----------------------+-----------------------------------------------------+
|activate_slack		|开始处理事件前要忽略的手指数量                       |
+-----------------------+-----------------------------------------------------+
|activation_height,	|立即激活的尺寸阈值                                   |
|activation_width	|						      |
+-----------------------+-----------------------------------------------------+
|min_height,		|低于该尺寸时手指将被忽略；不论在决定激活期间还是     |
|min_width		|活动期间均如此                                       |
+-----------------------+-----------------------------------------------------+
|deactivate_slack	|传播活动结束事件前要忽略的“无接触”帧数               |
|			|						      |
+-----------------------+-----------------------------------------------------+

当最后一根手指离开设备时，它会发送若干空帧。通过在若干帧内暂缓去激活，我们可以
容忍错误的断开连接——即传感器可能误判某个仍然存在的手指为未接触。因此
deactivate_slack 解决的是用户在绘制时看到线条中断、或在长拖拽中丢失对象的问题。


### 额外的 sysfs 项


这些节点只是方便地提供了对设备所上报范围的访问。

+-----------------------+-----------------------------------------------------+
|sensor_logical_height, | 活动期间所上报位置的范围                             |
|sensor_logical_width   |                                                     |
+-----------------------+-----------------------------------------------------+
|sensor_physical_height,| 内部范围，不用于普通事件，但对调优很有用             |
|sensor_physical_width  |                                                     |
+-----------------------+-----------------------------------------------------+

所有产品 id 为 1 的 N-Trig 设备上报事件的范围为

- X: 0-9600
- Y: 0-7200

然而并非所有这些设备都具有相同的物理尺寸。大多数似乎是 12 英寸传感器（Dell
Latitude XT 与 XT2 以及 HP TX2），并且至少有一款型号（Dell Studio 17）具有 17
英寸传感器。物理尺寸与逻辑尺寸之比用于调整基于尺寸的过滤参数。


### 过滤


随着早期多点触控固件的发布，这些传感器容易产生错误事件变得越来越明显。用户报告
既看到了被不当丢弃的接触，也看到了虚影（ghost）——即在实际上没有手指接触屏幕的
地方上报了接触。

去激活 slack 有助于防止单点触控使用中的接触丢失，但无法解决在其它接触仍然活动时
丢失其中一个接触的问题。多点触控场景下的丢失需要额外的处理，并应与跟踪（tracking）
配合处理。

据观察，虚影接触与实际使用传感器相似，但它们似乎具有不同的特征。虚影活动通常表现
为短促的小幅触摸。因此，我假定连续事件流越长，这些事件越可能来自真实接触；而每个
接触的的尺寸越大，它越可能是真实的。为了兼顾防止虚影与快速接受真实事件（以最小化
用户可感知的延迟）这两个目标，过滤器会为传入事件累积置信度，直到达到阈值才开始
传播。为了尽量减少所存储的状态以及做出决策的操作开销，我让该决策保持简单。

时间以所上报的手指数量来衡量，而非帧数，因为多个同时发生的虚影的概率预计会随数量
增加而急剧下降。我没有以尺寸为函数累积权重，而是仅将其用作一个二值阈值。一个足够
大的接触会立即覆盖等待期并导致激活。

将激活尺寸阈值设为较大的值将导致主要依据激活 slack 来决策。如果你看到存在时间更长
的虚影，在调大激活 slack 的同时减小尺寸阈值，可能足以消除虚影，同时让屏幕对用力
点按仍相当灵敏。

即使在初始激活过滤器满足之后，接触仍会持续被 min_height 与 min_width 过滤。其
意图是提供这样一种机制：在你实际正在使用屏幕时，以额外手指的形式过滤掉虚影。在
实践中这类虚影问题要小得多或相对罕见，因此我将这两个参数的默认值都设为 0，实际
上就是关闭了该过滤器。

我不知道这些过滤器的最优取值是多少。如果默认值对你不起作用，请自行调整这些参数。
如果你发现其它取值更舒适，我将很感激你的反馈。

这些设备的校准会随时间发生漂移。如果虚影或接触丢失加重并干扰设备的正常使用，请
尝试重新校准。

### 跟踪


迄今为止，所有测试过的 N-Trig 固件都不跟踪手指。当多个接触处于活动状态时，它们
似乎主要按 Y 位置排序。
