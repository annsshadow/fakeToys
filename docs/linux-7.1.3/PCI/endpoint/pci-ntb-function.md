
## PCI NTB 功能


:Author: Kishon Vijay Abraham I <kishon@ti.com>

PCI 非透明桥（NTB，Non-Transparent Bridges）通过将每台主机作为设备暴露给另一台主机，使两个主机系统能够相互通信。NTB 通常支持在远端机器上产生中断、将内存范围作为 BAR 暴露，以及执DMA 的能力。它们还支持便签寄存器（scratchpad），NTB 内可被两台机器访问的内存区域
PCI NTB 功能通过配置端点（endpoint）实例，使得来自一个系统的事务被路由到另一个系统，从而允许两个不同的系统（或主机）相互通信
在下面的图中，PCI NTB 功能以这样一种方式配置具有多PCI 端点（EP）实例的 SoC：来自一EP 控制器的 事务被路由到另一EP 控制器。一PCI NTB 功能配置了具有多EP 实例SoC，HOST1 HOST2 就可以以 SoC 作为桥接相互通信

## 用于实现 NTB 的构

 1) 配置区域（Config Region 2) 自身便签寄存器（Self Scratchpad Registers 3) 对端便签寄存器（Peer Scratchpad Registers 4) 门铃（Doorbell，DB）寄存器
 5) 内存窗口（Memory Window，MW

### 配置区域（Config Region）：


配置区域是使NTB 端点功能驱动实现NTB 所特有的一种构造。主机端与端点端NTB 功能驱动将使用该区域相互交换信息。配置区域具有用于配置端点控制器的控状态寄存器。主机可以写入该区域来配置出站地址转换单元（ATU），并指示链路状态。端点可以在该区域中指示主机所发出命令的状态。端点还可以使用该区域向主机指示便签偏移量以及内存窗口的数量
配置区域的格式如下。这里的所有字段均32 位

	+------------------------+
	|         COMMAND        |
	+------------------------+
	|         ARGUMENT       |
	+------------------------+
	|         STATUS         |
	+------------------------+
	|         TOPOLOGY       |
	+------------------------+
	|    ADDRESS (LOWER 32)  |
	+------------------------+
	|    ADDRESS (UPPER 32)  |
	+------------------------+
	|           SIZE         |
	+------------------------+
	|   NO OF MEMORY WINDOW  |
	+------------------------+
	|  MEMORY WINDOW1 OFFSET |
	+------------------------+
	|       SPAD OFFSET      |
	+------------------------+
	|        SPAD COUNT      |
	+------------------------+
	|      DB ENTRY SIZE     |
	+------------------------+
	|         DB DATA        |
	+------------------------+
	|            :           |
	+------------------------+
	|            :           |
	+------------------------+
	|         DB DATA        |
	+------------------------+


  COMMAND:

	NTB 功能支持三条命令
	  CMD_CONFIGURE_DOORBELL (0x1)：配置门铃的命令。在调用此命令之前，主机应分配并初始MSI/MSI-X 向量（即在端点中初始MSI/MSI-X 能力）。端点在接收到此命令后，将配置出ATU，使得发往 Doorbell BAR 的事务被路由到主机编程的 MSI/MSI-X 地址。ARGUMENT 寄存器应使用要配置的 DB 数量（低 16 位）以及应配MSI 还是 MSI-X（BIT 16）来填充
	  CMD_CONFIGURE_MW (0x2)：配置内存窗口（MW）的命令。主机在分配了一个可供远端主机访问的缓冲区后调用此命令。分配的地址应编程到 ADDRESS 寄存器（64 位）中，大小应编程到 SIZE 寄存器，内存窗口索引应编程到 ARGUMENT 寄存器。端点在接收到此命令后，将配置出ATU，使得发往 MW BAR 的事务被路由到主机提供的地址
	  CMD_LINK_UP (0x3)：指示主机侧NTB 应用已绑定到 EP 设备的命令。一旦端点从两台主机都收到此命令，端点将向两台主机触发一LINK_UP 事件，以指示主机侧的 NTB 应用可以开始相互通信
  ARGUMENT:

	该寄存器的值基于在命令寄存器中发出的命令。更多信息请参阅 COMMAND 一节
  TOPOLOGY:

	主接口设置为 NTB_TOPO_B2B_USD
	次接口设置为 NTB_TOPO_B2B_DSD

  ADDRESS/SIZE:

	配置内存窗口时要使用的地址和大小。更多信息请参阅 “CMD_CONFIGURE_MW”
  MEMORY WINDOW1 OFFSET:

	内存窗口 1 和门铃寄存器打包在同一BAR 中。该区域的初始部分将包含门铃寄存器，而区域的后半部分用于内存窗口 1。该寄存器将指定内存窗口 1 的偏移量
  NO OF MEMORY WINDOW:

	指定 NTB 设备支持的内存窗口数量
  SPAD OFFSET:

	自身便签区域和配置区域打包在同一BAR 中。该区域的初始部分将包含配置区域，而区域的后半部分用于自身便签。该寄存器将指定自身便签寄存器的偏移量
  SPAD COUNT:

	指定 NTB 设备支持的便签寄存器数量
  DB ENTRY SIZE:

	用于确定DB BAR 内为触发门铃而应当写入的偏移量。EPF NTB 可以使用 MSI MSI-X 来触发门铃（稍后将添MSI-X 支持）。MSI 对所有中断使用相同的地址，MSI-X 可以为不同的中断提供不同的地址。MSI/MSI-X 地址由主机提供，其给出的地址基于主机所支持MSI/MSI-X 实现。例如，使用 GIC ITS ARM 平台对所有中断将具有相同MSI-X 地址。为了支持所有组合并MSI MSI-X 使用相同的机制，EPF NTB 为每个中断在外出站地址空间中分配一个单独的区域。该区域将被映射到主机提供的 MSI/MSI-X 地址。如果主机为所有中断提供相同的地址，则所有区域都将被转换到相同的地址。如果主机提供不同的地址，则这些区域将被转换到不同的地址。这将确保在触发门铃时没有差异
  DB DATA:

	EPF NTB 支持 32 个中断，因此32 DB DATA 寄存器。它保存为了在触发门铃中断时写入 MSI 地址而必须写入的 MSI/MSI-X 数据。这将在调用 CMD_CONFIGURE_DOORBELL 时由 EPF NTB 填充
### 便签寄存器（Scratchpad Registers）：


  每个主机NTB 端点控制器的内存中都有自己分配的一段寄存器空间。它们既可从桥的任一侧读取，也可写入。它们被构建NTB 之上的应用程序使用，可用于在设备的两侧之间传递控制和状态信息
  便签寄存器有 2 个部 1) 自身便签（Self Scratchpad）：主机自己的寄存器空间
 2) 对端便签（Peer Scratchpad）：远端主机的寄存器空间
### 门铃寄存器（Doorbell Registers）：


  门铃寄存器被主机用于相互中断
### 内存窗口（Memory Window）：


  两个主机之间的实际数据传输将使用内存窗口进行
## 构造建模（Modeling Constructs）：


为了实现 NTB 功能，需要建5 个或更多不同的区域（配置、自身便签、对端便签、门铃、一个或多个内存窗口）。至少需要一个内存窗口，但允许多于一个。所有这些区域都应映射到 BAR，以便主机访问这些区域
如果为每个区域分配一32 BAR，则方案如下所示：

======  ===============
BAR NO  CONSTRUCTS USED
======  ===============
BAR0    Config Region
BAR1    Self Scratchpad
BAR2    Peer Scratchpad
BAR3    Doorbell
BAR4    Memory Window 1
BAR5    Memory Window 2
======  ===============

然而，如果我们为每个区域分配一个单独的 BAR，在仅支64 BAR 的平台上，就不会有足够的 BAR 来覆盖所有区域
为了能被大多数平台支持，这些区域应当以一种既能提NTB 功能、又能确保主机不会访问任何它不应访问的区域的方式进行打包并映射到 BAR
EPF NTB 功能中使用以下方案：

======  ===============================
BAR NO  CONSTRUCTS USED
======  ===============================
BAR0    Config Region + Self Scratchpad
BAR1    Peer Scratchpad
BAR2    Doorbell + Memory Window 1
BAR3    Memory Window 2
BAR4    Memory Window 3
BAR5    Memory Window 4
======  ===============================

采用此方案，实现基本 NTB 功能 3 BAR 应当足够
