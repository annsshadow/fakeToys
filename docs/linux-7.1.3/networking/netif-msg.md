## NETIF 消息级别


网络接口消息级别设置的设计。

### 历史


 消息级别接口的设计受到以往实践向后兼容性的指导和约束。为了理解当前的实践
 并将其与较旧的驱动源代码相关联，了解其历史与演进是有帮助的。

 从 Linux 诞生之初，每个网络设备驱动就有一个控制调试消息级别的本地整数
 变量。消息级别从 0 到 7，冗长程度单调递增。

 级别 3 以上的消息级别并未被精确定义，但始终在指定级别的 ±1 范围内实现。
 驱动在成熟过程中往往会去掉更冗长的级别消息。

   - 0  最小消息，仅包含致命错误的基本信息。
   - 1  标准消息，初始化状态。无运行时消息
   - 2  特殊的介质选择消息，通常为定时器驱动。
   - 3  接口启动与停止，包括正常状态消息
   - 4  Tx 与 Rx 帧错误消息，以及异常的驱动操作
   - 5  Tx 数据包队列信息，中断事件。
   - 6  每个已完成的 Tx 包和收到的 Rx 包的状态
   - 7  Tx 与 Rx 数据包的初始内容

 最初，这个消息级别变量在每个驱动中都有唯一的名字，例如 “lance_debug”，
 以便内核符号调试器能够定位并修改该设置。当内核模块变得普遍后，这些变量
 被一致地重命名为 “debug”，并允许作为模块参数设置。

 这种方法运行良好。然而对额外功能的需求始终存在。多年来，以下被认为是
 合理且易于实现的增强：

   - 使用 ioctl() 调用修改级别。
   - 按接口而非按驱动设置消息级别。
   - 对发出的消息类型进行更有选择性的控制。

 netif_msg 建议以极小的复杂度和代码体积增加添加了这些特性。

 该建议包含以下几点：

  - 保留每个驱动的整型变量 “debug” 作为模块参数，默认级别为 '1'。

  - 添加一个名为 “msg_enable” 的每接口私有变量。其

```
       1 << debug

    Or more precisely::

	debug < 0 ? 0 : 1 << min(sizeof(int)-1, debug)

    Messages should changes from::

      if (debug > 1)
	   printk(MSG_DEBUG "%s: ...

    to::

      if (np->msg_enable & NETIF_MSG_LINK)
	   printk(MSG_DEBUG "%s: ...


```
