## 命令行参
如果驱动以模块方式构建，可通过在命令行中使modprobe 命令
输入以下可选参数来使用```

    modprobe e1000e [<option>=<VAL1>,<VAL2>,...]

```
此驱动所支持的系统中，每个网络端口都需要有一个对应的 <VAL#>这些值将按函数顺序应用到每个实例```

    modprobe e1000e InterruptThrottleRate=16000,16000

```
在此例中，系统中e1000e 支持的网络端口有两个除非另有说明，每个参数的默认值通常为推荐设置
注意：描述符（descriptor）描述一个数据缓冲区以及与该数据缓冲相关的属性。该信息由硬件访问
### InterruptThrottleRate

:有效范围: 0,1,3,4,100-100000
:默认 3

Interrupt Throttle Rate（中断节流速率）控制每个中断向每秒可生成的中断数量。提ITR 会以增加 CPU 利用率为代价
降低延迟，不过在某些情形下可能有助于提升吞吐量
InterruptThrottleRate 设置为大于或等于 100 的值，
会令适配器编程为每秒最多发送那么多中断，即使有更多数据包到达这会减少系统的中断负载，并能在高负载下降CPU 利用率，
但会增加延迟，因为数据包的处理速度会变慢
该驱动此前默认行为假InterruptThrottleRate 静态值为 8000为所有流量类型提供了一个良好的回退值，但在小包性能和延迟方有所不足。不过硬件每秒可处理更多小包，因此实现了一自适应中断调节算法
该驱动有两种自适应模式（设置为 1 3），在此模式下它会根收到的流量动态调InterruptThrottleRate 值。在确定上一时间段内流入流量类型后，它会InterruptThrottleRate 调整适合该流量的适当值
该算法在每个时间间隔将流入流量分类为若干类别。一旦确定类别，
InterruptThrottleRate 值会被调整以最好地适配该流量类型。定义了
三个类别：“Bulk traffic”（大流量），对应大量正常大小的数据包；
“Low latency”（低延迟），对应少量流量和/或占比较高比例的小包以及 “Lowest latency”（最低延迟），对应几乎完全是小包或极小流量
 - 0: 关闭
      关闭任何中断调节，可能改善小包延迟      然而，由于更高的中断速率会增CPU 利用率，这通常不适合
      大吞吐量流量 - 1: 动态模      此模式尝试对每个向量的中断进行调节，同时保持极低的延迟      这有时会导致额外CPU 利用率。如果计划在延迟敏感的环境中
      部署 e1000e，应考虑此参数 - 3: 动态保守模式（默认      在动态保守模式下，对于归入“Bulk traffic”类别的流量      InterruptThrottleRate 值被设为 4000。如果流量归      “Low latency”或“Lowest latency”类别，InterruptThrottleRate
      会逐步提高20000。此默认模式适用于大多数应用 - 4: 简化平衡模      在简化模式下，中断速率基于 TX RX 流量的比例。如果每      字节速率大致相等，中断速率会降至每秒低2000 个中断。如      流量主要是发送或主要是接收，中断速率会高8000 - 100-100000:
      InterruptThrottleRate 设置为大于或等于 100 的值，
      会令适配器编程为每秒最多发送那么多中断，即使有更多数据      到达。这会减少系统的中断负载，并能在高负载下降低 CPU 利用率，
      但会增加延迟，因为数据包的处理速度会变慢
注意：InterruptThrottleRate 优先TxAbsIntDelay RxAbsIntDelay 参数。换言之，最小化接收或发送绝对延迟并不会
强制控制器生成比 Interrupt Throttle Rate 所允许更多中断
### RxIntDelay

:有效范围: 0-65535 (0=关闭)
:默认 0

此值以 1.024 微秒为单位延迟接收中断的生成。如果能针对特定网络
流量正确调优，接收中断的减少可以改善 CPU 效率。增大此值会给帧
接收增加额外延迟，并可能最终降TCP 流量的吞吐量。如果系报告接收丢包，此值可能设置过高，导致驱动耗尽可用的接收描述符
警告：当RxIntDelay 设置为非 0 值时，在某些网络条件下适配器可挂起（停止发送）。如果发生这种情况，系统事件日志中会记录一NETDEV WATCHDOG 消息。此外，控制器会被自动复位，恢复网络连接为消除挂起的潜在风险，请确保RxIntDelay 设为 0
### RxAbsIntDelay

:有效范围: 0-65535 (0=关闭)
:默认 8

此值以 1.024 微秒为单位，限制生成接收中断的延迟。仅RxIntDelay
0 时此值才有用。它确保在初始数据包于设定的时间内被接收生成中断，仅RxIntDelay 0 时才有用。与 RxIntDelay 一正确调优，可在特定网络条件下改善流量吞吐量
### TxIntDelay

:有效范围: 0-65535 (0=关闭)
:默认 8

此值以 1.024 微秒为单位延迟发送中断的生成。如果能针对特定网络
流量正确调优，发送中断的减少可以改善 CPU 效率。如果系统报发送丢包，此值可能设置过高，导致驱动耗尽可用的发送描述符
### TxAbsIntDelay

:有效范围: 0-65535 (0=关闭)
:默认 32

此值以 1.024 微秒为单位，限制生成发送中断的延迟。仅TxIntDelay
0 时才有用。它确保初始数据包在线路上于设定时间内发送后生成
中断。与 TxIntDelay 一起正确调优，可在特定网络条件下改善流吞吐量
### copybreak

:有效范围: 0-xxxxxxx (0=关闭)
:默认 256

驱动会将大小小于或等于此值的所有数据包复制到一块新的接收缓冲区再将其向上传递至协议栈此参数与其他参数不同，因为它是一个单一（而非 1,1,1 等）参数应用于所有驱动实例，并且在运行时也可通过
/sys/module/e1000e/parameters/copybreak 访问```

    modprobe e1000e.ko copybreak=128

```
### SmartPowerDownEnable

:有效范围: 0,1
:默认 0（禁用）

允许 PHY 在低功耗状态下关闭。用户可以在受支持的芯片组中关闭此参数
### KumeranLockLoss

:有效范围: 0,1
:默认 1（启用）

此变通方法跳ICH8 系统初始硅版本在关机时重PHY
### IntMode

:有效范围: 0-2
:默认 0

   +-------+----------------+
   | Value | Interrupt Mode |
   +=======+================+
   |   0   |     Legacy     |
   +-------+----------------+
   |   1   |       MSI      |
   +-------+----------------+
   |   2   |      MSI-X     |
   +-------+----------------+

IntMode 允许在加载时控制驱动注册的中断类型。MSI-X 是支持多队列
所必需的，而某些内核以及内.config 选项的组合会强制使用更低级别
的中断支持```

  cat /proc/interrupts

```
### CrcStripping

:有效范围: 0,1
:默认 1（启用）

在向上传递网络栈之前，从接收到的数据包中剥离 CRC。如果您的机启用BMC，但在加载或启用驱动后无法接IPMI 流量，可尝试禁用功能
### WriteProtectNVM

:有效范围: 0,1
:默认 1（启用）

如果设为 1，配置硬件忽略对 ICHx NVM GbE 区域的所有写/擦除周期
（以防止 NVM 意外损坏）。该特性可在初始驱动加载时通过将参数设0
来禁用
注意：通过将该参数设为 0 来启NVM 写入时，必须对整个机器进断电循环（完全关开机）。一NVM 被锁定（通过驱动加载时参数为 1），
除断电循环外无法解锁
### Debug

:鏈夋晥鑼冨洿: 0-16 (0=鏃?...,16=鍏ㄩ儴)
:默认 0

此参数调整系统日志中显示的调试消息级别

## 额外特性与配置


### Jumbo Frames（巨型帧
通过把最大传输单元（MTU）更改为大于默认1500 的值来启用
Jumbo Frames 支持
使用 ifconfig 命令增大 MTU 大小。例如，输入```

    ifconfig eth<x> mtu 9000 up

```
```

    ip link set mtu 9000 dev eth<x>
    ip link set up dev eth<x>

```
此设置不会在重启后保留。可通过在以下文件中添加 'MTU=9000' 使设永久生效
- 对于 RHELetc/sysconfig/network-scripts/ifcfg-eth<x>
- 对于 SLESetc/sysconfig/network/<config_file>

注意：Jumbo Frames 的最MTU 设置8996。此值与 9018 字节最Jumbo Frames 大小一致
注意：不支持10 100 Mbps 下使Jumbo Frames，可能导性能下降或链路丢失
注意：以下适配器将 Jumbo Frames 大小的数据包限制为最4088 字节
  - Intel(R) 82578DM Gigabit Network Connection
  - Intel(R) 82577LM Gigabit Network Connection

以下适配器不支持 Jumbo Frames
  - Intel(R) PRO/1000 Gigabit Server Adapter
  - Intel(R) PRO/1000 PM Network Connection
  - Intel(R) 82562G 10/100 Network Connection
  - Intel(R) 82562G-2 10/100 Network Connection
  - Intel(R) 82562GT 10/100 Network Connection
  - Intel(R) 82562GT-2 10/100 Network Connection
  - Intel(R) 82562V 10/100 Network Connection
  - Intel(R) 82562V-2 10/100 Network Connection
  - Intel(R) 82566DC Gigabit Network Connection
  - Intel(R) 82566DC-2 Gigabit Network Connection
  - Intel(R) 82566DM Gigabit Network Connection
  - Intel(R) 82566MC Gigabit Network Connection
  - Intel(R) 82566MM Gigabit Network Connection
  - Intel(R) 82567V-3 Gigabit Network Connection
  - Intel(R) 82577LC Gigabit Network Connection
  - Intel(R) 82578DC Gigabit Network Connection

注意：如果在系统上启用了 MACSec，则无法在基82579 的网络设备上
配置 Jumbo Frames

功能需要最新版本的 ethtool。请在此处下载：

### 速率与双工配
在处理速率和双工配置问题时，您需要区分基于铜缆的适配器和基于
光纤的适配器
在默认模式下，使用铜缆连接的 Intel(R) 以太网网络适配器会尝试与其
链路对端自动协商以确定最佳设置。如果适配器无法使用自动协商与链路
对端建立链路，您可能需要手动将适配器和链路对端配置为相同的设置以建立链路并传输数据包。这仅在与不支持自动协商的旧交换机，或已强制为特定速率或双工模式的交换机建立链路时才需要。您的链路对必须匹配您选择的设置 Gbps 及以上的速率无法被强制设定。请使用
自动协商通告设置来手动为 1 Gbps 及以上速率设置设备
速率、双工和自动协商通告通过 ethtool 工具配置
警告：只有经验丰富的网络管理员才应强制设置速率和双工，或手更改自动协商通告。交换机上的设置必须始终与适配器设置匹配。如果您
将适配器配置得与交换机不同，适配器性能可能下降或无法工作
然而，使用光纤连接Intel(R) 以太网网络适配器不会尝试与其链对端自动协商，因为这些适配器仅以全双工且仅以其原生速率运行

### 启用 Wake on LAN (WoL)（网络唤醒）

WoL 通过 ethtool 工具配置
在下一次关机或重启期间，系统上将启WoL。对于此驱动版本，要启用
WoL，必须在关机或挂起系统之前加e1000e 驱动
注意：Wake on LAN 仅支持以下设备的 A 端口- Intel(R) PRO/1000 PT Dual Port Network Connection
- Intel(R) PRO/1000 PT Dual Port Server Connection
- Intel(R) PRO/1000 PT Dual Port Server Adapter
- Intel(R) PRO/1000 PF Dual Port Server Adapter
- Intel(R) PRO/1000 PT Quad Port Server Adapter
- Intel(R) Gigabit PT Quad Port Server ExpressModule
