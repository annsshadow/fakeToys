### 英特R) 以太网流导向
英特尔以太网流导向器执行以下任务
- 根据其流将接收的数据包定向到不同的队列- 对平台中的流路由进行精细控制- 匹配流与 CPU 核心以实现流亲和性- 支持多个参数以实现灵活的流分类和负载均衡（仅SFP 模式下）
注意：Linux i40e 驱动支持以下流类型：IPv4、TCPv4 UDPv4。对于给定的流类型，它支IP 地址（源或目的）UDP/TCP 端口（源和目的）的有效组合。例如，您可以只提供IP 地址、源 IP 地址加目的端口，或这四个参数中一个或多个的任意组合
注意：Linux i40e 驱动允许您使ethtool user-def mask 字段，基于用户定义的灵活双字节模式与偏移来过滤流量。用户定义的灵活过滤器仅支持 L3 L4 流类型。对于给定的流类型，在更改输入集（针对该流类型）之前，必须清除所有英特尔以太网流导向器过滤器

```
禁用 ntuple 过滤器时，所有用户编程的过滤器会从驱动缓存和硬件中刷新。重新启ntuple 时必须重新添加所有需要的过滤器

```
```

  # ethtool -N ethX flow-type tcp4 src-ip 192.168.10.1 dst-ip \

边带完美过滤器用于定向匹配指定特征的数据流量。它们通过 ethtool ntuple 接口启用。要添加
```

  ethtool -U <device> flow-type <type> src-ip <ip> dst-ip <ip> src-port <port> \

```
其中  <device> - 要编程的以太网设  <type> - 可以ip4、tcp4、udp4 sctp4
  <ip> - 要匹配的 IP 地址
  <port> - 要匹配的端口  <queue> - 要定向流量的队列1 丢弃匹配的流量）

```

  ethtool -u <device>

```
```

  ethtool -U <device> delete <N>

```
其中 <N> 是打印所有活动过滤器时显示的过滤id，也可能在添加过滤器时使"loc <N>" 指定
以下示例匹配192.168.0.1、端5300 发送的 TCP 流量```

  ethtool -U enp130s0 flow-type tcp4 src-ip 192.168.0.1 dst-ip 192.168.0.5 \
  src-port 5300 dst-port 80 action 7

```
对于每个流类型，编程的过滤器必须具有相同的匹```

  ethtool -U enp130s0 flow-type ip4 src-ip 192.168.0.1 src-port 5300 action 7
  ethtool -U enp130s0 flow-type ip4 src-ip 192.168.0.5 src-port 55 action 10

```
但是，发出接下来的两条命令是不可接受的，因为第一```

  ethtool -U enp130s0 flow-type ip4 src-ip 192.168.0.1 src-port 5300 action 7
  ethtool -U enp130s0 flow-type ip4 dst-ip 192.168.0.5 src-port 55 action 10

```
第二条命令将失败并报错。您可以使用相同字段、不同值编程多个过滤器，但在一个设备上，不能编程两个具有不同匹配字段的 tcp4 过滤器
i40e 驱动不支持匹配字段的子部分，因此不支持部分掩码字段
该驱动还支持匹配数据包载荷中的用户定义数据。此灵活数据使用 ethtool 命令"user-def" 字段按以下方式指定：

+----------------------------+--------------------------+
| 31    28    24    20    16 | 15    12    8    4    0  |
+----------------------------+--------------------------+
| offset into packet payload | 2 bytes of flexible data |
+----------------------------+--------------------------+

例如
```

  ... user-def 0x4FFFF ...

```
告诉过滤器在载荷中查4 字节并匹配该值与 0xFFFF。偏移基于载荷的开头，而不是数据包的开头。因
```

  flow-type tcp4 ... user-def 0x8BEAF ...

```
将匹TCP/IPv4 数据包，TCP/IPv4 载荷中第 8 字节处的值为 0xBEAF
注意，ICMP 头被解析4 字节头和 4 字节载荷。因此，要匹配载荷的第一个字节，您实际上必须给偏移加 4 字节。还要注意，ip4 过滤器既匹配 ICMP 帧，也匹配原始（未知）ip4 帧，其中载荷将是 IP4 帧的 L3 载荷
最大偏移为 64。硬件只会从载荷中读取最64 字节的数据。偏移必须是偶数，因为灵活数据为 2 字节长，且必须对齐到数据包载荷的字节 0
用户定义的灵活偏移也被视为输入集的一部分，不能针对同类型的多个过滤器单独编程。但是，灵活数据不是输入集的一部分，多个过滤器可以使用相同偏移但匹配不同的数据
要创建将流量定向到特定虚拟功能的过滤器，请使"action" 参数。将 action 指定64 位值，其中32 位表示队列号，接下来8 位表示哪VF```

  ... action 0x800000002 ...

```
指定将流量定向到虚拟功能 7 1）的VF 的队2
注意，这些过滤器不会破坏内部路由规则，也不会路由原本不会发送到指定虚拟功能的流量

### 速率与双工配
在解决速率和双工配置问题时，您需要区分基于铜缆的适配器和基于光纤的适配器
在默认模式下，使用铜缆连接的英特R) 以太网网络适配器会尝试与其链路伙伴自动协商以确定最佳设置。如果适配器无法使用自动协商与链路伙伴建立链路，您可能需要手动将适配器和链路伙伴配置为相同设置，以建立链路并传递数据包。这仅在尝试与不支持自动协商的旧交换机连接，或被强制为特定速率或双工模式时需要。您的链路伙伴必须匹配您选择的设置 Gbps 及以上的速率无法强制。使用自动协商通告设置手动为设备设1 Gbps 及以上速率
注意：您无法为基于英特尔(R) 以太网网络适配XXV710 的设备设置速率
速率、双工和自动协商通告通过 ethtool 工具配置
警告：只有经验丰富的网络管理员才应强制设置速率和双工，或手动更改自动协商通告。交换机上的设置必须始终与适配器设置匹配。如果您将适配器配置得与交换机不同，适配器性能可能会下降或无法工作
然而，使用光纤连接的英特尔(R) 以太网网络适配器不会尝试与链路伙伴自动协商，因为这些适配器仅以全双工且其本机速率运行

### 流控
以太网流控制（IEEE 802.3x）可通过 ethtool 配置，以启用 i40e 的接收和发送暂停帧。启用发送时，当接收数据包缓冲区超过预定义阈值时会生成暂停帧。启用接收时，发送单元会在收到暂停帧时指定的延迟时间内暂停
注意：您必须有一个支持流控制的链路伙伴
流控制默认开启
使用 ethtool 更改流控制设置
```

  ethtool -A eth? rx <on|off> tx <on|off>

```
注意：此命令仅在自动协商禁用时启用或禁用流控制。如果启用自动协商，此命令会更改用于与链路伙伴自动协商的参数
```

  ethtool -s eth? autoneg <on|off>

```
注意：流控制自动协商是链路自动协商的一部分。根据您的设备，您可能无法更改自动协商设置

### VXLAN GENEVE 叠加硬件卸载

虚拟可扩展局域网（VXLAN）允许您L2 网络扩展L3 网络之上，这在虚拟化或云环境中可能很有用。某些英特尔(R) 以太网网络设备执VXLAN 处理，将其从操作系统卸载。这降低CPU 利用率

### 每端口多功能

某些基于英特尔以太网控制X710/XL710 的适配器在单个物理端口上支持多个功能。通过系统设置/BIOS 配置这些功能
最TX 带宽是保证的数据传输带宽最小值，作为物理端口链路速度的百分比，分区将获得该带宽。分配给分区的带宽永远不会低于您指定的水平
最小带宽值的范围为：
1 到（00 减去物理端口上的分区数）1例如，如果物理端口有 4 个分区，范围将是1 到（00 - 4 1 = 97
最大带宽百分比表示分配给分区的、作为物理端口链路速度百分比的最大发送带宽。可接受的值范围为 1-100。该值用作限制器，如果您选择让任何特定功能无法消耗端100% 的带宽（如果可用）。所有最大带宽值的总和不受限制，因为端口带宽的使用永远不会超过 100%
注意：当启用每端口多功能（MFP）和 SR-IOV 时，X710/XXV710 设备无法启用最VF 数（64）。i40e 会记录一个错误，提示 "add vsi failed for VF N, aq_err 16"。要解决此问题，请启用少64 个虚拟功能（VFs）
### 数据中心桥接（DCB
DCB 是硬件中的配置服务质量实现。它使用 VLAN 优先级标签（802.1p）来过滤流量。这意味着8 种不同的优先级可供过滤。它还启用优先级流控制（802.1Qbb），可减少或消除网络压力期间丢弃的数据包数量。带宽可以分配给这些优先级中的每一个，并在硬件级别02.1Qaz）强制执行
适配器固件按802.1AB 802.1Qaz 分别实现 LLDP DCBX 协议代理。基于固件的 DCBX 代理仅在 willing 模式下运行，可以接受来自支持 DCBX 的对等端的设置。不支持通过 dcbtool/lldptool 软件配置 DCBX 参数
注意：可以通过设置私有标志 disable-fw-lldp 来禁用固LLDP
i40e 驱动实现DCB netlink 接口层，以允许用户空间与驱动通信并查询端口的 DCB 配置
注意内核假定 TC0 可用，如TC0 不可用，将禁用设备上的优先级流控制（PFC）。要解决此问题，在交换机上设DCB 时确保启TC0
### 中断速率限制

:Valid Range: 0-235 (0=无限

英特R) 以太网控制器 XL710 系列支持中断速率限制机制。用户可以通过 ethtool 控制中断之间的微秒数
```

  # ethtool -C ethX rx-usecs-high N

```
0-235 微秒的范围提供了每秒 4,310 250,000 次中断的有效范围。rx-usecs-high 的值可以与同一 ethtool 命令中的 rx-usecs tx-usecs 独立设置，并且也独立于自适应中断调节算法。底层硬件支4 微秒间隔的粒度，因此相邻的值可能导致相同的中断速率
```

  # ethtool -C ethX adaptive-rx off adaptive-tx off rx-usecs-high 20 rx-usecs \
    5 tx-usecs 5

```
上述命令将禁用自适应中断调节，并允许在指示接收或发送完成之前最5 微秒。但是，它不是产生多达每200,000 次中断，而是通过 rx-usecs-high 参数将每秒总中断数限制50,000

### 应用设备队列（ADq
应用设备队列（ADq）允许您将一个或多个队列专用于特定应用程序。这可以降低指定应用程序的延迟，并允许按应用程序Tx 流量进行速率限制。按照以下步骤设ADq
1. 创建流量类（TCs）。每个接口最多可创建 8 TC。shaper bw_rlimit 参数是可选的
示例：设置两tc，tc0 tc1，每16 个队列，tc0 最tx 速率设为 1Gbit，tc1 设为 3Gbit
```

  # tc qdisc add dev <interface> root mqprio num_tc 2 map 0 0 0 0 1 1 1 1
  queues 16@0 16@16 hw 1 mode channel shaper bw_rlimit min_rate 1Gbit 2Gbit
  max_rate 1Gbit 3Gbit

```
map：最16 个优先级tc 的优先级映射（例map 0 0 0 0 1 1 1 1 将优先级 0-3 设为使用 tc0-7 设为使用 tc1
queues：对于每tcnum queues>@<offset>（例queues 16@0 16@16 16 个队列分配给偏移 0 tc06 个队列分配给偏移 16 tc1。所tc 的队列总数最大为 64 或核心数，取较小者。）

hw 1 mode channelhw' 设为 1 'channel' mqprio 中一个新的硬件卸载模式，充分利用 mqprio 选项、TC、队列配置和 QoS 参数
shaper bw_rlimit：对于每tc，设置最小和最大带宽速率。总计必须小于或等于端口速度
例如：min_rate 1Gbit 3Gbit：使`ifstat` `sar -n DEV [interval] [number of samples]` 等网络监控工具验证带宽限
```

    # ethtool -K <interface> hw-tc-offload on

```
```

    # tc qdisc add dev <interface> ingress

```
注意事项 - 所tc 命令iproute2 <pathtoiproute2>/tc/ 目录运行 - ADq 与云过滤不兼容 - 当使mqprio 配置 TC 时，不支持通过 ethtool（ethtool -L）设置通道 - 您必须拥有最新版本的 iproute2
 - 需NVM 版本 6.01 或更高 - 当启用以下任何功能时，无法启ADq：数据中心桥接（DCB）、每端口多功能（MFP）或边带过滤器 - 如果另一个驱动（例如 DPDK）已设置云过滤，您无法启ADq - ADq 不支持隧道过滤器。如果封装数据包以非隧道模式到达，将在内部头进行过滤。例如，对于非隧道模式的 VXLAN 流量，PCTYPE 被识别为 VXLAN 封装数据包，外部头被忽略。因此匹配内部头 - 如果 PF 上的 TC 过滤器匹配通过 VF（在 PF 上）的流量，该流量将被路由到 PF 的适当队列，而不会传递给 VF。此类流量会TCP/IP 栈更上层被丢弃，因为它不匹配 PF 地址数据 - 如果流量匹配指向不同 TC 的多TC 过滤器，该流量将被复制并发送到所有匹配的 TC 队列。硬件交换机在匹配多个过滤器时将数据包镜像到 VSI 列表

### 设备驱动DPDK 共享设备时的意外问题

i40e 设备处于多驱动模式，且内核驱动与 DPDK 驱动共享设备时，可能会出现意外问题。这是因为多个驱动之间对全局 NIC 资源的访问未同步。对全局 NIC 配置的任何更改（写入全局寄存器、通过 AQ 设置全局配置，或更改交换机模式）将影响设备上的所有端口和驱动。使"multi-driver" 模块参数加载 DPDK 可能会缓解其中部分问题
### 在交换机上设DCB 时必须启TC0

内核假定 TC0 可用，如TC0 不可用，将禁用设备上的优先级流控制（PFC）。要解决此问题，在交换机上设DCB 时确保启TC0
