### AutoNeg


（仅支持使用铜缆连接的适配器）

:有效范围:   0x01-0x0F, 0x20-0x2F
:默认 0x2F

该参数是一个位掩码，用于指定适配器通告的速率与双工设置。使用此参数时，
不得再指Speed Duplex 参数
注意       有关 AutoNeg 参数的更多信息，请参阅本文档的速率与双工一节
### Duplex


（仅支持使用铜缆连接的适配器）

:有效范围:   0-2 (0=自动协商, 1=半双 2=全双
:默认 0

该参数定义了允许数据流动的方向，可以为单向或双向。如Duplex 与链路对均设置为自动协商，网卡将自动检测正确的双工模式。如果链路对端被强制指定
（全双工或半双工），Duplex 默认为半双工
### FlowControl


:有效范围:   0-3 (0= 1=仅接 2=仅发 3=接收&发
:默认 EEPROM 中读取流控设
该参数控制以太网 PAUSE 帧的自动生成（Tx）与响应（Rx）
### InterruptThrottleRate


（Intel(R) 825422543 82544 系列适配器不支持
:有效范围:
   0,1,3,4,100-100000 (0=关闭, 1=动 3=动态保
   4=简化平
:默认 3

驱动可以限制适配器为接收数据包每秒生成的 interrupts 数量。其实现方式是向
适配器写入一个基于适配器每秒最多可生成 interrupts 数量的值
InterruptThrottleRate 设置为大于或等于 100 的值，会令适配器编程为每秒
最多发出该数量interrupts，即使有更多数据包到达也是如此。这可降低系统上中断负载，并能在高负载下降低 CPU 占用率，但会因数据包处理不够及时而增延迟
驱动此前的默认行为假InterruptThrottleRate 为固定的 8000，这能为所有流类型提供一个不错的回退值，但在小包性能和延迟方面有所欠缺。然而硬件每秒可
处理更多的小包，因此实现了一套自适应的中断调节算法
7.3.x 起，驱动提供两种自适应模式（设置值为 1 3），会根据接收的流量
动态调InterruptThrottleRate 值。在确定上一时间段内输入流量的类型后，它InterruptThrottleRate 调整为一个适合于该流量的值
该算法在每个间隔将流入流量分类为若干类别。一旦确定类别，便将
InterruptThrottleRate 值调整至最契合该流量类型。共定义了三个类别：“Bulk
traffic（大流量）”，对应大量正常大小的数据包；“Low latency（低延迟）”，
对应少量流量或占比较高比例的小包；以“Lowest latency（最低延迟）”，
对应几乎全部为小包或极少量流量
在动态保守模式下，落入“Bulk traffic”类别的流量InterruptThrottleRate 被设4000。如果流量落入“Low latency”或“Lowest latency”类别，InterruptThrottleRate 会逐级提升20000。此默认模式适用于大多数应用
对于集群或网格计算等延迟至关重要的场景，可将算法设置为模1 以进一步降延迟。在此模式下（与模式 3 工作方式相同），对于“Lowest latency”类别的
流量，InterruptThrottleRate 将被逐级提升70000
在简化模式下，中断速率基于 TX RX 流量的比例。如果每秒字节速率大致相等中断速率最低可降至每秒 2000 interrupts。如果流量以发送为主或以接收为主，
中断速率最高可8000
InterruptThrottleRate 设为 0 会关闭任何中断调节，可能改善小包延迟，但
通常不适合大吞吐量流量
注意       InterruptThrottleRate 优先TxAbsIntDelay RxAbsIntDelay 参数       换言之，即使将接收和/或发送的绝对延迟降至最小，也不会强制控制器
       生成超过 Interrupt Throttle Rate 所允许数量interrupts
警告          如果您使用的Intel(R) PRO/1000 CT 网络连接（控制器 82547），
          在某些网络条件下，将 InterruptThrottleRate 设置为大75,000 的          可能导致适配器挂起（停止发送）。如果发生此情况，系统事件日志中          记录一NETDEV WATCHDOG 消息。此外，控制器会自动复位以恢复网          连接。为消除挂起的可能，请确InterruptThrottleRate 不大75,000
          且不要设置为 0
注意       e1000 以默认设置加载且同时使用多个适配器时，CPU 占用率可能会
       非线性地增加。为了在不影响总体吞吐量的前提下限CPU 占用率，建议
       您按如下方式加载驱动```
           modprobe e1000 InterruptThrottleRate=3000,3000,3000

       这将第一、第二和第三个驱动实例的 InterruptThrottleRate 设为每秒 3000
       interrupts。每2000 3000 interrupts 的范围适用于大多数系统       是一个不错的起点，但最优值取决于具体平台。如CPU 占用率不是问题，
       可使RX_POLLING (NAPI) 及驱动默认设置
```
### RxDescriptors


:有效范围:
 - 基于 82542 82543 的适配器：48-256
 - 其他所有受支持适配器：48-4096
:默认 256

该值指定了驱动分配的接收缓冲区描述符数量。增大该值可让驱动缓冲更多入数据包，代价是增加系统内存占用
每个描述符为 16 字节。同时为每个描述符分配一个接收缓冲区，大小可20484096192 16384 字节，取决于 MTU 设置。最MTU 大小16110
注意       MTU 指定帧大小。仅在对 Jumbo Frames（巨型帧）进行设置时才需要修改       根据可用的系统资源，对更多接收描述符的请求可能会被拒绝。此时请
       使用一个较小的值
### RxIntDelay


:有效范围:   0-65535 (0=关闭)
:默认 0

该值以 1.024 微秒为单位延迟接收中断的生成。针对特定网络流量适当调优后，
接收中断的减少可提升 CPU 效率。增大该值会给帧接收增加额外延迟，并可能
最终导TCP 流量吞吐量下降。如果系统报告接收丢弃，可能是该值设置过高，
导致驱动耗尽可用接收描述符
警告          RxIntDelay 设置为非 0 值时，在某些网络条件下适配器可能挂          （停止发送）。如果发生此情况，系统事件日志中会记录一NETDEV
          WATCHDOG 消息。此外，控制器会自动复位以恢复网络连接。为消除挂起          可能，请确保 RxIntDelay 设置0
### RxAbsIntDelay


（该参数仅受 825402545 及后续适配器支持。）

:有效范围:   0-65535 (0=关闭)
:默认 128

该值以 1.024 微秒为单位，限制生成接收中断的延迟。仅RxIntDelay 非零才有用，它确保在初始数据包于设定时间内被接收后生成一个中断。结RxIntDelay
适当调优，可在特定网络条件下提升流量吞吐量
### Speed


（该参数仅受使用铜缆连接的适配器支持。）

:有效设置: 0, 10, 100, 1000
:默认  0 (在所有受支持速率上自动协

Speed 将线路速率强制为指定的兆比特每秒（Mbps）值。如果未指定该参数或将其
设为 0，且链路对端设置为自动协商，网卡将自动检测正确的速率。当 Speed 设置10 100 时，也应设置 Duplex
### TxDescriptors


:有效范围:
  - 基于 82542 82543 的适配器：48-256
  - 其他所有受支持适配器：48-4096
:默认 256

该值为驱动分配的发送描述符数量。增大该值可让驱动排队更多发送请求。每描述符为 16 字节
注意       根据可用的系统资源，对更多发送描述符的请求可能会被拒绝。此时请
       使用一个较小的值
### TxIntDelay


:有效范围:   0-65535 (0=关闭)
:默认 8

该值以 1.024 微秒为单位延迟发送中断的生成。针对特定网络流量适当调优后，
发送中断的减少可提CPU 效率。如果系统报告发送丢弃，可能是该值设置过高，
导致驱动耗尽可用发送描述符
### TxAbsIntDelay


（该参数仅受 825402545 及后续适配器支持。）

:有效范围:   0-65535 (0=关闭)
:默认 32

该值以 1.024 微秒为单位，限制生成发送中断的延迟。仅TxIntDelay 非零才有用，它确保在初始数据包于设定时间内发送到线路上后生成一个中断。结TxIntDelay 适当调优，可在特定网络条件下提升流量吞吐量
### XsumRX


（基82542 的适配器不支持该参数。）

:有效范围:   0-1
:默认 1

'1' 表示驱动应为接收到的数据包（包括 UDP TCP）启IP 校验和卸载到
适配器硬件
### Copybreak


:有效范围:   0-xxxxxxx (0=关闭)
:默认 256
:用法: modprobe e1000.ko copybreak=128

驱动会将大小小于或等于此值的所有数据包复制到一个新RX 缓冲区后，再向上
递交给协议栈
该参数与其他参数不同，它是单个（而非 1,1,1 等）应用于所有驱动实例的参数并且在运行时也可通过以下路径访问/sys/module/e1000/parameters/copybreak

### SmartPowerDownEnable


:有效范围: 0-1
:默认  0 (禁用)

允许 PHY 在较低功耗状态下关闭。用户可在受支持的芯片组上关闭此参数
## 速率与双工配

使用三个关键字来控制速率与双工配置。这些关键字Speed、Duplex AutoNeg
如果网卡使用光纤接口，这些关键字将被忽略，光纤接口网卡仅1000 Mbps 全双链路
对于使用铜缆的网卡，这些关键字的交互如下
- 默认操作为自动协商。网卡通告所有受支持的速率与双工组合，并且当链路对  设置为自动协商时，将以最高的公共速率与双工模式建立链路
- 如果 Speed = 1000，则启用有限自动协商，且仅通告 1000 Mbps000BaseT 规范
  要求自动协商）
- 如果 Speed = 10 100，则 Speed Duplex 都应被设置。自动协商被禁用  AutoNeg 参数被忽略。链路对端也应被强制指定
AutoNeg 参数用于需要对自动协商过程进行更多控制的情况。当您希望控制在自动
协商过程中通告哪些速率与双工组合时，应使用它
该参数可以指定为十进制或十六进制值，由下面的位图决定
============== ====== ====== ======= ======= ====== ====== ======= ======
位位          7      6      5       4       3      2      1       0
十进制        128    64     32      16      8      4      2       1
鍗佸叚杩涘埗鍊?      80     40     20      10      8      4      2       1
速率 (Mbps)     N/A    N/A    1000    N/A     100    100    10      10
鍙屽伐                             鍏ㄥ弻宸?          鍏ㄥ弻宸? 鍗婂弻宸? 鍏ㄥ弻宸?  鍗婂弻宸?============== ====== ====== ======= ======= ====== ====== ======= ======

```
  modprobe e1000 AutoNeg=0x01 (限制自动协商10 半双
  modprobe e1000 AutoNeg=1 (同上)
  modprobe e1000 AutoNeg=0x02 (限制自动协商10 全双
  modprobe e1000 AutoNeg=0x03 (限制自动协商10 半双工或 10 全双
  modprobe e1000 AutoNeg=0x04 (限制自动协商100 半双
  modprobe e1000 AutoNeg=0x05 (限制自动协商10 半双工或 100 半双
  modprobe e1000 AutoNeg=0x020 (限制自动协商1000 全双
  modprobe e1000 AutoNeg=32 (同上)

```
注意，使用此参数时，不得指定 Speed Duplex
如果链路对端被强制为特定速率与双工，则不应使用此参数。相反，应使用前提到Speed Duplex 参数将适配器强制为相同的速率与双工
## 其他配置


### Jumbo Frames（巨型帧

  Jumbo Frames 支持通过MTU 更改为大于默1500 的值来启用。使ifconfig
  命令来增MTU 大小```
       ifconfig eth<x> mtu 9000 up

  该设置不会在重启后保留。如果您将：

       MTU=9000

  添加到文/etc/sysconfig/network-scripts/ifcfg-eth<x> 中，则可使其永久生效  此示例适用Red Hat 发行版；其他发行版可能将此设置保存在不同位置
```
注意 在某Jumbo frames 环境中可能会观察到吞吐量性能下降。如果观察到这种情况 增大应用程序的套接字缓冲区大小和/或增/proc/sys/net/ipv4/tcp_*mem 条目 可能有所帮助。详见具体应用程序手册及 /usr/src/linux*/Documentation/
 networking/ip-sysctl.txt銆。
  - Jumbo Frames 的最MTU 设置16110。该值与最Jumbo Frames 大小 16128
    相对应
  - 10 100 Mbps 下使Jumbo frames 不受支持，并可能导致性能下降    链路丢失
  - 基于 Intel(R) 82542 82573V/E 控制器的适配器不支持
```
     Intel(R) PRO/1000 Gigabit Server Adapter
     Intel(R) PRO/1000 PM Network Connection

```
### ethtool


  驱动利用 ethtool 接口进行驱动配置与诊断，并显示统计信息。此功能需  ethtool 1.6 或更高版本
  最新发布的 ethtool 可从以下地址获取  https://www.kernel.org/pub/software/network/ethtool/

### 启用局域网唤醒 (WoL)


  WoL 通过 ethtool 工具进行配置
  WoL 将在系统下一次关机或重启时启用。对于此驱动版本，要启用 WoL，必须在
  关机或重启系统时加载 e1000 驱动
