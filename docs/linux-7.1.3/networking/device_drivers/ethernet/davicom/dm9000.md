### 简

本文件描述了如何使用位于 drivers/net/dm9000.c drivers/net/dm9000.h
文件中的、基于平台设备（platform-device）的 DM9000 网络驱动
该驱动支持三DM9000 变体：最先被支持DM9000E，以及较新的
DM9000A DM9000B 器件。目前由 Ben Dooks 维护并测试，任何针对
该驱动的补丁都应当抄送（CC）给他
### 定义平台设备


附着在平台设备上的最小资源集合如下：

    1) 地址寄存器的物理地址
    2) 数据寄存器的物理地址
    3) 设备中断引脚所连接IRQ 线
这些资源应按该顺序指定，因为两个地址区域的顺序很重要
（驱动期望先是地址，再是数据）
```

  static struct resource bast_dm9k_resource[] = {
	[0] = {
		.start = S3C2410_CS5 + BAST_PA_DM9000,
		.end   = S3C2410_CS5 + BAST_PA_DM9000 + 3,
		.flags = IORESOURCE_MEM,
	},
	[1] = {
		.start = S3C2410_CS5 + BAST_PA_DM9000 + 0x40,
		.end   = S3C2410_CS5 + BAST_PA_DM9000 + 0x40 + 0x3f,
		.flags = IORESOURCE_MEM,
	},
	[2] = {
		.start = IRQ_DM9000,
		.end   = IRQ_DM9000,
		.flags = IORESOURCE_IRQ | IORESOURCE_IRQ_HIGHLEVEL,
	}
  };

  static struct platform_device bast_device_dm9k = {
	.name		= "dm9000",
	.id		= 0,
	.num_resources	= ARRAY_SIZE(bast_dm9k_resource),
	.resource	= bast_dm9k_resource,
  };

```

注意bast_dm9k_resource[^2^].flags 中设IRQ 触发标志因为如果缺失该标志将会产生警告。注IRQ 处理程序时，
flags 字段中的触发方式会被传递给 request_irq()，以确保
IRQ 被正确设置
这展示了一个典型的平台设备，没有提供可选的配置平台数据下一个示例使用相同的资源，但增加
```

  static struct dm9000_plat_data bast_dm9k_platdata = {
	.flags		= DM9000_PLATF_16BITONLY,
  };

  static struct platform_device bast_device_dm9k = {
	.name		= "dm9000",
	.id		= 0,
	.num_resources	= ARRAY_SIZE(bast_dm9k_resource),
	.resource	= bast_dm9k_resource,
	.dev		= {
		.platform_data = &bast_dm9k_platdata,
	}
  };

```

平台数据定义include/linux/dm9000.h 中，并在下文中描述
### 平台数据


DM9000 的额外平台数据可以描述到设备IO 总线宽度是否连接了外PHY，以及是否存在外部配EEPROM
平台数据 .flags 字段的标志如下：

DM9000_PLATF_8BITONLY

	IO 应使8 位操作完成
DM9000_PLATF_16BITONLY

	IO 应使16 位操作完成
DM9000_PLATF_32BITONLY

	IO 应使32 位操作完成
DM9000_PLATF_EXT_PHY

	芯片连接到一个外PHY
DM9000_PLATF_NO_EEPROM

	这可用于表示板子没有 EEPROM	或EEPROM 应对用户隐藏
DM9000_PLATF_SIMPLE_PHY

	切换到使用更简单的 PHY 轮询方法，该方法不会
	定期尝试读取 MII PHY 状态。仅	使用内部 PHY 时可用。更多信息请参见链路状态轮询一节
	配置符号 DM9000_FORCE_SIMPLE_PHY_POLL，即 Kconfig 条目
	“Force simple NSR based PHY polling”，允许在构建时
	强制启用该标志
### PHY 链路状态轮

驱动跟踪链路状态，并向网络核心
告知链路（carrier）的可用性。这由若干方法管理，
具体取决于芯片版本以及所使用PHY
对于内部 PHY，原始（也是当前默认）方法是
读取 MII 状态，要么在状态变化时（如果我们拥有芯片中
必要的中断支持），要么通过周期性定时器每两秒一次
为了减少内部 PHY 的开销，现在可以选择
使用 DM9000_FORCE_SIMPLE_PHY_POLL 配置，或 DM9000_PLATF_SIMPLE_PHY
平台数据选项来读取摘要信息，而无需
代价高昂MII 访问。这种方法更快，但打印的
信息较少
当使用外PHY 时，驱动当前必须轮询 MII
链路状态，因为没有在链路变化时获取中断的方法
### DM9000A / DM9000B


这些芯片在功能上类似DM9000E，并由同一驱动轻松
支持。其特性为
   1) 内部 PHY 状态变化时产生中断。这意味着在使      内部 PHY 时，可以禁用这些器件PHY 状态的周期性轮询
   2) TCP/UDP 校验和卸载，当前驱动尚不支持
### ethtool


该驱动支ethtool 接口，用于访问驱状态信息、PHY 状态以EEPROM
