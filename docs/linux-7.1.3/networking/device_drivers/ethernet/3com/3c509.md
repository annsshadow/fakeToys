## 简

以下是关于在 Linux 中使3Com EtherLink III 系列以太网卡的说明和信息。这些卡通常
以使用最广泛的卡3Com 型号编号 3c509 来称呼。它们都10mb/s ISA 总线卡，不应
（但有时会被）与编号相似PCI 总线"3c905"（又"Vortex" "Boomerang"）系列混淆3c509 系列的内核支持由模块 3c509.c 提供，其中包含支持以下所有型号的代码
 - 3c509（原ISA 卡）
 - 3c509B（ISA 卡的后期修订版；支持全双工）
 - 3c589（PCMCIA - 3c589Bc589 的后期修订版；支持全双工 - 3c579（EISA
本文档的很大一部分大量借用3c509 驱动原作Donald Becker 所写的指南。该文档主副本包含关于驱动旧版本的说明，目前位于 Scyld Web 服务器上：http://www.scyld.com/

## 驱动的特定特

覆盖卡的默认设置

驱动允许在启动或加载时覆盖检测到IOADDR、IRQ 和收发器（transceiver）设置，尽管
这种能力通常并不需要，除非要启用全双工模式（见下文）。语法示例如```

    ether=10,0x310,3,0x3c509,eth0

```
这将第一张被找到3c509 卡配置为 IRQ 10、基址 I/O 0x310 和收发器类型 30base2）必须设置标志 "0x3c509" 以避免在覆盖 I/O 地址时与其他卡类型冲突。当驱动作为模块加载时，
只能覆盖 IRQ。例如，将两张卡分别设置IRQ10 IRQ11，可以通过使用 irq 模块参数完成
```

   options 3c509 irq=10,11


```
## 全双工模

v1.18c 驱动增加了对 3c509B 全双工能力的支持。为了启用并成功使用全双工模式，必须满足
三个条件
(a) 你必须拥有一块硬件支持全双工操作EtherLink III 卡。目前，3c509 系列中已确认支持
全双工的只有 3c509B（ISA 总线）和 3c589B（PCMCIA）卡。没B"型号标识的卡***支持
全双工模式；这些包括原始3c509（无" B"）、原始的 3c589c529（MCA 总线）和 3c579
（EISA 总线）
(b) 你必须使用卡10baseT 收发器（RJ-45 连接器），而不是其 AUI（粗缆网）或 10base2
（细缆网/同轴）接口。AUI 10base2 网络电缆在物理上不支持全双工操作
(c) 最重要的是，你3c509B 必须连接到一个自身支持全双工的链路对端（link partner）这几乎肯定是以下两种情况之一：一台支持全双工的以太网交换机（**不是**集线器），或通过交叉线直接连接到 3c509B 的另一台系统上支持全双工的 NIC
可以使用 'ethtool' 启用全双工模式

  关于全双工模式极重要的警
  要理解，3c509B 硬件对全双工的支持要比更现代的网络接口卡所提供的支持有限得多。尽  在网络物理层上它完全支持全双工操作，但该卡是在当前的以太网自动协商（N-way）规  撰写之前设计的。这意味着 3c509B 系列***在任何情况下都无法也不会与其链路对端自动
  协商出全双工连接，无论它如何被初始化***。如果启用了 3c509B 的全双工模式，其链路
  对端也很可能需要被独立地_强制_进入全双工模式；否则会发生各种严重的故障——至少，你会
  看到大量的数据包冲突。这是极少数需要或希望禁用自动协商并强制设置网卡或交换机双  模式的情形之一

## 可用的收发器类型


对于驱动版本 v1.18c 及更高版本，可用的收发器类型如下
== =========================================================================
0  来自 EEPROM 配置的收发器类型（通常10baseT）；强制半双1  AUI（粗缆网 / DB15 连接器）
2  （未定义3  10base2（细缆网 == 同轴 / BNC 连接器）
4  10baseT（RJ-45 连接器）；强制半双工模式
8  收发器类型和双工模式取自卡的 EEPROM 配置设置
12 10baseT（RJ-45 连接器）；强制全双工模式
== =========================================================================

在驱动版1.18c 之前，仅支持收发器代0-4。注意，新的收发器代8 12 *
唯一**能够启用全双工模式的代码，无论卡检测到EEPROM 设置是什么。这确保了仅仅将驱动
从早期版本升级，绝不会在现有安装中自动启用全双工模式；它必须始终通过这些代码之一显式
启用才能被激活
收发器类型可以使'ethtool' 更改

### 错误消息与常见问题的解读


##### 错误消息


eth0: Infinite loop in interrupt, status 2011.
这些基本无害"的消息，表明驱动在该中断周期内工作量过大。状0x2011 表示你接收数据包
的速度快于它们从卡中被取走的速度。这在正常操作中应当很少见或不发生。导致此错误报告可能原因有：

   - 启用了某绿色"模式，在没有键盘活动时会降低处理器速度
   - 其他某个设备或设备驱动占用了总线或禁用了中断。检/proc/interrupts 是否中断
     计数过多。定时器滴答（timer tick）中断应当总是比其他中断增长得更快
##### 收不到数据包


如果一3c509c562 3c589 能够成功发送数据包，但从未接收数据包（/proc/net/dev
'ifconfig' 所报告），你很可能遇到了中断线问题。检/proc/interrupts 以确认卡确实产生中断。如果中断计数没有增长，你很可能遇到了两个设备试图使用同一 ISA IRQ 线的物理
冲突。常见的冲突是与 IRQ10 IRQ5 上的声卡发生冲突，最简单的解决办法是将 3c509 移到
不同的中断线。如果设备正在接收数据包'ping' 不工作，你遇到了路由问题
##### /proc/net/dev 中报告的 Tx 载波错误


如果一EtherLink III 看起来在发送数据包，但 /proc/net/dev 中的 "Tx carrier errors"
字段Tx 数据包计数增长得一样快，你很可能遇到了未端接（unterminated）的网络，或选择不正确的介质收发器
##### 在带ISA PnP BIOS 的机器上检测不3c509B 

虽然更新后的驱动能与大多PnP BIOS 程序配合工作，但并非所有都能。这可以通过使用 3Com
提供的设置程序禁PnP 支持来修复
##### 在超频机器上检测不3c509 

id_read_eeprom() 中的延迟时间从当前500 增加到极高的值，例如 5000

### 状态与错误消息的解


主状态寄存器中的位含义为
=====	======================================
value 	描述
=====	======================================
0x01 	中断锁存
0x02 	Tx 溢出，或 Rx 欠载
0x04 	Tx 完成
0x08 	Tx FIFO 有可用空0x10 	一个完整的 Rx 数据包已到达
0x20 	一Rx 数据包已开始到0x40 	驱动已请求了一次中0x80 	统计计数器接近满
=====	======================================

发送（Tx）状态字中的位含义为
=====	============================================
value	描述
=====	============================================
0x02	窗口外冲突（Out-of-window collision）0x04	状态栈溢出（通常不可能发生）0x08	16 次冲突0x10	Tx 欠载（PCI 总线带宽不足）0x20	Tx 超时（jabber）0x40	已请Tx 中断0x80	状态有效（该位应始终被设置）=====	============================================


```

   eth0: Transmit error, Tx status register 82

```
这里通常看到的两种值为
##### 0x82


窗口外冲突。这通常发生于其他某个以太网主机在半双工网络上被错误地设置为全双工时
##### 0x88


16 次冲突。这通常发生于网络异常繁忙，或另一个主机在冲突后没有正确退避时。如果此错误
0x82 错误混合出现，则是一台被错误设置为全双工的主机所致（见上文）
这两种错误都是应当被纠正的网络问题的结果。它们并不代表驱动故障
