## 1. Cirrus Logic LAN CS8900/CS8920 以太网适配器


## 1.1. 产品概述


Cirrus Logic 基于 CS8900 的 ISA 以太网适配器遵循 IEEE 802.3 标准，并在 10 Mbps 以太网上的 ISA 总线计算机中支持半双工或全双工操作。这些适配器设计用于 16 位 ISA 或 EISA 总线扩展槽，并提供 10BaseT-only 或 3-media 配置（10BaseT、10Base2，以及用于 10Base-5 或光纤网络的 AUI）。

基于 CS8920 的适配器与基于 CS8900 的适配器类似，并增加了对即插即用（PnP）支持和唤醒帧（Wakeup Frame）识别的特性。因此，两类适配器的配置过程有所不同。有关配置两类适配器的详细信息，请参阅"Adapter Configuration"一节。


## 1.2. 驱动描述


适用于 Linux 的 CS8900/CS8920 以太网适配器驱动支持 Linux v2.3.48 或更高版本的内核。它可以直接编译进内核，或在运行时作为设备驱动模块加载。

## 2. 适配器安装与配置


基于 CS8900 和 CS8920 的适配器都可以使用存储在板载 EEPROM 中的参数进行配置。如果你想更改 EEPROM 中适配器的配置，必须使用基于 DOS 的 CS8900/20 设置工具。

将驱动作为模块加载时，你可以在命令行指定适配器的许多配置参数，以覆盖 EEPROM 的设置，或在未使用 EEPROM 时进行接口配置。（基于 CS8920 的适配器必须使用 EEPROM。）请参阅第 3.0 节"将驱动作为模块加载（LOADING THE DRIVER AS A MODULE）"。

由于 CS8900/20 设置工具是基于 DOS 的应用程序，你必须在基于 DOS 的系统中使用该工具安装并配置适配器，然后才能将其安装到目标 LINUX 系统中。（如果安装的是基于 CS8900 的适配器且默认配置可接受，则不需要。）


### 2.1. 基于 CS8900 的适配器配置


Cirrus Logic 出厂的基于 CS8900 的适配器已配置为

```
  Operation Mode:      Memory Mode
  IRQ:                 10
  Base I/O Address:    300
  Memory Base Address: D0000
  Optimization:	       DOS Client
  Transmission Mode:   Half-duplex
  BootProm:            None
  Media Type:	       Autodetect (3-media cards) or
		       10BASE-T (10BASE-T only adapter)

```
只有在与另一适配器存在冲突时才应更改默认配置设置。要更改适配器的配置，请运行 CS8900/20 设置工具。


### 2.2. 基于 CS8920 的适配器配置


Cirrus Logic 出厂的基于 CS8920 的适配器配置为启用即插即用（PnP）。然而，由于 cs89x0 驱动**不**支持 PnP，你必须在基于 DOS 的 PC 中安装 CS8920 适配器，并运行 CS8900/20 设置工具禁用 PnP 并配置适配器，然后才能将其安装到目标 Linux 系统中。如果不这样做，适配器将处于非活动状态，驱动将无法与适配器通信。

```

	*                    CS8920-BASED ADAPTERS:                    *
	*                                                              *
	* CS8920-BASED ADAPTERS ARE PLUG and PLAY ENABLED BY DEFAULT.  *
	* THE CS89X0 DRIVER DOES NOT SUPPORT PnP. THEREFORE, YOU MUST  *
	* RUN THE CS8900/20 SETUP UTILITY TO DISABLE PnP SUPPORT AND   *
	* TO ACTIVATE THE ADAPTER.                                     *
	****************************************************************




```

## 3. 将驱动作为模块加载


如果驱动被编译为可加载模块，你可以使用 'modprobe' 命令加载驱动模块。适配器的许多配置参数可以作为加载命令的命令行参数指定。此功能提供了一种在 EEPROM 未使用时覆盖 EEPROM 设置或进行接口配置的手段。

```
    insmod cs89x0.o io=0x200 irq=0xA media=aui

```
此示例加载模块并将适配器配置为使用 200h 的 I/O 端口基地址、中断 10，并使用 AUI 媒体连接。以下

```
  io=###               - specify IO address (200h-360h)
  irq=##               - specify interrupt level
  use_dma=1            - Enable DMA
  dma=#                - specify dma channel (Driver is compiled to support
			 Rx DMA only)
  dmasize=# (16 or 64) - DMA size 16K or 64K.  Default value is set to 16.
  media=rj45           - specify media type
   or media=bnc
   or media=aui
   or media=auto
  duplex=full          - specify forced half/full/autonegotiate duplex
   or duplex=half
   or duplex=auto
  debug=#              - debug level (only available if the driver was compiled
			 for debugging)

```
**注意：**

a) 如果存在 EEPROM，任何指定的命令行参数都将覆盖存储在 EEPROM 中的相应配置值。

b) "io" 参数必须在命令行指定。

c) 驱动的硬件探测例程设计为在知道所写地址处存在 cs89x0 卡之前，避免写入 I/O 空间。这可能会在设备探测时导致问题。为避免此行为，请给 `io=` 模块参数加一。这并不会实际更改 I/O 地址，而是一个标志，告诉驱动在尝试识别网卡之前先部分初始化硬件。如果你不确定所提供的地址处存在 cs89x0 卡，这样做可能有危险。

   例如，要扫描位于 I/O 基地址 0x300 的适配器，请指定 I/O 地址 0x301。

d) "duplex=auto" 参数仅支持 CS8920。

e) 如果不存在 EEPROM，所需的最小命令行配置为：

   io
   irq
   media type（无 autodetect）

f) 以下附加参数为 CS89XX 默认值（在没有 EEPROM 或命令行参数时使用的值）。

   - DMA Burst = enabled（启用）
   - IOCHRDY Enabled = enabled（启用）
   - UseSA = enabled（启用）
   - 如果未在命令行指定，CS8900 默认为半双工
   - 如果未在命令行指定，CS8920 默认为 autoneg
   - 其他配置参数使用复位默认值
   - dma_mode = 0

g) 你可以使用 ifconfig 设置适配器的以太网地址。

h) 许多 Linux 发行版使用 'modprobe' 命令加载模块。该程序使用 '/etc/conf.modules' 文件来确定在加载驱动模块时传递给它的配置信息。上述所有配置选项都可以放在 /etc/conf.modules 中。

```
     > cat /etc/conf.modules
     ...
     alias eth0 cs89x0
     options cs89x0 io=0x0200 dma=5 use_dma=1
     ...

```
   在此示例中，我们告诉模块系统，本机的以太网驱动应使用 cs89x0 驱动。我们要求 'modprobe' 在加载时向驱动传递 'io'、'dma' 和 'use_dma' 参数。

i) Cirrus 建议 cs89x0 使用 ISA DMA 通道 5、6 或 7。你可能会发现其他 DMA 通道无法工作。

j) cs89x0 仅支持接收方向的 DMA。DMA 模式效率显著更高。用大 ping 包淹没一台 400 MHz Celeron 机器时，非 DMA 模式会消耗其 82% 的 CPU 能力，而使用 DMA 后降低到 45%。

k) 如果你的 Linux 内核编译时带内置的即插即用支持，你将能够找到有关 cs89x0 卡的信息

```
     cat /proc/isapnp

```
l) 如果在 DMA 操作期间你发现异常行为或网络数据损坏，应使用 PC 的 BIOS 降低 EISA 总线时钟速度。

m) 如果 cs89x0 驱动直接编译进内核（非模块），则其 I/O 地址由 ISA 总线探测自动确定。IRQ 号、媒体选项等由网卡的 EEPROM 决定。

n) 如果 cs89x0 驱动直接编译进内核，可以通过向内核提供引导选项 'cs89x0_dma=N' 来选择 DMA 模式，其中 'N' 是期望的 DMA 通道号（5、6 或 7）。

```
	LILO boot: linux cs89x0_dma=5

   or they may be placed in /etc/lilo.conf::

	image=/boot/bzImage-2.3.48
	  append="cs89x0_dma=5"
	  label=linux
	  root=/dev/hda5
	  read-only

   The DMA Rx buffer size is hardwired to 16 kbytes in this mode.
   (64k mode is not available).


```

### 5.2. 测试适配器


一旦适配器安装并配置完毕，可以使用 CS8900/20 设置工具的"诊断（Diagnostics）"选项来测试适配器及其网络连接的功能。使用诊断的"Self Test"选项测试适配器在你所分配的硬件配置下的功能。你可以使用诊断的"Network Test"测试适配器通过以太网与另一台装有基于 CS8900/20 的适配器的 PC 通信的能力（该 PC 也必须运行 CS8900/20 设置工具）。

	 CS8900/20 设置工具的诊断程序设计为在纯 DOS 操作系统环境中运行。请勿在 Windows 95、Windows NT、OS/2 或其他操作系统的 DOS 或命令提示符会话下运行诊断程序。

要在 CS8900/20 适配器上运行诊断测试：

   1. 在 PC 上引导 DOS 并启动 CS8900/20 设置工具。

   2. 将显示适配器当前配置。按 ENTER 键进入主菜单。

   4. 从主菜单中选择"Diagnostics"（ALT-G）。
       - 选择"Self-Test"测试适配器的基本功能。
       - 选择"Network Test"测试网络连接和线缆。


##### 5.2.1. 诊断自检测试


诊断自检测试检查适配器的基本功能，以及基于硬件配置期间分配的系统资源跨 ISA 总线通信的能力。执行以下测试：

   - IO Register Read/Write Test（I/O 寄存器读/写测试）
     I/O 寄存器读/写测试确保 CS8900/20 可以在 I/O 模式下被访问，并且 I/O 基地址正确。

   - Shared Memory Test（共享内存测试）
     共享内存测试确保 CS8900/20 可以在内存模式下被访问，并且所分配的内存地址范围不会与系统中的其他设备冲突。

   - Interrupt Test（中断测试）
     中断测试确保与所分配的 IRQ 信号没有冲突。

   - EEPROM Test（EEPROM 测试）
     EEPROM 测试确保 EEPROM 可以被读取。

   - Chip RAM Test（芯片 RAM 测试）
     芯片 RAM 测试确保 CS8900/20 内部 4K 内存工作正常。

   - Internal Loop-back Test（内部回环测试）
     内部回环测试确保适配器的发送器和接收器工作正常。如果此测试失败，请确认适配器的电缆已连接到网络（例如检查 LED 活动）。

   - Boot PROM Test（Boot PROM 测试）
     Boot PROM 测试确保 Boot PROM 存在且可被读取。失败表明由于硬件问题或 Boot PROM 地址分配冲突，Boot PROM 未能成功读取。（仅当适配器配置为使用 Boot PROM 选项时适用此测试。）

某个测试项失败表明可能与 ISA 总线上的另一设备存在系统资源冲突。在这种情况下，你应使用"Manual Setup"选项，通过为失败的系统资源选择不同的值来重新配置适配器。


##### 5.2.2. 诊断网络测试


诊断网络测试通过在同一网络上不同 PC 中安装的两个 CS8900/20 适配器之间传输数据来验证可用的网络连接。（注意：诊断网络测试不应在跨路由器的两个节点之间运行。）

此测试要求两台 PC 各安装一个基于 CS8900/20 的适配器，并且都在运行 CS8900/20 设置工具。第一台 PC 配置为 Responder（响应方），另一台 PC 配置为 Initiator（发起方）。一旦启动 Initiator，它会向 Responder 发送数据帧，Responder 再将帧返回给 Initiator。

接收和发送的总帧数显示在 Initiator 的屏幕上，同时显示接收和发送正常或出错的帧数统计。用户可以随时在任一 PC 上终止测试。

设置诊断网络测试：

    1. 选择一台装有基于 CS8900/20 的适配器且网络连接已知正常的 PC 作为 Responder。运行 CS8900/20 设置工具，并从主菜单中选择"Diagnostics -> Network Test -> Responder"。按 ENTER 启动 Responder。

    2. 回到你要测试的装有基于 CS8900/20 的适配器的 PC，启动 CS8900/20 设置工具。

    3. 从主菜单中选择"Diagnostic -> Network Test -> Initiator"。按 ENTER 启动测试。

你可以随时在 Initiator 上停止测试，同时让 Responder 继续运行。这样，你可以移动到其他 PC，在另一台 PC 上启动 Initiator 来测试它们，而无需停止/启动 Responder。


### 5.3. 使用适配器的 LED


2 和 3-media 适配器在电路板后端、靠近 10Base-T 连接器的位置有两个可见的 LED。

Link Integrity LED（链路完整性 LED）：绿色 LED "稳定"亮起表示有效的 10Base-T 连接。（仅适用于 10Base-T。绿色 LED 对于 10Base-2 或 AUI 连接没有意义。）

TX/RX LED：每次适配器发送或接收数据时，黄色 LED 会短暂亮起。（在典型网络上，黄色 LED 会呈现"闪烁"。）


### 5.4. 解决 I/O 冲突


当两个或多个适配器使用相同的 ISA 资源（I/O 地址、内存地址或 IRQ）时，会发生 I/O 冲突。在安装和/或配置基于 CS8900/20 的适配器后，你通常可以通过以下四种方式之一检测到 I/O 冲突：

    1. 系统无法正常引导（或根本无法引导）。

    2. 驱动无法与适配器通信，报出"Adapter not found"错误消息。

    3. 你无法连接到网络，或驱动无法加载。

    4. 如果你已将适配器配置为在内存模式下运行，但驱动在加载时报告其正在使用 I/O 模式，这表示存在内存地址冲突。

如果发生 I/O 冲突，请运行 CS8900/20 设置工具并执行诊断自检测试。通常，冲突的 ISA 资源会在自检测试中失败。如果是这样，请为冲突的资源选择另一选项来重新配置适配器。再次运行诊断以检查是否还有进一步的 I/O 冲突。

在某些情况下，例如 PC 无法引导时，可能需要移除适配器，将其安装到另一台 PC 中运行 CS8900/20 设置工具来重新配置。一旦重新安装到目标系统，在再次加载驱动之前，运行诊断自检测试以确保新配置没有冲突。

手动配置适配器时，请记住下表所示的典型 ISA 系统资源使用情况。


1.) 适配器类型（CRD8900、CDB8900、CDB8920 等）

2.) 适配器配置
    - IO Base、Memory Base、启用的 I/O 或内存模式、IRQ、DMA 通道
    - 即插即用启用/禁用（仅基于 CS8920 的适配器）
    - 配置为媒体自动检测或特定媒体类型（哪种类型）。

3.) PC 系统配置
    - 即插即用系统（是/否）
    - BIOS（品牌与版本）
    - 系统品牌与型号
    - CPU（类型与速度）
    - 系统 RAM
    - SCSI 适配器

4.) 软件
    - CS89XX 驱动及版本
    - 你的网络操作系统及版本
    - 你的系统 OS 版本
    - 所有协议支持文件的版本

5.) 显示的任何错误消息。

### 6.3 获取最新驱动版本


你可以从 Cirrus Logic 的网站获取最新的 CS89XX 驱动和支持软件。你也可以联系 Cirrus Logic 技术支持（email：ethernet@crystal.cirrus.com），并请求注册以接收自动软件更新通知。

Cirrus Logic 在 http://www.cirrus.com 维护着一个网页，提供最新驱动和技术文档。

### 6.5. 内核模块参数


用于没有 cs89x0 EEPROM 的嵌入式环境，内核引导

```
	cs89x0_media=rj45    or
	cs89x0_media=aui     or
	cs89x0_media=bnc

```
