
## DPAA2 以太网驱动

本文档提供 Freescale DPAA2 以太网驱动的说明。

## 受支持的平台

该驱动为 Freescale DPAA2 SoC（例如 LS2080A、LS2088A、LS1088A）提供网络支持。


## 架构概述

与常规 NIC 不同，在 DPAA2 架构中没有单一硬件模块来代表网络接口；相反，多个独立的硬件资源共同协作来提供网络功能：

- 网络接口
- 队列、通道
- 缓冲池
- MAC/PHY

所有硬件资源都通过管理复合体（Management Complex，MC）的 portal 分配和配置。MC 将大多数这些资源抽象为 DPAA2 对象，并暴露可用于配置和控制它们的 ABI。少数硬件资源（如队列）没有对应的 MC 对象，被视为其他对象的内部资源。

有关 DPAA2 架构及其对象抽象的更详细描述，请参阅 **Documentation/networking/device_drivers/ethernet/freescale/dpaa2/overview.rst**。

每个 Linux 网络设备都构建在 Datapath Network Interface（DPNI，数据通路网络接口）对象之上，并使用缓冲池（DPBP）、I/O Portal（DPIO）和汇聚器（DPCON）。

```

                 -----------------------
                | DPAA2 Ethernet Driver |
                 -----------------------
                     .      .      .
                     .      .      .
             . . . . .      .      . . . . . .
             .              .                .
             .              .                .
         ----------     ----------      -----------
        | DPBP API |   | DPNI API |    | DPCON API |
         ----------     ----------      -----------
             .              .                .             software
    =======  .  ==========  .  ============  .  ===================
             .              .                .             hardware
         ------------------------------------------
        |            MC hardware portals           |
         ------------------------------------------
             .              .                .
             .              .                .
          ------         ------            -------
         | DPBP |       | DPNI |          | DPCON |
          ------         ------            -------

```

DPNI 是网络接口，但没有与 PHY 直接的一对一映射。DPBP 表示硬件缓冲池。数据包 I/O 在 DPCON 对象的上下文中执行，使用 DPIO portal 来管理和与硬件资源通信。

```
         -----------------------------------------------
        |           DPAA2 Ethernet Driver               |
         -----------------------------------------------
          |          ^        ^         |            |
          |          |        |         |            |
   enqueue|   dequeue|   data |  dequeue|       seed |
    (Tx)  | (Rx, TxC)|  avail.|  request|     buffers|
          |          |  notify|         |            |
          |          |        |         |            |
          V          |        |         V            V
         -----------------------------------------------
        |                 DPIO Driver                   |
         -----------------------------------------------
          |          |        |         |            |          software
          |          |        |         |            |  ================
          |          |        |         |            |          hardware
         -----------------------------------------------
        |               I/O hardware portals            |
         -----------------------------------------------
          |          ^        ^         |            |
          |          |        |         |            |
          |          |        |         V            |
          V          |    ================           V
        ----------------------           |      -------------
 queues  ----------------------          |     | Buffer pool |
          ----------------------         |      -------------
                   =======================
                                Channel

```
数据通路 I/O（DPIO）portal 提供入队和出队服务、数据可用性通知以及缓冲池管理。DPIO 在所有处理数据帧的 DPAA2 对象（以及隐式地所有 DPAA2 内核驱动）之间共享，但必须亲和（affine）于 CPU，以便进行流量分发。

帧通过硬件帧队列进行收发，这些队列可以分组到通道中以进行硬件调度。以太网驱动在出口队列上入队 TX 帧，传输完成后，一个 TX 确认帧会被发回 CPU。

当入口队列上有可用帧时，会向 CPU 发送数据可用性通知；通知是按通道发出的，因此即使同一通道中的多个队列有可用帧，也只发送一个通知。通道触发通知后，必须显式地重新武装（rearm）。

每个网络接口可以拥有多个亲和于 CPU 的 Rx、Tx 和确认队列，以及为每个服务至少一个队列的 CPU 提供一个通道（DPCON）。DPCON 用于通过核心亲和的 DPIO 将入口流量分发到不同的 CPU。

硬件缓冲池的作用是存储入口帧数据。每个网络接口都有一个私有拥有的缓冲池，它用内核分配的缓冲区来填充（seed）。


DPNI 与 PHY 解耦；一个 DPNI 可以通过 DPMAC 对象连接到 PHY，或通过内部链路连接到另一个 DPNI，但这种连接由 MC 管理，对以太网驱动完全透明。

```
     ---------     ---------     ---------
    | eth if1 |   | eth if2 |   | eth ifn |
     ---------     ---------     ---------
          .           .          .
          .           .          .
          .           .          .
         ---------------------------
        |   DPAA2 Ethernet Driver   |
         ---------------------------
          .           .          .
          .           .          .
          .           .          .
       ------      ------      ------            -------
      | DPNI |    | DPNI |    | DPNI |          | DPMAC |----+
       ------      ------      ------            -------     |
         |           |           |                  |        |
         |           |           |                  |      -----
          ===========             ==================      | PHY |
                                                           -----

```

## 创建网络接口

为在 MC 总线上探测到的每个 DPNI 对象创建一个网络设备。每个 DPNI 都有若干属性，决定了网络接口的配置选项和相关的硬件资源。

DPNI 对象（以及网络接口所需的其他 DPAA2 对象）可以通过两种方式之一添加到 MC 总线上的容器中：静态地，通过 MC 在启动时解析的 Datapath Layout Binary 文件（DPL）；或在运行时通过 DPAA2 对象 API 动态创建。


## 特性与卸载

对 IPv4/6 帧上的 TCP 和 UDP 支持硬件校验和卸载。校验和卸载可以通过 ethtool 在 RX 和 TX 上独立配置。

入口路径上支持单播和组播 MAC 过滤的硬件卸载，且永久启用。

收发路径都支持分散-聚集（scatter-gather）帧。在 TX 上，SG 支持可通过 ethtool 配置；在 RX 上始终启用。

DPAA2 硬件可以处理最大 10K 字节的巨型（jumbo）以太网帧。

以太网驱动定义了一个静态的流哈希方案，基于 5 元组键来分发流量：源 IP、目的 IP、IP 协议、L4 源端口、L4 目的端口。目前不支持用户配置。

网络接口的硬件特定统计信息以及一些非标准驱动统计可以通过 ethtool -S 选项查看。
