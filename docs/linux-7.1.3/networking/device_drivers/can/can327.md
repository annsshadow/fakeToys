
## can327：Linux SocketCAN ELM327 驱动


### 作

Max Staudt <max@enpas.org>



### 动机


本驱动旨在降低想要上CAN 总线的黑客的入门成本
CAN 适配器昂贵且稀少。ELM327 接口则便宜且随处可见。让我们ELM327 当作 CAN 适配器来使用


### 简

本驱动致力于将大量基ELM327 OBD 接口转变为（尽可能）功能完备CAN 接口
由于 ELM327 从未被设计成独立CAN 控制器，驱动必须尽可能快地在它的各种模式之间切换，以伪造全双工操作
因此，can327 是一个尽力而为的驱动。不过，这已经足以实现简单的请求-响应协议（例OBD II），以及监视总线上的广播消息（例如在车辆中）
大多ELM327 以不起眼的串口设备形式出现，通过 USB 或蓝牙连接。驱动自身无法识别它们，因此需要用户以 TTY 线路规程的形式将其接入（类似PPP、SLIP、slcan……）
本驱动面ELM327 1.4b 及以上版本，旧款控制器与仿制品的已知限制见下文

### 如何接入线路规程


每个 ELM327 芯片出厂时被编程为以如下串口设置运行8400 波特/秒 个数据位、无校验 个停止位
如果你保留了这一默认配置，可以使用如下方式接入线路规程：
```

    sudo ldattach \
           --debug \
           --speed 38400 \
           --eightbits \
           --noparity \
           --onestopbit \
           --iflag -ICRNL,INLCR,-IXOFF \
           30 \
           /dev/ttyUSB0

```
要更ELM327 的串口设置，请参考其数据手册。这必须在接入线路规程之前完成
一旦线路规程接入，CAN 接口初始处于未配置状态```

    # 接口需要处down 状态才能更改参    sudo ip link set can0 down
    sudo ip link set can0 type can bitrate 500000
    sudo ip link set can0 up

```
500000 比特/秒是 OBD-II 诊断的常用速率。如果你直接连到汽车OBD 端口，这是大多数（但并非所有！）汽车所期望的速度
此后，你可以像往常一样使candump、cansniffer 等工具

### 如何检查控制器版本


使用终端程序连接到控制器
发出 "`AT WS`" 命令后，控制器会回应如下内容```

    >AT WS


    ELM327 v1.4b

    >

```
注意，仿制品可能会声称自己是任意它喜欢的版本。这并不能表明其实际功能集


### 通信示例


这是一个关于如何与 ELM327 通信的简短且不完整的介绍。它旨在帮助理解控制器与驱动的限制（见下文所列），以及用于手动测试

ELM327 有两种模式：

- Command mode（命令模式）
- Reception mode（接收模式）

在命令模式下，它期望每行一条命令，CR 结尾。默认提示符"`>`"，之后可以输入命令：
```

    >ATE1
    OK
    >

```
驱动中的初始化脚本关闭了若干仅对芯片原本面向OBD 场景有意义、而对 can327 实际上构成障碍的配置选项

当命令无法被识别时（例如由旧版本），会返回：
```

    >ATUNKNOWN
    ?
    >

```
目前，can327 不会解析这一响应。详见下文的已知限制一节

当要发送一CAN 帧时，先配置目标地址，然后将该帧作为由数据十六进制组成的命令发送：
```

    >ATSH123
    OK
    >DEADBEEF12345678
    OK
    >

```
上述交互发送了 SFF "`DE AD BE EF 12 34 56 78`"，其1 位）CAN ID `0x123`。为此，控制器必须被配置SFF 发送模式（使用 "`AT PB`"，参见代码或数据手册）

一旦帧被发送且等待回复模式开启（`ATR1`，配置于 `listen-only=off`），或者当回复超时到期、驱动将控制器设为监视模式（`ATMA`）时，ELM327 会为接收到的每个 CAN 帧发送一行，其内容为```

    123 8 DEADBEEF12345678

```
对于 EFF9 位）CAN 帧，地址格式略有不同```

    12 34 56 78 8 DEADBEEF12345678

```
ELM327 会同时接SFF EFF 帧——当CAN 配置（`ATPB`）无关紧要

如果 ELM327 的内UART 发送缓冲区写满，它将中止监视模式，打印 "BUFFER FULL" 并退回命令模式。注意，这种情况下与其它错误消息不同，错误消息可能与最后（通常
```

    12 34 56 78 8 DEADBEEF123 BUFFER FULL



```
### 控制器的已知限制


- 仿制设备v1.5" 等）

  不支持发RTR 帧，并且会被静默丢弃
  接收 DLC 8 RTR 帧时，会表现为一个具有最近收到的帧的 DLC 与载荷的常规帧
  "`AT CSM`"（CAN 静默监视，即不发CAN ACK）不被支持，且被硬编码为开启。因此，在监听时不会对帧进行 ACK`AT MA`"（Monitor All，监视全部）将始终是"静默"的。然而，在发送完一个帧之后，ELM327 会立即进接收回复"模式，在该模式下** ACK 任何收到的帧。一旦总线静默，或发生错误（例BUFFER FULL），或接收回复超时到期，ELM327 会自行结束回复接收模式，can327 会回退"`AT MA`" 以继续监视总线
  根据仿制品及其固件质量的不同，可能还有其它限制

- 所有版
  不支持全双工操作。驱动会尽可能快地在输入/输出模式之间切换
  无法设置对外发RTR 帧的长度。实际上，某些仿制品（已用一个标识为 "`v1.5`" 的测试过）根本无法发RTR 帧
  我们没有办法获取 CAN 错误的实时通知。虽然有一个命令（`AT CS`）可获取一些基本统计，但我们不会轮询它，因为那会迫使我们中断接收模式

- 1.4b 之前的版
  这些版本在监视模式（AT MA）下不发CAN ACK。不过，它们在发送完帧后立即等待回复时会发ACK。驱动会最大化这段时间，以使控制器尽可能有用
  1.4b 版本开始，ELM327 支持 "`AT CSM`" 命令listen-only" CAN 选项将生效

- 1.4 之前的版
  这些芯片不支"`AT PB`" 命令，因此无法在运行中更改比特率SFF/EFF 模式。这必须由用户在接入线路规程之前编程设置。详见数据手册

- 1.3 之前的版
  这些芯片完全无法配合 can327 使用。它们不支持 "`AT D1`" 命令，而该命令对于避免对输入数据的解析冲突，以及区RTR 帧长度，都是必需的
  具体而言，这使得 SFF EFF 帧易于区分，并可检查帧是否完整。虽然可以通过 ELM327 发送给我们行的长度来推断类型与长度，但ELM327 UART 输出缓冲区溢出时，这种方法会失效。它可能会在行的中间中止发送，从而被误认为是其它内容


### 驱动的已知限

- 8/7 时序
  ELM327 只能设置形如 500000/n CAN 比特率，其中 n 为整数除数。但有一个例外：借助一个单独的标志，它可以将速度设为除数所指示速度8/7。这一模式目前尚未实现
- 不解析命令响应
  ELM327 在理解命令时OK，不理解时回 。驱动目前不检查这一点，而只是假设芯片理解每一条命令。尽管如此，驱动的设计使得功能能够优雅地降级。参见控制器已知限制一节
- 不使用硬CAN ID 过滤

  ELM327 UART 发送缓冲区CAN 总线负载较重时很容易溢出，导"`BUFFER FULL`" 消息。使用通过 "`AT CF xxx`" "`AT CM xxx`" 提供的硬件过滤器在此会很有帮助，SocketCAN 目前没有提供利用此类硬件特性的机制


### 所选配置背后的理由


`AT E1`
  Echo on（开启回显）

  我们需要它以便可靠地获得提示符
`AT S1`
  Spaces on（开启空格）

  我们需要它来区分收到的 11/29 CAN 地址
  注意  我们通常可以使用行长度（偶）来实现这一点，
  但如果整行没有被完整传送到主机（BUFFER FULL），就会失败
`AT D1`
  DLC on（开DLC
  我们需要它来分RTR 帧的"长度"


### 关于 CAN 总线终端电阻的注意事

你的适配器上可能已经焊有用于终端匹配总线的电阻。在插入 OBD-II 插座时这是正确的，但在试图接入一条已CAN 总线的中间时就没什么帮助了
如果连接适配器后通信不正常，请检查其 PCB 上的终端电阻并尝试移除它们
