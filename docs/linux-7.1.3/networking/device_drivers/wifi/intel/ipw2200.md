### 1.2. 命令行参

Linux 内核中使用的许多模块一样，Intel(R) PRO/Wireless 2915ABG Linux 驱动
允许将配置选项作为模块参数提供。指定模块参数最常见的方式是通过命令行
```

    % modprobe ipw2200 parameter=value

```
其中受支持的参数如下
  associate
	设置0 可禁用驱动的自动扫描与关联功能。如果禁用，在为目标网络
	配置了一个或多个属性（例如配置网络 SSID）之前，驱动不会尝试扫描
	并关联到网络。默认值为 0（不自动关联
	示例 modprobe ipw2200 associate=0

  auto_create
	设置0 可禁用自动创建与所提供的信道和网络名称参数匹配Ad-Hoc
	网络。默认值为 1
  channel
	用于关联的信道号。设置信道的常规方法是使用标准无线工具（	`iwconfig eth1 channel 10`），但在调试时有时设置此参数很有用	信道 0 表示“ANY”（任意
  debug
	如果使用调试版本，此参数用于控制记录多少调试信息。关于如何使用它	请参'dvals' 'load' 脚本（dvals load 脚本作为 ipw2200 开	快照发布的一部分提供，可http://ipw2200.sf.net SourceForge
	项目获取
  led
	可用于开启实验性的 LED 代码	0 = 关闭 = 开启。默认值为 1
  mode
	可用于设置适配器的默认模式	0 = Managed = Ad-Hoc = Monitor


### 1.3. Wireless Extension 私有方法


作为一个设计用来处理通用硬件的接口，有一些能力并未通过标准Wireless Tool
接口暴露出来。因此，提供了让驱动声明自定义（或私有）方法的机制。Intel(R)
PRO/Wireless 2915ABG Linux 驱动定义了其中若干方法来配置各种设置
```

	% iwpriv $IFNAME method parameters

```
其中 $IFNAME 是设备注册时使用的接口名（通常eth1，可通过 ifrename 等各网络接口名管理器进行自定义）

受支持的私有方法如下
  get_mode
	可用于报告驱动配置为支持哪种 IEEE 模式。示例：

	% iwpriv eth1 get_mode
	eth1	get_mode:802.11bg (6)

  set_mode
	可用于配置驱动将支持IEEE 模式
```

	    % iwpriv eth1 set_mode {mode}

	其中 {mode} 1-7 范围内的数字
	==	=====================
	1	802.11a (2915 only)
	2	802.11b
	3	802.11ab (2915 only)
	4	802.11g
	5	802.11ag (2915 only)
	6	802.11bg
	7	802.11abg (2915 only)
	==	=====================

  get_preamble
	可用于报告前导码长度的配置
  set_preamble
	可用于设置前导码长度的配置：

	Usage::

	    % iwpriv eth1 set_preamble {mode}

	其中 {mode} 为下列之一
	==	========================================
	1	Long preamble only
	0	Auto (long or short based on connection)
	==	========================================


```
### 1.4. Sysfs 辅助文件


Linux 内核提供了一种伪文件系统，可用于访问操作系统的各个组件。Intel(R)
PRO/Wireless 2915ABG Linux 驱动通过此机制暴露了若干配置参数
sysfs 中的条目可以支持读取或写入。你通常可以通过使用 cat 来查sysfs
条目的内容，
```

    % cat /sys/bus/pci/drivers/ipw2200/debug_level

```
将报告驱动日志子系统的当前调试级别（仅在构建驱动时配置了 CONFIG_IPW2200_DEBUG
时才可用）
```

    % echo $VALUE > /sys/bus/pci/drivers/ipw2200/debug_level

```
其中 $VALUE 在该 sysfs 条目的情况下是一个数字。sysfs 文件的输入不必是数字例如，hotplug 使用的固件加载器利用 sysfs 条目将固件映像从用户空间传入驱动
Intel(R) PRO/Wireless 2915ABG Linux 驱动在两个层级暴sysfs 条目——驱动级
（适用于驱动的所有实例，在安装了多个设备的情况下）与设备级（仅适用于单特定实例）

## 3. Wireless Tools 的交

### 3.1 iwconfig mode


配置适配器模式时，所有运行时配置的参数都会被重置为模块加载时所使用的值这包括信道、速率、ESSID 等
### 3.2 iwconfig sens


'iwconfig ethX sens XX' 命令不会iwconfig 文档所描述的那样设置信号灵敏度
阈值，而是设置将触发切换（即漫游到另一个接入点）的连续丢失信标数量。同时，
它会将去关联阈值设置为给定值的 3 倍

## 4.  关于版本

由于开源开发项目的特性，经常会合入一些尚未经过完整验证流程的改动。这些改被合入到开发快照发布中
发布版本采用三级编号方案
	major.minor.development

任何 'development' 部分0 的版本（例如 1.0.0.1.0 等）表示将提供给内核
合入的稳定版本
任何 'development' 部分不为 0 的版本（例如 1.0.1.1.5 等）表示提供给测用户与前沿用户使用的开发版本。开发版本的稳定性和功能性未知。我们努力让所快照都保持合理的稳定性，但由于发布频繁，并且希望尽快让这些版本可用，因此
应预期会出现未知异常
当驱动发生重大改动时，主版本号将递增。目前没有计划进行重大改动
