
## Devlink 健康机制


## 背景


`devlink` 健康机制面向实时告警，用于获知 PCI 设备何时发生了异常。

  - 提供告警调试信息。
  - 自我修复。
  - 如果问题需要厂商支持，提供一种收集所有所需调试信息的方式。

## 概述


主要思想是将驱动健康报告统一并集中到通用的 `devlink` 实例中，并允许用户设置健康报告与恢复过程的不同属性。

`devlink` 健康报告器（reporter）：
设备驱动针对每种错误/健康类型创建一个“健康报告器”。错误/健康类型可以是已知/通用的（例如 PCI 错误、固件错误、rx/tx 错误），也可以是未知的（驱动特定的）。
对于每个已注册的健康报告器，驱动可以异步地发出错误/健康报告。所有健康报告的处理都由 `devlink` 完成。
设备驱动可以为每个“健康报告器”提供特定的回调，例如：

  - 恢复过程
  - 诊断过程
  - 对象转储过程
  - 出厂初始参数

驱动的不同部分可以注册具有不同处理程序的不同类型的健康报告器。

## 操作


一旦报告了错误，devlink 健康机制将执行以下操作：

  - 向内核跟踪事件缓冲区发送一条日志
  - 更新该报告器实例的健康状态与统计信息
  - 获取对象转储并保存在该报告器实例中（只要启用了自动转储，并且没有其他已存储的转储）
  - 尝试自动恢复。取决于：

    - 自动恢复配置
    - 宽限期（以及突发周期）与自上次恢复以来所经过时间的比较

## Devlink 格式化消息


为了处理 devlink 健康诊断与健康转储请求，devlink 创建一个格式化消息结构 `devlink_fmsg` 并将其发送给驱动的回调，由回调使用 devlink fmsg API 填充数据。

Devlink fmsg 是一种以类 json 格式在驱动与 devlink 之间传递描述符的机制。该 API 允许驱动添加嵌套属性，如对象、对象对和值数组，此外还有名称和值等属性。

驱动应当使用此 API 以某种格式填充 fmsg 上下文，该格式随后会被 devlink 翻译成 netlink 消息。当它需要使用 SKB 将数据发送到 netlink 层时，会在不同的 SKB 之间对数据进行分片。为了进行这种分片，它使用虚拟嵌套属性，以避免无法在不同 SKB 之间划分的实际嵌套使用。

## 用户接口


用户可以通过 `devlink` 访问/更改每个报告器的参数和驱动特定的回调，例如按错误类型（按健康报告器）：

  - 配置报告器的通用参数（如：禁用/启用自动恢复）
  - 调用恢复过程
  - 运行诊断
  - 对象转储

   :widths: 10 90

   - - 名称
     - 描述
   - - `DEVLINK_CMD_HEALTH_REPORTER_GET`
     - 按 DEV 和报告器检索状态与配置信息。
   - - `DEVLINK_CMD_HEALTH_REPORTER_SET`
     - 允许设置与报告器相关的配置。
   - - `DEVLINK_CMD_HEALTH_REPORTER_RECOVER`
     - 触发报告器的恢复过程。
   - - `DEVLINK_CMD_HEALTH_REPORTER_TEST`
     - 在报告器上触发一个伪健康事件。就恢复流程而言，该测试事件的效果应当尽可能接近真实事件。
   - - `DEVLINK_CMD_HEALTH_REPORTER_DIAGNOSE`
     - 检索与该报告器相关的当前设备状态。
   - - `DEVLINK_CMD_HEALTH_REPORTER_DUMP_GET`
     - 检索最后存储的转储。Devlink 健康机制只保存单个转储。如果 devlink 尚未为该报告器存储转储，则 devlink 会生成一个新的转储。转储输出由报告器定义。
   - - `DEVLINK_CMD_HEALTH_REPORTER_DUMP_CLEAR`
     - 清除指定报告器最后保存的转储文件。
