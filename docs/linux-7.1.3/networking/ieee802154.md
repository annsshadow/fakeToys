## IEEE 802.15.4 开发者指南


## 简介


IEEE 802.15.4 工作组专注于最底层两层的标准化：介质访问控制（MAC）和物理接入（PHY）。上层主要有两个可选方案：

- ZigBee —— 来自 ZigBee 联盟的专有协议
- 6LoWPAN —— 低速率个人区域网络上的 IPv6 联网

Linux-wpan 的目标是提供 IEEE 802.15.4 和 6LoWPAN 协议的完整实现。IEEE 802.15.4 是用于组织低速率无线个人区域网络的一组协议栈。

该协议栈由三个主要部分组成：

- IEEE 802.15.4 层；我们选择使用普通的 Berkeley 套接字 API、通用的 Linux 网络栈来传输 IEEE 802.15.4 数据报文，以及一个基于 netlink 的特殊协议用于配置/管理
- MAC —— 提供对共享信道的访问以及可靠的数据交付
- PHY —— 代表设备驱动

## 套接字 API


```

    int sd = socket(PF_IEEE802154, SOCK_DGRAM, 0);

```
地址族、套接字地址等定义在 include/net/af_ieee802154.h 头文件或用户空间包中的特殊头文件里（参见 https://linux-wpan.org/wpan-tools.html 或 https://github.com/linux-wpan/wpan-tools 上的 git 树）。

## 6LoWPAN 的 Linux 实现


IEEE 802.15.4 标准规定 MTU 为 127 字节，在开启安全性的无线链路上，实际 MAC 载荷约为 80 字节，链路吞吐量为 250 kbps 或更低。[RFC4944] 中规定的 6LoWPAN 适配格式用于在这样受限的链路上承载 IPv6 数据报，同时考虑了无线传感器网络等应用中预期存在的有限带宽、内存或能量资源。[RFC4944] 定义了用于支持子网 IP 转发的 Mesh Addressing 头、用于支持 IPv6 最小 MTU 要求 [RFC2460] 的分片头，以及用于 IPv6 数据报的无状态头压缩（LOWPAN_HC1 和 LOWPAN_HC2），以将相对较大的 IPv6 和 UDP 头压缩到（在最佳情况下）几个字节。

2011 年 9 月发布了标准更新——[RFC6282]。它弃用了 HC1 和 HC2 压缩，并定义了本 Linux 实现中所使用的 IPHC 编码格式。

所有与 6lowpan 相关的代码可以在以下文件中找到：net/6lowpan/* 和 net/ieee802154/6lowpan/*

要配置一个 6LoWPAN 接口，你需要：
1. 添加 IEEE802.15.4 接口并设置信道和 PAN ID；
2. 通过类似如下的命令添加 6lowpan 接口：
# ip link add link wpan0 name lowpan0 type lowpan
3. 启用 'lowpan0' 接口

## 驱动


与 WiFi 类似，实现 IEEE 802.15.4 的设备有几种类型。
1) 'HardMAC'。MAC 层在设备自身中实现，设备导出管理（如 MLME）和数据 API。
2) 'SoftMAC' 或仅无线电。这类设备只是无线电收发器，可能带有某些加速功能，如自动 CRC 计算与比较、自动 ACK 处理、地址匹配等。

每种类型的设备需要不同的方式挂接到 Linux 内核中。

### HardMAC


参见头文件 include/net/ieee802154_netdev.h。你必须实现 Linux 的 net_device，且 .type = ARPHRD_IEEE802154。数据通过普通的 sk_buff 与套接字族代码交换。在接收 skb 时，skb->cb 必须包含 struct ieee802154_mac_cb 中描述的额外信息。在报文发送过程中，skb->cb 用于向设备的 header_ops->create 函数提供额外数据。注意，这些数据之后可能被覆盖（当套接字代码将 skb 提交给 qdisc 时），因此如果你之后需要该 cb 中的某些内容，应当自行将其存储在 skb->data 中。

要挂接 MLME 接口，你必须用指向 struct ieee802154_mlme_ops 实例的指针填充 net_device 的 ml_priv 字段。assoc_req、assoc_resp、disassoc_req、start_req 和 scan_req 字段是可选的。所有其它字段都是必需的。

### SoftMAC


MAC 是 IEEE 802.15.4 Linux 协议栈中的中间层。目前，它提供驱动注册接口以及从属（slave）接口的管理。

注意：目前仅支持 monitor 设备类型——它是用于网络嗅探器（如 WireShark）的 IEEE 802.15.4 协议栈接口。

这一层很快将会被扩展。

参见头文件 include/net/mac802154.h 以及 drivers/net/ieee802154/ 中的若干驱动。

### 伪驱动（Fake drivers）


此外，还有一个驱动可用，它通过 SoftMAC（fakelb —— IEEE 802.15.4 回环驱动）接口模拟真实设备。该选项提供了在没有真实硬件的情况下测试和调试协议栈的可能性。
