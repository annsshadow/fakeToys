## NXP SJA1105 浜ゆ崲鏈洪┍鍔。

## 概述


NXP SJA1105 是一个由 10 SPI 管理的汽车级交换机组成的系列
- SJA1105E：第一代，TTEthernet
- SJA1105T：第一代，TTEthernet
- SJA1105P：第二代，无 TTEthernet，无 SGMII
- SJA1105Q：第二代，带 TTEthernet，无 SGMII
- SJA1105R：第二代，无 TTEthernet，带 SGMII
- SJA1105S：第二代，带 TTEthernet，带 SGMII
- SJA1110A：第三代，带 TTEthernet、SGMII，集100base-T1 100base-TX PHY
- SJA1110B：第三代，带 TTEthernet、SGMII00base-T100base-TX
- SJA1110C：第三代，带 TTEthernet、SGMII00base-T100base-TX
- SJA1110D：第三代，带 TTEthernet、SGMII00base-T1

作为汽车级器件，它们的配置接口面向“一次设置、永久使用”（set-and-forget）的方式，运行时动态交互极少。它们要求由软件组成一份静态配置，并以 CRC 和表头（table header）打包，再通过 SPI 发送
静态配置由若干配置表组成。每个表包含一定数量的表项。某些配置表可以在运行时（部分）重新配置，某些不能。某些表是必选的，某些不是：

驱动在探测（probe）时创建一份静态配置，并始终将其保留在内存中，作为硬件状态的影子（shadow）。当需要更改某个硬件设置时，静态配置也会随之更新。如果该变更后的设置可以通过动态重配置接口传输给交换机，就这样做；否则交换机会被复位，并以更新后的静态配置重新编程
## 交换特

驱动支持在硬件中配置 L2 转发规则，用于端口桥接。端口之间的转发、广播和泛洪域可以通过以下两种方法来限制：要么L2 转发层面（将一个桥的端口与另一个桥的端口隔离），要么在 VLAN 端口成员关系层面（隔离同一桥内的端口）。硬件做出的最终转发决策是这两套规则的逻辑与（AND）
硬件会在内部为所有流量打上一个基于端口的 VLAN（pvid）标签，或者从 802.1Q 标签中解码出 VLAN 信息。高VLAN 分类是不可能的。一旦被赋予 VLAN 标签，帧会对照端口的成员规则进行检查，如果不匹配任VLAN，就在入向被丢弃。当交换机端口加入一个带 `vlan_filtering 1` 的桥时，此行为可用
通常硬件VLAN 感知（VLAN awareness）方面是不可配置的，但通过更改交换机所搜索802.1Q 标签TPID，可以保持带 `vlan_filtering 0` 的桥的语义（接受所有流量，无论带标签还是不带标签），因此这种模式也受支持
将交换机端口分隔在多个桥中受支持（例2 + 2），但所有桥应具有相同级别的 VLAN 感知（要么都`vlan_filtering` 0，要么都1）
通过 STP 进行的拓扑与环路检测受支持
## 卸载


### 时间感知调度


该交换机支持 IEEE 802.1Q-2018（原 802.1Qbv）中规定的调度流量增强功能的一个变体。这意味着它可用于确保优先级流量（在其网络调度中的开门（gate-open）事件带内发送）的确定性延迟
此能力可通过 tc-taprio 卸载flags 2'）来管理。与 taprio 的软件实现相比，区别在于后者只能整形（shape）源CPU 的流量，而不能处理自主转发的流
该器件有 8 个流量类别（traffic class），并根VLAN PCP 位将入向帧映射到其中一个（如果没有 VLAN，则使用基于端口的默认值）。如前面各节所述，根据 `vlan_filtering` 的值，交换机识别为 VLAN EtherType 既可以是典型0x8100，也可以是驱动内部用于打标签的自定义值。因此，standalone bridge 模式下且使用 `vlan_filtering=0` 时，交换机会忽略 VLAN PCP，因为它无法识别 0x8100 EtherType。在这些模式下，注入到特TX 队列只能DSA 网络设备完成，它们在出口侧填充打标签头的 PCP 字段。使`vlan_filtering=1` 时，情况正好相反：卸载的流可以根VLAN PCP 被引导到 TX 队列，但 DSA 网络设备不再能做到这一点。要VLAN 感知开启的情况下将帧注入硬TX 队列，必须在 DSA conduit 端口上创建一VLAN 子接口，并向交换机发送普通的x8100）VLAN 带标签帧，且 VLAN PCP 位设置得当
管理流量（DMAC 01-80-C2-xx-xx-xx 01-19-1B-xx-xx-xx）是显著的例外：交换机始终以固定优先级处理它，并忽略任何存在VLAN PCP 位。管理流量的流量类别当前值为 7（最高优先级），在驱动中不可配置
下面是一个在出口端口 `swp5` 上配500 us 周期调度的示例。管理流量（7）的流量类别门开100 us```

  #!/bin/bash

  set -e -u -o pipefail

  NSEC_PER_SEC="1000000000"

  gatemask() {
          local tc_list="$1"
          local mask=0

          for tc in ${tc_list}; do
                  mask=$((${mask} | (1 << ${tc})))
          done

          printf "%02x" ${mask}
  }

  if ! systemctl is-active --quiet ptp4l; then
          echo "Please start the ptp4l service"
          exit
  fi

  now=$(phc_ctl /dev/ptp1 get | gawk '/clock time is/ { print $5; }')
  # Phase-align the base time to the start of the next second.
  sec=$(echo "${now}" | gawk -F. '{ print $1; }')
  base_time="$(((${sec} + 1) * ${NSEC_PER_SEC}))"

  tc qdisc add dev swp5 parent root handle 100 taprio \
          num_tc 8 \
          map 0 1 2 3 5 6 7 \
          queues 1@0 1@1 1@2 1@3 1@4 1@5 1@6 1@7 \
          base-time ${base_time} \
          sched-entry S $(gatemask 7) 100000 \
          sched-entry S $(gatemask "0 1 2 3 4 5 6") 400000 \
          flags 2

```
可以tc-taprio 卸载应用到多个出口端口。硬件存在相关限制：任何两个端口上都不能同时触发门事件。驱动会根据此限制检查调度的一致性，并在适当时报错。要避免此问题需要调度分析，这超出了本文档的范围
### 路由动作（重定向、捕获、丢弃）


该交换机能够卸载（offload）基于流的、将数据包重定向到用户指定的一组目的端口的能力。在内部，这是通过利用虚拟链路（Virtual Link，TTEthernet 的一个概念）来实现的
驱动支持两种类型的虚拟链路键（key）：

- VLAN 感知的虚拟链路：它们匹配目的 MAC 地址、VLAN ID VLAN PCP- VLAN 不感知的虚拟链路：它们仅匹配目的 MAC 地址
当已安装虚拟链路规则时，无法更改桥的 VLAN 感知状态（vlan_filtering）
支持在同一个规则内组合多个动作。当只请求路由动作时，驱动会创建一个“非关键”（non-critical）虚拟链路。当动作列表还包tc-gate（详见下文）时，该虚拟链路变为“时间关键”（time-critical）（从预留的内存分区中支取帧缓冲区等）
受支持的 3 种路由动作是“trap”（捕获）、“drop”（丢弃）和“redirect”（重定向）
示例 1：将 swp2 上收到的、DA 42:be:24:9b:76:20 的帧发送到 CPU 以及 swp3。当端口VLAN 感知状态为这种键（DA）时
```

  tc qdisc add dev swp2 clsact
  tc filter add dev swp2 ingress flower skip_sw dst_mac 42:be:24:9b:76:20 \
          action mirred egress redirect dev swp3 \
          action trap

```
示例 2：丢swp2 上收到的、DA 42:be:24:9b:76:20、VID ```

  tc filter add dev swp2 ingress protocol 802.1Q flower skip_sw \
          dst_mac 42:be:24:9b:76:20 vlan_id 100 vlan_prio 0 action drop

```
### 基于时间的入policing


该交换机TTEthernet 硬件能力可以被约束为类似IEEE 802.1Q-2018（原 802.1Qci）中规定的逐流过滤policing（Per-Stream Filtering and Policing，PSFP）条款。这意味着它可以用于对多达 1024 个流（由目的 MAC 地址、VLAN ID VLAN PCP 组成的元组标识）执行严格基于时序的准入控制。在其预期接收窗口之外收到的数据包会被丢弃
此能力可通过 tc-gate 动作的卸载来管理。由于路由动作在 TTEthernet 中是虚拟链路固有的（它对时间关键流量执行显式路由，而不将其交给 FDB、泛洪等处理），在请sja1105 卸载 tc-gate 时，该动作绝不能单独出现。必须同时跟随一个或多个 redirect trap 动作
示例：创建一个与 tc-gate 调度相位对齐tc-taprio 调度（时钟必须由 1588 应用协议栈同步，这超出了本文档的范围）。发送方发出的数据包都不会被丢弃。注意接收窗口大于发送窗口（在本示例中更是大得多），以补偿链路的包传播延迟（该延迟可1588 应用协议栈确定）
```

  tc qdisc add dev swp2 clsact
  now=$(phc_ctl /dev/ptp1 get | awk '/clock time is/ {print $5}') && \
          sec=$(echo $now | awk -F. '{print $1}') && \
          base_time="$(((sec + 2) * 1000000000))" && \
          echo "base time ${base_time}"
  tc filter add dev swp2 ingress flower skip_sw \
          dst_mac 42:be:24:9b:76:20 \
          action gate base-time ${base_time} \
          sched-entry OPEN  60000 -1 -1 \
          sched-entry CLOSE 40000 -1 -1 \
          action trap

```
```

  now=$(phc_ctl /dev/ptp0 get | awk '/clock time is/ {print $5}') && \
          sec=$(echo $now | awk -F. '{print $1}') && \
          base_time="$(((sec + 2) * 1000000000))" && \
          echo "base time ${base_time}"
  tc qdisc add dev eno0 parent root taprio \
          num_tc 8 \
          map 0 1 2 3 4 5 6 7 \
          queues 1@0 1@1 1@2 1@3 1@4 1@5 1@6 1@7 \
          base-time ${base_time} \
          sched-entry S 01  50000 \
          sched-entry S 00  50000 \
          flags 2

```
用于调度入向门操作的引擎tc-taprio 卸载所用的引擎相同。因此，关于不能有两个门动作（无论是 tc-gate 还是 tc-taprio 的门）在同一时刻（在同一200 ns 时隙内）触发的限制仍然适用
为了更方便，可以通过流块（flow block）在多个入向端口之间共享时间触发的虚拟链路。在这种情况下，同时触发的限制不适用，因为只存在单一调度
```

  tc qdisc add dev swp2 ingress_block 1 clsact
  tc qdisc add dev swp3 ingress_block 1 clsact
  tc filter add block 1 flower skip_sw dst_mac 42:be:24:9b:76:20 \
          action gate index 2 \
          base-time 0 \
          sched-entry OPEN 50000000 -1 -1 \
          sched-entry CLOSE 50000000 -1 -1 \
          action trap

```
每个流的硬件统计信息也可用（“pkts”统计丢弃的帧数，它是由于时序违规、缺少目的端口以MTU 强制检查而丢弃的帧的总和）。字节级计数器不可用
## 限制


SJA1105 交换机系列始终执VLAN 处理。当配置VLAN 不感知时，帧在内部携带不同的 VLAN 标签，具体取决于端口standalone 还是处于一VLAN 不感知的桥下
虚拟链路键始终固定为 {MAC DA, VLAN ID, VLAN PCP}，但当端口处于一VLAN 感知的桥下时，驱动会要求提供 VLAN ID VLAN PCP。否则，它会根据端口standalone 还是VLAN 不感知的桥中，自动填VLAN ID PCP，并且只接受“VLAN 不感知”的 tc-flower 键（MAC DA）
使用虚拟链路卸载的现tc-flower 键，在以下任一情况发生后不再有效：

- 端口原本 standalone，加入了某个桥（VLAN 感知VLAN 不感知）
- 端口属于某个桥，VLAN 感知状态发生变- 端口原本属于某个桥，变为 standalone
- 端口原本 standalone，但另一个端口加入了一VLAN 感知的桥，从而改变了该桥的全局 VLAN 感知状
驱动无法否决所有这些操作，也无法更移除现有tc-flower 过滤器。因此为了正确运行，tc-flower 过滤器应当只在端口的转发配置完成之后安装，并在用户空间对其做任何更改之前由用户空间移除
## 设备树绑定与板级设计


本节引用 `Documentation/devicetree/bindings/net/dsa/nxp,sja1105.yaml`，旨在展示交换机可能存在的一些注意事项
### RMII PHY 角色与带外信

RMII 规范中，50 MHz 时钟信号要么MAC 驱动，要么由外部振荡器提供（但不是由 PHY 提供）。但规范相当宽松，设备会以几种方式超出它。有PHY 违反规范，可能提供一个输出引脚，由它们自己提50 MHz 时钟，以图“帮忙”。另一方面，SJA1105 只能二进制配置——当它处RMII MAC 角色时，它也会尝试驱动时钟信号。为了防止这种情况发生，必须将其置于 RMII PHY 角色。但这样做会带来一些非预期后果。在 RMII 规范中，PHY 可以通过 RXD[1:0] 传输额外的带外信号。这些实际上是在每个帧的前导码（preamble）之前发送的一些额外码字（/J/ /K/）。MAC 没有 RMII 规范定义的这种带外信令机制。因此，SJA1105 端口被置PHY 角色以避免时钟信号上有两个驱动者时，不可避免地创建了一RMII PHY PHY 的连接。SJA1105 完全模拟一PHY 接口，并在帧前导码之前生/J/ /K/ 符号，而真正的 PHY 不被预期能理解它们。于PHY 只是将来自“作PHY SJA1105”的额外符号编码100Base-Tx 线缆上。在线缆的另一侧，某些链路对端可能会丢弃这些额外符号，而另一些可能会“噎住”并丢弃随后整个以太网帧。这表现为与某些链路对端之间有丢包，而与另一些则没有。结论是，在 RMII 模式下，如果 SJA1105 连接PHY，必须让它来驱动参考时钟
### RGMII fixed-link 与内部延

如绑定文档所述，第二代器件在 MAC 中带有可调延迟线（delay line），可用于建立正确的 RGMII 时序预算（timing budget）。上电时，这些延迟线可以Rx Tx 时钟偏移 73.8 101.7 度之间的相位差。问题在于延迟线需要锁定到一个频率稳定的时钟信号上。这意味着旧频率与新频率的时钟之间必须至少2 微秒的静默期。否则锁会丢失，延迟线必须被复位（下电再上电）。在 RGMII 中，时钟频率随链路速率变化000 Mbps 时为 125 MHz00 Mbps 时为 25 MHz0 Mbps 时为 2.5 MHz），而链路速率可能在自协商（AN）过程中改变。在交换机端口通过 RGMII fixed-link 连接到一个链路状态生命周期不Linux 控制（例如不同的 SoC）的链路对端的情况下，延迟线将保持未锁定（且无效），直到有人工干预（对交换机端口执行 ifdown/ifup）。结论是，在 RGMII 模式下，交换机的内部延迟只有在链路对端从不改变链路速率，或者如果改变，也以与交换机端口协调的方式进行时才可靠（实际上，fixed-link 的两端都处于同一Linux 系统的控制之下）
至于为什fixed-link 接口会改变链路速率：有些以太网控制器复位后处于 100 Mbps 模式，如果要求以千兆工作，其驱动不可避免地需要改变速率和时钟频率
### MDIO 总线PHY 管理


SJA1105 没有 MDIO 总线，也不执行带内自协商（in-band AN）。因此，交换机器件不会发出任何链路状态通知。板级设计需要将连接到交换机PHY 挂到系统Linux 可用的任何其MDIO 总线（例DSA conduit MDIO 总线）上。随后，链路状态管理由驱动通过 SPI 命令手动MAC 链路速率PHY 协商的设置保持同步来完成
相比之下，SJA1110 支持一MDIO 从设备访问点，通过该访问点，主机可以访问其内部 100base-T1 PHY。不过驱动并未使用它，而是内部 100base-T1 100base-TX PHY 通过 SPI 命令访问，在 Linux 中建模为虚拟 MDIO 总线
连接SJA1110 端口 0 的微控制器也有一个以主模式运行的 MDIO 控制器，但驱动同样不支持它，因为Linux 驱动运行时微控制器会被禁用。连接到交换机端口的离散 PHY 应当将其 MDIO 接口挂到主机系统的某MDIO 控制器上，而不是挂到交换机上，这与 SJA1105 类似
