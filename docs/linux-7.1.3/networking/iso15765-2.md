
## ISO 15765-2（ISO-TP

## 概述


ISO 15765-2，也称为 ISO-TP，是一种专门为 CAN 上的诊断通信而定义的传输协议。它被广泛用于汽车工业，例如作为 UDSonCAN（ISO 14229-3）或排放相关诊断服务（ISO 15031-5）的传输协议
ISO-TP 既可用于基于 CAN CC（即 Classical CAN，经CAN）的网络，也可用于基CAN FD（具有灵活数据速率CAN）的网络。它也被设计为与SAE J1939 用作数据链路层的 CAN 网络兼容（不过这不是一项要求）
### 使用的规

- ISO 15765-2:2024：道路车- 基于控制器局域网络（DoCAN）的诊断通信。第 2 部分：传输协议与网络层服务
### 寻址（Addressing

在最简单的形式中，ISO-TP 基于两种寻址模式，用于连接到同一网络的节点：

- 物理寻址（physical addressing）由两个节点特定的地址实现，用1 1 的通信
- 功能寻址（functional addressing）由一个节点特定的地址实现，用1 N 的通信
可以采用三种不同的寻址格式
- "normal"（普通）：每个地址仅由一CAN ID 表示
- "extended"（扩展）：每个地址由一CAN ID 加上 CAN 载荷的第一个字节表示；两个地址之间CAN ID 和载荷内的字节都应当不同
- "mixed"（混合）：每个地址由一CAN ID 加上 CAN 载荷的第一个字节表示；两个地址之间CAN ID 不同，但那个额外的字节相同
### 传输协议与相关的帧类

当使ISO-TP 协议传输数据时，载荷可以放进单个 CAN 报文之内，也可能放不进——这还要考虑协议本身产生的开销以及可选的扩展寻址。在第一种情况下，数据使用所谓的单帧（Single Frame，SF）一次性传输。在第二种情况下，ISO-TP 定义了一个多帧协议，其中发送方通过首帧（First Frame - FF）提供要传输PDU 长度，并请求一个流控制（Flow Control - FC）帧，该帧提供宏数据块（macro data block）所支持的最大大小（`blocksize`）以及组成该块的单个 CAN 报文之间的最小时间间隔（`stmin`）。一旦收到这些信息，发送方就开始发送包含数据载荷片段的帧（称为连续- Consecutive Frames，CF），每发送完一`blocksize` 大小的块就停下来，等待接收方的确认，接收方随后应当发送另一个流控制帧，以告知发送方它有能力接收更多数据
## 如何使用 ISO-TP


与其CAN 协议一样，ISO-TP 协议栈支持是内建Linux 网络子系统（用于 CAN 总线的，Linux-CAN SocketCAN）中的，因此遵循相同socket API
### ISO-TP 套接字的创建与基本使

要使ISO-TP 协议栈，应当使用 `#include <linux/can/isotp.h>`。然后可以使`PF_CAN` 协议族、`SOCK_DGRAM` 类型（因为底层协议在设计上是基于数据报的）以`CAN_ISOTP` 协议来创建一个套接字

    s = socket(PF_CAN, SOCK_DGRAM, CAN_ISOTP);

在套接字成功创建之后，应当调`bind(2)` 将套接字绑定到所需CAN 接口；为此：

- 应当指定一TX CAN ID，作为提供给该调用的 sockaddr 的一部分
- 还应当指定一RX CAN ID，除非已通过套接字选项（下文解释）设置了广播标志
一旦绑定到某个接口，就可以使用通常`read(2)` `write(2)` 系统调用，以`send(2)`、`sendmsg(2)`、`recv(2)` `recvmsg(2)` 来读写该套接字。与 CAN_RAW 套接API 不同，用户空间应用程序使用这些调用只发送和接收 ISO-TP 数据字段（即实际载荷）。地址信息和协议信息由 ISO-TP 协议栈根据套接字创建时提供的配置自动填充。同样地，当需要时（即数据载荷的大小超过底CAN 总线MTU 时），协议栈会使用传输机制
用于 SocketCAN sockaddr 结构有用ISO-TP 的扩展，如下所示：


    struct sockaddr_can {
        sa_family_t can_family;
        int         can_ifindex;
        union {
            struct { canid_t rx_id, tx_id; } tp;
        ...
        } can_addr;
    }

- `can_family` `can_ifindex` 的作用与其它 SocketCAN 套接字相同
- `can_addr.tp.rx_id` 指定接收（RX）CAN ID，并将被用作 RX 过滤器
- `can_addr.tp.tx_id` 指定发送（TX）CAN ID
### ISO-TP 套接字选项


创建 ISO-TP 套接字时，会设置合理的默认值。一些选项可以通过 `setsockopt(2)` 修改，和/或通过 `getsockopt(2)` 读回
#### 通用选项


通用套接字选项可以使用 `CAN_ISOTP_OPTS` optname 传递：


    struct can_isotp_options opts;
    ret = setsockopt(s, SOL_CAN_ISOTP, CAN_ISOTP_OPTS, &opts, sizeof(opts))

其中 `can_isotp_options` 结构包含以下内容

    struct can_isotp_options {
        u32 flags;
        u32 frame_txtime;
        u8  ext_address;
        u8  txpad_content;
        u8  rxpad_content;
        u8  rx_ext_address;
    };

- `flags`：应用于 ISO-TP 协议栈默认行为的修饰符。可用的标志如下
  - `CAN_ISOTP_LISTEN_MODE`：仅监听（不发FC 帧）；通常用作测试特性
  - `CAN_ISOTP_EXTEND_ADDR`：使`ext_address` 中指定的字节作为额外的地址组成部分。如果单独使用，则启"mixed" 寻址格式；如果与 `CAN_ISOTP_RX_EXT_ADDR` 配合使用，则启用 "extended" 寻址格式
  - `CAN_ISOTP_TX_PADDING`：为发送的帧启用填充，使用 `txpad_content` 作为填充字节的值
  - `CAN_ISOTP_RX_PADDING`：为接收的帧启用填充，使`rxpad_content` 作为填充字节的值
  - `CAN_ISOTP_CHK_PAD_LEN`：检查接收帧的填充长度是否正确
  - `CAN_ISOTP_CHK_PAD_DATA`：根`rxpad_content` 检查接收帧的填充字节；如果未指`CAN_ISOTP_RX_PADDING`，则忽略此标志
  - `CAN_ISOTP_HALF_DUPLEX`：强ISO-TP 套接字进入半双工模式（即传输机制同一时刻只能是入向或出向，不能同时）
  - `CAN_ISOTP_FORCE_TXSTMIN`：忽略来自接FC stmin；通常用作测试特性
  - `CAN_ISOTP_FORCE_RXSTMIN`：根rx stmin 忽略 CF；通常用作测试特性
  - `CAN_ISOTP_RX_EXT_ADDR`：在接收路径上使`rx_ext_address` 而非 `ext_address` 作为扩展寻址字节。如果与 `CAN_ISOTP_EXTEND_ADDR` 配合使用，该标志实际启用 "extended" 寻址格式
  - `CAN_ISOTP_WAIT_TX_DONE`：在 `write(2)` `send(2)` 调用返回之前等待帧发送完成（即阻塞式写操作）
  - `CAN_ISOTP_SF_BROADCAST`：使1 N 功能寻址（不能与 `CAN_ISOTP_CF_BROADCAST` 同时指定）
  - `CAN_ISOTP_CF_BROADCAST`：使1 N、不带流控制的传输（不能`CAN_ISOTP_SF_BROADCAST` 同时指定）    注意：这未被 ISO 15765-2 标准覆盖
  - `CAN_ISOTP_DYN_FC_PARMS`：启用流控制参数的动态更新
- `frame_txtime`：帧传输时间（在 ISO 标准中定义为 N_As/N_Ar）；如果`0`，则使用默认值（或最后设置的值）。要将传输时间设置为 `0`，应当使`CAN_ISOTP_FRAME_TXTIME_ZERO` 宏（等于 0xFFFFFFFF）
- `ext_address`：扩展寻址字节，在指定`CAN_ISOTP_EXTEND_ADDR` 标志时使用
- `txpad_content`：用作发送帧填充值的字节
- `rxpad_content`：用作接收帧填充值的字节
- `rx_ext_address`：接收路径的扩展寻址字节，在指定`CAN_ISOTP_RX_EXT_ADDR` 标志时使用
#### 流控制（Flow Control）选项


流控制（FC）选项可以使用 `CAN_ISOTP_RECV_FC` optname 传递，以提供用于接ISO-TP PDU 的通信参数

    struct can_isotp_fc_options fc_opts;
    ret = setsockopt(s, SOL_CAN_ISOTP, CAN_ISOTP_RECV_FC, &fc_opts, sizeof(fc_opts));

其中 `can_isotp_fc_options` 结构包含以下内容

    struct can_isotp_options {
        u8 bs;
        u8 stmin;
        u8 wftmax;
    };

- `bs`：在流控制帧中提供的 blocksize
- `stmin`：在流控制帧中提供的最小分离时间；可以具有以下值（其它值保留）
  - 0x00 - 0x7F  - 127 毫秒

  - 0xF1 - 0xF9 00 微秒 - 900 微秒

- `wftmax`：在流控制帧中提供的最大等待帧数量
#### 链路层（Link Layer）选项


链路层（LL）选项可以使用 `CAN_ISOTP_LL_OPTS` optname 传递：


    struct can_isotp_ll_options ll_opts;
    ret = setsockopt(s, SOL_CAN_ISOTP, CAN_ISOTP_LL_OPTS, &ll_opts, sizeof(ll_opts));

其中 `can_isotp_ll_options` 结构包含以下内容

    struct can_isotp_ll_options {
        u8 mtu;
        u8 tx_dl;
        u8 tx_flags;
    };

- `mtu`：生成和接受CAN 帧类型，可以等于经典 CAN 帧的 `CAN_MTU`，或 CAN FD 帧的 `CANFD_MTU`
- `tx_dl`：发送帧的最大载荷长度，可以取以下值之一2604284。大8 的值仅适用CAN FD 流量（即：`mtu = CANFD_MTU`）
- `tx_flags`：在帧创建时设置`struct canfd_frame.flags` 中的标志。仅适用CAN FD 流量（即：`mtu = CANFD_MTU`）
#### 发stmin


可以使用 `CAN_ISOTP_TX_STMIN` optname 强制发送最小分离时间（stmin），并提供一个以微秒为单位的 stmin 值（32 位无符号整数）；这将覆盖接收方在流控制帧中发送的值：


    uint32_t stmin;
    ret = setsockopt(s, SOL_CAN_ISOTP, CAN_ISOTP_TX_STMIN, &stmin, sizeof(stmin));

#### 接收 stmin


可以使用 `CAN_ISOTP_RX_STMIN` optname 强制接收最小分离时间（stmin），并提供一个以微秒为单位的 stmin 值（32 位无符号整数）；时间戳差值小于该值的接收到的连续帧（Consecutive Frames，CF）将被忽略：


    uint32_t stmin;
    ret = setsockopt(s, SOL_CAN_ISOTP, CAN_ISOTP_RX_STMIN, &stmin, sizeof(stmin));

### 多帧传输支持


Linux 内核中包含的 ISO-TP 协议栈支持标准定义的多帧传输机制，但有以下限制：

- PDU 的最大大小由模块参数定义，并在编译时施加了硬限制
- 当传输正在进行时，后续对 `write(2)` 的调用会阻塞，而对 `send(2)` 的调用会根据 `MSG_DONTWAIT` 标志的存在与否而阻塞或失败
- 不支持发送“等待帧”：一PDU 是否能被完整接收，是在接收到首帧（First Frame）时决定的

## 示例


### 基本节点示例


以下示例实现了一个使用“普通”物理寻址的节点，RX ID 等于 0x18DAF142，TX ID 等于 0x18DA42F1。所有选项都保持为默认值

  int s;
  struct sockaddr_can addr;
  int ret;

  s = socket(PF_CAN, SOCK_DGRAM, CAN_ISOTP);
  if (s < 0)
      exit(1);

  addr.can_family = AF_CAN;
  addr.can_ifindex = if_nametoindex("can0");
  addr.can_addr.tp.tx_id = 0x18DA42F1 | CAN_EFF_FLAG;
  addr.can_addr.tp.rx_id = 0x18DAF142 | CAN_EFF_FLAG;

  ret = bind(s, (struct sockaddr *)&addr, sizeof(addr));
  if (ret < 0)
      exit(1);

  /** 现在可以使用 read(s, ...) 接收数据，使write(s, ...) 发送数**/
