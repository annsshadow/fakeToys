### 简

不断增长DRAM 容量与成本使得内存子系统的可靠性成为一个重要关注点。这些模块用于那些潜在被损坏的数据可能导致昂贵或致命问题的场景。内存错误是导致服务器和工作负载崩溃的最主要的硬件故障之一
内存擦除（scrubbing）是一项功能，其中 ECC（纠错码，Error-Correcting Code）引擎从每个内存介质位置读取数据，在必要时进行纠正，并将纠正后的数据写回同一内存介质位置
可以以可配置的速率DIMM 进行擦除，以检测未纠正的内存错误并尝试从检测到的错误中恢复，从而提供以下好处：

1. 主动擦除 DIMM 可降低可纠正错误演变为不可纠正错误的机会
2. 当检测到未纠正错误时，在尚未分配的内存页中捕获的错误会被隔离，并防止被分配给应用程序或操作系统
3. 这降低了软件或硬件产品遇到内存错误的可能性
4. 关于内存故障的额外数据可用于建立统计信息，随后用于决定是否使用诸如封装后修复（Post Package Repair）或备用（Sparing）等内存修复技术
内存擦除2 种类型：

1. 后台（巡逻，patrol）擦除，DRAM 空闲时进行
2. 按需擦除，针对特定的地址范围或内存区域
已经识别出多种针对硬件内存擦除器的接口类型，例如 CXL 内存设备巡逻擦除、CXL DDR5 ECS、ACPI RAS2 内存擦除，以ACPI NVDIMM ARS（地址范围擦除，Address Range Scrub）
不同内存擦除器之间的控制机制各不相同。为了支持标准化的用户空间工具，需要通过标准化的 ABI 来呈现这些控制
通用的内EDAC 擦除控制允许用户通过标准化的 sysfs 控制接口来管理系统中的底层擦除器。它将各种擦除功能的管理抽象为一组统一的操作
### 通用擦除控制功能的使用场

1. 已经识别出多种针对硬件内存擦除器的接口，包括 CXL 内存设备巡逻擦除、CXL DDR5 ECS、ACPI RAS2 内存擦除功能、ACPI NVDIMM ARS（地址范围擦除），以及基于软件的擦除器
   在已识别的硬件内存擦除器接口中，有些支持对巡逻（后台）擦除（例如 ACPI RAS2、CXL）和/或按需擦除（例ACPI RAS2、ACPI ARS）的控制。然而，不同擦除器之间的擦除控制接口各不相同，这突显了需要一个标准化的、通用sysfs 擦除控制接口，供用户空间进行管理并被脚本/工具使用
2. 用户空间擦除控制允许用户在必要时禁用擦除，例如，禁用后台巡逻擦除，或针对需要最小化或禁用后台活动的、对性能敏感的操作调整擦除速率
3. 用户空间工具能够在擦除器支持该功能的前提下，针对特定地址范围启用按需擦除
4. 用户空间工具还可以通过 sysfs 擦除控制，以可配置的擦除速率控制内存 DIMM 擦除。这种方式有几个好处
   4.1. 在用户访问受影响内存之前，尽早检测不可纠正的内存错误，有助于促进恢复
   4.2. 降低可纠正错误发展为不可纠正错误的可能性
5. 对热插拔内存进行策略控制是必要的，因为对于启动后添加CXL 设备，可能不存在系统级的 BIOS 或类似控制来管理擦除设置。确定这些设置是一项策略决策，需要在可靠性与性能之间进行权衡，因此应由用户空间来控制。因此，建议采用统一的接口来处理此功能，以与其他类似接口保持一致，而不是单独创建一个接口
### 擦除功能


#### CXL 内存擦除功能


CXL spec r3.1 [^1^]_ section 8.2.9.9.11.1 描述了内存设备巡逻擦除控制功能。设备巡逻擦除会主动定位错误并在常规周期内进行纠正。巡逻擦除控制允许用户空间的请求更改 CXL 巡逻擦除器的配置
巡逻擦除控制允许请求者指定完成巡逻擦除周期所需的小时数，前提是所请求的擦除速率必须在设备所能支持的擦除速率范围之内。在 CXL 驱动中，用户通过 sysfs 请求的每次擦除周期的秒数，会被重新缩放为每次擦除周期的小时数
此外，它们允许主机在该功能干扰需要关闭后台操作、对性能敏感的操作时，禁用该功能
#### 错误检查擦除（Error Check Scrub，ECS

CXL spec r3.1 [^1^]_ section 8.2.9.9.11.2 描述了错误检查擦除（ECS）—一项在 JEDEC DDR5 SDRAM 规范（JESD79-5）中定义的功能，允许 DRAM 在内部读取、纠正单比特错误，并将纠正后的数据位写回 DRAM 阵列，同时透明地统计错误计数
DDR5 设备每个设备包含若干个内存介质现场可更换单元（FRU，Field Replaceable Unit）。DDR5 ECS 功能以及 ECS 控制驱动支持针对每个 FRU 配置 ECS 参数
#### ACPI RAS2 基于硬件的内存擦

ACPI spec 6.5 [^2^]_ section 5.2.21 ACPI RAS2 描述了一ACPI RAS2 表，它提供平RAS 功能的接口，并支持对同一系统中同一组件的多个实例的给定 RAS 功能进行独立RAS 控制和能力管理
内存 RAS 功能适用于特定于内存RAS 能力、控制和操作。针对内存专RAS 功能RAS2 PCC 子空间具0x00（Memory）的功能类型
平台可以使用基于硬件的内存擦除功能来暴露与基于硬件的内存擦除引擎相关的控制和能力。按照规范，RAS2 内存擦除功能支持
1. 针对每个 NUMA 域（使用其邻近域标识）的独立内存擦除控制
2. 对整个内存系统进行后台（巡逻）擦除，以及针对特定内存区域的按需擦除
#### ACPI 地址范围擦除（Address Range Scrubbing，ARS

ACPI spec 6.5 [^2^]_ section 9.19.7.2 描述了地址范围擦除（ARS）。ARS 允许平台向系统软件通报内存错误。该功能允许系统软件阻止对内存中具有不可纠正错误的地址的访问。ARS 函数管理系统中存在的所NVDIMM。在任何给定时刻，整个系统范围内只能有一个擦除正在进行
按照规范，支持以下函数：

1. 查询给定地址范围ARS 能力，指示平台支ACPI NVDIMM 根设备未消费错误通知（Unconsumed Error Notification）
2. 启动 ARS 会触发给定内存地址范围的地址范围擦除。地址擦除可以针对易失性或持久性内存，或两者
3. 查询 ARS 状态命令允许软件获ARS 的状态，包括 ARS 的进度和 ARS 错误记录
4. 清除不可纠正错误
5. 转换 SPA
6. ARS 错误注入等
内核支持一个已有的 ARS 控制，ARS 目前尚未EDAC 中支持

### 示例


这些示例展示了其使用形式
1. CXL 内存巡逻擦
以下是已识别的、我们可能提高擦除速率的使用场景：

- 需要在设备粒度上进行擦除，因为某设备显示出异常高的错误
- 擦除可能应用于尚未上线的内存。这很可能是启动时系统范围的默认设置
- 以更高的速率进行擦除，因为监控软件已确定某个特定数据集需要更高的可靠性。这被称为差异化可靠性（Differentiated Reliability）
1.1. 基于设备的擦
CXL 内存通过 CXL 设备暴露给内存管理子系统，并最终暴露给用户空间。基于设备的擦除用于“第 1 CXL 内存巡逻擦除”中描述的第一个使用场景
当组合使用设备接口和区域接口的控制时“参见第 1.2 基于区域的擦除”
用于擦除sysfs 文件记录`Documentation/ABI/testing/sysfs-edac-scrub`

1.2. 基于区域的擦
CXL 内存通过 CXL 区域暴露给内存管理子系统，并最终暴露给用户空间。CXL 区域表示系统物理地址空间中已映射的内存容量。它们可以包含多CXL 内存设备的一个或多个部分，流量在它们之间交错。用户可能希望通过这个更抽象的区域来控制擦除速率，而不必找出组成设备并分别对它们进行编程。每个设备的擦除速率覆盖整个设备。因此，如果多个区域使用了该设备的某些部分，那么针对其他区域的擦除请求可能会导致比该特定区域所请求的更高的擦除速率
基于区域的擦除用于“第 1 CXL 内存巡逻擦除”中描述的第三个使用场景
用户空间必须遵循以下关于如何为任意混合需求设置擦除速率的规则集
1. 从最低期望擦除速率到最高期望擦除速率，依次处理每个区域并设置其擦除速率。后面的区域可能会覆盖单个设备上的擦除速率（从而可能潜在地覆盖整个区域）
2. 对于每个需要增强擦除（更高速率）的设备，设置其擦除速率。这将覆盖单个设备的擦除速率，将它们设置为它们所支撑的任何区域所需的最大速率，除非已经定义了特定速率
用于擦除sysfs 文件记录`Documentation/ABI/testing/sysfs-edac-scrub`

2. CXL 内存错误检查擦除（Error Check Scrub，ECS
错误检查擦除（ECS）功能使内存设备能够执行错误检查和纠正（ECC）并统计单比特错误。相关的内存控制器通过发送给内存设备的触发信号来设置 ECS 模式。CXL ECS 控制允许主机（即用户空间）更改错误计数模式的属性、每个段报告错误的阈值错误数（指示至少具有该数量错误的段数），并重置 ECS 计数器。因此，当检测到异常高的错误率时，在内存设备上发起错误检查擦除的责任可能在于内存控制器或平台
用于擦除sysfs 文件记录`Documentation/ABI/testing/sysfs-edac-ecs`
