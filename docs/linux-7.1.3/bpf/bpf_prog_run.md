
## 从用户空间运行 BPF 程序


本文档描述了用于从用户空间运行 BPF 程序的 `BPF_PROG_RUN` 机制。

    :local:
    :depth: 2


### 概述


`BPF_PROG_RUN` 命令可以通过 `bpf()` 系统调用使用，用于在内核中执行一个 BPF 程序并将结果返回给用户空间。这可用于针对用户提供的上下文对象对 BPF 程序进行单元测试，也可以作为在内核中显式执行程序以获得其副作用的一种方式。该命令此前名为 `BPF_PROG_TEST_RUN`，这两个常量都继续在 UAPI 头文件中定义，并被设为相同的值。

`BPF_PROG_RUN` 命令可用于执行以下类型的 BPF 程序：

- `BPF_PROG_TYPE_SOCKET_FILTER`
- `BPF_PROG_TYPE_SCHED_CLS`
- `BPF_PROG_TYPE_SCHED_ACT`
- `BPF_PROG_TYPE_XDP`
- `BPF_PROG_TYPE_SK_LOOKUP`
- `BPF_PROG_TYPE_CGROUP_SKB`
- `BPF_PROG_TYPE_LWT_IN`
- `BPF_PROG_TYPE_LWT_OUT`
- `BPF_PROG_TYPE_LWT_XMIT`
- `BPF_PROG_TYPE_FLOW_DISSECTOR`
- `BPF_PROG_TYPE_STRUCT_OPS`
- `BPF_PROG_TYPE_RAW_TRACEPOINT`
- `BPF_PROG_TYPE_SYSCALL`
- `BPF_PROG_TYPE_TRACING`
- `BPF_PROG_TYPE_NETFILTER`

使用 `BPF_PROG_RUN` 命令时，用户空间提供一个输入上下文对象，并且（对于操作网络数据包的程序类型）提供一个包含 BPF 程序所要处理的数据包数据的缓冲区。内核随后会执行该程序并将结果返回给用户空间。注意，在这种模式下运行期间程序不会产生任何副作用；特别是，数据包不会被真正重定向或丢弃，程序的返回码只会返回给用户空间。针对 XDP 程序的实时执行，另提供了一种单独的模式，下文单独说明。

### 在“实时帧模式”下运行 XDP 程序


`BPF_PROG_RUN` 命令具有一个用于运行实时 XDP 程序的单独模式，该模式可以执行 XDP 程序，使得程序执行之后数据包会像从物理接口到达一样真正由内核处理。该模式通过在向 `BPF_PROG_RUN` 提供 XDP 程序时设置 `BPF_F_TEST_XDP_LIVE_FRAMES` 标志来激活。

实时数据包模式针对所提供 XDP 程序的高性能重复执行进行了优化（例如，适合作为流量生成器使用），这意味着其语义不像常规的测试运行模式那样直接。具体来说：

- 在实时帧模式下执行 XDP 程序时，执行结果不会返回给用户空间；相反，内核将执行由程序返回码所指示的操作（丢弃数据包、重定向等）。因此，在此模式下运行于系统调用参数中设置 `data_out` 或 `ctx_out` 属性会被拒绝。此外，并非所有失败都会直接报告回用户空间；具体而言，只有建立过程或执行期间的致命错误（如内存分配错误）才会停止执行并返回错误。如果在数据包处理过程中发生错误（例如重定向到某个接口失败），执行将继续进行下一次重复；这些错误可以通过与常规 XDP 程序相同的跟踪点来检测。

- 用户空间可以像常规的（非实时）模式一样，在上下文对象中提供一个 ifindex。XDP 程序将如同数据包在该接口上到达一样被执行；即上下文对象的 `ingress_ifindex` 将指向该接口。此外，如果 XDP 程序返回 `XDP_PASS`，数据包将被注入内核网络协议栈，如同从该 ifindex 到达；如果它返回 `XDP_TX`，数据包将被**从该同一接口发出**。但请注意，由于程序执行并非发生在驱动上下文之中，一个 `XDP_TX` 实际上会被转换为与该同一接口的 `XDP_REDIRECT` 相同的操作（即，只有在驱动支持 `ndo_xdp_xmit` 驱动操作的情况下才会生效）。

- 当以多次重复运行程序时，执行将以批处理方式发生。批大小默认为 64 个数据包（与 NAPI 最大接收批大小相同），但可以由用户空间通过 `batch_size` 参数指定，最大为 256 个数据包。对于每一个批次，内核重复执行 XDP 程序，每次调用都会获得一份独立的数据包数据副本。对于每次重复，如果程序丢弃了数据包，该数据页会立即被回收（见下文）。否则，数据包会被缓冲，直到批次结束，此时该批次中以这种方式缓冲的所有数据包会被一次性发送出去。

- 在建立测试运行时，内核会初始化一个与批大小相同数量的、大小一致的内存页池。每个内存页都会用用户空间在 `BPF_PROG_RUN` 调用时提供的初始数据包数据进行初始化。在可能的情况下，这些页会在后续的程序调用中被回收，以提升性能。通常页会以整个批次为单位被回收，除非某个数据包被丢弃（无论是由于返回码，还是由于例如重定向错误），在这种情况下该页会立即被回收。如果一个数据包最终被传递给常规网络协议栈（因为 XDP 程序返回 `XDP_PASS`，或者因为它最终被重定向到某个将其注入协议栈的接口），该页会被释放，并在页池为空时分配一个新页。

  回收时，页内容不会被重写；只有上下文对象中的数据包边界指针（`data`、`data_end` 和 `data_meta`）会被重置为原始值。这意味着，如果一个程序重写了数据包内容，它必须准备好在后续调用中看到原始内容或被修改过的版本。
