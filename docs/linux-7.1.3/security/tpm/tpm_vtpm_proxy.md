## 用于 Linux 容器的虚拟 TPM 代理驱动


| Authors:
| Stefan Berger <stefanb@linux.vnet.ibm.com>

本文档描述用于 Linux 容器的虚拟可信平台模块（vTPM）代理设备驱动。

## 简介


这项工作的目标是为每个 Linux 容器提供 TPM 功能。这使得程序在容器中与 TPM 交互的方式，与它们在物理系统上与 TPM 交互的方式相同。每个容器都获得自己独特的、模拟的软件 TPM。

## 设计


为了让每个容器都能使用模拟的软件 TPM，容器管理栈需要创建一对设备，包括一个客户端 TPM 字符设备 `/dev/tpmX`（X=0,1,2...）和一个"服务端"文件描述符。前者通过创建具有相应主设备号和次设备号的字符设备被移入容器，而文件描述符被传递给 TPM 模拟器。容器内的软件随后可以使用字符设备发送 TPM 命令，模拟器将通过文件描述符接收这些命令，并用它来发回响应。

为了支持这一点，虚拟 TPM 代理驱动提供了一个设备 `/dev/vtpmx`，用于通过 ioctl 创建设备对。该 ioctl 以用于配置设备的 flags 作为输入。例如，这些 flags 指示 TPM 模拟器支持 TPM 1.2 还是 TPM 2 功能。ioctl 的结果是"服务端"的文件描述符以及所创建字符设备的主、次设备号。除此之外，还会返回 TPM 字符设备的编号。例如，如果创建了 `/dev/tpm10`，则返回的编号（`dev_num`）为 10。

一旦设备被创建，驱动将立即尝试与 TPM 通信。来自驱动的所有命令都可以从 ioctl 返回的文件描述符中读取。这些命令应当被立即响应。
