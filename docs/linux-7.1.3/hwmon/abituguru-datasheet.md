## uGuru 数据手册

首先，我所知道的关于 uGuru 的事情并非基于来自 Abit 的任何帮助、提示或数据手册。我关于 uGuru 的数据是通过我薄弱的“逆向工程”知识拼凑起来的。

顺便说一句，你可能已经注意到 uGuru 并不是像 Abit 声称的那样是由 Abit 开发的芯片。它实际上只是 Winbond（W83L950D）创建的一个微处理器（uC）。而且，读取这个特定 uC 的手册或给 Winbond 发邮件寻求帮助都不会得到任何关于 uGuru 的有用数据，因为是对 uC 内部程序的调用在做出响应。

## 探测（Detection）

据所知，uGuru 总是位于并使用（ISA）I/O 端口 0xE0 和 0xE4，所以我们不必扫描任何端口范围，只需检查这两个端口持有的值用于探测。我们将 0xE0 称为 CMD（命令端口），将 0xE4 称为 DATA，因为 Abit 用这些名称来指代它们。

如果 DATA 持有 0x00 或 0x08 且 CMD 持有 0x00 或 0xAC，则可能存在 uGuru。我们必须在数据端口检查两个不同的值，因为在重启后 uGuru 在这里将持有 0x00，但如果驱动被移除之后再次加载，数据端口将持有 0x08，更多内容见后文。

在对 Linux 内核驱动进行更广泛的测试后，出现了一些 uGuru 变体，它们会在 CMD 端口持有 0x00 而不是 0xAC，因此我们也必须针对两个不同的 CMD 值进行测试。在这些 uGuru 上，DATA 最初会持有 0x09，并且只有在先读取 CMD 之后才会持有 0x08，所以必须先读取 CMD！

为了真正确认 uGuru 存在，应对一个或多个寄存器集合进行测试读取。


## 读取 / 写入


### 寻址（Addressing）

uGuru 有几个不同的寻址层级。我们将第一个寻址层级称为 bank（存储体）。一个 bank 持有一个或多个传感器的数据。一个 bank 中某个传感器的数据为一个或多个字节大小。

给定 bank 的字节数是固定的，你应该总是读取或写入那么多字节，读取/写入更多将失败，写入少于给定 bank 字节数的结果是不确定的。

所有已知的 bank 地址、该 bank 中的传感器数量、每个传感器的字节数以及这些字节的内容/含义见下文。

尽管本文档和内核驱动都沿用了 bank 内寻址的传感器术语，但这并非 100% 正确，例如在 bank 0x24 中，bank 内的寻址选择的是 PWM 输出而非传感器。

注意，有些 bank 既有读地址也有写地址，这就是 uGuru 判断是对 bank 进行读还是写的方式，因此读取时应始终使用读地址，写入时使用写地址。写地址总是比读地址大 1。


### uGuru 就绪（ready）

在对 uGuru 进行读取或写入之前，必须先将 uGuru 置于 “ready（就绪）” 模式。

要将 uGuru 置于就绪模式，首先向 DATA 写入 0x00，然后等待 DATA 持有 0x09，DATA 应在 250 次读取周期内读到 0x09。

接下来**必须**读取 CMD，它应持有 0xAC，通常第一次读取时 CMD 会持有 0xAC，但有时需要读取若干次（最多 50 次）后 CMD 才持有 0xAC。

读取 CMD 后，DATA 应持有 0x08，这意味着 uGuru 已准备好接收输入。如上所述，DATA 通常第一次读取时持有 0x08，但并非总是如此。这一步可以跳过，但如果 uGuru 尚未在 DATA 报告 0x08 你就继续写入 bank 地址，会发生什么是未确定的。


### 向 uGuru 发送 bank 和传感器地址

首先 uGuru 必须处于上述 “ready” 模式，DATA 应持有 0x08，表示 uGuru 需要输入，这里是 bank 地址。

接下来将 bank 地址写入 DATA。写入 bank 地址后，等待 DATA 再次持有 0x08，表示它需要/已准备好接收更多输入（最多 250 次读取）。

一旦 DATA 再次持有 0x08，将传感器地址写入 CMD。


### 读取（Reading）

首先按上述方式发送 bank 和传感器地址。
然后对于你要读取的每个数据字节，等待 DATA 持有 0x01，表示 uGuru 已准备好被读取（最多 250 次读取），一旦 DATA 持有 0x01，从 CMD 读取该字节。

一旦所有字节都被读取，data 将持有 0x09，但没有必要测试这一点。注意字节数依赖于 bank 地址，见上文和下文。

完成一次成功读取后，建议将 uGuru 放回就绪模式，以便它为下一次读取/写入周期做好准备。这样，如果你的程序/驱动被卸载之后再次加载，上述探测算法仍然有效。



### 写入（Writing）

首先按上述方式发送 bank 和传感器地址。
然后对于你要写入的每个数据字节，等待 DATA 持有 0x00，表示 uGuru 已准备好被写入（最多 250 次读取），一旦 DATA 持有 0x00，将字节写入 CMD。

一旦所有字节都被写入，等待 DATA 持有 0x01（最多 250 次读取），别问为什么是这样。

一旦 DATA 持有 0x01，读取 CMD，此时它应持有 0xAC。

完成一次成功写入后，建议将 uGuru 放回就绪模式，以便它为下一次读取/写入周期做好准备。这样，如果你的程序/驱动被卸载之后再次加载，上述探测算法仍然有效。


### 陷阱（Gotchas）

在对 Linux 内核驱动进行更广泛的测试后，出现了一些 uGuru 变体，它们在写入 bank 地址后不会在 250 次读取内于 DATA 持有 0x08。对于这些版本，这种情况相当频繁，使用更大的超时没有帮助，它们只是离线一两秒，进行某些内部校准或其他操作。你的代码应该准备好处理这种情况，在这种无响应的情况下，就 sleep 一会儿然后重试。


## 地址映射（Address Map）


### Bank 0x20 告警（Alarms）（R）

该 bank 包含 0 个传感器，也就是说传感器地址被忽略（但必须写入），直接使用 0。Bank 0x20 包含 3 个字节：

字节 0：
  该字节持有 Sensor Bank1 中传感器 0-7 的告警标志，bit 0 对应传感器 0，1 对应 1，依此类推。

字节 1：
  该字节持有 Sensor Bank1 中传感器 8-15 的告警标志，bit 0 对应传感器 8，1 对应 9，依此类推。

字节 2：
  该字节持有 Sensor Bank2 中传感器 0-5 的告警标志，bit 0 对应传感器 0，1 对应 1，依此类推。


### Bank 0x21 Sensor Bank1 值 / 读数（Readings）（R）

该 bank 包含 16 个传感器，每个传感器包含 1 个字节。
目前已知以下传感器在所有主板上都可用：

- 传感器  0 CPU 温度
- 传感器  1 系统（SYS）温度
- 传感器  3 CPU 核心电压
- 传感器  4 DDR 电压
- 传感器 10 DDR Vtt 电压
- 传感器 15 PWM 温度

字节 0：
  该字节持有来自传感器的读数。Bank1 中的传感器既可以是电压传感器也可以是温度传感器，这取决于主板。不过 uGuru 似乎确实知道（被编程为）连接了哪种传感器，见 Sensor Bank1 Settings 描述。

电压传感器使用线性刻度，读数 0 对应 0 伏，读数 255 对应 3494 mV。然而，用于更高电压的传感器是通过分压电路连接的。目前已知使用的分压电路产生的范围为：0-4361mV、0-6248mV 或 0-14510mV。3.3 伏电源使用 0-4361mV 范围，5 伏使用 0-6248mV，12 伏使用 0-14510mV。

温度传感器也使用线性刻度，读数 0 对应 0 摄氏度，读数 255 对应 255 摄氏度。


### Bank 0x22 Sensor Bank1 设置（R）与 Bank 0x23 Sensor Bank1 设置（W）

这些 bank 包含 16 个传感器，每个传感器包含 3 个字节。每组 3 个字节包含与 Bank 0x21 中相同传感器地址的传感器的设置。

字节 0：
  所选传感器的告警行为。置 1 启用所描述的对应行为。

Bit 0：
  如果测量温度超过警告阈值则告警		(RW) [^1^]_

Bit 1：
  如果测量电压超过最大阈值则告警		(RW) [^2^]_

Bit 2：
  如果测量电压低于最小阈值则告警		(RW) [^2^]_

Bit 3：
  告警时蜂鸣（Beep）				(RW)

Bit 4：
  如果告警原因是测量温度超过警告阈值则为 1	(R)

Bit 5：
  如果告警原因是测量电压超过最大阈值则为 1	(R)

Bit 6：
  如果告警原因是测量电压低于最小阈值则为 1	(R)

Bit 7：
  - 电压传感器：如果告警持续超过 4 秒则关机	(RW)
  - 温度传感器：如果温度超过关机阈值则关机	(RW)

       注意：通过一些技巧，这可以用来找出检测到了什么类型的传感器，详见 Linux 内核驱动中一个带有大量注释、说明如何实现的示例。

字节 1：
  - 温度传感器：警告阈值  （刻度同 bank 0x21）
  - 电压传感器：最小阈值  （刻度同 bank 0x21）

字节 2：
  - 温度传感器：关机阈值  （刻度同 bank 0x21）
  - 电压传感器：最大阈值  （刻度同 bank 0x21）


### Bank 0x24 风扇的 PWM 输出（R）与 Bank 0x25 风扇的 PWM 输出（W）

这些 bank 包含 3 个 “传感器”，每个传感器包含 5 个字节。
  - 传感器 0 通常控制 CPU 风扇
  - 传感器 1 通常控制 NB（或单芯片的芯片组）风扇
  - 传感器 2 通常控制系统风扇

字节 0：
  标志 0x80 启用控制，禁用时风扇以 100% 转速运行。
  低半字节为 bank 0x21 中用于控制的（温度）传感器地址。

字节 1：
  0-255 = 0-12v（线性），指定当温度低于阈值（在字节 3 中指定）时风扇将旋转的 voltage。

字节 2：
  0-255 = 0-12v（线性），指定当温度高于阈值（在字节 4 中指定）时风扇将旋转的 voltage。

字节 3：
  低阈值温度  （刻度同 bank 0x21）

字节 4：
  高阈值温度  （刻度同 bank 0x21）


### Bank 0x26 Sensors Bank2 值 / 读数（R）

该 bank 包含 6 个传感器（据我所知），每个传感器包含 1 个字节。

目前已知以下传感器在所有主板上都可用：
  - 传感器 0：CPU 风扇转速
  - 传感器 1：NB（或单芯片的芯片组）风扇转速
  - 传感器 2：系统风扇转速

字节 0：
  该字节持有来自传感器的读数。0-255 = 0-15300（线性）


### Bank 0x27 Sensors Bank2 设置（R）与 Bank 0x28 Sensors Bank2 设置（W）

这些 bank 包含 6 个传感器（据我所知），每个传感器包含 2 个字节。

字节 0：
  所选传感器的告警行为。置 1 启用所描述的对应行为。

Bit 0：
  如果测量转速低于最小阈值则告警	(RW)

Bit 3：
  告警时蜂鸣（Beep）			(RW)

Bit 7：
  如果告警持续超过 4 秒则关机		(RW)

字节 1：
  最小阈值（刻度同 bank 0x26）


## 给喜欢冒险者的警告

给那些想做实验、看看能否弄清楚电压/时钟编程的人一句忠告：我曾尝试用用于传感器 bank（0x20-0x28）的读取代码只读取（仅读取）bank 0-0x30，这导致了电压的_永久_重编程，幸运的是我把传感器部分配置为在任何超出规格的电压下关闭我的系统，这可能救了我的电脑（重启后我设法立即进入 bios 并重新加载了默认值）。这可能意味着非传感器部分的读/写周期与传感器部分不同。
