### 描述

LM90 是一款数字温度传感器。它可感测自身温度以及最多一个外部二极管的温度。它与许多其它设备兼容，其中许多受本驱动支持。

本驱动所支持的芯片系列衍生自 MAX1617。该芯片以及多种兼容芯片支持本地与远端温度传感器，精度为 8 位。后续芯片提供了更高的精度以及其它附加特性，例如迟滞（hysteresis）和温度偏移寄存器。

请注意，没有简单的方法区分 MAX6657、MAX6658 和 MAX6659 变体。只有当芯片位于地址 0x4d 或 0x4e，或者芯片类型被显式选择为 max6659 时，本驱动才支持 MAX6659 的额外特性。
MAX6680 与 MAX6681 仅在引脚排列上不同，因此它们显然无法（也不必）被区分。

该系列中不同的芯片组虽然非常相似，但并不严格相同。作为参考，下面给出一份非穷举的具体特性列表：

所有温度值均以摄氏度给出。本地温度分辨率为 1.0 度，远端温度分辨率为 0.125 度，但 MAX6654、MAX6657、MAX6658 和 MAX6659 的两种温度分辨率均为 0.125 度。

每个传感器都有各自的高、低限值，外加一个临界限值。此外，两个临界值共用一个相对迟滞值。为方便用户空间应用程序，导出了两个绝对值（每个通道一个），但这些值当然是相关联的。只有本地迟滞可从用户空间设置，相同的增量也适用于远端迟滞。

lm90 驱动不会以高于 update_interval 属性所配置的频率更新其值；更频繁地读取不会造成损害，但会返回“旧”值。

### SMBus 告警支持

本驱动对 SMBus 告警提供基本支持。当接收到告警时，会读取状态寄存器并记录出故障的温度通道。

Analog Devices 芯片（ADM1032、ADT7461 和 ADT7461A）以及 ON Semiconductor 芯片（NCT1008）未能正确实现 SMBus 告警协议，因此需要额外小心：接收到告警时会禁用 ALERT 输出，仅当告警解除后才重新启用。否则，只要告警处于活动状态，该芯片就会阻塞总线上其它芯片的告警。

### PEC 支持

ADM1032 是该系列中唯一支持 PEC 的芯片。不过它并非在所有事务上都支持 PEC，因此需要一些小心。

读取寄存器值时，PEC 字节由 ADM1032 芯片计算并发送。然而，在组合事务（SMBus Read Byte）的情况下，ADM1032 只对消息的后半部分而非整体计算 CRC 值，因为它认为消息的前半部分属于不同的事务。因此，CRC 值与 SMBus 主设备所期望的不同，导致所有读取失败。

因此，只有当总线支持 SMBus Send Byte 和 Receive Byte 事务类型时，lm90 驱动才会为 ADM1032 启用 PEC。将使用这些事务而非 SMBus Read Byte 来读取寄存器值，PEC 才能正常工作。

此外，ADM1032 不支持带 PEC 的 SMBus Send Byte。相反，它会尝试将 PEC 值写入寄存器（因为带 PEC 的 SMBus Send Byte 事务类似于不带 PEC 的 Write Byte 事务），而这并非我们所期望的。因此，lm90 驱动在 SMBus Send Byte 事务上显式禁用 PEC。

在字节数据事务上启用 PEC 会在正常情况下显著增加带宽占用（写 +33%，读 +25%）。由于读取需要使用两个 SMBus 事务，这一开销跃升至 +50%。更糟的是，两个事务通常意味着等待事务完成的延迟加倍，实际上使寄存器缓存刷新时间翻倍。我想可靠性是有代价的，但这次代价相当高昂。

因此，考虑到并非所有人都愿意接受这种变慢，PEC 默认禁用，并可通过 sysfs 启用。只需向 "pec" 文件写入 1 即可启用 PEC，向该文件写入 0 则可再次禁用 PEC。
