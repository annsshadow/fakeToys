## 基础知识


该驱动是通用的，即它不包含任何针对特定磁带驱动器定制的代码。磁带参数可以通过以下三种方法之一指定：

1. 每个用户都可以直接使用 ioctls 指定其想要使用的磁带参数。这是一种管理上非常简单且灵活的方法，适用于单用户工作站。但在多用户环境中，下一个用户会发现磁带参数停留在上一个用户离开时的状态。

2. 系统管理员（root）可以使用 MTSETDRVBUFFER ioctl 为某些磁带参数（如块大小和密度）定义默认值。这些参数可以被编程为在新磁带装入驱动器时生效，或者在磁带开头开始写入时生效。如果磁带驱动器能很好地自动检测磁带格式（如某些 QIC 驱动器），则第二种方法适用。其结果是：任何磁带都可被读取，可以沿用现有格式继续写入，而如果使用从头重写磁带（或首次写入新磁带），则使用默认格式。第一种方法适用于驱动器自动检测能力不足，且设备只有单一"合理"模式的场景。例如，一个仅用于变长块模式的 DAT 驱动器（我不知道这是否合理 :-）。

用户可以覆盖系统管理员定义的参数。这些更改会一直保持到默认值再次生效。

3. 默认情况下，最多可定义四种模式，并通过次设备号（第 5 位和第 6 位）选择。模式数量可以通过修改 st.h 中的 ST_NBR_MODE_BITS 来改变。模式 0 对应上面讨论的默认值。其他模式处于休眠状态，直到由系统管理员（root）定义。开始定义新模式时，会使用模式 0 的配置作为定义新模式的起点。

使用模式可以让系统管理员在用户无法直接访问的部分缓冲参数（缓冲写入和异步写入）上给用户提供选择。模式还允许在多磁带操作中在格式之间选择（显式覆盖的参数在装入新磁带时会被重置）。

如果使用多种模式，所有模式应包含相同的一组参数定义。

许多 Unix 系统包含内部表，将不同的模式关联到受支持的设备。Linux 的 SCSI 磁带驱动不包含此类表（将来也不会包含）。取而代之的是，可以编写一个工具程序来获取设备发送的查询（inquiry）数据，扫描其数据库，并使用 ioctls 设置模式。另一种替代方案是编写一个小脚本，使用 mt 来设置针对系统定制的默认值。

该驱动支持定长块和变长块（在缓冲区限制内）。自动倒带（次设备号等于设备号）和非倒带设备（次设备号为 128 + 设备号）均已实现。

在变长块模式下，write() 中的字节数决定磁带上物理块的大小。读取时，如果 read() 的字节数至少达到块大小，驱动器会读取下一个磁带块并将数据返回给用户。否则，返回错误 ENOMEM。

在定长块模式下，驱动器与驱动之间的数据传输以块大小的倍数进行。write() 的字节数必须是块大小的倍数。读取时虽不要求如此，但为保证可移植性建议这样做。

支持使用一个或多个分区对磁带进行分区。默认情况下，每个驱动的分区磁带支持都是禁用的，可通过 ioctl MTSETDRVBUFFER 启用。

默认情况下，当设备在完成写入后关闭，且最后一次操作是写入时，驱动会写一个文件标记（filemark）。也可以可选地写两个文件标记。在这两种情况下，数据结束由连续两次读取返回零字节来表示。

不带 SCSI 命令块中 immediate 位的文件标记写入充当同步点，即在命令返回前，驱动器缓冲区中剩余的所有数据都会被写入磁带。这确保写入错误在该点被捕获，但这需要时间。在某些应用中，必须快速写入多个连续文件。可以使用 MTWEOFI 操作来写入文件标记而不刷新驱动器缓冲区。关闭时写入文件标记总是会刷新驱动器缓冲区。但是，如果上一次操作是 MTWEOFI，close() 不会写文件标记。如果程序想要在文件之间关闭/打开磁带设备并希望跳过等待，可以使用这一点。

如果执行倒带、offline、bsf 或 seek，且上一次磁带操作是写入，则在移动磁带之前会写一个文件标记。

编译选项在文件 linux/drivers/scsi/st_options.h 中定义。

4. 如果使用了 open 选项 O_NONBLOCK，即使驱动器未就绪，open 也会成功。如果未使用 O_NONBLOCK，驱动会等待驱动器就绪。如果在 ST_BLOCK_SECONDS 秒内未就绪，open 会以 errno 值 EIO 失败。使用 O_NONBLOCK 时，即使驱动中有写保护磁带，也可以打开设备以进行写入（尝试写入的命令会返回错误）。


## 次设备号


该磁带驱动目前支持最多 2^17 个驱动器（如果每个驱动器使用 4 种模式）。

```

    dev_upper non-rew mode dev-lower
    20 -  8     7    6 5  4      0

```
非倒带位始终是位 7（最低字节中的最高位）。定义模式的位位于非倒带位之下。其余位定义磁带设备号。这种编号方式与次设备号仅为 8 位宽时使用的编号方式向后兼容。


## Sysfs 支持


该驱动会创建目录 /sys/class/scsi_tape，并填充与现有磁带设备对应的子目录。每种模式都有自动倒带和非倒带两项条目。名称为 stxy 和 nstxy，其中 x 是磁带编号，y 是与模式对应的字符（none、l、m、a）。例如，第一个磁带设备的目录为（假设四种模式）：st0  nst0  st0l  nst0l  st0m  nst0m  st0a  nst0a。

每个目录包含以下条目：default_blksize  default_compression
default_density  defined  dev  device  driver。文件 'defined' 在模式已定义时包含 1，未定义时包含 0。文件 'default_*' 包含用户设置的默认值。值 -1 表示未设置默认值。文件 'dev' 包含与此设备对应的设备号。链接 'device' 和 'driver' 指向 SCSI 设备和驱动条目。

每个目录还包含条目 'options'，显示当前启用的驱动和模式选项。文件中的值是一个位掩码，其位定义与设置选项时使用的 MTSETDRVBUFFER 相同。

每个目录包含条目 'position_lost_in_reset'。如果此值为 1，则在设备重置后，对该设备的读写会被阻塞。大多数设备在重置后会倒带磁带，且读写无法访问用户期望的磁带位置。

会创建一个名为 'tape' 的链接，从 SCSI 设备目录指向上级目录中对应于模式 0 自动倒带设备的目录（例如 st0）。


## 磁带设备的 Sysfs 与统计信息


st 驱动在 sysfs 文件系统中维护磁带驱动器的统计信息。可以使用以下方法定位可用的统计信息（假设 sysfs 挂载在 /sys）：

1. 对目录 /sys/class/scsi_tape 使用 opendir(3)
2. 使用 readdir(3) 读取目录内容
3. 使用 regcomp(3)/regexec(3) 将目录条目匹配到扩展正则表达式 "^st[0-9]+$"
4. 从 /sys/class/scsi_tape/<match>/stats 目录访问统计信息（其中 <match> 是 /sys/class/scsi_tape 中匹配该扩展正则表达式的目录条目）

使用这种方法的原因是，指向同一磁带驱动的所有字符设备使用相同的统计信息。这意味着 st0 与 nst0 具有相同的统计信息。

该目录包含以下统计文件：

1. in_flight
      - 当前针对此设备未完成的 I/O 数量。
2. io_ns
      - 等待所有 I/O（包括读和写）完成所花费的时间（纳秒）。这包括磁带移动命令，例如在文件或集合标记之间查找，以及隐式磁带移动（如关闭磁带设备时使用倒带）。
3. other_cnt
      - 发送给磁带驱动器而非读或写命令的 I/O 数量。完成这些命令所花费的时间使用以下公式计算：io_ms - read_ms - write_ms。
4. read_byte_cnt
      - 从磁带驱动器读取的字节数。
5. read_cnt
      - 发送给磁带驱动器的读请求数量。
6. read_ns
      - 等待读请求完成所花费的时间（纳秒）。
7. write_byte_cnt
      - 写入磁带驱动器的字节数。
8. write_cnt
      - 发送给磁带驱动器的写请求数量。
9. write_ns
      - 等待写请求完成所花费的时间（纳秒）。
10. resid_cnt
      - 在读或写过程中发现残差（residual）量非零的次数。这应意味着程序发出了大于磁带上块大小的读请求。对于写，意味着并非所有数据都写入了磁带。


   in_flight 值在一个 I/O 开始时递增，但 I/O 本身在完成前不会加入统计。

read_cnt、write_cnt 和 other_cnt 的总和可能与设备级别的 iodone_cnt 值不同。磁带统计只统计通过 st 模块发出的 I/O。

读取统计时，在 I/O 进行过程中可能在时间上不一致。各个值是原子读取和写入的，但通过 sysfs 回读时，它们可能正处于启动 I/O 或 I/O 完成时的更新过程中。

in_flight 中显示的值在更新任何统计信息之前递增，并在 I/O 完成更新统计信息后递减。当没有 st 驱动发出的未完成 I/O 时，in_flight 的值为 0。磁带统计不考虑通过 sg 设备执行的任何 I/O。

## BSD 与 Sys V 语义


用户可以通过定义符号 ST_SYSV 的值，在磁带驱动的这两种行为之间选择。两者的区别在于读取文件被关闭时。BSD 语义将磁带留在当前位置，而 SYS V 语义会将磁带移动到下一个文件标记之后，除非刚刚跨过文件标记。

默认是 BSD 语义。


## 缓冲


驱动尝试直接与用户空间进行传输。如果不可行，则使用运行时分配的驱动缓冲区。如果整个传输无法进行直接 I/O，则使用驱动缓冲区（即不对单个页使用反弹缓冲区）。直接 I/O 可能因为多种原因而无法进行，例如：

- 一个或多个页位于 HBA 无法访问的地址
- 传输中的页数超过了 HBA 允许的分散/聚集（scatter/gather）段数
- 一个或多个页无法锁定到内存中（在任何合理情况下都不应发生）

驱动缓冲区的大小始终至少为一块磁带块。在定长块模式下，最小缓冲区大小由 ST_FIXED_BUFFER_BLOCKS 定义（以 1024 字节为单位）。对于小块大小，这允许缓冲多个块，并使用一次 SCSI 读或写来传输所有块。如果 ST_BUFFER_WRITES 非零且未使用直接 I/O，则允许在定长块模式下跨写调用缓冲数据。缓冲区分配使用大小为 2^n *（页大小）的内存块。因此，实际缓冲区大小可能大于最小允许缓冲区大小。

注意，如果使用直接 I/O，小写入不会被缓冲。从 2.4 迁移时这可能会造成意外。那时小写入（例如不带 -b 选项的 tar）可能具有良好的吞吐量，但在 2.6 中不再如此。可以关闭直接 I/O 来解决这个问题，但更好的解决方案是使用更大的 write() 字节数（例如 tar -b 64）。

异步写入。将缓冲区内容写入磁带的操作被启动，写调用立即返回。状态在下一次磁带操作时检查。异步写入不会用于直接 I/O，也不会用于定长块模式。

缓冲写入和异步写入在某些罕见情况下可能导致多卷操作出现问题，如果在提前警告标记之后磁带空间不足以刷新驱动缓冲区。

定长块模式的预读（ST_READ_AHEAD）。即使当前读命令不打算获取所有数据，也会尝试填充缓冲区。对于那些不喜欢文件标记截断读请求或不喜欢回退的驱动器，应禁用。

分散/聚集缓冲区（由物理内存中非连续块组成的缓冲区）在无法分配连续缓冲区时使用。为了支持所有 SCSI 适配器（包括不支持分散/聚集的），缓冲区分配使用以下三种块：

1. 初始段，用于所有 SCSI 适配器，包括不支持分散/聚集的。如果系统能提供该大小的块，则此缓冲区的大小为 (PAGE_SIZE << ST_FIRST_ORDER) 字节（且不大于 ST_BUFFER_BLOCKS 指定的缓冲区大小）。如果此大小不可用，驱动会将大小减半并重试，直到一个页的大小。st_options.h 中的默认设置使驱动尝试将整个缓冲区作为一块分配。
2. 用于填充指定缓冲区大小的分散/聚集段，分配时尽量使用尽可能多的段，但段数不超过 ST_FIRST_SG。
3. 阶段 1 和 2 使用的段数与 ST_MAX_SG（或模块参数 max_sg_segs）之间的剩余段，在必要时用于在运行时扩展缓冲区。如果 SCSI 适配器允许的最大分散/聚集段数更小，则不会超过该最大段数。如果 SCSI 适配器允许的最大值小于阶段 1 和 2 使用的段数，则扩展缓冲区将始终失败。


## 写入时的 EOM 行为


当遇到介质末端（end of medium）提前警告时，当前写操作完成并返回字节数。下一次写返回 -1，且 errno 被设为 ENOSPC。为了能够写入尾部（trailer），允许进行下一次写，如果成功，则返回字节数。此后，-1 和字节数交替返回，直到遇到物理介质末端（或其他错误）。

## 模块参数


缓冲区大小、写阈值以及分配缓冲区的最大数量可以在驱动作为模块加载时配置。关键字如下：

========================== ===========================================
buffer_kbs=xxx             定长块模式的缓冲区大小被设为 xxx 千字节
write_threshold_kbs=xxx    写阈值（以千字节计）被设为 xxx
max_sg_segs=xxx            分散/聚集段的最大数量
try_direct_io=x            若此值非零，尝试在用户缓冲区与磁带机之间直接传输
========================== ===========================================

注意，如果更改了缓冲区大小但未设置写阈值，写阈值会被设为新缓冲区大小 - 2 kB。


## 引导时配置


如果驱动被编译进内核，同样的参数也可以使用（例如）LILO 命令行设置。推荐的语法是使用加载为模块时相同的关鍵字，但前面加上 'st.'。例如，要设置分散/聚集段的最大数量，应使用参数 'st.max_sg_segs=xx'（xx 是分散/聚集段的数量）。

为兼容性，支持早期 2.5 和 2.4 内核版本的旧语法。可以使用与加载为模块时相同的关鍵字。如果设置了多个参数，键值对以逗号分隔（不允许空格）。可以使用冒号代替等号。定义以
```

	st=buffer_kbs:64,write_threshold_kbs:60

```
```

           st=aa[,bb[,dd]]

```
开头，其中：

  - aa 是定长块模式的缓冲区大小，以 1024 字节为单位
  - bb 是写阈值，以 1024 字节为单位
  - dd 是分散/聚集段的最大数量


## IOCTLs


磁带定位以及驱动器参数使用 mtio.h 中定义的 ioctls 设置。磁带控制程序 'mt' 使用这些 ioctls。尝试找一个支持所有 Linux SCSI 磁带 ioctls 的 mt，并在磁带内容将被修改时以写入方式打开设备（从 Linux ftp 站点查找 mt-st* 软件包；GNU mt 不会以写入方式打开，例如用于擦除）。

支持的 ioctls 如下：

以下使用结构 mtop：

MTFSF
	向前跳过 count 个文件标记。磁带定位在文件标记之后。
MTFSFM
	同上，但磁带定位在文件标记之前。
MTBSF
	向后跳过 count 个文件标记。磁带定位在文件标记之前。
MTBSFM
	同上，但磁带定位在文件标记之后。
MTFSR
	向前跳过 count 个记录。
MTBSR
	向后跳过 count 个记录。
MTFSS
	向前跳过 count 个集合标记（setmark）。
MTBSS
	向后跳过 count 个集合标记（setmark）。
MTWEOF
	写入 count 个文件标记。
MTWEOFI
	写入 count 个文件标记，并设置 immediate 位（即不等待数据写入磁带）。
MTWSM
	写入 count 个集合标记（setmark）。
MTREW
	倒带。
MTOFFL
	使设备离线（通常倒带并弹出）。
MTNOP
	除刷新缓冲区外不做任何事情。
MTRETEN
	重新张紧磁带。
MTEOM
	定位到已记录数据的末尾。
MTERASE
	擦除磁带。如果参数为零，使用短擦除命令；其他值使用长擦除命令。
MTSEEK
	定位到指定的磁带块计数。对 SCSI-1 驱动器使用与 Tandberg 兼容的 seek（QFA），对 SCSI-2 驱动器使用 SCSI-2 seek。seek 之后状态中的文件和块号无效。
MTSETBLK
	设置驱动器块大小。设为零将驱动器设为变长块模式（如果适用）。
MTSETDENSITY
	将驱动器密度代码设为 arg。可用代码参见驱动器文档。
MTLOCK 与 MTUNLOCK
	显式锁定/解锁磁带驱动器门。
MTLOAD 与 MTUNLOAD
	显式装载和卸载磁带。如果命令参数 x 介于 MT_ST_HPLOADER_OFFSET + 1 和 MT_ST_HPLOADER_OFFSET + 6 之间，则 x 的值被发送给驱动器，选择要使用的 HP C1553A 换带机的磁带槽。
MTCOMPRESSION
	使用 SCSI 模式页 15 设置压缩或不压缩的驱动器模式。注意有些驱动器使用其他方法来控制压缩。有些驱动器（如 Exabyte）使用密度代码控制压缩。有些驱动器使用另一个模式页，但该页尚未在驱动中实现。有些不具备压缩能力的驱动器会接受任何压缩模式而不报错。
MTSETPART
	将磁带移动到下一次磁带操作所给定参数指定的分区。除非下一次磁带操作是 MTSEEK，否则磁带定位到的块是磁带在新活动分区中之前定位的块。在这种情况下，磁带直接移动到 MTSEEK 指定的块。除非设置了 MT_ST_CAN_PARTITIONS，否则 MTSETPART 无效。
MTMKPART
	格式化磁带为一个分区（参数为零）或两个分区（参数非零）。如果参数为正数，它指定分区 1 的大小（以兆字节计）。对于 DDS 驱动器和若干早期驱动器，这是物理上磁带的第 1 个分区。如果参数为负数，其绝对值指定分区 0 的大小（以兆字节计）。这是许多较新驱动器（如 LTO-5 及以上的 LTO 驱动器）的物理第 1 个分区。驱动器必须支持由发起者指定大小的分区。除非设置了 MT_ST_CAN_PARTITIONS，否则无效。
MTSETDRVBUFFER
	用于多个目的。命令从 count 经掩码 MT_SET_OPTIONS 获得，低序位用作参数。此命令仅允许超级用户（root）使用。子命令如下：

 - 0
           驱动器缓冲区选项被设为该参数。零表示不缓冲。
        - MT_ST_BOOLEANS
           设置缓冲选项。位为以下选项的新状态（启用/禁用）（括号内说明该选项是全局的还是可为每种模式分别指定）：

	     MT_ST_BUFFER_WRITES
		写缓冲（模式）
	     MT_ST_ASYNC_WRITES
		异步写（模式）
             MT_ST_READ_AHEAD
		预读（模式）
             MT_ST_TWO_FM
		写入两个文件标记（全局）
	     MT_ST_FAST_EOM
		使用 SCSI 间隔方式到 EOD（全局）
	     MT_ST_AUTO_LOCK
		自动锁定驱动器门（全局）
             MT_ST_DEF_WRITES
		默认值仅用于写（模式）
	     MT_ST_CAN_BSR
		可以回退多个记录用于重新定位磁带（全局）
	     MT_ST_NO_BLKLIMS
		驱动不向驱动器查询块限制（块大小只能改为变长）（全局）
	     MT_ST_CAN_PARTITIONS
		启用对分区磁带的支持（全局）
	     MT_ST_SCSI2LOGICAL
		对 SCSI-2 驱动器，MTSEEK 和 MTIOCPOS 中使用逻辑块号而非设备相关地址。除非存在使用设备相关地址（旧式）的磁带，否则建议设置此标志（全局）
	     MT_ST_SYSV
		设置 SYSV 语义（模式）
	     MT_ST_NOWAIT
		对某些命令启用 immediate 模式（即不等待命令完成）（例如倒带）
	     MT_ST_NOWAIT_EOF
		启用 immediate 文件标记模式（即写文件标记时不等待其完成）。关于写 immediate 文件标记的可能危险，请参见基础知识中关于 MTWEOFI 的说明。
	     MT_ST_SILI
		在变长块模式读取时，启用在 SCSI 命令中设置 SILI 位，以在读取短于字节数的块时提升性能；仅当确定驱动器支持 SILI 且 HBA 正确返回传输残差时设置
	     MT_ST_DEBUGGING
		调试（全局；调试必须编译进驱动）

 - MT_ST_SETBOOLEANS, MT_ST_CLEARBOOLEANS
	   设置或清除选项位。
        - MT_ST_WRITE_THRESHOLD
           将此设备的写阈值设为最低位指定的千字节数。
 - MT_ST_DEF_BLKSIZE
	   定义自动设置的默认块大小。值 0xffffff 表示不再使用默认值。
 - MT_ST_DEF_DENSITY, MT_ST_DEF_DRVBUFFER
	   用于设置或清除密度（8 位）和驱动器缓冲区状态（3 位）。如果值为 MT_ST_CLEAR_DEFAULT（0xfffff），将不再使用默认值。否则，值的低序位包含参数的新值。
 - MT_ST_DEF_COMPRESSION
	   如果最低字节的值为 0xff，则不再使用压缩默认值。否则最低位包含新的默认值。如果位 8-15 被设为非零数字，且该数字不是 0xff，则该数字用作压缩算法。值 MT_ST_CLEAR_DEFAULT 可用于清除压缩默认值。
 - MT_ST_SET_TIMEOUT
	   设置此设备的正常超时（秒）。默认是 900 秒（15 分钟）。超时应该足够长，以覆盖设备在读/写时进行的重试。
 - MT_ST_SET_LONG_TIMEOUT
	   设置用于已知耗时较长操作的长时间超时。默认是 14000 秒（3.9 小时）。对于擦除，此值会再乘以八。
 - MT_ST_SET_CLN
	   使用参数的最低 24 位设置清洁请求解释参数。如果扩展感知数据中发现了清洁请求位模式，驱动可以设置通用状态位 GMT_CLN。许多驱动器在需要清洁时会设置扩展感知数据中的一个或多个位。这些位是设备相关的。驱动被给予感知数据字节的编号（参数的最低八位；必须 >= 18（值 1-17 保留）且 <= 请求的最大感知数据大小）、一个用于选择相关位的掩码（位 9-16），以及位模式（位 17-23）。如果位模式为零，则掩码下的一个或多个位表示清洁请求。如果模式非零，则该模式必须匹配被掩码的感知数据字节。

	   （无论 MT_ST_SET_CLN 如何设置，只要看到附加感知代码和限定符 00h 17h，就会设置清洁位。）

以下 ioctl 使用结构 mtpos：

MTIOCPOS
	从驱动器读取当前位置。对 SCSI-1 驱动器使用与 Tandberg 兼容的 QFA，对 SCSI-2 驱动器使用 SCSI-2 命令。

以下 ioctl 使用结构 mtget 返回状态：

MTIOCGET
	返回一些状态信息。返回文件内的文件号和块号。当无法确定块时（例如 MTBSF 之后），块为 -1。驱动器类型为 MTISSCSI1 或 MTISSCSI2。自上次状态调用以来恢复的错误数存储在字段 mt_erreg 的低字中。当前块大小和密度代码存储在字段 mt_dsreg 中（子字段的位移为 MT_ST_BLKSIZE_SHIFT 和 MT_ST_DENSITY_SHIFT）。
	GMT_xxx 状态位反映驱动器状态。GMT_DR_OPEN 表示驱动中没有磁带。GMT_EOD 表示已记录数据末尾或磁带末尾。GMT_EOT 表示磁带末尾。


## 杂项编译选项


如果定义了 ST_RECOVERED_WRITE_FATAL，恢复出的写错误被视为致命错误。

磁带设备的最大数量由宏定义 ST_MAX_TAPES 决定。如果在驱动初始化时检测到更多磁带，最大值会相应调整。

可以通过定义 ST_NOWAIT 来启用磁带定位 SCSI 命令的立即返回。如果定义了此项，用户应注意不要在上一个操作完成之前启动下一个磁带操作。驱动器和 SCSI 适配器应能妥善处理这种情况，但已知某些驱动器/适配器组合会在此情况下挂起 SCSI 总线。

MTEOM 命令默认实现为跳过 32767 个文件标记。使用此方法时，状态中的文件号是正确的。用户可以通过设置 ST_FAST_EOM 为 1（或使用 MT_ST_OPTIONS ioctl）来请求直接使用到 EOD 的间隔方式。在这种情况下文件号将无效。

当使用预读或缓冲写入时，文件关闭后文件内的位置可能不正确（正确位置可能需要回退多个记录）。如果在编译时定义了 ST_IN_FILE_POS，或使用 ioctl 为该驱动器设置了 MT_ST_CAN_BSR 位，则可以获取文件内的正确位置。（如果用户没有请求那么远的数据，驱动总是会回退读预读跨过的文件标记。）


## 调试提示


调试代码现在默认编译进内核，但调试通过内核模块参数 debug_flag（默认 0）关闭。调试仍可通过 ioctl 打开和关闭。要在模块加载时启用调试，在模块加载选项中添加 debug_flag=1，调试输出并不庞大。也可以通过向 sysfs 文件 /sys/bus/scsi/drivers/st/debug_flag 写入 '0'（禁用）或 '1'（启用）来启用和禁用调试。

如果磁带似乎挂起，我会非常有兴趣了解驱动在哪里等待。使用命令 'ps -l' 可以看到使用磁带的进程的状态。如果状态是 D，则进程正在等待某事物。字段 WCHAN 指明驱动正在哪里等待。如果你有正确的 System.map（在我使用的 procps 中位于 /boot）或更新了 /etc/psdatabase（用于 kmem ps），ps 会在 WCHAN 字段写入函数名。否则，你必须从 System.map 查找该函数。

还要注意，与其他大多数驱动相比，这里的超时非常长。这意味着 Linux 驱动可能看起来卡住了，而真正的原因是磁带固件混乱了。
