
## 53c700 驱动说明


## 一般描述


本驱动支持 53c700 和 53c700-66 芯片。它也支持 53c710，但仅处于 53c700 仿真模式。它是功能完整的，
支持同步（仅 -66 和 710）、断连以及标记命令队列。

由于 53c700 必须连接到一个总线，你需要用一个封装层将该卡的检测器围绕本驱动包装起来。示例请参见
NCR_D700.[ch] 或 lasi700.[ch] 文件。

53c700.[ch] 文件中的注释告诉你为了让驱动工作，需要填写哪些部分。


## 编译时标志


```

	CONFIG_53C700_LE_ON_BE

```
如果在大端架构上必须以小端模式支持该芯片组，则定义此宏（用于 parisc 上的 700）。


## 使用芯片核心驱动


为了将 53c700 芯片核心驱动接入一个可工作的 SCSI 驱动，你需要知道关于该芯片如何接入你的系统（或扩展卡）
的三件事。

1. SCSI 核心的时钟速度
2. 使用的中断线
3. 53c700 寄存器的内存（或 io 空间）位置

可选地，你可能还需要知道其他事情，例如如何从卡 BIOS 读取 SCSI Id，或者芯片是否接成差分工作方式。

通常你可以从通用规格文档中，甚至通过检查在另一个操作系统下工作的驱动的配置，找到第 2 和第 3 项。

时钟速度通常深埋在技术文献中。它是必需的，因为它用于设置芯片的同步和异步分频器。作为一般经验法则，
制造商会将时钟速度设置为在芯片最佳运行前提下尽可能低的设置（尽管有些选择用 CPU 或总线时钟来驱动它，
而不是额外花费一个时钟芯片）。最佳运行的时钟速度是：

=========  =====
53c700     25MHz
53c700-66  50MHz
53c710     40Mhz
=========  =====

## 编写你的封装驱动


这将是一个标准的 SCSI 驱动（我不知道有什么好的文档描述这一点，只需从其他某个驱动复制）至少带一个
detect 和 release 入口。

在 detect 例程中，你需要分配一块 struct NCR_700_Host_Parameters 大小的内存区并将其清零（这样所有
内容的默认值都为 0）。然后你必须填写你关心的参数（见下文），将 NCR_700_intr 例程接入中断线，并以
host 模板和新的参数作为参数调用 NCR_700_detect。你还应该调用相关的 request_*_region 函数，并将寄存器
基址放入 host 参数的 'base' 指针中。

在 release 例程中，你必须释放你分配的 NCR_700_Host_Parameters，调用相应的 release_*_region 并释放中断。

### 处理中断


一般来说，你只需用以下方式接入卡的中断线

request_irq(irq, NCR_700_intr, <irq flags>, <driver name>, host);

其中 host 是相关 NCR_700_detect() 例程的返回值。

你也可以编写自己的中断处理例程，直接调用 NCR_700_intr()。然而，仅当你的卡上有多个芯片，并且你可以读取
一个寄存器来判断哪一组芯片需要该中断时，才真正应该这样做。

### 可设置的 NCR_700_Host_Parameters


以下为用户可设置参数的列表：

clock:（必需）
  设置为芯片的时钟速度，单位为 MHz。

base:（必需）
  设置为寄存器组的 io 或 mem 区域的基址。在 64 位架构上，它只有 32 位宽，因此寄存器必须映射到内存的低 32 位中。

pci_dev:（可选）
  设置为 PCI 板卡设备。对于非 PCI 板卡留为 NULL。它用于 pci_alloc_consistent() 和 pci_map_*() 函数。

dmode_extra:（可选，仅 53c710）
  DMODE 寄存器的额外标志。这些用于控制 710 上的总线输出引脚。设置应为 DMODE_FC1 与 DMODE_FC2 的组合。
  这些引脚实际做什么完全由板卡设计者决定。通常忽略此设置是安全的。

differential:（可选）
  如果芯片驱动差分总线，则设置为 1。

force_le_on_be:（可选，仅当设置了 CONFIG_53C700_LE_ON_BE 时）
  如果芯片在大端架构上以小端模式运行，则设置为 1。

chip710:（可选）
  如果芯片是 53c710，则设置为 1。

burst_disable:（可选，仅 53c710）
  禁用 DMA 传输的 8 字节突发。
