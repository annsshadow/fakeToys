# laiyipao H5 端 实质优化 100 轮（2026-11-17 · 第七批 · 新分支）

> **目标（用户 2026-11-17 指定）**：重新开始 100 轮 H5 优化，**重点是战斗画面**，其它页面兼顾。
> **关键口径变更**：用户明确指出「之前都是小步打磨算一轮」是问题所在 —— **本批每一轮必须有实质性优化**，
> 一个 hover、一个描边、一次字距调整不再算数。

## 一、什么算「实质性」（本批判定标准）

每轮必须满足 **至少一条**，且能用一句话说清「玩家能感知到什么变化」：

1. **新增一个完整的可视系统**：如远景层、弹道拖尾、死亡碎裂、反应专属动画、BOSS 独立血条；
2. **让一个已有但无效的状态真正可见**：如潜地动画、抗性角标、连击计数、波次横幅；
3. **修复一个真实的体验缺陷**：如点了没反馈、看不懂的状态、假入口、信息错误；
4. **一次结构性重构带来可衡量的提升**：如把 N 次 draw call 合成 1 次、把每帧分配烘焙成一次性。

**不算数**：hover/按压/字距/描边/单个颜色微调/只加一句文案/只加一个计数角标（除非它解决了
「看不懂」的真实问题）。
**验证**：每轮必须有单测 / 真域截图 / 构建产物检查之一；战斗画面改动必须保持 perf 预算
（渐变恒 0 / L100 ≤120 / 满载 ≤700）。

## 二、红线

- 玩法文件（game/engine|damage|elements|heatmap|replay|lcg|score|terrain|tuning）零改动；
- 战斗增强只在 `render/canvas.ts`（只读引擎公开字段、只消费事件）；
- perf 预算不得突破；测试锚点只增不删。
- 新分支：`feat/h5-battle-substantive-100`。
