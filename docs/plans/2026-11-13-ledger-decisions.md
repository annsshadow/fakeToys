### 决策 #1 · A301 + A308：三个子项目里「三份默认目录」这一族（同根，合并一条）

**条目原文**（卷二 `OPTIMIZATION_LOOP_2.md`）：

- A308：「『默认注册表目录』在仓内有**三份**，而端点那一份与另外两份不是同一个地方」

**本轮实测**（`augmentor`）：

| 面 | 备份目录 | 注册表目录 |
|---|---|---|
| 端点（省略参数） | `<白名单首根>/.backups` = `augmentor/data/.backups` | `<白名单首根>/.dependency_registry` |
| CLI 默认 | `.backups`（**CWD 相对**） | `.dependency_registry`（CWD 相对） |
| SDK 默认 | `.backups`（CWD 相对） | `.dependency_registry`（CWD 相对） |

**症状实测**：SDK 在 CWD 下建出的备份落 `.backups/backup_20261113_115356.json` ⇒
端点默认目录里**有没有它 = False**；SDK 注册的 1 个数据集 ⇒ 端点
`GET /api/system/dependency/datasets` 回 **0 条** ⇒ **CLI/SDK 建的，页面看不见；反之亦然**。
（文档里已给过绕法：`--registry-path data/.dependency_registry`。）

**四个选项**：

| # | 方案 | 代价 |
|---|---|---|
| ① | **CLI 默认改成 `data/.backups` / `data/.dependency_registry`**（仍相对 CWD）⇒ CLI 与 API 在「项目根目录」这一常态下自动同源；**SDK 库级默认不动** | CLI 默认值变了 ⇒ 不传参的脚本落点从 `<根>/.backups` 变 `<根>/data/.backups`（**旧文件仍在原地**、不会被迁移）⇒ 有人会说「昨天建的备份不见了」 |

| ③ | 维持现状 + 写实（CLI 帮助与文档写明「相对当前工作目录」与那个绕法） | 零行为变更；用户困惑留着，且要**记住**绕法 |
| ④ | 端点**读两处**（`data/.backups` 合并旧 `.backups` 列表），写入仍只写 `data/.backups` | 兼容老落点、不改 CLI 默认；代价是「默认目录」继续有两个 |

### 决策 #2 · A287：质量面那两个恒零的相似度键

**条目原文**（卷二 `OPTIMIZATION_LOOP_2.md`）：
「`augmentor/comparison.py` 的 `similarity_to_a` / `similarity_to_b`（双集对比质量面的两个键）」。

**本轮实测**：

* **源码面**：全仓（不含 import 行）只有**两处**出现 —— dataclass 默认值
  `similarity_to_a: float = 0.0` 与 `to_dict()` 里那两行 ⇒ **没有任何赋值点**；
* **行为面**：两份**完全不同**的数据（4 条 vs 2 条、instruction 一句不重）跑一次，
  回执里两键都是 `0.0` ⇒ 不是「这次恰好是 0」，是**结构上恒零**；
* **消费面**：前端页面**不渲**它们（页面自 L228 起就不渲）、`docs/augmentor/API.md`
  全文**没有**这两个名字 ⇒ **线上消费者 0 个**。

**四个选项**：

| # | 方案 | 代价 |
|---|---|---|
| ① | **接上计算** | 要先拍「`similarity_to_a` 是 B 相对 A 还是 A 相对 B」；且重叠面**已经有**那一个数（`overlap_comparison.metrics.similarity_score`）⇒ 同一个东西两个权威 |
| ② | **从响应面删掉这两键** | 破坏性变更（同时动 SDK dataclass、`to_dict()` 与契约面）；但**线上消费者 0 个** ⇒ 破坏面是「SDK 下游代码会 KeyError」 |
| ③ | 维持现状 + 写实 | 恒零的数仍住在对外契约里 ⇒ 客户端读到 `0.0` 会理解成「A 与 B 毫不相似」 |
| ④ | 只在前端隐藏（现状） | API 面仍是双轨 ⇒ 同上 |

**推荐**：**②**。理由三条：
① 重叠面**已经有**那一个数（匹配键集合的 Jaccard 相似度）⇒ 在质量面再挂两个近义数
就是「一个值两个权威」（账本 A123 / A126 那一族的忌讳）；
② 质量面的职责是质量（分 / 通过率 / 长度 / 词汇量），**相似度不归它管**；
③ 恒零的数**比没有这个数更会骗人** —— `0.0` 会被读成「毫不相似」，真相是「从未被计算」。

**决策**（**代理人 2026-11-13 代用户拍板②**）：

- **谁**：代理人（AI），代账号持有人拍（用户 2026-11-13 交代「遇到决策全部采取你的建议」）；
  **何时**：2026-11-13；**选了哪条**：**② —— 从质量面删掉这两键**。
- **为什么**：见上三条；另有一条**实测**支撑：重叠面那一格**真在算**
  （4 条 vs 2 条、前两条重叠 ⇒ `similarity_score == 0.5`，不是恒 0）⇒
  删掉质量面那两个键**不会**让相似度从产品面上消失。
- **落地**（L329）：`augmentor/comparison.py` 的两个字段与 `to_dict()` 里那两行删掉；

### 决策 #3 · A335：备份回执里那一格 `name`

① ② 是**行为变更**（id 真唯一 ⇒ 同一秒内两只匿名备份不再共享 id），与账本 A298 未做的 ②

（`restore` / `delete` 仍只认 `backup_id`）；
② ③ 的猜法对调用方**不起作用**（见上）；
③ 存量兼容面可量化：**L329 之前写出的索引行没有这一格** ⇒ 读边补 `None`

### 决策 #4 · A370：静态闸判据与 `re` 权威的三处口径差

**条目原文**（卷二）：三处差 —— ① `a{+1}` 那一族；② 两格**已知误伤**；③ 四格**语法错**形状。

**本轮逐格量过**：

| 处 | 量到的现量 | 判决 |
|---|---|---|
| ① `{+n}` | `re` 把 `a{+1}` 读成「字面 `a` + 一个或多个 `{` + 字面 `1` + 字面 `}`」；本闸读同一串时**先把 `{` 当字面量、再把后面的 `+` 照常当量词** ⇒ **两边模型一致、判决也一致** | **不是差** ⇒ 写实 |
| ② 误伤两格 | `(\[[^\]]*\])+` 与 `(?:[^,]+,){3}[^,]+` 在 n=14…22 的必败语料上是 ~0.0003~0.002 ms 的**平坦**曲线；基准 `(a+)+b` 是 0.0007 → 0.0032 → 0.0132 → 0.0531 → 0.2083 秒（每 +2 字 ×4） | **是闸的假阳性** ⇒ 闸加一档「锚点不相交 ⇒ 豁免」 |
| ③ 语法错四格 | 括号不配对 / 字符类未闭合 / 组名没写完 / 结尾裸反斜杠 —— 闸**不下判断**，由 `re.compile` 折成 400 | **两个不同的真原因** ⇒ 写实（两种回执各自诚实） |

**决策**（**代理人 2026-11-13 代用户拍板「误伤是闸的缺陷，不是对外契约」**）：

- **谁**：代理人（AI），代账号持有人拍；**何时**：2026-11-13。
- **为什么**：「误伤算不算对外契约」这一问，在 ② 那一格上**没有争议的余地** ——
  合法模式被无理由拒（400）就是**闸的缺陷**；把一个实测**平坦**的形状判成指数级，
  是在用假警报换安全（而请求级超时与线性引擎那一半仍待拍，见账本 A371）。
- **豁免那一档的方向性**（这是关键）：判据只会让闸**比 `re` 宽**、不会比 `re` 窄 ——
  字符集算不出（`\d` / `\w` / `\s` / `.` / `\x41`）/ 有分支 /
  锚点不是组体**最后一个**单元 / 锚点可选（`?` / `*`）/ 片段来自子组
  ⇒ 一律**不豁免** ⇒ **四格孪生**（`(a*b*)+` / `(a*|b)+` / `([a-z]*a)+` / `(a*.)+`）
  必须**仍然被拦**。
- **落地**（L329）：`augmentor/validation.py` 新立一族字符集计算 + 一族扫描栈帧
  ⇒ `find_repeated_ambiguous_group` 多了一档「锚点不相交 ⇒ 豁免」。
- **守卫**：`tests/unit/test_pattern_disjoint_exempt_l329.py`（新立，含注入臂两支）
  + 旧守卫 `tests/unit/test_pattern_blowup_l278.py` 的真值表按现量重钉
  （危险面 26 → **30**、合法面 20 → **22**、`KNOWN_FALSE_POSITIVES` 改成**反向**的
  `EXEMPTED_BY_DISJOINTNESS` + `MUST_STILL_BE_CAUGHT`）。
- **红→绿已验**：把字符集计算打成「算不出」⇒ 豁免那几格当场红；把不相交判据打成恒真
  ⇒ 四格孪生当场漏过（那一支自己会红）。

### 决策 #5 · oa4rust P1-1：attendance 族的归属事实两列同写

**条目原文**（交接文档 §4）：
「attendance 五张配置表写侧只写 `creator_person`」。

**本轮实测**（L329 收口时按 `INSERT INTO x_attendance*` 的列名清单逐点重数，

`owner_scope(&["creator", "creator_person"], …)` ⇒ **两列都认**
⇒ 写侧不写 `creator` **不造成读写不一致**，但「归属事实只落一半列」仍在。

**两个选项**：① 写侧两列同写；② 维持现状（登记为「已知边界」）。

**推荐**：**①**。理由三条：
① **同族先例** —— `x_message_mass` 早就这么写（P0-2 那一格修的就是「`creator` 从不写入」），
attendance 族是**同一族的漏网**，不是一种设计；
② **不造成行为变更** —— 读侧两列都认 ⇒ 多写一列 = 多一份**事实**，现有判决一句不改；
③ **半列事实的代价** —— 任何只读 `creator` 的新读者都会看到 NULL，
而 NULL 在归属谓词里与「不是属主」同形 ⇒ **静默失效**而不是响亮失败。

**决策**（**代理人 2026-11-13 代用户拍板①**）：

  本轮已改成 `creator` 与 `creator_person` 同写，所以那里从「只写 `creator`」变成「两列同写」，
