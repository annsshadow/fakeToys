### 1. 翻译文件中的 `?` 编码损坏（需对照上游 RST 源文件逐文件校正）

**问题根因**: 中文翻译文件在 RST→MD 转换过程中，部分 GBK 编码的中文字符被错误保存为 UTF-8，导致显示为 ASCII `?`。由于翻译文件是独立翻译成果，不能简单用 GBK 重解码（会破坏已有的正确部分），必须逐文件对照上游 `.rst` 源文件确认每个 `?` 的正确中文标点或词汇。

**受影响语言及文件数**:
- zh_CN: 82 个 `?` — 主要分布在 `admin-guide/bug-hunting.md`、`dev-tools/kmsan.md`、`dev-tools/ubsan.md`
- sp_SP: 68 个 `?` — 主要分布在 `process/` 系列文件
- it_IT: 67 个 `?` — 主要分布在 `kernel-hacking/`、`process/` 系列
- zh_TW: 33 个 `?`
- pt_BR: 7 个 `?`
- ko_KR: 6 个 `?`
- ja_JP: 3 个 `?`

**校正方法**:
```
对于每个受影响的翻译文件：
1. 找到对应的上游 RST 源文件 (kernel.org git tree)
2. 对比翻译文件中的 `?` 位置与 RST 原文的标点位置
3. 确定正确的中文标点（。、，、：、；、《》、「」等）
4. 人工或脚本替换
```

**优先处理**: zh_CN 和 zh_TW 翻译（中文文档质量影响最大）
