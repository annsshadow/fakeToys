G3. 时区/精度三方对照（cal_event 家族）

  写前时刻： local 2026-11-06 00:03:58 / UTC 2026-11-05 16:03:58
  ① core_entity event create -> x_cal_event
     请求 start_time = "2026-11-06T09:00:00"（原样入库）
     库 create_time = 2026-11-05 16:03:58（列类型 timestamp without time zone）
     结论：落库用 Utc::now().naive_utc()，写的是 UTC，但列不带时区标记
     读：/api/calendar/core/entity/event/list/{calendarId} 不返回 create_time
  ② calendar crate event create -> CAL_EVENT
     库 create_time = NULL（INSERT 列清单无 create_time；列类型 text）
     结论：写后必读缺口 —— 字段从未写入，而不是时区问题
  ③ 口径族：
     信息架构查 28 张相关表的 create_time/update_time/start_time/end_time：
       text 列：cal_event, x_applications, x_attendance_detail, x_file, x_jpush,
                x_message, x_mind, x_program_agent
       timestamp without time zone：x_bbs_reply, x_bbs_topic, x_cal_calendar, x_cal_event, x_meeting
  全库 create_time/created_at/update_time/updated_at 列类型分布：
     text 394 · timestamp without time zone 188 · timestamp with time zone 44
  样本值：

     x_bbs_topic.create_time(naive)   = 2026-11-05 16:02:55.24423       （无时区标记，实为 UTC）
     x_attendance_detail.create_time  = ''                              （空串，见 M）

  判定：不存在“读出时把 UTC 当本地”的代码路径（相关 API 均不回显 create_time）；
