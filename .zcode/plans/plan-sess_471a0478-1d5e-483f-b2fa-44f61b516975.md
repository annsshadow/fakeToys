## 目标与边界

在不改变 oa4rust 的既有 API 兼容契约前提下，分批完成 `oa4rust` 与 `oa4rust-web` 的可验证优化。成功标准是：消除已确认的前端路由重复和设计器运行期资源泄漏；让 Rust CI 从仓库根可重复运行、补齐格式/静态检查防回归；每个批次都有针对性验证并形成独立提交。不会把 SeaORM/SQLx 共存、动态 SQL、`ActionResult<T>` 九字段响应、HTTP 200 业务错误语义、生产影子流量切换或全仓库 `any`/`unwrap` 机械替换纳入本轮。

当前工作区只有未跟踪的 `.zcode/` 会话计划文件，不属于产品代码。我会先在**单独的 hygiene 提交**中将 `.zcode/` 写入根 `.gitignore`，不会提交该会话文件。此后每一个新修改批次开始前都检查 `git status`；如出现既有可提交改动，会先按逻辑范围提交，绝不使用 `git add .`。

## 分批实施

### 批次 0：工作区卫生与提交纪律
1. 查看根 `.gitignore` 和 `.zcode/` 内容，确认 `.zcode/` 仅包含会话工件。
2. 仅将 `.zcode/` 忽略规则加入根 `.gitignore`，验证 `git status --ignored`，并提交为独立 hygiene 提交。
3. 后续每个批次都先检查状态、只暂存明确文件、验证通过后创建一个语义化提交。

**验收：**工作区清洁，`.zcode/` 不被跟踪；不会丢弃或纳入未知内容。

### 批次 1：前端重复路由与不可达页面
1. 检查 `QueryStatementDesigner.vue`、`QueryStatementDesignerApp.vue` 的直接路由引用和功能范围。
2. 按你的决定，保留一个 SQL 设计器页面：删除另一个页面对应的重复路由与仅被其使用的死引用；如页面本体没有其它引用，也删除该页面文件。若仍有其他入口或实际独有功能，则保留代码但移除对外重复注册，明确标记为非路由可达前会先以引用证据决定。
3. 整理 `apps/desktop/src/main.ts` 的该局部路由格式，严格不触及其它路由。
4. 新增最小路由表回归测试，断言 `query-statement-designer` 只解析到保留的页面，防止重引入重复路径。

**验证：**`pnpm test`、`pnpm typecheck`、`pnpm build`；构建后检查仅保留设计器的路由 chunk 可访问。

### 批次 2：ProcessDesigner 生命周期优化
1. 阅读 `ProcessDesigner.vue` 中 `onMounted`、`onUnmounted`、动画计时、document 事件监听和直接调用点，确认每个 handler 的配对生命周期。
2. 将匿名 `mousemove` / `mouseup` 等 handler 改为稳定具名引用，确保卸载时移除的是实际注册函数；统一停止 requestAnimationFrame/interval（如存在）。
3. 仅在设计器功能开启时启动边线/粒子动画；路由离开时确保停止。不会在该批进行大型组件拆分、模板 UI 改造或工作流业务逻辑改写。
4. 为抽出的生命周期辅助逻辑或稳定 handler 增加最小测试；若组件测试环境尚未具备，则优先测试纯清理辅助函数，并记录人工路由离开/回访冒烟结论。

**验证：**`pnpm test`、`pnpm typecheck`、`pnpm build`；手工覆盖打开设计器、开启/关闭动画、离开路由、回访、拖拽缩放和保存基本流程，确认无持续动画或重复监听。

### 批次 3：Rust CI 可重复性与质量门禁
1. 修正 `oa4rust/.github/workflows/ci.yml` 中 Cargo 命令的工作目录：所有 Rust 构建、测试和 target 产物访问显式以 `oa4rust` 为工作目录（或等效的 `--manifest-path`），避免 checkout 后在根目录找不到 `Cargo.toml`。
2. 调整脚本的相对路径，使 OpenAPI guard、种子 SQL、Python 聚类脚本和 artifact 上传仍对应 `oa4rust` 子目录。
3. 新增快速质量 job：`cargo fmt --all -- --check`、`cargo check --workspace`，并先以实际 clippy 输出确认是否可以无警告阻断；若存量告警存在，不虚报“`-D warnings` 已启用”，改为非阻断报告或先只针对改动 crate。显式固定/矩阵测试 MSRV 1.75 与当前稳定工具链的策略，将根据现有 lockfile 可用性选择最小实现。
4. 不改变当前行为对比 job 的 `continue-on-error`，也不把外部 Java 环境不稳定性伪装成硬门禁。

**验证：**本地在 `oa4rust` 目录执行 `cargo fmt --all -- --check`、`cargo check --workspace`，以及针对 workflow YAML 的路径/命令静态审查；如本地数据库不可用，明确报告 integration/behavior 未运行的原因，CI 仍保留 PostgreSQL/MySQL 矩阵作为最终环境验证。

## 明确延后项

- 高基数组织、消息、文件查询的分页需要逐端点确认 Java 行为、调用方与 PostgreSQL/MySQL 执行计划，风险较高，先不在同一轮混入。
- `ProgramCenterApp`/`PortalDesigner` 的按标签查询延迟加载有收益但涉及大量 API key 与 mutation 失效语义，需要单独审查后再以逐标签小批次执行。
- 生成测试拆分、realtime 锁重构、DB 测试分层、共享状态中的 `unwrap` 收敛均按独立设计/验证任务推进，避免“全面优化”变成不可审查的大提交。
- 生产影子流量、灰度和两周观测是替代上线验证，不属于本地代码优化，必须另获明确生产授权。
