目标：补齐并强化 GitHub Actions 门禁，覆盖现有三个主要子项目，同时修复已确认的脆弱门禁与 CD 脚本注入风险。保持现有工作流职责和路径触发习惯，不改动用户已有的审计 JSON 与 laiyipao 源码改动。

拟修改：
1. `oa4rust-ci.yml`：将两个旧 upload-artifact pin 统一到仓库已使用的 SHA；修正行为对比基线注释路径；让行为对比报告解析失败明确失败而非放行；保留外部 Java 服务不稳定时的非阻断定位，但确保实际报告一旦生成且 FAIL 超基线仍由独立 gate 阻断，并避免未生成报告被误当成通过（除非 job 明确跳过）。
2. `oa4rust-web.yml`：明确监听 `oa4rust` workspace 根级清单、锁文件、Biome/TS 配置和共享脚本变更，确保共享配置变更能触发桌面前端检查；增加移动端微信小程序生产构建，沿用独立 job 或同一 job 顺序执行并保持现有 H5 检查。
3. 新增 `laiyipao-ci.yml`：路径过滤覆盖 `laiyipao/**` 和该 workflow；服务端执行 gofmt 检查、`go vet`、`cmd/vectors -check`、Go 全量测试（PostgreSQL service，按运维文档采用 1200 秒超时并检查输出中无 SKIP）；管理后台和 miniapp 分别执行 frozen-lockfile 安装、单测、类型检查与生产构建，后台再执行 `size:check`。对可能耗时较长的 Go 测试配置足够 job 超时并与轻量检查分开。
4. `ai-platform-ci.yml`：将 Web 构建步骤改用已有 `build:check` 脚本，纳入 dist 校验。
5. `ai-platform-cd.yml`：避免将 `workflow_dispatch` 输入直接插入 shell 源码；将输入通过 `env` 传递并校验 tag 字符集。审查并改为安全传递 SSH 部署参数，避免 secrets 或路径经插值拼接形成远程 shell 命令注入；保留原有发布、部署触发与最小权限。

验证：静态检查 YAML 结构和 action SHA/权限/触发路径；对新增或改动的命令与现有 package scripts、Go 运维文档逐项对照；运行可本地执行的 YAML/脚本检查和受影响的轻量门禁。完整 PostgreSQL Go 集成测试及需 GitHub/容器发布凭据的 CD 实际执行若环境不具备，将明确标为未执行，不把静态验证描述为运行通过。
