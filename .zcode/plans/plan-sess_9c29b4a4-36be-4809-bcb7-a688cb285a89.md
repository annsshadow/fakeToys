## 工作项

### W1 后端认证语义对齐 U12（矩阵 #4/#5 + telemetry）
`oa4rust/crates/auth/src/lib.rs`
- **refresh 改 Cookie-only（矩阵 #5）**：把 `refresh` 的认证来源限定为 `Authentication::Cookie`；仅 Bearer/空凭据 → 401；Cookie+Bearer 同时存在仍按 Cookie（`extract_authentication` 已如此）。空 body、旋转旧会话、`Set-Cookie`+`no-store`、body 无 token 保持不变。
  - 已知取舍：CLI/service 若调用 `/refresh` 且只带 Bearer 将收到 401——按计划“浏览器 refresh 不得依赖 Bearer”，CLI 独立刷新契约留待后续，记录为 trade-off。
- **whoami 凭据语义（矩阵 #4，按决策=401）**：无凭据 → 匿名 200（Java 兼容，前端探测/首访）；凭据存在但无效（空/过期/篡改 Cookie，或无效 Bearer）→ 401，且无效 Cookie 绝不再回退 Bearer。前端 `restoreCurrentUser()` 已把 401 映射为 `user=null`，无需前端协议改动。
- **Bearer 兼容 telemetry**：在 shared `auth_middleware` 的请求边界，当最终选用 `Bearer` 时发一条结构化日志（`tracing::warn!`，字段 `auth_compat="bearer"`、`method`、`path`，严禁记录 token/cookie/UA 全值）。这是“兼容流量可观测”的最小落点；退出阈值=观察窗口内该事件计数归零，写入文档而非硬编码数字。

测试（`crates/auth/src/tests.rs`、`crates/shared/src/tests.rs`）
- refresh：Cookie 旋转成功 + 旧会话失效（已有）；**新增** Bearer-only refresh → 401；Cookie+Bearer → 用 Cookie。
- whoami：无凭据 → 匿名 200；**新增** 无效 Cookie → 401；无效 Cookie + 有效 Bearer → 401（不回退）。
- 矩阵补强：CSRF 四方法(POST/PUT/PATCH/DELETE)×缺失/null/错误 Origin→403、精确 Origin→200、Bearer-only 豁免；CORS preflight 覆盖 PUT/PATCH/DELETE 且 GET/HEAD 不误拦；logout 对有效/过期会话幂等并清 Cookie；无效 Cookie 永不回退。
