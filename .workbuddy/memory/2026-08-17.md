## 更新3：packed-refs 的 UTF-8 BOM 导致 git 拒读

## 续：agent 侧 git 彻底不可达的根因坐实（17:24 后诊断）
- **现象**：用户授权 agent 直接在 PowerShell 跑 git 后，git 从"可用"退化为 `fatal: not a git repository`（walk-up 与显式 `--git-dir` 均报）。`Get-Content` 能读到真实 `HEAD`/`packed-refs`（真实 SHA），但原生 `git.exe` 拒不认仓库。
- **追因 1（hung 进程）**：`Get-CimInstance` 发现 PID 29412(`git stash push -u`, PPID 29164 一 PowerShell) + 子 37784 仍存活——即上一轮 `git_sync_tmp.ps1` 卡在损坏索引条目（missing blob `7def9d93…` for `.workbuddy/memory/2026-08-16.md`）的遗留 hung 进程，持续占用 `.git` 致状态飘忽。`taskkill /PID 29412 /F /T` 已杀掉（含子 37784）。但杀掉后 git 仍报 not a repo → 非主因。
- **追因 2（空心 overlay，真根因）**：原生 `.NET`/`git.exe` 视图下 `.git/refs` 目录**缺失**（PowerShell 托管视图因缓存看似有），补建 `refs/heads`+`refs/remotes` 后 git 才结构识别仓库，但 `git fsck` 报**所有 ref 的 SHA1 指针 invalid、HEAD bad object**——即沙箱 `.git` 是**空心 overlay**：目录骨架（refs / objects/* 子目录 / packed-refs 真实 SHA）齐全，但**对象库零实际数据**。故 agent 在沙箱内跑任何 git（fetch/pull/push/rebase/stash）都不可能成功；唯有真机 `.git` 才有真实对象。
- **交付（替代直接执行）**：写出 `D:\WORKSPACE\fakeToys\recover_repo_sync.ps1`（仓库根，UTF-8 BOM，PARSE_OK）供用户在**真机**一键运行。流程：校验仓库 → 修复损坏索引条目（`git ls-files -s` 找 missing blob → `git add` 从工作树重建；失败则 `git update-index --force-remove`）→ fetch 重试(4 次) → 算 ahead/behind → 分叉则 `stash push -u`→`rebase origin/<branch>`→`push`→`stash pop`（冲突暂停不 abort）；无 `reset --hard`、无盲目 `add -A`。直接修复真机上那个 `7def9d93` 缺失 blob（agent 沙箱写的 index 引用了未落盘对象）。
- **结论重申**：agent 直接在沙箱修 git 不可行（空心 overlay，对象库空）；凡 `.git` 写操作须用户在**真机独立 PowerShell** 执行（agent 落脚本供其运行）。本轮用 `fsck` 把"沙箱 `.git` 不可用"从推测坐实为"对象库全空"。
