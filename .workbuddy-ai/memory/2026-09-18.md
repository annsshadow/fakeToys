|---|---|
| `gh auth status` | ❌ "You are not logged into any GitHub hosts" |
| `gh auth token` | ✅ 返回有效 token `gho_...` |

**有效绕过方式**（已实测成功）：

```bash

gh auth status          # 此时显示 ✓ Logged in as annsshadow (GH_TOKEN)
gh pr create --base main --head <branch> --title "..." --body-file <file>
```

token 权限含 `repo`、`workflow`、`gist`、`read:org`，足够建 PR。

**推送走 SSH 不受影响**：remote 为 `git@github.com:...`，已验证 `ssh -T git@github.com` 返回 `Hi annsshadow!`。

## ⚠️ 事故与修复记录（同日）— 重要教训

### 事故经过

删除污染文件 `ai/docs/FINAL_SUMMARY.md` 时发生连锁问题：

1. `git rm` 命令执行中被系统 SIGTERM 超时中断，导致误删 `ai/` 下 **288 个文件**（而非 1 个）。
   - 修复：`git checkout -- ai/` 全部恢复，无数据损失。
2. 期间**有外部进程（IDE git 集成）并发操作 git**，导致：
   - `.git/index.lock` 残留
   - 提交 `07def09f` 变为**游离提交**（不挂在任何分支）
   - 分支 `feat/oa4rust-mobile` 被回退到 **379 个提交之前**的 `5456bcc5`
   - 暂存区被塞入 32,751 个条目

### 关键根因：ref 存储位置

`refs/heads/` 目录**完全为空**——所有分支都打包在 `.git/packed-refs` 中。

因此修复时 `git update-ref` 写入的 loose ref 会被立即删除（或未生效），必须**同时改 packed-refs**：

- loose ref 路径：`.git/refs/heads/feat/oa4rust-mobile`（**需先 `mkdir -p` 父目录**，且必须写入**完整 40 位 SHA**，短 SHA 会导致 `rev-parse HEAD` 报 ambiguous）
- packed-refs 需同步 sed 替换

### 有效修复步骤（复用价值高）

```bash
git read-tree HEAD                              # 索引重置到 HEAD（不动工作区）
mkdir -p .git/refs/heads/feat
printf '%s\n' "$(git rev-parse <目标SHA>)" > .git/refs/heads/feat/oa4rust-mobile
sed -i 's|^<旧SHA> refs/heads/feat/oa4rust-mobile$|<新SHA> refs/heads/feat/oa4rust-mobile|' .git/packed-refs
```

CAS 安全写入（推荐，防并发）：`git update-ref <ref> <新值> <期望旧值>`

### 最终状态

- 分支恢复至 `07def09f`（领先 main **384 提交**，ahead origin 1）
- 污染文件已删除，全库 null 字节扫描**清零**
- 暂存区 0 条目

### 遗留说明

`git diff` 显示 198 个文件"已修改"，经 `git diff --ignore-cr-at-eol` 验证**内容差异为 0**，纯 CRLF/LF 行尾符差异（Windows `core.autocrlf=true` 正常行为）。**不要误当数据损坏处理**。

### 教训

1. **命令被 SIGTERM 中断后，必须复核实际影响范围**，不能凭命令意图判断结果。
2. **本仓库存在外部进程并发操作 git**，执行写操作前应确认，且优先用 CAS（`update-ref` 带旧值）。
3. **大仓库中避免 `git rm` / `git status` 全量操作**——易超时且输出巨大。
4. 删除文件用 `rm -f <单文件>` + `git status --short` 核对数量，比 `git rm` 更安全。

### ⚠️ 外部进程干扰再次发生（重要）

提交 `519f42d8` 后，**HEAD 又被回退到 `07def09f`**，提交变游离。与首次事故完全相同。

**根因确认**：该外部进程会删除 `.git/refs/` 下的 loose ref 文件，使 git 回落到 `.git/packed-refs` 中的旧值。

**通用修复法（已验证 2 次有效）**：

```bash
# 1. 写 loose ref（须先建父目录 + 写完整 40 位 SHA）
mkdir -p .git/refs/heads/feat
printf '%s\n' "$(git rev-parse <新SHA>)" > .git/refs/heads/feat/oa4rust-mobile

# 2. 同步 packed-refs（否则 loose ref 被删后立刻回退）
sed -i 's|^<旧SHA> refs/heads/feat/oa4rust-mobile$|<新SHA> refs/heads/feat/oa4rust-mobile|' .git/packed-refs

# 3. remote-tracking ref 同理
mkdir -p .git/refs/remotes/origin/feat
printf '%s\n' "<新SHA>" > .git/refs/remotes/origin/feat/oa4rust-mobile
sed -i 's|^<旧SHA> refs/remotes/origin/feat/oa4rust-mobile$|<新SHA> ...|' .git/packed-refs
```

**结论**：本仓库**任何 git 写操作后都必须复查 `git rev-parse HEAD`**，因为写入可能被静默回退。已在 `AGENTS.md`/`MEMORY.md` 层面提醒用户关闭 IDE 的 git 自动操作。
