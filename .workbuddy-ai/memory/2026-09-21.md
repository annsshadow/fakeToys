## 本机构建环境坑（重要，可复用）

1. **pnpm 版本被 pin 但二进制缺失**
   仓库 `oa4rust-web/package.json` 有 `packageManager: pnpm@11.25.0`，全局装的是 12.3.2，
   直接跑 pnpm 会报 `ERR_PNPM_ENGINE_BIN_MISSING: switch pnpm to v11.25.0`（`--config.manage-package-manager-versions=false` 无效）。
   解法：加环境变量前缀 → `npm_config_manage_package_manager_versions=false pnpm <cmd>`。

2. **Git Bash 的 `link.exe` 遮蔽 MSVC 链接器**
   `/usr/bin/link.exe`（coreutils link）排在 PATH 前面，Rust 链接会报
   `link: missing operand after '\377\376'`。
   解法：把 MSVC bin 前置并补齐 LIB/INCLUDE（本机版本 MSVC 14.44.35207 / SDK 10.0.26100.0）：
   ```bash
   export PATH="/c/Program Files/Microsoft Visual Studio/2022/Community/VC/Tools/MSVC/14.44.35207/bin/Hostx64/x64:$PATH"
   export LIB='C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.44.35207\lib\x64;C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\ucrt\x64;C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\um\x64'
   export INCLUDE='C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.44.35207\include;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\ucrt;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\shared'
   ```
   仅设 `CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_LINKER` 不够——会继续缺 `kernel32.lib`（LNK1181）。

3. **vite build 清 dist 触发 safe-delete 垫片超时**
   `Error: [safe-delete] 操作失败: spawnSync genie-trash ETIMEDOUT`（vite 的 `prepareOutDir` → `fs.rmSync`）。
   解法：构建前先手工 `rm -rf oa4rust-web/dist`（outDir 是 `oa4rust-web/dist/web`，未纳入版本控制）。

4. **PowerShell 工具限制**：禁止 `cmd.exe`，且 `& 'C:\...\cargo.exe'` 会报 "无法在管道中间运行文档"。Rust 构建走 Bash 通道更顺。

5. **后端 `cargo build` 被沙箱拦截，无法在本环境完成**（已确认根因，未解决）
   现象：反复在写 `oa4rust/target/debug/deps/*.d`、`.fingerprint/*.json`、拷贝 `incremental/*.rmeta`、
   删除 `.tmp*.temp-archive` 时报 `拒绝访问 (os error 5)`，每次失败的 crate 不同
   （pin-project-lite / itoa / percent-encoding / socket2 / fnv / time-macros …）。
   **根因**：沙箱拦截 rustc 的临时文件读写/删除，显式日志为
   `[sandbox] 命令被沙箱拦截：... (读/删 · 拒绝)`，并伴随
   `failed to remove temporary directory: 拒绝访问` —— 与 vite 清 dist 的 safe-delete 超时同源。
   已排除：磁盘空间（D: 余 148G）、残留进程、路径 ACL（Node 写同一 `.d` 文件成功）。
   尝试过且**均失败**（并行 `cargo build`）：显式指定 MSVC linker、补齐 LIB/INCLUDE、`--target-dir target-verify` 全新目录、
   `CARGO_INCREMENTAL=0`、多轮循环重试（每轮都能多编译一些，但始终收敛不了）。
   **关键突破（已验证有效）**：并行模式 30 秒内必挂，改用 **`cargo build -j 1`（单线程）后一次通过**：
   ```
   Finished `dev` profile [unoptimized + debuginfo] target(s) in 25m 10s   # rc=0
   产物：oa4rust/target/debug/oa4rust.exe（142MB, 17:39）
   ```
   说明根因是**并发写盘竞争**（多个 rustc 同时写 `deps/*.d` 触发拒绝），单线程可完全规避。
   注意：该次成功运行**未**申请非沙箱，即 `-j 1` 在沙箱内即可跑通。代价是慢（全量约 25 分钟）。
   `oa4rust/target` 已达 145G。
