## 可复用诊断配方：公益站适配器"静默假成功"

站点端点迁移时 SPA 兜底会以 200 返回 HTML，表现为"200 但状态纹丝不动"。排查步骤：

1. **扒前端 bundle 找真实端点**（无需登录，最快）：
   `fetch('https://<site>/')` → 正则取 `/assets/*.js` → 在 bundle 里 `indexOf('daily-reward')` 或正则匹配 `"..."` 字面量，直接看到 `ue("/user/xxx")` 这类调用。
2. **看请求封装**：搜 `async function ue(` 看默认头、是否带 `Authorization: Bearer`、是否 `credentials: "include"`；搜 token 来源（localStorage 键 / cookie 名）。
3. **真实会话探测**：`chromium.launchPersistentContext('sessions/<site>')` 复用登录态，`page.evaluate(fetch(...))` 对比新旧路径的 `content-type`（`text/html` = SPA 兜底，`application/json` = 真接口）。
4. **集成验证领取分支**（当日已领时无法自然走到）：用 `ctx.route()` 伪造 `GET` 状态端点返回 `canClaim:true`，并让 `claim` POST 后翻成 `false`。
   - 两个坑：适配器内部自己 `newPage()`，**路由/监听必须挂 `context` 而非 `page`**；站点有 **Service Worker 会绕过 route 拦截**，需 `serviceWorkers: "block"`。
5. 验证后删除临时脚本（仓库历史曾清理过 `diag.bat`，不留在库）。
