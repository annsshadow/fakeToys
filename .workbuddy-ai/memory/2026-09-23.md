### Task 7 详情（缓存）

- `vector/faiss.py` 的 `_query_cache` 有 **3 个缺陷**：①缓存键只有查询向量、不含
  `top_k` → `search(q, top_k=5)` 后 `search(q, top_k=10)` 返回被截断的 5 条；
  ②`add_vectors`/`delete`/`clear`/`load` 后不失效缓存 → 新向量永远查不出来；
  ③无容量上限。
- **技术债清理决策**：不再手写第 3、4 份有界缓存，改为统一复用
  `cache.MemoryCache`（`models/base.py` 的 `_generation_cache` 与 `faiss._query_cache`）。
  为支持自然的边界断言给 `MemoryCache` 加了 `__len__` / `__contains__`。
- 顺手修掉 4 个既有缺陷：
  - `CachedProcessor.__init__` 写的是 `cache or MemoryCache()`；`__len__` 一加上，
    **空缓存变 falsy 被静默丢弃**，`wrapper.clear_cache()` 清的不是同一个对象。
    改 `is not None`。
  - `MemoryCache._evict` 的 `sorted_keys[:len//2]` 在只剩 1 条时是空切片，
    **一条都删不掉** → `max_size=1` 时缓存退化成无界 dict。改 `max(1, len//2)`。
  - `MemoryCache(max_size<=0)` 同样退化成无界；`_max_size = max(1, ...)` 兜底。
  - `DiskCache` 只有 TTL 没有容量上限（**接进长跑路径就是把内存泄漏换成磁盘泄漏**），

### 方法论要点（可复用）

1. **反事实验证是性能/正确性测试的必需步骤**：逐个把缺陷注入回生产代码，确认对应
   测试真的失败（本次 7 个缺陷全部被捕获）。否则可能写出"空转测试"。
2. **`inspect.getsource` 字符串断言 = 假测试**：本次又清理 3 处（`test_chunked_matrix.py`
   的 `"chunk" in source`、`test_stream_memory_opt.py`、`test_quality_score_opt.py`）。
   改为行为测试（monkeypatch 间谍 / tracemalloc 峰值 / 与朴素参照实现比对）。
3. **边界断言不要引用被测对象自身的常量**：`assert len(cache) <= db._QUERY_CACHE_MAX`
   在把上限调大时空转通过。改为 monkeypatch 固定小上限 + 写死字面量断言。
4. **同一文件不得并行 Edit**：两次 Edit 都报成功但后写覆盖先写（本次会话踩过两次，
   导致 `NameError` 与 `ImportError`）。必须串行。
5. **shell 会吞掉 heredoc/`-c` 里的 `\n` 转义**（MSYS 路径转换把 `:\n` 变成 `:/n`）。
   需要多行锚点的脚本要写成独立 `.py` 文件，或改用 `"\n".join([...])`。
6. **CRLF 不是污染**：本仓库 `core.autocrlf=true`，工作副本混有 CRLF/LF 属正常；
   `git diff` 会自动归一化，`git status` 只显示真实内容变更。用 `grep -c $'\r'`
   判断行尾在 Git Bash 里**不可靠**（`$'\r'` 可能被当成空模式，退化成统计总行数）。
7. **triage 启发式漏判**：`scripts/triage_tests.py` 的污点规则只认 `ast.Name` 实参，
   漏了 `sleeper=slept.append` 这种"传出绑定方法"的写法，把有效断言误报为空洞。
   已扩展为同时认 `ast.Attribute`（基名是 `Name`）。改动后用 8 个合成用例验证判别
   准确性（4 个真空洞仍被捕获，4 个有效断言不再误报）。

### Task 13 详情（DiskCache 接入模型响应缓存，opt-in）

全量 **3217 passed / 3 skipped / 覆盖率 98.32%**（3 个 skip 是环境缺 pandas，既有）。

- **设计：opt-in，默认不落盘**。`ModelBackend.__init__` 新增
  `response_cache_dir=None` / `response_cache_ttl=None` / `response_cache_max_bytes=None`，
  `None` 即完全不构造 `DiskCache`。理由：开启意味着把 prompt 与模型响应**静默写进磁盘**，
  既是磁盘占用也是隐私语义变化，必须是显式选择。5 个后端（claude/ernie/gemini/ollama/

  刻意**没有**加 `AUGMENTOR_MODEL_CACHE_DIR` 环境变量、也没往 `AppConfig` 里加字段——
  那会牵连 `config.yaml` / API 请求体 / 文档一串改动，收益不匹配。
- **缓存键的三个硬约束**（`_cache_key`，内存与磁盘共用）：
  1. **覆盖所有影响输出的输入**：`provider / model / temperature / top_p /
     max_output_tokens / prompt` 用 `\x00` 拼接后取 `sha256`。只用 prompt 做键的话，
     同一实例改了 model 或 temperature 会静默命中旧配置的响应。
  2. **跨进程稳定**：内置 `hash()` 对 str 带 `PYTHONHASHSEED` 随机盐，拿它当磁盘键
     会让缓存**永远无法跨进程命中**（表现为"缓存文件越来越多但命中率恒为 0"）。
     这就是原来 `prompt_hash = hash(prompt)` 不能直接复用到磁盘的原因。
     用两个不同 `PYTHONHASHSEED` 的子进程各算一次键来验证。
  3. 用 `hashlib.sha256`（不是 `hash()`）保证 1、2。
- **降级而非报错**：`_build_response_cache` 把 `DiskCache(...)` 包在 `try/except OSError`
  里——`DiskCache.__init__` 会 `mkdir(parents=True)`，目录不可写/被占用时会抛。
  缓存只是优化手段，不该因为它建不起来就让整个模型后端不可用。降级为 None + warning。
- **写入失败不影响已成功的生成**：`generate()` 写回磁盘时 `try/except OSError`。

  7 项缺陷注入全部被捕获。
- **顺手修掉一个假测试**：原 `test_cache_is_bounded_by_eviction` 用 `hash("提示0")`

### 重要修正：Task 9 的守门测试曾是「空转测试」

Task 9 结束时我报的是"3215 passed"，但**那个数字是在守门测试失效的状态下取得的**。
本次全量跑出 7 个失败才暴露出来，根因两层，都值得记住：

1. **`app.routes` 遍历不到 `include_router` 的结果**。FastAPI 0.141.1 把
   `include_router()` 的结果包成 `fastapi.routing._IncludedRouter` 塞进 `app.routes`；
   这些包装对象**自身没有** `path` / `methods` / `response_model`（真正的 `APIRoute`
   藏在它内部，属性名也不是 `.routes`）。于是 `_modelled_routes()` 只找到 `/api/health`
   一个，其余 7 个端点的 `models.get(route_key)` 返回 None → 断言失败。
2. 更早的版本用 `set(payload) == _field_names(model)` 比对，即使遍历正常也**测不出
   "静默裁剪"**：FastAPI 按 `response_model` 过滤响应，所以模型漏声明字段时
   **响应和字段集一起变小**，两边永远相等，断言恒真。这是与「同源预言机」的经典错误。

**修正后的设计**（`tests/integration/test_api_openapi_contract.py` 重写，22 个用例）：

- **预言机换成领域契约**：`CALLS` 里为每个端点写死它**必须返回的键集合**，来源是
  handler 实际返回的领域对象（各报告 dataclass 的 `to_dict()` 键、或显式字典字面量），
  **独立于 `response_model`**。这样模型漏声明字段时契约不变、响应变小 → 立刻失败。
- **探测机制改用公开接口**：用 `app.openapi()` 的 200 响应 schema 是否为 `$ref` 判断
  「是否声明了 response_model」（未声明时 FastAPI 生成空 schema `{}`）。
  不再依赖 FastAPI 私有类名与私有属性。
- **递归校验嵌套子对象**：`SanitizeResponse.report` 里的 `total_matches` 是嵌套计算属性，
  顶层键一个不少，只有递归下去才看得见。
- **给守门测试加「非空转」元断言**：`assert len(modelled) >= len(CALLS)`，探测机制一失效
  就立刻失败，而不是静默通过。**教训：任何「枚举 → 差集断言」形态的守门测试，
  都必须先断言枚举结果非空/足量，否则探测失效时它只会安静地什么都不守。**
- 6 项缺陷注入全部被捕获，其中最关键的一项：把 `response_model=LeakageResponse`
  换成 `response_model=LeakageReport`（dataclass 直接当模型）——旧设计漏检，新设计抓住。
