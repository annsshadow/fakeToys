# 来一炮 · 玩法设计

> 版本 v1.0 · 2026-09-26 · 本文件是实现的单一事实源
> 定位：玩法机制与《向僵尸开炮》同构（关卡闯关 / 守防线 / 局内技能三选一 / 场外养成），
> **表达与系统全原创**，并在其之上做 6 项机制级创新以形成自有辨识度。

---

## 0. 设计红线

原作被玩家和媒体反复诟病的 4 个问题，直接决定我们的创新方向：

| 原作问题 | 后果 | 我们的对策 |
|---|---|---|
| 后期全靠堆数值（技能等级/宝石词条/装备等级都在加伤害） | 挑战性崩塌，"氪佬与平民差距"退化成纯资源量 | 创新 I-1 元素反应矩阵 + I-3 专精树，**反应伤害与攻击力解耦** |
| 局内选完技能就不用操作，关卡退化为波数推进 | 操作无意义，通关=时间问题 | 创新 I-2 插槽热量（构筑有代价）+ I-4 地形机制关（关卡是谜题） |
| 技能"三选一"是无脑增益，配方只是解锁更纯的数值 | 没有构筑决策 | I-2 热量/弃牌 + I-3 专精点有限，**必须做取舍** |
| 离线收益是纯挂机产出，社交只有排行榜 | 挂机无意义，社交浅 | 创新 I-5 防线值守（异步对抗）+ I-6 回放哈希验真（公开可验证） |

**三条不可退让的红线**
1. **不许出现"唯一最优解"** —— 每个机制都必须至少留 2 条可行路线。
2. **养成线之间必须互相咬合**，不允许 4 条线各自独立加伤害（金币/钻石也必须各有用处）。
3. **战斗必须确定性可复现**（见 I-6），这是反作弊与公平性的技术地基。

---

## 1. 核心循环

```
选关 → 布阵（4 主动槽 + 1 被动槽 + 3 工事）
     → 战斗：自动索敌开火，玩家可拖拽微调弹道与提前量
     → 波次间：抽 3 张手牌（技能/属性/机制）→ 有代价地选
     → 胜利：结算星级 + 资源 + 掉落 → 养成（专精/装备/宝石/皮肤）
     → 循环；或失败 → 诊断提示 → 复盘 → 重试 / 一次复活
```

单局目标：**在防线血量归零前清完所有波次（含 BOSS）**。防线血量不随关卡回复。

## 2. 创新点（核心）

### I-1 元素反应矩阵 —— 破数值通胀

**问题**：原作所有养成都加攻击力，于是后期"堆数值"就是唯一解。
**做法**：把伤害拆成三段，其中**反应伤害段与攻击力解耦**。

```
单次命中伤害 = 直接伤害(权重 0.40，吃养成攻击力)
             + 元素层数伤害(权重 0.20，吃元素层数/元素词条)
             + 反应伤害(权重 0.40，吃搭配与时序)
```

**反通胀的真正保证不是权重，而是"反应伤害里攻击力的占比"**：

```
反应伤害内部拆分：
    70%  ← 元素层数 × 反应倍率 × 反应等级   （与养成无关，弱玩家可拉满）
    30%  ← 玩家攻击力                       （与养成相关，强玩家更快）
```

> 硬性红线：`反应伤害中的攻击力权重 ≤ 30%`。
> 这意味着堆金币/等级**永远无法替代正确的元素搭配**，
> 而正确搭配 + 低养成 ≈ 错误搭配 + 高养成。养成线之间因此无法互相替代。

**5 种元素**：焰 Fire / 冰 Ice / 电 Lightning / 毒 Corrosion / 动能 Kinetic

**7 条反应链**（施加 A 后命中带 B 的目标即触发）：

| 反应 | 触发 | 效果 |
|---|---|---|
| 蒸汽爆发 | 焰 + 冰 | 范围伤害，**驱散护盾** |
| 过热 | 焰 + 电 | 爆炸 + 眩晕 1.5s |
| 燃烧云 | 焰 + 毒 | 生成持续 6s 火区，元素值可续燃 |
| 超导 | 冰 + 电 | 目标受击伤害 +60%，持续 4s |
| 急速冻结 | 冰 + 毒 | 冻结 2s，受击伤害 +30% |
| 腐蚀扩散 | 电 + 毒 | 把目标的元素层数按 50% 传播给半径内同族目标 |
| 破甲击退 | 动能 + 任意 | 击退 + 削穿护甲，为其他伤害开窗口 |

**敌人 5 维抗性**：每种敌人有 `fire/ice/lightning/corrosion/kinetic` 五个抗性值，范围 −50%（吃双倍）~ +50%（几乎免疫）。**每个 BOSS 至少对 1 种元素高抗、同时对另 1 种负抗** → 强制换搭配，"以弱胜强"始终有解。

**平衡红线（写进自动化测试）**：
1. **反通胀**：反应伤害中的攻击力权重 ≤ 30%（见上）。
2. **以弱胜强可行**：低养成阵容 + 正确反应搭配，**必须能**打过高养成阵容 + 无反应搭配（同关卡）。
3. **无唯一最优解**：任一关卡，穷举"元素组合 × 专精方向"，通过率最高与次高的搭配差距 ≤ 15%。
4. **BOSS 可解**：每个 BOSS 的高抗元素，其负抗元素所对应的反应链，伤害必须足以在合理养成下破防。

### I-2 插槽与热量 —— 让三选一变成风险管理

**问题**：原作局内三选一是纯增益，无脑拿。
**做法**：给选择装上代价。

- 玩家有 **4 个主动插槽 + 1 个被动插槽**。主动槽只能放主动技能，被动槽只能放被动。
- 每个波次间隙抽 **3 张手牌**：1 张技能 / 1 张属性卡 / 1 张机制卡。
- **弃牌**：每波可免费弃 1 张，弃牌回 +1 热量（热量是资源，不是惩罚）。
- **热量**：释放技能消耗热量，上限 **100**，超限进入 **过热**（2s 内无法释放）。
  - 但**过热期间元素层数不清除** → 高热量爆发流是可行策略，而非纯惩罚。
- 抽到重复技能可**就地升格**（同一技能 3 选 1 变成 1/2/3 阶），高阶 = 更高热量但更强反应倍率。

**设计后果**：玩家每波都在回答"我要 build 什么、留多少热量、要不要弃牌保空间"。

---

### I-3 专精树 + 装备契合度 —— 让养成线互相咬合

**问题**：原作技能/装备/宝石/皮肤 4 条线各自加伤害，资源可以随便堆。
**做法**：

**8 系专精树**（焰/冰/电/物/光/毒/无人机/工程），每系 12 节点（3 层 × 4 节点）：
- 节点类型：元素层数上限 / 反应倍率 / 热量上限 / 额外插槽 / 机制改造
- **专精点有限**：初始 3 点，每 10 级 +1，且同系树内**每层只能选 2 个**（4 选 2）
- 结果：不可能点满，必须选方向

**装备契合度**（关键咬合设计）：
- 每件装备带一个 `element` 标签
- 装备标签与**已装备的技能同系** → 反应伤害 +X%（X 大）
- 不同系 → 直接伤害 +Y%（**Y < X/3**）
- → 玩家必须"技能 + 装备 + 专精"成套搭配，不能乱穿

**货币分流**（解决"金币钻石都能升一切"）：
| 货币 | 唯一用途 |
|---|---|
| 金币 | 技能/装备的基础升级（便宜、量大、线性） |
| 钻石 | 专精点重置、洗练、皮肤（稀缺、不可逆决策） |
| 体力 | 进入关卡（软墙，只卡"刷"不卡"玩"） |
| 钥匙 | 资源副本 / 每周 BOSS 门票 |

---

### I-4 地形机制关 —— 让关卡是谜题而非波数

5 类可交互地形（约 25/100 关使用，每章至少 3 关）：

| 地形 | 机制 |
|---|---|
| 油桶 | 受到**焰**元素命中即引燃 → 爆炸 + 生成 8s 火区 |
| 潮汐闸 | 周期升降：低层通路开合，改变敌人路径与弹道受阻 |
| 旋转风障 | 持续改变区域内弹丸飞行方向（角速度固定） |
| 崩塌掩体 | 受到**动能**伤害累计到阈值即崩塌 → 弹道永久改变 |
| 蓄能塔 | 累积被击杀敌人的元素值，满则给全场敌人上同种元素（翻盘机制） |

**设计后果**：地形既是解法（用火区烧整队、用崩塌打开射界）也是约束（掩体会挡你的弹），无法纯靠堆伤害通關。

### I-5 防线值守 —— 让"放置"有社交意义

**问题**：原作离线收益是纯挂机，社交只有一张排行榜。
**做法**：把玩家的构筑变成可被挑战的资产。

- 玩家在**自家防线**布 3 个防御工事（减速带 / 阻击墙 / 电栅），使用同一套养成数据
- 生成**防线快照**（技能槽 + 工事 + 元素覆盖 + 战力 + 种子）
- 其他玩家挑战该快照：**客户端下载快照 → 用同款引擎本地模拟 → 回传结果与回放哈希 → 服务端做上限校验**
  - ⚠️ **服务端不跑战斗引擎**，因此不需要 Go/TS 双引擎同步（这正是 I-6 的价值）
- 胜者窃取败者 **10% 资源**（可被偷上限保护）
- 每日 3 次挑战机会；被挑战每日最多被偷 2 次；可开启 24h 护盾

**副产品**：这让"我的构筑够不够多样"变成可被检验的，从而反哺 I-3 的搭配决策。

---

### I-6 回放哈希验真 —— 公开可验证的公平

**问题**：客户端结算的分数天然不可信，只能靠上限校验被动防守。
**做法**：让分数**任何人可复现**，作弊即自证。

1. 战斗**完全确定性**：`seed + 固定 60Hz 步进 + 定点整数数学`
2. 每局记录关键事件序列（发射/命中/反应/击杀/漏怪/波次）
3. `replayHash = FNV64(事件序列)` 存入 `battle_records`
4. **验真入口**：小程序「战绩验真」页 + 后台「验真」按钮 → 输入 battle_id，用同种子本地重放，比对哈希
5. 排行榜分数因此**公开可复现**；被质疑的分数可当场验证

**⚠️ 关键技术约束（影响整个引擎）**：
> 浮点运算在不同 JS 引擎/设备上结果可能不一致 → 哈希必然不稳定。
> 因此**所有伤害、速度、坐标、生命值一律使用定点整数**（统一 `×1000` 取整，禁止 `Math.random`，随机只走 PRNG）。
> 渲染层在绘制前才转回浮点。这一条是硬约束，改动物理/伤害代码时必须遵守。

**防作弊的升级路径**：
- 旧做法：上限校验（被动，信任服务端给上限）
- 新做法：哈希可复现（主动，**分数的正确性由任何人可独立证明**）
- 上限校验保留为第一道过滤，防止有人构造极端回放骗哈希

### I-7 构筑评分替代战力评分

**问题**：原作把所有投入折算成一个"战力 9999"数字，引导玩家堆数值。
**做法**：主指标改为**构筑评分**（战力榜仍保留）。

```
构筑评分 = 元素覆盖数(5)      × 12
         + 反应链完备度(7)    × 15
         + 专精树完成度(8系)  × 10
         + 装备契合度          × 12
         + 机制解锁深度        × 8
```

- 首页用**雷达图**展示，短板高亮："你缺 冰 系 → 无法触发 超导 / 急速冻结"
- 明确告诉玩家**缺什么、为什么缺、怎么补**，而不是告诉他"再升 5 级"
- 成本很低（纯展示层 + 一段评分计算），但设计感与引导效果最强

### 轻量创新（附带）

| 编号 | 内容 | 解决 |
|---|---|---|
| L-1 | **针对性诊断**：连续 2 次失败 → 分析卡点（"你在 第37关 被 高火抗 敌人 卡住 87% 的伤害"），给具体换装建议 | 原作玩家卡关时只能自己猜 |
| L-2 | **效率榜**：按"通关时最低战力"排名 | 让技巧有位置，而不是只有氪金榜 |
| L-3 | **阵型预设**：保存多套技能槽 + 工事配置，一键切换 | 100 关换装成本过高 |

## 9. 双端公式一致性契约

以下公式在 **Go（服务端校验）** 与 **TS（客户端渲染/结算）** 各实现一次，**必须同输入同输出**：

1. 元素反应伤害与抗性结算
2. 构筑评分与战力计算
3. 掉落表与掉落上限

实现方式：固定输入向量 `testdata/vectors.json`，双端各跑一遍断言，CI 比对输出。**任一公式改动必须同时改两处并更新向量** —— 这是本项目最大的正确性风险点。
