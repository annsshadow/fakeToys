#
# 每行：<METHOD> <route pattern>\t<reason>
#   reason = column:<列名>    → 反序列化/类型错配
#   reason = category:no-error-log → handler 500 但没有任何 ERROR 日志（可观测性缺陷，待定性）
#
# 规则（全部硬断言）：
#   1. 当前扫描到的 500 集合必须与下面这组条目【完全相等】：
#      - 出现基线外的新 500 → 红（新写的类型错配当天被拦）
#      - 基线里的条目复现不出来 → 红（已修但没删行，必须同 PR 删掉）
#   2. 条目数必须等于 tests/idor_matrix.rs 里的 BASELINE_COUNT；
#      每修一条就删一行并下调 BASELINE_COUNT —— 基线只许变小，diff 强制可见。
#   3. 禁止为了变绿而往这里加行：加了 BASELINE_COUNT 也要加，评审可见。
