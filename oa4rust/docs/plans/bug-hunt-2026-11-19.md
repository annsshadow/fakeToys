# oa4rust 缺陷台账（2026-11-19）

范围：backend 业务逻辑、frontend/packages/apis|sdk、tests/contracts。

## BUG-001 — validate_length 按字节计数，误拒合法中文名（已修复）

- **文件**：`oa4rust/backend/crates/shared/src/input_validation.rs:67`（`validate_length`）
- **复现步骤**：
  1. 构造一个 100 个中文字符的文件名字符串（`"中".repeat(100)`，字符数 100，UTF-8 字节数 300）。
  2. 调用 `validate_length("name", &name, 1, 255)`。
  3. 期望：合法（100 字符 ≤ 255）；实际：返回 `TooLong { max: 255, actual: 300 }`（按字节判定）。
  4. 用户可见影响：`POST /api/file/folder/create` 与 `/api/file/folder/update` 对 86–255 字符的中文文件夹名返回 400；数据库列 `file_folder.name VARCHAR(255)` 按字符计数本可容纳。
- **根因**：`validate_length` 用 `value.len()`（UTF-8 字节数），与错误文案 `"must be at most {max} characters"` 及 PostgreSQL `VARCHAR(n)` 的字符计数口径不一致。CJK 字符占 3 字节，导致合法值被误判超长。
- **RED**：新增单测 `validate_length_counts_unicode_characters_not_bytes`；失败信息 `100 个字符应通过 1..=255 校验（按字符而非字节）`，因 `validate_length` 返回 Err(TooLong)——正确原因。
- **修复**：`let len = value.chars().count();`，并补充说明文档注释。
- **验证命令**：
  - `cd oa4rust/backend && cargo test -p shared validate_length_counts_unicode`（RED：FAILED，因 TooLong）
  - 修复后 `cargo test -p shared input_validation::tests`（GREEN：10 passed）
  - 门禁：`cargo check --workspace`、`cargo test --workspace`、`pnpm test -- --run`、`pnpm typecheck`、`pnpm lint`（见任务回执）
- **状态**：已修复、已 GREEN。

## 门禁测试中的环境依赖失败（非本次修改引入）

- `cargo test --workspace` 出现 1 个失败：`shared::netguard::tests::validate_target_unresolvable_hostname_is_invalid_host`（`netguard.rs:356`）。
- 复现：单独运行 `cargo test -p shared validate_target_unresolvable_hostname_is_invalid_host` 稳定失败。
- 根因：测试假设 RFC 2606 `.invalid` 域名不可解析（预期 `Err(FetchError::InvalidHost)`），但本机 DNS 对任意域名做通配解析，将 `this-host-does-not-exist.invalid` 解析为某 benchmark 保留段地址（脱敏为 `<BENCHMARK_RESERVED_IP>`）。Node -e DNS 探针确认解析成功（ERR=null，ADDR 为 benchmark 保留段，已脱敏）。
- 与本次修复无关：该测试不调用 `validate_length`，代码路径独立；`netguard.rs` 未改动。属本机 DNS 环境 artifact，生产/常规环境不复现。按收敛原则未修改该测试或产品代码，仅记录。
