    02 · 嵌入与位置编码¶

    一句话定位：嵌入（embedding）把离散的 token 编号变成稠密向量，位置编码（positional encoding）再把"顺序"信息注入进去——没有它们，Transformer 既读不懂词义，也分不清语序。

    直觉：从"编号"到"坐标"¶

    上一讲里，分词器把文本变成了一串整数编号。但编号 7 和编号 8 之间没有任何数值意义——它们只是标签。模型需要的是：语义相近的 token，向量也相近。

    嵌入层就是一张可学习的"坐标表"：词表里每个 token 都对应高维空间里的一个点（向量）。训练过程会不断挪动这些点，让"猫"和"狗"靠得近、"猫"和"方程"离得远。

    但 Transformer 的注意力机制有个"天生缺陷"：它是置换不变的——打乱输入 token 的顺序，注意力的计算结果只是跟着打乱，模型本身感知不到"谁在前谁在后"。而语言里顺序至关重要（"狗咬人"≠"人咬狗"）。所以我们必须额外把位置信息喂进去，这就是位置编码。

    数学原理：查表与位置相加¶

    token 嵌入¶

    设嵌入矩阵 $W_{te} \in \mathbb{R}^{V \times d}$（$V$ 是词表大小，$d$ 是嵌入维度）。对编号为 $i$ 的 token，它的嵌入就是矩阵的第 $i$ 行：

    $$ e_i = W_{te}[i] $$

    这只是一次"查表"（行选择），没有矩阵乘法。但反向传播时，被查到的那几行会收到梯度。

    位置嵌入与相加¶

    本项目用可学习绝对位置编码：再准备一张位置表 $W_{pe} \in \mathbb{R}^{T_{max} \times d}$，位置 $t$ 的编码是 $W_{pe}[t]$。最终输入到 Transformer 的向量是两者逐元素相加：

    $$ x_t = W_{te}[\text{idx}t] + W[t] $$

    一个常见疑问：为什么是相加而不是拼接？ 相加不增加维度（省参数、省计算），而且模型完全有能力在 $d$ 维空间里"分配"出一些方向去承载位置信息、另一些承载语义——加法并不会让两种信息不可分离。

    结合本项目代码：Embedding 层¶

    来自 minigrad/nn.py：

    class Embedding(Module):
    """查表嵌入，权重小随机初始化（std=0.02，GPT-2 惯例）。"""

    def __init__(self, num_embeddings, dim):
        self.weight = Tensor(np.random.randn(num_embeddings, dim) * 0.02)

    def forward(self, idx):
        return engine.embedding(self.weight, idx)

    两个细节值得注意：

    1. 初始化 * 0.02：权重用标准正态乘以 0.02，即 std≈0.02 的小随机值。这是 GPT-2 的经验惯例——嵌入太大会让初始激活爆炸、训练不稳。
    2. forward 把实际查表委托给 engine.embedding，这样反向传播能自动接上。

    查表的前向与反向：engine.embedding¶

    来自 minigrad/engine.py：

    def embedding(weight, idx):
    """按整数索引 ``idx`` 从 ``weight`` (V, C) 中取行；反向时做 scatter-add。"""
    idx = np.asarray(idx)
    out = Tensor(weight.data[idx], (weight,), "embedding")

    def _backward():
        np.add.at(weight.grad, idx, out.grad)

    out._backward = _backward
    return out
    • 前向：weight.data[idx] 用 NumPy 的高级索引一次性取出所有需要的行。
    • 反向：这是精髓。查表的反向是 scatter-add（散射累加）。为什么用 np.add.at 而不是普通的 weight.grad[idx] += out.grad？因为同一个 token 可能在序列里出现多次，idx 里会有重复索引。普通赋值在重复索引上只会保留最后一次，而 np.add.at 会正确累加所有梯度——这是一个极易踩坑的点。

    结合本项目代码：GPT 里 token 与位置相加¶

    来自 minigrad/nn.py 的 GPT：

    def __init__(self, cfg: GPTConfig):
    self.cfg = cfg
    self.wte = Embedding(cfg.vocab_size, cfg.n_embd)   # token 嵌入
    self.wpe = Embedding(cfg.block_size, cfg.n_embd)   # 位置嵌入
    ...

def forward(self, idx):
    idx = np.asarray(idx)
    B, T = idx.shape
    assert T <= self.cfg.block_size, "序列超过 block_size"
    x = self.wte(idx) + self.wpe(np.arange(T))  # token + 位置嵌入
    for block in self.blocks:
        x = block(x)
    ...

    关键就是这一行：

    x = self.wte(idx) + self.wpe(np.arange(T))
    • self.wte(idx)：形状 (B, T, n_embd)，每个 token 的语义向量。
    • self.wpe(np.arange(T))：np.arange(T) 生成 [0, 1, ..., T-1]，查出前 $T$ 个位置的向量，形状 (T, n_embd)。
    • 两者相加时，(T, n_embd) 通过广播加到 (B, T, n_embd) 的每个 batch 上——即每个样本的第 $t$ 个位置都加上同一个位置向量 $W_{pe}[t]$。

    assert T <= self.cfg.block_size：位置表只有 block_size 行，这是"绝对位置编码"的硬约束——超过训练长度就没有对应的位置向量，模型无法外推到更长序列。这正是绝对位置编码的最大短板。

    结合本项目代码：权重共享¶

    来自 torchgpt/model.py 的 GPT.__init__：

    self.lm_head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
# 权重共享：输入嵌入与输出投影同一张表（GPT-2 的做法，省参数、更稳）
self.transformer.wte.weight = self.lm_head.weight

    这叫 weight tying（权重绑定）：输入端的 token 嵌入矩阵 $W_{te}$（$V \times d$）和输出端把隐状态投影回词表的 $W_{head}$（$d \times V$）本质是同一张表的转置关系，于是干脆共享同一份参数。

    好处：

    • 省参数：词表大时，$V \times d$ 是模型里最大的矩阵之一，共享直接省掉一份。
    • 更稳、泛化更好："把 token 映射进空间"和"把空间映射回 token"用同一套几何，训练更一致（Press & Wolf, 2017 的发现）。

    注意本项目的 minigrad/nn.py 版 GPT 没有做权重共享——它的 self.head = Linear(cfg.n_embd, cfg.vocab_size, bias=False) 是独立参数。这是教学轨为了简单清晰而做的取舍，对照 torchgpt 正好看出"手写版"和"工程版"的差异。

    延伸：其他位置编码方案（本项目未实现）¶

    本项目用的是可学习绝对位置编码。工业界还有几种主流方案，这里讲概念、不涉及本项目代码：

    正弦位置编码（Sinusoidal）¶

    原版 Transformer 的做法，不需要学习，用固定的三角函数：

    $$ PE_{(t, 2i)} = \sin!\left(\frac{t}{10000^{2i/d}}\right), \quad PE_{(t, 2i+1)} = \cos!\left(\frac{t}{10000^{2i/d}}\right) $$

    好处是不占参数、理论上能外推到任意长度；缺点是外推效果实际并不理想。

    RoPE（旋转位置编码）¶

    LLaMA、GLM 等现代模型的主流选择。它不往输入里"加"位置向量，而是在注意力计算时，把 Q 和 K 向量按位置旋转一个角度。核心优势：注意力分数只依赖两个 token 的相对位置 $t_i - t_j$，而非绝对位置，因此外推性和长文本表现更好。

    ALiBi（Attention with Linear Biases）¶

    更简单粗暴：不改嵌入，直接在注意力分数上按两个位置的距离线性地减去一个惩罚 $-m \cdot |t_i - t_j|$，距离越远分数越低。几乎零成本，外推能力强。

    一句话对比：绝对位置编码（本项目）简单直观但不能外推；RoPE/ALiBi 把"相对位置"编进注意力，是长上下文模型的标配。

    常见坑 / 误区¶

    1. 忘了加位置编码——只做 wte(idx) 不加 wpe，模型就彻底感知不到语序，训练出来效果奇差且难以察觉。
    2. 嵌入初始化太大——不乘 0.02 而用标准正态，初始激活会偏大，叠加多层后数值不稳。
    3. 误用普通索引赋值做反向——weight.grad[idx] += g 在重复 token 上会丢梯度，必须用 np.add.at（见 engine.embedding）。
    4. 以为绝对位置编码能处理任意长序列——block_size 是硬上限，超了直接触发 assert。
    5. 分不清权重共享的两端——wte.weight 和 lm_head.weight 共享的是同一个对象，改一个等于改另一个；本项目 minigrad 轨未共享，不要张冠李戴。

    动手练习¶

    1. 验证广播相加：构造一个 GPTConfig，手动跑一遍 wte(idx)、wpe(np.arange(T))，打印两者的 shape，确认相加后是 (B, T, n_embd)，并解释位置向量是如何广播到每个 batch 的。

    2. 复现 scatter-add 陷阱：构造一个 idx 里包含重复 token 的输入，跑一次 engine.embedding 的前向再 backward，然后把 np.add.at 换成 weight.grad[idx] += out.grad 对比两种结果，亲眼看到重复索引下梯度被覆盖的 bug。

    3. 估算权重共享省下的参数：按 torchgpt/config.py 的默认 vocab_size、n_embd，计算 wte 和 lm_head 各自的参数量，说明 weight tying 到底省了多少，并解释为什么词表越大这个收益越明显。
