    09 评估：从困惑度到下游基准与生成质量¶

    一句话定位：训练 loss 下降不等于模型变好用——评估就是回答"它到底好在哪、好多少"的那套度量，从内在的困惑度到外在的任务基准，再到生成质量与采样参数的影响。

    直觉¶

    你训了个模型，val loss 从 3.2 降到 1.8。然后呢？这个数字说明不了"它会不会做数学题""它回答得像不像人""它会不会一本正经地胡说八道"。

    评估分三个层次，由近到远：

    1. 内在指标（intrinsic）：直接量模型对文本的"预测能力"，最典型的是困惑度（perplexity）。便宜、自动、训练时随手就能算，但只衡量"预测下一个词的概率分布有多准"，离"任务做得好不好"还有距离。
    2. 下游基准（downstream benchmark）：让模型去做具体任务——答选择题（MMLU）、做数学题（GSM8K）、常识推理（HellaSwag）、写代码（HumanEval），用准确率等打分。更贴近真实能力，但数据可能泄漏、也量不出"回答得好不好听"。
    3. 生成质量（generation quality）：开放式生成（写作、对话、摘要）没有唯一答案，得用 BLEU/ROUGE 这类重叠度指标（局限很大），或干脆让另一个强模型来当裁判（LLM-as-judge）。

    原理¶

    困惑度 = exp(平均交叉熵)¶

    语言模型本质是在估计 token 序列的概率。给定一段文本 w₁…w_N，模型给它的（条件）概率越高，说明模型对这段文本"越不意外"。困惑度定义为每 token 平均负对数似然的指数：

    $$ \text{PPL} = \exp!\Big( -\frac{1}{N}\sum_{t=1}^{N} \log p(w_t \mid w_{<t}) \Big) = \exp(\text{平均交叉熵}) $$

    直觉解读：PPL 可以理解为模型在每一步"平均在多少个等概率选项之间犹豫"。PPL=1 表示完全确定（每步都 100% 猜对）；PPL=50 表示大致相当于在 50 个等概率候选里挑。越低越好。

    交叉熵损失（以 e 为底的自然对数）和困惑度是一一对应的：PPL = exp(loss)。所以训练时监控的 loss，取指数就是困惑度。

    困惑度的局限¶

    • 跨词表不可比：字符级模型和 BPE 子词模型的"一个 token"含义不同，PPL 数值不能直接比。本项目用的是字符级（torchgpt/data.py 的 CharDataset），PPL 会和子词模型差一个量级，这不代表谁强谁弱。
    • 不等于任务能力：PPL 低只说明"拟合文本分布准"，不保证会推理、会遵循指令。
    • 对测试集敏感：换一份测试文本，PPL 就变。只在同分布、同 tokenizer 下纵向比较才有意义。
    • 会被数据泄漏污染：若测试文本在训练集里出现过，PPL 会假性偏低。

    下游基准（本项目未实现，仅讲概念）¶

    • MMLU：57 个学科的多选题，测广度知识。常用做法是比较各选项的对数似然，选模型概率最高的那个。
    • GSM8K：小学数学应用题，测多步推理。通常让模型生成推理链再抽取最终答案，比对数值。
    • HellaSwag：从几个续写里选最合理的，测常识。
    • HumanEval：给函数签名和 docstring，让模型补全代码，用单元测试判对错，指标是 pass@k（采样 k 次至少一次通过的比例）。

    评测这些基准讲究 few-shot 提示（在题目前拼几个示范）、答案抽取规则、以及是否允许思维链，细节极影响分数——同一个模型报出的分差好几个点往往只是评测设置不同。

    生成质量评估¶

    • BLEU / ROUGE：基于 n-gram 重叠。BLEU 偏精确率（机器翻译常用），ROUGE 偏召回率（摘要常用）。局限：它们只看字面重叠，一个意思对、用词不同的好答案会被判低分；而堆砌参考词的烂答案可能虚高。开放生成里参考价值有限。
    • LLM-as-judge：用一个强模型按评分标准给回答打分或做成对比较。可扩展、和人类相关性往往高于 BLEU/ROUGE，但有位置偏置（倾向选前一个）、长度偏置（倾向更长的）、自我偏好（偏爱自己家族模型），需要用交换顺序、控制长度等手段去偏。

    温度 / top-k / top-p 对生成的影响¶

    同一个模型，采样参数不同，输出的"性格"天差地别：

    • 温度 T：对 logits 除以 T 再 softmax。T<1 让分布更尖锐（更保守、更可能复读），T>1 更平、更随机（更有创意也更容易胡说），T→0 退化为贪心（永远取最大概率）。
    • top-k：只在概率最高的 k 个 token 里采样，截断长尾，防止偶尔采到离谱的低概率词。
    • top-p（核采样，nucleus）：取累积概率达到 p 的最小 token 集合里采样。本项目未实现，与 top-k 的区别是：阈值随分布形状自适应——分布尖锐时候选少、平坦时候选多，通常比固定 k 更自然。

    评估生成质量时，必须报告采样参数：同一模型 T=0.2 和 T=1.2 的输出判若两人，不说参数的生成评测没有可比性。

    结合本项目代码¶

    困惑度：torchgpt/eval.py¶

    # torchgpt/eval.py
@torch.no_grad()
def perplexity(model, data, block_size, device="cpu", stride=None, max_blocks=None):
    """在一段连续 token 上以滑动窗口计算困惑度。"""
    model.eval()
    stride = stride or block_size
    nll_sum, token_count, blocks = 0.0, 0, 0
    for start in range(0, len(data) - block_size - 1, stride):
        x = torch.from_numpy(data[start : start + block_size].astype("int64"))[None].to(device)
        y = torch.from_numpy(data[start + 1 : start + 1 + block_size].astype("int64"))[None].to(device)
        _, loss = model(x, y)
        nll_sum += loss.item() * block_size
        token_count += block_size
        blocks += 1
        if max_blocks and blocks >= max_blocks:
            break
    mean_nll = nll_sum / max(1, token_count)
    return math.exp(mean_nll)

    对照原理逐点看：

    • @torch.no_grad() + model.eval()：评估不需要梯度，且关掉 dropout 等训练态行为，保证结果可复现。
    • 滑动窗口：从 0 开始、每次前进 stride，切出长度 block_size 的 x 和错位一位的 y。stride 默认等于 block_size，即不重叠地扫过全文；若把 stride 设小则窗口重叠，每个 token 被更充分地"带着上文"预测，PPL 估计更准但更慢。
    • model(x, y) 返回的 loss 就是这一窗的平均交叉熵（见 torchgpt/model.py 里的 F.cross_entropy，默认对 token 取平均）。
    • nll_sum += loss.item() * block_size：把"平均"还原成"总和"（乘回 token 数），再除以总 token 数得到全局平均交叉熵 mean_nll——这样不同窗等权重地按 token 聚合，比简单对各窗 loss 求平均更正确。
    • return math.exp(mean_nll)：exp(平均交叉熵) = 困惑度，与公式完全一致。
    • max_blocks：限制窗口数，在大语料上快速估一个近似 PPL，不必扫完全文。

    数据来自 torchgpt/data.py 的 CharDataset：直接把它的 val_ids 传进来即可，例如 perplexity(model, ds.val_ids, cfg.block_size)。因为是字符级词表，算出的 PPL 不要和子词模型横向比。

    采样参数：GPT.generate¶

    生成与采样参数的实现在 torchgpt/model.py：

    # torchgpt/model.py
@torch.no_grad()
def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -self.cfg.block_size :]
        logits, _ = self(idx_cond)
        logits = logits[:, -1, :] / temperature          # 温度缩放
        if top_k is not None:
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits[logits < v[:, [-1]]] = -float("inf")   # top-k 截断
        probs = F.softmax(logits, dim=-1)
        idx_next = torch.multinomial(probs, num_samples=1) # 按概率采样
        idx = torch.cat((idx, idx_next), dim=1)
    return idx
    • logits / temperature：温度缩放，T 越小分布越尖。注意 T=0 会除零，实际要走贪心就得特判（纯 NumPy 版 minigrad/sample.py 里用 max(temperature, 1e-6) 兜了底）。
    • torch.topk + 把低于第 k 大的 logits 置为 -inf：这就是 top-k 截断，softmax 后那些位置概率归零。
    • torch.multinomial：按概率采样（不是取最大），这正是温度/top-k 能影响多样性的原因。
    • 本项目没有 top-p：想加核采样，需在 softmax 后对概率排序、累加到阈值 p、截断尾部再归一化。

    torchgpt/sample.py 的高层封装 sample(...) 默认 temperature=0.8, top_k=20——偏保守的组合，适合字符级小模型，太高的温度在这种小模型上很容易生成乱码。

    两条轨对照：minigrad/sample.py 的 generate(model, idx, max_new_tokens, temperature, top_k, rng) 是同一套逻辑的纯 NumPy 实现（softmax_np + rng.choice），可以对照着读，理解"框架到底替你做了什么"。

    常见坑¶

    1. 拿 PPL 跨 tokenizer 比。 字符级和子词级的 PPL 不可比；本项目是字符级，别拿它的数字去对标 GPT-2 的 PPL。
    2. 把 loss 当 PPL 报。 loss 是交叉熵，PPL 是它的 exp。报告时说清是哪一个。
    3. 评测集和训练集重叠（数据泄漏）。 CharDataset 已经切了 train_ids/val_ids，但如果你自己拼数据时让验证文本混进了训练，PPL 会假性偏低、基准分虚高。评估前务必确认划分干净、无重复。
    4. 过拟合不看验证集。 训练 loss 一路降但验证 PPL 开始回升，是过拟合信号。只盯训练 loss 会被骗。
    5. 生成评测不报采样参数。 不写温度/top-k 的生成质量对比没有意义——同模型不同参数就是两种表现。
    6. 滑动窗口 stride 没想清楚。 stride=block_size（默认）扫得快但每个 token 的上文较短；想要更准可减小 stride 让窗口重叠，代价是更慢。
    7. 过度信任 BLEU/ROUGE 或裸用 LLM-as-judge。 前者只看字面重叠，后者有位置/长度/自我偏好偏置，用时都要配去偏手段。

    练习¶

    1. loss 与 PPL 的对应。 训练（或随机初始化）一个 GPT(GPTConfig())，在 CharDataset.val_ids 上调 perplexity(model, ds.val_ids, cfg.block_size)。再手动跑一遍 estimate_loss（torchgpt/train.py）拿到平均交叉熵，验证 exp(loss) 约等于 perplexity 的返回值（注意聚合方式差异带来的小偏差）。随机初始化模型的 PPL 应接近词表大小 vocab_size，想想为什么。
    2. stride 的影响。 对同一个模型和同一段 val_ids，分别用 stride=block_size（默认）和 stride=block_size//4 调 perplexity，比较两个 PPL 值和耗时，解释重叠窗口为何通常给出略低（更准）的困惑度。
    3. 采样参数的性格。 固定随机种子，用同一个 GPT 和同一个起始 prompt，调 GPT.generate 分别试 (temperature=0.5, top_k=5)、(1.0, 20)、(1.5, None) 三组，各生成 200 字符并用 CharDataset.decode 解码。对比输出的重复度和"胡说程度"，用一句话描述温度和 top-k 各自的影响。
