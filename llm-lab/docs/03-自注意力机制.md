# 03 · 自注意力机制

> 一句话定位：自注意力（self-attention）让序列里每个 token 都能"看"其它 token 并按相关度加权汇总信息——它是 Transformer 的心脏，也是大模型能理解长距离依赖的根本原因。

## 直觉：图书馆里的检索

把注意力想象成一次图书馆检索：

- **Query（查询，Q）**：你心里的问题——"我想找关于猫的书"。
- **Key（键，K）**：每本书书脊上的标签——"猫""狗""数学"。
- **Value（值，V）**：书里真正的内容。

检索时，你拿自己的 Query 去和每本书的 Key 比对相似度，相似度高的书权重大，然后按权重把这些书的 Value（内容）加权汇总，得到答案。

自注意力的妙处在于：Q、K、V 全都来自**同一个输入序列**（所以叫"自"注意力）。序列里第 $t$ 个 token 用自己的 Query，去和包括自己在内的所有 token 的 Key 比对，决定该从每个 token 身上"抄"多少信息过来。这样每个位置的输出都融合了全局上下文。

## 数学原理：缩放点积注意力

给定查询矩阵 $Q$、键矩阵 $K$、值矩阵 $V$（形状都是 $T \times d$，$T$ 是序列长度，$d$ 是每个头的维度），注意力定义为：

$$ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right) V $$

分步理解：

1. $QK^\top$：$(T \times d)(d \times T) = (T \times T)$，第 $(i, j)$ 个元素是 token $i$ 的 Query 和 token $j$ 的 Key 的点积，即"相关度分数"。
2. $/\sqrt{d}$：缩放。
3. $\text{softmax}$：沿最后一维归一化，把每一行变成一个和为 1 的注意力权重分布。
4. 乘 $V$：$(T \times T)(T \times d) = (T \times d)$，用权重对所有 Value 加权求和。

### 为什么要除以 $\sqrt{d}$？

假设 Q、K 的每个分量是独立、均值 0、方差 1 的随机变量，那么点积 $q \cdot k = \sum_{i=1}^{d} q_i k_i$ 的方差是 $d$，即标准差 $\sqrt{d}$。维度 $d$ 越大，点积的数值摆动越剧烈。

如果不缩放，这些偏大的分数喂进 softmax 会把分布推向极端（一个位置接近 1、其余接近 0），导致 softmax 梯度几乎消失、训练停滞。除以 $\sqrt{d}$ 把方差拉回 1，让分数分布平缓、梯度健康。

## 结合本项目代码：minigrad 的手写版

来自 `minigrad/nn.py` 的 `CausalSelfAttention`：

```python
def __init__(self, n_embd, n_head):
    assert n_embd % n_head == 0, "n_embd 必须能被 n_head 整除"
    self.n_head = n_head
    self.head_dim = n_embd // n_head
    self.q = Linear(n_embd, n_embd)
    self.k = Linear(n_embd, n_embd)
    self.v = Linear(n_embd, n_embd)
    self.proj = Linear(n_embd, n_embd)
```

教学版刻意用**三个独立的 Linear** 分别产生 Q、K、V，读起来一目了然。前向过程：

```python
def forward(self, x):
    B, T, C = x.shape
    H, d = self.n_head, self.head_dim

    def split_heads(t):
        # (B, T, C) -> (B, H, T, d)
        return t.reshape(B, T, H, d).transpose((0, 2, 1, 3))

    q, k, v = split_heads(self.q(x)), split_heads(self.k(x)), split_heads(self.v(x))

    att = (q @ k.transpose((0, 1, 3, 2))) * (1.0 / np.sqrt(d))  # (B,H,T,T)
    mask = np.triu(np.ones((T, T), dtype=np.float64), k=1) * -1e9  # 未来位置置 -inf
    att = engine.softmax(att + Tensor(mask), axis=-1)
    y = att @ v  # (B,H,T,d)
    y = y.transpose((0, 2, 1, 3)).reshape(B, T, C)  # 合并多头
    return self.proj(y)
```

逐段对照公式：

- `split_heads`：把 `(B, T, C)` 拆成 `(B, H, T, d)`——这就是**多头注意力**，下面详述。
- `q @ k.transpose((0, 1, 3, 2))`：对最后两维做 $QK^\top$，得到 `(B, H, T, T)` 的分数矩阵。
- `* (1.0 / np.sqrt(d))`：对应公式里的 $/\sqrt{d}$，这里 `d` 是 `head_dim`（每个头的维度），不是整个 `n_embd`。
- `engine.softmax(att + Tensor(mask), axis=-1)`：加上因果 mask 后沿最后一维 softmax。
- `att @ v`：加权汇总 Value。
- `y.transpose(...).reshape(B, T, C)`：把多头拼回原维度，再过一层 `self.proj`。

### 因果 mask：保证自回归

```python
mask = np.triu(np.ones((T, T), dtype=np.float64), k=1) * -1e9  # 未来位置置 -inf
att = engine.softmax(att + Tensor(mask), axis=-1)
```

`np.triu(..., k=1)` 取**严格上三角**（不含对角线）为 1、其余为 0，再乘 `-1e9` 得到一个"上三角是极大负数、其余是 0"的矩阵。把它加到分数上：

- 位置 $(i, j)$ 当 $j > i$（未来）时，分数被加上 $-10^9$，softmax 后权重≈0。
- 当 $j \le i$（当前及过去）时，分数不变。

效果是：**第 $i$ 个 token 只能注意到自己和它之前的 token**，看不到未来。这就是"因果"（causal）——语言模型逐字预测下一个词时，不能偷看答案。为什么用 `-1e9` 而不是真的 `-inf`？避免 `exp(-inf)` 在数值计算里产生 `nan`，用一个足够大的负数在 float64 下等效且安全。

数值稳定的 softmax 实现在 `minigrad/engine.py`：

```python
def softmax(x, axis=-1):
    """数值稳定的 softmax：先减去最大值（常数，不影响梯度）再做 exp。"""
    shift = x.data.max(axis=axis, keepdims=True)
    e = (x - Tensor(shift)).exp()
    return e / e.sum(axis=axis, keepdims=True)
```

**先减最大值**是关键：`exp` 很容易上溢（`exp(1000)` 直接 inf）。减去每行最大值后，最大的指数是 `exp(0)=1`，既不溢出，又因为分子分母同乘常数而不改变 softmax 结果，梯度也不受影响。

### 多头注意力

`split_heads` 把 `C = H * d` 维向量切成 `H` 个 `d` 维的"头"，每个头独立做一遍注意力。直觉上，不同的头可以关注不同类型的关系——有的头盯着语法依赖，有的头盯着指代，有的头盯着邻近词。最后 `reshape` 拼回来再 `proj` 融合。本项目默认 `n_head=4`、`n_embd=64`，即每个头 `head_dim=16`。

## 结合本项目代码：torchgpt 的工程版

来自 `torchgpt/model.py` 的 `CausalSelfAttention`：

```python
def __init__(self, cfg: GPTConfig):
    super().__init__()
    assert cfg.n_embd % cfg.n_head == 0
    self.n_head = cfg.n_head
    self.n_embd = cfg.n_embd
    self.c_attn = nn.Linear(cfg.n_embd, 3 * cfg.n_embd, bias=cfg.bias)
    self.c_proj = nn.Linear(cfg.n_embd, cfg.n_embd, bias=cfg.bias)
    ...
    self.flash = hasattr(F, "scaled_dot_product_attention")
```

和 minigrad 版最明显的区别：**用一个 `c_attn = nn.Linear(n_embd, 3*n_embd)` 一次性产生 QKV**，再切开：

```python
def forward(self, x):
    B, T, C = x.size()
    q, k, v = self.c_attn(x).split(self.n_embd, dim=2)
    q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
    k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
    v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
    if self.flash:
        y = F.scaled_dot_product_attention(
            q, k, v, dropout_p=self.dropout if self.training else 0.0, is_causal=True
        )
    else:
        att = (q @ k.transpose(-2, -1)) / math.sqrt(k.size(-1))
        att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float("-inf"))
        att = self.attn_dropout(F.softmax(att, dim=-1))
        y = att @ v
    y = y.transpose(1, 2).contiguous().view(B, T, C)
    return self.resid_dropout(self.c_proj(y))
```

对照两份实现，三点工程差异：

1. **QKV 合并计算**：`c_attn` 一次矩阵乘产生 `3*n_embd`，再 `split(n_embd, dim=2)` 切成 Q/K/V。合并成一个大矩阵乘比三次小矩阵乘更利于 GPU 并行，这是工程优化；minigrad 用三个独立 Linear 则是为了可读性。两者数学等价。
2. **FlashAttention 快路径**：`self.flash = hasattr(F, "scaled_dot_product_attention")` 检测 PyTorch 2 是否提供融合算子。若有，`F.scaled_dot_product_attention(..., is_causal=True)` 一行搞定缩放、因果 mask、softmax、加权——而且**不显式构造 $T \times T$ 的注意力矩阵**，用分块计算把显存从 $O(T^2)$ 降到 $O(T)$，速度也大幅提升。
3. **mask 的实现**：fallback 分支用 `torch.tril`（下三角）构造 buffer，再 `masked_fill(... == 0, -inf)`。注意方向：minigrad 用 `np.triu(k=1)` 把**上三角**（未来）置负，torchgpt 用 `tril` 保留**下三角**（过去）——殊途同归，都是"只看过去"。`is_causal=True` 则让 FlashAttention 内部自动处理，连 mask 矩阵都不用建。

## 数学原理：注意力的复杂度

注意力分数矩阵 $QK^\top$ 的形状是 $T \times T$，对序列长度 $T$ 而言，计算量和显存都是：

$$ O(T^2 \cdot d) $$

这意味着序列翻倍，注意力开销涨 4 倍。这是 Transformer 处理长文本的**根本瓶颈**，也是 FlashAttention（省显存）、稀疏注意力、线性注意力等一系列工作想解决的核心问题。minigrad 版显式构造了 `(B, H, T, T)` 的 `att`，这个 $O(T^2)$ 的矩阵清晰可见；torchgpt 的 FlashAttention 路径则刻意避免把它整体物化。

## 常见坑 / 误区

1. **忘了缩放或缩放错维度**——`/sqrt(d)` 的 `d` 是**每个头的 `head_dim`**，不是整个 `n_embd`。minigrad 用 `np.sqrt(d)`（`d=head_dim`），torchgpt 用 `math.sqrt(k.size(-1))`（最后一维即 head_dim），都正确。
2. **mask 方向搞反**——`triu(k=1)` 遮未来、`tril` 留过去，弄反会让模型偷看答案，训练 loss 异常低但完全学不到自回归。
3. **softmax 不减最大值**——直接 `exp` 大分数会上溢成 inf/nan，`engine.softmax` 的减 max 是必备操作。
4. **用 `-inf` 而非大负数做 mask**——`exp(-inf)=0` 理论没问题，但某些路径下 `-inf` 参与运算会产生 nan；minigrad 用 `-1e9` 规避。
5. **以为 FlashAttention 改变了数学结果**——它只是等价的高效实现（省显存、更快），输出和朴素实现在数值误差内一致。

## 动手练习

1. **可视化注意力权重**：在 `minigrad/nn.py` 的 `CausalSelfAttention.forward` 里，把 `att`（softmax 之后）的 `.data` 取出来打印成一个 `T×T` 矩阵，确认它是**下三角**结构（上三角≈0），亲眼验证因果 mask 生效。

2. **对比有无缩放**：复制一份注意力计算，去掉 `* (1.0 / np.sqrt(d))`，用一个较大的 `head_dim`（比如把 `n_embd` 调大）跑前向，观察 softmax 后权重分布是否变得极端（接近 one-hot），理解缩放为何必要。

3. **对齐两份实现**：用相同的输入和手动设成相同的权重，分别跑 minigrad 的三 Linear 版和 torchgpt 的 `c_attn` 合并版（fallback 非 flash 分支），验证两者输出在数值误差内一致，从而确认"三个独立 Linear"和"一个大 Linear 再 split"数学等价。
